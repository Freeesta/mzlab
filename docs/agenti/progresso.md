# Barra di caricamento unica (`mzlab/web/progresso.js`)

- **Un solo modello** per ogni caricamento (`.mzML`, `.raw`, `.wiff`, cartelle `.D`/Waters, `.mzidx` già pronto): `PROGRESSO` (classic script, prima di `conversione.js`; riga in `carica.js` e in `tools/tipi/pagina.json`/`stretto.json`). Le barre della pagina mostrano ciò che dice il modello: la barra della scheda di carico (`#up`), il velo di «Apri» (`waitStato` in `shell.js`) e Tabui (`loadMaker` in `20_tpmine.js`).
- **Ingresso**: l'evento `mzlab-index {name, frac, phase}` (`frac` = 0..1 dell'intero file; fasi `read`, `scans`, `chrom` di `nativo-fasi.js`, `W`; un mzML dice solo l'indice). `upload0` in `shell.js` fa `PROGRESSO.begin(nome, dimensione)` per tutti i file del caricamento prima di leggerne uno, `set` a ogni evento, `end` alla fine (anche in errore). L'app desktop manda il file sulla rete: i primi `PROG_NET.send` (30 %) della barra.
- **Regole** (provate da `tests/test_progresso.py`, per ogni lettore, con sequenze che tornano indietro e si ripetono, più un fuzz): un file non torna mai indietro; il totale non torna mai indietro (un file aggiunto a metà allarga il denominatore, il valore mostrato resta); niente 100 % prima di `end()` dell'ultimo file (al più 99); peso di un file = dimensione; finito il lotto, il prossimo `begin` riparte da 0. La fase mostrata è quella del file più lento, con «n di N» quando i file sono più d'uno.
- **Conversioni** (cartelle convertite in mzML, `ConvUI` in `conversione.js`): ha la sua barra (non c'è la barra di `#up`) con le stesse regole (`maxPc`, al più 99 fino a `end()`); i pesi delle fasi convertire/indicizzare stanno in `PROG_W.conversione` (0,75/0,25, come `CONV_W`; `progCompose`).
- **Prova nel browser**: `tests_e2e/e2e_progresso.py` (serie mzML + coppia `.wiff`, registra `aria-valuenow` della barra: solo in avanti, 100 solo alla fine, una barra sola).
