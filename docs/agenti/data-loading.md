# Loading: first load and load table
- **Work area from the first draw** (`index.html`, `applyView` in `shell.js`, `workState`/`syncWork` in `area-lavoro.js`): `#v-data` is visible right away; `#v-workspace` shows a single thing, decided by the state (`data-work`): `panels` (a shown file or an open panel), `landing` (`#start` with `#drop`, folder, examples, `.dam` method, conversion, and below `#wtable` with `.samphead`, `#flist`, `#hrmix` as soon as the table has rows); `add` (the same page, from "+" or "Sample table") and `opening` separately.
  `landing` stays until a file is shown: the first non-blank file read by a load shows itself (`OPENNOW.showFirst` in `open-now.js`, like the first click: `soloFile`, starting layout with the TIC; once per session, never if there is already a shown file or a panel, never in restored sessions, which do not go through `boot`, nor for the tour's example: `OPENNOW.noAuto`), then the click in the list applies (`workShown`).
  It is also the only empty state: first visit, files being read (progress is only in the side list; the table grows below the drop zone, which does not move), all files removed (`workRows`: a row of a removed file does not count), last panel closed (X of the panel or of the bar, `workClosedAll`; `untickAll`: no file ticked; Undo reopens panels and ticks; a click on a file or "Back to work!" brings a file back) and "+" of the side panel (`S.adding`, state `add`: same page, no second screen).
  `#backwork` "Back to work!" (with open files, states `add` and `landing`) and Esc put the panels back as they were (`backToWork` in `shell.js`: scroll included; without panels it shows the first file); a file added from there closes `add` (`upload`). "Full reset" of `#avvio-fase` appears after 10 s of startup only if there are files waiting for the engine. `#up` and `#unopen` (errors only) sit above the boxes in `#wdata`; before the session the side panel also takes dropped files.
  `#drop` is a button (`role=button`, `tabindex=0`, `load.drop.aria`; Enter and Space open `#pick`). In `#tools` the data buttons are `disabled` + `aria-disabled` until a file is open (already in the markup); the header calculators stay usable. An empty `#fsel` keeps the width of a name. With `#/draw` `html.in-draw` hides `#v-data` before any script.
  **Sample table** (`renderFiles` in `shell.js`, `e2e_tabella_campioni`): a single `.samptool` bar (count "N samples", Columns, Groups, options, download icon `#dlall`, "Remove all files" `#rmall` with confirmation `removeAllFiles`); file names are not underlined (only on hover and focus); the last column is `sticky` on the right (× always visible); the download icons (`CONV.menu`) open a menu with the two formats written, "mzML" and "mzML + Numpress" (`saveAs`). `#start` loses its top margin when `#backwork` is visible: the button sits right below `#tools`.
- After a reload the table rows are rebuilt from the engine state (`restoreRows`, `shell.js`; `e2e_tabella_demo`): they take role and time from the open files and do not ask for proposals from the names, which `OPENNOW.sync` would write over the saved ones (`e2e_campioni_salva`).
  **`#tools` button row**: always ONE row (never `flex-wrap`; height reserved even when empty, `e2e_toolbar_wrap`); order file | "+ panel" | undo-redo-close … Method, dividers only between groups; with little space `#fsel` shrinks first (`cqw` of the `#tools` container, not `vw`), then `#g-add` scrolls sideways (keyboard focus brings it into view).
- Return visit with a saved session (`mzlab.sessione`): the landing is never painted; `avvio-progressivo.js` immediately shows `#opening.restoring` ("load.session.restoring", reserved height) in place of `#wdata`, then the panels (or the sample table) replace the box; with an empty session the landing appears in the same box.
- **First load** (`bootSession0` in `explore.js`; `e2e_apri_uno`, `e2e_apri_subito`): every new file enters the session HIDDEN (`vis` false, except the visibility saved by `restoreUi`); only the first non-blank file of a load opens by itself (`OPENNOW.showFirst`; until the student acts, the following files do not move the view to their tab: `OPENNOW.batchShown`), the others are shown with a click in the list and the drop zone makes room for the charts.
  "Sample table" (`#samptab`, file panel, fixed at the bottom; visible as soon as the list has rows, never inert, not a toggle: no `aria-pressed`, no `S.table`).
  Drop zone and table are ONE page (state `add`/`landing`): from the charts the button opens the page (`STATO.aggiunta`, the charts' scroll stays for "Back to work!") and brings the table under the header; on the page it only scrolls (smooth, instant with reduced motion) and moves the focus to the title `.samphead b`, without redrawing or moving anything (`e2e_tabella_scroll`: 1000/1366/1600 px, no layout shift). A click on a file in the list goes back to the charts. Series and calibrations use all open files: `vis` changes only what is drawn.
  Table width (`.ldtab`, `table-layout:fixed`): at least 860 px or the whole area (`#flist .ldtab`), 1060 px below 900 px; the area scrolls sideways, so the "File" column does not shrink to 32 px with the panel open on a tablet (test `e2e_safari_ipad`, 1024×768).
- **Load table, fields** (`renderFiles` in `shell.js`; `e2e_tempo_un_clic`): a value leaving the field (click on another field, Tab) is applied with the focus already moved, and the reordered table gives the focus back to the field (or the × button) that received it: a single click is enough.
- **Roles and times in the load table** (`ruoli-carica.js` model and proposals, `ruoli-celle.js` role and time cells; global object `RUOLI`; `e2e_ruoli_tempi`): the Rust engine `samples/1` reaches the page with POST `api/samples/<op>` (`statRoute` in `lr-map.js`, `lr_samples` in `rust-worker.js` and `rpc_lr.rs`).
- **Proposals** (`ruoli-carica.js`, `ruoli-celle.js`): `propose` gives role and time from the names (`f.gR`, `f.gT`); proposed and untouched cells carry the class `guess` (yellow, `load.guess.title`) like the concentration read from the name, and lose it at the first edit. Time is optional: no stripe, no warning, no `aria-invalid` cell for a missing time. The role is chosen only in the "Type" column.
- **Roles without t0 or subtypes**: there is no t0 role: a sample at time 0 is the t0 (`sottrazione.js` and Rust look for it that way). A single Blank type, without subtypes.
- **Dark time**: the dark time is NEGATIVE (minutes of dark before zero; the cell accepts "-30" or "−30", and a positive number written in a dark is read as negative: `darkTime` in `ordine.js`); the dark stays out of the gradient (`gradientLegend`, `byTime` in `explore.js`) and of the `auto` reference. An old project or TSV with `t0` or `blank:solvent`/`blank:procedure` opens as a sample at 0 and a plain blank (`CDOC.fields`, `parseTsv`).
- **Entry of `ST.files`**: `type` (base: sample/blank/standard), `role` (`tipo` of samples/1), `time` (minutes), `prop`, `gR`/`gT` (role and time still proposed), `ed` (chosen by the student: a late proposal does not overwrite it). Tests that open many files call `lib._tempi(pg)` to write the missing times (`lib.AUTO_TEMPI`) and `lib.open_first(pg)` for the first click on a file.
- **Subsequent load** (`bootSession0`, `remap` and `PEND` in `explore.js`; `e2e_ms2_ricarica`, `e2e_ricarica_a_meta`): open panels stay on their files even if the list is reopened file by file (intermediate steps do not yet have all files): a panel's file index (`k`, `ref`, `bk`, `bg`) and the active file follow the file NAME; a file not yet returned keeps name, visibility and label (`E._mem`) until it returns. A removed file stays removed: it is the same object as its "Removed · Undo" entry, it does not return when another file is opened.
- **Cache in file-by-file loads** (`bootSession0`): if the new session is the old one with files added at the end, `CACHE`, `CHROM1` and `SC` stay (keys follow `k`), so every open file asks for its answers only once; otherwise they are emptied. Test: `e2e_mrm_cache_aggiunte`.
- **Page closed right after a change** (`nb-pendiente.js`, `lr.js` boot; `e2e_chiusura_rapida`): if the notebook write into the engine does not arrive, `pagehide` leaves the last notebook in `localStorage` (`NBP.keep`); at the visit after the engine boot it reopens the files of that copy if it is more recent (`NBP.peek`, field `_t`), not only those of the engine's notebook, and `nbLoad` applies it (`NBP.take`).
- **Open immediately** (`OPENNOW` in `open-now.js`; `e2e_progressivo`, `e2e_carica_subito`): every file opens as soon as it is read. `upload0` (`shell.js`) calls `OPENNOW.add(nome)` as soon as a file is in the table; a queue opens one file at a time, in drop order (during a load a file read early waits for those dropped before, `CONVROWS.rank`; when the load is finished it opens everything), so `k` does not depend on which file finishes first:
  the first of the session with `api/explore`, the others with `append:true` (`Session.add`: the session is the same as opening the whole list in one call).
- **`#` in names** (`hashFree` in `conversione.js`, `hashRename` in `upload0`; `e2e_nome_cancelletto`): `#` separates a file from its parts in the list (`x.mzML#MS1`, `lr.rs`), so a file given with `#` enters with `_` (same name for the two files of a `.wiff` pair, counter `_2` if the name is taken) and the notice says "A#1.mzML opened as A_1.mzML" (`load.note.hashRenamed`, once per pair). The same `_` in the DATA names of `.wiff` samples (`wiffName`) and in `.d`/`.raw` folders (`mzmlName` of `agilent-d.js` and `waters-raw.js`).
  `bootSession` at most every 200 ms (a single redraw per group of files), then `RUOLI.commit` of the new files; a file that fails is removed from the tick and the others continue. Table tick = "in the session": removing the tick calls `removeFile` (undoable, `STORIA.tolto`), putting it back reopens the file (`fileRemoval(g).back()` or `add`); choosing again a table file that is not open re-ticks it instead of calling it "already loaded" (`dropDups`). `OPENNOW.idle()` resolves with an empty queue; `E.pending` stays an empty list for existing waits.
  "Switch to …" (`OPENNOW.toWorld`) and the question "Open all / Choose" above 50 files (`OPENNOW.many`) live in `open-now-raro.js`, and the box of a conversion requested from the table ("Download .mzML" of a vendor sample, `ConvUI.card`) in `conversione-carta.js`: both loaded at first use with `carica()`, outside the startup list (`test_peso_avvio.py`). The conversions of a load draw nothing (`ConvUI.group()`: only the stops).
- **First file first** (`createCopyGate` in `rust-carica.js`, `copiesOf` in `lr.js`, `e2e_copie_coda`): on the site the OPFS copies of a batch go two at a time, in list order (`rank` of the row), the others are "Queued"; so the first file reaches its builder first and is shown first (measurements in `measurements-copies.md`). `?copie=N` or localStorage `mzlab.dev.copie` = N chooses how many together, 0 = all together; the choice goes to the console once and into the diagnosis of the queued rows. The desktop app already loads one file at a time (chain of `upload0`).
- **Batch larger than the browser space** (`quota-lotto.js`, loaded the first time by `upload0`, `e2e_quota_lotto`): above 50 MB in total, before copying every data file × 1.8 is summed (copy + index during loading, `ROOM` of `archivio.js`) and compared with `storage.estimate()`; if it is not enough, ONE question: how many files, how much is needed, how much is left, how many fit, with "Load the first K" / "Try with all" / "Cancel".
- **Files rejected for space** (`error.quota`, `error.quotaWrite`): no error per file nor red row; they go into `rep.quota` and `reportLoad` shows ONE message (loaded n, not loaded m, the closed names, "Retry the rest"), which explains that the browser copies every file into its own space (part of the free disk, not RAM); with a single file the text is its error, with MB written, of the file and declared free. The queue is not cancelled: files that do not fit are stopped by `ensureRoom`. A short read of the index's spill file (`idx-spill.js`) counts as full space.
- **In-place reading** (`rust-sul-posto.js`, `tests_e2e/e2e_sul_posto.py`): a plain mzML of 50 MB or more (not `.gz`, not a vendor file) without space for the copy (`ensureRoom` refuses or the copy stops halfway) is read from the user's `File`: only the index (0.8 × the file) and the mark `idx/<nome>.sul` go into OPFS; `prima` of `quota-lotto.js` counts only the index for these files. Calm notice `load.sulPosto`. `lrFree` and `lrSpace` do not count its index as an orphan.
- **In-place reading, reading and reload**: `lettura-sync.js` reads the `File` with `FileReaderSync` and a read-ahead that restarts from 64 KiB after a jump (`.raw` members go between index and scans) and doubles up to 16 MiB while reads are in order (on 1 GB the same time as the copy, +17 % without). After a reload the `File` is gone: `lr_boot` removes index and mark and, if the file was loaded, says `load.sulRiapri` (load it again, it is still on the disk).
- **In-place reading, vendor files** (`rust-nativo.js` `putHeld`, `tests_e2e/e2e_nat_sul_posto.py`): if `ensureRoom` refuses the members or the browser stops their copy, and all members are user `File`s, the missing members are read from the `File` (map `posto`, read by `memberFiles`): only the stub (with `sul: true`) and the indexes go into OPFS, notice `load.sulPosto` per sample. At startup `lostDi` removes `sul` stubs without members and their indexes, and `rust-sul-posto.js` `boot` says `load.sulRiapri` (not `load.natInterrupted`).
- **In-place reading, member fingerprints** (`rust-nativo.js` `inPlace`, `impronta.js` `fileOf`): the fingerprint workers read the user's `File`; only the SHA-1 is awaited (needed by the `.raw` reader), SHA-256 and probe arrive alongside the index (`hashing`): the builder does not reread the member (`.raw` 1.55 GB in a private window: 34.3 s → 26.4 s; in a normal window the copy is complete and nothing changes). Without a worker the builder takes them as before. Test also WebKit: `e2e_impronta_file`.
- **In-place reading, limits**: the index contains the decoded peaks, so with compressed data (zlib) it weighs as much as or more than the file and may still not fit; the Flow's centroid copy (`lr_cen_have` `source`) requires the copy; two tabs: starting one removes the index of a file read in place in the other.
- **"Free space"** (`quota-lotto.js` `libera`, button of the space notice): from `api/spazio` shows granted and used space, loaded files, indexes and work files, leftovers of removed files; "Remove leftovers" (POST `api/spazio`) and "Remove all files" (`removeAllFiles`, undoable). Below 2 GB granted it says that a private window gives little space.
- **Space, tests** (`e2e_quota_lotto.py`): no `.part` nor index without a file after a rejected batch; "Remove all" immediately lowers `estimate().usage`.
- **Writing into the session** (`OPENNOW.edit`/`sync`): a student edit on an open file goes through `campioniEdit` (one undoable step); a proposal arrived after opening is applied silently with `CAMPIONI.apply(…, true)` to untouched cells (`!ed`), from the `FILETAB` callback.
- **Progress rows** (`UPROWS` in `upload-rows.js`, drawn by `renderFileList` in `#fl-up`): from the drop, a gray row `.fl.pend.up` (`data-up`, `title` = long text, `aria-busy`, bar `.prog` `role=progressbar`, phase and percentage from `CONVROWS.short`) for every file being read, converted or opened, at the end of the side list; it disappears when the file is open or set aside. Above the rows, while the batch runs, "3 of 5 ready · 0:12" (`data-cvhead`) and "Cancel" for everything (`data-up-all`, `CONVROWS.onCancel`).
  × on a row in progress = `OPENNOW.hold` + `ConvUI.stop` (conversion) or `lr_cancel` (the file stays unticked); an error stays red with "Details" (`DIAG`) and × closes it. `CONVROWS.fill` also updates these rows. (`.fl.pr` stays the MS2 precursor.)
- **Large folder** (`OPENNOW.many`, `#askdlg`): more than 50 data files in one drop ask once "Open all" / "Choose…"; "Choose" (or Esc) puts them in the table unticked (`OPENNOW.hold`).
- **Large table** (`renderFiles`): above 500 rows the body arrives in blocks of 200 per frame (`FRAME.next`, `FILECHUNK`).
- **Redraws during load** (`FILETAB`, `RUOLI.coalesce`): at most one per frame, and after a redraw that cost c ms the next waits 8×c (200 rows ≈ 30 ms → ≈ 240 ms); with few files it stays one per frame, `flush` at the end of the load paints immediately (`tests/ruoli_coalesce_node.mjs`).

## Row groups and summary
- **Table groups** (`gruppi-tab.js`, `GRUTAB`; `e2e_carico_gruppi_trascina`): without labels the rows stay in arrival order (`CONVROWS.rank`; a student edit dissolves it and `sortFiles` reorders it), without headers.
  `renderFiles` loads `gruppi-tab.js` at the first draw with files and redraws once. The group is `ugrp` on the `ST.files` row, written by `GRUPPI` together with the open files: a single writer, a single undo step (`stg()` is in the `files.view` snapshot); `mergeFiles` keeps it and a file that opens takes the label of its row (`GRUPPI.adopt`, in `renderFileList`).
  With at least one label `GRUTAB.rows` puts a row `tr.tg-head[data-ug]` (name, number, 24 px fold button) before its rows and "No group" (`data-ug=""`) at the bottom; from two rows up every row has `data-nm`, the `.tg-grip` handle (dragged onto a header or ONTO another row, `GDND.startT`) and the "Move to group ▸" button (`data-mv`, the same menu as the side list, `GDND.moveMenuT`).
  Above the table `#tb-by` (set by `GRUTAB.wire`) opens the same "Group by" menu (`GRUPPIPER.open("tb-by")`).
- **Inline group name** (`gruppi-nome.js`, `GRUNOME.edit`, lazy; `e2e_gruppi_tabella_nome`): double click on the header (not on the fold button: the second click does not fold it), F2 or Enter on the name (`.tg-name`, `role=button`, `aria-label` "Rename group …") turn the name into `input.tg-edit`.
  Enter and blur save, Esc cancels, empty = free "Group N"; an already existing name leaves the field open with `.tg-err` (`role=alert`, `aria-invalid`).
  It writes with `GRUPPI.renameTo(vecchio, nuovo)` (one undo step "rename"; `rename()` with the side list's prompt uses it). "No group" (`vecchio` = "") changes only the label `E.ugNone` (saved in `NB.ui.ugNone` and in the undo snapshot, `GRUPPI.noneName()` shows it also in the menus), it creates no groups.
- **Drop from the desktop on a header** (table or side list): `gruppi-dnd.js` highlights a group's header and `GRUPPI.expect(nomi, gruppo)` promises the label; the drop proceeds as usual and `GRUPPI.arrive()` (from `GRUTAB.pre`, at the top of `renderFiles`) puts it on the rows as soon as they arrive (key "custom", no undo step). On `#drop` or outside the headers nothing changes.
- The box below the table (`CONVROWS.summary()`, `conv.sum.aria`) lists only errors, cancelled and files with missing scans, with the total and "Close"; if all went well it does not appear, and at the end of the batch no "finished" text nor ring remains. Removing a file removes its row (`CONVROWS.dropEnded`, the last closes the box); "Remove all files" closes it (`clearDone`). Test: `e2e_togli_resoconto`.

## Low and high resolution together
- **World rule** (`OPENNOW.world`, `hrMixNote()` in `shell.js`; `e2e_carico_lrhr`): the session's world (low or high resolution, `f.hr` from the engine) is that of the first file read; files of the other world stay in the table unticked (re-ticking them does not open them: the focus goes to the `#hrmix` button). `#hrmix` (`role=status`, not an error) says how many files are set aside and offers a single button "Switch to high/low resolution". The switch first closes the panels of the closed world (`closeAllPanels`), then the first file of the other opens by itself.
- `OPENNOW.toWorld(hr)`: `api/new` closes the open files, ticks the other world and opens it with the same queue; a "Removed · Undo" entry (`STORIA.tolto`) brings back the previous world. Without any open file `#hrmix` still offers "LR only (n)" / "HR only (n)" (`hrMixPick`, `hrMixPreselect`: the more numerous world, LR on a tie). The engine's `err.hr.mix` error stays as a safety net.

## Drop on the file list
- Dragging files or a folder onto the `#dfiles` panel (with an open session, outside the load table) adds them immediately: `#fl-dz` shows the drop zone, `shell.js` uses the same `upload()`/`CartCarica.fromDrop(e, done)` and every file opens as soon as it is read (`OPENNOW`), without a loading screen (progress = `.fl.up` rows of the list).
  At the end of the batch `OPENNOW.note()` lowers the `#loading` veil (that of the tour's example file) and writes in `#fl-note` the files set aside (with the pointer to "Switch…" in the sample table). Opening a file of another tab does not raise the veil (`setTab(t, false, "file")`); the veil, when it falls, also removes the `#ldact` button. Duplicates are discarded by `dropDups`.
- Side list: only the first group is open by default (`E._grpOpen` keeps the student's choice); the group that receives moved files (drag or Ctrl+Shift+↑/↓, `gruppi-dnd.js` `openFor`) opens, so the row stays visible and keeps the focus; on reload the user's groups (`ugrp`) also return with an empty work area (`restoreUi`); the file name takes the space (`.fl .nm` flex:1) and the right-hand text (`.fmeta`) is compact.
- Files of a different resolution from those open (or the less numerous world of a mixed drop) do not open: they stay in the load table, unticked; `#fl-note` (`role=status`, 9 s; "added" fades after ~1 s) says so without errors. Test: `e2e_elenco_file`.
- The folder button `#cartpick` sits to the right of the title "1." (vertically centered, ≥8 px from the dashed zone); the file selector `#navfile` (arrows + `#fsel` menu) has equal height (32 px, 40 on touch), the menu is as wide as the longest name (min 9ch, max 40vw, "…" and full name in `title`). Dragging on the panels shows only the highlight of the drop zone, without a bubble. Test: `e2e_carico_pulizia`.
- **Initial active file** (`firstOpenK` in `lista-file.js`): the list order stays, but the first file that is not a blank (`type` blank or name with blk/blank/bianco) opens (and becomes active), the very first if all are blanks; a blank opened first during file-by-file loading closes when the first non-blank arrives. The live spectrum of a chromatogram follows the file chosen in the list (`followSpectra`) until its file menu has been used; a DDA never carries "· Full Scan" in the name (`noFullScan`). Test `e2e_dda_attivo`.
- **Saved MSn graph** (`upload0` in `shell.js`, before `fileKind`): `.json` files with `msngrafo/N` header leave the list and open in the graph window (`infusion-graph.md`); other files go on as usual and a graph error ends up in the `#unopen` box like that of an unreadable file. `#pick` also accepts `.json`.
  **"+"** (`#colsplus`, last cell of the header, `th.colplus` sticky on the right like the buttons column, `aria-label` "Add column"): opens the same picker as "Columns…" (`COLS.open`); on closing the focus goes back to "+".
- **Extra columns** (`colonne-campioni.js`, `COLS`, lazy; `e2e_colonne_campioni`): the "Columns" button opens a `<dialog>` with predefined and custom columns (name, text/number, unit; rename, move, remove) (grid layout: `e2e_colonne_dialogo`). Definitions in `NB.sampleCols`, values in `NB.sampleEx`; `renderFiles` uses `COLS.head/row`, `tsvText()` adds the columns to the TSV. Not yet in xlsx nor in the Flow's sample sheet.
- **Same height in every state** (`e2e_dati_stati_altezze`): bar and file panel have the same top margin in work, add files and return (the stuck scroll of `#dfiles` starts from its natural position, `--hh` + 1 px, not from +4 px); returning from "add" the panels enter only with the fade (`opn-rev`, as from the landing), without the 6 px slide of `.pnl`.
- **`.wiff` and `.wiff.scan` chosen alone**: the browser does not see neighboring files, so the site pairs them only if the two are chosen together or a folder is dragged. The desktop app opens `X.wiff.scan` or `X.wiff` from the system and takes the companion from the same folder by itself (`plan_from_paths` in `opening.rs`, `docs/agenti/rust-desktop.md`): technical limit of the site, not a parity gap.
