# "Fragmentation graph" tab of the MSn infusion (view)
Interface of the `msngrafo/1` graph (contract and engine: `msn-grafo.md`). JS is interface only: formulas, ppm, filters and the export texts come from the engine. Test: `tests_e2e/e2e_infusione_grafo.py` (engine answers simulated with `tests_e2e/fixtures/msngrafo_esempio.json` until the routes are in the site).
- **Appearance**: `gra` tab of the Bench drawer (`barra.js`, `banco.js`), visible only with ONE loaded file that is an infusion (`INF.single()`). ES modules loaded by `banco.js` on first opening (`carica("m:infusione-grafo.js")`); `window.INFG = { render, G }`.
- **State** (`infusione-grafo-stato.js`): `G` (text, chosen molecule with its `id`, adduct, SMILES, settings, `scelte`, answer `j`, chosen node). `params(k)`/`query(k)` build the `api/msn_grafo` request: `formula`, `smiles`, `ppm_formula`, `mz_basso`, `ppm_basso`, `prove_min`, `attivazione`, `isotopi`, `scelte` (JSON) plus `k`, `tol`, `ce` of the precursor tree. Defaults taken from `opzioni` of the first answer.
- **Field** (`infusione-grafo-campo.js`): text with a charge or parentheses is passed as is; otherwise formula + chosen adduct (text concatenation). The `#ig-ion` field holds only the formula (the adduct is in its own menu) and next to it `#ig-ionfmt` shows a preview with subscripts and the charge as a superscript (`formulaHtml`); the `#ig-sum` line ("Ion …, theoretical m/z …") uses the same rendering too.
- **Field, molecules**: above the field is the search in the molecule database (`molecole-campo.js`, `docs/agenti/molecules.md`): choosing a molecule writes the formula into the field (adduct `[M+H]+` if the molecule has no suitable one) and carries SMILES and `id`.
- **Molecule name**: the displayed name has its first letter capitalised (`nomeMaiuscolo`, `infusione-grafo-nome.js`, `etichetta` option of the field; the saved name does not change; names with a digit, Greek letter, parenthesis or a short lowercase prefix before the hyphen stay as they are: "p-", "tert-", "cis-"); retyping the formula by hand forgets the molecule. Adducts by file polarity: + `[M+H]+ [M+Na]+ [M+NH4]+ [M+K]+`, − `[M-H]- [M+HCOO]- [M+Cl]- [M+CH3COO]-`.
- **Graph** (`infusione-grafo-svg.js`, thin adapter): passes the tab state and the drawings to `drawVista` of `msngrafo-vista.js` (pure module, `// @ts-check`, no page globals; the Flow uses it too: `drawGraph(host, j, cb, {t, sel, mode})`, tree without filters or drawings). Two views from the `vista` key of `msngrafo/1` (`vistaOf`: without `vista` only the tree with `pos`): tree (columns per MS level, rows `vista.albero`) and radial (rings `vista.radiale`, radius increased until the boxes no longer touch). `ig-*` styles in `infusione-grafo-css.js`.
- **Box and edges**: m/z, % of the base peak (not at the root), MS levels, candidates with ppm and evidence (ambiguous = triangle); common ion = double border and "×N". Edges of the best path solid, the others thin dashed; loss as a formula with subscripts or "Δ x Da" with the compatible formula. The label rule is at the top of the module; subscripts are presentation only (tspan, `<sub>`, Unicode in tooltips), aria-label and "Copy data" are ASCII.
- **Keyboard**: tree ←→ columns, ↑↓ within the column; radial → best child, ← parent, ↑↓ along the ring; Enter opens the `msn:<id>` spectrum in the active cell, Esc turns it off. Zoom and pan with buttons.
- **Node** (`infusione-grafo-nodo.js`): candidate table with "Use" (new request with `scelte`), isolation window (note "isotopes not expected" if `stretto`), `non_spiegati`, node warnings and the fragment box: "Draw" opens Drawing (`TPDraw.load`), "Save drawing" saves SMILES and SVG (`TPDraw`) in `localStorage` `mzlab.infg.frag`; the broken bond is a user hypothesis. With a SMILES, `infusione-grafo-rotture.js` adds the structure's breaks (key `rotture`) to the panel as evidence.
- **Node activation**: under the candidates `activationLine` lists activation (CID/HCD, from `misure[].att`) and energy (`ce`) of the spectra where the ion appears, from the edges ending in the node; it exists even without interpretation (key `msngrafo.act.line`).
- **Structure cuts** (in the fragment box): with a SMILES and a node of level ≥2 it lists the structure's candidate cuts (`fetchStrutture`: the graph request plus `strutture=<id>`, key `strutture` of `msngrafo/1`, `msn-interpreta.md`; no row if the engine answers without the key): `.ig-cuts` table with bond, piece atoms, m/z, ppm, other explained peaks; test: `e2e_infusione_grafo` with `fixtures/msngrafo_strutture.json`.
- **"Show" of a cut** (keyboard, 28 px): opens Drawing with the SMILES, `TPDraw.mark` selects the bond (atom indices as in the SMILES) and `TPDraw.highlight` colours it as a cut (`cuts`, label `msngrafo.str.ev.label`; evidence colours in `disegno.md`). Test: `e2e_infusione_grafo`.
- **Rules** (`infusione-grafo-regole.js`; the graph request carries `interpreta=1&regole=1`): under the loss of each edge `arcLabel` writes at most 2 rule ids (`(weak)` if priority 3, `+n` for the others, `a + b` for the composite); the node box (`rulesPanel`) lists for each incoming edge the rule, error in mDa, priority, energy, reason for the downgrade (`perche`), sources as DOI links (`https://doi.org/`, `rel=noopener`), note of the sum of two rules, stepped spectrum and global warnings (`warn.msngrafo.radicalLoss`, `belowCutoff`), then the thresholds with `origine` and "to be calibrated".
- **Rules filter and data**: checkbox `#ig-rf` "Only losses with a rule" (`G.rf`, `filtered`): keeps the explained edges, the nodes reached and the roots. The data table and "Copy data" have the columns Rule, Source, Priority (`arcCells`). Keys `msngrafo.rule.*`; e2e `e2e_infusione_regole.py`.
- **Export** (`infusione-grafo-esporta.js`): `api/msn_grafo/export` (`formato` csv|mgf|msp, `pulito`, `nodo`) → `dl()` or clipboard; "Add to library" → POST `api/msnlib/aggiungi` and file `msnlib.json` in OPFS; "Download library".
- **View bar** (`#ig-bar2`, `viewBar`/`syncBar` in `infusione-grafo.js`): "Tree/Radial" (`G.view`, `aria-pressed`, the chosen node stays), "Min %" (`G.minRel`), "Levels" (`G.maxLevel`), "Best path only" (`G.bestOnly`), "Close/Open subtree" (`G.collapsed`, closes the descendants of the best path of the chosen node), "Structures" (`G.structs`, visible only with a molfile); `visible` filters by reachability from the roots.
- **Drawings** (`infusione-grafo-mol.js`): with a SMILES `prepareMolfile` loads OpenChemLib (`ocl()` of `mol-svg.js`, a single load per page) and sets `G.molfile`; `viewUrl` adds `molfile=` and `strutture=tutti` (an unreadable SMILES: retry without cuts). `drawingsOf` draws the root and, for each ion with cuts (`strutture_tutti`), the parent with the `pezzo` atoms of the first cut highlighted (`.ig-hl`, `--grad` plus dashed circle) and the label "hypothesis"; the node box repeats the drawing larger (`.ig-hypo`). `fetchStrutture` reads `strutture_tutti` first.
- **Graph data**: "Data" button (`TDATI.table`) and "Copy data"; same content, columns id, MS levels, m/z, relative %, chosen, candidates, loss, best path, common, isolated, remarks, rule, source, priority (subscripts in the table, ASCII in the copy). Tests: `e2e_infusione_grafo`, `e2e_msngrafo_vista` (80 ions: 0 overlaps, crossings ≤ 50 % of `pos`, axe), `tests/flow_msn_view.js`.
- **Run MSn workflow**: "Run MSn workflow" button next to "Show graph" (`#ig-flow`, `G.auto`): builds the graph with the ion/SMILES in the field and, once drawn, starts the library search by itself (`searchRow(..., auto)`); export and "Add to library" stay in the row below.
- **Search the library** (`infusione-grafo-cerca.js`, below the export): field "Largest precursor difference (Da)" (0 = same precursor only) and button "Search lab library"; reads `msnlib.json` from OPFS (empty = warning) and POSTs `api/msnlib/cerca` with the graph request + `delta_max` (`msnlib.md`). `msncerca/1` table: entry, ion, type (same precursor or analogue with Δ Da), Δ ppm, the three scores MS2/tree/losses kept separate (never merged), evidence and, for analogues, shifted peaks and coverage. They are candidates, not an identification. Test: `e2e_infusione_grafo` (simulated answer).
- **Open a g.json without the raw data** (`infusione-grafo-apri.js`; `e2e_msngrafo_apri`): a `.json` chosen with `#pick`, dropped in the data area (`upload0` in `shell.js` calls `INFGAPRI.take`) or in the tab ("Open a graph file…" button, drop) is recognised from the header (`"formato": "msngrafo/N"`, first 4 KB) and is never opened as data; another `.json` stays "format not recognised".
- **Complete and errors**: without `vista` the page calls the `complete` op of the msngrafo `.wasm` (`msnCompleta`: no `api/` request, no computation in JS). N > 2 → `error.newerFormat`; over 200 MB → `error.msngrafo.tooBig` (size, cap, not opened, reopen the raw data), without reading its text; broken JSON or not `msngrafo/1` → `error.msngrafo.badFile`, with "Details" and "Copy diagnosis" in the loading box (`rep.errs`/`rep.diag`) or in the tab (`mostraErrore`).
- **Read-only window** (`#ig-ro`, modal `<dialog>`, Esc closes; `INFG.renderRo`, `G.ro` = file name; the tab state is restored on closing): same graph and node box, without ion field, settings, export or search; "Use" and opening the spectrum are off with a reason (`msngrafo.file.off`, `.nospec`), no structure cuts; rules and filter apply if `regole` is in the file. In the Flow the `msngrafo/1` report opens by itself (`flow-views-msn.js`).

- **Fullscreen and gestures**: `#ig-stage` encloses message, bars, canvas and node box. The `#ig-fs` button (end of the first bar, `infusione-grafo-schermo.js`) works like `_setMax` of the panels: same icons `IC_FS`/`IC_FSX` and texts `panel.max.*`, class `ig-max` (fixed position like `.pnl.max`), rest of the page `inert`, Esc from the `ESC` registry (prio 50), focus on the button on exit; the node does not move in the DOM, so zoom and selection stay.
- **Gestures on the canvas**: `infusione-grafo-gesti.js` on the canvas (also in the side panel and in the read-only window): wheel without modifiers = pan, Ctrl/Cmd+wheel (the trackpad pinch) and Safari `gesture*` = zoom around the pointer, drag (after 4 px, so a click on an ion still works) = pan, two touches = pinch; `preventDefault` only on the canvas (`overscroll-behavior:contain`, `touch-action:none`). Test: `e2e_infusione_grafo`; names: `tests/test_grafo_nome.py`.

## XIC lens and the infusion data rule
- **"XIC" button and lens off**: if the spectrum file is an infusion (`f.kind === "infusion"` of the engine, rule of `infusion.rs`, or `infus|fia|direct|syringe` in the name) the "XIC" button of the spectrum bar is disabled with the tooltip `xicbtn.infusion` and the lens (`lensArgs` in `xic-spettro.js`) does not open: there is no real chromatogram. Test: `tests_e2e/e2e_xic_infusione.py`; the data rule in `infusion/tests.rs`: MSn cascade up to MS8 with more than 64 keys = infusion; a single key over the whole run (targeted LC MS2) is not.
- **Diagnosis**: `cargo run --release -p mzlab-core --example infusion_diagnosis -- FILE.mzML [FILE2.mzML ...]` prints (one block per file, to paste in chat) scans per level, RT range, MSn keys with scans and RT, CV of the TIC and the verdict of `infusione` with the reason.
- **Experiment menu** (`tipo-file.js`, `TIPOF`): the "Experiment" cell of the start table is a plain select of the types (full, ms2, mrm, infusion) with the detected or chosen one preselected (tooltip = reason, with `msn.chiavi`/512), with no auto/manual distinction; choosing the detected type saves nothing; the choice, saved per file name in `mzlab.filekind`, always wins (`f.manual`, `f.kindAuto`), is applied at once to the table, `E.files` and the XIC button (`TIPOF.viewer`); the select on the group row sets the whole group. Test: `e2e_tipo_file`.

## Drawing traces from the window (decima.js)
- **Module**: `mzlab/web/decima.js` (pure ES module, `// @ts-strict`, in `tools/tipi/moduli.json` and `stretto2.json`): `isSorted` (x never decreasing, cached per array), `windowIdx` (binary search of the interval [x0, x1], no points outside), `amax`/`amin` (maximum and minimum of an interval without spread: `Math.max(...a)` gives `RangeError` beyond ~10^5 values), `m4` (four vertices per pixel column: first, lowest, highest, last), `rangeExtent` and `runsAbove` (maximum and minimum per block of 128 points, cached per array).
- **Use**: `drawLines` (`grafici.js`) loads the module once (`window.DECIMA`), finds the window of each trace with `windowIdx`, computes `traceMax` and the y-axis minimum over the interval, and draws with `m4`: the columns are those of `Math.round(X(x))`, the end of a column is found by doubling jumps and binary search, the extremes are compared as values and `Y(U(s, v))` runs 4 times per column instead of for each point. With an unsorted time axis the point-by-point loop stays.
- **Blocks**: `extent` (y scale of each trace, twice per drawing) reads the whole blocks of the interval with `rangeExtent` and scans only the two ends; the vertical-zoom triangles (peaks beyond the chart) come from `runsAbove`, which skips the blocks with no points above the edge. Same values and same triangles as the point-by-point loop (120 traces of 50 000 scans: `misure-grafici.md`); `clipY` clips the lines without an array per segment.
- **Dense raw traces**: with smoothing off and more than 1.5 points per pixel `drawLines` uses `rawLine` (not `m4`): the maximum of each column, joined by a 1 px line (peaks never lost, no solid band); with fewer points per pixel (zoom) it draws the real points. With smoothing on, `polyline`/`m4` stays. Test: `tests_e2e/e2e_traccia_grezza.py` (fewer than 35% of filled columns on 90 000 noisy points).
- **1 px line**: every line with more than half a point per pixel column in the window (`hairline`, threshold `HAIR` = 0.5; raw or smoothed) is 1 px wide: in the software canvas a 1.25 px stroke on dense noise costs tens of times more (`misure-grafici.md`). Threshold test: `tests/test_decima.py`.
- **Cached copies**: the smoothed version (`smooth`) and the one with negatives set to 0 of a trace depend only on the data: `WeakMap` per array (`SMOOTHED`, `CLIPPED`), so a zoom or a pan does not copy 1M values at every drawing (without cache ~38 ms of `smooth` and ~32 of GC per step). Traces with background or subtraction have new arrays at every drawing and gain nothing.
- **Tests**: `tests/test_decima.py` (`tests/decima_node.mjs`): every window/width/scale (linear, log) of 15 synthetic traces (narrow Gaussians, one-point and three-point peaks, zeros, NaN, negatives, non-uniform and duplicate x, `Float64Array`) gives the same vertices as the point-by-point loop, the maximum and minimum of each column are vertices, `windowIdx` equals the linear search on 10^5 cases, no `RangeError` with 10^6 values; `rangeExtent`, `runsAbove` and `clipY` equal the simple loop (NaN, ties, growing array).
- **Pixel test**: `tests_e2e/e2e_decima.py`: canvas identical at the pixel (`toDataURL`) between `m4` and the point-by-point loop (forced with `isSorted` false) on TIC and XIC of an LR file and an HR file, at full view and three zooms. `TDATI` is not touched (it reads the whole data).
- **G5 `lr` measurements** (4-CPU Xeon 2.3 GHz cloud container, built site, base 4a3b5fb, n = 30, 3 alternating rounds before/after, p50 / p95 ms): XIC 1M zoom before 49-67 / 70-97, after 5.7-6.3 / 7.6-15.5; XIC 1M pan before 50-64 / 64-95, after 6.7-7.1 / 8.8-8.9
- **G5 `lr` measurements (continued)**: XIC 50k zoom 5.7-5.9 / 7.7-8.8 -> 2.8-2.9 / 3.6-4.9, pan 6.3-6.8 / 8.6-10.8 -> 3.8-3.9 / 5.0-5.5; XIC 3k zoom 2.4-2.5 / 3.5-4.8 -> 2.4-2.5 / 3.4-4.5, pan 3.7-4.2 / 5.3-6.4 -> 3.4-3.7 / 4.4-5.4; TIC and spectrum unchanged (4.6 / 6.1-6.9 and 3.3 / 4.4-5.3 of TIC pan, noise between rounds 1-3 ms). G5 criterion (p95 ≤ 8 up to 50k, ≤ 16 at 1M): met in all XIC rows; one round in three of the 1M zoom has p95 15.5 (an isolated tail, p50 5.7).
- **G2 and G6 (2 alternating rounds before/after, p50 / p95 ms)**: G2 XIC of a file 23.2 / 30.4 and 17.7 / 24.1 -> 19.4 / 25.4 and 17.4 / 22.0; G6 arrow 5.7 / 9.1 and 5.3 / 7.0 -> 5.2 / 6.0 and 5.4 / 8.5 (G1 unchanged): no worsening beyond the noise between rounds.
- **Where the remaining time goes (1M, zoom at full view)**: `amax` + `amin` ~7.7 ms per step (three passes over 1M values: maximum, minimum of `traceMax` and minimum of the axis), `m4` ~2 ms, and `keyOf` of `etichette-picchi.js` sums all the values at every drawing (~1 ms; the file is not part of this work).
- **Tried and discarded**: loading the module with `await import()` at every drawing cost 1.5-2 ms of p50 on pan (TIC, XIC 3k): the result is in `window.DECIMA` and `||=` does not wait from the second time.
