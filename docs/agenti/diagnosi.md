# Read-error diagnosis (`mzlab/web/diagnosi.js`)

- A load error of any format has a single shape `{codice, fase, causa, dettagli}`: `codice` = the error key (`err.engine.index`, ...), `fase` = `open|copy|index|decode|write`, `causa` = short `diag.cause.*` key (quota, read, memory, engine, format, decode, unknown), `dettagli` = `{format, size, raw, head}`.
- `lr.js upload()` follows the phase (copy -> index -> open) and puts `fase` and `raw` (the engine's original technical text, <=600 characters) in the `params` of the error reply; `I18N.err` passes them to the `Error` (`e.params`).
- A JS exception in an LR route that exists (`lr.js`, `catch` branch of `handle`) answers `err.load.failed` with `fase: "decode"` and `raw` in the `params`: `DIAG.da` shows its cause and original text. `err.route.unavailable` stays only for a route the engine does not serve (`window.MZLAB_LR_MISS`).
- A scan outside the file (`api/spectra`, `scan`, `scanavg`, `scanbin`, `scaninfo`) is an engine refusal with its own key (`err.scan.outsideN`, `err.scan.outside`, `err.scan.range`, `err.scan.maxRequest`, `err.scan.noneValid`, `err.scan.maxAverage`: `hrscans.rs`), which `rust-scans.js` (`refusal`) passes to the page with status 400 like the desktop; tests `tests_e2e/e2e_scansione_fuori.py` and `a_scan_outside_the_file_is_refused_with_its_reason`.
- `DIAG.da(e, {name,size}, head)` builds the diagnosis; `DIAG.causa` infers it from the raw text (QuotaExceeded, NotReadable, memory, `unreachable`/`panicked` = `engine`: a WASM trap is not the computer's memory, XML/index/zlib...); `DIAG.pulisci` strips disk paths (Windows, Mac, Linux, `file://`); `DIAG.testa` keeps the first lines up to `<spectrumList` (never spectra); `DIAG.leggiTesta(file)` reads the first 8 KB (a vendor file has no header).
- `reportLoad` (shell.js) adds to the error line the short cause (if recognised) and the `DIAG.html` block: a closed "Details" button (`aria-expanded`) with phase, format, size, original error, header and "Copy diagnosis" (`DIAG.testo`: version, code, phase, cause, format, size, error, header; never the file name). Diagnoses are grouped by message like the error lines.
- **Load trace** (`dettagli.trace`, `CONVROWS.trace`): device memory and cores, browser space (`MZLAB_STIMA`), for each row state, %, scans, time, seconds without news, members by extension and size, phases with their times, last worker message; never names (numbered rows; `DIAG.da` also strips the file name from the error). It is in the "Copy diagnosis" of an error and in the "Details" of the row header while loading runs (`cabla` accepts a function).
- Every error key states its cause and carries the values that its text names. `err.module.reply` (`detail`) = reply of the readers module that the engine does not decode (never `err.file.notAccepted`, which stays the file type and always has `name`: `FileSet::not_accepted`); `error.workStopped` (`detail`: `hash`, `order`, `decode`, `detect`) = a worker thread stopped without a result, never `error.memoryBudget`; `err.file.unknown` with `detail=incomplete` = the file gave fewer bytes than its size; a failed mzML write = `err.file.mzmlWrite`.
- The vendor files page (`rust-nativo-pagina.js` `fail`) keeps the engine's refusal with its key; a lost worker or a text without a key becomes the operation key with `name` (the pair's .wiff, the .d folder) and `detail`: `err.file.nativeStopped` for the sample list and the SRM traces, never `err.file.notAccepted`.
- Reads and limits: `err.file.read` (`offset`, `length`) = the source file did not give its bytes (`readat.rs`: `Vec`, `File`, `JsReader` and `JsMember` of the site, `MapAt` of the desktop); index reads (`index_bytes`) stay `error.badIndex`. `error.fixedLimit` (`what`, `limit_mb`, `Error::fixed_limit`) = a fixed cap (`Limits::byte`, mzML region, zlib/numpress arrays, OLE files) that no budget moves; `error.memoryBudget` stays only for memory, the only one that the builders pool retries with fewer workers.
- `tests/test_errori_segnaposti.py` checks that every `Error::new("key")` in the Rust code (tests excluded) fills with `.with` every `{placeholder}` of the it and en text.
- Test it: `tests/test_diagnosi.py` (node: one cause per phase, no personal data, header without data, text to copy; generator variants) and `tests_e2e/e2e_diagnosi.py` (truncated and non-XML mzML, it/en, copy to clipboard).
- `tools/mzml_msconvert_synthetic.py` writes an mzML like msconvert (indexed wrapper with SHA-1, id different from the name, `<sample id="_x0038_" name="">`, Orbitrap Exploris 120) with `--variant` variants and a size of your choice (`--scans`, `--peaks1`, `--peaks2`): to reproduce failures of large files.
- `tools/mzml_diagnosis.py FILE.mzML` looks at a large mzML like the loader, without a browser and without printing data: size, header, wrapper, `indexListOffset`, end of file, number of spectra, full block-wise read, first and last well-formed spectrum, accessions.
- `DIAG.LONG` (long task > 50 ms with the active phase, `marca`/`registra`/`righe`; the observer starts with the page): `DIAG.testo` adds the lines of the longest ones and `DIAG.testoLento(versione, da)` gives the text for a slow page without errors (Tabui, "Copy diagnostics"; `mzfinder.md`). Test: `tests/test_diagnosi.py`.
- `mzlab-cli validate FILE.mzML` says whether an mzML is valid (structure, PSI-MS vocabulary, index offsets and SHA-1) with the XML path of each problem and without printing data; for a file that does not load it is the first check, before `tools/mzml_diagnosis.py` (`cli.md`). The file from `tools/mzml_msconvert_synthetic.py` (variant `base`) is valid, the variants `indice_falso` and `accessione_ignota` are not.
