# Metrics of main (trend over time)
- **Script**: `tools/metriche.py` (standard library only) measures one commit and appends lines to `metriche-YYYY-MM.jsonl` in the directory given by `--dati`; on CI that is a worktree of the branch `stat-ci` (never main). The old `eventi*.jsonl` files of `ci_metrics.py` are not touched.
- **Lines**: `{v, sha, ts (UTC), part, recorded, ...}`, schema version `v` (bump when a field changes meaning). A commit has up to three parts: `site` (`wasm`, `startup`, `tests`, `bench`), `ci` and `manual`; `leggi_commit` merges them by sha, the latest line wins per section (`bench`/`manual` merge by key). Lines are only appended; an identical (sha, part, content) is skipped.
- **`wasm`**: per built module `raw`, `gz`, `br` (`br` is null unless the `brotli` tool is installed), `cap` (the `limit_*` variables, via `tools/ci_wasm_dimensioni.py`), `head_b` and `head_pct` (headroom). Caps are never raised to make a number look better.
- **`startup`**: bytes of the scripts in the list `L` of `carica.js` (raw, gz) against `MAX_TOTAL` of `tests/test_peso_avvio.py`.
- **`tests`**: counts read from the sources, no build and no run: `pytest` (`def test_`, a parametrised test counts once), `cargo` (`#[test]`), `e2e` (`tests_e2e/e2e*.py`).
- **`ci`** (`--ci`, GitHub API via `ci_metrics.api_get`): per workflow wall time, attempts and conclusion; duration of every job and of the required ones; failed and flaky (green only after a re-run) runs; `pr`, open-to-merge time of the PR of the commit; PRs merged in the last 24 h and the median open-to-merge time over the last 7 days. `complete` is false while a run is still going.
- **`bench`/`manual`**: numbers that need no private data come from `--bench FILE.json` (`{name: number}`); benches on private data (for example `bench_mappa.py` on `hrc`) are added by hand: `python3 tools/metriche.py --aggiungi bench_mappa_hrc_first_draw_ms=812 --dati DIR [--sha SHA]`.
- **Tests**: `tests/test_metriche.py` (synthetic files and a fake API).
- **Workflow** (`.github/workflows/metriche.yml`, not a required check): after every completed `pages` or `test` run on a push to main it checks out that commit, takes the `metriche-wasm` artifact of the pages run (built `.wasm`, uploaded by `assemble`), runs `tools/metriche.py --registra --ci` and pushes the lines to `stat-ci`, sparse-checking-out only `metriche-*.jsonl`. Identical content is skipped; a `ci` part with more finished runs wins on read. Failures are warnings, never red.
- **Report**: `python3 tools/metriche.py --rapporto [--dati DIR] [--html FILE]` (`tools/metriche_trend.py`) flattens the merged records into series (wasm totals raw/gz/br and the tightest headroom, start-up bytes and headroom, test counts, CI wall time, slowest required job, failed/flaky runs, PRs merged in 24 h, open-to-merge median, every `bench.*`/`manual.*` number), compares the last value with 7 and 30 days earlier and prints `better`/`worse`/`flat` (`n/a`: history too short; `tracked`: direction unknown, e.g. a name not ending in `_ms`/`_s`/`_mb`/`_b`/`_per_s`).
- **Noise and page**: under 3 % change, or under one run / half a point of headroom, is `flat`. The HTML page has inline SVG sparklines and no script or network; `metriche.yml` writes the table to the job summary and uploads the page as artifact `metriche-rapporto`.
- **Copilot section** (`tools/metriche_copilot.py`, `--copilot`, rows in `copilot-YYYY-MM.jsonl`, latest row of a PR wins): one row per closed PR of Copilot (author `copilot-swe-agent[bot]` or branch `copilot/*`) and of our chat PRs (`claude/*`, the baseline): open-to-merge, open-to-first-green (all required checks), fix rounds (commits after the first), human/Claude commits on Copilot PRs, red required checks, files, lines, merged or closed unmerged, unchanged (merged with only Copilot commits).
- **Copilot safety**: `sensitive` lists touched paths under `.github/`, `tools/`, `Cargo.toml`/`Cargo.lock` and package files; `secret_runs` names the workflows that read a secret (any `secrets.X` but the token) and actually ran on the PR head; `revert_7d`/`followup_7d` count commits on main within 7 days of the merge that mention the PR (rows younger than 7 days are written again).
- **Copilot reviews**: comments by `copilot-pull-request-reviewer`; a comment is accepted when a later commit touched the same file within 3 lines (`touches`), else counted as not accepted (the API cannot tell resolved from ignored). Whether a flagged bug was real is added by hand (`--aggiungi copilot_bug_confirmed=N`).
- **Copilot verdict**: compared with our chat PRs of at most 5 files; fewer than 10 Copilot PRs gives `too few samples yet`; otherwise `worse` if the median open-to-merge is 20 % slower or reverts/follow-ups are more frequent, `better` if 20 % faster, else `same`. Sensitive-path PRs get their own verdict line. `--rapporto` prints the section after the trend table.
