# Tabella delle transizioni di un triplo quadrupolo (`chrom.transitions@1`, `crates/mzlab-feat/src/transitions/`)
Aree vicine: `wiff.md` (canali SIM `SIM SIC Q1=`), `liste.md` (editor `flow/liste`), `cli-passi.md`, `wasm-tetti.md` (`flowtab`).

- Cosa fa: per ogni campione e ogni riga di una tabella di ioni SIM (solo Q1) o transizioni MRM/SRM (Q1>Q3) trova il cromatogramma della riga e integra il picco in RT ± finestra con `mzlab_core::peak1d::find_peak` (`legacy::lr::peak1d` lo riesporta; nessun secondo integratore). Le righe senza RT danno solo candidati, mai un'attribuzione di isomero.
- Tabella = dati, mai codice: un CSV modificabile (parametro `transitions`, `x-liste` = `transitions`), salvato nel piano e nella sessione, modificato dall'editor delle liste (`flow-liste.js`, solo app). Intestazione obbligatoria che comincia con `name`; colonne `name;q1;q3;polarity;rt;rt_window;isomer_group;note;formula;adduct` in qualsiasi ordine (`table.rs`, `HEADER`). `to_csv` riscrive le celle come scritte (`;`).
- Righe: `q1` scritto, oppure calcolato da `formula` + `adduct` con `mzlab_core::elements` (mai un numero nel codice); addotto predefinito `[M+H]+` o `[M-H]-` dalla polarità; polarità vuota = quella dell'addotto, altrimenti `+`. Virgola decimale letta come punto se il separatore non è la virgola. Errori per riga `error.liste.*` (`noName`, `badPolarity`, `badAdduct`, `badMz`, `noMz`, `badFormula`, `badRt`, `twice`, `noHeader`, `badColumn`).
- Canali (`traces.rs`): i cromatogrammi `srm` di `mzmlhead` (anche SIM, `q3` assente) letti con `TracceMzml::cromatogramma`; polarità dal testo dell'id (`polarity=positive|negative`), assente = vale per entrambe. `srm::leggi` e i byte MRM esistenti non cambiano.
- Abbinamento (`text.rs`): Q1 entro `mz_tol` (0,5), Q3 entrambi assenti o entrambi entro `mz_tol`, stessa polarità; vince il più vicino, a pari distanza il primo. Una riga SIM non prende un canale SRM e viceversa.
- Esiti per riga e campione (`peak`): `ok`, `edge` (apice sul primo o ultimo punto della finestra), `no_peak` (sotto `snr_min` o `min_points`), `no_trace` (nessun canale), `no_rt`. Solo `ok` ed `edge` contano in `n_peaks` e nelle medie.
- Uscite (parametro `output`, un solo file per istanza): `peaks` (lunga: campione, riga, apex_rt, area, height, snr, fwhm_s, peak), `table` (una riga per transizione: `area <file>`, `apex_rt <file>`, `n_peaks`, `rt_mean`, `rt_sd`), `candidates` (solo righe senza RT: picchi del canale in tutti i campioni, raggruppati per distanza di RT ≤ `group_rt`, ordinati per area massima; un fianco non è un candidato). Esportazione CSV = il file stesso.
- Preset `example_1` (`data/transitions-example-1.csv`): 14 prodotti di trasformazione da formula + `[M+H]+`, senza RT; si applica solo se scritto (`--set tr.preset=example_1`). Le formule di BQM (C15H12N2O2) e BQD (C15H10N2O3) sono quelle della letteratura dell'ozonazione (m/z 253 e 267). Il nome del composto non compare in codice, id o interfaccia.
- Parità: un solo testo `transitions_text` (CLI `flow_transitions.rs`, `Exec::File`) e `transitions_packed` (browser, `flow_transitions` di `flowtab`, file impacchettati con manifest `[{name,len}]`); `flow-web-transitions.js` blocca con `platform.computer` se una sorgente non è un mzML aperto in Dati o se i file superano 128 MB. Nel browser un `.wiff` va prima esportato in mzML; CLI e app: `convert.mzml` → `chrom.transitions`.
- Prove: `transitions/tests.rs` (canali sintetici come `tools/wiff_sim.py`), `flow_transitions_tests.rs` (`.wiff` SIM → mzML → `flow run`: byte = `transitions_text`, isomeri 2,5/4,0 min, ione negativo, preset e candidati, `transitions_packed` = CLI), `e2e_flow_transitions.py` (browser = `flow run` byte per byte per le tre uscite).
- Tabella SIM di Dati (`simtab::table_text`, `sim-tabella.js`, carta `#simtab`): con file di transizioni aperti (kind `mrm`), ogni canale SIM (transizione di `/api/mrm` senza Q3) di ogni file integrato da `peak1d::find_peak` su tutta la traccia (il picco più alto; lisciatura 3, almeno 3 punti, S/N ≥ 3 come `chrom.transitions@1`). Una riga per canale (Q1 a 0,01, nome, rango nel file), una colonna per campione (nome del file senza `.mzML`), uscita `area` o `apex_rt`; cella vuota = nessun picco; nessun canale SIM = `err.simtab.noChannel` e la carta resta nascosta.
- Tabella SIM, parità: sito `api/simtab?k=..&output=area|apex_rt` (`rust-bridge-info.js`: `mrm` di ogni slot, poi `sim_table` di `mzlab-wasm`), app op `simtab` di `rpc.rs`, CLI `mzlab-cli sim-table FILE... [--set output=area|apex_rt] [--out PATH]` (`sim_table_cmd.rs`: mzML così com'è, file del fornitore da `lettori_mzml::guscio`, nomi dei campioni come `conversione.js::wiffName`; un campione con record oltre la fine del file dà un avviso su stderr e integra i punti prima del taglio). Il CSV scaricato (`sim-table-<uscita>.csv`, riga di provenienza in testa) = l'uscita della CLI.
- Tabella SIM, prove: `simtab.rs` (unitarie), `sim_table_cmd_tests.rs` (`.wiff` `sim3` di `tools/wiff_sim.py`: 7 righe x 3 campioni, apici, `.wiff` = suoi mzML byte per byte, copia tagliata al 60 %), `e2e_sim_wiff.py` (pagina = CLI byte per byte per le due uscite e per il CSV scaricato; copia tagliata).
