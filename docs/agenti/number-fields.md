# Hand-written numeric fields

- `mzlab/web/campi.js` (`CAMPI`, loaded right after `ordine.js`): capturing listeners on the document for every `<input type=number>` and every text field with `data-num`. A rejected `change` does not reach the field's handler (neither state nor a request); an invalid keyboard `input` stops the live handlers; `submit` (Enter in a form) with an invalid field is blocked.
- Rules in `data-num`, separated by spaces: `a:b` limits (either may be missing), `>a` exclusive lower limit, `i` integer, `v` empty allowed, `a` at the end the word "auto" allowed, `<=ID` / `>=ID` at most / at least the field `#ID` ("from / to" pairs). Without `data-num`, `min`/`max` apply and empty is allowed; with `data-num` without `v`, empty is rejected.
- `CAMPI.num(t)`: decimal comma or point (only one of the two, once), sign (also U+2212), exponent; letters, "12abc", "1,2.3", 1e999 → NaN; empty → null. `numIt` (ordine.js) stays tolerant (a unit after the number is ignored) but never gives Infinity. `CAMPI.spec` reads the rules, `CAMPI.why` gives the rejection text or "".
- Rejection: the value the field had before the first key of the edit comes back (`beforeinput`, so a value set by code also counts), `aria-invalid=true`, a synthetic `input` only if a valid key of the edit had already reached the live views, and a calm note (`role=status`, `aria-live=polite`, text set after 20 ms so that every rejection is read, removed after 6 s): in a panel below the header (`.xr-msg`, inside `.cpop`/`.sp-pop`), elsewhere after the label (`.campo-msg`). Texts `campo.num|empty|int|gt|range|min|max|order` in `lang/*/ctl.js`.
- Covered fields: panel headers (range, background stretch, SNIP, delays, background zone, spectrum threshold and labels, peak table, map), Settings/LLM, and the calculators: composition drawer and window (`elementare-pannello.js`, `composizione.js`, element table in `elementare.js`, read on `change`), "calculate here" (`calc-qui-html.js`), KMD (`kmd.js`), recalibration (`masscal.js`), origin of an ion (`origine.js`). All text fields, so "250,8" is accepted in every browser language; `inputmode=decimal` and `autocomplete=off` set on `focusin`.
- HR bench (`banco.js`): isotopic profile (charges, points, resolution, concentration), "XIC from formula" (ppm, minimum intensity), new XIC trace (ppm). Subtraction (`sottrazione.js`): m/z of the internal standard and RT tolerance. Fields read with `numIt`, so "2,5" means 2.5.
- Statistics: blank subtraction (`bianco.js`: factor, integer minimum of detections), difference from the reference (`riferimento-corpo.js`: factor, minimum, pseudocount number or "auto", threshold), PCA (`pca.js`: minimum intensity, integer minimum samples), PFAS (`pfas.js`: MS1 and MS2 ppm above 0, relative intensity 0-100), profile over time (`profilo.js`: RT). QA/QC (`qaqc.js`): RT of the ion and of the ratio, window above 0. A rejected field blocks its module.
- Tools: peak parameters (`picchi.js`, rules by key in `peakParams`), m/z of the contaminant rows and ± tolerance of the lists (`liste.js`), ppm and S/N of the target screening (`liste-target.js`), library search (`libreria-corpo.js`, `libreria-finestra.js`: precursor, tolerances, thresholds of "What is it?"; Enter does `blur` first so that the rejected field does not start the search), fragmentation graph (`infusione-grafo.js`, `infusione-grafo-cerca.js`: integer Δ 0-500, minimum intensity 0-100, settings). Fields read with `numIt`.
- List and map: m/z and RT filters of the MSn list (`msn-elenco.js`, empty allowed), 3D map threshold (`mappa3d.js`).
- Outside `data-num`, with their own check: "from / to" pairs of the headers and λ of the events (`xic-bordi.js`), 3D map range (`m3d.err.range`), baseline points (`integra-base.js`, note in `#ib-msg`), time and concentration of the samples (`shell.js`, `ruoli-celle.js`, `samples-table.js`: `parseDecimal`, negative time only for the dark), user columns (`columns-samples.js`, type chosen by the user). Free text, not numbers: XIC row (name, formula or m/z), "calculate here", loss search, adduct Δ (read by the engine).
- The "from / to" pairs of the headers (`xic-bordi.js`) use `CAMPI.num` and `CAMPI.note` with their own order rules. Tests: `tests_e2e/lib_campi.py` (`sweep`: in every visible field letters, 1e999, "12abc", "1,2.3", empty, out of limit, decimal where an integer is needed, "from" above "to"; note, previous value, `aria-invalid`, unchanged state), used by `e2e_campi_garbage.py`, `e2e_calcolatori_garbage.py`, `e2e_banco_garbage.py` and `e2e_analisi_garbage.py`, `e2e_strumenti_garbage.py`; no request with NaN/Infinity/undefined.
