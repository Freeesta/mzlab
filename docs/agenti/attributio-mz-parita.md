# MZ track: parity with mzmine, baseline, smoothing and local-maximum
Continuation of `attributio-mz.md`: mzmine 3.9.0 and 4.10 in the cloud, parameter names, golden data, `arpls.rs`, `smooth.rs`, `localmax.rs`, 4.10 outcome per stage.

- **mzmine 3.9.0 in the cloud**: `tools/bench/corri_mzmine.py::installa_39()` downloads the bioconda package (sha256 checked) and Adoptium's OpenJDK 20 into `~/.cache/mzlab/mzmine39` (`MZMINE39_DIR` to change it) and does not download again if they are already there; `run_batch` launches `bin/MZmine -b` without an interface. `batch_xml(..., fasi=DIR, isotopi=bool)` also exports the lists after each stage (`adap|risolutore|join|riempimento_<list>.csv`) and, with `isotopi`, stops the batch after the isotope grouping.
- **Parameter names**: mzmine silently ignores a parameter whose name does not exist and its log never lists the applied values; `parametri_non_letti(xml, mzmine)` looks up the names of each step in the module's parameter classes (and the packages above) and returns the unknown ones. The benchmark batch gave the resolver "Minimum scans (data points)", which does not exist: the real name is "Min # of data points", and the comparison with mzmine ran with the resolver's default value.
- **Golden data** (`tests/data/untargeted/mzmine39/`, full provenance and batch in its `LEGGIMI.md`): `python3 tools/bench/oro_mzmine.py --oro` writes `adap.csv`, `resolved.csv`, `aligned.csv`, `gapfilled.csv`, `isotopes.csv` from 4 synthetic mzML (`--genera DIR` rewrites them with the same content: fixed seed, content sha256 in `LEGGIMI.md`, with every array decoded and rounded to 6 significant digits, because neither the zlib bytes nor the last bits of the floats are equal on every machine; they are not in the repository).
- **mzmine 4.10 reference**: the 4.10.90 golden data (the only 4.10.x with the new "Isotopic peaks finder") are in `tests/data/untargeted/mzmine410/` (six CSVs plus `adap_asse.csv` and `adap_scansioni.csv` from `oro_scansioni.py --dest`), generated on Federico's Mac with `tools/bench/oro_mzmine410.py` and not by CI (mzmine 4.x in batch wants a logged-in user, `.mzuser` with `-u`); without the folder the `untargeted_*_410.rs` tests declare SKIP.
- **arPLS baseline** (`untargeted/arpls.rs`, from mzmine 4.10.90's `ArplsBaseline`): `baseline`, `correct` (= max(y−z,0)), `correct_excluding_peaks` (peaks found with `resolve::regions`, fixed mzmine parameters, linear bridge between anchors, edge adjustment like `adjustStartAndEnd`); lambda 1e5, max 50 iterations, stop 1e-6; numpy reference `tools/arpls_reference.py` → `tests/data/untargeted/arpls/casi.json` (tolerance 1e-9 of the series scale), test `untargeted_arpls`.
- **Baseline**: OPTIONAL step before the resolver (recipe `"baseline"`: `true` or `{lambda, max_iter, exclude_peaks}`), off: the 4.10.90 golden data does not apply it.
- **Smoothing** (`untargeted/smooth.rs`): `Method::{None,Gaussian,SavitzkyGolay}`, odd window ≥3 (even → +1), segments `[min,max)` separated by m/z jumps, window truncated at the edges without renormalizing, SG ≥0; used only for maxima and valleys, test `untargeted_smooth`.
- **Local-maximum detector** (`untargeted/localmax.rs`, from mzmine 4.10.90's `LocalMaxMassDetector`; not yet in the pipeline, which starts from centroid scans): `detect(mz, y, &Params)`; segments closed by a jump ≥ the spectrum's maximum m/z step (on a uniform grid every point is a segment, as in mzmine), maxima and valleys on the smoothed series, 0.7 rule with the active peak, centroid and height/area on the raw data; numpy reference `tools/localmax_reference.py` → `tests/data/untargeted/localmax/casi.json`, test `untargeted_localmax`.
- **4.10 outcome per stage** (tests `untargeted_*_410.rs`): all stages equal to the 4.10.90 golden data: ADAP (also the intervals), resolver, join, gap filling, final table (52/52 cells, areas included), isotopes and finder (charge and peaks, 49/49 rows). The resolver follows 4.10's `adjustStartAndEnd` (the zero next to the edge is included: one more scan per side) with `MinParams::adjust_edges`: off in `MinParams::default()` (3.9.0, 3.9.0 tests), on in `UntParams::default()` (the product), can be turned off with `"resolve": {"adjust_edges": false}`.
- **Other known differences 3.9.0 → 4.10** (from the source): the centroid detector no longer has "Detect isotope signals below noise level"; the 4.10 mzML parser does not read the TIC chromatogram of our files (the script removes it); the isotope finder writes the pattern on the feature without removing rows and does not export the m/z of the peaks.
- **Content of the synthetics**: isolated peaks, two pairs that touch (valley at 40 % and at 70 %), a trace with a one-zero gap, a long background trace with a peak on top, isotopic pairs z=1 and z=2, drift of ±0.05 min between files and a missing peak in one file.
