# Folders in the Data view
Two functions of the landing box (`#start`, in the middle of the work area when no file is open); both go through `upload()` (`index.html`).

- **Upload a folder** (once, not remembered): `cartella-carica.js`, object `CartCarica`. Hidden input `#pickdir` (`webkitdirectory`), opened by the `#cartpick` icon only where `showDirectoryPicker` is missing, or a folder dropped on `#drop` (`webkitGetAsEntry` taken inside the event, recursive reading in blocks). `.mzML`, `.mzXML`, `.dam`, `.raw`, `.wiff`, `.wiff.scan` pass (no hidden files).
- **Agilent folders**: `.D` folders (`AgilentD.group`, extension and `AcqData` case-insensitive: one run = one sample) and method folders `*.m` outside any `.D` (`AgilentD.groupMethods`: the files stay in `AgilentD.held`, `#cartinfo` says "Agilent method "name" (.m) recognised", not "ignored"); the others are counted in `#cartinfo` ("N files ignored").
- **No compatible file**: the message lists all accepted formats. Tests: `tests/test_agilent_d.py`, `e2e_cartella`.
  `CartCarica.dir` gives the folder of the file: `.wiff` and `.wiff.scan` pair only in the same folder (`pairKey` in `wiffToMzml`); two same-named pairs without a folder in the same upload (loose files from two folders) do not open, error `load.wiffTwin` (`tests/wiff_pair_node.cjs`); two same-named mzML files from different folders take the folder name. Tests: `tests/test_cartella_carica.py`, `e2e_cartella`.
- **Pointed and remembered folder**: `cartella-puntata.js`, object `CartPunt`, in the row under the drop zone of the landing (`#start`, hidden on phones): the `#cartpick` icon ("Open folder", top right) picks the folder and the grey list lives in `#cartbody`. A folder is pointed ONCE (`showDirectoryPicker`, mode `read`); the handle is stored in IndexedDB `qqq_lab`, store `kv`, key `cartella.puntata` (opened with `lab()` of `qqq-db.js`, no schema change).
  On return `queryPermission` runs; if the browser requires it, only the "Allow access" button appears, with no sentences before the popup (`requestPermission` needs a click). No byte is copied until a file is opened: `open()` reads `getFile()` and passes it to `upload()`, so OPFS, quota, the per-file Web Lock, the engine budget and the worker recycling (`memoria.md`) stay as usual.
- **Buttons**: each data row not yet loaded has its own "Load" (`.cpone`, loads that file alone) and under the folder row sits "Load all" (`#cartgo`, primary: opens in sequence the data files not yet loaded). **No duplicates**: `upload()` ignores a file with the same name and size as one already in the list or being read (`dropDups`, `INFLIGHT` in `shell.js`): short notice in `#cartinfo` ("already loaded") and the existing row is highlighted (`.dupflash`) for a moment; this holds for a click on the folder, file picking and drag and drop. Test: `e2e_carica_cartella`.
- **Taxonomy** (`kindOf`; the same in `crates/mzlab-desktop/src/folder.rs`): "Data" = `.mzML`, `.raw`, `.wiff` (its `.wiff.scan` in the same folder opens with it and has no row); the list shows only data; `.dam` methods, libraries and `.csv .tsv` tables are collected by `kindOf` but do not appear (they load by drag and drop or from their panels). `.txt` and `.json` (too generic), hidden files and unrecognised files do not appear. Depth 3, at most 3000 files.
- **Refresh**: `FileSystemObserver` if it exists (600 ms debounce after the last event), otherwise a new read every 20 s with the tab visible and on return to the tab (`visibilitychange`, `focus`); `getFile()` only for files never seen (size and date).
- **Without the API** (Safari, Firefox, iPad): the `#cartpick` icon opens the one-off upload (`#pickdir`).
- **Desktop** (`window.MZLAB_DESKTOP`): `cartella-puntata-desktop.js` (`CartPuntDesk`, lazy: `start()` loads it with `carica()` only if `window.MZLAB_DESKTOP`, it is not in the startup list) uses the commands `data_choose_dir`, `data_get_dir`, `data_list`, `data_register`, `data_forget` of `main.rs`; the path stays in `config.json` (`Config.dati`), the page sees names and relative paths (`cartella::resolve` rejects `..` and absolute paths); an opened file is registered like those of the system dialog. No change notification: a new read every 10 s and on return to the window.
- Tests: `tests/test_cartella_puntata.py` (pure parts and desktop side with a fake Tauri), `e2e_cartella_puntata` (a real browser folder in OPFS as handle, persistent context: in the cloud Chromium a throwaway context closes if it reads a saved handle), `cargo test -p mzlab-desktop` (`folder.rs`). Not testable in the cloud: the disk folder picker, `FileSystemObserver` on a disk folder, the Tauri window.
- `.m` methods held back by the folder do not open as data: the Method window shows them with `METODO_M` (`metodo-m.js`, `showHeldMethods` in `eventi.js`).
- **`.D` folder dropped in pieces**: if a drop contains files of a `.D` run (`MSScan.bin`, `MSPeak.bin`, `analysis.tdf`...) but no folder, `CartCarica.fromDrop` shows the `cart.loose` notice in `#cartinfo` and the drop proceeds; the drop area states ".D (folder)" and its `aria-label` says to drag it whole. Test: `e2e_carico_icone`.

## Background warm-up of the pointed folder
After the pointed folder (`CartPunt`, `CartPuntDesk`) is listed, the mzML files are prepared in the background so that the next click is a cache hit. Nothing changes in what the student sees.

### Measured opening cost (site, headless Chromium, synthetic files)
- Folder DROPPED or picked with the dialog: `upload()` copies to OPFS, indexes and fills everything visibly; each file opens as soon as it is read (`OPENNOW`) and the first one shows by itself. Nothing is missing here.
- POINTED folder: the OPFS copy and the index start only on click. Click to file in table: 11 MB 1179 ms cold, 125 ms warm; 40 MB 2443 ms cold, 123 ms warm. The cold cost grows with the MB (reading, OPFS copy, SHA-256/SHA-1, index with the TIC inside the `.mzidx`); when warm only `lr_entry` remains.
- Native `.raw`: ~0.2-0.3 s for 32 MB; `.wiff(+.scan)` and `.D` cannot be measured without real data: they are not warmed (small or unknown gain).

### How it works
- `riscalda.js` (ES module, loaded on demand by `cartella-puntata.js`): queue in list order, one file at a time, only data `.mzML`, duplicate names skipped. It starts when the page is quiet (tab visible, `UPBUSY` zero, no input for 1.5 s). It skips phones, `saveData`, `deviceMemory` < 4, battery < 25 % not charging. Limit: 128 MB on the site (`prepare_upload` is synchronous in the worker), 1 GiB on desktop. Errors are silent, no new text.
- Site: `/api/warm` -> `lr_warm` (`rust-scalda.js`, lazy in the worker) runs `lr_put` + `lr_index` and writes the marker `warm/<name>.json` (size, mtime); `lr_boot` hides files with a marker. Budget: a quarter of the quota with 256 MB of reserve; a real upload evicts the warm files (`makeRoom`).
- Desktop: `lr_warm` (`rpc_warm.rs`) builds the index without a store entry; `lr_boot` skips the warm names.
- On open `upload()` first calls `lr_warm_claim`: if size and mtime match and the index belongs to the file (`index_built_from`: size and probe) it skips copy and index (same bytes as the cold open), otherwise the normal path. A click on a queued file removes it from the queue (`claim`) or waits for the running one: work is never doubled.
- `forget()` of the folder stops the queue; `lr_clear`, `lr_remove` delete the warm files.

### Warm-up tests
`tests/test_riscalda.py` (queue, order, pauses, limits, errors), `e2e_riscalda` (order, hidden after reload, hit with no load phase, same index SHA-256 and same TIC cold and warm), `cargo test -p mzlab-desktop --test rpc`.
Known limits: work in progress on another file is not cancelled (it finishes silently); the warm files of a forgotten folder stay hidden and evictable.
- **Folder datasets in «Open folder»** (English, new): `collect` lists a `*.d`/`*.D` folder (Agilent, Bruker) and a `*.raw` folder holding `_FUNC001.DAT` (Waters) as ONE data row each (`bundle`: `d` / `waters-raw`), never entered; a `*.raw` folder without `_FUNC001.DAT` is only a folder.
  - A click walks the handle with `CartCarica.entryOfHandle` through the same `cartWalkEntries` and `CartCarica.load` as a dropped folder (`fromHandle`): grouping, Bruker, the incomplete-`.D` notice (files received) and naming are one code path; the row counts as loaded by its mzML name (`listName`).
  - Without the API (Safari, Firefox) the one-time `#pickdir` input already goes through `load`.
  - Desktop and CLI: the one scan `mzlab_cli::folder_cmd` (`mzlab-cli folder list DIR --json`, `folder/1`, exit 4 if DIR is missing); the app opens a bundle row as a stub of the folder, like a dropped one.
  - Tests: `tests/test_cartella_puntata_d.py` (page list == CLI list on one tree; a pointed `.D` walks like a dropped one), `e2e_cartella_puntata_d` (needs the site and wasm). No wasm change: the wasm cannot read a directory handle, so the page scan is JS, proved equal to the Rust scan by that test.
