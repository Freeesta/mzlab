# Liste dell'utente (`liste/1`, `crates/mzlab-feat/src/liste/`)
Aree vicine: `mzfinder-ingresso.md` (la lista di trasformazioni di mzFinder), `rust-flow.md` (`prov/1`).

- Tre tipi: `transformations` (nome, cambiamento di formula, ripetizioni massime 1-10 o il predefinito delle regole, commento), `adducts` (nome, cambiamento di formula, carica ±1…3) e `suspects` (nome, formula neutra e/o massa monoisotopica). Schema `docs/schemi/liste-1.json`.
- `from_csv(kind, testo)`: separatore `;` (o tabulazione o virgola se l'intestazione non ha `;`), righe vuote e `#` saltate, campi fra virgolette doppie; l'intestazione dà le colonne (`name`, `delta`, `max_repeat`, `charge`, `formula`, `mass`, `comment`, in qualsiasi ordine). Ogni riga sbagliata dà un `RowError` (riga, `error.liste.*`, testo) e la lista è rifiutata se ce n'è una; `errors_json` li scrive.
- `to_json`/`from_json`: JSON canonico (chiavi in ordine alfabetico, elementi ordinati per nome e cambiamento), stessi byte per ogni ordine delle righe e per il giro CSV → JSON → lista → JSON; `Liste::digest()` è lo SHA-256 che entra in `prov/1`.
- La lista di mzFinder (`nome;cambiamento[;commento]` per riga) è la forma senza intestazione dello stesso CSV: `from_legacy_text` e `Liste::transformation_rows` la fanno passare da qui prima di `legacy::transf::merge`, con le stesse righe e gli stessi errori; `ripetizioni_max` diventa `passi_max` della regola nuova (2 se manca), quindi la lista predefinita dà le regole di prima. Prove: `tests/liste.rs`, `tests/legacy_transf.rs`.
