# Library of MSn trees of the standards (`msn-lib/1`)
Second part of the project in `docs/agenti/msn-graph.md` (graph `msn-graph/1`, PR plan in §9 of that file). Done: format, `mzlab-cli msn-lib add|build|export`, `msn-graph compare`, the Flow steps `msn.library_export` / `msn.table_export` (`rust-flow.md`), the tree search (§2: `msn-lib search`, `mzlab_core::msngraph::cerca`) and the analogues with the route `msnlib/search`; the page panel is in `infusion-graph.md`.
Goal: measure in the lab the MSn trees of the available standards (the idea of spectral trees, but open and our own) and search them for unknown ions.
## 1. Format
- **File**: a JSON document `msn-lib/1` (`*.msnlib.json`, schema `docs/schemi/msn-lib-1.json`, tested by `tests/test_msnlib_schema.py` on the library from `msn-lib build`), written `{"schema":"msn-lib/1","entries":[...]}` by `msngraph::aggiungi`; entries sorted by `id`, then ion, then activation: deterministic like `msn-graph/1`. A library of 1000 standards with 4 levels takes a few tens of MB: compress it separately (zstd like `.mzlib`) only if needed.
- **Entry** (one standard in ONE condition: ion + polarity + activation): `{id, ion {formula, theoretical_mz, polarity}, activation [..], graph}`, `id` being the lab code (`STD-0001`; the name and synonyms stay private until there is the "go-ahead"). `graph` is the whole `msn-graph/1` of the measurement, with the ion formula given: the fragment formulas stay "proposed".
- **Not in the format yet**: standard, instrument, source and infusion metadata (supplier, lot, purity, solvent, additive, flow, instrument model and resolution, operator, date, raw-file hashes, validation) are not part of `msn-lib/1` yet: a later version adds them as new keys, and the manifest columns below already carry them.
- **Link with today's spectral libraries**: `mzlab-cli msn-lib export` writes the MS2 spectra (with `--all` every level, with `--clean` only the peaks explained by a node) as MSP, with `--format massbank` as MassBank `.txt` records (`MS_TYPE MS2/MS3…`, precursor path in the comment, `export` in `crates/mzlab-cli/src/msn_lib.rs`); the `.mzlib` builder (MS2 only, `docs/agenti/libraries.md`) indexes them and today's search (entropy, cosine) finds them with no new code. The precedent is `unito-standard` (UniTO record, CC BY). The complete tree stays in the `msn-lib/1`.
- **Annotations and Flow**: with `--annotate` every explained peak carries the proposed formula and the neutral loss from the precursor (MSP: note between quotes; MassBank: `PK$ANNOTATION` and a `COMMENT`); the steps `msn.library_export` and `msn.table_export` (`rust-flow.md`) write the same bytes from a graph, without going through the library.
## 2. Search (an unknown ion → similar trees)
- Filter on the precursor (ppm, same polarity and compatible adduct), then three scores, all as candidates with evidence and never as truth: (1) MS2: weighted entropy (`mzlab-lib::scores`) against the entry at the same activation and the nearest energy; (2) tree: for the unknown's isolated nodes (if it has MSn) the entropy of the nodes aligned by precursor path (m/z within ppm), averaged weighted by the intensity of the isolated fragment; (3) losses: fraction of the unknown's losses that the entry has (by formula if both have one, otherwise by mass).
- **Analogues**: an equal subtree with the root shifted by Δ (the same "shifted/unshifted" idea as `finder_base/msn/localize.rs`) flags an entry as an analogue, with Δ and the shifted fragments: useful for TPs (a change on the parent shifts only the fragments that contain it).
- **Done**: `mzlab_core::msngraph::cerca(library, ignoto, &OpzioniCerca)` (`msn-lib/1` text + `msn-graph/1` text → `msn-search/1` text; `crates/mzlab-core/src/msngraph/search.rs`) and `mzlab-cli msn-lib search LIB.json GRAPH.json [--ppm 10] [--tol 0.01] [--min-evidence 1] [--top 10] [--out PATH]`. The filter keeps the entries of the same polarity whose precursor (graph root) is within `precursor_ppm`, and the entries with at least `min_evidence` shared peaks in the best MS2 pair.
- **Candidate** (`msn-search/1`): `{id, ion, att, delta_ppm, scores{ms2, tree, losses}, proofs{common_peaks, aligned_nodes, unknown_nodes, common_losses, unknown_losses}, analog}` with the three scores in 0..1 always kept separate (null if the unknown has no MSn or edges); order: tree, then MS2, then losses, then `id`; never a verdict. Tree alignment: same precursor path without the energies, same activation and precursor within `tol`; weight = relative intensity of the isolated ion in the spectrum above.
- **Equal energy**: if the same ion is reached with different energies upstream, at equal energy distance the most similar spectrum is taken, so that a tree finds itself (tree = 1).
- **Analogues searched**: `analog` is null for exact entries, otherwise `{delta_da, shifted, unshifted, coverage}`; they are searched with `delta_max` > 0 (`--delta N`, Da): entries with the precursor farther than `precursor_ppm` and at most `delta_max` away, in the best MS2 pair each peak of the unknown is "unshifted" (m/z of a peak of the entry) or "shifted" (m/z of the entry + Δ, Δ = unknown − entry); at least 1 shifted and `min_evidence` peaks are needed; they come after the exact entries, by decreasing coverage (explained intensity).
- Test: `msngraph::tests_search` (synthetic graphs) and `msn_lib_tests`.
- **In the Flow**: `spectra.match` with `algorithm=tree` writes `msn-search/1` or, with `tree_output=candidates`, the `candidates/1` that `annot.level` reads (`rust-flow.md`).
- **Route**: POST `api/msnlib/search` (`rust-routes.md`), in the `.wasm` `msngrafo` (`msnlib_search`); test in `tests_e2e/e2e_msngrafo.py`.
- **Evidence for Attributio**: `cerca_ms2` (`msngraph/search.rs`) compares the MS2 of a row (peaks and precursor m/z, without activation: every MS2 of the entry counts) with the entries of the same polarity within 10 ppm; `evid::msntree::msn_tree_hits` turns them into `ExternalHit`s "MSn tree of a reference" (score = entropy, at least 3 shared peaks) that shift the order of the candidates without giving the level. It is not yet wired to `proofs.rs` or to the `.wasm`.
## 3. Acquisition protocol (Orbitrap, direct infusion)
- **Solution**: 0.1-1 µg/mL (≈ 0.5-5 µM) in MeOH/H2O 50:50 with 0.1 % formic acid (ESI+) or 5 mM ammonium acetate (ESI−); syringe at 3-5 µL/min; stable spray before the MSn (MS1 TIC with RSD < 15 % over 1 min).
- **MS1**: 1 min at 120 000 (m/z 200): check of the expected ion, adducts and in-source fragments (noted in the manifest).
- **Levels**: MS2 always; MS3 on the 3-5 most intense MS2 fragments (≥ 10 % of the base peak); MS4 on the 2-3 most intense of each MS3; deeper only if the isolated ion is still above ~m/z 80 and the spectrum has at least 3 fragments. Isolation 1.0-1.5 m/z (2 at levels ≥ 3 if the signal is weak, noting it).
- **Energies**: MS2 in CID (trap, activation Q 0.25, 10 ms) at NCE 20, 30, 40 and in HCD at NCE 15, 30, 45 (separate events, not "stepped": the graph keeps one measurement per energy); MSn in CID at NCE 30 (plus 20 and 40 if the instrument has time); a single activation per event, written in the filter.
- **Scans**: ≥ 20 per node (the consensus wants the peak in half of the scans: with 20, 10 are enough), MSn at 30 000; AGC and maximum injection time automatic, noted.
- **File name**: `STD-<id>_<instrument>_<pol>_<activation>-<energies>_MS<n>_<YYYYMMDD>_d<day>.raw` (e.g. `STD-0042_Orbitrap_pos_CID-20-30-40_MS4_20261021_d1.raw`); the blank `BLK_<instrument>_<pol>_<YYYYMMDD>_<n>.raw`.
- **Controls**: solvent blank with the same method before every standard (the blank's ions within 5 ppm are flagged in the entry, not removed); blank after the standard (carryover); second day with a fresh solution and the same method (`d2`) for validation.
- **Manifest** (`manifest.tsv` per session, fixed columns, one row per file): `id, name, neutral_formula, smiles, inchikey, supplier, lot, purity, solvent, additive, conc_ug_ml, flow_ul_min, polarity, expected_adduct, instrument, method, activation, energies, levels, file, sha256, day, operator, date, notes`. The manifest is the input of `mzlab-cli msn-lib add`.
## 4. Data handling, engine and validation
- **Where**: raw files in `dati/HRMS/standard_msn/<AAAA>/<id>/` of mzlab-dati with the manifest; library built in `librerie/msnlib/` of the same repository by the CLI (never by hand). In the public repo only format, code and synthetic files; no compound name, raw file or entry until Federico gives the explicit "go-ahead"; after the "go-ahead" a public subset like `unito-standard` (license to be decided).
- **What the engine needs**: the corrected Thermo reader for scan events with 3+ reactions and the CID/HCD label per scan (Mac chat); the energy and activation of each stage from the filter (already in `msnalbero`); `msngrafo` (PR 1-3); `msn-lib add/build/export` (PR 6).
- **Validation of a tree**: two days (`d1`, `d2`) → two graphs with the same options → `msn-graph compare`: same isolated nodes (precursor paths within ppm), edges with `rel` ≥ 10 % present in both, same proposed formulas, MS2 entropy ≥ 0.8 per energy, m/z deviation ≤ 3 ppm after calibration. Outcome and numbers in `convalida`; an entry that is not validated stays in the library with `convalida: null` and the search says so.
- **`msn-graph compare A.json B.json`** (`crates/mzlab-cli/src/msn_graph_compare.rs`): JSON `msn-compare/1` with the numbers of each criterion and `validated`; pairing window 5 ppm; an isolated node is the same if they have the same path labels (rounded) and the precise m/z within the ppm; maximum deviation over the paired nodes.

Step-by-step use (command line and Flow steps): `msn-manual.md`.
