# Command line (`crates/mzlab-cli`)
Part of the Rust engine (`rust.md`). Native binary `mzlab-cli` (never in the site; `mzlab` is the app's binary). Plans and `prov/1`: `rust-flow.md`; `step/1` descriptors: `rust-step.md`; canvas: `flow-graphics.md`.

- `mzlab-cli features FILE... [--out PATH] [--preset auto|pos|neg | --params FILE.json] [--help]`: runs the same engine as the page on the files (several files = a series, in the given order; index, peaks and weak candidates per file on a thread pool: `par.rs`, `MZLAB_PHASES=1`: seconds per phase) and writes the aligned feature table as CSV. Each command is an entry in `src/cmd/<family>.rs`: `execute` of `src/lib.rs` looks it up and `--help` comes from the table.
- Inputs: a `.mzML` goes through the scan table (`upload::prepare` + `mzidx::build_mzml_spill`); every other single file the app reads (`.raw`, mzXML, `.cdf`, ...) goes through the registry reader (`mzlab_lettori::apri`, `upload::index_reader`). Multi-file sets (`.wiff` + `.wiff.scan`, `.D` or `.raw` folders) are not accepted. Indexes go in a temp folder.
- Parameters: the same source as the Pipeline panel. The JSON text (`--params FILE.json`; keys `polarity`, `mode`, `floor`, `min_height`, `min_points`, `ppm`, `rt_tol`, `fill`) goes to `run::recipe_for`, which picks the recipe suited to the first file as the site does. `--preset` names `{"polarity":1}` (pos), `{"polarity":-1}` (neg) or no text (auto, default); preset and parameter file together are an error.
- Steps: `run::detect` per file, `run::read_files`, `run::align` (alignment and filling), then `mzlab_ops::run::table::core::table_file(.., "full")`: the mzmine "full" CSV that the page downloads (`export::csv_full`), samples proposed from the file names (`samples/1`), no view.
- Output: `--out` with a `.csv` path writes there, with a folder writes `features.csv`, without `--out` it goes to stdout. Progress and errors on stderr; code 2 for usage, read or stdout error.
- `mzlab-cli samples vars [--names FILE|-] [--pos N [--sep CHARS]] [--has a,b [--substring]]`, `samples table [--names FILE|- | FILE...]` and `samples group NAME...` (`samples_cmd.rs`, tests in `samples_cmd_tests.rs`): the `samples` routes `variables`, `propose` (`samples/1`) and `group_name` on the same names, same bytes as the page; `samples.md`.
- `mzlab-cli samples list FILE... [--json] [--probe]` (`samples_cmd.rs`, `tests/test_samples_list_parita.py`): what each file holds, sample by sample (`samples_list/1`), from the container and index alone, same bytes as the page's `native_samples`; exit 0 ok, 1 refused (or a cut `.wiff.scan` with `--probe`), 2 usage, 4 missing input; `wiff-sample-choice.md`.
- `--sample LIST` (`1,3,5`, `2-4`) of `convert`, `channels`, `features` and `samples select` (dry run): exit 5 for an unknown id; `sample-flag.md`.
- Old names still accepted as input (never printed, except the last `--help` line): `variabili`, `nome-gruppo`, `--canale`, `--jsonl`, the camelCase `--set` names of `peak-edges`; command aliases are a field of the entry.
- `mzlab-cli peak-edges TRACE.csv|- --at MIN [--ref MIN] [--mrm] [--set ...]` (`peaks_edges_cmd.rs`): the edges of `peakq_lr::lr_edges` (`QUALITA.edges`), JSON or `null`.
- `mzlab-cli peak-auto TRACE.csv|- [--from MIN] [--to MIN] [--set ...]` (`peaks_auto_cmd.rs`): the HR peaks of `peakq_auto::auto_integrate` (areas in counts x s; `--set area_unit=s|min`, `min` = the previous unit); `peak-area` (`peak_area_cmd.rs`): from zero or from a line (the line is held at 0 wherever it would be negative and the JSON has `clamped`, `data-integration.md`). Keys: `data-integration.md`.
- `mzlab-cli peak-auto-lr TRACE.csv|- [--from MIN] [--to MIN] [--set lr_half=.. lr_valley=.. lr_sn=.. lr_min_pts=.. lr_despike=.. lr_split=drop|valley area_unit=s|min]` (`peaks_auto_lr_cmd.rs`): all the low-resolution peaks of `peakq_lrauto::lr_auto_integrate` (`QUALITA.lrAuto`), same bytes.
- `mzlab-cli llm tools [--demo] [--out FILE]` (`llm.rs`, tests in `llm_tools_tests.rs`; catalogue in `mzlab-llm`): the `strumenti/1` catalogue generated from `flow::steps()` and from `executable` (`--demo`: the demo subset); `docs/agenti/llm.md`.
- `mzlab-cli llm replay REG.jsonl --conv CONV.json [--turn N] [--strict]` (`llm.rs`, tests in `llm_replay_tests.rs`, synthetic recordings in `tests/data/llm/`): the normalised events of a turn of an `llmreg/1` recording, one JSON line per event; the turn is the number of `assistant` messages of the conversation; errors = code 2.
- `mzlab-cli llm inspect DIR [--budget N] [--hide-names]` and `mzlab-cli llm params DIR [--answers FILE]` (`llm_facts.rs`, tests in `llm_facts_tests.rs`): the `ispezione/1` and `proposta-param/1` of the mzML files of a folder, the same bytes as the page's "Files" card; `docs/agenti/llm.md`.
- `mzlab-cli llm context RUNDIR [--budget N] [--hide-names]` and `mzlab-cli llm eval CASES_DIR --replay DIR` (`llm_ctx.rs`, tests in `llm_eval_tests.rs`): the `contesto/1` of a run folder and the score of the evaluation cases on the recordings; details in `docs/agenti/llm.md`.
- `mzlab-cli msn-graph FILE.mzML [--formula ION] [...]` (`src/msn_graph.rs`): the `msn-graph/1` graph of an MSn infusion with the options of `msngraph::Opzioni` (`--help`; `--budget-mb N` of the consensuses); `--truth FILE --summary`: one line of numbers against the expected paths. `--structures NODE` (with `--smiles`) adds `structures` (`msn-graph.md` §2). `--figure svg,html[,png]` and `msn-graph figure IN.json`: `msn-manual.md`. Contract in `msn-graph.md` §3 and §6.
- `mzlab-cli msn-lib add LIB FILE.mzML --id ID [msn-graph options] | build MANIFEST.tsv [--dir D] [--out LIB] | export LIB [--clean] [--all] | search LIB GRAPH [--delta N]` (`src/msn_lib.rs`): the `msn-lib/1` library written by `msngraph::aggiungi`, like the route `api/msnlib/add`; `build` reads columns `id, neutral_formula, expected_adduct, file` (optional `smiles, activation`), `export` writes the MS2s (or all levels) as MSP. Contract in `msnlib.md`.
- `mzlab-cli validate FILE.mzML... [--json]` (`validate.rs`, logic in `mzlab_core::mzml_validate`): structure (required elements, `count`, `defaultArrayLength`, m/z in order, `encodedLength`), PSI-MS vocabulary (accession, name, allowed units, required terms of spectrum, chromatogram and array; table `crates/mzlab-core/data/psims-cv.json` from `tools/psims_tabella.py`) and, for `indexedmzML`, offsets, `indexListOffset` and SHA-1 of `fileChecksum`. Same JSON as "Validate mzML" of the site (module `valida`) and of the app (`lr_valida`).
  Output: one line `error|warning XML-PATH code: message` per problem on stdout (with several files each line starts with `FILE: `), the summary of each file on stderr, `--json` = an array with one object per file; exit 0 no errors, 1 errors, 2 usage or unreadable file; warnings (obsolete term, value without unit) do not change the code. Stops at 1000 problems.
- `manual-table` (`shifts=true`: window in the other samples; `auto=true [params=FILE]`: peaks of each file); `peak-split`: window split at the valleys (`transitions.md`).
- `mzlab-cli background FILE [--blank FILE] [--set NAME=VALUE...] [--out PATH]` (`background_cmd.rs`, tests `background_cmd_tests.rs`): the JSON of `api/tic_background` (TIC/BPC without the chemical background, `mzlab_core::ticbg_route::route_files`); `--set` names and algorithm in `tic-background.md`.
- `mzlab-cli match-mz X --tables FILE.json [--set hr=1|mda=N|ppm=N|unit=da|ppm|tol=N|pol=+|-]` (`match_mz_cmd.rs`): the `ricerca/1` of `mzlab_core::search::match_number` (losses, adducts, known contaminants: candidates with their error, never a verdict), same bytes as the site and the app (`lr_ricerca`, step in `parity_routes.rs`); the tables are a JSON `{losses, adducts, contam}`; exit 2 for wrong usage.
- `mzlab-cli ion-pattern FORMULA ADDUCT [--out PATH]` (`ion_pattern_cmd.rs`): the JSON of `api/ion_pattern`, the unit-resolution isotope pattern of an ion (`mzlab_core::ionpattern`); exit 2 for unknown formula, adduct or element.
- `mzlab-cli mol-{label,anal,check,cip,hilite,mech,cut,sel,link}`: etich/1, anal/1, check/1, cip/1, hilite/1, mecc/1, cut/1, sel/1, link/1 (drawing.md); `mol-export MOL`, `mol-search --sub QUERY TARGET...|--db LIST`: sdf/1, sub/1, subdb/1 (mol.md).
- `mzlab-cli channels FILE [--sample ID] [--channel ID [--rt T0[,T1]] [--n N]] [--out PATH]` (`channels_cmd.rs`): the `channels/1` of the file (TIC, BPC, one channel per scan type or precursor, `dd:<level>` beyond 64 precursors, one per SRM transition, `uv:twc`, `an:<i>`) equal to `api/canali`; with `--channel` the trace of the UV/analog channel (`--rt`: UV spectrum of `uv:twc`) equal to `api/chrom?kind=pda`, `api/uvxic`, `api/analog`, `api/uvspec`; vendor files: chromatograms of `guscio` (SIM of the `.wiff`). Model: `data-channels.md`.
  - `--channel uv:auto`: the XWC band proposed from the DAD matrix (`{nm, bw, rt, n}`, like `api/uvpropose`), in the `--rt` window if given.
- `mzlab-cli flow run PLAN.json [--in FILE|FOLDER...] --out FOLDER [--set INSTANCE.PARAMETER=VALUE...] [--workers N] [--budget-mb N] [--dry-run] [--fresh] [--events]` (`flow_run.rs`: arguments, `--set`, inputs, check; `flow_out.rs`: folder and exit code). `--events`: `flowlive/1` events on stdout (`flow-live.md`). `--dry-run` checks plan, `--set` and inputs and prints on stdout the inputs found and the instances in order with the canonical parameters, writing nothing.
- **Alignment memory**: `features.align` and `features.gapfill` use `slabs::align_and_fill_stored` under a `MemBudget`: native RAM/4 divided among the `--workers` (`job_budget_mb`, `share_mb`: min 128 MB), `--budget-mb N` sets it. Filling runs one file per thread (`run::align_to_par`). Paths with the same bytes: `memory`, `slabs` (m/z slices, also in family mode), `refused` (`error.memoryBudget`). `prov/1` and `corsa/1` give for the step `mem_mb` and `via` (`slabs::stima`); only they change with `via`.
- `mzlab-cli normative build --cache DIR --out normative/ [--only ID...] [--update-pins] [--no-resolve] [--allow-large]` (`normative/`, native only): builds the EU and US normative lists from the official sources; exits 0/1 (`stale` list)/2 usage/3 pin/4 too large/5 source/6 file, keys `err.normative.*`; details in `normative.md`.
- An mzML with MS-Numpress arrays opens wherever the CLI asks for a file (`features`, `channels`, Flow index): `flow_pace::build_index_with` sends it to the registry's `mzml-numpress` reader, like `convert`.
- `mzlab-cli convert INPUT... --out FOLDER [...]` (`convert.rs`, `convert_report.rs`): one or more vendor files and folders to mzML with the `convert.mzml` step; options, `--report` and exits in `cli-convert.md`.
- `mzlab-cli flow record RUNDIR --roles ROLES.json [--out FILE]` and `flow verify FILE [--json]` (`flow_mzrun.rs`): the `mzrun/2` record of a run and the check of its fingerprints; see `mzrun.md`, "From the CLI".
- `mzlab-cli flow report RUNDIR [--out FILE]` (`flow_report.rs`): the `corsa/1` of `prov.json` and the `.json` files next to it (members read).
- `mzlab-cli steps [--json] [--id ID[@V]]` (`steps_cmd.rs`): the steps of the registry `flow::steps()` of the binary itself. Without `--json` one line `id@version  native|page  title` (`native` = `flow::executable`); with `--json` the `step/1` array of `registry_json` with `"executable_native"` as the last key of each step; `--id` a single step (with `--json` an object; without `@V` the highest version); unknown step = exit 2 with `err.flow.step.unknown`.
- `mzlab-cli flow check PLAN.json [--set INSTANCE.NAME=VALUE...] [--json]` (`flow_json.rs`): checks the plan like `flow run` (`prepare`: comparisons, `flow::check`, steps without an executor) without looking for the inputs; exit 0 valid, 3 problems, 2 usage, 4 unreadable plan. With `--json` `flowcheck/1` `{valid, problems:[{instance, port, error_key, params}]}` on stdout.
- `--json` of `flow run` (also with `--dry-run`): on stdout a single document, `flowdry/1` (inputs with bytes and SHA-256, instances in order with canonical parameters and `params_sha256`), `flowrun/1` (code, folder, `plan_sha256`; per instance `ok|cached|error|skipped`, `ms`, outputs (port, file, SHA-256, bytes), `warnings`, `files`, error (key, parameters)) or `error/1`. Exit codes, stderr, `--out` files and `prov.json` do not change.
  `error/1`: `code`, `error_key`, `params`, `message`, `hint`, `command`, `problems` if the plan is not valid; keys `err.cli.usage|set|file|input.missing|input.twice|out` besides the engine's `err.flow.*`. `--progress jsonl`: on stderr one JSON line per job `{job, of, instance, item (from 1, or null), status ok|cached|error, ms}` in place of `[3/9] ...`. Schemas `docs/schemi/{flowcheck,flowdry,flowrun,error}-1.json`; tests `flow_json_tests.rs`, `tests/test_cli_json.py`.
- Test: `cargo test -p mzlab-cli` (`src/tests.rs`, in the crate: a test binary would be a second compilation of the engine): three synthetic mzMLs, the binary's CSV (default recipe, `--params`, `--preset neg`) is character for character equal to that of the page's chain on indexes built in memory; `--help` and usage errors. No browser, no Python.
- Headers: no column is called "formula" alone (neutral formula or ion formula); the `src/tests.rs` test checks it on the CSV.

## CLI rules (apply to every new command and module)
- **One registry**: `mzlab_cli::flow::steps()` is the union of ALL descriptor families (core, Attributio, Tabui, steps of the crate); the `docs/schemi/steps-*-1.json` files are its exports and the page reads the same ones. The native executor is a single `id → function` table in `flow.rs`; the list of executable steps is derived from it (no second hand-written list).
- **No interface-only parameter**: every `params` property of the descriptor (also those of an algorithm, the algorithm and the preset) is an option: `--set INSTANCE.PARAMETER=VALUE`, `--set INSTANCE.algorithm=NAME`, `--set INSTANCE.preset=NAME`. INSTANCE is the `id` of the instance in the plan; the step `id` also works if the plan has only one instance of it. The value is read with the descriptor's type (number, integer, boolean, choice, text, pair `a,b`) and goes through `flow::check`.
- **New module (checklist)**: (1) `step/1` descriptor in the family and regenerated export; (2) executor in `FileRunner` that takes names and bytes and returns the file's text/bytes (no `std::fs` outside `flow.rs`); (3) CLI = page-engine parity test (equal bytes); (4) help line if a command is born; (5) a line here and in the area file. A parameter read by the interface but absent from the descriptor is an error.
  (6) `flow_rule_tests.rs` stays green: every parameter (also of the algorithms) reaches the canonical parameters with `--set`, every `native: true` step has an executor or is in `BUCHI`. (7) Names follow "Names" below and `name_rule_tests.rs` stays green.
- **Messages**: all in English; progress only on stderr, written while the run proceeds, one line per job (`[3/9] features.table (feat) ... done in 12.4 s`; a `per_item` step adds `item 2`), then `done: N steps; outputs in FOLDER`; stdout stays for data. An error prints `error: <key> <parameters>` and a `hint:` line with the remedy.
- **Exit codes** (the table is in `cli-agenti.md`): 0 complete run; 1 instances in error (the other outputs, `prov.json` and `corsa.json` are written); 2 usage (option, malformed `--set`); 3 invalid plan (one problem per line); 4 missing, unreadable or SHA-256-mismatched input; 6 `--out` cannot be written.
- **Inputs**: the `inputs` names of the plan are looked up among the files given with `--in` (by name), then in the folders given with `--in`; without `--in`, in the plan's folder. Native formats go through `mzlab_lettori::apri` (`Limiti::desktop()`); a multi-file set (`.wiff` + `.wiff.scan`, `.D`/`.d`/`.raw` folders) is an input of `convert.mzml` (`flow_set.rs`); `NAME@ID` names the sample `ID` of a multi-sample set, without `@` the first.
- **Outputs** (`--out FOLDER`): one file per output port (`<instance>.<ext>`, `<instance>-<k>.<ext>` for a `per_item` step), `plan.json` (the effective plan: canonical form with the `--set`s applied, which relaunched without `--set` redoes the same run), `prov.json` (`prov/1`) and `corsa.json` (`corsa/1`). Temporary files live in `--out` and are deleted.
- **Reproducibility**: same plan and same inputs give the same bytes of every output file with 1 or N `--workers`; in `prov.json` and `corsa.json` only `ms`, `total_ms` and `heap_peak_bytes` change. The `prov/1` carries crate version, platform, target, CLI build commit and, if the build knows them (`option_env!`: `MZLAB_RUSTC`, `MZLAB_CARGO_LOCK_SHA256`), `rustc` and SHA-256 of `Cargo.lock`, plus `modules.mzlab-cli` = SHA-256 of the executable (`docs/agenti/rust-flow.md`).
- Cache test: `src/flow_cache_tests.rs`: second run entirely `cached` with the same bytes; a parameter of `align` recomputes `align` and `gapfill`, not index and `detect`; `--fresh` recomputes everything with the bytes of the first run; an output file changed by hand is recomputed; `run_plan_cached` of the desktop route picks up the same cache.
- Test: `src/flow_run_tests.rs` on three synthetic mzMLs: the BASE gives the page's table (`gap.mzfeat` = `run::align` with filling, `ali.mzfeat` = without), `plan.json` relaunched with 2 workers and the `run_plan` route give the same files and the same `prov/1` (times and heap aside), `--set` per step and per instance, `--dry-run`, codes 2/3/4.
- **Build identity** (`flow::build_agent`, the same for CLI, desktop and `.wasm`): full `commit` (given by the caller: the CLI build script; the `.wasm` has none), `platform` and, if known, `target` (`MZLAB_TARGET`), `rustc` (`MZLAB_RUSTC`), `cargo_lock_sha256` (`MZLAB_CARGO_LOCK_SHA256`), `modules` (name → SHA-256; the CLI writes `mzlab-cli` = its own executable). Missing key = not written: a record without new keys has the same bytes.
  `tools/prepara_sito.py` sets the variables; the `.wasm` is built WITHOUT commit (its bytes would change at every commit): the site's commit is in `version.js` and `static/build.json` (`build_site.py --build-json` after the `.wasm` files).
- **Cache** (`flow_cache.rs`): in `--out/cache/index.json` (`mzflow-cache/1`) each job is written under `flow::cache_key` (SHA-256 of the inputs per port, step, algorithm, `run_sha256`) plus instance, element and program version (the build commit included), with output file, SHA-256, estimates and the provenance that the following BASE steps read (`Lineage`: profile index and parameters written by each step, so the recipe is redone).
- Resume: a run in the same folder resumes a job whose key is present and whose file still has that SHA-256: no computation, `cached: true` in `prov/1`, `... reused` on stderr, state `cached` in `corsa/1`. `--fresh` recomputes everything and rewrites the index; files of old entries the run does not use are deleted. Nothing is read or written outside the folder.
- **Cluster**: no network, no file outside `--in`/`--out`, no questions; `--workers N` (default: cores minus one, from 1 to 4, like the app) for the instances of a level and the `per_item` elements; one plan per node, one `--out` folder per run; the exit code is enough; the `wasm32-wasip1` build of the same source runs in a WASI sandbox. Splitting a plan across nodes is not done.
- **Copyable command** ("Run on CLI"): Rust text from the canonical plan with the real names of the Data files, never built in JS. POSIX: `command -v mzlab-cli || cargo install --path crates/mzlab-cli` (no precompiled binaries), `MZLAB_IN='…'` (placeholder `FOLDER_PLACEHOLDER`, filled by `F.cliFill`, quoted once), folder `mzlab-run-<date-time>`, plan in a here-doc `<<'MZFLOW'`, `flow run`. Also from `mzlab-cli flow command PLAN` and the route `api/flow/command`.
- **Short line and `--set`** (`mzlab_core::flow::line`): `mzlab-cli flow run plan.json --in <folder> --out mzlab-out --set INSTANCE.NAME=VALUE …`, one `--set` per algorithm, preset and parameter different from the default, in plan order. `apply_sets` (algorithms and presets first) is the code of the CLI (`flow_apply.rs` refers there), of the site and of the app; error `err.cli.set` with `set` and `message`.
- Route `api/flow/line` (app: `flow/line`): without `line` it gives the line, with `line` the plan with the `--set`s applied; `err.cli.line` if it is not a `flow run`.
- **Out of scope without a "way"**: precompiled binaries, releases, new CI dependencies. The command assumes `mzlab-cli` in the PATH (`cargo install --path crates/mzlab-cli --profile cli`).

## Names (grammar of command, option, step and parameter names)
1. **Language**: English for every name the engine and the CLI read or print; the options of `tools/` stay Italian (group tools).
2. **Order**: commands are `name` or `name-name` with the object first (`msn-graph`, `ion-pattern`), subcommands are verbs (`run`, `check`, `build`, `sum`); options are a noun or an adjective (`--out`, `--clean`), a verb only for an action (`--annotate`).
3. **Singular** in commands and step names (`peak-edges`); plural only for a value that is a list (`--names`).
4. **Case**: commands and options in kebab-case (`^--?[a-z][a-z0-9]*(-[a-z0-9]+)*$`); step ids `family.name[_name]` (`^[a-z]+\.[a-z0-9]+(_[a-z0-9]+)*$`); parameters in snake_case; environment variables `MZLAB_UPPER_SNAKE`.
5. **One spelling per concept**: `ppm` (window in ppm, always as a suffix: `tol_ppm`, `ppm` if the step has only one), `da` (in Da: `tol_da`), `rt` (retention time), `tol` (tolerance), `min`/`max` as a prefix of a count or threshold (`min_points`, `max_gap`) and as a suffix only for a pair of extremes (`mz_min`/`mz_max`), `ms2`, `mz`, `seed` or `*_seed` for random seeds, `UPDATE` for "rewrite the expected file" in the variables. No other abbreviation (neither `toll`, nor `prec`, nor `att`).
6. **Lengths**: command ≤ 12, subcommand ≤ 8, option ≤ 14 without the dashes, parameter ≤ 20, step id ≤ 20, environment variable ≤ 24; longer only if a shorter name would force guessing.
7. **Aliases**: an old name stays accepted as input forever, is never printed except in the single `old names still accepted` line of `--help`, and the alias is a field of the entry in `src/cmd/`.
- **Test**: `name_rule_tests.rs` reads the `--help` of every command, the step ids of `flow::steps()` and their parameters (also of the algorithms) and rejects names outside the rule and those with an Italian root (`basso, prove, toll, perdita, regole, rotture, legami, vista, figura, canal, campion, somma, tutti`). Out-of-rule names kept by choice (ids and parameters saved in plans, `explain-missing`) are in `KNOWN`, each with its reason: the list can only shrink; a name that is back in the rule must be removed.
- **Kept by choice**: step ids, parameters saved in plans, schema ids and output file names are not renamed (they would need a format version and two readers: they change only when the format changes for another reason), nor `explain-missing`, `normative`, `--budget-mb`, `--dry-run`, `--hide-names`, `MZLAB_DATI`, which shorter would force guessing.
