# Triple-quadrupole transition table (`chrom.transitions@2`, `crates/mzlab-feat/src/transitions/`)
Nearby areas: `wiff.md` (SIM channels `SIM SIC Q1=`), `lists.md` (`flow/liste` editor), `cli-passi.md`, `wasm-caps.md` (`flowtab`).

- What it does: for every sample and every row of a table of SIM ions (Q1 only) or MRM/SRM transitions (Q1>Q3) it finds the row's chromatogram and integrates the peak in RT ± window with `mzlab_core::peak1d::find_peak` (`legacy::lr::peak1d` re-exports it; no second integrator). Rows without RT give only candidates, never an isomer assignment.
- Table = data, never code: an editable CSV (parameter `transitions`, `x-liste` = `transitions`), saved in the plan and in the session, edited by the lists editor (`flow-liste.js`, app only). Mandatory header starting with `name`; columns `name;q1;q3;polarity;rt;rt_window;isomer_group;note;formula;adduct` in any order (`table.rs`, `HEADER`). `to_csv` rewrites the cells as written (`;`).
- Rows: `q1` written, or computed from `formula` + `adduct` with `mzlab_core::elements` (never a number in the code); default adduct `[M+H]+` or `[M-H]-` from the polarity; empty polarity = that of the adduct, otherwise `+`. Decimal comma read as a point if the separator is not the comma. Per-row errors `error.liste.*` (`noName`, `badPolarity`, `badAdduct`, `badMz`, `noMz`, `badFormula`, `badRt`, `twice`, `noHeader`, `badColumn`).
- Channels (`traces.rs`): the `srm` chromatograms of `mzmlhead` (also SIM, `q3` absent) read with `MzmlTraces::cromatogramma`; polarity from the id text (`polarity=positive|negative`), absent = valid for both. `srm::leggi` and the existing MRM bytes do not change.
- Matching (`text.rs`): Q1 within `mz_tol` (0.5), Q3 both absent or both within `mz_tol`, same polarity; the closest wins, on a tie the first. A SIM row does not take an SRM channel and vice versa.
- Outcomes per row and sample (`peak`): `ok`, `edge` (apex on the first or last point of the window), `no_peak` (below `snr_min` or `min_points`), `no_trace` (no channel), `no_rt`. Only `ok` and `edge` count in `n_peaks` and in the means.
- Baseline (parameter `baseline`, `baseline.rs`): `zero` (default since version 2: trapezoids of y between the `find_peak` edges, `peak1d::area_against`; includes any background under the peak) or `edges` (the line between the same edges with the negative stretches at 0); it changes only the area (also of the candidates), never edges, apex, height, S/N or FWHM. Every output ends with the `baseline` column, `peaks` also with `below` (empty with `edges`).
- Baseline, saved plans and tests: a `@1` plan is migrated to `@2` with `baseline` = `edges` (`flow::migrate`), same numbers as then. Tests: `from_zero_*` of `transitions/tests.rs`, `flow_transitions_tests.rs` (CLI = `transitions_packed`, `@1` plan = `edges`), `migrate_tests.rs`.
- Outputs (parameter `output`, one file per instance): `peaks` (long: sample, row, apex_rt, area, height, snr, fwhm_s, peak), `table` (one row per transition: `area <file>`, `apex_rt <file>`, `n_peaks`, `rt_mean`, `rt_sd`), `candidates` (only rows without RT: peaks of the channel in all samples, grouped by RT distance ≤ `group_rt`, sorted by maximum area; a shoulder is not a candidate). CSV export = the file itself.
- Preset `example_1` (`data/transitions-example-1.csv`): 14 transformation products from formula + `[M+H]+`, without RT; applied only if written (`--set tr.preset=example_1`). The formulas of BQM (C15H12N2O2) and BQD (C15H10N2O3) are those of the ozonation literature (m/z 253 and 267). The compound name does not appear in code, ids or interface.
- Parity: a single text `transitions_text` (CLI `flow_transitions.rs`, `Exec::File`) and `transitions_packed` (browser, `flow_transitions` of `flowtab`, files packed with manifest `[{name,len}]`); `flow-web-transitions.js` blocks with `platform.computer` if a source is not an mzML opened in Data or if the files exceed 128 MB. In the browser a `.wiff` must first be exported to mzML; CLI and app: `convert.mzml` → `chrom.transitions`.
- Tests: `transitions/tests.rs` (synthetic channels as `tools/wiff_sim.py`), `flow_transitions_tests.rs` (`.wiff` SIM → mzML → `flow run`: bytes = `transitions_text`, isomers 2.5/4.0 min, negative ion, preset and candidates, `transitions_packed` = CLI), `e2e_flow_transitions.py` (browser = `flow run` byte for byte for the three outputs).
- Manual integrations of Data (`manint::table_text`, `integrazioni-manuali.js`, card `#manint`, `window.MANINT`): every window integrated by hand on a trace of a transitions/SIM ions panel (`p.ints` with `bm` and the name `nm`, saved in the session) = one row, measured again by the engine; the card sits under `#dpanels`. The module loads at the first integration (`grafici.js` → `carica`); `MANINT.sync` after every panel draw and from `syncWork`. No automatic channel table.
- Manual integrations, window applied to the other samples (`manint_follow.rs`): a window with `follow` (that of the sample with the last trace on the channel) is applied to the same channel of every other given sample that has none of its own; the engine looks for the apex within the window width per side (`peak1d::find_peak`, S/N ≥ `FOLLOW_SN` = 3): inside the window = `applied`, outside = the window moves (`shifted`), no peak = it stays where it is (`no_peak`).
- Manual integrations, all files (`manint_auto.rs`, `integra-tutti.js` `runFiles`, entry "Integrate peaks in all selected files" of the ▾ of the automatic tool and of the trace menu): the engine (`peakq_lrauto::lr_auto_integrate`, the numbers of the peaks window + `rt_tol`, 0.10 min) finds the peaks of every trace of every shown file, groups them by channel (apex within `rt_tol` of the group mean, one peak per file) and makes the table windows from them (`baseline: line`, `grp` = mean apex, `origin` = `auto` | `unmatched` if no other file has the peak).
  - The page adds them to `p.ints` (`org`, `grp`) in an undoable step; the rows are those of `manint::table_text` (Origin column "Automatic" / "No counterpart"), the area labels the usual ones (`AREALBL.draw`); `org` windows are not a source for `follow`.
  - Site `api/manauto?k=..&p=NUMBERS` (`manual_auto`, op `auto`) = app op `auto` = CLI `manual-table --set auto=true [--set params=FILE]`: `{tol, windows, log, groups, unmatched}`.
  - Status (aria-live) with every number used, log per file under the card. Tests: `manint_auto_tests.rs`, `manual_table_cmd_tests.rs`, `e2e_integrazione_auto.py`.
- Manual integrations, on-screen application (`integra-segue.js`, `SEGUE.all`/`SEGUE.sources` in the drawing of `grafici.js`): on the traces shown without a window of their own the window is redrawn with the engine's edges (`MANINT.follow` asks `api/manfollow`), label "A = …" on the peak, box with the origin (`int.follow.org.*`) and S/N (`MANINT.snr`); every shown sample is also a row of the card. Tests: `e2e_integrazione_multi`, `e2e_sim_wiff`.
- Manual integrations, columns (`manint::HEAD`, the same on screen and in the CSV, no column with the channel name in the method): `channel` (m/z of a SIM ion, `q1>q3` of a transition, `ion N` without Q1), `sample` (file without `.mzML`), `label` (the name given by the user), `apex_rt_min`, `area` (counts × s), `start_min`, `end_min`, `height`, `snr` (`peak1d::find_peak`, empty without a peak), `baseline`, `overlap`, `pv`, `origin`. Rows per channel (order of first appearance in the files), then peak group (start of the traced window), then sample; areas and heights in `sci` with 5 decimals.
- Integrations card, look (`integrazioni-manuali.js`, `app.css`): `apex_rt_min` is immediately left of `area` in the engine (CSV, copy, site, CLI alike); on screen both columns are semi-bold on a light tint (`.manint-key`, `color-mix` of `--accent` and `--panel`, header included), and the sample cell starts with a decorative square (`.manint-sw`, `aria-hidden`) in the file's colour (`E.files[k].color`, the Files list and chart colour; the card redraws when it changes). Proof: `e2e_manint_layout.py`.
- Column `time_min` (right after `sample`, also in copy/CSV; on screen as a label `3h`/`t0`): the `time` field of the file in the list (minutes, `null` = none), otherwise the time of the name (`samples::role_and_minutes`, none for blanks); the page sends the time of the samples table (`tm` of `api/manint`, recomputed at every `campioni` event), the CLI reads the names or `--set times=FILE` (`{"campione": minutes|null}`).
- Manual integrations, column `origin`: `manual` (traced by hand), `applied`, `shifted`, `no_peak` (engine decision for a sample the window reaches, written as a row even without a peak); on screen (`canali.manint.org.*`, `tr[data-org]`) the column is there only if a row is not `manual`, after the baseline; an announcement `canali.manint.applied` (`#manint-live`, `role=status`) says how many samples it reaches.
- Manual integrations, channel: Q1 and Q3 rounded to 0.01, name and place among the channels of the file that round equal (`Trace::dup`), so two transitions less than 0.005 Da apart stay two channels with their own rows; the first of each file is grouped with the first of the other files.
- Manual integrations, split columns: `overlap` = `drop` in the parts of a window split at the valleys ("yes" on screen), `pv` = height of the part / highest adjacent valley (1 decimal; empty if the valley is ≤ 0); on screen the two columns stay hidden if empty in all rows, with the meaning in the header `title`.
- Manual integrations, column `label` (third, after the sample): the name the user gave the window (`label` of the request), without control characters, at most `LABEL_MAX` = 40 characters; empty without a name and in `sum` rows.
- Manual integrations, traces the page makes itself (chromatogram, XIC, DAD; step 1 of one integration table):
  - Site POST `api/mantraces` (`{files, windows, sums}`, `rust-bridge-info.js::tracesRoute`, op `manint`; the app takes the same route through `rpc.rs`) = CLI `manual-table --set traces=PATH --set windows=PATH`.
  - A trace with `panel` (plus `label`, `unit`; per file `conc`, `conc_unit`; per window `corr`) adds `panel,conc,conc_unit,correction,below,area_unit` after `origin` (`manint_csv.rs`); tables of file transitions keep their bytes.
  - Page side: `integrazioni-tracce.js` (rows of the card «Manual integrations», next to the transition rows).
  - Tests: `manint_ext_tests.rs`, `manual_table_traces_tests.rs`, `e2e_manint_tracce.py` and `e2e_manint_dad.py` (the card's area, height, apex, below, correction = the dialog table's).
- Manual integrations, baselines as in the Data view: `zero` and `line` (`bl` = `[t0, y0, t1, y1]`) with `baseline::peak_area`, `edges` = line between the 3-point means of the edges (`integ` of `picchi.js`); an `edges` record with the line of the HR automatic integration (`base`) goes as `line`. Old records with `zero: true` (window down to zero) do not enter. Errors `err.manint.channel` (window without a trace or times) and `err.manint.baseline`.
- Manual integrations, card: header with the title "Manual integrations (N)" as a button that opens and closes (`aria-expanded`, `title` and `aria-describedby` = `canali.manint.note`; open or closed is kept in `NOMI.KEY("manint.open")`, it reopens when integrations arrive after none).
- Manual integrations, 28 px icon buttons in the header: Download CSV (engine bytes, provenance line on top, `manual-integrations.csv`) and Copy table (engine rows separated by tabs after the provenance line; outcome "Copied!" or `bn.noClip` with `AREACOPY.say` under the button).
- Manual integrations, no help sentences nor sums box on screen: the `sum` rows stay with the engine (`sums=1`) and the CLI (`--set sums=true`).
- Manual integrations, rows: `#manint-b` is as tall as the rows (header + one per row) up to `min(60vh, 40rem)`, then scrolls inside (`sticky` header); the card sits under the last panel (`fitHost` keeps the 520 px only without panels). The row (click, Enter or Space; `tr[data-go]`) reveals the panel and selects the window, the 24 px X ("Delete integration", `delInts`, undoable) removes it. Test: `tests_e2e/e2e_manint_layout.py`.
- Manual integrations, name: column "Name" after the sample (then the area), `input[data-nm]` (40 characters, `aria-label` `canali.manint.nm.aria`, tooltip `canali.manint.nm.tip`). Enter or leaving the box gives the name to the group (`it.nm` of the traced window, `pushIh`, undoable); Alt+Enter to that sample only (`it.fn[trace key]`, `names` of the request); a name given to a single sample stays. It goes in the CSV, in the copy and on the label; Esc restores the previous name; X only in traced rows; a window duplicated on two panels counts once.
- Manual integrations, copyable cells: apex, area and height (also the area of the sums) are `span.manint-cp` (`role=button`, 24 px, `aria-label` `canali.manint.cp.aria`, `title` `canali.manint.cp`): click, Enter or Space copy the CSV value at full precision (`AREACOPY.put`, notice "Copied!" 1.2 s + 150 ms fade next to the pointer or the cell) without revealing the row. Test: `e2e_sim_wiff`.
- Manual integrations, parity: site `api/manint?k=..&w=JSON&sums=1` (`rust-bridge-info.js`: `mrm` of every slot, then `manual_table` of the `rotte` module, `mzlab-rotte-wasm`), app op `manint` of `rpc.rs`, CLI `mzlab-cli manual-table FILE... --set windows=PATH [--set sums=true] [--set shifts=true] [--out PATH]` (`manual_table_cmd.rs`: `file` = place of the sample in the file order, a `.wiff` gives all its samples named as `conversione.js::wiffName`; truncated sample = warning on stderr).
- Manual integrations, where a window falls in the other samples: site `api/manfollow?k=..&w=WINDOW` (`manual_follow` of `rotte`, worker op `follow`) = app op `follow` of `rpc.rs` = CLI `manual-table --set shifts=true` (`follow_text`): `[{file, tr, a, b, shift, origin}]`.
- Manual integrations, split at the valleys (`valley.rs`): on the trace minus the baseline, smoothed over 3 points, the minima between two maxima; the valley with the smaller rise is merged step by step until the rise (lower peak − valley) is ≤ depth × higher peak (`DEPTH` = 0.1). A shoulder has no minimum and is not split. The parts are integrated against a single line (`edges` = line through the edges), so they sum to the area of the window; the window carries `splits: [min, ...]` (those outside (a, b) ignored).
- Manual integrations, "Split at valleys" (`integra-valli.js`, `INTVALLI`; action `int.split` of the chart menu, key V with the window selected): the engine proposes the cuts at the depth of the bar (`input[data-depth]` in %, remembered in `NOMI.KEY("int.split.depth")`), "No valley" if it finds none; 24 px markers (`role=slider`) draggable with mouse or finger on the points of the trace, ←/→ one point (Shift five), Delete removes, Enter or "Split" confirms (`pushIh`, undoable), Esc leaves it as it was; the vertical lines are drawn on the chart.
- A split window has one label "A = …" per part on its vertex (`area-etichette.js`, `AREALBL`; area, apex and height from the engine rows, `MANINT.parts`; a label covering another, of any window, moves up or down one row with a thin line to the vertex; inside the chart; with several overlaid files the text has the file's color and the name is in the tooltip).
- "Split by hand" (key M, `INTVALLI.startManual`, action `int.split.hand`): a guide line follows the pointer, a click in the window adds a cut to `it.splits`, the handle is dragged with live areas, Delete removes the cut, Esc exits; one undo step per action. No Rust code: the `splits` primitive already takes the times.
- Manual integrations, split parity: site `api/manvalley?k=K&depth=D&w=WINDOW` (`manual_valleys` of the `rotte` module, worker op `valleys`) = app op `valleys` of `rpc.rs` = CLI `mzlab-cli peak-split FILE... --set file=I tr=J a= b= [baseline= line= depth= label=]` (`{"splits":[...]}`); with `--set split=auto|MIN,...` the CLI prints the table of the split window, the bytes of `api/manint`.
