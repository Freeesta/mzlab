# Periodic table for MS
Dialog «Periodic table» (`mzlab/web/tavola-periodica.js`, opened by `tables.js`): tiles by element class with atomic number, symbol and monoisotopic mass only; card with the class, average and monoisotopic mass, a note on the isotope marker and the isotope table; legend (colour + pattern swatch + full class name) that dims by class; arrow-key navigation.
- Data: `mzlab-core::periodic` (`elements/1`, the ONE place of names and classes; masses and abundances from `nuclides`/`isoscore`). Same bytes from `mzlab-cli ion elements --json`, the route `api/elements` (`.wasm` `motore`, op `lr_elements`) and the app; `parity_routes.rs` compares app and wasm.
- Keys: `mono` (nuclide table where the abundance tables lack the element), `avg` and `isotopes` only with abundances, `mono_only` (one isotope), `m2_rel` (M+2 / main, from 0.04).
- Colour is never the only signal (WCAG 1.4.1): Okabe-Ito hues, a 4 px bar and one fine, faint pattern per class (nine different shapes, `PATTERNS` in `tavola-periodica.js`). No class code on the tiles: the class is in the legend, the tooltip, the accessible name and the card.
- Isotope markers ("1" single isotope, "+2" M+2 pattern) are CSS-drawn (`data-m`, not part of the button text) in the top row beside the number and show on hover, focus or pin; the card says the same in words. Hidden by default so tiles stay quiet and nothing can overlap.
- The accessible name starts with the visible text in order (number, symbol, mass: WCAG 2.5.3), then name, class and masses (`tbl.pt.aria*`); the markup keeps spaces between the tile's elements so axe reads separate words.
- Tests: `e2e28.py` (contrast on the flat colour), `e2e_tavola_fissa.py` (fixed layout), `e2e_tavola_celle.py` (content of a tile, boxes of every child at 1024 and 1440 px in light and dark: no overlap, no clipping; pattern spectra, hue pairs under simulated deuteranopia/protanopia, text contrast over the darkest pattern pixel), `e2e_a11y_dati.py` (axe and Label in Name on the dialog, light and dark).
