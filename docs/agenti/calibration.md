# Calibration line on integrated peaks (`quant.curve@1`)
Files: `crates/mzlab-core/src/calib.rs` (pure math: weights, QR, R², inverse), `crates/mzlab-ops/src/run/table/curve_read.rs` (reads the two CSVs and the parameters), `curve.rs` (choices and log), `curve_write.rs` (JSON/CSV texts), `crates/mzlab-cli/src/flow_curve.rs` (step descriptor and files), `crates/mzlab-flowcal-wasm/src/lib.rs` (`flow_curve` in the browser), `flow/lazy/flow-web-quant.js` (site executor). Different from `quant.calibrate`, which applies imported curves and estimates nothing.

## Inputs
- **responses** (CSV, `;`, tab or `,`; decimal comma accepted if the separator is not `,`): one row per peak. Columns: `sample`, the analyte name (`analyte` > `label` > `name` > `channel`), `area` and/or `height`; optional `snr` and `peak`. This is the shape of the integration export and of `chrom.transitions`.
- Peak rows: `sum` rows and rows without a sample are skipped (`skipped`, `sum_row`/`no_sample`, note = the row). `peak` = `edge` (peak cut at the window edge) is kept, with one `kept`, `peak_at_window_edge` row per peak and the warning `warn.flow.curve.edge` (it is excluded with `exclude`); any other value different from `ok` = no peak (`treated_as_no_response`, `peak_status`, note = the value). An `snr` ≤ 0 does not enter the S/N limits (`snr_not_used`, `snr_not_positive`).
- **standards** (CSV): `sample`, `concentration` required; optional `analyte` (empty = all analytes), `level`, `unit`, `role`, `dilution` (factor for the final concentration, 1 if missing). Roles: `standard` (`std`, `calibration`, `cal`), `qc`, `sample` (`unknown`, `empty`), `blank`. A sample of the peaks missing from the standards is treated as an unknown (warning `warn.flow.curve.unlisted`).
- An analyte repeated in the same sample = error `err.flow.curve.duplicate`; different units among the standards of an analyte = `err.flow.curve.unit`. A QC or sample with a non-empty unit different from that of the standards is reported in the unit of the line, QCs without accuracy (`reported_in_curve_unit`, `unit_differs`, note `its -> the line's`; warning `warn.flow.curve.unit`).

## Parameters
- Defaults chosen by the owner (list in the PR): `signal` `area` or `height`; `model` `linear` or `quadratic`; `weight` `1`, `1/x` (default), `1/x2`, `1/y`, `1/y2`; `zero` (line through the origin, false; only `true`/`false`, any other value = `err.flow.curve.param`).
- `istd`: one name for all analytes or `analyte|IS` pairs separated by `;`. The response becomes area/area of the IS of the same sample; the IS are not calibrated (log row `internal_standard`).
- `exclude`: `analyte|sample|reason` separated by `;`, `*` = every analyte. It is the only way to exclude a point: no automatic exclusion of outliers; every exclusion goes in the log with the reason written by the user.

## Model and solver
- Weighted least squares with relative weights (scaling them does not change the line). The design (1, x, x²; without the column 1 if `zero`) is multiplied by √w and x is divided by max|x|; the system is solved with Householder QR, never with the normal equations (the conditioning stays that of the design, not its square).
- Insufficient rank (column below 1e-10 of its own norm) = `err.flow.curve.singular`; fewer points than parameters = `err.flow.curve.points`; non-finite value or weight = `err.flow.curve.value`. These three errors stay in the curve (field `error`), the step goes on with the other analytes (warning `warn.flow.curve.failed`).
- Undefined weight (1/x with x = 0, 1/y with y ≤ 0): the point is excluded with reason `weight_undefined`. A zero-concentration standard therefore enters only with weights 1, 1/y, 1/y² (if y > 0). A response ≤ 0 (area after blank subtraction, ratio) with weights 1, 1/x, 1/x² stays in the line but goes in the log (`kept`, `response_not_positive`, note = y) with the warning `warn.flow.curve.notPositive`.
- Centred weighted R² (also with `zero`; `null` if all y are equal); `s_yx` = standard deviation of the unweighted residuals, n − p degrees of freedom (the ICH σ); `s_w` = the weighted one. With n = p there is no σ (`null`).
- Inverse: linear (y − a)/b; quadratic with the stable root 2(y − a)/(b + sign(b)·√(b² + 4c(y − a))), which also holds for c → 0; no real root = note `no_root`.
- Tests: `calib_tests.rs` (exact line, Miller & Miller examples §5.4 unweighted and §5.10 weighted, closed form 1/x, a 1/x² computed by hand in fractions, Σxy/Σx² for the origin, quadratic over three decades, singular designs, a 500-case check: standards recovered within 1e-9).

## Outputs
- **calibration** `<id>.json`, format `calibration/1`: `signal`, `model`, `weight`, `zero`, `curves[]` and `log[]`. Each curve: `analyte`, `istd`, `unit`, `error`, `a`, `b`, `c`, `n`, `r2`, `s_yx`, `s_w`, `range` [min, max] of the standards used, with the minimum taken from the standards above zero (LLOQ = lowest non-zero calibrator: a zero standard helps the line but does not quantify; log row `range_lower`, `lowest_nonzero_standard`, note = the minimum), `lod[]`, `loq[]`, `points[]` (`sample`, `level`, `x`, `y`, `weight`, `used`, `reason`, `fit`, `residual`, `back`, `accuracy_pct`).
- LOD/LOQ, always with the method in the name: `ich_3.3_s_yx_over_slope` / `ich_10_s_yx_over_slope` (3.3σ/b and 10σ/b, σ = `s_yx`, b = slope; for the quadratic b is the slope at zero concentration, as the help of the `model` parameter also says; `null` with a `limit_not_computed` log row: `no_degrees_of_freedom` if n = p, for example a line on two points, and `slope_not_positive` if b ≤ 0) and `sn_3_lowest_standard` / `sn_10_lowest_standard` (mean of k·x/(S/N) of the lowest used standard that has an S/N). The second is an extrapolation: the name says so.
- Log `log[]`: `analyte`, `sample`, `choice` (`skipped`, `kept`, `treated_as_no_response`, `snr_not_used`, `treated_as_sample`, `excluded`, `reported_in_curve_unit`, `not_fitted`, `range_lower`, `limit_not_computed`), `reason` (`sum_row`, `no_sample`, `peak_at_window_edge`, `peak_status`, `snr_not_positive`, `excluded_by_user`, `no_response`, `no_istd`, `weight_undefined`, `response_not_positive`, `not_in_standards`, `unit_differs`, `internal_standard`, `lowest_nonzero_standard`, `no_degrees_of_freedom`, `slope_not_positive`), `note`.
- **concentrations** `<id>.csv`: `analyte,sample,role,level,signal,istd_signal,response,concentration,unit,accuracy_pct,note`; concentration = back-calculated value × `dilution`. Notes: `ok`, `below_range`, `above_range` (only for non-standards: outside the standards used, the value stays), `no_response`, `no_istd`, `no_root`, `no_curve`, `excluded_by_user`, `weight_undefined`.
- Accuracy: `accuracy_pct` = 100·back-calculated/nominal for standards, QCs and blanks with nominal > 0, both in the injected solution: the dilution multiplies only `concentration`, it does not enter the accuracy (same number in the `points` of the JSON and in the CSV; `concentration` of the standards is the x of the line, so that of the QCs is also in solution).
- Numbers with the Rust `Display` (`{}`), the same on native and wasm: same bytes in the app, in the CLI and on the site.

## Where it runs
- CLI/app: `quant.curve` in `EXECUTORS` of `flow.rs`, two outputs (`Made.extra`); descriptor in `docs/schemi/steps-cli-1.json` (regenerated with `MZLAB_UPDATE_STEPS=1 cargo test -p mzlab-cli --lib flow_ms2`).
- Site: `flow_curve` of the `flowcal` module (bridge `flowcal/2`, `wasm-tetti.md`), op `flow_curve` of `feat-worker.js`, executor `F.webQuant.curve` (`flow-live-jobs.js`): the two inputs come from a file of the plan or from the text of a previous step; both outputs stay in OPFS, the CSV also in `x.files` under `<id>.concentrations` for a step linked to that port.
- Parity: `crates/mzlab-cli/src/flow_curve_tests.rs` (golden files `crates/mzlab-cli/tests/data/calibration/golden.json` and `.csv`, `MZLAB_UPDATE_GOLDEN=1` to rewrite them), `tests/test_flowcal_curve_wasm.py` (wasm in Node = `flow run`, four groups of parameters), `tests/test_calibrazione_golden.py` (the golden files recomputed from the inputs alone with the closed-form normal equations: a, b, weighted R², `s_w`, unweighted `s_yx`, residuals, back-calculations, accuracy, LOD/LOQ, concentrations).
- Parity in the browser: `tests_e2e/e2e_flow_web_quant.py` (site = native, also for a second `quant.curve` that reads the standards from `cu.concentrations`). The ICH limits of the Miller & Miller §5.4 line are compared with the numbers in the book in `curve_tests.rs`.
- Test data: `tools/synthetic_data_calibration.py` (8 levels 0.5–100 ng/mL, blank, QC at 15, four unknowns of which one below and one above the range, linear analyte A, curved analyte B, constant IS, injection volume ±5 %), called by `tools/dati_sintetici.py` in the `taratura` folder.
