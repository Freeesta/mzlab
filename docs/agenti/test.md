# Verification, test levels and thresholds

- **One command**: `python3 tools/verifica.py` (JS syntax, text checks, pytest, `prova_hr`, every e2e found with the glob `tests_e2e/e2e*.py`; ~9 min with 4 CPUs). Options: `--changed` (only the e2e of the files changed against `origin/main`, from the `# covers:` lines of the e2e; a core file such as `explore.js` or `index.html` asks for all of them, documents alone for none), `--last-failed`, `--quick`, `--only e2e6,e2e18`, `--no-e2e`, `--parallel N`, `--browser firefox|webkit`, `--smoke` (`SMOKE`). Logs in `.verifica/log/<name>.log`: only for FAILs, read by the `verifier`.
- **Three levels**: (1) while working and before the merge `--changed` + the PR's CI; (2) CI of every PR (`test.yml`: pytest Linux 3.11 (3.14 only at night), JS syntax, `--smoke` Chromium, which on Linux Chromium also includes `SMOKE_CHROMIUM_LINUX` of `verifica.py`; its 4 jobs are the required checks of "protected main"; a new push stops the old run); (3) every night on main and by hand at the end of a big package (`notte.yml`: pytest Linux 3.14, Mac and Windows, `--smoke` Firefox/WebKit/Chromium Windows, full verification Chromium Linux).
- **Map and thresholds**: `docs/agenti/mappa.md` is NOT in the repository: it is generated with `python3 tools/indice.py` (~1 s; at the start of the session and after adding or moving files; CI checks with `--verify` that every file belongs to a group: a new folder goes in `GROUPS`). `python3 tools/controlla.py` warns about files/functions/lines that are too long and FAILS only if they get worse than `tools/soglie_base.json`; it warns (never an error) about base entries less than 20 lines from the tolerance: split the file; the base shrinks with `--update`, never widens.
- **Net after the merge**: the `sito-e2e` job of `sito-rust.yml` runs, only on push to `main` (never in PRs, not a required check), one extra step with the e2e of the user paths (file groups, load folder, Draw/Ketcher, integration, headers, tour; about 10 minutes); a red marks the commit's run in Actions, workflow `sito-rust`, branch `main`.
- **Smoke round in two shards**: `browser-shard` runs `--smoke --part K/2` (K=1,2); the job `browser (ubuntu-latest, chromium)` only sums them up, so the required check keeps its name.
- **Night in parts**: the "full" run of `notte.yml` runs in 5 jobs (`verifica.py --part K/5`: part 1 also does syntax, texts and `prova_hr` (no pytest: its own jobs run it), each part a share of the e2e, the slow ones dealt out in turn; part 5 also does `e2e_rust` and the measurements; first the `sito` job builds the `.wasm` of engine, libraries, readers and mzFinder with the caches of `pages.yml` and the parts download them), each with its own report `ultimo.md` in the artifact `notte-completa-K` even if a test fails.
  - `--budget` (40 min, part 1: 47): once expired, no part is started and the report is written (not run: FAIL "TIMEOUT budget, not run", never KNOWN).
- **Night, pytest and WebKit**: pytest jobs: halves a/b (`CI_PYTEST_MITA`), cap 60 min. WebKit on macOS turns the night red like the other browsers: its OPFS (`navigator.storage.getDirectory()`) fails in the ephemeral context of `new_page()`, so with `--browser webkit` `lib.py` opens every context as persistent (temporary profile, removed on close). `webkit-mac.yml` (by hand) redoes the diagnosis. `noti_rossi.txt` applies to Chromium only.
- **OPFS and WebKit**: `archivio.promote` renames with `fh.move(folder, name)` (WebKit rejects `move(name)`; if the move fails it copies); `e2e_opfs_promote` (in `SMOKE`) tries it in a worker on all engines.
- **Synthetic hashes in the determinism tests**: the fixed hashes of the synthetic inputs of `test_flow_determinismo.py` hold where the bytes coincide (libm/zlib on macOS differ); elsewhere only the runs are compared with each other.
- **Known reds**: `tools/noti_rossi.txt`: known red e2e (non-blocking); a line whose e2e passes for 3 runs in a row of `verifica.py` becomes FAIL until it is removed.
- **Safety set of the `e2e-cambiati` job** (core files): only tests green on the runner, allow-list `tools/ci_e2e_verdi.json` (name → seconds): the e2e `OK` in the `ultimo.md` of the `notte-completa-K` shards of the last full run; what is missing runs only at night.
  It is rewritten with `ci_e2e_cambiati.py --verdi <ultimo.md of each shard>` (keeps tests of at most 30 s, without Ketcher, workers or heavy fixtures); a red or expired test in a recent run of the job is removed by hand. A test that needs the `.wasm` of the CI jobs goes in `NEEDS` with `wasm`.
- **Rewriting the expected files**: always `MZLAB_UPDATE_<WHAT>=1` (`GOLDEN`, `FIXTURE`, `GUARDS`, `STEPS`, `LLM`, `FLOW_CASES`, `SCHED_CASES`); `MZLAB_REGEN_GOLDEN`, `MZLAB_WRITE_GOLDEN`, `MZLAB_GOLDEN_WRITE`, `MZLAB_WRITE_FIXTURE` and `MZLAB_GUARDIE_CREA` are accepted aliases (`tests/test_env_nomi.py`). `verifica.py --show-ok` also prints the OK lines. `MZLAB_APP_DIR` is the app folder for `examples/serve.rs` (alias `MZLAB_DATA`).
- **Fixed pauses**: `controlla.py` only lets the number of `wait_for_timeout`/`time.sleep` per e2e file go down (`tools/attese_base.json`): a new file cannot have any, wait for the STATE with `wait_for_js()`.
- **Reload and import**: an e2e that reloads the page and resumes the session first calls `saved(pg)` (the notebook is written in the background) and then waits for the state (`wait_for_js()`/`ready()`), never a pause; `tools/check_import.py` (and `tests/test_import_e2e.py`) checks that every import of the scripts in `tests_e2e/` and `crates/*/tests/*.py` points to a file of the repository, to an installed package or a known one (`THIRD_PARTY` list).

- **Structure**: `tests/` = pytest (also pure JS functions with node; `I18N` from `tests/node_i18n.js`); `tests_e2e/` = Playwright scripts, one per topic; helpers (`NOT_TESTS`): `lib.py` (`Run`: serves `site/` (the site with the Rust engine, built by `tools/prepara_sito.py`, which `verifica.py` launches by itself) + browser in `it-IT`, own port),
  `lib_hr.py`, `lib_reset.py`, `synth.py` (example images and arrow measure: `tools/make_examples.py`, `tools/lat_arrows.py`).
- **Opening in tests** (`lib.py`): files open as soon as they are read and at the end of the batch the first one is shown by itself. `stage(pg, files)` waits for the table rows; `open_first(pg)` waits until nothing is being read or opened (`UPBUSY`, `OPENNOW.busy()`, no `#flst .fl.up` row), writes the missing times (`_tempi`) and, if no file is shown, clicks the one that would be shown first (`firstOpenK`). `pg.click("#opbtn")` goes through `open_first`. The progress rows are `.fl.up` (`.fl.pr` = MS2 precursor).
- **Header commands in tests** (`lib.py` `hd_click(pg, sel, keep=False)`): a narrow header moves commands into the "⋯" menu; `hd_click` opens it if needed, clicks and closes it (`keep=True` leaves it open).
- **Private data**: a single resolver, `tools/dati_percorsi.py` (pytest, e2e, tools) and `tools/dati_percorsi.rs` (Rust tests, included with `#[path]`); ask for `percorso("dati/3200 qtrap/mzML")` and get the real path or `None`: the test is skipped and says so on the terminal beyond cargo's capture (`skipped: no data: <test> (…)`, without the path). No other file reads `MZLAB_DATI` or writes folder names of the data repo (`tests/test_dati_percorsi.py`).
- **New tests**: `r.port` (never a port in the URL); after an action that asks for data `ready(pg)` instead of fixed pauses; a check that already exists is not repeated (`grep -n 'step("' tests_e2e/*.py`); the line `# covers: <prefix>` at the top of the test if it covers precise files and in `NEEDS` if it needs something; the CSP forbids `eval` (pass expressions to `wait_for_function`, not long functions); a test that depends on the time tolerates the change of minute; on Windows read node's output with `encoding="utf-8"`.
- **`# covers:`**: at the top of `tests_e2e/e2e_<name>.py`, a line `# covers: <prefix>, <prefix>` with the files the test covers (a prefix is a file, a folder or the start of a name, such as `mzlab/web/an-`); `--changed` and CI read them with `covers()`. The "no e2e" prefixes (`tools/build_site.py`, `tests/`, ...) are `NO_E2E` in `verifica.py`; a file without a prefix is core and asks for all the e2e. `tests/test_verifica_aree.py` checks that every prefix finds a tracked file.
- **Storage names in the e2e**: the e2e use the canonical names: localStorage/sessionStorage `mzlab.*` (`mzlab.admin`, `mzlab.tour.lr`, `mzlab.bar.*`, `mzlab.prefs`, `mzlab-theme`, `mzlab-labels`), IndexedDB `mzlab_lab` and caches `mzlab-app-*`/`mzlab-big-*`; the `qqq.*` and `qqq_lab` names appear only in `tests/test_migrazione_qqq.py`.
- **E2E that CI does not run in full** (with synthetic data they are skipped or skip a step; try them locally before touching what they cover): real lab data: `e2e_studenti` (`NEEDS` table, "veri"), the steps on real Orbitrap cuts of `e2e_hr_base` and `e2e_hr_ppm` (`lib_hr.real_cuttings`), `e2e_hr_msntree` (MSn infusion file), `prova_hr` (folder `HRMS`);
  a `.dam` file (`MZLAB_DAM`): `e2e9`, `e2e10`, `e2e15`, `e2e_dam_incoerente`;
  `cargo` and `wasm-bindgen`: `e2e_feat_run`, `e2e_feat_na`, `e2e_feat_worker`, `e2e_pipeline`, `e2e_pipeline_nominal`, `e2e_lettori` (`verifica.py` builds `mzlab-cli` and the `native` example once before the parallel group: tests that launch `cargo run` do not wait for cargo's lock inside their 600 s); `axe-playwright-python`: `e2e_axe_grafici`, `e2e_axe_release` (HR bench, Drawing without the Ketcher iframe, tour). The others pass with the synthetic files.
- **Bug matrix** (`tests_e2e/e2e_matrice_bug.py`, ~25 s, synthetic files): actions of the Data, Statistics and Molecules areas × states (no file, one, many, file removed, reload, language, theme, narrow window, keyboard, undo/redo, repeated clicks); a cell fails on page or console errors, unhandled rejections, `MZLAB_LR_MISS` entries, empty sections or axe violations.
- **Accessibility in the `--smoke` run** (`e2e_a11y_dati`, "browser" job): axe (`serious`+, WCAG 2.2 AA, contrast) on six states (start, file loaded, MRM, map, Settings, search); Tab with focus indicator, Esc closing dialogs, 320 px without horizontal scroll, `forced-colors`, `prefers-reduced-motion`. Without axe it FAILS. Known gaps: `docs/agenti/accessibility.md` ("Known gaps of the Data view").
- **Check ⇒ run of Flow** (`crates/mzlab-cli/src/flow_pairs_tests.rs`, ~90 s in debug, synthetic series `identita`, skips without numpy): every port of every step of the registry receives every source of its type (file, outputs of the producers, `table.filter` view, empty table, single-file table); if `flow check` passes and the step runs on the canonical input but not on that one, it is a disagreement. The known ones are in `KNOWN` (with the why): a new one, or one that is gone but still listed, fails the test. Report in `$TMPDIR/mzlab_pairs_report.tsv`.
  - `BY_DATA` holds those that only the data reveal (`error.badSamples`: the check reads the plan, not the table rows): the run must fail with that key.
- **Identical input names** (fixtures of `flow_pairs_tests.rs`): the inputs have distinct bytes because the run names an artifact after the first input with that SHA-256, so two identical files can swap names depending on the timing of the steps.
- **Reader robustness**: `cargo test -p mzlab-core --test robustness_common` (~15 s, without `MZLAB_DATI`; the `.wiff` seeds need python3) gives every reader a valid seed and deterministic mutations (cuts, flipped bytes, counts at `u32::MAX`/`u64::MAX`, zeros, empty file, valid head + random body): every case gives a reading or an `err.*`/`error.*` key, never a panic, a hang beyond 20 s or an allocation beyond `8 MB + 64 × bytes`.
- **Vendor reader robustness**: `cargo test --release -p mzlab-core --features estesi --test robustness_vendors` (~20 s) passes the same mutations to Agilent `.D` LC/MS seeds (QqQ MRM, Q-TOF centroids, method) and to the `.wiff` pairs of `tools/wiff_riferimento.py` (MRM, sMRM, periods, TOF and v13 blocks, DAD); in addition every key met must have a text in the catalog (`lang/en/errors-*.js`) without `{detail}`: the reader's detail stays after the key, never in the sentence of the notice.
- **Bruker reader robustness**: `cargo test --release -p mzlab-lettori --features bruker --test robustness_bruker_keys` passes the same mutations to synthetic timsTOF seeds (TDF MS1, PASEF, row-based TSF): no panic, hang or memory out of measure, and every key met has a text in the catalog without `{detail}`/`{message}`; the unreadable parts are `err.file.brukerDamaged`.
- **Hostile `.wiff.scan` blocks**: `cargo test -p mzlab-core --test robustness_scan_blocks` reads a virtual 8 GB `.wiff.scan` with a block declaring 2^32 points, a 16 MB one at two points per byte and a 2 GB MRM block: `error.memoryBudget`, never an abort. The sums of lengths read from the file (DAD, OLE properties) are checked (`dad::span`, `properties`): on the 32-bit site they do not wrap onto bytes the app does not read.
- **Points of a `.wiff.scan` scan**: `read_scan` trusts the header count up to two points per block byte and refuses with `error.memoryBudget` a scan whose decoded points (44 B each) exceed the target's memory (192 MB the site, 1 GB the app).
- The bench is in `tests/robustness/mod.rs` (per-thread counting allocator, `uno`, `corri`); `ROBUSTEZZA_TRACCIA=1 … -- --nocapture` prints every case before running it.
- **Unused dependencies**: the `rust-lint` job runs `cargo machete`: a dependency that no source of the crate names must be removed from its `Cargo.toml`; locally `cargo install cargo-machete --locked && cargo machete`.
- **Rosina bench** (every reader against an external truth, `docs/studies/ROSINA.md` F): `tools/rosina/` with `verita.py MZML` (→ `verita/1` per `verita-1.json`), `verita_trfp.py`, `verita_timsdata.py` (oracles that run on Mac or Windows, never in the cloud), `scarica.py`, `indice.py` and `mappa_metadati.tsv` (`tests/test_rosina_strumenti.py` checks its coverage).
- **`.wasm` bench** (`python3 tools/banco_wasm.py --variants base,o3,o3simd,o3simd_zrs,mix,mix_zrs [--chromium] [--rounds 5] [--raw]`, `wasm-potential.md` §9): builds `tools/banco_wasm/` (its own `[workspace]`) in every variant with the `wasm-opt` of `tools/wasm_opt.sh`, runs the real `mzlab-core` functions in Node and in Chromium, prints one JSON line per variant and the base → variant table; fails if two variants give different check values. Data in a temporary folder; `--raw` uses a `.raw` from `percorso("dati/HRMS")` (without it, skipped). Times only on the same machine.
- **Rosina bench in Rust**: `crates/mzlab-lettori/tests/common/truth.rs` (F0-F5 with the tolerances of F.2; outcome per file `L`/`P`/`NV`; a defect fails the test), run in public CI by `truth_bench.rs` on built files and the synthetic truth in `tests/rosina/`; on the corpus one `truth_<family>.rs` per family (skipped without data; `MZLAB_ROSINA_RAPPORTO=<file>` collects the report rows). Private nightly workflow: `docs/studies/rosina/WORKFLOW_NIGHTLY.md`.
- **External reference of `convert`** (`python3 tools/external_reference.py [--only NAME] [--json FILE] [--keep DIR]`, tests in `tests/test_riferimento_esterno.py`): converts with `mzlab-cli file convert --compression none` every public file of `tools/external_reference.json` (public names; paths in the data repository) and compares with the msconvert mzML saved next to it: well-formed XML, number and level of the spectra, polarity, RT, precursors, isolation window, selected ion, activation method and energy, arrays, SRM/SIM traces paired by data (Q1/Q3, polarity).
  `expected` ties every known difference to an ID of the external review or to an `RE-n` observation of the manifest and only shrinks: exit 1 for a new difference or for an expectation that now passes. Without data it prints "SKIPPED: no data" and exits 0.
- **Parser fuzzing** (`fuzz/`, cargo-fuzz, separate workspace, nightly): one target for `ole`, `xmltree_methodinfo`, `mzmlhead`, `idxread`, `raw`, `wiff`, `mzlib_msp_mgf` (functions of `fuzz/ingressi.rs`) and one for every reader module (`lettori_<family>`, functions of `fuzz/ingressi_lettori.rs`, tried in `cargo test` by `crates/mzlab-lettori/tests/fuzz_readers.rs`).
- **Reader mutations** (`crates/mzlab-lettori/tests/reader_mutations.rs`, feature `tutte`): for every reader a valid synthetic file cut at every `<`/`>` (text) or on a grid (binary), with changed bytes, hostile u32/f64 words, NaN/inf/huge attributes, rows removed or doubled, BOM, CRLF and garbage tail.
- Every mutant is read in full (index, scans, headers, chromatograms, method, mzML writer) in a thread with 5 s of time: panic, hang or non-finite number = error. Fixed seeds; `MZLAB_MUTAZIONI=N` multiplies the random rounds. `mutated_engine_mzml` also passes the plain mzML through the site route. The cases found are in `finite_numbers.rs` (readers) and `mzlab-core/tests/engine_finite_numbers.rs` (engine).
  Synthetic seeds with `sh fuzz/semi.sh`; run from `fuzz/` with `cargo +nightly fuzz run <target>`. It is not in the required CI: `fuzz.yml` runs it (by hand and every Sunday; a crash uploads the input as an artifact). A fixed crash is saved in `fuzz/regressioni/<target>/` and `crates/mzlab-lib/tests/fuzz_regressions.rs` replays it in `cargo test`.
- **Golden answers in the e2e** (`e2e_lr`, `e2e_rust`, `e2e_hr_albero`, `e2e_hr_mappa`, `tests_e2e/golden_ref.py`, data in `tests/golden/e2e/`): the keys contain the hash of the loaded files, so they exist only for the synthetic files; `verifica.py` always launches them with the synthetic ones, even if the real data are present (`con_golden`). The synthetic ones come out identical on every CPU and Python:
  exp/log/sin from the scalar libm (`_libm`, numpy changes the last bit with AVX-512), m/z from formula rounded (`hr_parent_mz()`: `sum()` changes from 3.12); `tests/test_golden_sintetici.py` checks it.
- **Weight of the start scripts** (`tests/test_peso_avvio.py`): every file of the list `L` of `carica.js` ≤ 100 kB and the total ≤ 1.90 MB (uncompressed); a large, rarely used tool goes behind `loadScript(name)`.
- **Types without a build** (`tsconfig.json`, `tools/tipi/`): three projects `pagina.json` (classic scripts), `moduli.json` (ES modules) and `worker.json` (workers). Every file of `mzlab/web/` and `TP_Mine/` is in one (`python3 tools/tipi/genera_globali.py --verify` checks it and rejects a duplicate top-level name between two classic scripts).
  `globali.d.ts`, `globali-nomi.d.ts` and `stretto*.json` are NOT in the repository (git ignores them): `controlla_tsc.py` rewrites them with `genera_globali.py` at every start; for the editor, in a fresh clone run `python3 tools/tipi/genera_globali.py` once. Hand-written types are in `manuale.d.ts`. `modello.d.ts` describes `MzFile`, `Pannello` and session.
  `tools/tipi/controlla_tsc.py` ("tipi" job) runs `tsc` and compares the errors per file with `base_errori.json`: it fails if a file gets worse or if a new file has errors; the base only goes down (`--update`). A file with `// @ts-check` must be brought to 0 errors.
  `// @ts-strict` in the first lines turns on `strict` without noImplicitAny: the files of `TP_Mine/` and `flow/` are in `stretto*.json` (catch `any`), all the others in `stretto2*.json` (catch `unknown`: in the `catch` the value is narrowed with `const e = /** @type {Lanciato} */ (e_)`, type in `manuale.d.ts`); generated by `genera_globali.py`, zero errors, never in the base.
  `// @ts-noany` (with `// @ts-strict`, in the first 3 lines) adds `noImplicitAny` and moves the file to `stretto3*.json`: every parameter and variable is typed (JSDoc; explicit `any` only for external objects, with a comment); zero errors, never in the base.

`python3 tools/fondi_main.py` does `git fetch` and `git merge origin/main`; if only generated files remain in conflict (`GENERATI` table at the top of the file: schemas `steps-*`/`tools-1`/`records-1`, `mappa.md`) it takes them from main, regenerates them with their tool and concludes the merge; for any other conflict it stops and prints the files. Then `pre_pr.py --fast`. Exit 0 / 1 (human conflicts) / 2 (red checks). A new generated file must be added to `GENERATI`. Test: `tests/test_fondi_main.py`.

`python3 tools/pre_pr.py`: the CI checks in order, stops at the first red. Local (browser present) = full run (clippy if Rust changes, e2e of the changed files); cloud (`CLAUDE_CODE_REMOTE` or Playwright absent) = `--fast` run (map, thresholds, i18n, globals, tsc, e2e imports, CSP hash, fmt if Rust changes, JS syntax if `mzlab/web/` changes, lib tests of `vendor/opentfraw` if it changes: the crate is outside the workspace and no CI job runs them), exit 0 and a notice that clippy and e2e are done by CI; `--full` forces everything (e2e without a browser: exit 2).

If the diff of `pre_pr.py` against `origin/main` touches only documents (list of `tools/ci_solo_doc.py`) it does only map, thresholds, document paths and prints "solo documenti". Test: `tests/test_pre_pr.py`. `tools/check_link_docs.py` (in both runs) rejects in a `.md` a backticked path or a link to a file that does not exist; it skips `docs/studies/`, `docs/archivio/`, `tests/data/`, `vendor/` and the untracked generated files (`GENERATED` in the script); a placeholder is written with `<...>` or `*` so it is not read as a path.

Pre-push hook: `python3 tools/installa_hook.py` puts `tools/hook_pre_push.sh` in `.git/hooks/pre-push` (the SessionStart of `.claude/settings.json` already does it; it does not touch someone else's hook, `--remove` removes it): it launches `pre_pr.py --fast` and refuses the push if it exits with an error (skip with `git push --no-verify`). `controlla.py` warns from 90 % of the cap (450 lines, 22.5 KB) about files touched by more than 5 of the last 50 merges of `origin/main`. The PR template is `.github/pull_request_template.md`. Test: `tests/test_hook_pre_push.py`.

- **Rust toolchain in the e2e**: `tools/prepara_sito.py` installs once the toolchain of `rust-toolchain.toml` with `tools/ci_toolchain.py` (checks rustc, cargo, components and targets; if the installation is broken it removes it and retries; in the e2e jobs the step `python tools/ci_toolchain.py` does it too), then `verifica.py` gives the tests `RUSTUP_AUTO_INSTALL=0`: a test that calls cargo downloads nothing and, without a toolchain, fails at once. Test: `tests/test_ci_toolchain.py`.
- **E2E site like the published one**: `tools/prepara_sito.py` also puts in `site/` the libraries engine (`static/wasm-lib`, `mzlab-lib-wasm`, in its own cargo run) and the reader modules with their `manifest.json` (`static/wasm-lettori`, `tools/build_lettori_wasm.sh` as `pages.yml`): without them, the worker of "Libraries" or the opening of a .wiff/.raw/.d asks for a missing file and the browser writes it to the console as an error. `e2e_safari_ipad` counts as an error every HTTP response from 400 up, also in Chromium.
- **Profile LR benchmark** (`tools/lr_synthetic.py OUT --seed N --jitter DA` + `crates/mzlab-cli/src/flow_lr_bench_tests.rs`): synthetic QTRAP with truth and decoys; the thresholds are the current numbers, raised only with a proven fix; skips without python3/numpy (`MZLAB_GOLDEN_STRICT=1` fails).
- **Interaction fuzzer** (`tools/fuzz_ui.py --seed N --steps K --view data|draw|flow|hr|mix [--tablet] [--minimize] [--replay FILE] [--cycles N]`, smoke `tests_e2e/e2e_fuzz_ui.py`): reproducible sequences of keys, clicks, drags, wheel, resizes, views, synthetic files, language, theme and reloads; after every step it checks page errors, rejected promises, stuck busy, focus lost on the body, duplicate rows, NaN/-0 shown; `--cycles` measures the growth of nodes and listeners. An error writes `fail-<vista>-<seed>.json` to replay with `--replay`.
