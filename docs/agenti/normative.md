# EU and US regulatory lists: builder (`mzlab-cli normative build`)

Area: `crates/mzlab-cli/src/normative/` (native only, `#[cfg(not(target_family = "wasm"))]`), data in `normative/` (`sources.json`, `overrides.tsv`; `lists/`, `provenance.json` and `unresolved.tsv` are the output), tests in `crates/mzlab-cli/src/normative/tests.rs` (unit tests: a `tests/*.rs` file would make cargo also build the binary with `panic=abort` and break `cargo test --workspace --release`) with invented fixtures in `crates/mzlab-cli/tests/data/normative/`. The lists are DATA downloaded on click (package B), never code in the `.wasm` files.

The pure part, with no network or disk, lives in `crates/mzlab-feat/src/normative/` (feature `attributio`): `csvrd`, `entry`, `import_csv`, `resolve` (the core; loading the sources stays in `mzlab-cli`), `rows`, `pack` (package writer), `sidecar`, `official`.

## Usage
- `mzlab-cli normative build --cache DIR --out normative/ [--only ID...] [--update-pins] [--no-resolve] [--allow-large] [--sources FILE] [--overrides FILE]`. `--cache` keeps one file per URL (`DIR/<sha256 URL>` plus `.json` with URL, date, SHA-256, bytes); with a warm cache there is no request and the output is byte-for-byte identical (the clock is read only at the first download).
- Exit: 0 done; 1 a list is `stale` (it keeps the last good CSV, `stale:true` and `error` in `provenance.json`); 2 usage or `sources.json`; 3 different pin; 4 download above 90 MB (`--allow-large`); 5 source, reader or resolver in error; 6 file. Keys `err.normative.usage|sources|pin|large|fetch|parse|io`.
- A list never empties silently: 0 entries is a read error.

## Sources and pins
- `normative/sources.json` (`normative-sources/1`): `resolve` (SusDat on Zenodo, PubChem `CID-Identifiers.tsv.gz` and `CID-Parent.gz`, PUG REST template for the properties, optional DSSTox) and `lists[]` with `id`, `reader`, `urls[{url, sha256}]`, `params` and the labels of study §4 (`jurisdiction`, `instrument`, `citation`, `annex`, `status`, `in_force_from`, `applies_from`, `version_date`, `licence`, `attribution`).
- The pin is the SHA-256 of the bytes read (for the paged Pesticides API, the SHA-256 of the page SHA-256 values); `null` the first time. A different byte stops the build (exit 3); `--update-pins` rewrites `sources.json` after the curator's check.
- `file:PATH` URL: a file downloaded by hand by the user (ECHA SVHC, OEHHA Proposition 65), cached like the others.
- No downloads from the ECHA site: REACH XIV/XVII and CLP Annex VI are read from the consolidated texts on Cellar (phase 2); the `svhc` reader exists only for the user's file.

## Readers (`readers.rs`)
- `eu_water`, `eu_chem`, `us_epa_html`: header-driven table (`params.columns`: `ref`, `name`, `cas`, `ec`, `dtxsid`, `attr[{match,label}]`; `annexes`; `prefix`), with `colspan` and `rowspan` (`markup.rs`, `table_rd.rs`); Cellar XHTML with `Accept: application/xhtml+xml`.
- `us_ecfr`: eCFR versioner XML (gzip), `section` by heading, mode `lines` ("12. Name") or table.
- `eu_ppp`: paged Pesticides API v3.0 (`nextLink`); microorganism = `uvcb`, group = `group`.
- `voci`: file of transcribed entries (`entry_ref;name;cas;ec;attr;kind;group_entry;act`, act cited on every row, optional `inchikey` = `law`).
- `svhc`, `ca_prop65`: user's CSV, separator guessed.
- Every entry is `{entry_ref, name, cas, ec, dtxsid, attr, group_entry, kind}`; `kind` ∈ structure | group | uvcb | inorganic (`entry.rs`). A CAS is found by its form; the check digit only tells the curator that a number may be a typo.

## `resolve` (`resolve.rs`)
Order: `law` (InChIKey given by the act), `susdat` (StdInChIKey and MS_Ready), `pubchem` (CAS → CID → parent → PUG properties in batches of 100, only for the CAS values SusDat does not have), `dsstox` (only where the list gives a DTXSID), `curated` (`overrides.tsv`: `list_id;entry_ref;cas;inchikey;reason`), otherwise `unresolved`. Key: first block of the MS-ready InChIKey (`inchikey_skeleton`). A CAS with two skeletons is `unresolved`, with both in `unresolved.tsv`. `form`: salt (dot in the SMILES, positive charge, listed CID ≠ parent), anion, parent, as_listed.

## Output (`build.rs`)
- `lists/<ID>.csv`: schema A1 plus `entry_ref;ec;dtxsid;form;status`, separator `;`, rows sorted by (`entry_ref`, skeleton, name), readable by `reglists::schema::read_list`. `status` is the row type: `screenable`, `group`, `uvcb`, `inorganic`, `unresolved`. Formula and mass come from SusDat if the recorded form is the MS-ready skeleton, otherwise they are computed from the MS-ready SMILES (`mzlab_feat::chem`).
- `provenance.json` (`normative-prov/1`): per list labels, URLs with SHA-256 and date, coverage `{entries, screenable, groups, uvcb, inorganic, unresolved}`, `csv_sha256`, `stale`.
- `unresolved.tsv`: `list_id, entry_ref, name, cas, reason`; lists not rebuilt (`--only`) keep their rows.
- `lists/`, `provenance.json` and `unresolved.tsv` are committed in `normative/` (decision D1 by Federico: CSVs derived from public legal texts live in the public repository); `normative/README.md` has licences, attributions and the command to rebuild them. ECHA Candidate List and Proposition 65 are never committed.

## Package (`pack.rs`)
- `mzlab-cli normative pack IN OUT` (no network): reads `IN/lists/*.csv` and `IN/provenance.json` and writes `OUT/normative.mzsus` (a `.mzsus` with the `listings` extension, `docs/agenti/sospetti.md`: one row per skeleton of the `screenable` rows with mass and formula, memberships sorted by catalog order and `entry_ref`, rows by mass and key), the 4 MiB zlib pieces `NNN.bin` and `catalogo.json`.
- `catalogo.json` (`normative/1`: format, raw and compressed bytes, SHA-256 of the raw data, `skipped_no_mass`, lists with `tags`, `coverage`, `csv_sha256`, attributions, pieces with SHA-256). Same inputs, same bytes; `screenable` rows without mass or formula (metals and inorganic salts) do not enter and are counted.
- Every list of the manifest also carries `retrieved` (the latest date of `inputs[].retrieved` of its provenance).
- Step `annot.regulatory@1` (`list_membership`, `crates/mzlab-feat/src/flow_regulatory.rs`): compares the identities of an `annot/1` (`entry`, otherwise `inchikey`) with the package via B1 `match_campaign`: same full key = `InChIKey`, same first block = `first block` (stereo, charge or isotopes may differ), never by name or formula; parameters `lists`, `include` (as in `screen.suspects`) and `window` (mass).
- **Imported lists** (optional port `imported_lists`, many `.mzsus`, of `screen.suspects` and `annot.regulatory`): every imported file (`normative-imported-ID.mzsus`) stays a file of its own, never merged into the package; each of its lists is used whole (the `lists`/`include` mask applies only to the package).
  The files are opened after the `suspects` and after the package, so the package memberships stay first. A file without the `listings` extension gives `err.flow.regulatory.imported`. An imported list gives memberships, never a tier: the `screen.suspects` tier comes only from the formulas.
  Provenance: in `screen/1` the `suspect_files` entry has `imported:true` and the SHA-256 of the file; in `annot/1` `regulatory.imported[]` (`name`, `sha256`, `lists`); the `prov/1` already records the SHA-256 of every input; the report adds "Lists you imported: <file> (SHA-256 …)" and `imported[]`.
  On the site `flow-web-suspects.js` reads the port like `suspects` and passes `flow_screen_suspects` the names as `{suspects, imported}` with the `lists` bytes in that order, and `flow_regulatory` `importedNames`/`imported` (`u64` length + bytes per file). Tests: `flow_screen_suspects_imported_tests.rs`, `run_report_tests.rs`, data `crates/mzlab-cli/tests/data/normative_imported/`.
  Interface: in the module of `screen.suspects` and `annot.regulatory` (`flow-inspect.js`) `F.importedLists` (`flow/lazy/flow-imported.js`, loaded after) shows a checkbox per imported list (`libreria-normative.js`: `importedLists`, `importedBytes`; site OPFS `normative-imported/ID.mzsus`, app `lib/stat` + `lib/read` on `normative-imported-ID.mzsus`).
  Ticking it adds the input `imported-ID.mzsus` to the plan (type `library`, SHA-256 on the input, `b64:` content in `S.samplesJson`) and wires it to `imported_lists`; unticking unwires it and removes the input if no other step uses it. The app decodes `b64:` in `flow_stage.rs`. Tests: `tests_e2e/e2e_flow_imported.py`; app = CLI parity in `tests/test_normative_imported_app_parity.py` (`flow_imported_parity.rs`), CLI = wasm in `tests/test_normative_screen_wasm.py`.
- Output of `annot.regulatory`: every row receives `regulatory[]` (`match`, `listed_inchikey`, `membership`), the file the `regulatory` block (lists asked, package SHA-256, manifest of the lists). Native executor `regulatory_job` in `crates/mzlab-cli/src/flow_screen_suspects.rs`; on the site `flow_regulatory` of the `attributio-all` `.wasm` (`flow/lazy/flow-web-suspects.js`, operation in the `feat-worker.js` worker).
- "Regulatory lists" section of the `corsa/1` report (`crates/mzlab-core/src/flow/run_report_reg.rs`): heading "Screened against: …" with version, retrieval date and SHA-256 of every list, one coverage row per list, table with the "Listed in" column and the membership row "<instrument>, <entry> (<list text>), version of <date>", warning of study §7; the words are written by Rust, `flow report` and `rapporto-flow.js` show them. `tests/test_normative_wording.py` rejects verdict words (detected, present, non-compliant, exceeds, violation, contaminated).
- `mzlab-cli normative listings PATH`: the `listings` JSON of a package folder (with `normative.mzsus`) or of a `.mzsus`.
- Site: `pages.yml` (job `packages`) builds `mzlab-cli` and runs `pack` on `normative/` towards `site/static/normative/`, with a cache keyed on the CSVs.
- `mzlab/web/normative-scarica.js` (ES module, loaded only on first use) downloads the catalog and the pieces into the Cache Storage `mzlab-libs`, checks every SHA-256 and the total, decompresses with `DecompressionStream("deflate")` and gives the raw bytes; `ensure()` uses the cache if the catalog is the same (or the site does not answer), `check()` compares the catalogs and does not download; texts `normative.dl.*` in `lang/{it,en}/normative.js`. Test: `tests_e2e/e2e_normative_scarica.py`.
- "Regulatory lists" section of the Libraries window (`mzlab/web/libreria-normative.js`, ES module mounted by `libreria-corpo.js`): one row per list of the installed catalog (instrument, jurisdiction, status, version, coverage `normative.lib.coverage`, checkbox; ticked by default the statuses `in_force` and `adopted_not_applicable`) and at the bottom the report warning (`normative.lib.disclaimer` = `corsa_reg::DISCLAIMER`, checked by `tests/test_normative_wording.py`).
- "Download the lists" and "Check for updates" of the section: on the site `normative-scarica.js` on `static/normative/`; in the app the routes `normative/install`, `normative/check` and `normative/catalog` (the same bytes as `catalogo.json`).
- The ticked lists are kept in localStorage `mzlab.normative.sel` as `{lists, include}` (`include` = statuses beyond the base ones among the ticked; none ticked = nothing); the "Use Library lists" button of the `screen.suspects` and `annot.regulatory` module (`flow/lazy/flow-form.js`) copies them into the step parameters. The mask belongs to the engine alone (`regulatory::Package`). Test: `tests_e2e/e2e_normative_panel.py` (invented package, no site or cargo).
- Reader in the `.wasm`: `normative_listings(raw)` in `crates/mzlab-feat-wasm/src/finder.rs` (feature `finder`, group `hr`); parity with native in `tests/test_normative_wasm.py`.

## Import of an official file (`mzlab_feat::normative::official`)
- `import_official(reader, csv, sidecar, label) -> u32 LE + JSON summary + .mzsus`: `reader` ∈ `svhc` | `ca_prop65`, `csv` the user's file (BOM removed, separator guessed), `sidecar` the text of `mzlab-cas/1`, `label` `{"file","date"}` (the date is given by the caller). The list has id `SVHC` or `CA_PROP65`, `status` `in_force`, citation "imported by you on <date> from <file>, SHA-256 …"; CAS values the sidecar lacks stay `unresolved` and are counted and listed in the summary.
- Sidecar `mzlab-cas/1` (`sidecar.rs`, written by `tools/genera_sospetti.py` in `<package>/cas/` with `catalogo.json` in the `normative/1` keys): TSV text `cas key ms_key formula mass form ms_smiles`, one SusDat record per CAS; the choice of the record and the refusal of a CAS with two skeletons are those of `resolve` (`pick_susdat`).
- CLI: `mzlab-cli normative import-official READER CSV SIDECAR OUT [--file NAME] [--date YYYY-MM-DD]` (`.mzsus` in OUT, summary on stdout). App: `POST normative/import-official?reader&file&date` (body = CSV; downloads the sidecar from the site the first time, `normative-cas.tsv` in the libraries folder) writes `normative-imported-ID.mzsus` and `.json`; `normative/imported` gives `{"lists": [...]}` from the manifests. Never uploaded.
- Site: own lazy module `wasm-feat/normative/` (crate `mzlab-normative-wasm`, bridge `mzfeat-normative/1`: `import_official`, `lists_of`; `normative` manifest entry with SHA-256; 235 306 B, cap 512 000), loaded only by the Library window.
- Import on the site: `normative-importa.js` runs it in `normative-importa-worker.js` (not in `feat-worker.js`) with the sidecar from `normative-scarica.js` (format `mzlab-cas/1`, Cache Storage `mzlab-libs`, from `static/mzfinder/sospetti/cas/`); the worker writes OPFS `normative-imported/ID.mzsus` and `ID.json`.
- The "Import an official file…" button is in `libreria-normative.js` (selector `#lib-reg-kind`, button `#lib-reg-import`); imported lists appear without a checkbox (they are not yet chosen for the Flow `lists`). Parity CLI = app = `.wasm`: `tests/test_normative_import_parity.py` and `normative_tests.rs`.

## Words and choices
- **Words** (`run_report_reg.rs`, the same in the CLI and in the page): mzLab says what a candidate corresponds to, never what a sample contains nor whether it complies with a law. Column "Listed in"; cell "Candidate formula … matches N listed substances" (mass route) or "Candidate structure matches a listed substance (InChIKey)", with "first block" if stereo, charge or isotope may differ; the warning says that a match is not an identification, does not give the concentration and does not assess compliance.
- **Forbidden words**: "detected", "present", "non-compliant", "exceeds", "violation", "contaminated".
- **Choices**: lists built from public texts live in the public repository (`normative/`), built in native Rust (`mzlab-cli normative build`); regulatory screening is per user, on HR data; ECHA Candidate List and Proposition 65 are imported from the user's official file, never committed; the TSCA inventory stays out; proposals and drafts are marked lists (`proposal`, `draft`); the text of the legal limit is shown as a citation, never compared with a measurement; CAS values are written as printed in the law.
