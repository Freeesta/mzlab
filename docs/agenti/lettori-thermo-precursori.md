# Thermo `.raw`: activation and precursors
How `vendor/opentfraw` and `crates/mzlab-core/src/rawreader/extra.rs` name the activation, what stays unknown, and which precursors a scan gives (filter, scan header, mzML). The rest of the reader is in `docs/agenti/lettori-modulo.md`.

- Activation of a step: the reaction's own code (`Reaction::activation`, bit 0 set; a code the Thermo enumeration does not name is unknown); without one, the final step falls back on the preamble only for the codes seen in real files (`CONFIRMED_ACTIVATION_CODES`: 1 HCD, 4 CID or HCD on FTMS) and an earlier step stays unknown.
- Unknown is written as `opentfraw.activation = unknown` (both mzML writers, scan header), an mzML `<activation>` without a dissociation term and a filter clause without `@<activation>`; `rawreader/extra.rs` maps CID to `MS:1000133` on every analyzer, as the writer of `opentfraw` does.
- A v66 scan-event table that no known layout (nor the count) walks to its end is not read: `Warning::Skipped` «ScanEvents» with `Error::EventTableMisfit` in `metodo/1.avvisi`; the scans then have no event (no polarity, no filter, MS level unknown). `RawReader::losses` says so with its own cause `warn.raw.eventsRefused` (`EVENTS_REFUSED`): declared = index rows, read = scans with an event (`ScanMetadata::has_event`); `conv/1`, the CLI (exit 3) and the loading row («n of N scans without their scan event», `conv.row.noEvent`) show it; a cut file keeps `warn.file.truncated`.
- The thermo module hands the cause of its losses to the engine (`cause(h, c)`, `ExternalReader::losses`), so the site row says what the app row says.
- MS level (`ScanMetadata::ms_level`, `Option`): SRM is 2 and a v66 Q3 full scan is 1 (as RawFileReader reports them); any other scan has a level only from its event, so a scan without a readable event (or an undefined MS power) has none. mzLab writes it as `livello` 0 (index and spectrum), and its mzML has neither `ms level` nor a spectrum type; the `openmassspec-core` record gets 0.
- Precursors (`mzml.rs` `scan_metadata_with`): target = final reaction m/z, else trailer `Target M/Z`; selected ion = trailer monoisotopic m/z only if `plausible_selected_ion` (in the window or ≤3 isotopes below), else the target, and `ScanMetadata::selected_ion_rejected` marks the scan (counted in `raw::ScanNotes`: `meta.ioneScartata` in `metodo/1.avvisi` with «N of M scans»); in an MSn chain the trailer ion and charge go to the first step, every step keeps its own energy (trailer energy only for a step without one).
- mzML precursors (`rawreader/extra.rs` `precursors`): MSX = one per reaction with the shared trailer width and `msx` in the filter; MSn chain = one per step, final step first (its SPS ions from `SPS Masses`/`SPS Mass N` when present). SRM: Q1/CE, filter and traces from each scan's event (`srm_transition`, `srm_traces`), the transition table only without events (`ScanMetadata::srm_from_table`: `meta.daTabella` in `metodo/1.avvisi` with the count); no assumed Q1 width. The reader counts the notes while it builds its index, `raw::method` reads them once (`ScanNotes::of`): same document.
- Unverified or refused scans (`ScanMetadata`, counted in `raw::ScanNotes`, `meta.nonDecodificato` in `metodo/1.avvisi` with «N of M scans»; no value changes): an MS order `MsPower` does not name (byte 6: precursor-ion, neutral-loss, MS9+; `ms_order_unknown`) leaves the level 0 while the filter text still says `ms`; an event found by number in a table the open cut short (`events_by_class`, `by_class_in_cut_table`) is passed on unchecked.
- Profile calibration (`scan_data::calibration_known`): a count of coefficients other than 0/4/5/7 is refused (`calibration_unknown`, `meta.nonDecodificato`), never given in frequency units; that scan is not decoded.
- Damaged units (reader rules R1-R3): a scan whose index entry points past the end of the file (`robust::kept_prefix`, found at open, `RawFileReader::damaged`, `Warning::Skipped` «ScanData») or whose record does not decode (`raw::scan_or_row`, found when the scan is read) keeps its row (time, level, number, no `position`) with no points and is counted with cause `warn.raw.damaged` (`RAW_DAMAGED`): declared = index rows, read = rows with points; a last entry past the end looks like a cut and counts as `warn.file.truncated`. Only a file with no readable scan is refused.
- Controllers: a run header that cannot be read is skipped with `Warning::Skipped` («RunHeader» before the MS one, «AnalogTrace» with «n of M controllers» for an analog one, `analog_traces_counted`) in `metodo/1.avvisi`; the MS scans, the TIC and every other channel load. The file is refused only when no MS run header is readable.
- Where the count shows: damage found at open is whole in `conv/1` (header of the mzML), the CLI (exit 3), the site and app loading row (`conv.row.damaged`); damage found while decoding is known only after the scans are read, so it reaches the loading row (index build) and a stderr line of `write_mzml_with` (exit 0), not the `conv/1` written before the spectra. The site rebuilds the cause from `missing` (`ExternalReader::losses`).
