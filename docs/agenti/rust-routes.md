# Rust engine in the page: routes and Thermo files
Part of the Rust engine (`docs/agenti/rust.md`).

## Rust engine in the page
- The Rust engine is the only engine of the page (no switch, no fallback): without WebAssembly, OPFS or `Worker` the page says `load.err.oldBrowser`. A request the engine cannot serve answers 501 `err.route.unavailable` and is listed in `window.MZLAB_LR_MISS` (empty in every site e2e).
- **One file, one reader**: for every whole file (not a `#` part of a mixed file) the Rust worker opens its `.mzidx` from OPFS (`mzlab/idx/<name>.mzidx`, operation `idxopen`; `Engine.open_index` in `mzlab-wasm`) and answers without reading the mzML. The mzML is opened (`openMzml`, `stats.mzml`) only for what asks for spectra (`api/spectra`, the first time) or when the file has no index (no OPFS) or no scans (MRM).
  `rust-bridge.js` dispatches: `chrom`, `filters`, `scanlist`, `nearest_scan` (`Engine.route`, which gives the JSON of `api.py` or the empty string = not its own) and `xic` (`Engine.index_xic`, one element of `traces` per file); `ref=` (difference from a reference file) goes to `rust-diff.js` (`Engine.diff_traces` for `chrom`/`xic`, `mrm_diff_post` for `mrm` from the transitions of the files; `diffroute.rs` + `difference.rs`; `""` = not its own, `"E"` + JSON = error with a user key); a `kind` other than `tic`/`bpc`/`pda` is not served.
- The index reader lives in `mzlab-core`: `idxread.rs` (`Index<R: ReadAt>`: header, metadata, scan table, per-scan arrays, `search` = `np.searchsorted`: the `fence` picks the block of 16384 peaks (one read), the cache of 8 blocks evicts the least used, `sum_window`/`max_window` sum in the table order like `np.bincount`), `routes.rs` (`Routes::handle`, `xic`; `Query`, which decodes like `URLSearchParams`),
  `scantable.rs` (the scan table read from the mzML headers alone, without regex: `scantable::read(&mut ReadAt, size)` gives the rows of `SCAN_COLUMNS` as JSON, `nce`, `hr1` and the number of chromatograms; test `tests/scantable_parity.rs` against the rows written by Python, all equal on synthetic files and examples),
  `rois.rs` (`build_rois` and `extract_trace` of `ionfamily` from the index: same assignments and same sums; test `tests/rois_parity.rs` against `tools/roi_reference.py`; rows with the same centre have no fixed order in numpy and the test sorts them), `json.rs` (minimal reader and writer, `round` like Python's `round()`, `fmt_g` like `format(x, "g")`). Errors are i18n keys; `Ok(None)` is never an error: it means "not served".
- Parity: `crates/mzlab-core/tests/routes_parity.rs` compares the routes with `tools/routes_reference.py` (Python `dispatch` on synthetic files and examples: all levels, m/z windows, `bpc`, `filt`, `prec`, filters, `scanlist`, `nearest_scan`, XIC; identical indices and counts, numbers within 1e-9); it skips without python3 and numpy (`MZLAB_GOLDEN_STRICT=1` fails). `e2e_rust` (site and `.wasm` built) compares Rust with the golden data `tests/golden/e2e/` (`tests_e2e/golden_ref.py`; rewritten with `MZLAB_UPDATE_GOLDEN=1` and `tests_e2e/pyref.py`, which the suite does not run)
  and proves that no mzML (except MRM) was read by Rust to draw the TICs.
- `browser.js` hands to `rust-bridge.js` every GET of the routes in `RUST_ROUTES` (`chrom`, `xic`, `xicbin`, `spectra`, `spectrum`, `dda`, `mrm`, `filters`, `scanlist`, `nearest_scan`, `scaninfo`, `scan`, `scanavg`, `scanbin`, `scan_axis`, `ms2tr`, `fileinfo`, `masscal`, `msntree`; header `X-Engine: rust`); the others go to `lr.js`. An MRM file has `chrom` from the chromatogram of the mzML and the page uses `mrm`. The MRM and polarity parts of a mixed file have a place of their own; the polarity part reads the `+`/`-` sections of the index (`Routes::pol`, operation `idxopen` with `pol`).
- `rust-worker.js` (module) loads `static/wasm/` (built by `pages.yml`, with `simd128`: one binary) and keeps a set of `ArrayBuffer`s returned by `recycle`; the bridge sends them back after building the JSON.
- Supervisor (in `rust-bridge.js`): if the worker dies, it terminates it, creates a new one, reopens the files of the session (`api/explore`; index and, if needed, mzML) and shows `error.engineRestarted`; a second death within 1 minute stops the engine (`error.engineFallback`: "reload the page"; requests answer `load.err.engineLost`). `window.MZLAB_RUST` = `{enabled, disabled, stats, crash(), stop()}` for the tests and for `reset.js`. Test `e2e_rust`; `python3 tools/bench.py` measures the engine, table in `docs/agenti/measurements.md`.
- **Files and session** (`lr.js`, started by `lrInit` in `browser.js`): answers, with the JSON of `api.py`, `upload`, `state`, `session`, `explore`, `meta`, `remove`, `new`, `notebook`, `spazio`, `contaminants`, `perf`, `formula` and, in `lr-method.js`, `method`, `method_warnings`, `analog`, `delay`, `chrom?kind=pda`, `gradient` and `gradient_parse`;
  the `lr_*` operations of `rust-worker.js` write the files to OPFS, build the index (scan table with `prepare_upload`, index with a worker of the `idx-worker.js` pool: a worker that dies twice fails the file with a keyed error, there is no fallback builder), open the index and produce the list row (`lr_entry`) and session items (`lr_items`);
  IndexedDB `qqq_lab` keeps the notebook and, from an old visit, the files that `lr_boot` moves to OPFS (`lrMigrate`). At startup a file in OPFS without an index (interrupted upload) is indexed again; with `?riparti=1` `lr.boot(true)` reads neither the database nor the notebook (another tab may hold it: `within(…, 5000)` in `lr_clear`). The bridge also answers `spectrum`, `mrm` and `scaninfo`; every item of the session (every part of a mixed file too) has its own slot.
  Engine errors with a key (`e.raw` JSON) go back to the user with status 400; any other error or unserved route is `err.route.unavailable`. The load screen shows `load.blocked` if another tab holds the database (`onBlocked` of the bridge) and, after `?ripresa=` ms (30 s), `load.err.resumeTimeout` with "Start from scratch".
  Test: `tests_e2e/e2e_lr.py` (network requests counted, JSON equal to the golden data `tests/golden/e2e/` (`tests_e2e/golden_ref.py`), reload) in the "site" job of `sito-rust.yml`, which runs all the site e2e with the `.wasm`; `e2e_mzidx` and `e2e_avvio` test OPFS, the migration from IndexedDB and the blocked startup.

## Inventory of the `api/...` routes (who answers)
**Rust** = the engine answers from the index or without a file (`Routes` in `mzlab-core`, `lr.js`, `lr-map.js`, `lr-origin.js`); **JS** = `lr.js` alone. A case the engine does not serve answers 501 `err.route.unavailable` (entry in `MZLAB_LR_MISS`); Python is only the reference of the tests. A route is born in Rust with parity (`tools/*_riferimento.py` + `crates/mzlab-core/tests/*_parity.rs`) and the `e2e_lr` test.

## Thermo `.raw` files
- Site and desktop app: the `.raw` is read as it is (`native-reading.md`): the index is built from the reader (site: `natives.rs` opens it in 1 MB blocks from `File.slice`; desktop: mapped file, `rust-desktop.md`) and the mzML is written only on request (`native_to_mzml` / `nat2mzml`). The data are the instrument's (centroids or profile as in the file); no choice box.
- `rawToMzml` in `shell.js`: `.raw` files become `x.mzML` samples (`NATIVO.raws`) read as they are. The single notice with the guide "Don't have mzML files?" (`data.md`) appears only for the formats the engine does not read; `#dropraw` tells on the load screen that `.raw` files are accepted.
- Download (`conversione.js`, `CONV`; `tests/test_conversione.py`): the download menus (mzML, mzML + Numpress) only in the load table (in sequence, no zip), with the progress panel (`ConvUI`: scans written, MB written, elapsed time, never an estimate of the remaining time; `aria-live=polite`, still dot with `prefers-reduced-motion`).
  Browser: the mzML goes to `conv/` of OPFS (`rust-opfs.js`, `SyncAccessHandle`) and is downloaded as a file; an incomplete write stops with `error.quota`; cancel and error delete the file.
  Desktop app: native save dialog (`window.MZLAB_SAVE_MZML` → Tauri command `save_mzml`, permission `dialog:allow-save`; Blob with `mzlabId` = number of the mzML on disk). Cancel = `AbortSignal`: the bridge terminates the worker and starts another (the session files are reopened, no notice).

- Parity: `crates/mzlab-core/tests/raw_parity.rs` compares the `.raw` with the msconvert mzML (m/z 1e-6, intensity 1e-4, relative) only if the private data repository is there (`MZLAB_DATI` or `mzlab-dati` alongside); never a `.raw` in the public repository. `cargo run --release --example raw2mzml -- IN.raw OUT.mzML` converts from the command line. The `.raw` step of `e2e_rust` is skipped without data.
- The selected precursor may differ from msconvert by a few MS2 scans (monoisotopic correction of OpenTFRaw); the MS2 spectrum does not change.
- **mzFinder LR (`finder_lr`)**: the low-resolution Dig of mzFinder is not a `/api/...` route: it is served by the mzFinder worker with `wasm-feat/finder-lr/` (`crates/mzlab-finder-lr-wasm`, on top of `mzlab_feat::legacy::lr`) and the pool of `feat-worker.js`; details in `docs/agenti/mzfinder-lr.md`.
- Desktop, mzFinder (`rpc`, `feat.rs`/`feat_finder.rs`): `feat/detect`, `feat/align`, `feat/hypotheses`, `feat/evidence`, `feat/table`, `feat/clear` and `finder/classify|plan|dig|detail|inclusion_csv|frag_tree|frag_tree_compare|formula_info|identity_graph|polarity_pairs|origin_evidence`; same functions and same bytes as the `.wasm`.
