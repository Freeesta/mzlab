# Samples: file roles, times and metadata (`samples/1`)

One Rust model of the roles and times of the files of a series, for the Data view and for mzFinder: `crates/mzlab-core/src/samples/` (`mod.rs` types and `route`, `names.rs` name parser, `validate.rs` warnings and indices for the TP path, `json.rs` canonical JSON). Schema: `docs/schemi/samples-1.json`. Tests: `crates/mzlab-core/tests/samples.rs` (with `tests/samples3/` for the metadata and free columns). The document also carries the metadata of the physical sample (last section).

## Model
- One `Sample` per file, in injection order. JSON fields and values in English: `file`, `sha256` (the key; empty if not yet known), `kind` ∈ `sample t0 blank dark infusion std calibration qc pool` (`pool` in `per_tp` goes with `qc`), `blank_kind` ∈ `solvent procedure wash` or null (optional: solvent and procedure are subtracted the same way; a `wash` is a rinse, in `per_tp` it goes with the standards: neither reference nor sample, no warning if missing), `time` + `time_unit` ∈ `s min h d` (as written or confirmed),
  `time_min` (derived, the only one used in calculations), `time_confirmed`, `series` (`""` = the only one, or shared by all), `replicate`, `concentration`, `concentration_unit`, `injection_order`, `istd`, `note`, `compound` (for `infusion`, filled by mzFinder).
- `Sample::role()`: a `sample` at 0 minutes counts as `t0`. `set_time` derives `time_min` (`minutes_per`). The Data view never writes `kind: t0` or `blank_kind` (a sample at 0 minutes and a single Blank type) and the time of the `dark` is negative; Rust reads `t0` and `blank_kind` and `SAMPLES_DOC.fields` converts them.
- `to_json` is canonical (keys in alphabetical order, same bytes) and `digest` is its SHA-256; `from_json` rejects invalid schema, types, units and numbers (`error.badSamples`) and recomputes `time_min`.

## `propose(&[(name, sha256, kind)])`
- One name parser, times always with `time_confirmed = false`. Time = last number with a unit or prefix `t` (`Smp_01_30h_2` = 30 h; `Run_5` no time). Role and minutes follow `project::guess_sample` (same minutes on the generated names of `project_parity`, checked by the test), with in addition: seconds (`90 s`, `90s`), the replicate written `(2)` at the end of the name, infusion (`infusion`, `infusione`, `direct-infusion`, `FIA` or `kind == "msn"`), the dark (`dark`, `buio`, `adsorption`, `control`, `ctrl`), `blank_kind` from `solv…`/`proc…`.
- Blank words from the name (`wash`, `MQ`, `milliq`, `milli`, and `H2O` only as a whole token, never `H2O2`: table `crates/mzlab-core/data/blank-names.json`, `blank_words.rs`) give `blank` only if every other token is a number or neutral (`pos`, `neg`, `q`, `init`); with `wash` the `blank_kind` is `wash`: with a time or series (`MQ_PMS_T00`) the file is a sample.
- With at least two different first words of 2-4 letters, each at the start of two or more names (`TW_`, `MQ_`), `propose` writes the `matrix` on all files and the `group` `MAT-COND` (series without matrix) on those with a time; a single first word proposes nothing; the user changes everything with the name template or by hand.
- `finder_base/sample.rs::guess` (mzFinder, golden `tests/golden/feat/finder.json["guess"]`) delegates to `samples::role_and_minutes` (same logic as `propose`, without series or replicates) (blank→blank, dark→control, std/calibration→standard, other→sample; time only for samples). In `names.rs`: `control`/`ctrl` mean dark, "m" alone means minutes only after "t" (`t30m`; `S_30m` has no time), "(" closes the time (`x_t30min(2)`).
- The time is a whole token (start, end, space, `_`, `-` or parentheses around it; never inside a word: `H20`, `80-20`, `blk 90-10` have none): `t0` `t=0` `t 0` `t30` (minutes) or number + unit, with or without a space (`3h`, `3 hr`, `8hrs`, `30 min`, `T=3h`; units `s sec secs second(s)`, `min mins minute(s)`, `h hr hrs hour(s) ore`, `d day(s) gg giorno giorni`, `m` only after a `t`).
  Hours with minutes: `1 h 30`, `1h30`, `1h 30min` (two digits below 60, or with `min`; `3h_15` and `3h 2` are replicates). `d1` (day written first) only if the name has no other time. The last one wins; a bare number (`Run_5`, `80-20`) never; anything not in the list gives no time. Code `samples/time_token.rs`, table of cases `crates/mzlab-core/tests/samples_time.rs`.
- One refresh path: `renderFileList` (`explore.js`) ends by firing the `filelist` event, and the sample table (`samples-table.js`) and the loading table (`shell.js`, which first pulls roles, times and concentrations of the open files with `pullOpen`) repaint from it, except the one being typed in, which repaints itself on commit; so rename, delete, group, role, experiment, time and unit show in all three views at once.
- File list: a sample with no time text of its own (SIM, MRM, MS2) carries a mute tag with the time read from the name or written in the table ("t0", "3h", "90min", always in the unit of the table's Time selector, updated live on change; `timeTagUnit` and `timeBadge` of `ordine.js`, `title` and `aria-label` `files.time.title`), only if there is one; "Group by" offers the time (variable `time`, from the names).
- Without a unit in the name the time is proposed in minutes. A number before `ppm`, `mg/L`… is a concentration, not a time (`X25ppm_t10` = 10 min). Concentration only for standards and calibration. Infusion and QC have no time.
- The role words are searched in the name with the folders, like the roles of the model; the time in the name without folders or extension.
- `series`: the prefix before the time (`X_TiO2_t005min` → `X_TiO2`); if the files with a time have a single non-empty prefix, all are `""`. A file without a time takes the longest series its name starts with, otherwise `""`.
- Replicates numbered per series, role, minutes, concentration, polarity and matrix (`number_replicates`; `propose` leaves polarity and matrix empty); the replicate written in the name wins.
- `table_kind_of_name(name)`: the role a name gets without the infusion words, for `mzlab-feat/src/samples.rs` (the table model has no infusion role; this is not a converter of another format).

## `validate(&[Sample]) -> Vec<Warning>`
- `Warning {code, severity, file, series}`; stable codes, the pages supply the words. JSON `{"warnings":[{"code","severity","file","series"}],"blocking"}`; `blocking` if there is an error (mzFinder does not start).
- Per file (errors): `timeMissing` (sample without a time), `timeUnconfirmed` (sample, even at 0 minutes, with an unconfirmed time), `t0WithTime` (`t0` with a time other than 0).
- Per series (the files of the series plus those with an empty `series`): `noControls` (error: no t0, no blank, no dark), otherwise `noT0` and `noBlank` (warnings) and `noDark` (information); `onePoint` (warning: a single treated time); `replicates` (information: two treated with the same time and concentration).
- Overall: `noTreated` (error: no sample; with `noControls` if the controls are missing too), `noInfusion` (information).

## `per_tp(&[Sample]) -> PerTp`
- 0-based indices by role: `treated` (sample with time > 0), `t0`, `blank`, `dark`, `infusion`, `std` (with `calibration`), `qc`, `untimed` (sample without a usable time).
- `minutes[]` compatible with `feature_pipeline/3` (`parent.minutes`): the time of the treated, 0 for the t0, null for all others; infusion is null and lives only in its index, never among the controls.

A document with other key names is refused (`error.badSamples`).

## Binding
- One function per engine: `samples(op, json)` in `mzlab-rotte-wasm/src/lib.rs` (Data view) and in `mzlab-feat-table-wasm` (mzFinder), with `op` ∈ `propose` (`{"files":[{"name","sha256","kind"}]}`: a `samples/1` with matrix and group), `validate`, `per_tp`, `canonical` and `digest` (canonical JSON and SHA-256). JSON errors `{error_key, params}` (`error.badSamples`).
- mzFinder links only `route_finder`: `propose`, `validate`, `per_tp`, `canonical`, `digest`; `propose_explained`, `relink` are served by the site from `rotte` and by the app from `finder/samples` with `route` (same bytes: `route_finder_same_bytes_as_route`; guard `test_finder_ops_are_in_route_finder`).
- `mzlab-core/src/project.rs` remains for parity with the Python of the main program.

## mzFinder Pipeline panel (`TP_Mine/files/finder-ruoli.js`, `TP_Mine/js/34_pipeline_run.js`)
- The functions of `finder-ruoli.js` that call Rust (`build`, `check`, `forTp`, `canonical`) are async: the `call` is the table's `.wasm` binding on the site and the native route `finder/samples` (`pool.samples`) in the app; `stemOf` also strips double extensions (`x.mzML.mzidx` of the app).
- The notebook keeps the roles in `NB.samples` (canonical `samples/1`, one entry per file, key = `.mzML` name). `build` starts from there; for files without an entry it proposes the roles from the names with `propose` (unconfirmed times).
- The panel shows a file/role/time table (native `select` and `input`, `aria-label`, focus restored after every edit) with a single unit selector; the proposed time is yellow until you confirm it (Enter or "Confirm times"). Short warnings in `role=status` come from the `validate` codes; "Run" is off, with the reason in the `title`, if `validate` is blocking.
- The pipeline receives `minutes[]` from `per_tp` and the canonical `samples/1` (`samples` of the parent → `build_evidence_to`, optional trailing parameter: TP gate 1 reads the roles, infusion is never a control); the run log also carries the `samples` operation (canonical JSON and SHA-256 from Rust); Feature QC uses roles and minutes of the model.

## `relink(&[Sample], &[(path, sha256)]) -> Vec<RelinkMatch>` (`samples/relink.rs`)
- Finds moved or renamed files: first by SHA-256 (among identical copies the same name wins), then by name without folders (`/` and `\`) only if at least one of the two SHA-256 is unknown, with `by_name = true` (the page asks for confirmation). A known, different SHA-256 is a replaced file: never matched by name. A candidate serves only one file; a name shared by several free candidates is not guessed. Candidates are read in path order: same answer for any order. Test: `crates/mzlab-core/tests/relink.rs`.
- Binding `samples(op="relink", {"samples","file":[{"path","sha256"}]})` → `{"matches":[{"index","by_name","path"}]}`.
## `order_like(text, names) -> Result<String>` (`samples/order.rs`)
- Puts the files of a samples document (`samples/1`, other fields kept) in the order of a table's files, matched by name without folders: exactly first, then without the extensions of `EXT` (`T5` = `T5.mzML` = `T5.mzML.mzidx`). Same text when already in order, or when `names` is empty or has an empty name (a table that does not record its files).
- A table file with no sample, or a sample naming no file of the table, is `error.badSamples` with `file`. The readers of the roles pair by position, so every step that holds a table calls it first with its meta `inputs` (`mzlab_feat::store::input_names`/`table_names`, `TpRoles::for_table`).
## Experimental design (`design/1`, `crates/mzlab-core/src/design/`)
- A plan datum (type `design` of `step/1`) with the conditions, the reference, the comparisons, the factors and the batches; schema `docs/schemi/design-1.json`, test `crates/mzlab-core/tests/design.rs`. It decides nothing: it proposes from the files and the user confirms; no statistical comparison.
- Canonical JSON (keys in alphabetical order, factors sorted by name, batches by `sha256` then `file`, levels by factor): same bytes for every permutation of the files, `digest` = SHA-256 for `prov/1`. `error.badDesign`.
- `conditions[]` = `name` (a `series`; `""` if it is the only one), `replicates` (the minimum number of `sample` files among the times of the condition, derived) and `levels` (factor → value). `comparisons[]` = `{kind:"pair",a,b}` or `{kind:"vs_reference"}` (every condition against `reference`). `factors[]` = `{name, values[]}`. `batches[]` = `{file, sha256, batch}` (the key is the SHA-256 if known; default `"1"`).
- `propose(&[Sample]) -> Design`: conditions from the `series` of the `sample` files in injection order; reference = the first called `ref…`, `reference`, `control` or `no gas` (with "all against the reference" if the conditions are ≥ 2); a single batch.
- `validate(&Design, &[Sample]) -> Vec<Warning>` (same `Warning` as `samples`): `fewReplicates` (warning, per condition with fewer than 3 replicates), `batchNoQc` (warning, per batch with samples without a QC before the first and one after the last), `emptyComparison` (error, condition without `sample` in a comparison), `refMissing` (error, "against the reference" without a reference).
- `route(op, json)`: `propose` (a `samples/1`), `validate` (`{"design","samples"}`, answer like `samples.validate`), `canonical`, `digest`.

## Positions in the name (`propose_explained`, `samples/positions.rs`)
- `propose_explained(files) -> Vec<Proposta {sub_sample, positions}>`: the same values as `propose` (which is a wrapper of it) and, for each proposed field, the part of the name that decided it, in characters of the whole name (folders included), end exclusive: `kind` (the role word, or the time for a `t0`), `blank_kind`, `time` (number and written unit; without a unit only the number), `series` (the prefix), `replicate` (the written `(2)`), `concentration` (number and unit, or the number after the standard word).
- A field whose part is not found has no position (a bare `sample` has none); a name with capitals that change length: no position.
- Binding `samples(op="propose_explained", {"files":[...]})` → `{"samples":<samples/1>,"positions":[[{"field","end","start"}]]}`, one list per file in file order. Test: `crates/mzlab-core/tests/samples.rs` (values equal to `propose` and positions inside the name on the over 30 000 generated names).

## Variables in the names (`samples/variables.rs`, `variable_classes.rs`)
- `samples(op="variables", {"files":[{"name"}], "manual"?: {"pos":N,"sep"?} | {"has":[terms],"substring"?}})` → `sample-vars/1` (keys in alphabetical order, schema first): `common` (equal part at head/tail, `MQ*T00`), `files[].tokens[]` `{class,end,start,text}` (characters of the whole name; classes `folder matrix role time conc rep cond num word`), `variables[]` `{coverage,id,kind,score,values[{files,key,label}]}`, `manual` (same shape, `multiple` for `has`).
- `id` ∈ `matrix cond time role matcond conc rep folder pos:N has`. `group_name` (`{"names":[..]}` → `{"name"}`): the common tokens in the order of the first, with the most frequent separator (`""` if none). Limits 5 000 names and 256 characters: `error.badSamples` with `limite`. Same bytes for every permutation of the names (except the order of `files[]` and the indices).
- Role, time and concentration belong to the name parser (`role_and_time`, `guess_conc`); the `t0` role counts as `sample`. A name without separators (`MQH2O2T00`) is cut into atoms (known word, chemical piece with element symbols, `T00`); `H2O2`, `TiO2`, `Na2SO4` stay whole.
- Matrix = first word of letters only (neither role nor condition) with 2-6 values on ≥ 2 files each; condition = the tokens between matrix and time (without a time no value: `BTZ`, `mid`, `Wash` are not conditions); replicate = number ≤ 20 at the end if the same name without it appears with another number.
- Score = coverage × balance (1 − normalized Σp², only + × /: same bits in `.wasm` and app). Hidden: constants, identifiers (categorical with one file per value, ≥ 3), score < 0.05. Order: above 0.25 the fixed `matrix cond time role matcond folder`, then by score (`conc`, `rep`).
- `has`: whole token (`O2` does not take `H2O2`) or `substring`; a file goes to the first term, those with several are in `multiple`, those with none in `without`. CLI `mzlab-cli sample vars|group`.
- Tests: `crates/mzlab-core/tests/samples_variables.rs` (list of the study in `crates/mzlab-core/tests/samples_variables/federico.json`), `crates/mzlab-cli/src/samples_cmd_tests.rs`, parity `.wasm` = app in `parity_routes.rs` (`name_steps`).

## Free columns and metadata of the table (`docs/schemi/samples-1.json`, `sample_id.rs`, `columns.rs`, `json3.rs`, `validate3.rs`, `csv.rs`, `model.rs`, `regex.rs`, `from_file.rs`)
- One file = one entry; a physical sample measured in the two polarities is TWO files with the same `sample_id`.
  Besides the roles and times (all optional on reading but the identity of the file): `sample_id`, `polarity` (+1, −1 or null: given by the file, a name template can propose it), `matrix`, `batch` (the batch of `design/1`: `design::propose` uses it, empty = default batch), `acquired` (ISO `AAAA-MM-GGTHH:MM[:SS]`, local time of the instrument PC, from the file), `group`, `extra{}` (name → text or number) and `file_data` (only if read from the file: `model`, `metodo`, `mz_min/max`, `rt_min/max`, `scans`; the user does not edit it).
- The document also has `columns[{name, kind: text|number|category, values?, required?}]`, the declared free columns. The name maps of the CSV/English: condition = `series`, replicate = `replicate`, injection_order = `injection_order`, dose = `concentration` + `concentration_unit` (`25 ppm`), role = `kind` (`control` = `dark`, `standard` = `std`), time = `time_min`.
- Canonical form (`table_to_json`, `table_digest` = SHA-256): `schema` first, then the keys in alphabetical order, files sorted by `injection_order` then by their own bytes, free columns and values by name, category `values` sorted: same bytes for every permutation. `table_from_value` reads the document; Rust types: `Table {samples, columns}`, `Column`, `Cell` (`Text`/`Number`), `FileData`; the metadata fields of `Sample` are `sample_id`, `polarity`, `matrix`, `batch`, `acquired`, `group`, `extra`, `file_data`.
- `validate` (and `validate3`) adds to the codes above: `missingValue` (error, `required` column without a value; the warning carries `colonna`), `typeMismatch` (error: number in a text column, text in a number column, value outside a category's list), `duplicateKey` (error, from the second file with the same SHA-256, or the same name if missing), `pairMissing` (warning: a `sample_id` with a single polarity), `pairMismatch` (warning: positive and negative of the same `sample_id` with a different time, role or series). A column warning also has `"colonna"` in the JSON.
- `sub_sample`: the sample inside a file that holds several (a `.wiff` with a series: index or internal name), empty if the file is one sample; the key of a row is file (or SHA-256) + `sub_sample`, and `duplicateKey` uses it. `csv_read`/`csv_write` also have the `sub_sample` column (and `reinjection`).
- `sample_id.rs`: the ID convention `MAT-COND-Ttt` (MAT `TW|MQ`; irradiated COND `C N2 O2 AIR H2O2 PMS`, dark `H2O2D PMSD BLKD` → `dark`; `tt` in minutes with `p` for the decimal, `T2p5` = 2.5; suffix `-R` = re-injection: `sample_id` keeps it, `reinjection` = true, the pages exclude it from the kinetics), `MAT-STD<cc>` (`std`, concentration cc in mg/L), `QC-MAT` (`qc`), `P-<name>` (`pool`), `BLK`, `BLKP`, `SB`, `MQ_Wash`, `MAT-BLK` (`blank`).
- `model` + `sample_id`: `model` derives from it, for the fields the template did NOT capture, `matrix`=MAT, `series`=COND, `group`=`MAT-COND`, `time`, `kind`, concentration; a captured field wins. The `{time}` placeholder also accepts the `p` (`2p5`).
- `validate`: `unknownCondition` (warning, column `series`) for an ID `MAT-COND-Ttt` with an unknown COND; `typeMismatch` with column `time` (error) for an ID whose time part is not numeric.
- `model` (`{"model", "samples"}` or `{"model", "files"}` → `{"samples":<samples/1>,"positions","unmatched"}`): a regex with named groups (`(?P<sample_id>[A-Z]\d+)_(?P<polarity>pos|neg)`) or a template with placeholders (`{sample_id}_{polarity}_{time}min_r{replicate}`, without capitals). A group named like a field fills it (`sample_id`, `polarity`, `matrix`, `batch`, `group`, `series`, `time`, `time_unit`, `replicate`, `concentration`, `concentration_unit`, `kind`, `injection_order`, `note`, `compound`); another name goes into a free column.
  The name is the one without folders or extension, whole (max 256 characters), positions are in characters of the whole name like `propose_explained`; times stay unconfirmed; a file the template does not recognize stays as it was. Own engine in `regex.rs` (backtracking with a step cap; no dependencies): literals, `.`, classes, `\d \w \s`, groups, `|`, `* + ? {n,m}` (lazy with `?`), `^`, `$`, `(?i)`. Error `error.badModello`.
- `csv_read` (`{"text","separator"?: "," ";" "\t","columns"?}` → `samples/1`) and `csv_write` (`{"samples","separator"?}` → `{"text"}`): headers = field names (also the English synonyms), unknown column = free column (number only if every value is written as Rust writes it, otherwise text; the types declared in `columns` constrain), quotes `""`, line breaks and separators inside fields, BOM, empty rows skipped, separator detected by itself.
  `time_confirmed` absent = confirmed if there is a time (the user wrote it); written replicates win, the others are numbered. What `csv_write` writes, `csv_read` reads back identical (`time_min` is recomputed, `file_data` is not in the CSV). Error `error.badCsv` with `riga` and `colonna`.
- `from_file` (`{"samples","file":[{"name"?,"sha256"?,"polarity":[..],"rt_min","rt_max","mz_min","mz_max","scans","acquired"?,"model"?,"metodo"?,"method_json"?}]}` → `{"samples","mismatches":[{"index","field","before","after"}],"unmatched"}`): the entry is matched by SHA-256 (if known), otherwise by name; polarity (a single one, otherwise null) and `acquired` replace those proposed from the names (replacements of different values are in `mismatches`), the rest goes into `file_data`.
  A `method_json` (`method/1`) gives `origine.file_creato`, `strumento.model`, `sub_sample.metodo_file` and the m/z range of the experiments when the entry does not say them. In Rust `riassunto_da_scansioni(&[Scan])` derives polarity, RT, scans and m/z (from the filter strings `[a-b]`) of an index.
- Binding: `samples(op, json)` with in addition `model`, `from_file`, `csv_read`, `csv_write`, `canonical` and `digest` (any other schema is refused with `error.badSamples`). The Flow metadata grid calls them (`flow-meta-grid.md`).
