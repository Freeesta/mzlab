# Attributio: `.wasm`, desktop route and level table
Administrator entry: the level table of a campaign folder. The cascade is in `docs/agenti/attributio.md`.
- **Table** (`crates/mzlab-feat/src/attributio/table.rs`, feature `attributio`): `run(&Io, root) -> Run` reads `campaign.toml`, the sources, the curation (`TableCuration::load`), the cascade with `gnps_comparer` and the fingerprint; `Run {features, warnings, fingerprint, settings, counts}` (counts per key `1`, `2a`, `2b`, `3a`, `3b`, `4`, `0`); `COLUMNS` has 14 columns: the first ten (`pol` … `reasons`), `engine_name`, `engine_score`, `engine_agrees` (MS2 engine evidence, never a level) and at the end `origin`.
- **Origin and log**: `origin` is `auto` if level and name were chosen by the program, `auto-2b` if the 2b is the program's (`[levels] auto_2b`), `user` if a decision by the chemist changed them; `Run::audit_csv_to` writes `pol;id;field;auto;chosen;reason` (one row per field `level`, `name` or `group` changed by the chemist, with the automatic value: removing the decision row restores it).
- **Automatic 2b in the bridge**: `review::auto2b::table_with_auto(io, root)` is the table entry point wherever the review exists (`.wasm` with feature `rev`/`all`, desktop route `feat/attributio/annotate`): if `campaign.toml` has `[levels] auto_2b = true` it computes the automatic rows and runs `table::run_auto(io, root, Some(rows))`, otherwise it is `table::run`.
- **Automatic 2b in the page**: the "Automatic 2b" checkbox (`#flx-auto2b` in the Flow campaign view, `flow/lazy/flow-campaign.js`, off by default): rewrites `campaign.toml` in memory (`[levels] auto_2b`, the folder is not touched) and redoes the cascade; the "Set by" column (`origin`) is in the "Columns" menu and the counts row says how many features the program brought to 2b.
- **Table renders**: three, in chunks on an `emit` callback: `json_to` (`{"columns","rows"}`), `csv_to` (`;`, UTF-8, cells with `;`, quotes or newlines in quotes), `xlsx_rows_to` (`{"hojas":[{"nombre":"Attributio","filas":[...]}]}`, like `export::xlsx_rows`).
- **Columns and summary**: `pol, id, mz, rt, level, sub, basis, name, identity, reasons`. `summary()` gives `{n_features, by_level, fingerprint, settings, warnings}` without campaign data.
- **`.wasm` `attributio`** (`crates/mzlab-attributio-wasm` without the `rev` feature, `wasm-feat/attributio/` in the manifest, cap 512 000 B, measured 432 347 B after `wasm-opt -Oz`): `annotate_to(read, names_json, write)` (JSON table), `table_csv(...)`, `table_xlsx_rows(...)`, all with the same signature. 
- **Inputs and outputs**: `names_json` = `{"root": folder, "files": [{"path","size"}]}`; `read(k, off, len) -> Uint8Array` gives file `k` of the list (only the files that `campaign.toml` names are read); `write(off, bytes)` receives the render in order in 64 KiB chunks. JSON errors `{error_key: "error.attributio", params: {detail}}`. The core without `js_sys` (`Files`, `run_with`, `render_to`) is tested natively.
- **Test**: `cargo test --release -p mzlab-attributio-wasm` (`tests/annotate.rs`: the three bridge renders byte for byte equal to those of the native path composed by hand on the synthetic campaign; levels, sublevels, bases and names of `livelli_attesi.csv`; 15 features, 16 rows with the header).
- **Worker** (`TP_Mine/files/feat-worker.js`): `mods.attributio` is loaded with `ensure(slot, "attributio")`; the operation `attributio_annotate` reads the page's `File`s in slices with `FileReaderSync`; `createFeatPool(...).attributioAnnotate(files, root, kind)` with `files = [{path, file}]` and `kind` = `json | csv | xlsx` answers `{summary, bytes}`.
- **Desktop app** (`crates/mzlab-desktop/src/feat_attributio.rs`): route `feat/attributio/annotate` `{root, kind, files: [{path, text}]}` → `{summary, text}`; the page sends only the text files of the folder (`feat-desktop-pool.js`, `attributioAnnotate`, same signature as the worker).
- **Page** (`TP_Mine/js/50_attributio.js`, `51_attributio_table.js`, `// @ts-check` in `tools/tipi/pagina.json`): Attributio has no entry of its own: it is the "Confidence level" node of Flow (`flow/lazy/flow-campaign.js`, `docs/agenti/flow-grafica.md`). `50_attributio.js` exposes only `ATTRIBUTIO_CORE` (`pool`, `walk`, `download`, `MAX_FILES`). The campaign folder is read up to `MAX_FILES` files: beyond that, `flow-campaign.js` shows a single calm note (`#flx-camp-cut`, English like Flow) with the cap, the files found and the next step (keep the raw data out of the folder).
- **Folder and table**: "Open a campaign folder…" in Flow uses `showDirectoryPicker` (otherwise an `<input webkitdirectory>`); with the picker the Review and Bench 2b write `feature_decisions.csv` into the folder (`ATTRIBUTIO_BANCO.writeInFolder`), with the input the file is downloaded; the files stay in the browser.
  `ATTRIBUTIO_TABLE.mount(box, {columns, rows}, {onReview})` draws the counts row (`#at-counts`) and a `TPTAB` (`#at-table`): level with sublevel (`TPTAB.level`) and name pinned, m/z, RT, polarity, optional columns (basis, identity, reasons,
  ID) from the "Columns" menu, level and polarity tokens, sorting from the headers (`aria-sort`), "Export view". The row opens below itself (only one) with the basis and reasons of the level and the "Open in Bench 2b" button (`onReview(view list, index)`). "Export CSV" and "Export XLSX" redo the render in the engine and download (XLSX with `dlx(..., false)`).
- **Notebook and `.mzflow`**: after each computation `WORKFLOW.logOp("attributio", {attributio: {fingerprint, settings, counts}})`; `attributio` is in `KNOWN_OPS` of `workflow.js`. No campaign data leaves the browser or enters the file.
- **Browser test**: `python3 tests_e2e/e2e_attributio.py` (builds the site and the `.wasm`; `MZLAB_PIPE_SITE=<site>` reuses one): without `qqq.admin` the entry is absent; with `qqq.admin` the synthetic folder (`set_input_files`) gives 15 rows with the levels of `livelli_attesi.csv`, tokens and sorting, a row that expands below itself, only one open, axe with no violations in light and dark theme, CSV and XLSX downloaded, fingerprint in the notebook, targets ≥ 24 px, `MZLAB_LR_MISS` empty.
