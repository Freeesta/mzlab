# CI: which tests run and how they are split

The pytest shards of `test.yml`: `target` cache, diff-based exclusions (`doppi`, `aree`), shared builds (`prebuilt`), order and halves. The rest of the conditional workflows is in `ci-fast.md`.

- The `target` cache is saved only by the 3.11 shards, one per shard (key `pytest-wasm-<shard>-…-rel`, with the hash of `tools/ci_cargo_mtime.py` and of the shim: changing the shim rebuilds the cache); the `solo311` shard runs the `--release` builds of the slow tests.
- `tools/ci_pytest_doppi.py <base>` (step `doppi`) excludes `test_guardie_memoria`, `test_feat_wasm` and `test_flow_determinismo` if the diff triggers the Rust filter of `rust.yml`, which already runs them. Test: `tests/test_ci_pytest_doppi.py`.
- `tools/ci_pytest_aree.py <base>` (step `aree`, `pull_request` only; push and merge_group run everything) excludes the tests that call cargo if the diff does not reach them: they depend on `crates/`, `Cargo.*`, toolchain, vendor, the files the crates embed (`include_str!`) and the areas their source names (web, `TP_Mine`, `docs`, `tests_e2e`). Outside these areas or with a non-test file of `tests/` it runs everything; with `--build` `prebuilt` does not build if none remains. Test: `tests/test_ci_pytest_aree.py`.
- Shared builds: the `prebuilt (native|wasm-a|wasm-b)` jobs of `test.yml` build once `mzlab-cli`, the examples and the test `.wasm` files (`tools/ci_prebuilt.py`, list `GROUPS`); they restore the cache `pytest-wasm-v3-rest-a-` (same paths as the shard's save, part of the version; `MZLAB_CACHE_JOB=pytest-shard` for the mtime registry); the shards start after them (`needs: prebuilt`, `if: !cancelled()`), download them and set `MZLAB_PREBUILT`.
- `tests/cargo_util.py` (`build`, `cli`, `example`, `installed`) installs that file instead of launching cargo; without the variable, or for a build not listed, cargo runs as usual. `prebuilt` is not a required check (if it fails the shards build on their own) and `browser` does not use it; `test_ci_prebuilt` verifies that every test build is in `GROUPS`.
- `tools/pytest_lenti.txt` (files and average seconds, slowest first; regenerate with `python3 tools/ci_pytest_slow.py --write` from the latest 3.11 runs of `stat-ci`, average ≥ 5 s) gives the order (`ci_pytest_ordine.py`: slow ones first) and the halves (`ci_pytest_meta.py`: each slow file to the lighter half; the others by hash; the `SPLIT_FILES` files, `test_lettori_parita` with 8 cargo builds, alternate their tests between the halves). Tests: `tests/test_ci_pytest_lenti.py`, `tests/test_pytest_meta.py`.
