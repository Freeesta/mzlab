# Motore Rust (`crates/`)
Stato attuale; il Python in Pyodide resta il riferimento finché Rust non lo eguaglia sui dati d'oro. Decisioni complete: `ARCHITETTURA.md` nel repository privato dei dati (`scratchpad/`).

## Struttura
- `crates/mzlab-core`: `raw.rs` (lettore dei `.raw` Thermo con OpenTFRaw `=2.0.0`, Apache-2.0, da `Read + Seek`: `read` dà gli stessi `Spectrum` dell'mzML (centroidi), `to_mzml` scrive l'mzML che il resto del programma già legge), `mzml.rs` (lettore a eventi con quick-xml da `Read`: spettri con livello, RT in minuti, polarità, precursore, filtro, m/z `f64`, intensità `f32`; cromatogrammi TIC/BPC/SRM/PDA; Numpress rifiutato), `analysis.rs` (TIC e XIC come `Item.total`/`PeakTable.xic`), `peaks.rs` (porta riga per riga di `ionfamily.detect_peaks`), `entropy.rs` (somiglianza di entropia spettrale), `error.rs` (chiave i18n + parametri); Rust puro. `crates/mzlab-wasm`: ponte `wasm-bindgen`, gira SOLO in un Web Worker.  `crates/mzlab-desktop`: l'app per il computer (sezione sotto). `crates/mzlab-lib`: le librerie spettrali (parser MSP/MGF/MassBank/JSON, formato `.mzlib`, costruttore, lettore; `docs/agenti/librerie.md`), Rust puro con `ruzstd` e `serde_json`.
- `mzlab-wasm` espone `Engine` (un file per «slot» = indice `k` della sessione): `open` legge il file a blocchi da una callback JS (`FileReaderSync` sul Blob), `tic`, `xic` e `spectra` scrivono in un `Float64Array` fornito dal chiamante (`[rt(n), y(n)]`; spettri `[n, conteggio, (sid, rt, k, mz, y)…]`, con gli stessi arrotondamenti di Python), `px > 0` riduce a min/max per pixel (`analysis::minmax_indices`). Gli errori sono JSON con chiave i18n.
- Toolchain fissata in `rust-toolchain.toml`, `Cargo.lock` nel repository. Il `.wasm` e `pkg/` non si committano: li costruisce `pages.yml` in `site/static/wasm/`.

## Vincoli (breve)
- Nel grafo WASM solo dipendenze pure Rust: `flate2` con `default-features = false, features = ["rust_backend"]`; `zstd` solo `cfg(not(target_arch = "wasm32"))` (su wasm `ruzstd`); `memmap2` solo nel desktop. `rust.yml` rifiuta `memmap2|zstd-sys|libz-sys|cc` in `cargo tree --target wasm32-unknown-unknown -p mzlab-wasm`.
- Memoria WASM 32 MB iniziali, 256 MB al massimo (`.cargo/config.toml`); grandi allocazioni con `try_reserve` e errore con chiave i18n; release con `panic = "abort"` (il panic non si cattura: la difesa è un supervisore JS).
- m/z `f64`, intensità `f32`; entropia in `f64`. Rust restituisce chiavi i18n e parametri, mai testi.

## Compilare e provare
- `cargo test` (nativo), `cargo build --release --target wasm32-unknown-unknown -p mzlab-wasm`, `cargo tree --target wasm32-unknown-unknown -p mzlab-wasm`. `cargo fmt --check` e `cargo clippy` avvisano soltanto.
- `rust.yml` gira solo su modifiche a `crates/**`, `Cargo.*`, toolchain e config; non è un controllo obbligatorio di «main protetto».
- Parità: `crates/mzlab-core/tests/golden.rs` confronta il lettore con `tests/golden/` (prima gli indici dei bordi, poi le tolleranze); i file sintetici li scrive `python3 tools/golden.py --sintetici DIR` (senza python3 e numpy il test si salta, con `MZLAB_GOLDEN_STRICT=1` fallisce). Se un'area esce dalla tolleranza è logica diversa: si corregge la logica. Carico di un file: `cargo run --release --example carico -- FILE.mzML`.
- Dati d'oro: `python3 tools/golden.py --controlla` (aree 1e-4, m/z 1e-6, entropia 1e-9, indici dei bordi identici); `--crea` solo se il riferimento Python cambia di proposito.

## Motore Rust nella pagina (`?motore=rust`)
- Opzione: `?motore=rust` o `localStorage qqq.motore = "rust"` (`?motore=python` la spegne). Senza, `rust-bridge.js` non viene nemmeno caricato.
- `browser.js` passa a `rust-bridge.js` ogni GET `api/chrom` (solo `kind=tic`, senza mz0/mz1/prec/filt), `api/xic` e `api/spectra` (senza prec/filt/merge; solo file a risoluzione unitaria `is_unit_resolution` e tutti centroidi); le risposte hanno lo stesso JSON di Python (intestazione `X-Engine: rust`). Tutto il resto, e ogni caso che Rust non sa rispondere identico (MRM, parti `#` di file misti, profilo, HR, file riaperti dal browser senza nuovo caricamento), va a Pyodide.
- `rust-worker.js` (modulo) carica `static/wasm/` (costruito solo da `pages.yml`) e tiene un insieme di `ArrayBuffer` restituiti da `recycle`; il bridge li rimanda dopo aver costruito il JSON.
- Supervisore (in `rust-bridge.js`): se il worker muore, lo termina, ne crea uno nuovo, riapre i file dalla sessione (`api/explore`) e mostra `error.engineRestarted`; una seconda morte entro 1 minuto spegne Rust per la sessione (`error.engineFallback`). `window.MZLAB_RUST` = `{enabled, disabled, stats, crash()}` per i test. Test `e2e_rust` (valori contro Python, morte del worker); `python3 tools/bench.py` misura i due motori, tabella in `docs/agenti/misure.md`.
- Il motore predefinito non cambia: lo decide solo l'Architetto con le misure.

## File Thermo `.raw` (solo con `?motore=rust`)
- `Engine.raw_to_mzml(nome, size, read, sink)` (`mzlab-wasm`): il `.raw` si legge a blocchi di 1 MB da `File.slice` (`BlockReader` con `Seek` e l'ultimo blocco in memoria, mai il file intero nella memoria WASM) e l'mzML esce a pezzi verso `sink`, che la pagina tiene come parti di un Blob. Operazione `raw2mzml` di `rust-worker.js`, `convertRaw(file)` di `rust-bridge.js` (errore: `json` con `error_key`, `err.file.raw`).
- `rawToMzml` in `index.html` converte i `.raw` prima di `upload()`: il file prosegue come `NOME.mzML` e Python lo legge come ogni altro (la risoluzione sta nel `userParam` `opentfraw.resolution`, letto da `_resolution` in `reader/mzml.py`). Senza motore Rust resta la ricetta di conversione (`load.recipe.raw`); `#dropraw` dice sulla schermata di carico che i `.raw` sono accettati.
- Parità: `crates/mzlab-core/tests/raw_parity.rs` confronta il `.raw` con l'mzML di msconvert (m/z 1e-6, intensità 1e-4, relativi) solo se il repository privato dei dati c'è (`MZLAB_DATI` o `mzlab-dati` accanto); mai un `.raw` nel repository pubblico. `cargo run --release --example raw2mzml -- IN.raw OUT.mzML` converte da riga di comando. Il passo `.raw` di `e2e_rust` si salta senza dati.
- Il precursore selezionato può differire da msconvert di qualche scansione MS2 (correzione monoisotopica dell'OpenTFRaw); lo spettro MS2 non cambia.

## App desktop (`crates/mzlab-desktop`, Tauri v2)
- Stessa interfaccia del sito in una finestra: nessuna seconda interfaccia. `lib.rs` (senza Tauri, sempre compilata, `cargo test` del workspace non vuole librerie di finestre): `mapped.rs` (`memmap2`, l'unico `unsafe`), `engine.rs` (`State`: file scelti per numero, file aperti per «slot», TIC, XIC, scansioni, `.raw` → mzML in una cartella temporanea; stessi arrotondamenti di `mzlab-wasm`), `protocol.rs` (`handle(state, path, query)`: funzione pura). `main.rs` e `tauri.conf.json` solo con la feature `app` (`cargo build -p mzlab-desktop --features app`; su Linux servono `libwebkit2gtk-4.1-dev` e `libgtk-3-dev`); binario `mzlab`.
- Protocollo `mzlab://localhost/<rotta>?...` (Windows: `http://mzlab.localhost/`), tutte GET, risposte binarie: `tic`, `xic`, `spectra` = `f64` little-endian con il formato di `mzlab-wasm` (`[rt(n), y(n)]`; spettri `[n, conteggio, (sid, rt, k, mz, y)…]`); `open?slot&id` (JSON di riepilogo come il WASM), `close`, `reset`, `lookup?name&size`, `raw2mzml?id`, `file?id&off&len` (a pezzi, usata anche per l'mzML convertito). Errori: stato 400 e JSON `{error_key, params}`. Il limite di 150 MB dei `.raw` non c'è: il file è mappato, non letto in memoria.
- File: il comando Tauri `pick_files` (finestra di scelta del sistema, `tauri-plugin-dialog`) e `register_paths` (file trascinati sulla finestra, evento `tauri://drag-drop`) registrano i percorsi e danno alla pagina numero, nome e dimensione; la pagina non vede mai i percorsi. Capacità minime (`capabilities/default.json`): finestra di dialogo e titolo, nessun accesso al file system; la rete è solo il Rust dell'aggiornamento (sotto), mai la pagina.
- `prepare.py` (dopo `tools/build_site.py`) copia `site/` in `crates/mzlab-desktop/dist/` (non nel repository) e cambia solo tre cose: la CSP di `index.html` ammette `mzlab:`, `static/rust-worker.js` diventa `shim/desktop-worker.js` (stessi messaggi del worker WASM, ma le risposte vengono da `mzlab://`), e `shim/desktop-shim.js` si carica prima di `browser.js` (accende il motore Rust, sostituisce il clic su `#drop` e `#dropdam` con la finestra del sistema, imposta il titolo della finestra da quello della pagina). `mzlab/web` e `tools/` non si toccano; senza `window.__TAURI__` lo shim non fa nulla. Un `.raw` scelto arriva alla pagina come `File` vuoto con il numero in `type` (`application/x-mzlab-file;id=N`): lo converte il motore nativo; gli mzML arrivano interi (a pezzi da 32 MB) con lo stesso `type`.
- Prove: `crates/mzlab-desktop/tests/protocol.rs` (protocollo contro `tests/golden/esempio_FullScan_t10.json`, pezzi di file, errori), `tests/e2e_shim.py` (Chromium: pagina del desktop + shim + worker contro `examples/serve.rs`, il protocollo su HTTP, con una finestra di dialogo finta; TIC, XIC e scansioni uguali a Python). La finestra vera si prova a mano (`desktop.yml` costruisce, non guida la finestra).
- `desktop.yml`: job `shim` (Linux: `cargo test` + e2e_shim) e job `build` (macOS universal `.dmg`, Windows NSIS `.exe`) con gli installatori come artefatti dell'azione (14 giorni); solo a mano e con modifiche a `crates/mzlab-desktop/**`; non è un controllo obbligatorio. Nessuna firma né notarizzazione (servono account Apple e Microsoft): l'app non firmata sul Mac si apre con clic destro → Apri; su Windows SmartScreen chiede «Ulteriori informazioni» → «Esegui comunque».
- **Aggiornamento della parte web** (`src/update.rs`, logica pura con test; `main.rs` ha solo i comandi `update_check`, `update_apply`, `update_restart` e l'evento `update-progress`). `tools/build_site.py` scrive `site/static/manifest.json` (percorso → SHA-256 e dimensione di ogni file tranne `sw.js`, `version` = commit, `desktop_min` = `crates/mzlab-desktop/DESKTOP_MIN`: da alzare quando la parte web chiede un binario nativo più nuovo, per esempio una rotta di `mzlab://` o una modifica dello shim; mai oltre la versione di `Cargo.toml`). L'app confronta il manifest del sito con il proprio (`<app data>/web/static/manifest.json`, altrimenti quello incorporato), scarica solo i file diversi (mai Pyodide se l'hash è uguale; `static/rust-worker.js`, `static/desktop-shim.js` e `sw.js` sono nativi e non si scaricano), verifica ogni SHA-256, costruisce `web.next/` (copia di `web/` più i file nuovi, `index.html` con le stesse due modifiche di `prepare.py` in `patch_index`, `check.json` con gli hash dei file su disco) e la scambia con `web/` con due rinomine; `recover` all'avvio chiude uno scambio interrotto e mette da parte (`web.bad`) una cartella con un file corrotto. La finestra è creata nel codice (`on_web_resource_request`): se `<app data>/web/` ha il file richiesto risponde quello (`serve_override`, mai fuori dalla cartella), altrimenti la copia incorporata. Rete solo qui: `ureq` con rustls, solo `https://freeesta.github.io/mzlab/`, nessun reindirizzamento seguito, la CSP della pagina non cambia; fuori dal grafo WASM. Se `desktop_min` supera la versione del binario l'app non scarica e rimanda alla pagina degli installatori (nessuna firma né plugin updater di Tauri). La parte nativa si riscarica intera.
- Pagina: `mzlab/web/aggiorna.js` (`DESKUPD`, solo con `window.MZLAB_DESKTOP`): riga «Controlla aggiornamenti» nelle impostazioni (`settings.js`), riquadro con progresso, «Riavvia ora», messaggio senza rete e link per `newapp`; all'avvio un controllo silenzioso al massimo una volta al giorno (`qqq.upd.last`) che mostra solo l'avviso «Aggiornamento disponibile». Prove: `cargo test -p mzlab-desktop` (confronto dei manifest, SHA-256, scambio atomico, file corrotto → nessun cambio, cartella danneggiata → ripiego, sorgente HTTP locale), `tests/test_manifest_sito.py`, e passi «settings: …» di `tests/e2e_shim.py` (Tauri finto). La finestra vera e il vero sito si provano a mano.
- Non incluso: firma, installatore Linux, Rust nativo per le altre rotte (MRM, filtri, HR, profilo vanno a Pyodide come con `?motore=rust`).
