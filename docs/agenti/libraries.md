
- `frag_tol.rs`: `FragTol` (Da or ppm of the query peak; an `f64` converts to Da with the same bits) is the fragment tolerance of `match_peaks`, `pair_scores`, `Scorer::score`, `modified_cosine`, `search::identity_with` and `decoy::best_scores_with`; `identity` and `best_scores_by` keep `frag_da`.
- `scores.rs` (contributions): `entropy_contributions`, `cosine_contributions`, `modified_cosine_contributions` give `(peak m/z, contribution)` for each matched pair; their sum is the score (entropy, cosine, modified cosine) within 1e-12. `spectra.match` with `score_terms` writes them as `score_terms` records (`mzlab-core::score_terms`, `docs/agenti/levels.md`). Test: `tests/score_terms.rs`.
- Filters of the `spectra.match` step on library entries (`flow_match_filter.rs`): `name_contains`, `adduct_contains`, `instrument_contains`, `ce_contains` keep the entries whose name, adduct, instrument or collision energy contains the text (case-insensitive, they combine, they do not apply to `tree`). Test: `metadata_filters_keep_the_matching_entries`.
- Bench of `search::identity` (`cargo run --release -p mzlab-lib --example identity_bench -- N unit|hr`): deterministic synthetic library, 200 queries, `top` 10. At 1M spectra, 0.5 Da window: ~2.5 ms cold (chunks included), ~1.5 ms warm; HR 10 ppm: ~0.55 and ~0.05 ms. `prep::Scorer` prepares the query once and reuses the buffers (`match_peaks_into`, `weighted_into`, `Library::peaks_into`): numbers bit-identical to `pair_scores` (test: `scorer_over_many_spectra_equals_pair_scores`).
- Retention time of entries: `Spectrum.rt` (minutes, `Option`), read by `parse.rs` (`rt_minutes`: `RT`/`RetentionTime`/`RTINSECONDS` of MSP, MGF and JSON, `AC$CHROMATOGRAPHY: RETENTION_TIME` of MassBank; unit "s" = seconds) and written in the `.mzlib` as `f32` in bytes 28..32 of the spectrum record with `FLAG_HAS_RT`.
- Peak cap per entry: `spec::MAX_RAW_PEAKS` (200 000); a longer entry keeps the first peaks and counts in `Stats.cut` (`parse/rec.rs`). The import JSON of the `.wasm` carries `cut` and `cutAt`, the Libraries window says so in one calm line in the outcome (`lib.cutN`: cap, what was kept, centroid or filter); `--example build` prints them. Test: `very_long_names_and_huge_peak_lists_do_not_panic`, step "peak cap" of `e2e_libreria_wasm`.
  In v1 files (no RT) the bytes are zeros and the flag is off; `SpecRec::rt_min()` reads it. Test: `tests/retention.rs`.
- RT filter of the `spectra.match` step (`flow_match_filter.rs`, with the metadata filters): `rt_tol` (min, 0 = off) drops entries more than `rt_tol` away from the RT of the searched spectrum (entries or spectra without RT stay) and writes `rt_delta_min` (searched minus library). Test: `rt_tol_excludes_entries_by_retention_time`.
- Peak evidence (`flow_match_evidence.rs`): `matched_peaks` (bool, off) adds to each `spectra.match` candidate the `matched_peaks` list (by query m/z: `query_mz`, `library_mz`, relative `query_int`, `library_int`, `shifted` if the precursor shift is needed); the number of pairs is `shared`, the scores do not change; it does not apply to `tree`. Test: `matched_peaks_list_the_pairs_behind_the_score`.
- `spectra.match@1` `tol_ppm` (default 0, also `table.match`): above 0 it replaces `tol_da` as the fragment window of `spectral_entropy`, `cosine` and `modified_cosine` (ppm of the query peak, `mzlab_lib::frag_tol::FragTol`; the neutral-loss count uses ppm of the precursor); the analogue search and `tree` keep `tol_da`. Test `flow_match_tests::tol_ppm_replaces_the_fragment_window_in_da`, library `tests/frag_ppm.rs` (two HR compounds 0.008 Da apart: tied at 0.01 Da, separated at 5 ppm).

- `.mzlib` v2 format (`format.rs`, `MIN_READER` = 1: a v2 reader also opens v1 files, which have no RI, empty info and a zero InChIKey hash). All numbers are little-endian. 36 B header: `"MZLB"`, version `u16`, min_reader `u16`, n_spectra `u32`, n_sections `u32`, n_peaks `u64`, flags `u32`, CRC32C of the first 32 B `u32`. Section table from 36: 32 B per entry (type `u32`, 4 B zero, offset `u64`, length `u64`, dir_len `u32`, CRC32C `u32` of the directory only); the first section starts at 512 B (256 in v1), sections are aligned to 8 B.
- Sections: 1 spectra (blocked), 2 peaks (blocked), 3 metadata (blocked), 4 Flash index of fragments, 5 neutral-loss index, 6 `SEC_LIBINFO` (v2 only), 7 `SEC_INCHI` (v2 only). Blocked section: directory = n_blocks `u32` + 4 B + 40 B per block (offset `u64`, first precursor `f64`, stored `u32`, raw `u32`, first record `u32`, CRC32C `u32`, method `u8` 0 = raw 1 = zstd, polarity key of the first record `u8`); the CRC of each block is checked at first read.
- Spectrum record: 36 B in v2 (32 in v1): precursor `f64` 0..8, first peak `u32` 8..12, n_peaks `u16` 12..14, polarity `i8` 14, licence `u8` 15, flags `u16` 16..18 (1 few peaks, 2 `FLAG_HAS_RT`, 4 `FLAG_HAS_RI`), 18..20 zero, original order `u32` 20..24, scale `f32` 24..28, RT in minutes `f32` 28..32, Kovats retention index `f32` 32..36 (v2 only). Order: polarity (negative, unknown, positive), then precursor. `ri` is read from `RI`/`RetentionIndex`/`Kovats` (MassBank `KOVATS_RI`).
- `SEC_LIBINFO` (6): UTF-8 JSON with `kind` (`experimental`|`in_silico`|null), `tech` (`lc_msms`|`gc_ei`|`msn`|null), `pol` (`pos`, `neg`, `unknown`), `analyzers` (spectra per `orbitrap`, `qtof`, `qqq`, `it`, `ei`), `source`, `version`, `sha256`; dir_len = length, CRC32C of the whole JSON. `SEC_INCHI` (7): one `u64` per spectrum in table order, FNV-1a of the first 14 uppercase characters of the InChIKey, 0 if missing; dir_len = length, CRC32C of the whole section.
- Detection in the builder (`libinfo.rs`, `BuildOpts.declared`, `Builder::set_source`): polarity from the sign of each entry; `tech` `gc_ei` if the entries are EI without precursor or with RI, `msn` if MSⁿ trees prevail, otherwise `lc_msms`; `kind` `in_silico` from known keywords in the source or the name, otherwise `experimental`; analyzer from `Instrument_type`. What the user declares in `BuildOpts` takes precedence. Test: `tests/format_v2.rs`, `tests/data/v1_small.mzlib` (fixed v1 file).
- Flash index and section 4/5: 10 B entries (m/z in 1e-5 Da `u32`, spectrum `u32`, intensity `u16` as a fraction of the scale) in fixed 64 KB pages (6553 entries); directory = n_entries `u64`, n_pages `u32`, entries per page `u32`, then 12 B per page (first m/z, n. entries, CRC32C); the neutral-loss entry is `precursor − m/z` and the precursor is derived from `Light.precq`.
- Flash search (`flash.rs`, `flash_resolve.rs`): `flash_top` accumulates the contributions in flat slots per spectrum (`f64` sum, counter, 64-bit signatures of the query and library peak already used) after sorting them into buckets of 4096 spectra and scoring bucket by bucket.
- Flash conflicts: spectra with a repeated peak (equal signature: at worst a false conflict) are resolved one-to-one by `score_pairs` on their own pairs only, so scores and pairs match the pairwise version within 1e-9 (`tests/flash_parity.rs`, reference in `tests/common/flash_pairs.rs`). `keep` keeps the first k (`topk::keep_first`) and `accept` filters before the choice. `flash_scores`/`flash_scores_with` stay the simple entry points.
- `LibSet` (`libset.rs`): up to 16 open `Library` objects (id = position, bit of the `u16` mask); `identity`, `analogs` and `open` search each library of the mask with the same accumulators and merge the tops by score, then library, then index (`SetHit`: library, index, group, mask of the libraries with the same spectrum). `Library::fingerprint()` = SHA-256 of header and section table.
- Deduplication: `LibSet::dedup()` builds the `libset.bin` sidecar (`"MZLS"`, version `u16`, n_libraries `u16`, per library 32 B fingerprint + n_spectra `u32`, total `u32`, `group_id` `u32` and mask `u16` per spectrum, CRC32C); group key = (InChIKey14, polarity, precursor to 0.001, hash of the 6 highest peaks by rank with m/z to 0.01 Da). `attach_sidecar` refuses it (and it must be rebuilt) if a library changed. Results carry one hit per group.
- `stein_cosine` (`stein.rs`, re-exported from `scores`): Stein composite cosine with weights `I^a·(m/z)^b` (defaults a = 0.53, b = 1.3, NIST values as reported by Kim et al. 2012; the source was not re-read in the text), one-to-one pairs, `forward`/`reverse`, no precursor (GC-EI); with RI of query and entry the score is multiplied by `ri_factor = exp(-(ΔRI/σ)²/2)`, σ = 10.
- `hybrid_entropy(a, b, tol)` = entropy of the pair with direct peaks and peaks shifted by Δprec (pairs of `hybrid_pairs`, same score as the hybrid Flash search).
- `libmatch/1` result (`matchres.rs`, schema `docs/schemi/libmatch-1.json`, `MatchResult::to_json` with fixed field order): `match_query(set, query, MatchParams)` runs identity (window `exact`, ppm or Da) and analogues (`analog_max_delta`, ≥ `min_matched` peaks) on the libraries of the mask and groups by first InChIKey block (otherwise normalised name); badge `exact` | `analog` | `in_silico` (an `in_silico` library is never exact), order exact, analog, in_silico then score, at most `top_compounds` (10).
- Spectra of `libmatch/1`: `score` (+ `score_kind` entropy | modified_cosine), `reverse`, `explained`, `matched`/`of`, `direct`, `shifted`, `delta_mz` = query − library, `delta_ppm`, mask of the libraries and `pairs[]` (direct | shifted; `loss` is in the schema, not produced). `confidence` is always null: the cascade reads `experimental`, `hr`, scores and peaks.
- Bench (`cargo run --release -p mzlab-lib --example libset_bench -- N unit|hr [libraries]`): native timings for `identity`, `analogs`, hybrid open search with flat accumulators and pairwise reference, 1 or 3 libraries; rows in `measurements-rust.md`.

- "Identification with the libraries" tab of the info bar (`ident-pannello.js`, loaded by `banco.js` `tIdn`): spectrum row (RT, precursor m/z, polarity), "Search this spectrum", the loaded libraries as rows with a checkbox (name, spectra, polarity, level, format) and the candidates table (`LIB.call("search", {ids})`, redone by itself at every scan change after the first search). No introductory texts. Test: `e2e_ident_librerie`.
  Libraries compatible in polarity and level are ticked automatically (MSn only for scans of level ≥3); each row has a status column (On/Off) and a tooltip saying what it is and why it is off; without an MS2 spectrum the checkboxes are disabled; a user tick prevails.
  "Load file…" / "Load folder…" read msp/mgf/json/mzlib; "ignored: N" opens the list of the files left out, grouped by reason (unsupported format, already loaded, engine error) and of the files read with spectra skipped (no precursor, no peaks, damaged). The identification of all MS2 is not here (`LIB.identifyAll` stays for mzFlow).
- "Get libraries" menu (`ident-catalogo.js`, data in `mzlab/web/librerie-pubbliche.json`: public links only, never files in the repository): per entry ↓ (`<a download>`: the CSP `connect-src 'self'` and the CORS of GNPS prevent downloading from the browser; then "Load file…") and 🌐 (site, `rel="noopener noreferrer"`); a format the engine does not read (`isSupported`) has the ↓ disabled.
