# Desktop app (Tauri) and native engine
Part of the Rust engine (`docs/agenti/rust.md`).

- Same interface as the site in a window (`crates/mzlab-desktop`, Tauri v2), with a native Rust engine (files read with `memmap2`) behind `mzlab://`: no second interface. `lib.rs` (no Tauri, always compiled, the workspace `cargo test` does not want window libraries): `mapped.rs` (`memmap2`, the only `unsafe`), `engine.rs` (`State`: files chosen by number, files opened by "slot", TIC, XIC, scans, mzML written in a temporary folder; same roundings as `mzlab-wasm`), `protocol.rs` (`handle(state, path, query)`: pure function).
  `main.rs` and `tauri.conf.json` only with the feature `app` (`cargo build -p mzlab-desktop --features app`; on Linux `libwebkit2gtk-4.1-dev` and `libgtk-3-dev` are needed); binary `mzlab`.
- **Build profile**: the app is built with `[profile.desktop]` of `Cargo.toml` (inherits `release`, but `opt-level = 3` instead of `"z"`; LTO and `codegen-units = 1` stay): `cargo tauri build --features app -- --profile desktop`, or alternatively `CARGO_PROFILE_RELEASE_OPT_LEVEL=3`. The `release` profile (`opt-level = "z"`) stays for the `.wasm` files, whose SHA-256 does not change. Quick test of the native engine with the same profile: `cargo run --profile desktop --example raw_times -p mzlab-core -- FILE.raw`.
- Protocol `mzlab://localhost/<route>?...` (Windows: `http://mzlab.localhost/`), all GET, binary answers: `tic`, `xic`, `spectra` = little-endian `f64` in the format of `mzlab-wasm` (`[rt(n), y(n)]`; spectra `[n, count, (sid, rt, k, mz, y)…]`);
  Everything else the page asks of its engine is `rpc` (POST, JSON body with `op` and the parameters; `rpc.rs`, native twin of `rust-worker.js` + `mzlab-wasm`, same code as `mzlab-core` on mapped files: indexes per slot, index routes, `mzmlroute`, `scanbin`, `specexact`, maps, origin, `diff`, `qaqc`, statistics, `.dam` methods, gradient, analog traces; every `lr_*` operation of the file list and of the notebook, `lr_valida` = "Validate mzML") and `lr/upload` (chunked POST: a `File` that exists only in the page, not chosen in the window).
  Answers are text (the route's JSON; empty = not its own) or bytes (`scanbin`). `store.rs`: files stay where they are on disk (`files.json`: name → path, size, date; a changed file loses its index), the notebook is in `kv.json` ("File": `startup.md`), the user's molecules in `molecole.json` (JSON `molecules/1`, route `lr_molecole_archivio`; `lr_clear` does not touch it; `docs/agenti/molecules.md`), only what the app does by itself (file that arrived as bytes) is copied into `files/`; the folder is `app_data_dir()/sessione` (`set_data_folder`), indexes are in the app cache.
  Changed file on disk: `Store::list` reports it without rewriting the saved size and date; only `lr_boot` (after removing the index) and `lr_index` (with the date taken before building) renew them, with `Store::restamp`, so a listing made for another purpose (`lr_space`, `.dam` methods) does not hide the change at the next start. Test `tests/rpc.rs` (`a_file_changed_on_disk_loses_its_index_at_the_next_boot_even_after_another_listing`).
  `idxxicbin` = `[rt(n), y(n)]` in LE `f64` of the index XIC (route `xicbin`): the shim forwards it as `scanbin`.
  `open?slot&id` (summary JSON like the WASM), `close`, `reset`, `lookup?name&size`, `rawprogress?id` (`{total, read, written, scans, scansTotal}`: bytes and scans of the mzML being written, `{}` if it never started: `desktop-worker.js` polls it every 300 ms), `file?id&off&len` (chunked, also used for the mzML written by `nat2mzml`). Errors: status 400 and JSON `{error_key, params}`. No size limit: files are mapped, not read into memory.
- Files: the Tauri command `pick_files` (system choice window, `tauri-plugin-dialog`) and `register_paths` (files dragged onto the window, event `tauri://drag-drop`) register the paths and give the page number, name and size; the page never sees the paths. Minimal capabilities (`capabilities/default.json`): dialog window, title, drag, zoom and full screen of the window, no file system access; the network is only the Rust of the update (below), never the page.
- `prepare.py` (after `tools/build_site.py`) copies `site/` into `crates/mzlab-desktop/dist/` (not in the repository), has no Python to remove (the site has none) and changes only three things: the CSP of `index.html` admits `mzlab:`, `static/rust-worker.js` becomes `shim/desktop-worker.js` (same messages as the WASM worker, but the answers come from `mzlab://`),
  `shim/desktop-shim.js` is loaded before `browser.js` (it turns on the Rust engine, replaces the click on `#drop` and `#dropdam` with the system window, sets the window title from the page's; on macOS the title bar is overlaid and the page header sits on the traffic-light row: `shim/desktop-titlebar.css`, dragging and double click from the empty part, left margin removed in full screen).
  `mzlab/web` and `tools/` are not touched; without `window.__TAURI__` the shim does nothing. A chosen file reaches the page as an empty `File` with the number in `type` (`application/x-mzlab-file;id=N`); mzML files arrive whole (in 32 MB chunks) with the same `type`. `shim/desktop-worker.js` forwards every bridge message to the native `rpc`, in a queue (a `reset` does not overtake the `idxopen` that follows it); only `lr_index` and `nat2mzml` do not wait.
- **CSP and security**: `app.security.csp` of `tauri.conf.json` is the CSP of `index.html` plus `mzlab: http://mzlab.localhost ipc: http://ipc.localhost` in `connect-src` (`tests/test_csp_desktop.py` keeps them equal); `dangerousDisableAssetCspModification` stops Tauri from adding nonces and blocking inline scripts.
- The real window is not tested in the cloud (the GTK libraries are missing): `desktop.yml` compiles it and it is tested by hand. `SECURITY.md`, `.github/dependabot.yml`, `deny.toml` (job `deny` of `rust.yml`, non-blocking) and `sbom.yml` (CycloneDX SBOM, callable from the release) are at the root.
- Tests: `crates/mzlab-desktop/tests/protocol.rs` (protocol against `tests/golden/esempio_FullScan_t10.json`, file chunks, errors), `tests/rpc.rs` (register, index, open, route, new run on the same folder), `tests/e2e_shim.py` (Chromium: desktop page + shim + worker against `examples/serve.rs`, which serves the protocol over HTTP with `MZLAB_APP_DIR`; a fake dialog window; every route of the LR and HR flow equal to the golden data `tests/golden/e2e/` (`tests_e2e/golden_ref.py`), empty `MZLAB_LR_MISS`, reload, file that arrived as bytes).
- **MSn graph** (`src/rpc_msn.rs`, test `tests/parity_msn.rs`): `msngrafo {slot, name, fid, query, esporta?, cerca?, libreria?, molecola?}` = `api/msn_grafo*` and `api/msnlib/*`, twin of `mzlab-msngrafo-wasm` (same bytes as `mzlab-cli msn-graph`). A native sample is read from the derived mzML (written once in `temp` with its index `msn~<nome>~<hash>`, reused until the members change), like the OPFS copy of the site; `desktop-worker.js` passes the name of the file opened in the slot by `idxopen`.
- **Centroids and SRM** (same file): `mzml2cen {name, pid}` = centroid copy of a profile mzML in `temp` (`{id, size}` like `nat2mzml`, `{none:true}` without profile); `lr_index_cen {name}` = `<name>.cen.mzidx` of a native sample; `natsrm {name}` = bytes of `srm::impacchetta`.
- **Route-by-route parity** (`tests/parity_routes.rs`, `tests/test_parita_rotte_app.py`): the same plan of 37 steps (index routes, mzML, maps, TIC/XIC/spectra, `lr_stat` with the invented tables of `tests/golden/ref/statistica.json`, a slot never opened) and a synthetic SRM file (`mrm`, `mrmchrom`, channels) go to the app and to the `.wasm` (Node) on the same `.mzidx`; every answer (text, numbers, bytes or error key) must match.
  `tic`, `xic` and `spectra` on a slot never opened give `err.file.raw` in both (`engine.rs` `with_run`; `count` and `spectra_len` of `mzlab-wasm` give `u32::MAX` and the worker turns it into the error).
- DAD: `tests/dad.rs` (`lr_pda*` = `mzlab-core`, mzML and `.wiff`) and `e2e_shim.py`; `SrmFromScans` forwards `dad_*`.
- `desktop.yml`: job `shim` (Linux: `cargo test` + e2e_shim) and job `build` (macOS universal `.dmg`, Windows NSIS `.exe`, Linux AppImage and `.deb`) with the installers as action artifacts (14 days); manual only and with changes to `crates/mzlab-desktop/**`; it is not a required check. No signing or notarization (Apple and Microsoft accounts are needed): the unsigned app on the Mac opens with right click → Open; on Windows SmartScreen asks "More info" → "Run anyway".
- **Update of the web part** (`src/update.rs`, pure logic with tests; `main.rs` has only the commands `update_check`, `update_apply`, `update_restart` and the event `update-progress`). `tools/build_site.py` writes `site/static/manifest.json` (path → SHA-256 and size of every file except `sw.js`, `version` = commit, `desktop_min` = `crates/mzlab-desktop/DESKTOP_MIN`: to be raised when the web part asks for a newer native binary; never beyond the version of `Cargo.toml`).
  The manifest is written last: `build_site.py --build-json` (after the `.wasm` files and `seal_sw`) rewrites it, so it describes `build.json` and every `.wasm` as they are on the site; `pages.yml` (`assemble`) and `tests/test_manifest_sito.py` check it again byte for byte.
  A file with a different hash or size is downloaded again once with `?v=<version>` (`Http` only); on the second error `update.error.hash` carries in the detail `<rel>: got <len>/<sha8>, want <size>/<sha8>, tries 2` and `apply_refetch` redoes the comparison once if the manifest changed (`tests/update_retry.rs`).
  `aggiorna.js`: detail under the message and "Copy details"; `newapp` also without `scaricaApp` (no link); `upd.last` only after a non-offline answer.
  The app compares the site manifest with its own (`<app data>/web/static/manifest.json`, otherwise the embedded one), downloads only the differing files (`static/rust-worker.js`, `static/desktop-shim.js` and `sw.js` are native and are not downloaded), downloads them in parallel (`download_all`: 8 threads, shared `ureq` agent, stop at the first error, `update-progress` from the main thread; tests `tests/update_parallel.rs`),
  checks size and SHA-256 of each, builds `web.next/` (copy of `web/` if its manifest is the local one, plus the new files, minus those not listed, `index.html` with the two changes of `prepare.py` (`patch_index`), `check.json`) and swaps it with `web/` with two renames;
  `recover` at start closes an interrupted swap and sets aside (`web.bad`) a corrupt folder or one for a newer binary. The window is created in code (`on_web_resource_request`): if `<app data>/web/` has the requested file, that answers (`serve_override`, never outside the folder), otherwise the embedded copy. Network only here: `ureq` with rustls, only `https://freeesta.github.io/mzlab/`, no redirect followed, the page CSP does not change; outside the WASM graph.
  `parse_manifest` refuses (`update.error.manifest`) a file above `MAX_FILE` (48 MiB) or a sum above `MAX_TOTAL` (300 MiB); `fetch_one` reads at most `size + 1` bytes (`Source::get_capped`).
  If `desktop_min` exceeds the binary's version the app does not download and points to the installers page (no signing). The native part is downloaded again whole.
- Page: `mzlab/web/aggiorna.js` (`DESKUPD`, only with `window.MZLAB_DESKTOP`): row "Check for updates" in the settings (`settings.js`), box with progress, "Restart now", offline message and link for `newapp`; at start a silent check at most once a day (`qqq.upd.last`) that shows only the "Update available" notice; a click on "Check for updates" while that check is running takes it over (same answer, as a box).
  Tests: `cargo test -p mzlab-desktop` (manifest comparison, SHA-256, atomic swap, corrupt file → no change, damaged folder → fallback, local HTTP source), `tests/test_manifest_sito.py`, and "settings: …" steps of `tests/e2e_shim.py` (fake Tauri).
- **Opening from outside and default app** (`src/opening.rs`, pure logic, test `tests/opening.rs`; Tauri glue in `open.rs` and `startup.rs`; page `mzlab/web/predefinito.js`, `DESKDEF`, test `tests_e2e/e2e_predefinito.py`):
  Extensions, a single source: `mzlab_lettori::estensioni()` (`apertura::file_extensions`, without the `.d` folders); the filter of `pick_files`, `is_openable` and `bundle.fileAssociations` of `tauri.conf.json` (mzML, mzXML, raw, wiff, lcd, qgd, cdf, and `scan` for the companion `.wiff.scan`; not `.nc`) derive from it;
  Associations: `rank` (tauri-utils 2.10.1, `LSHandlerRank`): `Editor`+`Default` for raw, wiff, lcd, qgd (vendor formats, no other common program claims them), `Viewer`+`Default` for mzML and mzXML, `Viewer`+`Alternate` for cdf and `scan` (generic: never default, never `Owner`). The system is not forced: the "default app" notice (`predef.*`) explains how to set it, no system call.
  Opening from the system: `plan_from_paths`: `X.wiff.scan` opens the `.wiff` beside it (same folder, case-insensitive), a `.wiff` brings its `.wiff.scan` along, `.wiff.scan` without `.wiff` and stray `.scan` files are refused (`Plan.refused`, `take_opened` → `refused`): the page says why (`predef.scan.needs.wiff`), nothing opens; `mzlab x.wiff.scan` = same function; the site has no equivalent (the browser does not see neighbouring files).
  Drawings (`.ket`): associated (`opening::DRAWING`); `take_opened` separates them (`is_drawing`) and gives them in `drawings`; `predefinito.js` opens Drawing with `TPDraw.load`. Saving = the editor's export (asks where). `.mol`, `.sdf`, `.smi` never claimed.
  Check: `tests/opening.rs` compares the configuration file with the list. Folders (`.D`, `.d`, Waters `.raw`): no OS associates them (macOS only with a "package" UTI, which would break the Thermo `.raw`); they open from `mzlab <folder>`, second instance, "Open with"/icon (`is_folder_dataset`), same queue as "Open".
  `.mzml.gz` opens from the dialog (filter `gz`) and from the system but has no association of its own (compound extension); `.mzxml.gz` has no reader.
  Single instance: `tauri-plugin-single-instance` 2.5.4 (first plugin, feature `app` only) passes argv and current folder of a second launch (Windows, Linux) to the open window; argv at cold start; `RunEvent::Opened` on macOS.
  The paths (existing files of the registry, `.d`/`.raw` folders, `.ket`) go into the `Pending` queue; event `mzlab-open` and command `take_opened` register them like the files of the choice window and open them in the Data view (`MZLAB_TOFILE` of the shim). Files arrive in the side list (`tests_e2e/e2e_predefinito.py`, step `opened_files_reach_the_side_list`, with simulated Tauri).
  `record_opening` counts the openings from outside and asks on alternate openings until `risposta` in `config.json` (`Config.aperture`, `Config.risposta`: `si` | `mai`) closes it. Commands `assoc_get`, `assoc_answer` (`si`/`mai`/`no`), `assoc_reset`. Modal `<dialog>` window (Yes → guide for Windows / Mac / Linux `xdg-mime`; Not now; Don't ask again), row "Default app" in the settings (resets and asks).
- **New app version notice** (`src/release.rs`, pure logic, test `tests/release.rs`; command `release_check` of `main.rs`; page: `release()` of `aggiorna.js`): the binary does not update itself (no signing, no updater), so at start, at most once a day (`qqq.rel.last`), the Rust asks `https://api.github.com/repos/Freeesta/mzlab/releases/latest` (5 s in all, no redirect, no user data) and compares `tag_name` with the binary's version (`CARGO_PKG_VERSION`, semver `X.Y.Z`; drafts, prereleases and tags with a suffix ignored). 
  If a newer one exists the page shows `#relbox` ("New version X available", link to `releases/latest`, "Close"; closed = `qqq.rel.seen` for that version). Offline, error or a binary without the command: silence. The CSP does not change (network only in the Rust). Tests: `cargo test -p mzlab-desktop --test release`, "release" steps of `tests_e2e/e2e_aggiorna.py`.
- **Native `.mzidx` builder** (`src/idxbuild.rs`, `IdxBuilder`; test `tests/idxbuild.rs`): the same `mzlab-core::mzidx`, with the mapped file (`memmap2`) and a `rayon` pool (cores − 1, at most 4: several files together, the others wait for a free thread); the index goes into the app cache folder (`app_cache_dir()/mzidx`, `set_index_folder`; the system may delete it, it is rebuilt) as `<size>_<name>.mzidx` (first `.part`, then renamed).
- **Spare file and table of the native `.mzidx`**: `IdxBuilder::scrivi` (also for `build_nat`) opens `<nome>.mzidx.part` and peaks beyond the budget go into `<nome>.mzidx.sp.part`, removed at the end even after an error: the file is decoded once. For `lr_index` of an mzML the table is read in the pool (`upload::prepare_parallelo`: SHA-256 on a second thread while the table is read).
  Routes: `idx/build?id&name` (POST, body = scan table: eight parts with `u32` length, `decode_inputs`), `idx/stat?name`, `idx/read?name&off&len`, `idx/remove?name`. They serve to index in the native engine (`idxbuild.rs`, `protocol.rs`, `engine.rs`; test `tests/idxbuild.rs`) and to re-read the index in chunks; no page script calls them.
  The Rust test compares byte for byte with Python (also files built together by several threads); `tests/e2e_shim.py` tests the round trip in the page.
- Not included: signing. No route goes to Python: the app contains neither Python nor Pyodide.

- Pointed data folder: `src/folder.rs` (`list`, `kind_of`, `resolve`: relative paths, no `..`) and the commands `data_choose_dir`, `data_get_dir`, `data_list`, `data_register`, `data_forget` of `main.rs`; the path is in `config.json` (`Config.dati`). Page side `cartella-puntata-desktop.js`; details in `docs/agenti/data-folder.md`.
- Native mzFinder (`src/feat.rs`, `src/feat_finder.rs`, routes `feat/*`, `finder/*`, Pipeline panel, `feat_import.rs`, `feat_attributio.rs`, `feat_graph.rs`, `finder-desktop`): `docs/agenti/rust-desktop-finder.md`.
- **Native samples** (`.raw`, `.wiff` + `.wiff.scan`, `.D` folders; `src/natives.rs`, `rpc_nat.rs`, `idxbuild_nat.rs`; test `tests/natives.rs`): the same `mzlab-core::lettori` as the site plus the formats of the readers module (`mzlab_lettori::apri`), on mapped files (`Limiti::desktop()`). `natsamples {members:[{name,fid}]}` lists the samples; `lr_put {name, nat:{key,c,id,centroid,members}}` registers the sample without copying the members (`store.rs`: `Entry.nat`, `files.json` remembers the members; size and date are the sum and the latest of the members, a vanished one = changed file);
- **The same dataset again** (`natsame {members:[{name,fid}], names}`, `rpc_nat.rs`; test `tests/natives.rs` and `e2e_shim.py`): the names in the list that are samples of exactly those members (same names and paths, size and date as when registered: `Store::same_nat`) and have the index; the page (`NATIVO.cached`) then adds neither a second sample nor a second index, for `.raw`, `.wiff` pairs and `.D` folders (`agilent-d.js` `toMzml`). The shim passes the members as for `natsamples`.
- **Members sent as bytes** (`lr/upload?name&off&total&mtime`, `rpc.rs` `upload_chunk`; test `tests/rpc.rs` and `e2e_shim.py`): the window's `File` objects (a `.D` folder from "Upload a folder") go into `files/` with the path inside the chosen folder (`/` → `~`, the shim's `members()`), so two `.D` do not share `MSScan.bin`; the received file takes the date of the `File` (`lastModified`) and one with the same name, size and date already there answers at the first chunk without being rewritten, so `natsame` recognizes the same folder given again.
- **Conversion queue** (`src/conv_queue.rs`, routes `conv_add {name}`, `conv_list`, `conv_cancel {name?}`, command `save_mzml_folder`; test `cargo test -p mzlab-desktop conv_queue`): every native sample loaded (`CONVQ`, `conversione.js`) queues its dataset; `mzlab_cli::convert::run` (bytes of `mzlab-cli convert`) writes into `app_cache_dir()/mzml/<hash>/` on the threads of `convert` (if the budget reduces them `conv_list` carries `notice`, the CLI note), paused while a Data index is being built (`Indexing`); reuse by SHA-256, writer and parameters is the cache of `convert`.
  `conv_list` gives `{jobs:[{name, state: queued|run|done|failed|cancelled, error}]}` (the table row says "mzML ready ✓" or the error);
  Cancel stops what has not started; "Save the mzML files…" (`MZLAB_SAVE_MZML_DIR`) puts all the ready mzML files in a chosen folder. `flow/run` puts the ready mzML in place of a native input (same date and size as the dataset).
  `lr_index` answers `{ms, missing}` (`missing` = spectra that a truncated file declares beyond those read, also a numpress mzML: `Stats.missing` of `build_nat`; for the row's warning) and builds the v2 `.mzidx` from the reader (`IdxBuilder::build_nat`). The routes that also read the file (`mzmlroute`, `scanbin`, `specexact`, MRM, `scaninfo`, method and gradient) read from the reader and the sample's `guscio` (`nativi::Src`, like `Src::Nat` of the site: at most 4 open readers, 32 MB of `guscio`).
  `nat2mzml {name, pid, compression}` (`standard` = zlib, `smallest` = zlib and Numpress, `none`; `mzmlwrite::compression_options` as site and CLI) writes the mzML on request in the temporary folder and registers it as a chosen file (`{id, size}`; progress in `rawprogress?id=pid`), the page saves it from disk with `MZLAB_SAVE_MZML`.
  `natregistro {name, serie}` = one series of the instrument log of a `.raw` (`/api/registro`), the same text as the site's `thermo` module (`mzlab_lettori::json::chromatogram_json`). Every op of `rust-worker.js` has a branch in the app or a reason in `tests/test_parita_operazioni.py` (`docs/agenti/parity.md`).
- **Cold start**: `desktop-shim.js` calls `QQRESET.cold()` (`reset.js`): without `sessionStorage["mzlab.run"]` (new process) it does `run("cold")`: files, indexes, session, notebook (also the native archive, via `?riparti=1`) and work choices in localStorage disappear, then it sets the marker and reloads; a reload in the same run touches nothing. Language, theme, settings and libraries stay (`KEEP_LS`). The site does not call it. Test: `e2e_shim.py` (`__NEWRUN`).
- **Routes `feat/untargeted/*`** (`crates/mzlab-desktop/src/feat_untargeted.rs`, feature `untargeted` of `mzlab-feat-wasm`): `feat/untargeted/detect {name, params}` (a `.mzfeatf` in the `FeatState` state, answers `{bytes, sha256}`) and `feat/untargeted/align {names, params}` (the table stays for `feat/table`); `params` is the recipe `UntParams` (`docs/agenti/attributio.md`); same bytes as `detect_to`/`align_to` of the `.wasm` (`tests/feat_untargeted.rs`).
- **Graphical Flow plans** (`src/flow_run.rs`, route `flow/run`, outside the engine lock; test `tests/flow_run.rs`): `{plan, fresh?}` (text `mzflow/2`) → `{prov, dir}`. It runs `mzlab_cli::flow::run_plan_cached` (the same engine as `cargo run -p mzlab-cli --example flow`) with the plan's files registered in the app, linked (symbolic link, otherwise hard link or copy) in `<temp>/mzlab-flow/in`; outputs are in `<temp>/mzlab-flow/out`. Unregistered file: `err.flow.input.missing`. Page: `flow/lazy/flow-desktop.js` (`docs/agenti/flow-graphics.md`).
- Flow cache: `<temp>/mzlab-flow/out` stays between runs (only `in` is emptied); with the folder cache (`cli.md`) a step with the same key is not recomputed (`cached` in `prov/1`), `fresh: true` recomputes everything.
- `flow/read {name}` (same file): the text of an output file of the last Flow run (plain names only, ≤ 4 MB); with `encoding: "base64"` it answers `{"base64": "..."}` with the exact bytes (a `.mzfeat`).
- **Live run** (`src/flow_live.rs`, routes `flow/live/<op>`): a plan that accepts changes while it runs, same texts as `api/flow/sched/<op>` (`start`={`plan`, `files?`, `fresh?`}, `update`={`plan`} → jobs to cancel, `events`={`since`}, `nodes`, `jobs`, `rev`, `pause`, `resume`, `retry`/`unblock`={`job`}, `cancel`, `drop`, `finish`={`llm?`} → `{prov, dir}`); one plan at a time. `in/` and `out/` are those of `flow/run` (`<temp>/mzlab-flow`): `flow/read` and `flow/report` read what the live run wrote.
  The `convert.mzml` of the files that the queue (`conv_coda`) holds are its own: the threads leave them and `sync_queue` shows them running/finished/failed at every `events`/`nodes`/`jobs`.
- `flow/report {}`: the `run-report/1` (`mzlab_cli::flow_report::report`, the same as `mzlab-cli flow report`) of the last `flow/run` run; `flow/run` writes `prov.json` beside the outputs.
- **Regulatory lists** (`normative.rs`, routes `normative/*` of `protocol.rs`): the package lives in the libraries folder as `normative.mzsus` + `.mzlab/normative.catalogo.json`; `install` downloads from the site (chunks with SHA-256, the old file stays until the new one is complete), `check` compares the catalogs, `import?path=` accepts a `.mzsus` or the folder of `normative pack`, `listings` gives the same JSON as `.wasm` and CLI (parity: `tests/test_normative_wasm.py`), `catalog` the bytes of the installed catalog ("Regulatory lists" section of the Libraries window).
