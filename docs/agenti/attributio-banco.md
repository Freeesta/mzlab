# Attributio: Bench 2b (guided review of a feature)

The chemist reviews the features one by one; the program proposes and shows the evidence and decides a 2b only with `[levels] auto_2b = true` (`docs/agenti/attributio.md`). Cascade in `docs/agenti/attributio.md`; proposals and evidence in `docs/agenti/attributio-revisione.md`.

- **Rules** (`crates/mzlab-feat/src/attributio/review/rules.rs`, parity on the golden data of `tests/golden/attributio/`): `page_level(level, sub, decision_2b)` (`1`, `2a`, `2b`, `3`; a 2b counted as 3 stays `2b`), `decision_changes(&Current, &Rec)` (messages `level X -> Y`, `identity rejected`, `name -> N`), `note_required` (true when the decision changes level, name or group), `livello_to_level`.
- **Alternatives with the same formula** (`review/alternatives.rs`, new in mzLab): `same_formula(formula, &LibraryIndex, &AltSources{csi, exp, tol, st}) -> Vec<Alt{name, source, entry, ik1, smiles, score, matched, logp}>` from the already indexed libraries and the CSI:FingerID candidates of the campaign (no network); same compound = same first InChIKey block, otherwise same name; order by decreasing cosine, then without score, then by name; the logP comes from CSI.
- **Review of a feature** (`review/bench.rs`): `Bench::load(&Io, root)` runs the cascade and the settings; `review_json(&Io, root, pol, id) -> String` gives `{pol, id, mz, rt, current{level, sub, basis, name, identity, group}, proposal, checklist[{key, label, proof}], alternatives[..., is_best], rtlogp, decision, decision_rows, decisions_path, libraries, has_ms2, warnings}`. The proofs are computed one feature at a time; without raw data (`NoRaw`) those that need it are `null`.
- **Checklist**: six items (`CHECKLIST`: `diagnostic_fragment`, `neutral_loss`, `isotopes`, `pure_precursor`, `rt_plausible`, `alternatives_excluded`), never ticked by the engine nor mandatory; `proof` is the computed proof or `null`.
- **View for the charts** (`review/view.rs`, `proposal.rs`): `proposal.evidence.view` = `{peaks[{mz, rel, frag{formula, mz_th, ppm, loss}}], mirror{reference, peaks[[mz, rel]], pairs[[i, j, shifted]]}, isotopes[[mz, rel]]}`.
- **Saving** (`review/save.rs`): `decision_text(&Io, root, decision_json) -> Saved{path, text, replaced, added, unchanged}`; input `{pol, id, level, name, identity, group, justification, decided_on, decided_by, rt_check, checklist[keys], evidence{type, library, entry, cosine, matched, delta_mz, delta_formula, note}}`. 
- **Save refusals**: a missing note when `decision_changes` is not empty or the level is `2b`, a level outside `""|2|2a|2b|3|3a|3b`, an unknown checklist item, an analog at 2a. Append-only history (`merge_decisions`: only the row with the same `decided_on` and `decided_by` is replaced); `evidence_checklist` column last, items separated by `|`.
- **`.wasm` `attributio_rev`** (same crate `mzlab-attributio-wasm`; in the site it is the merged module `attributio-all` of the `all` feature, which the `attributio`, `attributio_export` and `attributio_ms2` manifest entries also point to; ceilings in `docs/agenti/wasm-tetti.md`): exports `export_to` (`evidence` only, see `attributio-export.md`), `review_to(read, names_json, feature_id, pol, write)` (JSON in 64 KiB chunks, answers `{bytes}`) and `decision_to(read, names_json, decision_json, write)` (CSV, answers `{path, added, replaced, unchanged}`).
- **Why separate `.wasm` files**: `attributio_rev` also contains the cascade, which is why it is not under 512 000 B; the `attributio` `.wasm` (table) stays under its ceiling and the worker loads `attributio_rev` only at the first review. Native core: `review_with`, `decision_with`, `text_to`, `saved_summary`.
- **Worker and pool** (`feat-worker.js`): `attributioReview(files, root, pol, id)` (review object) and `attributioDecision(files, root, decision)` (`{summary, text}`) with the operations `attributio_review` and `attributio_decision`; `feat-desktop-pool.js` has the same methods (`attributioDecision` additionally accepts `folder`).
- **Desktop app** (`crates/mzlab-desktop/src/feat_attributio.rs`): route `feat/attributio/review` `{root, files, kind: "review", pol, id}` → review JSON; `{kind: "decision", decision, folder?}` → `{path, added, replaced, unchanged, written, text}`, with direct writing into the `folder` if present (a path that leaves the folder is not written).
- **Page** (`TP_Mine/js/52_attributio_banco.js`, `ATTRIBUTIO_BANCO.open(ctx)`; `// @ts-check` in `tools/tipi/pagina.json`): opens from the "Open in Bench 2b" button of the expanded row of `ATTRIBUTIO_TABLE` (`#at-banco-host`).
- **Bench content**: at the top current level, class and reasons; feature/library mirror with fragments, isotopes, purity, RT against logP (SVG, `--lv*` Okabe-Ito colors, solid stroke = explained; each with its own `TDATI` table, T key on the chart); zoom with the "+", "−" buttons, arrows and "Reset"; tables of fragments, of the chemical classes from rules (`classes`, `classi/1`, `docs/agenti/classi.md`) and of the alternatives; six boxes always empty on opening with the proof beside them; decision (level, name, identity, "reject the identity", evidence, justification, reviewer). 
- **Decision in the page**: "Save" stays disabled without reviewer, without anything to save or while the note is missing (JS copy of `decision_changes`; the engine rechecks). The reviewer is kept in `localStorage` `qqq.attributio.reviewer`.
- **Keyboard**: right/left arrows (outside the text fields) = next/previous feature of the displayed list, Esc closes.
- **After "Save"**: the whole text of `feature_decisions.csv` is written into the folder if there is a writable `FileSystemDirectoryHandle` (permission asked at the click) or by the app; otherwise `feature_decisions.csv` is downloaded. Then `WORKFLOW.logOp("attributio", {attributio: {decision, feature_decisions}})` (notebook and `feature_decisions` field of the `.mzflow`), the in-memory file replaces that of the folder and the cascade reruns: the table updates.
- **Proofs**: `cargo test --release -p mzlab-feat --features attributio --test attributio_regole` (hand-written rules, alternatives on the `campagna_banco` library, review, full round: the 2b decision on POS 15 gives `level 2`, `level_sub b`, basis "diagnostic evidence", CSV equal to `tests/golden/attributio/banco/feature_decisions.csv`, all levels equal to `banco/livelli.json` of the Python reference)
- **Sublevel in the comparison**: the Python reference has `level_sub` only for 2a and 2b; 3a/3b (in Rust, `annotate/decide.rs`) is not compared with `banco/livelli.json`.
- **Other proofs**: `-p mzlab-attributio-wasm --test review`; `-p mzlab-desktop --test feat_attributio`; `python3 tests_e2e/e2e_attributio_banco.py` (weights of the two `.wasm` files, Bench on POS 15, data table, zoom, targets, mandatory note, CSV download, updated table, arrows, empty `MZLAB_LR_MISS`).
- **Test campaign**: `tests/data/attributio/campagna_banco/` (invented) overlays the synthetic one: it adds POS 15 (level 3 paracetamol with MS2), a library of three isomers `library/banco.json` and the SIRIUS top-5 files; it is not a complete folder on its own.
