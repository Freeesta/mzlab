# `mzlab-cli file convert`: conversion to mzML
Part of the command line (`cli.md`); the `convert.mzml` step and its choices are in `cli-passi.md`.

- `mzlab-cli file convert INPUT... --out FOLDER [--compression standard|smallest|none] [--zlib N] [--numpress] [--peaks file|profile|mzlab] [--spectrum auto|centroid|profile] [--workers N] [--report FILE.json] [--fresh] [--set conv.NAME=VALUE...]` (`convert.rs`, `convert_report.rs`; tests in `convert_tests.rs` with `convert_fixtures.rs`): thin caller of the `convert.mzml` executor (`flow_base::convert_job`, which reads `zlib_level`, `numpress`, `peaks` and `spectrum`). Plan of one `conv` step (one input per file or sample), cache in `FOLDER/.convert`, `NAME.mzML` in `FOLDER`.
- `--peaks` chooses the peaks written (wrong value: exit 2); a profile sample with `file` stays profile and the plan records `warn.flow.profile`.
- `--spectrum` chooses the spectrum-type term only, never the points (`spectrum_type.rs`, `Conversion::spectrum`; wrong value: exit 2; `--set conv.spectrum=VALUE` is the same). A reader flags a whole instrument family as profile (the `.wiff` reader always does), but sparse data (isolated ion counts, as a unit-resolution triple quad gives) are centroids, and a tool that trusts MS:1000128 (MZmine) smooths them and loses counts.
  - `auto` (default) keeps the reader's flag unless a level is sparse. It looks at up to 64 scans and, per MS level, at the points of the scans flagged profile. A level is sparse when under half of them sit in runs of 4+ consecutive points closer than 0.6 Da on a regular grid and under 2 % of its neighbour spacings (none at all counts too) are under 0.05 Da: a fine high-resolution grid is never touched, even among isolated single-bin hits. Only the scans of a sparse level are written as centroid MS:1000127. `centroid` / `profile` write every spectrum as asked. With `--peaks` other than `file`, `auto` leaves the flags alone.
  - One decision per sample, the same on the site, in the app and in the CLI (all go through `Conversion`; the site has no choice control and writes `auto`).
  - The decision is the stderr line `spectrum type: INPUT: spectrum=..; written=..; basis=..` (also for a file taken from the cache; `written` says `centroid for ms_level N` where `auto` acted, `as the reader` where it left the flags, `centroid` and `basis=peaks mzlab` with `--peaks mzlab`), the `spectrum_type` of the file note in `prov.json` and of the `--report` item, and, only when it is the user's word or `auto` changed a flag, the `<run>` userParam `mzLab spectrum type` of the mzML (a file whose type is what its reader says keeps its old bytes).
- Inputs: a file, a manufacturer folder (`.D`, `.d`, `.raw`) or a folder scanned in name order (only the extensions of `mzlab_lettori::estensioni()`, never `--out`). A set with several samples gives `NAME-ID.mzML` per sample; with equal names the input's extension is kept.
- `--compression` is the short form of the three choices of the page's "Download as mzML" dialog (standard = zlib level 2, smallest = zlib + MS-Numpress, none = uncompressed arrays) and gives `zlib_level` and `numpress` (`convert_report::compression_sets`).
- Bytes of `flow run` with a `convert.mzml` plan, independent of `--workers` (default `budget_auto::convert_workers`, note `warn.convert.fewerWorkers` as in the app); a file already converted (same SHA-256, parameters, program) is skipped, `--fresh` redoes it. Progress on stderr; stdout lists the mzML files.
- `--report`: array with `{input, output, sha256, spectra, seconds, skipped, conversion, warnings, centroids}` (`centroids` `{merged, saturated}` with `--peaks mzlab`, `cli-passi.md`) or `{input, error, cause}`. Exit 0 ok, 1 file in error (others written), 2 usage or output over an input, 3 partial read (`conversion/1.partial`), 4 input missing or empty.

## Converter rules
- One writer and one path: `Lettore` → `readers_mzml` → `MzmlWriter`, for site, desktop, `convert.mzml` and CLI; the metadata do not depend on the route. The writer stays in `mzlab-core`, no new crate.
- The extras of the spectrum (precursors with charge, window, activation and energy, `spectrumRef` of the parent; manufacturer TIC and base peak; injection time; scan windows) live in `SpectrumExtra`, in conversion only: `Spectrum` does not change.
- Zero declared losses: whatever has a PSI-MS term becomes a cvParam with units, the rest a userParam `<format>.<field>`; every file carries in `<run>` the userParam `mzLab conversion/1` (reader, fields as CV, as userParam, not carried with the reason): keys `reader`, `version`, `compressor`, `cv_fields`, `user_fields`, `declared`, `read`, `partial` (+ `loss` cause key, + `unit` `cycles` for MRM), `not_carried` [{`field`, `reason`}] and the same row goes into `--report`. A field not carried without a reason is a red test.
- Peaks: no manufacturer library; the "manufacturer" centroids are only those written in the file. No SDK or DLL (RawFileReader, SCIEX SDK, Agilent, Bruker, Waters): per-system runtime, redistribution constraints, no WASM. The vocabulary `psi-ms.obo` (CC BY 4.0) enters as a generated table with attribution in `THIRD-PARTY-LICENSES.md`.
- Same bytes with 1 or N encoding threads; memory O(threads × spectrum); index and SHA-1 streamed (measurements: `raw-mzml.md`, "Codifica in parallelo"). On the site conversion is on request only (the OPFS quota cannot hold a copy of every file); in the app the background queue reuses by SHA-256 + writer version + parameters.
- A file's error has phase and cause (single form of `diagnosi.js`), never `err.route.unavailable`, which stays the key of a route the engine does not serve.
- Tolerances of the comparison with the oracles (`examples/mzml_compare.rs`, at the bottom): m/z 0 ppm for the same source (0.05 ppm if the oracle writes 32-bit m/z), RT ≤ 1e-6 min, relative intensity ≤ 1e-6; with numpress the declared error of the codecs, ≤ 2e-4. Oracles: MSConvert (Windows only) and ThermoRawFileParser, on the lab's computer, not in CI.
- "Better" is declared only where a measurement says so; the formats only MSConvert reads (TripleTOF, Agilent IMS) are listed as such. The converter cannot be better than the reader: Thermo profile, TSQ MRM and the `.raw` files not opened depend on `vendor/opentfraw`.
- Open goals: DDA Q Exactive 1.6 GB ≤ 12 s with 4 threads and ≤ 256 MB; BAF Orbitrap 595 MB ≤ 6 s; TDF timsTOF ~100 MB into centroid mzML in < 10 min with RAM ≤ 2 GB; ≥ 38/41 `.raw` of the lab's corpus converted; 100 % of converted files valid (XSD + CV + index + SHA-1).
- `examples/mzml_compare.rs A.mzML B.mzML [--per scan|indice] [--f32] [--numpress]` (pass of `mzml_validate::analizza`): pairs the spectra by `scan=` number (or by position) and the chromatograms by type, Q1 and Q3; prints counts and max deviations of level, polarity, RT (≤1e-6 min), precursors (m/z, charge), points, m/z (0 ppm; `--f32` 0.05) and intensity (relative ≤1e-6; `--numpress` 2e-4); exit 1 if anything exceeds the tolerance or stays unpaired.
