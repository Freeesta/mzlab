# Waters MassLynx `.raw` (folder): `waters` module

Reader in `crates/mzlab-lettori/src/waters/` (feature `waters`, `ENTRY` `id: "waters-raw"`, module ceiling 327 680 B). The format was derived from real files (Xevo TQ-S/TQ-XS/TQ in MRM, Xevo G2-S, Synapt HDMS and G2-Si, ProteoWizard's Vion/SONAR) with `openwraw` 4.0.0 (Apache-2.0) as a guide for the TOF record encodings; the code is written from scratch. A Waters `.raw` is a FOLDER `X.raw/`; the Thermo `.raw` is a file (no conflict: `locateWaters` wants a file inside a `*.raw` folder).

## Page
- `waters-raw.js` (`WatersRaw`, classic, `// @ts-strict`, called by `cartella-carica.js` before `AgilentD.group`): `group(files)` gives `{ runs, rest }`; the `*.raw` folders with `_FUNC001.DAT` are `runs`, as `{ name, root, files: [{ rel, file }] }` (only the files directly in the folder, without hidden ones); a `*.raw` folder without `_FUNC001.DAT` is not a run and its files stay in `rest`.
- `toMzml` makes a placeholder `File` of it with `LETTORI_MOD.stand(nome, membri, 0, "waters")`: no engine reads Waters, so the run goes straight to the module (rule R of `shell.js`, `docs/agenti/readers-module.md`), which writes the mzML into OPFS. The members are called `x.raw/_FUNC001.DAT`, ….
- `lettori-famiglie.js`: row `waters` (`ext: [".raw"]`, `membri: ["_func001.dat"]`, `errori: []`: no engine error sends a folder to the module, the run goes there directly). `cartella-carica.js` counts the folder as one file to load. Tests: `tests/test_waters_raw.py` (node), `tests_e2e/e2e_waters.py` (synthetic folder from `tools/waters_sintetico.py`).

## The reader
- `riconosci`: `_FUNC001.DAT` present = `Forse`; with `_FUNCTNS.INF` of whole records (416 B) = `Si`. `apri`: error `err.file.raw` (`detail`) if `_FUNCTNS.INF` or `_FUNC001.DAT` is missing. A scan with a record word, a size or a range that no acquisition writes (`dat::whole`) stays out, counted (`warn.waters.damaged`) and named ("function N: k damaged scans left out"); the check reads every scan once, at the first index or scan request (`scans::ready`). One sample per folder. The `.DAT` files are read by position.
- Limits: every number read goes through `Limiti::ok_entries`. A member the folder has is read or the folder is rejected, never taken as absent (`Folder::read`): `_HEADER.TXT`, `_extern.inf`, `_INLET.INF`, `_CHROMS.INF` and `.CMP` up to 8 MB; `_FUNCnnn.IDX`, `.STS` and `.EE`, which grow with the run, up to the byte budget; beyond that, `error.memoryBudget` (WA-05). Test: `crates/mzlab-lettori/tests/waters_optional.rs` (index over 8 MB read whole, index over the budget = error) [eseguito].
- `meta.notDecoded` warnings of `apri`: missing member named ("function N: _FUNCnnn.DAT missing" or ".IDX missing"; "no scans" if the index is empty); for a targeted function, index scans with fewer channels than the others and channels of `_FUNCTNS.INF` different from the records per scan of the IDX; functions of `_extern.inf` beyond the list of `_FUNCTNS.INF`. Also: scans beyond the end of a cut DAT, per function; `_HEADER.TXT` missing next to a scan function (m/z without a calibration polynomial). Test: `crates/mzlab-lettori/tests/waters_counts.rs`.
- `apri` also gives `err.file.functionsEmpty` (`name`) if `_FUNCTNS.INF` is empty and `err.file.recordVariant` (`name`, `function`, `type` in hexadecimal; `unknown_variant`) if the folder gives no scans, no channels and no analog traces because a function with data, not MRM/SIR, has records of undecoded width (`cod` absent). Next to a readable function the `meta.notDecoded` warning "record width" remains.
- Losses (`Reader::losses`, `counts::losses`): index scans not read, declared = read + lost; cause = the one with the most scans. `warn.file.truncated` beyond the end of a cut DAT; `warn.file.memberMissing` for a scan function without its DAT (its rows do not count as a cut); `warn.file.recordWidth` for a scan function with records of undecoded width. Targeted functions (channels, not scans) do not count. Test: `crates/mzlab-lettori/tests/waters_losses.rs`, parity in `tests/test_lettori_parita.py`.
- Incomplete copy in `apri`: folder without `_FUNCTNS.INF` = `err.file.folderIncomplete` (`name`, `file`); `_FUNCTNS.INF` whose length is not a multiple of 416 B = `err.file.folderFileCut` (`name`, `file`). A damaged part stays out, counted (`warn.waters.damaged`) and named; the rest is read (partial read, code 3 in the CLI). The folder is rejected, with the key of the first part left out, only if no scan, no channel and no analog trace remains. Without `_FUNC001.DAT` the folder is not recognized (`waters-raw.js`). Tests: `waters_incomplete.rs`, `waters_damaged.rs`.
- `_FUNCTNS.INF` (`functions.rs`): 416 B record. Type at +0, subtype at +1, cycle time `f32` at +2, `tof_depth` `u16` at +0x10, dwell times `f32` ×32 at +0x20, Q1 (or minimum mass) ×32 at +0xA0, Q3 (or maximum mass) ×32 at +0x120. A targeted function (MRM; SIR [non provato]: no real SIR folder) has the low nibble of the type equal to 9 and its channels are the slots with Q1 > 0; bit 7 of the subtype of a non-targeted function is the lock mass (reference).
- `_FUNCnnn.IDX` (`idx.rs`): one row per scan, in two variants. A: 22 B with the DAT offset `u32` at +0; B: 30 B with the `u64` offset at +22. In both: number of records in the low 22 bits of `u32` at +4 (the bits above are marks; the high byte, seen only whole: 0x18 continuous uncalibrated scans, 0x08 reference function or MRM, 0x4C centroids that the acquisition already calibrated), TIC `f32` at +8, RT in minutes `f32` at +12.
- IDX variant: chosen from the size; if the size fits both, A holds only if every row has a known mark and the offsets do not go back. The DAT record width is (bytes of the scan) / (records of the scan).
- `_FUNCnnn.DAT` scan (`dat.rs`), three encodings by width: 6 B (A: ion count `u16` + 4 B m/z word, no real file), 8 B (D) and 12 B (E, with 4 unread trailing bytes). D and E: intensity word `u32` (21-bit mantissa with bit 20 set, 5-bit exponent from bit 22: `m·2^(e-21)`, exact against the index TIC) and m/z word `u32` (5-bit exponent at the top, 27-bit mantissa with bit 26 set: `mant/2^27·2^e`). A record with mantissa 0 is skipped. The peaks are profile (6 and 8 B) or centroids (12 B).
- Calibration: `_HEADER.TXT` has lines `Cal Function N: c0,…,ck,T1`; the polynomial is applied to the square root of the raw m/z (proportional to flight time) and the result is squared; `T0` = no correction.
- Per-scan calibration (IDX mark): the polynomial goes to the 0x18 and 0x08 scans and NOT to the 0x4C ones (m/z as the acquisition wrote them, having already calibrated them); an unknown mark keeps the polynomial with the warning "unknown calibration flag 0xNN in N scans".
- The header of every scan says which calibration ("m/z calibration"). Reference function 0x08 at 12 B (MTBLS178, Synapt): the polynomial is right (lock mass calibrant at about +390 ppm without it, about −23 ppm with it: the remaining offset is the uncorrected drift); other instruments not verified. Test: `crates/mzlab-lettori/tests/waters_flags.rs` (`flags_folder`, twin `write_flags` of `tools/waters_sintetico.py`, parity in `tests/test_lettori_parita.py`).
- Targeted `_FUNCnnn.DAT` (`mrm.rs`): one value per channel per scan, no m/z. Width 4 B (22-bit mantissa, 10-bit exponent: `m·2^(e-21)`, exact against the TIC) or 2 B (13-bit mantissa, 3-bit exponent in base 4: `m·4^e`, within quantization).
- Interrupted copy (`load.rs`): an IDX scan that does not fit whole in the DAT is emptied and counted (`warn.file.truncated`). Left out whole, rows counted: the function with an IDX cut inside a row (`err.file.indexCut`), with an IDX that does not match the DAT (cut to a whole row, offsets going back or beyond 2^40; `err.file.indexCut`) or with a missing IDX next to a DAT with data (`err.file.folderIncomplete`); an index that cannot be counted gives "at least 1". Functions with data beyond the list of `_FUNCTNS.INF` stay out with their rows (`err.file.functionsCut`).
- `_HEADER.TXT` empty or cut inside a `$$ Cal` row: a scan function with data and without a whole `Cal Function` row stays out (`err.file.headerCut`), never with uncalibrated m/z; the others are read. One cut at a line end is not recognized. An unreadable analog trace stays out alone, named ("k analog traces unreadable, left out: n (name)"); an unreadable `_CHROMS.INF` leaves the traces out. Test: `crates/mzlab-lettori/tests/cuts_counted.rs` (every cut of every member), `waters_damaged.rs`.
- `.STS`/`.EE` (`sides.rs`): per-function tables with field name and one value per scan or channel ("Set Mass" = precursor, "Collision Energy"); `.CMP` = channel compound names.
- Polarity (`inf.rs`): "ES+"/"ES-", "Positive"/"Negative" or a mode ending with the sign ("ESCi+", "APCI-").
- `_extern.inf` and `_INLET.INF` (`inf.rs`): method text (source, capillary, cone, temperatures, gases, per function label, mode, polarity, collision energy ramp or value, ranges) and LC gradient, flow, oven. `_CHROMS.INF` + `_CHROnnn.DAT` (`chroms.rs`): analog traces (pressure, flow, % solvents, UV) as chromatograms.

## Functions and levels
- Scan function: spectra `function=N process=0 scan=K` sorted by RT. Level (`level_of`): lock mass (bit 7 of the subtype or reference mode) = 1, and it is also in the spectra as `function=N` with the filter "function N lock mass" (like msconvert; folders without lock mass do not change); MS/MS mode or "daughters" of `_extern.inf` = 2 (precursor from "Set Mass" of `.STS` or from `_extern.inf`).
- MSe: MS mode with an energy ramp and another MS function without a ramp = MSe, level 2, no precursor (the 775 ± 725 m/z "precursor" that msconvert writes on every MSe spectrum is the center and half-width of the 50-1500 range, not an isolation; the header says "acquisition: MSe, no precursor selection"); otherwise the first function (or the only one) is level 1 and the others level 2.
- Targeted function: no spectra (like msconvert); one SRM chromatogram per channel, id `SRM SIC Q1=<q1> Q3=<q3> ce=<CE> polarity=negative function=<f> offset=<j> name=<composto>` (`ce=`/`polarity=`/`name=` are mzLab's, `polarity=negative` only if `_extern.inf` says ES-; msconvert puts "- " in front; the rest is msconvert's id); for SIR `SIC <q1> …`.
- Targeted channels, values: Q1 and Q3 (mzML id and target) are the shortest decimal that gives back the `f32` of `_FUNCTNS.INF`. A channel has a point only in the scans that contain it (no invented 0). `TIC` = sum of the non-reference functions, by RT. The lock mass function is also given as chromatogram `lock mass function=N TIC` (type `Other`).
- Lock mass: mzLab applies no correction of its own. The 0x4C scans are as the acquisition wrote them (already calibrated, with its possible correction); for the others the m/z are those of the file calibration (30-100 ppm offset on files with lock mass). The `calibration.lock_mass` field of `method/1` and the header of every scan say so.
- Ion mobility: IMS functions (HDMSe, HDDDA, SONAR, cyclic) are read as m/z summed over all drifts, without drift time; the `meta.notDecoded` warning "ion mobility" is there only if `_extern.inf` marks the function (`Extern::mobilita`): yes on HDDDA, no on HDMSe and SONAR [eseguito]. msconvert with `--combineIonMobilitySpectra` gives one scan per cycle, comparable with ours.

## `method/1` and mzML header
- `Header::run_params` carries `("mzLab method/1", documento)`. Sections: `instrument` (model and serial from `Instrument: MODELLO#SERIALE`), `origin` (folder, SHA-1 of every `_FUNCnnn.DAT`, `file_created` from "Acquired Date/Time"), `sample` (name = "Sample Description", vial = "Bottle Number", id), `operator` ("User Name", "Submitter", "Laboratory Name" and the paths, marked `identity`: never copied into the mzML).
- Sections, continued: `ms` (source, experiments per function with type MRM/lock mass/MSe/MS2/MS, transitions Q1/Q3/dwell/CE/name/polarity, cycle time, `tof_depth`, `calibration.lock_mass`), `lc` (gradient, flow, oven, duration).
- Every row of `_HEADER.TXT`, `_extern.inf`, `_INLET.INF` and `_CHROMS.INF` is in `fields`; what is not decoded is in `warnings` (`meta.notDecoded`). Header sources: `_FUNCnnn.DAT` with SHA-1; CV `MS:1000769` (Waters nativeID) and `MS:1000526` (Waters raw format).

## Tests
- Test classes for the reader claims: `[eseguito]` = proven on a real or built file (command or test given); `[letto]` = from reading the code only; `[non provato]` = neither. The codes (WA-02, TS-01) are those of the readers review.
- `crates/mzlab-lettori/tests/waters_synthetic.rs` (folder built in the test by `comune_waters`: 2 functions, 3 scans, m/z and intensity words encoded in the test), `robustness_waters.rs` (cut, empty, missing members, swapped bytes, absurd numbers in the IDX, small limits), `waters_data.rs` (13 real folders, with `MZLAB_DATI`).
- Parity with msconvert (`ST004453_TQXS_04292022_038`, Xevo TQ-XS): 128 SRM chromatograms + TIC + 4 analog traces equal to 1e-6 relative; no spectra, like the mzML.
- On real folders the sum of the intensities of a scan equals the index TIC (0.2 %) [eseguito], 0x4C centroids included, except the reference lock mass function.
- Reference lock mass function (MTBLS178: mark 0x08, 12 B centroids): its TIC is not the sum of its intensities (the vendor library reads the same intensities and the same TIC, up to 10 % offset), and `waters_data.rs` compares the scans with "role: lock mass reference" within 10 %.
- Calibration of the MTBLS178 reference function [eseguito]: the leucine-enkephalin [M-H]- 554.2615 peak is at +390 ppm without the `_HEADER.TXT` polynomial and at -23 ppm (from -40 to -12) with it, over 53 scans: the 0x08 function is not saved already calibrated and the polynomial must be applied to it; the -23 ppm is the drift that the lock mass would correct. The offset against the TIC does not come from the calibration.
- **Against msconvert** [non provato]: the spectra of the TOF files (MTBLS178, MTBLS1198, MTBLS957: no mzML in the data repository), DDA, SIR and the 6-byte encoding (no file). `HDMSe_Short_noLM`, `HDDDA_Short_noLM`, `HDMRM_Short_noLM` and `SONAR_Short` have an msconvert `-combineIMS` mzML, comparable per cycle [non provato qui].
- `waters_mse_oracle.rs` (MTBLS7394 `Blk_ext_2_C18MSe_1`, MSe + lock mass + IMS, `MZLAB_ROSINA_DATI` or `/Volumes/Fred/rosina`, skips without): cycles 242/241/97, RT, TIC and weighted mean m/z of the first 3 cycles of each function against the msconvert profile mzML (constants in the test; msconvert gives one scan per drift bin, we one per cycle, so the cycle sums are compared).
- Folder with empty `_FUNCTNS.INF` (lipidomics MTBLS1584): gives `err.file.functionsEmpty` [eseguito] (the cyclic IMS PXD052561 opens [eseguito]); the function list is not rebuilt from the `_FUNCnnn.*`. Synthetic tests: `crates/mzlab-lettori/tests/waters_variants.rs`.
- Module build: `tools/build_lettori_wasm.sh` (family `waters` in `con_lettori`). What is not extracted: `raw-not-extracted.md`.
