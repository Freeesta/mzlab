# Mutation tests (cargo-mutants) of the readers and the wiff module

What the `cargo-mutants` runs on `crates/mzlab-lettori` and `crates/mzlab-core/src/wiff/` say, which survivors remain and why. These are sampled runs: the full run (3891 mutants in the readers, 1582 in the wiff module) takes days with the complete suites.

## How to rerun
- `cargo install cargo-mutants` (version 27). The wiff module: `cargo mutants -p mzlab-core -f 'crates/mzlab-core/src/wiff/*.rs' --shard 0/16 --sharding round-robin -j 3 -o DIR -- --lib --test 'wiff_*' --test mzml_modes_sciex` (one `--test` per `tests/wiff_*.rs` file; the whole `mzlab-core` suite costs ~18 min per mutant). A single mutant: `-F '<line of missed.txt>'`.
- The readers: `cargo mutants -p mzlab-lettori --shard 0/32 --sharding round-robin -j 3 -o DIR` (all the crate's tests, ~3 min per mutant).
- Code under `#[cfg(feature = "estesi")]` (`extended.rs`, `scan_extended.rs`, `run_extended.rs`) is compiled only with the feature: a run with the default features of `mzlab-core` always reports it as "missed". Try it with `--features sciex`; CI compiles it because it builds `mzlab-core` together with `mzlab-lettori` (`ci_binari_test.py -p mzlab-core -p mzlab-lettori`, unified features).
- The `mutants.out` folders do not go into the repository; each run needs ~4 GB of disk per job.

## wiff module (1/16 sample, 99 mutants)
- First run: 53 caught, 28 survived, 17 unviable, 1 timeout.
- Caught afterwards by the new tests: DAD step and wavelength axis (`wiff_synthetic_ci.rs`, 2 nm step because with 1 nm `*` and `/` coincide), rest of the DDE records, ITC offset and every TDC token (`dad_tests.rs`), `.dam` names (`method_name.rs`).
- Also caught by the new tests: CV term of the spectrum type and polarity from the IS voltage (`modes.rs`, `source_polarity`), mzML header (`run.rs`: every field, known and unknown model), block size and time of an unindexed section (`unindexed.rs`, also with two experiments per cycle), zero runs of a sparse MRM block (`scan_extended.rs`).
- Remaining, only with real data (the tests that cover them read the `.wiff` files of the private repository and are skipped without it): `reader.rs` `wiff_member` → `Some(0)` (in synthetic files the `.wiff` is always the first member: equivalent there), `scan_header`, `add_unindexed` (`==` → `!=`); `reader_extra.rs` `header_tic` and the `tic` field of `extra_of` (they need scan spectra with a TIC in the index).
- Remaining by choice: `reader.rs` `not_carried` (descriptive text only, no behavior), `dad_wavelength` (it only passes to `dad_uv::dad_wavelength_json`, tested by `mzml_dad_tests.rs`; no test opens the wiff reader on a file with DAD), `scan.rs:171` `>` → `==` in the memory cap (a block of ~13 MB would be needed to hit it), `scan.rs:38` `+=` → `-=` in `Nibbles::long` (endless loop: timeout, i.e. caught).
- Under `estesi` (run with `--features sciex`, tests `--lib`, `wiff_*` and `mzml_modes_sciex`): caught `refine` and `header_estesi` replaced, `visit` → `Ok(vec![])`, the two conditions of `read_mrm_cols`. Remaining: `extended.rs:67` `>` → `>=` in `refine` (only with a precursor mass of exactly 0, at the boundary), `run_extended.rs:76` `||` → `&&` in `chromatograms` (scan records are needed: the synthetic generator only makes MRM, files with scans belong to the private repository). `visit` → `Ok(vec![Default::default()])` was not judged (disk full during the run).

## Readers (1/32 sample, 122 mutants)
- First run: 76 caught, 40 survived, 5 unviable, 1 timeout.
- Caught afterwards by the new tests (Bruker): C2·C4 terms of the calibration and temperature factor (`calib.rs`), long LZF references, zstd window with dictionary id, empty scans of an LZF frame (`block_tests.rs`), TSF profile with the zero next to the signal (`tsf.rs`), two-level WITHOUT ROWID table and negative short integers (`sqlite_columns.rs`), collision energy and half-widths of the DDA-PASEF precursors (`bruker_precursor.rs`).
- Caught afterwards by the new tests (others): family of the test build and empty probe (`build_family.rs`), mzML header of an ANDI (`andi/header_tests.rs`), first `instrumentConfiguration` of an mzML (`mzml_header_tests.rs`), closing tag (`mzml_numpress_tests.rs`), charge and activation of the mzXML precursor in the written mzML and `parentFile` path as identity (`open_mzxml.rs`), ISO date, parameters and gradient rows of Waters (`waters/doc_tests.rs`, `waters/inf_tests.rs`).
- Remaining, equivalent or only at the boundary: memory and field caps taken at equality (`shimadzu/mod.rs:130`, `bruker/header.rs:36`, `shimadzu/load.rs:240`, `andi/ms/counts.rs:112`), `shimadzu/dir.rs:35` (a 512-byte file has no directory), `bruker/tsf.rs:36` (the read that follows fails anyway), `open/mzml_header.rs:277` (the signal is read only in the first configuration), `bruker/sqlite_min.rs:356` (the last overflow page read beyond the payload: the record header ignores its tail).
- Remaining, only with real data (Waters `.raw` folders, Shimadzu files and damaged mzXML of the private repository): `waters/chroms.rs`, `cuts.rs`, `functions.rs` (`riferimento`), `inf.rs:170`, `mrm.rs`, `sides.rs`; `shimadzu/meta.rs:77` and `:234`; `open/mzxml_index.rs:82`; `andi/netcdf/pieces.rs:95` (record variables with more than one entry per record).
