# LLM: tools, providers and recordings (`crates/mzlab-llm`)
Principles and choices: `llm-choices.md`. The `mzlab-llm` crate (workspace member, depends only on `mzlab-core`, no network, no key) is used by `mzlab-cli llm`; no `.wasm` includes it (it arrives with the transport).

## Catalogue `tools/1`
- `mzlab_llm::tools::catalog(&[Step], &[UiTool], &dyn Fn(&str)->bool) -> Vec<Tool>` and `catalog_json(..) -> String`: 20 fixed meta-tools (`flow_list_steps`, `flow_describe_step`, `flow_get_plan`, `flow_check`, `flow_propose_plan`, `flow_add_step`, `flow_set_param`, `flow_remove_step`, `flow_run`, `flow_status`, `flow_read_result`, `data_summary`, `data_inspect`, `params_propose`, `table_check`, `table_rows`, `ask_user`, `chart_make`, `code_export`, `ui_show`), each with a `class` (`read|propose|edit|run|ui`) and an `input_schema` JSON Schema 2020-12.
- The arguments are generated from the `flow::steps()` registry: `flow_add_step.step` and `flow_describe_step.step` = `enum` of all `id@version`; `flow_set_param` = `oneOf` with one branch per step (`step` const, `name` = `enum` of the `--set` names: common parameters, parameters of each algorithm, `algorithm`, `preset`; `value` = parameter schema, `anyOf` if the same name has different schemas across algorithms); `flow_list_steps` carries `x-executable-native` (ids with a native executor, from the function passed in).
- `docs/schemi/tools-1.json` is made for merging: no registry hash, steps sorted by id, one element per line in every long list (`spread` in `mzlab-llm/src/tools.rs`), so two PRs adding different steps merge without conflict; after a merge `MZLAB_UPDATE_STEPS=1 cargo test -p mzlab-cli --lib llm_tools` is enough.
- `UI_TOOLS` is the closed list of `ui_show` (`show_xic` → `spec.xic`, `show_spectrum_at_rt` → `chrom.specAtRt`, `show_row` → `table.showRow`, `select_node` → `flow.selectNode`; the last two ids are registered in the page PRs, list `NOT_YET` in `tests/test_tools_catalog.py`, which only gets shorter).
- `mzlab-cli llm tools [--demo] [--out FILE]` (`crates/mzlab-cli/src/llm.rs`) prints the catalogue; `docs/schemi/tools-1.json` is its export (`MZLAB_UPDATE_STEPS=1 cargo test -p mzlab-cli --lib llm_tools` rewrites it).
- Demo catalogue: `tools::demo_catalog(..)`/`demo_catalog_json(..)` keeps the 12 names of `DEMO_TOOLS` (`flow_list_steps`, `flow_describe_step`, `flow_get_plan`, `flow_check`, `flow_propose_plan`, `flow_set_param`, `data_summary`, `data_inspect`, `params_propose`, `table_check`, `ask_user`, `chart_make`) in the order of the full catalogue and with the same schemas (a test proves it); export `docs/schemi/tools-demo-1.json` (`--demo`), copied by `tools/build_site.py` into `static/llm/`, read by the proxy.

## Providers `llm-provider/1` and adapters (`provider/`)
- `provider::builtin()` reads `data/fornitori-1.json` (anthropic, `mzlab-demo`, openai, gemini, local ollama): `price_per_mtok` carries `in`, `out`, `cache_read`, `write_5m`, `write_1h`, the optional tier `over{above_tokens,..}` (Haiku 5.5 beyond 100 000 prompt tokens) and `as_of`: the Anthropic prices were verified on 2026-10-22, for the others 0 = unknown; a test forbids a price without `as_of`; absent caches: read = `in`, writes 1.25× and 2×. `Provider::parse` reads a user descriptor. Schemas: `docs/schemi/{llm-provider-1,llm-conv-1,llmlog-1,llmreg-1}.json`.
- Provider `mzlab-demo` (the mzLab proxy, `proxy/`): `anthropic` adapter, placeholder `base_url` `https://proxy.invalid`, no key (empty `auth.header`), `session_headers` `x-mzlab-session`/`x-mzlab-owner`, only Sonnet 5.5 and Haiku 5.5. `provider::demo::for_send(p, req, host, session, owner)` puts the host of `mzlab/web/llm/proxy-host.js` (single constant, empty = nothing is sent: `err.llm.network` reason `proxy`) in place of the placeholder and adds the headers; the body does not change.
- `for_send` is used by `demo_send` of the `.wasm` (worker) and by the app's `llm/send` route (binary's host, `session`, `owner`); `demo/body.sha256` proves app = site. With `mzlab-demo` the roles take `demo_max_tokens` of `assist-roles-1.json` (`assist::roles_for`, `orchestrator_caps`: 1500, 3000 after the phase prompt).
- `provider::request(&Provider, &Conversation, &[Tool]) -> Result<Request>`: `{url, headers, body, auth: AuthSlot{header, prefix}}`, never the key (empty header = no key, local servers). `tools: native` sends the schemas in the provider's field, `prompted` puts them in the system text, `none` does not send them; an image to a model without `vision` and an unknown provider or model give `err.llm.conversation`.
- `provider::request_with(&Provider, &Conversation, &[Tool], &Options)`: `Options` (only the `anthropic` adapter reads them; `request` = `Options::default()`, plain body) = `cache_ttl` (explicit cache point `5m|1h` on the system block), `cache_auto` (automatic point at the top), `effort` (`output_config.effort`), `adaptive_thinking`, `strict_tools` (`strict: true` on every tool), `format_schema` (`output_config.format`, only without tools, otherwise `err.llm.conversation`); `temperature`, `top_p` and `top_k` are never sent; the header stays `anthropic-version: 2023-06-01`.
- `Conversation` (`conv.rs`, `llm-conv/1`; the system text is the `system` field; `Role::System` = a `role: "system"` message mid-conversation, for the other providers a user turn); adapters `anthropic`, `openai` (Chat Completions and compatibles), `gemini` (schema in `parametersJsonSchema`; a tool result carries the name from the call with the same id).
- `provider::Stream::new(Adapter)` with `push(&[u8]) -> Vec<Event>` and `finish() -> Vec<Event>`: SSE lines (`sse.rs`) and UTF-8 bytes can be split anywhere, the JSON of a tool-call comes out in pieces in `tool_call_delta`. A stream finished without `stop` gives `err.llm.network` (`reason=truncated`). `.prompted()` reads the last ```json block `{"tool":NAME,"args":{}}` of the answer and emits it as a tool-call (id `prompted-1`, `stop` = `tool`); the `text_delta` already emitted stay.
- `provider::retry_delay(status, retry_after, n)`: only a 429 with `retry-after` is retried (at most `MAX_RATE_RETRIES` = 2); `provider::http_error(status, body) -> Event`: the 400 "specified workspace API usage limits" and the 429 `enforced_spend_limit_reached` are `limit.workspace` (never retried), 401/403 `auth`, 429/529 `rate`, 413 or context words `context`, 408/5xx `network`, other `bad_response` (`err.llm.*`); a message that looks like a key is discarded.
- `event.rs`: `Event` = `text_delta`, `tool_call_start/delta/end`, `usage{in,out,cache_read,cache_write_5m,cache_write_1h}` (writes are emitted only if > 0; the `anthropic` adapter reads them from `usage.cache_creation`, or from the total `cache_creation_input_tokens` as a 5-minute write), `stop{end|tool|length|refusal}`, `error{key,params}`; `to_json()` one line with ordered keys.

## Recordings, log, cost
- `fake::Replay::parse(text, strict)` reads `llmreg/1` (one line per turn: `events`, `request_sha256`); `respond(&Request)` gives the next turn, `at(n, &Request)` turn n, `reset()` starts over. `strict` compares the SHA-256 of the body (`err.llm.replay.mismatch`); `record_line` writes a line. Errors: `replay.exhausted`, `replay.format`.
- `log::Log::event(turn, &Event)` builds `llmlog/1` in memory (the caller writes the file); `log::has_secret` rejects `sk-`, `sk-ant-`, `AIza` at the start of a word followed by a character (`err.llm.log.secret`).
- `cost::estimate(&Usage, &Model) -> Option<f64>`: in the price's currency, caches read and written as input; `None` if `in` or `out` is 0.
- `spend` (`spend.rs`): `Prices` in micro-dollars per million tokens (`list()` from the providers, `parse` of the `PRICES` variable), `cost(model, &Usage)` with the caches and the high tier, `max_cost`; `Meter::admit(model, input_estimate, max_tokens) -> Ticket` reserves the worst case and never lets the cap be exceeded (`err.llm.limit.spend`), `charge(ticket, model, &Usage)` replaces it with the true cost, `release` returns it, `soft_notice()` is true once at 80 %. `Ledger` (`spend/ledger.rs`) is the shared ledger of the public proxy (`docs/agenti/assistant-proxy.md`).
- `mzlab-cli llm replay REG.jsonl --conv CONV.json [--turn N] [--strict]`: the events of a turn, one line per event (`docs/agenti/cli.md`).

## Profile, settings, consent (`mzlab/web/llm/`)
- Profile (`settings.js`, `uipProfile()`): not a user choice: `ricerca` with administrator mode (5 clicks on the logo) or in the desktop app, otherwise `demo` if `UIP_DEMO` (D2) is true, otherwise `corso`. With `demo` the settings have no assistant and only the Flow page shows "Try the assistant" (`F.demo()`);
- Profile `demo`: nothing of `llm/` is downloaded before the click on "Try the assistant", then consent for `mzlab-demo` (`demoOpen` of `llm-agente.js`) and fixed settings of `llm-demo.js`: level L1, "Hide file names" on, cap $0.50 per panel opening that cannot be changed (`spendCheck`), one random session per opening; two chips "Explain these files" and "Set up mzFlow for me" (labels `llm.chip.*`, fixed text sent).
- With `corso` no LLM element in the DOM and no file of `llm/`; with `ricerca` and the switch off there is only the switch: `llm-impostazioni.js` is imported when `mzlab.llm.on` is true or the switch is turned on. The old text `mzlab.profilo` ("corso"/"ricerca") is deleted.
- `llm-impostazioni.js` (`mount`): provider and model from `fornitori-1.json`, level (L0 default, L1, L2), L2 limit, spend cap, "Hide file names", revocation, key area, test message with "What will be sent" preview (the request without key). Settings in `mzlab.llm`; the test hook `window.MZLAB_LLM.replay(text, strict)` loads an `llmreg/1` recording.
- Errors that stop a turn: text in the catalogues (`err.llm.*`, shown by `llm-impostazioni.js`) and, for the Flow panel (English only), in `flow/lazy/flow-llm-errors.js` (extends `F.message`); `tests/test_llm_errori.py` enforces both for every terminal key.
- `llm-consenso.js`: modal `<dialog>` (focus on "Cancel", Esc closes only the dialog, texts `llm.consenso.*`); consent per provider and class (`plan`, `summary`, `names`) in `localStorage mzlab.llm.consenso`, revocable. For `mzlab-demo` classes `inspection` and `plan`, one visit only (`sessionStorage`), D4 text (`llm.consenso.demo.*`) with "What will be sent" = the request of the first chip built by Rust; refusal leaves the parts without a model.

## Transport on the site
- After consent the page creates the `llm/trasporto.html` iframe with its own CSP (`default-src 'none'`, `connect-src 'self' http://localhost:* http://127.0.0.1:*` plus the proxy host): the key lives only there (memory; "Remember on this device" encrypts it with AES-GCM in IndexedDB `mzlab_llm`, non-extractable key; "Forget key" deletes it).
- The response bytes pass to the `llm-worker.js` worker over a `MessageChannel` (origin check at port delivery); the worker loads `wasm-feat/llm/` (`mzlab-llm-wasm`) at the first request and decodes with `LlmStream`; `tools-1.json` sits beside it (`tools/build_site.py`).
- Demo proxy host: ONE constant, `PROXY_HOST` of `llm/proxy-host.js` (empty: nothing is sent, the card says "Assistant not available"). Worker, clients and app read it; `tools/build_site.py` (`transport_csp`) writes it into the `connect-src` of the built transport. No provider host in the site, `tests/test_llm_csp.py` the allowed sources.
- The key goes only to the origin of its provider: the app checks every ready `request` of `llm/send` with `demo::url_belongs` (otherwise `err.llm.network`, `reason=url`; proxy host from `proxy-host.js` in the binary, never from the page; `ureq` does not follow redirects); the site transport derives the origin from `llm/fornitori-1.json` and `proxy-host.js`, `redirect: "error"` (`tests/test_llm_trasporto_origine.py`); the iframe has no `.wasm`.
- Owner phrase: for `mzlab-demo` the transport "key" is the phrase (`x-mzlab-owner`, name from the descriptor), always in IndexedDB `mzlab_llm`, "Forget" deletes it; the field is visible only after a 403 `err.llm.proxy.closed` (the panel moves `#llm-owner-box`) or in the settings in administrator mode. Never in the page, the worker, `prov/1` or exports (`tests/test_llm_chiavi.py`); in the app it is the `mzlab-demo` entry of `llm-chiavi.json`, read only by Rust.
- Proxy errors: Rust's `http_error` keeps the keys `err.llm.proxy.{closed,off,budget,body,origin}` and `err.llm.limit.spend` of the body with only the parameters `limit` and `field`. In the demo panel `off`, `budget`, `origin`, `limit.spend` and `network` give "Assistant not available" once (`llm.unavailable`): no more sending or chips, the facts card and the charts without a model remain, no retry. With the demo the panel turns on the subagents (limits `demo_*`) and a refusal to a subagent closes the turn (`FINAL`, `llm-agente.js`).
- Spend: the transport passes `x-mzlab-spend` (`<spent>/<cap>` in micro-dollars) and `x-mzlab-soft` of a 2xx response; Rust reads them (`demo::spend_json`, `.wasm` `demo_spend`; in the app `llm/poll` gives `spend`) and the panel shows `#flx-llm-spend` (`llm.spend`, $ to two decimals) and a single `llm.spend.soft` warning.
- Proof: `e2e_llm_consenso` routes `https://localhost:<port>` to the real proxy on `adapters/memoria.js` (`tests_e2e/finto_proxy.mjs`). `index.html` and `tauri.conf.json` do not change.

## Transport in the app (`crates/mzlab-desktop/src/llm.rs`)
- Routes `llm/providers` (providers + `has_key` per provider, never the key), `llm/request` (the request without key), `llm/send` (opens the request with `ureq` on a thread, returns `{id}`), `llm/poll` (`{events, done}`: normalized events, one JSON line each), `llm/abort`, `llm/key/set`, `llm/key/forget`; routing is in `rpc.rs`.
- The key is in `llm-chiavi.json` in the data folder (0600 on Unix), read only by Rust; it does not appear in plans, `prov/1`, exports or diagnostics (`tests/test_llm_chiavi.py`).

## Agent, permissions, context and evaluation
- `agent::step(&mut State, Input) -> Vec<Output>` is the loop as a pure state machine (no I/O, no clock): `Input` = `User`, `Event`, `ToolResult`, `Confirm`, `Stop`, `SubResult{role, body}`; `Output` = `Send(Request)`, `Sub{role, request}`, `CallTool`, `AskConfirm`, `Show`, `Log(line)`, `Done`.
- `State::new` checks plans by itself; `State::without_check` (the `.wasm`) does not: the page checks them and `plan::problems` is not linked (-27 KB in the `.wasm` `llm`). The transport (page, app) executes the outputs; `State::outcome()` = `end|length|refusal|stopped|error:<key>`. The system text is `data/sistema-1.md` (`agent::SYSTEM`).
- `policy::decide(&Tool, &args, Level, &Counters, Profile) -> Allow|Confirm|Deny{key}`: profile `corso` → `err.llm.profile.course`; L0 denies `edit|run|ui` (`err.llm.level.denied`), L1 asks confirmation for `edit|run|ui`, L2 allows but from the 4th `run` asks confirmation; `read` and `propose` always allowed; arguments outside `input_schema` (`schema::validate`) → `err.llm.tool.args`; L2 at 20 calls (`MAX_CALLS`) → `err.llm.limit.calls` and the turn ends.
- `flow_check` and `flow_propose_plan` are answered by the agent with `plan::problems` (`flow::check` on the real registry): a plan with problems goes back to the model as an error, at most 3 times (`MAX_PLAN_TRIES`, then `err.llm.plan.tries`); a plan without problems reaches the page with `CallTool`. A text read from the data (file name, cell) never changes a decision: the policy looks only at tool, arguments and counters.
- `compact::compact` (re-exported by `agent`) triggers at 70% of `context_tokens` (estimate `ceil(byte/3)`): the oldest results become `{"summarized":true,"tool","ok"}`, then the oldest `Context`; the last `flow_get_plan` and the last context stay whole.
- `context::build(&sources, budget) -> Result<String>` makes the `context/1` (schema `docs/schemi/context-1.json`): only profile "ricerca"; TIC ≤200 points (maximum per interval), numbers to 4 significant digits, `alias` f1.. with `hide_names`, `table_summary` (rows, per column filled/min/max, first 50 rows by `area`); `truncated` lists the sections removed (features, msn, run, annot, then tic), `err.llm.context.budget` if it is not enough.
- `inspect::build(&sources, budget) -> Result<String>` makes the `inspection/1` (schema `docs/schemi/inspection-1.json`, `inspect.rs` + `inspect_qc.rs`): per file type, polarity, resolution class (high/unit/unknown with the basis), levels, acquisition (full_scan, sim, dda, dia, aif, product_ion, mrm, infusion…), ranges, cycle, isolation windows, gradient, role (proposed or confirmed) and order
- `inspection/1`, series: `series` has the `qc/1` (RT and area drift of the QCs, proposal `features.align.rt_gap`/`rt_warp` or `missing`) and the blank signals absent in the samples.
- `params_rules::propose(&inspection, &answers, &flow::steps()) -> Result<String>` makes the `param-proposal/1` (schema `docs/schemi/param-proposal-1.json`, `params_rules.rs` + `_det.rs` + `_tab.rs`): one function per `R-*` rule (`03-parametri.md` §5; `TARGETS` = rule → parameters), each proposal with signals, confidence, `range_ok` from the `step/1` limits and evidence; absent signal = `missing` with the question, never an invented value. The axis at unit resolution is `Da`. Proofs: `llm_params_tests.rs` (mzlab-cli, real registry, cases G15-G22). It is not exported by the `.wasm` `llm`.
- `.wasm` `llm`: `inspect_build` and `params_propose` (the page's `step/1` registry), worker operations `inspect.build`/`params.propose`, `AgentRun.inspectText`/`paramsProposeText`, `factsRun()` (worker without conversation or consent). Sources of the `inspection/1`: engine answers (`Item.info()`, route `/api/scan_stats` = `mzlab_core::scanstats`, site and app, `method/1`, `campioni/2`), from a whitelist of fields: never paths, operator, serial, computer name. Proof: `cargo test -p mzlab-llm --test inspection`, `-p mzlab-llm-wasm` (`tests_facts`), `tests/test_llm_inspection.py`.
- `eval`: `llm-eval/1` cases (`tests/data/llm/eval/E*.json`: `request`, `level`, `context`, `tool_results`, `expect`) against the recordings `tests/data/llm/<id>.jsonl`; `mzlab-cli llm eval DIR --replay DIR` exits 1 if a check fails, `--provider/--key-file` gives `err.llm.network` (no transport in this build). `mzlab-cli llm context RUNDIR [--budget N] [--hide-names]` prints the context of a run folder.
- `flow::prov_json_llm(agent, plan_sha256, run, Option<&LlmRef>)` adds to `prov/1` the optional block `llm{log_sha256,turn,provider,model,level}` (`$defs/prov1`); with `None` the bytes are those of `prov_json`.

## Panel in the Flow (D5)
- `crates/mzlab-llm-wasm/src/agent.rs`: class `Agent` (the `agent::State` machine + an internal `Replay` for tests) that speaks in JSON lines `{"o":"send|call|ask|show|log|done"}`; the plan check is outside the machine (`external_plan_check`: the page has the step registry, `Agent::result` counts the rejected plans, 3 at most). `context_build(sources, budget)` exposes `context::build`.
- `llm-worker.js`: operations `agent.new`, `agent.in`, `context`.
- `mzlab/web/llm/llm-agente.js` (`AgentRun`) executes what the machine asks (show, call a tool, ask confirmation, send the request with `MZLAB_LLM.client` or `DesktopClient`); no decision. `window.MZLAB_LLM_AGENT.replay(text, strict)` sets a recording for the next conversation (test, no network).
- `flow/lazy/flow-llm.js` (panel to the right of the canvas: level, estimated cost, "What will be sent", "Apply"/"Discard" cards with the plan difference and the problems with `F.message`, "Allow"/"Deny" cards (`preflight` estimate), "by assistant" log with "Undo", "Stop", Esc closes and focus returns to the button, width by keyboard with Alt+←/→) and `flow/lazy/flow-llm-readers.js` (readers card: `llm-subagents.md`) and `flow/lazy/flow-llm-tools.js` (tools: same functions as the clicks, every change is an `S.undo` entry).
- `flow-shell.js` downloads `flow-llm-errors.js` and `flow-llm-facts.js` with profile "ricerca" (even with the assistant off: no request outside the site) and the rest of the panel only with the assistant on and consent given. `data_summary` (the inspection), `data_inspect` (by alias) and `params_propose` (per step) answer with the page's facts; `code_export` answers `err.llm.tool.unavailable`; `chart_make` is active (section "Charts").
- Facts without a model (`flow-llm-facts.js`): collects from the engine routes (`api/session`, `api/scan_stats`, `api/mrm`, `api/metodo`, `api/campioni/proponi`; the same on the site and in the app) the sources of the inspection in the order of `mzlab-cli llm inspect`, asks Rust for inspection and proposals (cache per open files and `hideNames`) and shows under the canvas the "Files" card (type, polarity, resolution class with basis, acquisition, isolation windows, gradient, proposed role) and the proposals with "Apply" (the value on every instance of the step: one Undo entry) and "Discard".
- `F.llmFacts.readerInput(S, role)` gives `{"inspection/1"}` to `metadati` and `cromatografia`, `{"param-proposal/1"}` to `parameters`, `{"tabcheck/1"}` to `interprete` only if the page defines `F.tabcheckSource`. Proof: `tests_e2e/e2e_llm_fatti.py` (same bytes as `tests/data/llm/fatti/`, Undo, accepted reader, axe, targets).
- At level L2 the `l2max` cap of changes per turn is applied by the page.
- Every run launched by the assistant carries `llm` in `prov/1`: in the app `flow/run` accepts the `llm` field (`flow::prov_with_llm`), on the site `run` of the web executor returns `llm` in its record (`S.llmRef`).
- Proof: `tests_e2e/e2e_llm.py` (recordings from `tests/data/llm/`, no network).

## Charts (`grafico/1`, no sandbox)
- Schema `docs/schemi/grafico-1.json`: the model names a view (`data.ref`: `tic:f1..`, `tic:*`, `features:area`, `features:mzrt`, `qc:cv`, `drift:rt`, `blank:ratio`, `peaks:width`, `bpc:*`) and the fields; never the data or the style. Marks `line|point|bar|stick|box|hist|heat`; `color` ≤ 8 nominal values, `facet` ≤ 12, `detail` ≤ 50; `{"error":"no_view","why"}` is an answer, not an error.
- Rust (`crates/mzlab-llm`): `chart_views.rs` builds the views from the sources `{files:[{name,tic,bpc,widths}], features_csv, qc}`, `chart.rs` validates (`err.llm.chart.*`, every error carries the existing views) and `chart_data.rs` fills `data.rows` (≤ 5000, reduction by interval maximum per series, stable bytes); `presets()` gives the five charts without a model.
