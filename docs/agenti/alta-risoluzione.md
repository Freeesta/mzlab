# HR world (high resolution) and Bench
The core is in CLAUDE.md; the shared Data view is in `dati.md`.

- **Bench** (`banco.js`, `BANCO`; in the LR world `BANCO.on()` is false and none of this exists). Each cell has a **scan filter** (`/api/filters?k=`, key `scan_key`, e.g. "FTMS + ms2 @hcd") that travels with every request (`filt=`; in caches it sits in the precursor slot: `prk` / `prSplit`); `p.filt`/`p.flv` are saved with the session; an MS2/MSn filter clears the precursor, one from another experiment moves the cell (`p.tab`). **Pin** `p.pin`.
- The spectrum panel has the **"+ scan"** button (`scanPicker`/`openScan` in `banco.js`, in place of the type menu; MSn infusion keeps the menu): it lists all scans of the file in time order (`/api/scanlist` for each level, filter by type inside the box) and opens a TIC with the scan below it at the top, at the bottom, above or below the panel (`e2e_scansione`).
  **Stacked charts** (`p.ranges`, up to 8): TIC, BPC or XIC in ppm, **NL** (`p._a.nl`), `p.norm100`. DDA trio: filter on chromatogram and MS1, not on MS2.
- **Cell bar** (`#hrbar`, `BANCO.bar`): a single row together with `#tools` (file arrows, undo/redo, `#hrbar`, Method); scans are stepped with left/right arrows; it acts on the **active cell** (`E.active`): Cell (add), Type, MSn tree (if the file has MS2+: `hasMsn`). If it does not fit: first the words disappear (`#tools.nolab`), then the last buttons move into "⋯" (`#hr-more`, `fitRow`) keeping their name.
- **Spectrum panel header** (`.pnl.spec .hd`, `app.css`): the controls do not shrink (`flex-shrink:0`, `nowrap`) so `fitHd` (`pannelli.js`) moves into "⋯" whatever does not fit instead of leaving it overlapped; the file menu is at least 16ch wide. The active panel (`.pnl.act`) is marked by a bar on the left (`inset` 3 px, the coupling colour if coupled), not by a frame. Test `e2e_spettro_header`.
- **Bar rule**: an action already in a cell header (pin, % and 0-100, delete ×, zoom, integration, download and copy in the `dl` menu) is NOT in the top bar, which holds only global actions or actions on several cells; a single undo/redo pair (`#np-undo`, `#np-redo`); ‹ › only mean "previous/next" (file, scan), never ◀ ▶. Test: `e2e_banco_barra`.
- The cells of all experiments sit together: `tabPanels()` with no argument = all, each cell draws with the files of ITS tab (`shownFor(p)`, not `shown()`). Non-modal notices (`nearMsg`), never `info()`.
- **HR tools in the bar** (`#stbar`, group after the separator; `#hrinfo` in the side panel, `infoBar`/`renderInfo`, tab in `qqq.banco.info`): six tools on the active cell, named in words, two menus and a button. Scan ▾: scan header (`/api/scaninfo`), scan list (`/api/scanlist`), file and instrument (`/api/fileinfo`: only what the mzML says). Formulas ▾: elemental composition and isotope simulation (existing functions). Libraries: identification (`LIB.searchFrom`, `LIB.identifyAll`).
  There is no peak detection, composite spectrum or MSn tree (the MSn tree opens from the chromatogram menu, `COMP.tree`). The last item chosen in each menu stays on the button (`last` in `qqq.barra.hr`). The bodies are in `BODY` (`banco.js`); mounting and the side panel are in `barra.js`.
- **Elemental composition** (`elementare.js`, `ELEM`; extended form and call in `composizione.js`, `COMP`; `/api/composition` → `comproute.rs`/`composition.rs` in the Rust engine, reference `chem/composition.py`, `chem/isoscore.py`): compact side-panel panel ("Formulas ▾ → Elemental composition", body `tCmp` in `banco.js` → `ELEMP.panel` of `elementare-pannello.js`), Xcalibur style:
  Two-column grid (Mass (m/z), Max results: default 5, cap 10, minimum 1), "Results" (5 visible rows, scrolls; Idx/Formula/RDB/Δ/Score if there is a spectrum with peaks around the m/z; Δ in ppm or mDa according to the Tolerance unit), "Limits" (charge/ion, nitrogen rule, tolerance ppm|mDa, RDB min–max).
  "Elements in use": "Element set" with Load/Save as…, isotope table, Min, Max, DB Eq., mass with ×, Add row; the text `C:0-13,H:0-25,…` in `mzlab.comp.els` is the saved value, the table edits it. Then Apply and ⤢. Ions follow the polarity of the file. The score text is in `#cx-desc` (`aria-describedby`), never as a paragraph.
  Score (`r.score.total`, 0–1, higher is better): weighted mean (weights mass 1, isotopes 2, fragments 1; a missing term is excluded, `isoscore::combined`) of the Gaussian mass term exp(−½(Δ ppm/σ)²) with σ = 3 ppm, of the agreement of the isotope profile with the observed peaks and of the share of MS2 explained. Order: Score descending, without it |Δ| ascending; `title` on the Score header.
  Defaults 12C 0-13, 1H 0-25, 14N 0-4, 16O 0-3, 32S 0-1, tolerance 5 ppm, 5 results: computes at once and at every change (typing after 120 ms; Enter, leaving the field and the menu immediately; one request at a time). Computation in the `.wasm` 2-60 ms; ± mode tested in `crates/mzlab-core/tests/composition_ions.rs`.
  A click on a cell copies only its value as plain text (formula, RDB, Δ as shown, Score; on Idx, or Ctrl+C/Enter on the row: the formula); the row stays selected and the copy is announced (`#cx-live`). "Apply" writes the chosen formula into `p.fm` and the chart draws it in italics between the m/z and the peak bar within the tolerance (candidate; right-click "Remove written formulas"). Right-click on an HR peak → "Generate formula" (`ELEM.generate`): opens the panel with that m/z.
  ⤢ (`COMP.open`, central popup, FreeStyle style): Prediction settings (ion, tolerance, results, nitrogen, RDB, centroid algorithm "as in the file | local maxima", normalisation `norm` fit|mono|max|sum, "Use representative elements"), elements in use with a custom periodic table (the elements known to the computation), Seven Golden Rules, Isotope profile comparison (intensity threshold 0.10 % = `imin`/`inoise`, intensity tolerance 30 % = `sint`/`isotol`, R, σ ppm, weights),
  Fragment comparison (minimum fit = filter on the list, S/N threshold = × median, mass tolerance = `fppm`). Candidates with evidence, never identifications.
- **Full isotope score and fragment constraint** (`chem/isoscore.py`, called by `compose` when `obs` and/or `frags` arrive; computed in Rust (`isoscore.rs`, called from `compose`) with the same numbers as Python): the theoretical fine structure (`fine_pattern`, each isotopologue with its exact mass, up to M+6) is merged at the resolution (`merge_res`, adjustable R200) and compared with ALL the isotope peaks observed in the spectrum (window −0.5/+6.5 from m/z; `obsText` in `composizione.js`):
  for each theoretical peak a Gaussian mass term (expected error `sppm`, default 3 ppm) times a log-normal intensity term (expected error `sint`, 10 %); expected but absent peaks, and observed but unexpected peaks, weigh against the formula; the observed intensity is scaled by least squares (the monoisotopic peak is not privileged). Thresholds visible in the detail table (click on a row): theoretical peaks below 1 % not required; each peak weighs the same (WEIGHT_POW = 0), observed peaks below 1 % ignored.
  Fragment constraint (`fragment_constraint`, idea from BUDDY/msbuddy): share of the precursor MS2 intensity explained by subformulas (`subformulas`, ±max(tolerance, 5 ppm)) and number of peaks explained; the MS2 is pasted in the window or taken with "From the MS2 spectrum on screen". Candidates are ordered (top 100 by mass error) with the weighted mean of mass, isotopes and fragments (adjustable weights, a missing term does not count); without a spectrum or MS2 the order is the mass error and there is no score.
  Columns: Halogens (Cl/Br evident), Score, Terms, MS2 explained; no learned model, no verdict. It does not exist in the LR world. Measurement (`python3 tools/test_isotopes.py`, synthetic spectra with noise, fixed seed; first series / series with halogens): 100 formulas per series (CHNOSP; with Cl and Br), 8 ppm, R200 = 70000, mass error 3 ppm and intensity 8 % in the synthetic spectrum, weak peaks lost and noise peaks; the true formula is first: only M+1/M+2 (M+1/M+2 check, then mass error) 63 % / 28 %; full isotope score 83 % / 74 %;
  with the MS2 (6 true subformulas and 5 noise peaks) 90 % / 81 % (in the top 3: 100 % / 92 %). Defaults: weights mass 1, isotopes 2, fragments 1; expected errors 3 ppm and 10 %; the defaults are tuned on these same synthetic spectra, so the rate on real data may be lower.
- **Display options** (`visualizza.js`, `DISP`): right-click on a chromatogram/XIC or on an HR spectrum → "Display options…" opens the `disp` side panel for the active chart (command `disp` of the Ctrl/⌘K palette, `bar: false`). **Extensible**: each list is per chart type (`spec`, `chrom`) and a package adds entries with `DISP.register(type, {id, label, kind: number|select|check|button, get, set, when?})`; the texts are `lang/` keys.
  Entries: spectrum = m/z decimals (`UIP.hrDec`, 3-5), threshold and maximum number of labels, profile/sticks (if there is a profile), axis in %; chromatogram = normalise to 100 %; XIC (HR only) = ion m/z, range unit (ppm or Da) and range (±), per trace (`traces[i].mz`, `ppm` or `wda`; `HR.xicArgs`/`xicEdges` read them). The header of an XIC in HR says only `XIC • m/z <value>` (`.xlab`); in LR the "m/z from … to …" fields remain. An icon button in the header (HR) opens the chart options.
  "Dots only" (`p.dots`, entry of the `visualizza.js` registry and checkbox in the "Parameters" popover in LR): each spectrum point is a dot, with no line or sticks, so isolated peaks stay isolated (`picchi.js`; `e2e_spettro_punti`).
  In HR the decimals field of the bar and the ▾ button of the spectrum are not there (in LR the `spettro.js` popover remains).
- **Isotope simulation** ("Formulas ▾ → Isotope simulation", `tIso` in `banco.js`, computation in `hr.js`): formula, one or more adducts each with its concentration (%, `p.iso.adds`), charge distribution (most abundant charge and half width, `p.iso.cd`: protonated/deprotonated charge states weighted 2^(−4((z−z0)/hw)²), `HR.isoSeries`), output Bars | Profile (Gaussian, samples per peak) | Centroids, resolution (resolving power, Da, ppm; FWHM, 10 %, 5 %).
  The combined profile of all ions is `HR.isoPat` (asynchronous: `isoFine` asks the engine for the fine structure, `api/isotope_fine`; then `mergeBy`); each peak carries the ion label when there is more than one.
- **Isotopes with the resolution**: `HR.mergeBy` in `hr.js` merges fine-structure peaks closer than the FWHM = m/R(m), R(m) = R200·√(200/m); entry "Isotope profile resolution…" (`p.iso.R`: number, "auto", 0 = fine structure).
- **MSn infusion** (`infusione.js`, `infusione-albero.js`, `infusione-menu.js`, `INF`; type `infusion`, one element): the nodes of `/api/msn_albero` are the `msn:<id>` filters of the cells (`INF.qs` adds `mtol`, `mce`, `modo=somma` to every request that names a node). "Precursor tree" tab (`alb`, Bench drawer): rows MS1 > MS2 > MSn, level, tolerance, energies separate or merged, Mean | Sum; click or Enter put the node on the active cell, arrows to move, right-click on the row or on a peak ("Fragment this ion", "Back to the precursor").
  - Starts on the richest node; the options travel with the session (`NB.ui.msn`).
- **MSn tree** (file with ≥ 2 stages): chromatogram menu → `COMP.tree(k)` → `/api/msntree` → `chem/msntree.py`: one node per fragmentation path; exact precursor = most intense peak of the parent node within ±0.5 Da (the one in the file is nominal); formula = best subformula candidate of the parent's. Max 400 paths; DDA: `msn-manuale.md`.
- **Libraries** (`libreria.js`, `libreria-worker.js`; format, parser, indexes and scores in `docs/agenti/librerie.md`): "Identity" and "Analogues" tabs. Confidence levels (HR only, a single module: `livelli.js` + versioned data file `livelli-1.js`, format "livelli/1", with the profiles "mzlab" (default) and "attributio" (hidden: Attributio's rules, thresholds and texts)): used by "Identify all MS2", by the Identity tab and by mzFinder (same words, same colours: `.lvb` + `.lv-N` in `app.css`, Okabe-Ito).
  Always "candidate, level LN, evidence", never "is X" (Schymanski scale with label "L": `LIVELLI.tag`; `livelli.md`). Each result has "proposed level" and "decided level" (empty until the chemist decides); the program never assigns 2b or 1: 2b is written only in "decided", from 2a, 3a, 3b or 4 (refused on 5 and 0 with a message), 1 only with a standard marked by the user.
  Cascade of the "mzlab" profile: 2a (experimental library: mzCloud, MassBank, MoNA) = |Δ precursor| ≤ 5 ppm, entropy ≥ 0.75, ≥ 6 shared peaks (≥ 3 if the library entry has fewer than 6), ≥ 2 agreeing scans, advantage ≥ 0.05 over the first candidate of another structure (first InChIKey block); otherwise 3a (entropy ≥ 0.60, a single scan, indistinguishable candidates) or 3b (only an analogue with modified cosine ≥ 0.60), 4 with a unique formula, 5 without evidence. The evidence is one line per gate ("entropy 0.62 vs 0.75 ✗") plus a deciding sentence (`lv.*` in `lang/`).
  Thresholds in `qqq.lib.soglie` and in the `.mzflow` (`LIVELLI.exportState/importState`, also reads the previous format `{ent, shared, ppm, ent2}`); candidates carry `ik`, `nlib` and, in the rows of "Identify all", `alt` (best candidate of another structure, from the worker/`best` of `mzlab-lib-wasm`). Analogues: modified cosine; Δm explained with the transformation table or with the simplest formula within 3 mDa.
  "Identify all MS2" (`LIB.identifyAll`, "What is it?" window, resizable, size in `mzlab.libwhat.size`, rows in blocks of 120): groups by precursor (10 ppm) and RT (0.2 min); contaminants excluded (`LISTE.compat(...).hid`) left out, counted ("Show"); a row opens the best scan; more scans, higher level (a single one = 3).
  Columns Structure, Adduct, Library, InChIKey, Shared peaks, Δ ppm; thumbnails (`lazyThumbs`) for the rows in view; click = enlarged with the SMILES.
  **Engine**: where WebAssembly starts, the worker uses `static/wasm-lib/` (`crates/mzlab-lib-wasm`, a separate `.wasm` under 600 KB, loaded with `import()` only at the first request for a library):
  the import (MSP, MGF, MassBank `.txt`, MoNA/GNPS/mzMine JSON, recognised from the content) writes `<id>.mzlib` in OPFS (working file `<id>.tmp`, then deleted; without synchronous OPFS, memory and IndexedDB) with limited memory, the search reads in slices with `FileReaderSync` (no blocking of the file) and an LRU cache (64 MB in total, 32 MB on iPad/phone, divided among the open libraries: `total_cache_budget` in `read.rs`).
  Each result also carries the weighted cosine next to entropy, shared peaks and Δppm, plus reverse, forward, explained fraction, common neutral losses, licence, authors, accession and SMILES (the window does not show them).
  Libraries in the old `MZL1` format (`.idx`, `.peaks`, `.meta.json`) are converted to `.mzlib` once, at the first listing, without re-importing, and the old files are deleted; where WebAssembly does not start (old browser, development server without `.wasm`) the JavaScript path remains, which also reads the old archives (`?libjs=1` forces it).
  Supervisor in `libreria-corpo.js`: a dead worker (trap, memory) is replaced and the request is repeated once (`lib.err.restarted`); a second death within 1 minute sends the page to the JavaScript path (`lib.err.fallback`; `.mzlib` libraries ask to reload, `lib.err.needWasm`).
  The libraries live in ONE folder ("Libraries" window, "Library folder" box; format, states and paths in `docs/agenti/librerie.md`, code in `libreria-cartella.js`): in the desktop app a native folder, on Chrome/Edge a folder chosen once with `showDirectoryPicker` (permission requested at the first click of the visit), elsewhere the OPFS `librerie/` where files are imported only once (`navigator.storage.persist()` requested, warning if refused).
  The window lists name, spectra, size, polarity and state (Ready, To index, Update available, Damaged) with "Index" and "Remove" (for a source it removes only the index: the user's file is not touched). The MassBank library lives in the data repository; private tests `tests/test_hr_identificazione.py` (JavaScript path) and `tests/test_librerie_rust.py` (Rust engine); browser tests `e2e_libreria` (JavaScript, development server) and `e2e_libreria_wasm` (built site).
- **"What is it?"** (HR only; entry `ctx.libWhat` of the menu of an HR MS2 spectrum, also in the DDA trio, `LIB.whatIs`; also from the "Identity" buttons; in LR it stays "Search in libraries…", without levels: `e2e_ricerca_ms2`): large resizable window `#libwhat` (`libreria-finestra.js`, at first use): on the left the Candidates (Flash entropy) and Analogues (hybrid search) tabs, on the right the chosen entry; profile tolerances (precursor ppm, peaks 10 ppm, minimum 0.005 Da).
  Sortable candidates (same first InChIKey block = one expandable group); on the right 2D structure from the SMILES (`mol-svg.js`), mirror, "Details" (reverse, explained intensity, CE, licence, neutral losses, authors: texts with `EHt`). At the top the best candidate and the level (`LIVELLI.assess`, scans from `LIB.scansOf`; evidence and decision in "Details"); tolerances, thresholds and libraries in Options; Copy and Excel in the download.
  Mirror (`LIB.mirror`): solid lines between peaks paired at the same m/z, dashed for those shifted by the precursor difference (type 1), dotted for those with the same neutral loss at another m/z; the drawn lines are in `canvas.dataset.lines` / `.nl`, the mouse hover (m/z, Δ) reads `canvas._mg` (the pairs coincide with those of `tests/golden/librerie/parita_attributio_ms2.json`).
  Cosine on visible peaks (`LIB.cosVis`): if the mzML gives the lower limit of the MS2 window (`/api/method` → `scan_params.ms2.window_lo`), the reference peaks below that limit are removed and the cosine is an extra line of the evidence, without changing the level. The JavaScript path also carries reverse, explained intensity, accession, authors and licence.
- **Panel view**: each HR spectrum carries in its header the title "MS" with the level as a superscript (`SPECBAR.title`, called by `ctl` and `BANCO.header`). In the DDA trio (`dda.js`) the Full Scan (MS1) takes the full width and the MS2 panel sits below it, full width; "Add an MS2 panel alongside" (right-click menu on the Full Scan, `DDA.addMs2`) places further MS2 panels (`p.extra`) on the same row, which share the width, and the next choice (▼, click on a bar, triangle) goes into the active MS2 panel of that Full Scan;
  the MS2 is chosen from a DDA event (▼, triangle, list) or from a followed ion (XIC).
- **File list (HR)**: no labels in the bar rows ("HR", "DDA", "centroids", polarity): profile/centroids, instrument and resolution are in the info bar (`#hrinfo`) and in the Method.
- **XIC from formula** (HR only; entry "Cell" → "XIC from formula (subformulas)…", `subXic` in `banco.js`): the formula of an ION → `/api/subxic` → `chem/subformulas.py` (all subformulas, m/z = mass ∓ electrons, adjustable lower limit, adjustable ±ppm; at most 300 000 combinations). The server sums the peaks of all windows (a peak in two windows counts once) and measures each subformula with signal: theoretical m/z, weighted mean Δppm, apex intensity and RT, correlation r with the XIC of the whole formula.
  No "fragment" label, no proposal; the sum enters the cell as a stacked chart (`kind: "sub"`). In LR the endpoint refuses (`err.subxic.lr`) and the entry does not exist (`tests/test_subformulas.py`, `e2e_hr_vista`).
- **Pitfalls**: the HR peak table is float32 (for the exact values of a scan, read from the file). In Thermo files the "selected ion m/z" may not be the isolated peak: use the centre of the isolation window (`tgt` of `/api/dda`).
- **Reproducibility and exports** (`workflow.js`): format `.mzflow` / `mzflow/1` (SHA-256 of the files, version, commit, parameters, operation history) to export and reopen the session; MGF and MSP export from an MS2 spectrum and from "Identify all MS2" (in LR only spectra, never annotations or names, Principle 1).
  **Open data** (entries: `fair-azioni.js`; `fair.js` lazy, `window.FAIR`; tests `tests/test_fair.py`, `e2e_fair`): from the download menu of an HR MS2 spectrum (`FAIR.available`, never in LR) two files with no network:
  "MassBank record" (MassBank 2.x text format; instrument, instrument type from `fileinfo`, CE and activation, precursor and peaks from the scan; name, SMILES and InChIKey are written by the user, the SMILES also "From Drawing" with `TPDraw.smiles()`; formula and exact mass from OpenChemLib; contributor, identifier, authors and default CC BY licence, remembered in `qqq.fair`; `FAIR.check` lists the errors that block the download and the warnings, e.g. formula+adduct against precursor beyond 10 ppm; the SPLASH is not written) and "File for SIRIUS 6"
  (`.ms`: `>compound`, `>parentmass`, `>ionization`, optional formula, `>ms1` from the parent scan if the file indicates it, `>collision`/`>ms2`). The pure functions (`record`, `check`, `siriusMs`) are tested with node against hand-written examples in `tests/data/fair/` and an independent validator of the MassBank rules.
- **QA/QC in HR** (panel `qaqc`, `dati-strumenti.md`): known ions and internal standards with Δppm per file and mass accuracy (mean and maximum absolute error); sample/blank ratio of all mzFinder features with a 3:1 or 10:1 threshold (`/api/stat/reference` with the blanks as reference and mean of the areas, see `alta-risoluzione-statistica.md`; never verdicts). The study report (`dati-strumenti.md`) has in HR the section of the confidence levels of the annotated candidates.
- **Compact side-panel panels** (HR): the panel title is only that of the side panel (`#hri-ttl` is hidden there); `.row` rows of `#hri-body` with labels that wrap; "Reference lists" in three `.lb-row` rows (m/z and ± ppm · search · "Nominal | High res." and "ESI+ | ESI− | All") with a table of 22 px rows. `e2e_hr_pannelli` checks that no text is cut off at 1280, 1440 and 1680 px.
- **Statistics in HR** (feature table, blank subtraction, difference from the reference, exploratory PCA): `docs/agenti/alta-risoluzione-statistica.md`.
- **Map crosshair in HR** (`mappa.js`, `mirino.js`; `dati-mappa.md`): the XIC under the map has the ppm window of the file profile (`HR.tolDa`), the side spectrum is the scan with its centroids (`/api/spectra`, like `/api/spectrum` on a window with a single scan); the preview takes row and column of the map matrix (cells of equal ppm) and has no m/z labels. - **Map in HR**: the "How it is extracted" box has the m/z window in ppm; with an mzFinder result on the page the map can show its features as markers (switch off by default) and "How it was found" for that choice, read-only (`dati-mappa.md`, `mzfinder.md`).

- **Gradient, pressure and PDA in HR**: the options of the overlaid gradient (delay in min), of the PDA → mass delay and of "Align PDA and mass" are in "Display options" of the chromatograms (`visualizza.js`, entries `gdelay`, `pdadelay`, `pdaalign`); the data, the Method window and the overlays are in `dati-3200.md` (same in LR and HR; the program does not estimate the dead volume and gives no gradient other than that of the `.dam`, of the `.raw` or entered by the student).
- **"File and instrument" tab** (`banco-file.js`, loaded by `banco.js`, global `BFIL`): `fileHtml(j)` puts all the sections on a grid (same label column, rows without a value omitted, names capitalised, placeholder software "custom unreleased software tool" with a hint); "Scans by type" is a list (name that wraps by words, count on the right, small RT below). Test: `e2e_banco_file.py`.
