# Native reading (site): `.raw`, `.wiff` + `.wiff.scan`, `.D` folders without mzML

Vendor files are read as they are: no intermediate mzML. "Download .mzML" writes it only on request. The engine lives in `crates/mzlab-wasm/src/natives.rs` (on top of `mzlab-core`: `readers::apri`, `upload::prepare_lettore`, `mzidx::build_lettore`), the JS part in `rust-nativo.js` (worker) and `rust-nativo-pagina.js` (bridge); `nativo.js` is the page part without DOM (test: `tests/test_nativo.py`).

- **Sample = file of the list**: each sample (a `.raw`, an injection of a `.wiff`, a `.D` folder) is a `File` named `x.mzML` that carries `mzlabNat = {key, members, c, id, centroid, size}` (`NATIVO.sample`). `upload()` treats it as an mzML; `lr.js` reads `blob.mzlabNat`, copies the members and writes the placeholder.
- **OPFS**: members live in `files/` with the flat name `nat~<key>~<path with ~>` (a `.wiff` shared among its samples is written once, `writing`); the file `files/x.mzML` is a small JSON (`{mzlab:"mzlab/nat1", ds, c, id, centroid, members, size}`, `readStub`). The index `idx/x.mzML.mzidx` is v2 (the rows say where each scan sits in the members). `lr_boot`/`lr_entry` give the true size and `nat:true`; `lr_remove` removes the members no placeholder uses any more (`sweep`).
- **Interrupted copy**: `put` holds the Web Lock `mzlab-nat:<key>` in shared mode while it copies the members and writes the placeholder. At startup `lr_boot` calls `nativo.orphans()`: the `nat~` members that no placeholder uses (tab closed during the copy) are removed, checking again under the exclusive `ifAvailable` lock, if no other tab holds that lock; the warning `load.natInterrupted` names the file to reload. Without Web Locks nothing is removed (`tests/carica_worker_node.mjs`, `e2e_nativi_orfani`).
- **Opening**: `lrOpen`/`idxopen` call `nativo.attach(engine, name, slot)`, which links the slot to the reader (`Engine.native_attach`, idempotent); the blob of the slot is ignored by the engine.
- **Progress in phases** (`nativo-fasi.js`, weights `copy .2, sha .1, open .1, scans .35, chrom .25`; with the fingerprints in the placeholder the `sha` phase disappears and its weight goes to `scans`): copy, SHA-256, opening (phase 4 of `build_mzidx_native`: the reader reads the scan table of ALL the samples), scan index, chromatograms. At most one message every 200 ms `{frac, phase, done, total}`.
- **Measure inside the phase** (`buildNative`, `rust-nativo.js`): `build_mzidx_native` receives `step(done, total)` from the reader wrapped in `Counting` (`natives.rs`), which counts the decoded scans of the sample (about every 1 %), because the bytes of a `.wiff.scan` belong to all the samples. `scans` is measured with the scans, `chrom` with the bytes re-read from the support file (`spill`) or with the re-read scans, the other phases with the bytes read.
- **Loading rows** (`CONVROWS`, `conversione.js`): each native sample has a row from the start (`upload0`) with phase, %, "scans n of N", elapsed time and, after 5 s without news (`CONV_QUIET`, not when queued), "no news for N s"; `NATIVO.rowState` chooses the key (`conv.row.nread|nopen|nscan|nchrom`), `wait` = queued for a free builder (`idxpool.build`). Never remaining time.
- **Outcome** (`CONVROWS.finish`, `summary`): below the table stay "Loaded ✓ (n scans, t s)", the error with "Details" and "Copy diagnosis" (also for a pair that does not open) or "Cancelled", until "Close" or the next load. **Cancel** (`cancelLoads` in `shell.js`, in the row header and in the veil of "Load data"): stops the files not started, sends `lr_cancel` to the worker (copy and index stop, `err.load.cancelled`, `lr.js` removes the placeholder with `lr_remove`); the files already loaded stay.
- **Summary** (`CONVROWS.totals`, `[data-cvtot]`): when loading ends, above the list of outcomes, "N files: n full scan, n MS2, …, n failed, n cancelled, n from cache, n with missing scans · m:ss" (only the non-zero counts; type = `kind` of the file entry, "mixed" if it has several parts; time from the first start to the last end). A sample with `missing` > 0 (`build_mzidx_native` → `lr_index` → `missing` map of `lr.js`; the file entry stays equal to the reference) adds to its row "n scans missing: the .wiff.scan ends early" (`data-cvmiss`).
- **Scans without event** (`.raw`): with `cause` `warn.raw.eventsRefused` (`causes` map of `lr.js`; `noteKey` gives the row key, `note` of `ConvRow`) the row says "n of N scans without their scan event: level and polarity unknown" (`conv.row.noEvent`) and the summary counts it among the partial reads (`conv.sum.missing`); never "the file ends early".
- **From cache** (`NATIVO.cached`; on the desktop `natsame` of `rpc_nat.rs`, below): a `.wiff` + `.wiff.scan` pair dropped again, whose samples are already in the list, asks the worker (`natsame`, `nativeSame`) which OPFS stubs have the same members (name, size, `mtime` = `lastModified`), the files in `files` and an `.mzidx` of the current format; if all the samples are, each row says "Loaded from cache ✓ (n scans)" and nothing is copied, re-read or added to the list (no duplicates); if one is missing, the pair follows the normal path.
- **From cache, `.raw`** (`shell.js` `rawToMzml`): a `.raw` given again goes through the same check (one sample per file, without reading it); if its sample is in the list with copy and index, the row says "Loaded from cache" and the file does not become a second sample (`X.raw.mzML`), nor a second copy or a second `.mzidx`, even after a page reload (`tests_e2e/e2e_raw_riaggiunto.py`; desktop: step "natsame" of `crates/mzlab-desktop/tests/e2e_shim.py`).
- **From cache, `.D`** (`agilent-d.js` `toMzml`): a `.D` folder given again with "Load a folder" goes through the same check (one sample per run, the members of the folder); if its sample is in the list with copy and index, the row says "Loaded from cache" and the run does not become a second sample (`uno (serie).mzML`), nor a second copy or a second `.mzidx`, even after a reload (`tests_e2e/e2e_agilent_riaggiunto.py`; desktop: step ".D" of `crates/mzlab-desktop/tests/e2e_shim.py`).
- **From cache, run read by the module** (`agilent-d.js`, `NATIVO.cachedModulo`): a run that the engine refuses and the readers module reads (also Bruker `.d`) leaves no stub in OPFS for `natsame`; its members (name, size, date) are compared with `CONV.sources` of the samples in the list, and if they match the row says "from cache" and no second sample is born. It holds within the same page: after a reload the members are gone and the run is reloaded (`e2e_agilent_riaggiunto.py`, engine refused with a `nativeSamples` that throws `err.file.agilent`).
- **Sample removed from the list** (`shell.js` `mergeFiles` → `CONV.forget`): its mzML, the source in `CONV.sources` and the mzML files written for download go away, so a file arriving later with the same name is not taken for that run by `cachedModulo` nor downloaded as it (`e2e_agilent_riaggiunto.py`, `test_conversione.py`).
- **One `probe` per pair**: `wiffToMzml` saves the answer of the sciex module in `mzlabNat.probed` and `moduloWants` reuses it for each sample (a probe per sample would re-read the headers of the whole `.wiff.scan`). Synthetic pair of true size: `tools/wiff_grande.py OUT [--samples] [--scans] [--points]`; test: `tests_e2e/e2e_wiff_carico.py` (also a `.wiff` with 48 samples). The index builder of a sample opens only that sample (`apri_solo`, `wiff.md`).
- **Large load**: `tests_e2e/e2e_wiff_240.py` (240 small pairs in ≈2.5 min: no error, list order, at most 3 builders, reopening, "from cache", Cancel); measures and space (≈200 MB of OPFS per profile sample) in `misure-formati.md`.
- **mzML on request**: `CONV.make(name)` (`conversione.js`) → `rb.nativeToMzml` → worker `nat2mzml` → `native_to_mzml` writes into `conv/` of OPFS (`rawSink`), then the file is downloaded. Arrays are in zlib-rs level 2 (`mzmlwrite::ZLIB_LEVEL`);
- **Compression of the mzML on request**: the "Compression" choice (`CONV.compression`: standard = zlib, smallest = zlib and MS-Numpress, uncompressed; in the "Advanced" block, with the size estimate before and the real size on the button after) passes `compression` to `nat2mzml` and `native_to_mzml`, which translate it with `compression_options` like `convert --compression` (linear m/z, slof intensity, with zlib if smaller). The core mzML reader refuses numpress; the "open" readers read it.
- **Parallel encoding** (native, not in the `.wasm`): `Opzioni::thread` (default cores − 1, at least 1) takes `Conversione::scrivi` to `MzmlWriter::spettri` (`mzmlwrite/pool.rs`): the calling thread reads and writes in order, `thread` threads (`std::thread::scope`) build the text of each spectrum (`mzmlwrite/encoding.rs`: zlib, numpress, base64), at most 4×`thread` blocks in flight.
  Blocks of ≤ 32 spectra or ≈ 100 000 points; the spectra return to the reader thread with the text, so that whoever allocated them frees them (`raw-mzml.md`, D8). The bytes are those of `spectrum_with` for any `thread` (zlib comes out of a fixed block); the first error in order (of the reader or the encoder) stops the writing and the file is not closed.
- `thread` 1 and the `.wasm` use the sequential loop. Measure: `cargo run --release -p mzlab-core --example convert_times FILE --thread N` (`raw-mzml.md`, "Parallel encoding").
- **mzFinder**: reads the `.mzidx` v2 of the sample and the SRM traces from `rb.nativeSrm` (`native_srm`); a profile sample has a separate centroid index, `<name>.cen.mzidx` (`lr_index_cen`, `rb.nativeCentroidIndex`; the one of the Data tab stays); the mzML is written only for a sample without an index (`mzfinder-ingresso.md`).
- **Desktop**: same page and same flow; `desktop-worker.js` sends `natsamples`, `lr_put` with `nat` and `nat2mzml` to the native engine, which opens the mapped members with the same readers (`rust-desktop.md`, "Native samples"); the members stay where they are on disk.
- **Background queue (desktop)**: after loading each native sample enters the conversion queue (`CONVQ` in `conversione.js`, `rb.convQueue`); the row shows "mzML ready ✓" or the error and "Save the mzML files…" puts everything in a folder (`rust-desktop.md`). On the site the conversion stays on request.
- The engine `.wasm` stays under 2 174 976 B (`pages.yml`). The samples of a `.wiff` and the `.D` folders are listed with `rb.nativeSamples(members)` (`native_samples`, on the desktop `natsamples`: the same `readers::samples_json`, `{format, samples:[{id,name,scans,why?,refused?}], unindexed?}`; `why` is `refused` for a sample the reader refuses, with its error in `refused` (`Reader::refused`), `inferred` or `empty`; tests `wiff_refused_listing.rs`, `natives_tests.rs`, `test_parziali_parita.py`); the member names of a `.D` folder are `x.D/AcqData/MSScan.bin`.
- **Thermo `.raw`**: the site engine has no reader (feature `thermo` of `mzlab-core` off); `Members::open_fs` (`natives.rs`) tries `readers::apri` and, for `err.file.notAccepted`, the external reader registered with `native_external(open)` (`ExternalReader`, `external.rs`: synchronous calls in the same worker to the `thermo` module).
  `lettore-esterno.js` (`createEsterno`, `prepara(names)`) loads the module (`carica-modulo.js`, SHA-256 check) BEFORE every entry point that opens a `.raw` (`attach`, `toMzml`, `samples`, `srmDi` in `rust-nativo.js`; `buildNative` in `idx-worker.js`): never for other files.
- For the `.raw` the v2 index with positions, routes, `native_srm` and "Download .mzML" (byte for byte that of the core reader) hold as for any reader; test `tests_e2e/e2e_thermo_modulo.py`. The desktop keeps Thermo in the core (default feature), with no external reader.
- Profile/centroid data of a `.raw`: the reader gives the data as they are; there is no choice box. In the `convert.mzml` step of the command line the `peaks` parameter chooses: `file` (as the reader), `profile` (profile points of the file) or `mzlab` (our own centroids, `readers_mzml::Picchi::Mzlab`); details in `rust-step.md`.
- The mzML of a `.raw` carries per scan what `RawReader::extra_scansione` reads: precursor (chosen m/z, charge, target window ± half width, activation CID/HCD/ETD/EThcD/…, collision or normalised energy, `spectrumRef` = last scan of the level above that precedes), vendor TIC and base peak, injection time, FAIMS voltage, scan window and every `opentfraw.*` as userParam.
- **Rule R** (`moduloToMzml`, `shell.js`): what the engine does not read (`soloModulo` extensions, sample refused with an error of `LETTORI_FAM`, `probe` with `motivi`, `?lettori=modulo` for `.D`) is converted by the readers module of the family into an OPFS mzML before `upload()`: `docs/agenti/lettori-modulo.md`.
- **Desktop, module types** (`moduliToNat` in `shell.js`, `NATIVO.desktop`): the app's Files are placeholders without bytes, no page module reads them; each `soloModulo` extension (`.mzML.gz`, `.mzXML`, `.cdf`, `.nc`, `.qgd`, `.lcd`) and each mzML that `natsamples` accepts (Numpress; a plain one is refused) becomes a native sample, named as the module names its mzML (`LETTORI_MOD.mzmlName`). Test: step "module types" of `crates/mzlab-desktop/tests/e2e_shim.py`, `tests/test_nativo.py`.
- **Fingerprints in one pass** (`impronta.js`, `impronta-worker.js`, `upload::Passata`, class `Passata` of the engine): during the copy into OPFS (`putChunks`, callback `after`) each written chunk goes to a dedicated Web Worker (`Transferable`, at most 4 chunks waiting; without Worker or with `mode: "qui"` it is computed in the copy worker) that computes SHA-256, SHA-1 of the whole file and `probe`.
- **Two fingerprint workers** (`impronta.js`, `Passata::sha1_only`, third argument `sha1_only` of the class `Passata`): with `navigator.hardwareConcurrency` ≥ 4 a member goes to two workers, SHA-256 and `probe` in the first (`without_sha1`), SHA-1 in the second (one copy of each chunk, also there at most 4 waiting); the three fingerprints are the same as from a `Passata`.
  In Chromium, 512 MB in 8 MB chunks, N=10: 3007 [2949-3185] → 1953 [1895-2010] ms; with CPU ×4 3079 → 2636 ms. App and CLI: `upload::fingerprint3` takes the SHA-1 in a second thread from the same chunks (512 MB in memory: 732 → 471 ms).
- **Fingerprint worker ready early**: `impronta.js` starts the Worker at creation, without its `.wasm` (it sends it with the first chunk). Until the Worker script has arrived at least once (message `up` from `impronta-worker.js`), a member is computed in place with the same `Passata`: on a slow first visit the script stayed queued behind the page downloads and held the copy for 10-19 s (`e2e_impronta_lenta`).
- The result is stored in the placeholder (`sha256`, `sha1`, `probe` of each member, optional): `build_mzidx_native` receives it (`prints`, skips `upload::impronte`) and the SHA-1 reaches the reader (`Membro::sha1`; to the `thermo` module with `open_with_sha1`) which uses it in `testata_mzml` instead of re-reading the file.
- **Late fingerprints** (`free` of `impronta.js`, `lateJob` of `rust-nativo.js`, `fingerprints.rs`): the copy of a member waits only for the SHA-1 (the `thermo` module wants it at opening), which goes in the placeholder; SHA-256 and `probe` read the dropped `File` in a second worker next to the copy (with one worker only: the OPFS copy, finished) while the index is built. `prints` is then a function the builder calls where it writes `source` (`build_after`, like `with_parallel_prints` in the app): it waits on a `SharedArrayBuffer`; without `crossOriginIsolated` the rpc awaits them first.
- A missing, empty or mismatching late value makes the builder re-read the members (`upload::impronte`): never an index without fingerprints; the same `.mzidx` in all cases (`tests/test_impronte_tardive.py`). The placeholder has SHA-256 and `probe` only if the hash finished before writing it: a rebuild in a later session recomputes them in the engine. A `File` changed during loading is no longer read: no fingerprint, the builder takes them.
- A placeholder without fingerprints (or with incomplete ones) makes the engine recompute them as before (`tests_e2e/e2e_lettori.py`). Desktop: the fingerprint stays `upload::impronte` on the in-memory map.
- **Provisional TIC of a `.raw`** (`tic-nativo.js`, op `early` of `idx-worker.js`, `native_early_tic`, `readers::tic_ms1`): while `nativo.put` copies the members into OPFS, a free builder of the index pool opens the dropped `File` objects with the `thermo` module and reads the rt/TIC MS1 of the scan index (all scans if none is MS1). It arrives as `early_tic` of the `progress` of the rpc that is loading the sample; the page draws it like that of an mzML (zoom: `tic-provvisorio.md`).
- Measure of the provisional TIC, synthetic 422 MB, 38 000 scans, N=10: TIC at 1813 [1495-2868] ms (CPU ×4: 2215 [1620-3691]) instead of 15234 [14563-18905] ms with the file open; whole load 15928 [15175-16469] ms (CPU ×4: 17198 against 16986).
- **MSn graph of a native sample** (`api/msn_grafo`, `msnlib/*`): the `msngrafo` module decodes only an offset mzML, so for a sample with a placeholder the worker (`rust-msngrafo-nativo.js`, `createDerivata`) writes the mzML into `conv/` (`msn~<name>~<hash of the members>.mzML`), builds its index in `idx/` and reuses them at the next request.
- The JSON is that of the graph from the same mzML (`sorgente.nome` = the sample, `sha256_idx` = that of the derived index). The worker sends `progress` `{phase: load|convert|index|graph, frac}` (bar 0-.5 / .5-.65 / .65-1; without conversion the graph takes the whole bar, `graph` = bytes read of the mzML) and the page relays them as the `mzlab-msngrafo` event (`rust-msngrafo-pagina.js`).
- The "Fragmentation graph" tab (`infusione-grafo-avanza.js`) shows the bar and, after 30 s without news (`STALL_MS`), the error `msngrafo.stalled` with "Details" and "Copy diagnosis"; every engine error also has its diagnosis. Test: `tests_e2e/e2e_msngrafo_nativo.py`.
- **"Size" column**: the size of the sample if the reader knows it, otherwise the sum of its members (`.wiff` + `.wiff.scan`; `shownSize` in `rust-worker.js`, for `lr_list` and `lr_entry`); "—" only if both are missing. The "Download mzML" buttons (row and group) stay for native samples: they write the mzML on request (`CONV.make`). The actions column (`.ldtab col.c-act`) is wide enough for "Download mzML" + ×; `tests/test_carico_colonne.py`.
- **Member reads in the worker** (`rust-nativo.js` `viaHandles`): `toMzml`, `srm` and `registro` read the OPFS copies with read-only handles open for the duration of the call (`openSource`, closed in `finally`); a reader kept after closing (the session of `registro`) falls back to the Blob. `attach` and `samples` read from Blobs (the reader stays in the engine between requests; `samples` reads the user's Files). Each opening of a reader (`readers::apri`) re-reads the two members of a `.wiff` in full.
- **Member blocks in the engine** (`Members::fileset`, `natives/member.rs`): each member is read through `mzlab_core::blocks::BlockCache` with a 256 KB block (`READ_AHEAD`) that, along reads in order, doubles up to 4 MiB (`read_ahead(LETTURA_MAX)`), so the `.D` makes one `read` call every few MB instead of one per scan; reads of at least one block go direct. Memory: at most 4 MiB per member of an open reader.
- **Reading into the `.wasm` memory** (`read.into(i, offset, view)` of `rust-nativo.js`, only with the handles of `lettura-sync.js`): the engine (`natives/member.rs`) and the reader modules (`leggi` of `reading.rs`) give a view of their memory and the handle reads into it, without a JS buffer copied afterwards. The view is valid only during the call: JS fills it at once, does not keep it, does not call the `.wasm`, and answers the bytes put. Without `into` (Blob, old page) the `read` path. Test: `e2e_lettura_sync`, `tests/lettura_nativi_node.mjs`.

## Recognised formats
- Single table by name in `mzlab/web/formati-noti.js` (`read` or `unsupported`). Read: SCIEX `.wiff`/`.wiff.scan` (3200 QTRAP by the engine; other QTRAPs by the `sciex` module, partial), Thermo `.raw`, Agilent `.D` (GC/MS by the engine, LC/MS by the module), Bruker `.d` TDF/TSF, Waters `.raw`, Shimadzu `.qgd`/`.lcd`, ANDI `.cdf`, mzML (also gzip and numpress), mzXML. Recognised and refused: SCIEX `.wiff2` and TOF, Bruker `.baf` and `.yep`, Shimadzu `.lcdx`, LECO, mzData; JEOL and PerkinElmer go through ANDI.
- Each format read is converted to mzML with the same writer (`mzmlwrite`). In the native app each family is read without an intermediate mzML; on the site only the engine (3200, Agilent GC/MS, mzML) and Thermo do, the other families go through an mzML in OPFS (`parita.md`).
