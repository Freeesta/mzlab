# Finding the other half of a SCIEX pair (`.wiff` + `.wiff.scan`)

- **Rule** (names only, one copy in Rust): `crates/mzlab-lettori/src/pair.rs`. `X.wiff` goes with `X.wiff.scan`, same base name, any case; the exact spelling wins, else the first equal ignoring case in byte order, so the answer never depends on the order a folder lists. Any other `.scan` is another maker's file and has no companion. `companion_in_dir` lists the names of one folder and opens nothing.
- **Users of the rule**: the desktop app (`opening.rs`: a `.wiff.scan` opens as its `.wiff` plus itself, a `.wiff` takes its scan along), the CLI (`flow_set::members`, so `convert`, `channels`, `flow run` take a lone half with its companion; the `.wiff` leads the dataset).
  Also `mzlab-cli file pair FILE... [--json]` (`wiffpair/1`: `ok`, `pairs[{input, half, wanted, found, size, looked_in}]`; exit 0 all found, 1 one missing, 2 usage). The page has a twin of the name functions in `wiff-pair.js`; `tests/test_wiff_pair.py` compares both on one synthetic folder. Cargo tests: `pair_tests.rs`, `opening.rs`.
- **Browser limit**: a page cannot read the neighbours of a picked or dropped file, and a file handle has no parent. The user grants the FOLDER; the file handle only serves as `startIn`, so the dialog opens in the right place. The site never opens a pair by itself without that grant.
- **Page** (`wiff-pair.js`, lazy, called by `upload()` after a batch with a `.wiff` / `.wiff.scan` that `WIFF_WAIT` still holds alone; not in the desktop app, which has the path): the loaded half goes through the normal loader (it waits in `WIFF_WAIT`, with today's notice); the status region `#wiffpair` (`role=status`, `aria-live=polite`) says «The pair file X.wiff.scan is needed: choose the folder it is in» with «Choose folder» and «Not now».
  - Order: the folder granted in this page session; the pointed folder the page remembers (`CartPP.S`, IndexedDB) if its permission is granted, or one «Allow» click if it needs it and its listing holds the name; then the prompt.
  - «Choose folder»: `showDirectoryPicker({ id, mode: "read", startIn: handle of the file })` (handles from `showOpenFilePicker` in `pickFiles`, shell.js, and `getAsFileSystemHandle` in `DROP`, drop-unico.js; automated browsers use the input, `window.MZLAB_FS_PICKER = true` forces the picker). Safari and Firefox have no `showDirectoryPicker`: a `webkitdirectory` input, of which only the top-level names that match are taken (the other files are never read).
  - Only the companion is read; «Found: X.wiff.scan, 3 MB, opening the pair.» is shown, then `upload()` pairs it. Absent: «Not found: X.wiff.scan. Looked in the folder F by file name only…» and the prompt stays.
  - Not done: persisting the folder chosen in the prompt (the session keeps it; the pointed folder is the persistent one, with its own «forget»).
- Tests: `tests_e2e/e2e_wiff_pair.py` (fake folder handle: a native dialog cannot be driven), `tests/test_wiff_pair.py`.
