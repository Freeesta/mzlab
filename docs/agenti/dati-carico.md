# Caricamento: primo caricamento e tabella di carico
- **Primo caricamento in bassa risoluzione** (`bootSession0` in `explore.js`; `e2e_apri_uno`): con più file, anche di tipi diversi (Full Scan, MS2, MRM), si apre solo il PRIMO della lista (come in HR); gli altri restano nell'elenco e un clic sulla riga li apre, con la scheda del suo tipo. Serie (t0, t5, t10) e calibrazioni usano comunque tutti i file letti: `vis` cambia solo cosa è disegnato.
- **Tabella di carico, campi** (`renderFiles` in `shell.js`; `e2e_tempo_un_clic`): un valore uscito dal campo (clic su un altro campo, Tab) si applica a focus già spostato e la tabella riordinata restituisce il focus al campo (o al pulsante ×) che l'ha ricevuto: un solo clic basta.
- **Ruoli e tempi nella tabella di carico** (`ruoli-carica.js` modello e proposte, `ruoli-celle.js` celle ruolo e tempo; oggetto globale `RUOLI`; `e2e_ruoli_tempi`): il motore Rust `campioni/2` raggiunge la pagina con POST `api/campioni/<op>` (`statRoute` in `lr-map.js`, `lr_campioni` in `rust-worker.js` e `rpc_lr.rs`).
- **Proposte** (`ruoli-carica.js`): `proponi` dà ruolo e tempo dai nomi; il tempo è una cella normale, modificabile, senza colore né conferma, e il ruolo si sceglie solo nella colonna «Tipo». Il tempo è facoltativo: «Load data» è la conferma e non si ferma mai per un tempo mancante (nessuna striscia, nessun avviso, nessuna cella `aria-invalid` per questo). Solo la concentrazione letta dal nome resta gialla (`guess`) finché non la tocchi.
- **Ruoli senza t0 né sottotipi**: non esiste il ruolo t0: un campione a tempo 0 è il t0 (lo cercano così `sottrazione.js` e il Rust). Un solo tipo Bianco, senza sottotipi.
- **Tempo del buio**: Il tempo del buio è NEGATIVO (minuti di buio prima dello zero; la cella accetta «-30» o «−30», e un numero positivo scritto in un buio è letto come negativo: `darkTime` in `ordine.js`); il buio resta fuori dal gradiente (`gradientLegend`, `byTime` in `explore.js`) e dal riferimento `auto`. Un progetto o un TSV vecchi con `t0` o `blank:solvent`/`blank:procedure` si aprono come campione a 0 e bianco semplice (`CDOC.fields`, `parseTsv`).
- **Voce di `ST.files`**: `type` (base: sample/blank/standard), `role` (`tipo` di campioni/2), `time` (minuti), `prop`, `ed` (scelto dallo studente: una proposta tardiva non lo sovrascrive). Le prove che aprono molti file chiamano `lib._tempi(pg)` per scrivere i tempi mancanti (`lib.AUTO_TEMPI`).
- **Caricamento successivo** (`bootSession0`, `remap` e `PEND` in `explore.js`; `e2e_ms2_ricarica`): i pannelli aperti restano sui loro file anche se la lista è riaperta file per file (i passi intermedi non hanno ancora tutti i file): indice di file di un pannello (`k`, `ref`, `bk`, `bg`) e file attivo seguono il NOME del file; un file non ancora tornato mantiene nome, visibilità ed etichetta (`E._mem`) fino al suo ritorno.
- **Apertura progressiva** (sito e desktop; `?progressivo=1` la accende anche col server di sviluppo, per i test): `exploreList` in `shell.js` apre il PRIMO file della lista con `api/explore` e la vista Dati si apre su di lui;
  gli altri sono in `E.pending` (righe grigie `.fl.pend` in fondo all'elenco, casella disabilitata, `aria-busy`, nome e «in caricamento», pulsante × per toglierli; barra `.pendbar` `role=progressbar` finché ne manca uno) e `openRest` li aggiunge uno alla volta, nell'ordine della lista, con `api/explore` + `append:true` (`Session.add`: la sessione è quella di sempre, il risultato è uguale all'apertura di tutta la lista in una chiamata).
  Mentre la lista si apre così (`E._seq`, test `e2e_carica_scheda`) i passi successivi non cambiano scheda: resta quella del primo passo; un file aggiunto più tardi apre la scheda del suo tipo.
  `bootSession` ricarica la vista al massimo ogni ~200 ms (un solo ridisegno per gruppo di file arrivati); i file nuovi seguono le regole del primo caricamento (HR: si apre solo il primo). Un file che fallisce resta in rosso col messaggio, gli altri continuano; un file tolto dall'elenco non si legge. `e2e_progressivo`.

## Gruppi della tabella e riepilogo
- La tabella di carico raggruppa prima per strumento (`loadGrp` in `shell.js`: bassa risoluzione, poi alta risoluzione `f.hr`, campo di `sniff.rs`), poi per esperimento; un file con più parti (Full Scan + DDA/IDA) ha un gruppo suo, mai quello dell'MS2 puro. Test: `e2e_carico_gruppi`.
- Il riquadro sotto la tabella (`CONVROWS.summary()`) elenca solo errori, annullati e file con scansioni mancanti; se è andato tutto bene non compare.

## Bassa e alta risoluzione insieme
- Se la tabella di carico contiene file LR e HR (`f.hr`, dal motore), `#hrmix` (`hrMixNote()` in `shell.js`) mostra una nota con stato (non un errore) e due scelte, «Solo LR (n)» / «Solo HR (n)» (`aria-pressed` sul mondo attivo): `hrMixPick()` spunta un mondo e toglie la spunta all'altro, i file non scelti restano in elenco per un secondo caricamento.
- All'arrivo di file nuovi `hrMixPreselect()` sceglie il mondo più numeroso (a parità, LR); se l'utente rispunta entrambi i mondi, «Carica dati» resta disabilitato (`checkGo()`) finché non ne sceglie uno. L'errore `err.hr.mix` del motore resta come rete di sicurezza (file già aperti dell'altro mondo). Prova: `e2e_carico_lrhr`.

## Rilascio sull'elenco dei file
- Trascinare file o una cartella sul pannello `#dfiles` (con una sessione aperta, fuori dalla tabella di carico) li aggiunge subito: `#fl-dz` mostra la zona di rilascio, `shell.js` usa lo stesso `upload()`/`CartCarica.fromDrop(e, done)` e, a caricamento finito (`directDone()`), `openStaged()` apre i file come il pulsante «Carica dati», senza schermata di caricamento (avanzamento = barra dell'elenco, `E.pending`). I duplicati li scarta `dropDups`.
- I file di risoluzione diversa da quelli aperti (o il mondo meno numeroso di un rilascio misto) non si aprono: restano nella tabella di carico, senza spunta; `#fl-note` (`role=status`, 9 s) lo dice senza errori. Prova: `e2e_elenco_file`.
