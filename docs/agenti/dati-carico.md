# Caricamento: primo caricamento e tabella di carico
- **Area di lavoro dal primo disegno** (`index.html`, `applyView` in `shell.js`, `workState`/`syncWork` in `area-lavoro.js`): `#v-data` è visibile da subito; `#v-workspace` mostra una cosa sola, decisa dallo stato (`data-work`): `panels` (un file mostrato o un pannello aperto), `table` (nessun file mostrato dopo che uno lo è stato, o «Tabella dei campioni» premuto: `#wtable` con `.samphead`, `#flist`, `#hrmix`), `landing` (`#start` con `#drop`, cartella, esempi, metodo `.dam`, conversione, e sotto `#wtable` appena la tabella ha righe); `add` e `opening` a parte.
  `landing` resta finché lo studente non mostra un file (clic nell'elenco: `workShown`); è anche l'unico stato vuoto: prima visita, file in lettura (l'avanzamento sta solo nell'elenco laterale; la tabella cresce sotto la zona di rilascio, che non si sposta), tutti i file tolti (`workRows`: una riga di un file tolto non conta). `#up` e `#unopen` (solo errori) stanno sopra i riquadri in `#wdata`; prima della sessione anche il pannello laterale prende i file rilasciati.
  `#drop` è un pulsante (`role=button`, `tabindex=0`, `load.drop.aria`; Invio e Spazio aprono `#pick`). In `#tools` i pulsanti dei dati sono `disabled` + `aria-disabled` finché non c'è un file aperto (già nel markup); le calcolatrici della testata restano usabili. `#fsel` vuoto tiene la larghezza di un nome. Con `#/draw` `html.in-draw` nasconde `#v-data` prima di ogni script.
- Visita di ritorno con sessione salvata (`mzlab.sessione`): la landing non viene mai dipinta; `avvio-progressivo.js` mostra subito `#opening.restoring` («load.session.restoring», altezza riservata) al posto di `#wdata`, poi i pannelli (o la tabella dei campioni) sostituiscono il riquadro; con sessione vuota compare la landing nello stesso riquadro.
- **Primo caricamento** (`bootSession0` in `explore.js`; `e2e_apri_uno`, `e2e_apri_subito`): ogni file nuovo entra nella sessione NASCOSTO (`vis` false, salvo la visibilità salvata da `restoreUi`); nessun file si apre da solo: il primo clic su un file dell'elenco lo mostra e la zona di rilascio lascia il posto ai grafici.
  «Tabella dei campioni» (`#samptab` nel pannello dei file, visibile appena l'elenco ha righe, `aria-pressed`, `S.table`; sulla landing con la tabella in vista è premuto e inerte) mostra la tabella al posto dei grafici; un clic su un file dell'elenco torna ai grafici. Serie e calibrazioni usano tutti i file aperti: `vis` cambia solo cosa è disegnato.
- **Tabella di carico, campi** (`renderFiles` in `shell.js`; `e2e_tempo_un_clic`): un valore uscito dal campo (clic su un altro campo, Tab) si applica a focus già spostato e la tabella riordinata restituisce il focus al campo (o al pulsante ×) che l'ha ricevuto: un solo clic basta.
- **Ruoli e tempi nella tabella di carico** (`ruoli-carica.js` modello e proposte, `ruoli-celle.js` celle ruolo e tempo; oggetto globale `RUOLI`; `e2e_ruoli_tempi`): il motore Rust `campioni/2` raggiunge la pagina con POST `api/campioni/<op>` (`statRoute` in `lr-map.js`, `lr_campioni` in `rust-worker.js` e `rpc_lr.rs`).
- **Proposte** (`ruoli-carica.js`, `ruoli-celle.js`): `proponi` dà ruolo e tempo dai nomi (`f.gR`, `f.gT`); le celle proposte e non toccate portano la classe `guess` (gialla, `load.guess.title`) come la concentrazione letta dal nome, e la perdono alla prima modifica. Il tempo è facoltativo: nessuna striscia, nessun avviso, nessuna cella `aria-invalid` per un tempo mancante. Il ruolo si sceglie solo nella colonna «Tipo».
- **Ruoli senza t0 né sottotipi**: non esiste il ruolo t0: un campione a tempo 0 è il t0 (lo cercano così `sottrazione.js` e il Rust). Un solo tipo Bianco, senza sottotipi.
- **Tempo del buio**: Il tempo del buio è NEGATIVO (minuti di buio prima dello zero; la cella accetta «-30» o «−30», e un numero positivo scritto in un buio è letto come negativo: `darkTime` in `ordine.js`); il buio resta fuori dal gradiente (`gradientLegend`, `byTime` in `explore.js`) e dal riferimento `auto`. Un progetto o un TSV vecchi con `t0` o `blank:solvent`/`blank:procedure` si aprono come campione a 0 e bianco semplice (`CDOC.fields`, `parseTsv`).
- **Voce di `ST.files`**: `type` (base: sample/blank/standard), `role` (`tipo` di campioni/2), `time` (minuti), `prop`, `gR`/`gT` (ruolo e tempo ancora proposti), `ed` (scelto dallo studente: una proposta tardiva non lo sovrascrive). Le prove che aprono molti file chiamano `lib._tempi(pg)` per scrivere i tempi mancanti (`lib.AUTO_TEMPI`) e `lib.open_first(pg)` per il primo clic su un file.
- **Caricamento successivo** (`bootSession0`, `remap` e `PEND` in `explore.js`; `e2e_ms2_ricarica`): i pannelli aperti restano sui loro file anche se la lista è riaperta file per file (i passi intermedi non hanno ancora tutti i file): indice di file di un pannello (`k`, `ref`, `bk`, `bg`) e file attivo seguono il NOME del file; un file non ancora tornato mantiene nome, visibilità ed etichetta (`E._mem`) fino al suo ritorno.
- **Apertura subito** (`OPENNOW` in `open-now.js`; `e2e_progressivo`, `e2e_carica_subito`): ogni file si apre appena letto. `upload0` (`shell.js`) chiama `OPENNOW.add(nome)` appena un file è nella tabella; una coda apre un file alla volta, nell'ordine del rilascio (durante un caricamento un file letto presto aspetta quelli rilasciati prima, `CONVROWS.rank`; a caricamento finito apre tutto), così `k` non dipende da quale file finisce prima: il primo della sessione con `api/explore`, gli altri con `append:true` (`Session.add`: la sessione è uguale all'apertura di tutta la lista in una chiamata).
  `bootSession` al massimo ogni 200 ms (un solo ridisegno per gruppo di file), poi `RUOLI.commit` dei file nuovi; un file che fallisce si toglie dalla spunta e gli altri continuano. Spunta della tabella = «nella sessione»: togliere la spunta chiama `removeFile` (annullabile, `STORIA.tolto`), rimetterla riapre il file (`fileRemoval(g).back()` o `add`). `OPENNOW.idle()` risolve a coda vuota; `E.pending` resta una lista vuota per le attese esistenti.
  «Passa a …» (`OPENNOW.toWorld`) e la domanda «Apri tutti / Scegli» oltre 50 file (`OPENNOW.many`) stanno in `open-now-raro.js`, e il riquadro di una conversione chiesta dalla tabella («Download .mzML» di un campione del costruttore, `ConvUI.card`) in `conversione-carta.js`: entrambi caricati al primo uso con `carica()`, fuori dalla lista d'avvio (`test_peso_avvio.py`). Le conversioni di un caricamento non disegnano nulla (`ConvUI.group()`: solo gli stop).
- **Scrittura nella sessione** (`OPENNOW.edit`/`sync`): una modifica dello studente su un file aperto passa da `campioniEdit` (un passo annullabile); una proposta arrivata dopo l'apertura si applica in silenzio con `CAMPIONI.apply(…, true)` alle celle non toccate (`!ed`), dal richiamo di `FILETAB`.
- **Righe di avanzamento** (`UPROWS` in `upload-rows.js`, disegnate da `renderFileList` in `#fl-up`): dal rilascio, una riga grigia `.fl.pend.up` (`data-up`, `title` = testo lungo, `aria-busy`, barra `.prog` `role=progressbar`, fase e percentuale da `CONVROWS.short`) per ogni file in lettura, conversione o apertura, in fondo all'elenco laterale; sparisce quando il file è aperto o messo da parte. Sopra le righe, finché il lotto corre, «3 di 5 pronti · 0:12» (`data-cvhead`) e «Annulla» per tutto (`data-up-all`, `CONVROWS.onCancel`).
  × su una riga in corso = `OPENNOW.hold` + `ConvUI.stop` (conversione) o `lr_cancel` (il file resta senza spunta); un errore resta in rosso con «Dettagli» (`DIAG`) e × lo chiude. `CONVROWS.fill` aggiorna anche queste righe. (`.fl.pr` resta il precursore MS2.)
- **Cartella grande** (`OPENNOW.many`, `#askdlg`): più di 50 file di dati in un rilascio chiedono una volta «Apri tutti» / «Scegli…»; «Scegli» (o Esc) li mette in tabella senza spunta (`OPENNOW.hold`).
- **Tabella grande** (`renderFiles`): oltre 500 righe il corpo arriva a blocchi di 200 per fotogramma (`FRAME.next`, `FILECHUNK`).

## Gruppi della riga e riepilogo
- La tabella di carico non ha righe di gruppo: le righe restano nell'ordine di arrivo (`CONVROWS.rank`; una modifica dello studente lo scioglie e la tabella torna ordinata da `sortFiles`). Il gruppo di una riga (`loadGrp` in `shell.js`: bassa risoluzione, poi alta risoluzione `f.hr`, poi esperimento; un file con più parti Full Scan + DDA/IDA ha il suo, mai quello dell'MS2 puro) sta in `data-grp` e nell'etichetta «HR». Test: `e2e_carico_gruppi`.
- Il riquadro sotto la tabella (`CONVROWS.summary()`, `conv.sum.aria`) elenca solo errori, annullati e file con scansioni mancanti, con il totale e «Chiudi»; se è andato tutto bene non compare, e a fine lotto non resta nessun testo «finito» né anello.

## Bassa e alta risoluzione insieme
- **Regola del mondo** (`OPENNOW.world`, `hrMixNote()` in `shell.js`; `e2e_carico_lrhr`): il mondo della sessione (bassa o alta risoluzione, `f.hr` dal motore) è quello del primo file letto; i file dell'altro mondo restano nella tabella senza spunta (rispuntarli non li apre: il fuoco va al pulsante di `#hrmix`). `#hrmix` (`role=status`, non un errore) dice quanti file sono messi da parte e offre un solo pulsante «Passa all'alta/bassa risoluzione». Il passaggio chiude prima i pannelli del mondo chiuso (`closeAllPanels`), poi si apre da solo il primo file dell'altro.
- `OPENNOW.toWorld(hr)`: `api/new` chiude i file aperti, spunta l'altro mondo e lo apre con la stessa coda; una voce «Tolti · Annulla» (`STORIA.tolto`) riporta il mondo di prima. Senza nessun file aperto `#hrmix` offre ancora «Solo LR (n)» / «Solo HR (n)» (`hrMixPick`, `hrMixPreselect`: il mondo più numeroso, a parità LR). L'errore `err.hr.mix` del motore resta come rete di sicurezza.

## Rilascio sull'elenco dei file
- Trascinare file o una cartella sul pannello `#dfiles` (con una sessione aperta, fuori dalla tabella di carico) li aggiunge subito: `#fl-dz` mostra la zona di rilascio, `shell.js` usa lo stesso `upload()`/`CartCarica.fromDrop(e, done)` e ogni file si apre appena letto (`OPENNOW`), senza schermata di caricamento (avanzamento = righe `.fl.up` dell'elenco).
  A lotto finito `OPENNOW.note()` abbassa il velo `#loading` (quello del file di esempio del tour) e scrive in `#fl-note` i file messi da parte (con il rimando a «Passa…» nella tabella dei campioni) e, con file già mostrati, quanti ne sono stati aggiunti. Aprire un file di un'altra scheda non alza il velo (`setTab(t, false, "file")`); il velo, quando cade, toglie anche il pulsante di `#ldact`. I duplicati li scarta `dropDups`.
- I file di risoluzione diversa da quelli aperti (o il mondo meno numeroso di un rilascio misto) non si aprono: restano nella tabella di carico, senza spunta; `#fl-note` (`role=status`, 9 s; «aggiunti» sfuma dopo ~1 s) lo dice senza errori. Prova: `e2e_elenco_file`.
- Il pulsante cartella `#cartpick` sta a destra del titolo «1.» (centrato in verticale, ≥8 px dalla zona tratteggiata); il selettore file `#navfile` (frecce + menu `#fsel`) ha altezza uguale (32 px, 40 al tocco), il menu è largo quanto il nome più lungo (min 9ch, max 40vw, «…» e nome intero nel `title`). Il trascinamento sui pannelli mostra solo l'evidenziazione della zona di rilascio, senza fumetto. Prova: `e2e_carico_pulizia`.
- **File attivo iniziale** (`firstOpenK` in `lista-file.js`): l'ordine dell'elenco resta, ma si apre (e diventa attivo) il primo file che non è un bianco (`type` blank o nome con blk/blank/bianco), il primo di tutti se sono tutti bianchi; un bianco aperto per primo durante il caricamento file per file si chiude all'arrivo del primo non-bianco. Lo spettro vivo di un cromatogramma segue il file scelto nell'elenco (`followSpectra`) finché il suo menu file non è stato usato; un DDA non porta mai «· Full Scan» nel nome (`noFullScan`). Prova `e2e_dda_attivo`.
- **Grafo MSn salvato** (`upload0` in `shell.js`, prima di `fileKind`): i `.json` con testata `msngrafo/N` escono dalla lista e si aprono nella finestra del grafo (`infusione-grafo.md`); gli altri file vanno avanti come sempre e un errore del grafo finisce nel riquadro `#unopen` come quello di un file illeggibile. `#pick` accetta anche `.json`.
