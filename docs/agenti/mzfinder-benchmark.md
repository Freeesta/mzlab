# mzFinder benchmark (`tools/bench/`, `tests/test_bench.py`)
The plan (competitors, datasets D1-D5, endpoints, margins, sets) and the pre-registration are in the private repository. It measures only the QUALITY of the results, never time or memory. It reuses `tools/valida/` (`match_points`, `nativo`, `cancello.run_synthetic`, `sintetici_identita`, `rapporto.a_json`) without changing it. `import bench` is the `tools/bench/` package (the `tools/bench.py` file of the speed measurements is run only as a script).

- **Common table `bench/1`** (`adatta.py`): `{formato, strumento, dataset, config, file[], righe[]}`; row `{id, mz, rt, rt_min, rt_max, aree[], altezze[], ms2_scan, gruppo, candidato, livello, punteggio}` (null if the tool does not give it). Rows sorted by (m/z, RT, area) and numbered from 0: same content = same bytes. `tabella`, `a_json`, `leggi`, `matrices`.
- **mzFinder**: `da_serie(Serie)` (areas of the aligned table; `candidato` = identity with a proof in favour, `livello` = `livello_max`, `punteggio` = `totale`); `corri_mzfinder_sintetico(seme, profilo, cartella)` generates the D2 series, runs the `native` example (the site pipeline) and gives (table, truth).
- **Other tools**: `da_csv(strumento, percorso, file, dataset)` with `RULES` for the columns of mzmine, XCMS (`featureDefinitions` + `featureValues`), OpenMS (consensus in CSV), asari, patRoon; RT in seconds -> minutes where needed. The column rules are tested on fake files; the real outputs of the runners (below) confirm them.
- **Truth** (`verita.py`): compounds `{id, mz, rt, ruolo, fascia, atteso, area_attesa}`. `from_rows`/`da_json` (D2 `ioni`; D3 `parent` + `tps`, one compound for each observed RT: `id`, `id#2`), `da_maf` (D1: columns by name, RT in seconds optional). True features = parent, tp1, tp2, isomer, adduct, isf with RT; products = tp1, tp2, isomer; decoys = `esca` (no signal, searched by m/z only) and `isf_finto`.
- **Metrics** (`metriche.py`), one list per compound (so two tools are paired and the compounds can be resampled):
  - `p1` recall (also per `fascia`); `p2` accuracy (D1: |log2(observed/expected ratio)| with `gruppi={"A":[col],"B":[col]}`; D2: relative area error with `area_attesa`; NaN if not measurable).
  - `p3` integrity (exactly one row, not shared with another true compound);
  - `p4` products among the candidates + ranks + `per_90` (candidates to scroll through for 90 %);
  - `p5` decoys with a candidate of level better than 4 + candidate precision;
  - `secondarie` (unexplained rows, rows per compound, separated isomers). Candidate order: score, then maximum area (as in the panel); without a flag, all rows by maximum area.
- **Statistics** (`statistica.py`): cluster bootstrap of the compound (2000 resamples, fixed seed, also stratified), 95 % percentile interval of a metric (`intervallo`) and of the paired difference (`difference`, with bootstrap p), exact McNemar, Holm, `non_inferior` and `upper` with the pre-registered margins (`MARGINS`: P1 −0.02, P2 +0.05, P3 −0.02, P5 +0.01).
- **Report** (`rapporto.py`): `misura(verita, tabella)`, `unisci` (several seeds: strata), `rapporto(dataset, mzfinder, altri)` -> deterministic `bench-rapporto/1` JSON (sorted keys, rounded numbers, no date), `a_markdown`. It writes numbers, not the concluding sentences (people decide those). Command: `python3 tools/bench/rapporto.py --d2 --seme 7 --profilo piccolo --out DIR` -> `bench1.json`, `rapporto.json`, `rapporto.md`.
- **Tests** (`tests/test_bench.py`): Holm, McNemar and bootstrap on cases with a known result; metrics on a hand-made table; adapters; mzFinder on D2 `piccolo` (skipped without cargo) with two byte-identical runs.
- **Data**: `scarica.py MANIFESTO CARTELLA [--gruppo G] [--solo N] [--elimina N]` downloads the files of a `bench/manifesto/1` manifest (resume with Range, SHA-256 and size verified, a file with a wrong hash is deleted and the command fails; files in parallel with several calls). `converti.py RAW_DIR MZML_DIR [--parser P] [--elimina-raw]` converts the `.raw` files into indexed mzML with centroid peaks (ThermoRawFileParser; needs libicu: in invariant mode every scan fails) and writes `converti.json` (version, hash and bytes of input and output).
- **Data checks**: `controlla_rt.py MAF MZML_DIR` looks for the XIC apex of each compound (±5 ppm, sum of the files, ±1 min window) and reports the percentiles of apex − truth RT and how many stay under a tolerance; `prepara_d1.py` makes `verita/D1.json` from it (ion from formula and m/z); `parita_raw.py A B` compares two mzML of the same `.raw` (scans, RT, peaks per scan, m/z in ppm, intensity). `verita.rapporto_atteso` reads "a\\b" (SA\\SB) of the MAF.
- **Data tests** (`tests/test_bench_dati.py`): download from `file://` with right hash, wrong hash and wrong size; conversion registry with a fake converter.
- **Competitors**: `corri.py` (common arguments, mzML files, `salva` -> `<strumento>_<dataset>_<config>.json` in `bench/1`); one runner per tool, parameters in `parametri/<strumento>/<config>.json`; `versioni.py` writes the exact versions.
- **Runners**: `corri_mzlab.py` (`native` example; without `--genitore` only `series.mzfeat`, with `--genitore` also identities and candidates), `corri_openms.py` (pyOpenMS: FeatureFinderMetabo per file + KD linking with its RT warping; the pose clustering of pyOpenMS 3.6 fails on these maps), `corri_asari.py` (`asari process`, `export/full_Feature_table.tsv`), `corri_xcms.py` + `corri_xcms.R` (centWave, obiwarp, peak density, fillChromPeaks; R 4.3.3 and Bioconductor 3.18).
- **mzmine** (`corri_mzmine.py`): headless batch XML (mzML import, centroid, ADAP, local minimum, join aligner, gap filling, modular CSV); mzmine 3.9.0 from bioconda with the exact OpenJDK 20. The parameter names are those of the `.class` files: "m/z tolerance (sample-to-sample)" in the join aligner and in gap filling; an RT tolerance is `<parameter name="Retention time tolerance" unit="MINUTES">0.2</parameter>`. A step with invalid parameters stops the batch without a message: read it with jdb on `AbstractTask.setErrorMessage`.
- **mzmine, installation and per-ion comparison**: `install_39()` downloads mzmine 3.9.0 and JDK 20; `unread_parameters` flags the parameter names that mzmine would ignore (the resolver wants "Min # of data points"); per-ion protocol and reasons for lost rows in `docs/agenti/attributio.md`.
- **Report from tables**: `rapporto.py --verita V --tipo d1|d3 --rt-tol T --gruppi A=SA1,.. B=SB1,.. --tabelle PRIMA ALTRE.. --out DIR` measures tables already written by the runners (the first is the tool under test); D1 counts only the compounds `visto` in the data.

## Identification truth (test 5 of the workflow study)
- `tools/bench/verita_identificazione.py LIB QUERIES [--out FILE]` runs `cargo run -p mzlab-lib --example truth_lib` (the calculation is Rust): queries of one public library against another with fragment decoys, truth = first block of the InChIKey.
- Per score (cosine, modified cosine, spectral entropy): rank-1 count and hits at q <= 1 %. The record is `prov/1`-style: input SHA-256, parameters, outcomes (entropy rank-1 not below cosine; same answer on a second run).
- Without the files it skips; they stay outside git and the numbers go to the private repository. Test: `tests/test_verita_identificazione.py` (invented libraries).
- **Batch mzmine 4.10** (`oro_mzmine410.batch_xml`): `Scan filters` with `selected="true"` in mass detection and ADAP and `selected_item` on the detector; `check_filter`/`controlla_selected` reject the batch otherwise (4.10 silently ignores the 3.9 names and also processes the MS2). Test: `tests/test_bench.py`.
- **Smeared peaks** (batch `valida.sintetici_mzml.genera_larghi`, `verita.json` with `ruolo` broad/narrow): `valida.abbina.abbina_larghi` (a band accepts |dRT| ≤ max(tol, 0.35·FWHM) or interval IoU ≥ 0.40; narrow compounds as `abbina`, which does not change); `metriche.larghi` gives P1_narrow, P1_broad, P2_broad (median relative area error), P3_split (rows per band, excluding the narrow peaks above) and P5_fp (rows that no compound accepts); `confronto_larghi.py --verita V --tabelle "Nome=tabella.json" ...` prints one column per table. Tests: `tests/test_bench_larghi.py`.

## patRoon and identification endpoints
- **Runner** (`corri_patroon.py` + `corri_patroon.R`): patRoon (GPL-3) is only an external program, inside the Docker image `versioni.PATROON` (`nome` + `digest`; the runner refuses to run while the digest is None and SKIPS, exit 0, when Docker is absent); the mzML folder is mounted read-only. Steps: `findFeatures` (config `openms` or `xcms`), `groupFeatures`, `filter` (blank x5, replicate abundance, RSD 0.75), then with `--sospetti name,mz,rt` `screenSuspects` + `annotateSuspects` (`estIDLevel`); `--analisi analysis,group,blank` gives replicates and blanks.
- **Parameters** (the book values): `parametri/patroon/{openms,xcms}.json`. Never copy patRoon code or R logic into the repository.
- **Tables**: `featureGroups.csv` -> `adatta.da_csv("patroon", ..., sospetti=suspects.csv)`: `gruppo` = patRoon group, `candidato` = the group has a suspect hit, `livello`/`punteggio` = those of the best hit (patRoon's own strings, e.g. "3a"); the document gains `identificazioni` (`riga`, `hits` best first with `rango`) only when suspects were screened. Without it the bytes of every other table are unchanged.
- **Endpoints, declared before the first real run** (`metriche.endpoint_nts`, truth standards named by `strutture` {id: name in the suspect list}): feature recall (`p1`); area accuracy (`p2`); suspect-hit recall = standards whose matched row has a hit with the true name; false positives = share of decoys (`esca` by m/z, `isf_finto` by m/z and RT) with any hit; rank of the true structure among the hits of its row (mean reciprocal rank, 0 if absent); level reached per standard (`livelli`: count per level).
- **Levels** of each tool are listed side by side (`rapporto.identificazione_affiancata`) and never converted: ours is Schymanski 2014 plus 2b only by the chemist
- **Reading**: the same function reads any table with `identificazioni` (the mzLab side must write the same field to be compared). `p5` is not used for patRoon levels.
- **Real run (local agent, Mac, `MZLAB_DATI`)**: `python3 tools/bench/corri_patroon.py MZML_DIR OUT_DIR --dataset D3 --config openms --analisi A.csv --sospetti S.csv --pull`, then `xcms`; only aggregates (`rapporto.identificazione_markdown`) leave the private repository. Test: `tests/test_bench_patroon.py` (invented CSV, no Docker).
