# Data view: panel header, correction, lists, workflow, QA/QC, statistics, report
Part of the Data view (`docs/agenti/data.md`).

- **Reference and contaminant lists** (`liste.js`, `#np-liste`): one engine for LR and HR; the world is decided by `TBL_HR()` (tables.js, no file = HR), without a switch: LR = 4 columns (exact m/z to 4 decimals, name, ion, polarity), search by nominal m/z (±0.5 Da, hidden tolerance), no Target view and no diamonds; HR = 9 columns with Δ in ppm; lab contaminants (`openLab`) are imported from CSV up to `LAB_MAX` (5000) rows per file: beyond that, the toast `lst.lab.importedCut` says the rows taken, those in the file, those left out and the next step.
- **Contaminant name in the formula field** (`isoAsk`, `spettro.js`): the field accepts a formula or the name (even partial, ignoring case and accents) of a list entry. `liste-nomi.js` (lazy, `LISTENOMI.suggest`, `byName`) reads the `LISTE` index: preferred adduct [M+H]+, then [M-H]-. `ask-suggerisci.js` (lazy, `ASKSUG`; `ask(title, value, {suggest, tip})` is in `explore.js`) draws the combobox `#asksug` (arrows, Enter chooses, Esc closes the list); the choice writes "formula adduct". Test: `e2e_ask_contaminante.py`.
- **Name with parentheses** (`byName`): "dibutylphthalate (DBP)" is found by the full name, by the name before the parenthesis or by the text inside (`dibutylphthalate`, `DBP`), only if exactly one entry matches; the exact name and the English one win first. Tests: `tests/test_pesticidi.py`, `e2e_xic_nomi`.
- **"Known contaminants" panel** (`liste.js`; the spectrum menu and the palette redirect to it): one field `#lst-q` (a number sorts by m/z; text filters by name, formula, class), tolerance = the "Adducts & losses" component (`CALCQUI.mount` `controls`: Da/ppm, choice kept in `calcqui`), list chips with their entry counts (`lst.grp.*`), `#lst-cont-signs`, `#lst-count`, table with wrapped names. The "HRMS Target Screening" tab shows only with `FEATURES.targetScreening` (`?targetscreening=1`). Rust: `mz-match/1`, `ion match unit=da|ppm tol=N`. Tests: `e2e28.py`, `e2e_liste_target.py`.
  Add list, provenance and the CSV reader: `reference-lists.md`.
  without "?", references or sources (`noRef()` removes "(Keller 2008)" from names; the Source column appears only with two or more lists). (CSV with `;` and decimal comma, NORMAN format; IndexedDB `"qqq_lab"`, store `user_lists`). LR: NO automatic flagging on spectra (principle 1), from the right click "Search the contaminant lists...", teaching text on chance matches and series (PEG every 44 Da, siloxanes every 74 Da).
  HR (only with real `hrp` and the switch on): ppm search, row "Compatible with a known contaminant" on mouse-over of the peak, diamond (`contMarks` in `picchi.js`, shape + `--warn`) on peaks compatible within `UIP.hrPpm` with the right polarity, "Contam." column in the peak table of the MSn tree.
  Exclusions = hide (peak dimmed, no m/z label, out of the tables; TIC, XIC, normalisation and export unchanged), counter "N peaks hidden · Show" per cell; click on the diamond (or the button next to the legend) -> "Exclude this entry / the whole class / the list" (user and lab lists) or "Include again"; list with "Restore all" in the Lists panel; memory `mzlab.contaminants.excluded` = `{voci, classi, liste}`, also saved in the session (`NB.ui.contEx`, union on restore);
  the `menu()` is used from the keyboard (arrows, Enter, Esc; opens with the button next to the legend) (API `LISTE.exclSet/exclReset/exclExport/exclImport/compat`).
  Built-in lists (`/api/contaminants`, ions computed by `contaminants.py`): `keller` (`chem/contaminants.json`, Keller 2008, 286 entries, **without m/z**; English names in `contaminants_en.json`) and `pesticides` (`chem/pesticides.csv` + `pesticides_meta.json`, area `pesticides.md`); user lists in `mzlab.contaminants`, global switch `mzlab.contaminants.on` (Settings, on if it was never turned off; the checkbox reads localStorage directly).
  Lab contaminants are not in Settings: only the `labcont` command of the search opens them (Ctrl/⌘ K, "contaminanti" / "contaminants").
  Lists panel: with ONE list only, no per-list checkbox, just a fixed title with its source, always active (`activeMap()` ignores the choice saved in `mzlab.lists.active`); with two or more (the two built-in ones, plus user lists) there are the "Active lists" checkboxes. The structure is an array (`ST.lists` + `ST.userLists`): a new built-in list is added to `/api/contaminants` and the selector appears by itself (only with a compatible licence and without real compound names in the repository).
  "Remove contaminants" stays in the HR spectrum menu (`LISTE.keller`). Tests `e2e_contaminanti`, `e2e28`, `tests/test_liste.py`.
- **Provenance of exported tables** (`provenienza.js` = `PROV`; schema `provenance/1` written by the engine: `mzlab-core/src/provenance.rs`, route `api/provenance`): CSV/TSV (`dl(name, text, type, {table, ...})`), copied tables (`PROV.tsv(text, {...})`) and .xlsx (`dlx(name, sheets, {table, p, ...})`, last sheet "Provenance"; `dlc(name, sheets)` = CSV of the first sheet, with BOM) carry version, file, background/SNIP, smoothing, tolerance and date. With `false` as last argument the file stays as it was (mzFinder: files for mzmine, GNPS). A new export passes `{table: "..."}`.
- **Header of an exported MS2/MSn spectrum**: `ofScan` in `provenienza.js` adds precursor, charge, activation, CE, RT, scan and polarity (only the known fields); copy, CSV and .xlsx all go through `PROV.ctx`.
  CSV/TSV: first line `# mzLab x.y.z · file=… · …`; pandas skips it with `comment="#"`, Excel shows it as row 1 (delete it, or Data -> From Text/CSV and start from row 2); the imports of `liste.js` and `samples.js` ignore `#` lines. Tests: `tests/test_provenienza.py` (list of the exports covered), `tests_e2e/e2e_provenienza.py` (real files).
- **Workflow and exports** (`workflow.js`): no entry in the interface (`WORKFLOW.export/open/applyWorkflow` stay in the code without an entry): format `.mzflow` (`mzflow/1`, with SHA-256 check of the files; it also opens the legacy `.mzworkflow`/`mzworkflow/1`, and ignores unknown operations with a warning); the study report in HTML is in the bar/palette ("report" command); MGF and MSP export from the menu of an MS2 spectrum (in LR without names or annotations).
- **QA/QC** (`qaqc.js`, `QAQC`; `mzlab/qaqc.py`, `/api/qaqc`; tests `tests/test_qaqc.py`, `e2e_qaqc`): "QA/QC" panel of the side panel, `qaqc` command of the single list (field `feature: "qaqc"`), the same in LR and HR.
- **QA/QC is DORMANT, code kept**: the single switch `FEATURES.qaqc` (`features.js`, off by default; it turns on only with `?qaqc=1` or localStorage `qqq.dev.qaqc`=`1`, never from the interface, `?qaqc=0` binds it again) hides button, "More" entry, palette command, `#sb-panel-qaqc` (removed from the DOM), the "Normalise on" menu of the Time profile and section 4 of the report; the QC/dark roles (`QAQC.setRole`), the file type and `parametri.qaqc` of the `.mzflow` (read and kept if present) stay active;
  tests turn it on with `Run.page(p, qaqc=True)`, `e2e_qaqc_dormiente` tests the off state.
  Type of each file (sample, blank, QC, standard, dark) from the name (`project.py` + QC/dark words) corrected by hand; control ions chosen by the student (m/z or formula, expected RT, ± RT): for each file RT, ΔRT, area, area/median of the files that are neither blank nor dark, in HR Δppm and mass accuracy (mean, maximum); ΔRT and relative area plots along the file order (different shapes per type), area CV, RT drift per file.
  Sample/blank ratio of an ion (3:1 or 10:1, blank = mean area of the blanks) and, in HR, of all features of the open mzFinder table (`/api/stat/reference` with the blanks as reference; values, no TP list). In LR only the chosen standards and the blanks (no list of sample ions). State in `mzlab.qaqc` and in the workflow file (`parametri.qaqc`; `candidati` = annotated confidence levels).
- **Statistics** (`stat.js`, `STAT`; command `stat` (`search: true`: hidden from the bar, from "More" and from menus, found ONLY by searching in the Ctrl/⌘K search/palette by name and it/en synonyms: statistica, PCA, blank, time profile...), panel `#sb-panel-stat`; tests `e2e_statistica`): a side panel made of sections (`STAT.add({id, title, hr, visible, mount})`, one `<details>` each, in LR and in HR unless `hr: true`).
- **Sample metadata** (`samples.js` model and `apply`, `samples-table.js` table, `samples-doc.js` document `samples/1`; `SAMPLES`, `SAMPLES_DOC`; pure TSV, replicates and time-scale functions tested with node by `tests/test_samples.py`): one row per file with role (sample, blank, dark, infusion, standard, QC; t0 is the sample at time 0), time (unit in the header; saved in minutes, negative for dark, proposed in yellow until confirmed: Enter confirms it), concentration with unit and replicate; prefilled on load, editable.
- **Fields of the Statistics panel**: every `input` (except the file one) and every `select` of `#sb-panel-stat` (sample table, profile) is at least 24 px tall (`app.css`, WCAG 2.5.8); the matrix `e2e_matrice_bug.py` measures all visible fields, because axe lets them pass when rows are few (spacing exception).
  The workspace sample table (`renderFiles`) writes to the same files just opened: a student edit = `samplesEdit` (one undoable step), a late proposal = `SAMPLES.apply(…, true)` silently (`OPENNOW.edit`/`sync`, `data-loading.md`).
  `SAMPLES.apply` is the only writer of `f.role`, `f.type` (base type), `f.time`, `f.tconf` (confirmed time), `f.conc`, `f.cunit`, `f.rep`: it notifies the server (`/api/meta`, which also keeps `role`, `tconf` in the element) and the notebook, and sends the `samples` event. `QAQC.roleOf` reads `f.role` (`mzlab.qaqc.roles` is not written).
  The notebook keeps `NB.session` in `samples/1` format (one entry per file, plus `rep`; `NB_V` 2); a notebook of another shape is not migrated. The `.mzflow` carries `role` in the files and `samples` in the operations (canonical entries and SHA-256 from Rust, `source: "data"`); an old `.mzflow` keeps only its own entries.
  TSV export/import with the mzmine columns `filename`, `sample_type`, `time`, `time_unit`, `concentration`, `concentration_unit`, `replicate`, then `time_confirmed` (an export with `blank_type` or `t0` still imports: the column is ignored, `t0` is a sample at 0).
  Colours: the viridis gradient by time is the one of `paintFiles`; the gradient bar (`SAMPLES.gradientLegend`) is in the Samples panel, in PCA and in the profile, not in the chromatogram legend (file names in a column). HR-only sections (`hr: true`): feature table, blank, "Difference from the reference" (`riferimento.js`, `RIFERIMENTO`; details in `high-resolution.md`) and PCA.
- **Time profile** (`profilo.js`, `PROFILO`; `mzlab/statistica.py` `time_profile`, `/api/stat/profile`; tests `tests/test_statistica.py`, `e2e_statistica`): section "Time profile of an ion" of Statistics, in LR and in HR. The ion (m/z or formula) and the peak RT are chosen by the student; for each file of the order `XIC → autoEdges → integ` (the same integration as `picchi.js`) it gives RT, area and height; Python sorts by time (files without time at the end, not joined by the line), divides by the internal standard and says which points are joined.
- **Profile, error**: an error (input or engine) removes the previous result (`fail` in `profilo.js`): the plot of another ion does not stay next to the message.
  SVG plot (points with the file colour, diamond for QCs, line joining them), table below, "Copy" (TSV) and Excel. LR: only raw values of an m/z typed by the student, no normalisation, no curve, no list of ions. HR: "Normalise on" menu with the internal standards defined in QA/QC (ratio between the value and the standard's value in the same file). `PROFILO.show(mz, rt)` fills, opens and measures. A result measured on another set of files (one removed or added) is no longer shown: it is measured again (`e2e_matrice_bug`).
  A table without controls in the rows (Profile; in QA/QC ratio and features) is in a `.qq-scroll` with `tabindex=0`, `role=region` and name from the summary above (`aria-labelledby`): the keyboard reaches it and scrolls it with the arrows (`scroll.js` does not take them inside a `.qq-scroll`).
- **Study report** (`rapporto.js`, `RAPPORTO`; buttons in the QA/QC panel and `report` command): printable HTML and JSON (`mzreport/1`) built in the browser from the workflow file (version and commit, SHA-256 of the files = those of the workflow, parameters, operations), from `/api/fileinfo` (instrument, analysers, software, start: only what the mzML says) and from the QA/QC measures;
  sections in the order of the NORMAN guide: 1 study design, 2 acquisition, 3 processing, 4 QA/QC (only with `FEATURES.qaqc`; off, the confidence levels are section 4 and the JSON has no `qaqc`), 5 (HR only) Schymanski confidence levels of the candidates with the evidence (`RAPPORTO.note`, called by `libreria.js` at every evaluation). No data leaves the computer.
- **Correction and reference** (menu "Correct.", command `subref`, `sottrazione.js` ES module, `SUBREF`; computation in `mzlab/differenza.py`, tests `tests/test_differenza.py`, `e2e_sottrazione`):
  Chromatogram, XIC and MRM have ONE "Subtraction" button (`corrWidget` with `grp`, `data-o=corr`) and a menu with two `fieldset.corrg` groups with `legend`, each with its own state: "From a file" (`data-g=0`: none | file X, writes `p.bk`, `setSub`; off on MRM with the reason) and "From the background" (`data-g=1`: none | segment | flat window | automatic, `p.fondo = {mode: none|auto|tract, w, ib}`, `setFondo`).
  `FONDO.migra` also reads the `snip/snipw/ibk` fields of saved notebooks; fixed order in `corrected()`: raw traces → difference in the engine (`clip=0`, never cut) → ONE background on the difference (`fondo.js`, pure functions tested in `tests/fondo_node.js`).
  Button icon: at rest `CIC.msub` (peak with "−"), never the ⊘ of "None"; with a single subtraction active it takes the icon of the chosen entry, with two it goes back to `CIC.msub`; active = class `.on` (accent border and background); tooltip and `aria-label` "Subtraction: − file · Automatic background" name what is on. Off on MS2.
  Summary of the corrections: no fixed bar; ONE icon `data-o="cinfo"` (`corrInfo`/`corrInfoWire` in `pannelli.js`, `CIC.sub`) in the command bar of chromatogram, XIC, MRM, spectrum and map (on the phone it ends up in "⋯" like the other commands). It opens the `.corrbar` popover of the panel (absolute, hidden; it holds notes, `.subchip` chips of the subtraction and `.ibk` chips of the segment background); it closes with Esc or a click outside. The `.cidot` dot and the `.act` class follow `corrActive(p)`; a `MutationObserver` on the popover keeps the icon aligned.
  The automatic background is SNIP raised on the noise mean (0 = mean background level, like the segment); "negatives to 0" (`p.clipDraw`, or "clip to zero" of the reference) changes only the drawing (`s.ys`): areas, heights and S/N use `s.y`. The "Background" menu is also active on MRM.
  With a background active: axis title "Intensity − background" / "Sample − blank" / "Sample − blank − background" (`yTitleI`); zero line always dashed with the label "background" (`zeroMarks`); chip under the plot (`ibkChip`: min–max cps of the automatic background, or segment); mouse box with the small raw value (`s.yraw`); "Correction" column (`it.corr`) in table and Excel.
  Initial zone (solvent front): `p.fondo.zd` minutes from the first scan (default `FONDO.ZD` = 0.5; box and "detect" = `FONDO.front` in the chip), grey band, excluded from `ymax`/`ymin` (`traceMax`) and from SNIP.
  Automatic spectrum background (`fondo-spettro.js`, `FONDOSP`; tests `tests/fondo_node.js`, `e2e_fondo_spettro`): with "segment background" and `p.bw0`/`p.bw1` empty the segment is chosen from the TIC of each file (`regioni`: outside the initial waste `waste`, front `FONDO.front` (at least `FONDO.ZD`) and margin; windows of ~6 % of the run sorted by "mean + 2 SD", up to 3 non-overlapping).
  "Flat window" background of the chromatogram (`fondo-piatto.js`, `FONDOP`; test `e2e_fondo_piatto`): it is a `tract` with `ib = {mode:"median", a, flat:true, mod?}`; `corrected()` asks Rust (`chrom_background::flat_window` → wasm `flat_window` → `QUALITA.flatWindow`) for the lowest and most stable window after the initial zone, until `mod` is set; you move it with a handle on the plot, ◀ ▶ (arrows, Shift = 5 steps) or the menu; `mod` → "modified by you" and "restore automatic".
  The segment in use is in the legend and in the box placeholders; the menu `data-o=bwi` (`p.bwi`) chooses another one; typing the two ends wins and ↺ (`data-o=bwauto`) appears to go back to automatic.
  The menu (`corrWidget`/`corrWire` in `pannelli.js`; on the spectrum and on the map it is a single menu; the spectrum has no baseline: 3 entries, "segment background" = `p.bg="w"` with the two ends in the header, file = `p.bg=k`) has 4 entries (none | a single row "Subtract file:" + file selector + ✓ at the end if active (aria-label "Subtract file: X") | segment background | SNIP baseline, each with a one-line hint; arrows/Enter/Esc, `aria-pressed`):
  the proposed file is `p.bk` if present, otherwise the session reference `S.ref.k` (or `auto`), with a single file the entry is disabled with the reason; choosing from the selector writes `p.bk` (the panel's choice wins over `S.ref`) and the chip in the summary declares it. The `subref` command (Ctrl/⌘K palette) turns on the sample − reference difference on ALL panels of the tab (TIC/XIC/MRM, spectrum, map); state `S.ref = {on:{tab:bool}, k:"auto"|file, factor, norm: none|tic|istd, istd, rttol, clip}` in the notebook (`NB.ui.ref`, the file by name).
  `auto` = the t0 file of the tab (the sample at time 0, the first), otherwise the only blank, otherwise the first by time (never the dark, which has negative time); the chip in the summary always writes it ("− file (auto) × f · normalisation ▾": popover with file, factor slider 0-2 in steps of 0.05, normalisation chosen by the student (none, TIC, internal standard = m/z typed by them), RT tolerance, "clip to zero" off by default, ◀ ▶ that scroll through the files keeping the reference, × back to raw). A panel's own choice (`p.bk`, `p.bg`, `p.ref`) wins over the session one.
  Traces: `corrected()` calls `/api/xic|chrom|mrm` with `ref, factor, norm, istd, rttol, clip` (reference = local maximum over ±rttol, outside its time range no point; negatives stay, axis and zero line); first the difference, then the background (segment or SNIP).
  Spectrum: `/api/spectrum` with `bgk, bgrt0, bgrt1, bgf, bgtol, bgclip` (LR same nominal mass, HR ±ppm), same time window as the sample, only the factor (no normalisation); with a reference the spectrum is mirrored (`d.diff`, always lines): above `--diff-pos` (orange, more intense in the sample), below `--diff-neg` (blue, more intense in the reference), zero line, words "rises/falls" on the axis and in the hint with the sign; the "background" menu starts from the session reference (`p.bg = "x"` = none in this panel).
  The integration table and Excel say "area on the trace minus {file} × {f}".

- **Merge of centroids by nominal mass** (`/api/spectrum`, `/api/spectra`, `/api/scanbin`; `spectrum.rs`, `hrscans.rs`; Python `App.spectrum`): no setting.
  `merge` omitted = AUTO: unit-resolution centroid files are merged per nominal mass, profile and HR files never (they ignore the flag).

  No Flow step or CLI option consumes the flag yet (add one with its run-log line if a consumer appears). Tests: `tests/test_peaks.py`, `spectrum::tests`.
