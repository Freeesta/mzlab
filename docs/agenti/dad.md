# DAD (UV/Vis detector) in the 3200 `.wiff` files

Reading the DAD matrix of `.wiff` files (feature `mappa-dad`), its routes and interface: RT-λ map, UV spectrum, TWC (total trace), XWC (single-band trace), integration, MRM panel. On-screen names: DAD, TWC, XWC; stored keys and values stay `pda`. Other SCIEX variants: `wiff-variants.md`.

- `Devices/Device_N/DAD/{DADSampleHeader, DADIdx, DADRealTimeData}` (only in lab files with the detector): decoded in `crates/mzlab-core/src/wiff/dad.rs` (`struct DadData`, `read_dad`).
  - Byte layout: standard 32-byte OLE header offset (`+0..+32`); in `DADSampleHeader` (86 bytes total) there are `n_points` at `+34` (`u32`, N_t), `n_channels` at `+38` (`u32`, N_λ), duration at `+46` (`f32`, min), start wavelength `wl_start_nm` at `+50` (`f32`, nm), end `wl_stop_nm` at `+54` (`f32`, nm) and step `wl_step_nm` at `+58` (`f32`, nm, e.g. 200–400 nm, step 1.0, 201 channels).
  - In `DADIdx` (32 + 8 × N_t bytes read): after the 32-byte header, each 8-byte record carries the retention time at `+32 + 8*i` (`f32`, min) and the pre-summed TWC (Total Wavelength Chromatogram) absorbance at `+36 + 8*i` (`f32`, mAU).
  - In `DADRealTimeData` (32 + 4 × N_t × N_λ bytes read): after the 32-byte header, it holds the 2D absorbance matrix in mAU stored row by row (row-major order: row i = time t_i, column j = channel λ_j, 32-bit little-endian IEEE-754 `f32` values).
  - What it returns: a 2D time × wavelength matrix in mAU (`DadData.matrix_mau`, with `spectrum_at(t_idx)`), the TWC total chromatogram (`dad.twc_chromatogram` / ID `"DAD TWC"`, type `ChromKind::Pda`, unit `"mAU"` in `cromatogrammi(c)` and in the mzML userParam `unità`; last in the list, same index in `Wiff::visit` and `WiffReader` (`chromatograms_of`)) and a single-wavelength chromatogram with optional band (`dad.wavelength_chromatogram` / ID `"DAD <nm> nm"`, e.g. `"DAD 254 nm"`, `"DAD 254.1 nm"`).
  - TWC trace of an mzML: with `<chromatogram id="TWC">` (`MS:1000813`, ProteoWizard) it fills `twc_mau` when it has one point per matrix row (`mzml_dad::twc_trace`).
  - 2D map: `dad_to_map_json` (`wiff/dad_map.rs`, base64 little-endian `f32`) answers `/api/map?kind=pda` (`itemroutes::pda_map` → `dad_map` of the `Lettore` trait) in the wasm engine and in the native app: it sits behind the `mappa-dad` feature of `mzlab-core` (default; `mzlab-wasm` turns it on), which the `sciex` module leaves off to stay under its size cap.
  - 2D map, reduction: beyond `MAP_MAX_RT` × `MAP_MAX_NM` (2000 × 500) the matrix is averaged over blocks of consecutive rows/channels (`reduce`, `agg:"mean"`, `dmz` = step × block; `agg:"none"` if sent as is). The engine reads the 3200 `.wiff` directly, so the matrix is there; a `.wiff` passed through the `sciex` module (a variant, e.g. blocks all of version 1) is converted with the matrix, which the engine re-reads from the mzML.
  - Matrix in the mzML: `convert.mzml` with `dad` (off by default in the CLI and the app, bytes unchanged; always on in the module's `to_mzml`, same as `--set conv.dad=true`; `dad_dati` and `uv_spettri` exist in the wasm only with the `sciex` feature, the engine goes without): the matrix is written as `MS:1000804` profile spectra with no MS level (one per instant, `wavelength array` in nm, 32-bit mAU; `mzmlwrite/uv.rs`, `Lettore::dad_data`) which `mzml_dad` reads back, and `/api/map?kind=pda`, `/api/uvspec`, `/api/uvxic` answer the same JSON as the `.wiff` (test `mzml_dad_tests`).
  - Matrix in the mzML, read once: `Mzml::dad_memo` keeps the matrix read per file (fingerprint = size + 3 samples of 64 KiB, up to 16 matrices and 64 M values, also the "no matrix" outcome): a click or a new λ slices it in memory. `dad_spectra` reads in 4 MB steps and consumes all spectra of each step (each byte read about once). Timings: `tools/bench_uv.py` (synthetic `tools/dati_sintetici_uv.py`): 3 files of 24.5 MB, first double click 0.9 s, the following ones 10 ms, λ trace 0.15-0.2 s.
  - Decode cost: the walk keeps one inflater for the whole file, decodes the wavelength axis once (later rows with the same text are compared, not decoded) and decodes the absorbance straight to f32 (`Want::F32`): 162 MB mzML (30000 x 401), cold `api/map?kind=pda` in the site 4059 -> 3116 ms. The `lr_pda_map` op itself is 865 ms (173 ms in the readers); the rest of the cold 3.2 s is the open pipeline of the same worker (`lr_put`, `lr_index`, `canali`, `lr_metodo`, ...) reading the file about 9 times (1.5 GB, 2.1 s in the readers): the cost of a UV-heavy file is there, not in the map.
  - Layout pass: `lr_entry`, `lr_items` and `canali` used to scan the chromatogram tail and read the PDA/analog traces each (`facts_from`).
    They now share one `Layout` per file (`mzlab-core/src/layout.rs`, held in `Index`, found again by the sha256 of the file so the slot of a panel next to the one of the list reuses it), so the tail is read once (`tests/open_layout.rs`: 31.2 MB -> 7.2 MB on a 14 MB synthetic TWC file).
    Whole open in the site (`tools/bench_open.py`, 174 MB synthetic DAD, OPFS): 7.64 -> 3.02 passes, 1328 -> 524 MB, 508 -> 298 reads, 1628 -> 400 ms in the readers.
    Same answers byte for byte; a rebuilt index starts with an empty layout.
  - Matrix in the mzML, size: `dad` stays off by default because the file grows a lot: the 3200 DAD (191 wavelengths, 210-400 nm, 0.24 s) adds ~12 MB over 20 min (about 2.4 kB per spectrum, 3 times the 3.8 MB raw: incompressible noise and mzML headers), `size_of_a_real_sized_matrix`; it is the OPFS cost of every sample of a variant with the DAD.
  - Matrix tests: `e2e_mappa_pda_wiff.py`, `crates/mzlab-lettori/tests/sciex_dad_method.rs` and `tests/test_lettori_parita.py` (synthetic pair `dadmetodo` from `tools/wiff_riferimento.py`: 3200 QTRAP, V1 blocks, DAD on `Device_1`, `VendorAppMethod`).
  - UV spectrum: `dad_spectrum_json` (`wiff/dad_uv.rs`, same `mappa-dad` feature) averages the DAD rows between `rt0` and `rt1` (the nearest row if none falls inside) and answers `/api/uvspec?k=&rt0=&rt1=` (`itemroutes::pda_spectrum`, trait `Lettore::dad_spectrum`; `err.pda.none` without a matrix).
  - UV spectrum UI: a double click on the DAD map (`mappa.js` `spectrumAt`) or on the DAD trace (action `chrom.uvAtRt`, `eventi.js`) opens a `spec` panel with `uv: true` (`uv-spettro.js`: nm against mAU, `TDATI` table, keyboard zoom; linked (`p.link`) to the DAD chromatogram, with "Follow"/"Fixed"; `sliceUv` slices the `getMap(k,"pda")` matrix in memory, `api/uvspec` only for a file without a matrix); without a matrix (Thermo `UV_VIS_n`, Agilent) a `uv.none` message and no panel. Tests: `tests_e2e/e2e_uv_spettro.py` (`.wiff`), `e2e_uv_overlay.py` (mzML of the `sciex` module).
  - UV spectrum, several samples: one trace for each DAD sample shown in the source chromatogram (`p.ks`, per-sample legend, one mAU column per sample in the table and export); from a single-λ trace the spectrum is whole with that λ marked (`p.wl`); a double click on the spectrum opens the trace at that λ (`uv.wlAt`).
  - Wavelength (λ) trace: `/api/chrom?kind=pda&mz0=&mz1=` (nm) is the mean of the DAD channels in the interval (`wiff/dad_uv.rs` `dad_wavelength_json`, `Lettore::dad_wavelength`, op `lr_pda_wavelength`); it is a `chrom` panel `kind=pda` with `mz0/mz1` in nm (`wlOpen`/`wlCtl` in `eventi.js`, `openWl` in `uv-spettro.js`), extra bands in `p.xw` (`panel.source`, one series `c|k|pda|nm0-nm1` each). On the DAD trace the XIC button becomes "XWC", `chrom.wl` replaces `chrom.xic` in the right-click menu and `mapxic` on the DAD map extracts the λ of the crosshair.
  - Proposed XWC band: `dad_propose_json` (`wiff/dad_uv.rs`) takes the highest TWC peak (or the `rt0..rt1` window), removes the background spectrum (median of the rows at the two ends of the run) and gives the λmax, skipping the lowest 10 nm if something else absorbs, band 4 nm: `{nm, bw, rt, n}` on `/api/uvpropose` (`itemroutes::pda_propose`, op `lr_pda_propose`, `mzlab-cli channels --channel uv:auto`).
  - XWC UI in `xwc.js` (lazy module): split "XWC" button on the TWC and on the UV spectrum (click = proposed band, Shift = extra trace, arrow = λ and band popover, Enter/Esc), hidden without a matrix. Tests: `dad_uv.rs`, `channels_tests.rs`, `mzlab-desktop/tests/dad.rs`, `tests_e2e/e2e_xwc.py`.
  - Integration: an XWC (`kind=pda` with `mz0`) is integrated like an XIC (`picchi.js` `canInt`); area in mAU·s (unit chosen by the engine for the Manual integrations card and its exports); on the TWC `guardInt` asks `int.guard.uv` and "yes" opens the proposed XWC (`xwc.js` `press`); TIC/BPC stay on `int.guard`. On-screen names: DAD (detector), TWC (total trace), XWC (single-band trace), y axis and export "Absorbance (mAU)", trace, caption and file name of TWC/XWC (`kindUp` in `legende.js`); stored keys and values (`pda`) unchanged. Test: `tests_e2e/e2e_dad_integra.py`.
  - MRM panel with DAD (`dad-mrm.js`, lazy module loaded by `sim-ui.js` `mark`): menu and double click open the UV spectrum at that time (`mrm.uvAtRt`), the "TWC" checkbox (`p.overlay = "twc"`) draws the TWC on the right axis like the pressure (wrapping the hooks of `GRADIENTE`) with the TWC column in `TDATI`, "Align" shifts the spectrum by the DAD → MS delay. Test: `tests_e2e/e2e_dad_mrm_overlay.py`.
  - λ trace of a file without scans (MRM, SIM): `rust-bridge-info.js` sends to `mrmchrom` (`itemroutes::mrm_chrom`, mzML chromatograms) every `kind` except `pda`: `pda` (with or without nm) returns `null` and is served by `lr-method.js` (`lr_pda`, `lr_pda_wavelength`), so the band does not become the TWC. Tests: `tests_e2e/e2e_dad_mrm.py` and `crates/mzlab-desktop/tests/dad.rs` on the synthetic pairs `dadmrm`/`dadsim` of `tools/wiff_dad_mrm.py` (bands at 274 and 230 nm).
  - λ from the UV spectrum: `uv.wlAt` (right-click menu) traces the λ under the pointer and `uv.wlView` (X key, active with zoom) traces the nm interval in view: the interval is chosen with keyboard zoom or from the axis, without dragging. Opening the UV spectrum or the λ trace is `panel.open` and changing its nm interval is `panel.source` (registry `comandi.js`): Ctrl+Z/Ctrl+Y undo and redo them. Test: `e2e_uv_spettro`.
  - Validation and warnings: decoded, not validated (the values are not yet compared with a numeric export from SCIEX OS). No `meta.nonDecodificato` warning is emitted in the code for the DAD (neither in `method_wiff.rs` nor in `wiff/`).
- Subtraction of two DAD matrices (`wiff/dad_ops.rs`, `dad_subtract`; routes in `itemroutes.rs`: `pda_dad`, `pda_sub_args`, `pda_subtract`, `pda_subtract_data`): A minus `scale` times B on the grid of A. B is interpolated linearly in time (read at `t - shift`) and in wavelength; rows and columns of A that B does not cover (more than half a B step outside) are dropped; no overlap is `err.pda.nooverlap`. `scale` is `none` (default), `max`, `tic`, `fit` (least squares on the overlap) or a number.
The answer is the plain JSON of the view (`map`, `spectrum`, `trace`) plus `sub`: `a_rt`, `b_rt`, `a_nm`, `b_nm`, the median steps, `rows` and `cols` as [kept, total], `shift_min`, `scale`, `factor`, `interp_rt`, `interp_nm` and `warnings` (`rt_range_partial`, `nm_range_partial`, `rt_interpolated`, `nm_interpolated`, `rt_step_differs`, `nm_step_differs`, `shift_applied`, `scale_applied`). Equal grids subtract exactly and carry no warning.
  - Seams: site and app share the op `lr_pda_sub` (`name`, `ref`, `view`, `a`, `b`, `scale`, `shift`): wasm `item_pda_sub`, desktop `rpc_lr.rs`, page `lr-method.js` `/api/pdasub` (`k`, `ref` = k of the other item). The matrix of a native sample comes from the reader's `dad_data` (not gated out of the engine wasm), an mzML from `dad_memo`.
  - CLI for agents: `mzlab-cli dad subtract A B [--view report|map|spectrum|trace]`, `dad spectrum FILE --rt`, `dad trace FILE --nm` (both with `--minus B`), `dad ms-at FILE --rt T --offset M` (MS1 spectrum and TIC at the UV time plus the signed offset, `ms_file` names the file used), `dad delay FILE` (the estimate of `/api/delay` with its `peaks` and `corr`, never applied). Always JSON on stdout; exit 0 done, 1 data error, 2 usage; `--json` adds `error/1` on stdout. Tests: `dad_ops_tests.rs`, `dad_tests.rs` (CLI), `mzlab-desktop/tests/dad.rs` (the app op equals the core route).
  - Card (`grafici.js` `drawMap`, `mappa-dad.js`; controls in `pannelli.js`): on a DAD map the file chosen in «Correction» (or the session reference) is subtracted with `/api/pdasub` (`getPdaSub`); the map is the answer, drawn with the difference palette, and the legend and the summary carry a visible note (kept ranges, rows and wavelengths kept of the total, scale, shift, one line per warning code, keys `map.sub.*`). Options in the map options: normalization none (default) | max | tic | fit, a typed factor `subFactor` (wins over it), a shift `subShift` (min).
  - Card failures: a failed subtraction (no overlap, reference without DAD) writes the reason on the map (`map.sub.fail`) and draws the plain map: never a silent no-op. Test `tests_e2e/e2e_mappa_pda_sub.py`.
  - Strips of the map (`mappa.js` `show`, `drawSide`, `drawBottom`): on a DAD map (plain or subtracted) the right strip is the UV spectrum at the cursor time and the bottom strip the UV trace at the cursor wavelength, both read from the page matrix (`a.mat`, the subtracted matrix on a difference; a block-averaged matrix above 2000 × 500 cells) with titles `mappa.uv.*`; the MS routes (`scan_axis`, `spectra`, `xic`) are never asked. Test `tests_e2e/e2e_mappa_pda_strips.py`.
  - Linked MS (`mappa-dad-ms.js`, `p.stripMs = "ms"`): the strips switch to the MS1 scan nearest to the cursor RT plus the signed DAD→MS offset (`p.msOffset`, minutes; default 0 because no reader exposes one) and the TIC / BPC / EIC (`p.msTrace`, `p.msMz`) of the same file drawn on the DAD time axis. A subtracted map uses the first file's MS, or the reference's with `p.msFrom = "b"`.
  - Offset estimate: the popover Estimate button asks `/api/delay` (cross-correlation of the DAD total trace and the TIC) and shows delay, peaks and correlation; nothing is applied until Use estimate, which sets the offset and writes the choice in the popover (`p._msLog`). Offset, trace and file choices are not saved with the session. Test: `e2e_mappa_pda_ms`.
  - 3D (`mappa3d.js` `open` / `load`, `mappa-dad.js` `grid`): opened from a DAD map the viewer (`V.pda`) shows the DAD matrix of the map (or A − B for the reference chosen in the viewer), cut to the window of the viewer on the bins, axes and read-out in nm, no high-resolution mode and no sticks; it never asks the MS map (the old cause: it requested `api/map&level=` with nm numbers read as m/z, or failed on a DAD-only file). Without WebGL2 the viewer's technical box explains it, as before. Test `tests_e2e/e2e_mappa_pda_3d.py`.
