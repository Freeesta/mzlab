# interp: per-row interpretation of the products (`interp/1`, `filtri/1`)

- **What it is** (`crates/mzlab-feat/src/interp/`, feature `interp`, schemas `docs/schemi/interp-1.json` and `filtri-1.json`): for each row of the feature table that `tp/1` declares a product or formed-unexplained (and that F1-F4 do not hide) it gives the modification relative to the parent, all the DDA MS2 of the series with the purity, the comparison with the parent's MS2 and with the infusion's MSn tree. It does not decide identity and does not delete rows: a hidden row keeps its id and the reason. Texts in English only (Tabui).
- **Block in the `.mzfeat`** (`store.rs::append`): meta `interp` (version, parent, parameters, calibration per file, `msnlib` = nodes and entries of the library, `filtri`) plus three arrays: `interp_id` (u32, sorted), `interp_off` (u32, n+1) and `interp` (u8, one uncompressed JSON per row). `append` rewrites the container replacing a previous block; a table without a block reads as before. `read_meta` and `read_row(id)` read by offset.
- **Entry** (`run.rs::run_to`): reads the `.mzfeat` by offset, the parent (`finder_base::series::parent`) and the `hypotheses/2` registry, calls `build` and writes the `.mzfeat` with the block to a sink. The `interp` `.wasm`, the native engine and the tests use it, so they write the same bytes.
- **Pass** (`build.rs::build`): file by file (the infusion never among the series MS2) reads the MS2 scans of the rows and of the parent, the MS1 at the apex and, once, the infusion library (`finder_base::msn::build_tree` + `library::build`, with the parent's DDA MS2); calibrates each file; interprets each row. Without a `tp/1` block it gives `error.interp.noTp`.
- **Modification** (`edit.rs`): `candidates` = hypotheses of `hypotheses/2` within 5 ppm of the row's m/z, the closest is `change`, the others `alternatives`; `label` writes the Δ with the true minus (U+2212) and gains first (`+O`, `−2H`, `+O−2H`, `+3C`). `iso_check` compares the observed M+1 and M+2 with those of the formula and says whether the sulfur count is consistent (`s_count`). Without a matching hypothesis `change` is `null`.
- **Linked MS2** (`ms2link.rs`): `pick_scans` (`_in`: one `Ms2Sorted` per file)/`fill_purity` give for each scan file, scan, RT, precursor, window, CE and scan range (`parse_filter` if the index does not have them); purity = precursor (±5 ppm) over total in the window, MS1 before and after interpolated at the time (`interpolate`); `chimeric` below 0.8, excluded from the consensus. `separate`: two groups of scans whose traces of the 5 most intense fragments have Pearson < 0.5 between the groups (at least 4 clean scans) are `separated`, each with its own consensus; fewer than 4 is `single`.
- **Comparison** (`comparison.rs`): `against_dda` = modified cosine, entropy, equal fragments, fragments shifted by the Δ and losses against the parent's DDA consensus; `by_formula` = equal or shifted fragments by formula mass against the infusion library (never intensities: CID against stepped HCD). `reference` says which reference there was (`dda`, `infusion`, `both`).
- **Tree** (`tree.rs`): for each node of the parent's tree the state `same`, `shifted` (at m/z + Δ), `absent` or `not_checkable` (node and node + Δ outside the MS2 scan range or above the precursor). Without infusion `tree` is `null`.
- **Filters** (`filters.rs`, `filtri/1`): F1 peak quality, F2 same molecule (not first of an isotope group), F3 formed by the treatment, F4 not an in-source fragment (the first four from the `tp/1` state), F5 mass error against the file calibration (`calibrate`: tolerance max(3, 2 MAD) ppm, at most 5). The first one that hides the row wins; the registry counts and lists the hidden ids.
- **Decoys** (`filters.rs`): `decoys` = `{rules, survived}`: the decoys are the m/z of the registry rules + 0.0137 Da × k (k = 1..5), discarded if within 10 ppm of a true rule; `survived` counts the decoys matching (10 ppm) a row that passes F1-F5 (`filtri::table_decoys`); `null` if the registry has no rules.
- **Position** (`site.rs`, `site` of the row): the sites come from `chem::positions::sites` (transformation derived from the formula difference: `+O`, `-CH2`, `-2H`, `+O-2H`, `+Cl-H`, `+Br-H`, `+2O`, `+2O-2H`, `+3O`, `-C2H4`, `-Cl+OH`, `NH2>OH` (`+2O-2H` also includes `CH3>COOH`); otherwise `multiple_changes` if O ≥ 2, `unsupported_change`). For `+2O`, `+2O-2H` and `+3O` (sets of atoms) the tree is not used (`masks` gives `None`, `source: "cuts"`) and the confidence is never `site`.
  The votes come from `finder_base::msn::localize::localize_sites` with the infusion tree (positive polarity, ≤ 64 atoms, same graph as the parent; `source: "tree"`) and otherwise from the cuts of `match_spectrum` (`source: "cuts"`, 10 ppm); the support of a class is the softmax of the likelihood among the classes not excluded (an order, not a probability). Constants with the why at the top of the file: `MARGIN` 2, `MIN_INFORMATIVE` 3, `MIN_REL` 5 %, `INFO_PPM` 5, `LL_SUPPORT`/`LL_AGAINST`.
- **Confidence**: `site` only with a single class inside the margin, `supported`, no fragment against, all atoms of the class equivalent by symmetry and a unique isomer; `region` if the classes inside the margin are in a single group (`ring A`, `chain A`, names of `default_groups_en`); `uncertain` if in different groups; `cannot_say` with the `reasons` `no_ms2`, `chimeric`, `isomers_not_separated`, `no_reference`, `few_fragments`, `change_lost`, `multiple_changes`, `unsupported_change`.
  `proposal.sublevel` is that of `posiz/1` (3a only with one class excluded and at most 3 left), 3b with `cannot_say`. The Fukui `prior` never enters.
- **From the `mol/1` record** (feature `record`, in no `.wasm`): `sito::candidates_record` and `drawing::drawing_record` do the same with a record instead of the SMILES (graph `Mol::from_record(rec, true)`); the SMILES stays as text from which the groups and rings are read (`fragtree::Graph`). Parity test: `tests/interp_record.rs`.
- **Drawing from a `site`** (`redraw.rs`, `drawing_of_site`): rereads the `site` JSON of a `sites/1` row and draws it with `drawing::drawing`; used by `render_text` (`structure.render` of mzFlow: `flow run` and `flow_render` of the `interp` `.wasm`).
- **Drawing** (`drawing.rs`, `drawing`): a single shape per row: `structure` only with `site` (atom `added` on the outer bisector, for `-CH2` and `-C2H4` the `lost` atoms; `fallback: "bracket"`, and `Drawing::without_molfile` makes it `bracket` when the page has no molfile), `multicenter` if all aromatic candidates are in one ring (`ends`), `bracket` on the group for the other regions and on the whole parent for `uncertain` and `cannot_say`; `delta` and `label` with the true minus U+2212 and `uncertainty` `none|zone|whole`.
  In the `structure` of `-2H` and of the substitutions `-Cl+OH`, `NH2>OH`, `CH3>COOH` there is no `added`: only `atoms` and `kind`.
- **`interp` `.wasm`** (`crates/mzlab-feat-wasm/src/interp_js.rs`, flat functions in `crates/mzlab-ops/src/run/feat/interp.rs`, folder `wasm-feat/interp/`, `interp` entry in the manifest, row in `tools/build_feat_wasm.sh`): `interp_build(table_read, size, parent_json, registry, polarity, index_read, index_sizes, infusion, write)` writes the `.mzfeat` with the block and answers `{bytes, sha256}`; `table_interp(table_read, size, id)` gives the row's JSON (`null` if not interpreted).
  Cap 623 200 B (`tools/moduli/interp.toml`, +10 % over the measured size); the tree is built by `interp` itself (moving it to `finder_msn` is a decision for the Coordinator, measurements in `measurements.md`).
- **Worker and app**: `TP_Mine/files/feat-worker.js` (`interpBuild`, `interpRow`, ops `interp_build` and `table_interp`, `interp` module loaded only on request); `feat-desktop-pool.js` and `crates/mzlab-desktop/src/feat.rs` (`feat/interp/build`, `feat/interp/row` on the table held by the app, which it replaces with the one with the block).
- **Real data** (`tests/interp_data.rs`, skips without `MZLAB_DATI`): full run on the timolol series (`dati/HRMS/Timolol/`), without asserting agreement with the literature (hypotheses found by hand, not truth); with `MZLAB_MISURE_OUT` it writes the interpreted rows as JSON, which `tools/valida/tp_timololo.py` compares with the hypotheses and writes to the private repository (`coordinamento/consegne/TABUI_TP_TIMOLOLO_MISURE.md`).
- **Parity on real data** (`crates/mzlab-cli/src/flow_parity_data_tests.rs`, `cargo test --release -p mzlab-cli flow_parita_dati`, skips without `MZLAB_DATI`; unit test because an integration test of mzlab-cli sees two copies of `mzlab_core` in the `--workspace` build): on the mzML of `dati/HRMS/Timolol/` the `.mzidx` index built twice, the index→detect→align→gapfill plan of `run_plan` with 1 and 2 workers and the browser chain (`run::recipe_of_layers`) give the same bytes; at the first differing byte it names file and offset. On stderr only time and peak RSS.
- Tests: `tests/interp.rs` (labels, candidates, sulfur, filter text, purity, isomers, tree states, formulas, calibration, first filter, block written/read/replaced); `tests/interp_synthetic.rs` (synthetic series `tools/feat_synthetic.py`: block, row read, table unchanged, second pass identical).
- **MS1 at the apex** (`apex.rs::apex_ms1_many`): for each file a single pass over the MS1 section for all rows and the parent (windows sorted by `sweep::windows`); each row gets the same values as a pass of its own.
- **Timings** (`mzlab-feat/src/prof.rs`): with `MZLAB_PHASES=1` on stderr the seconds per sub-phase, as "interp phase …" lines for the pass (open, ms2 index, pick scans, purity, peaks, apex ms1, library, candidates, pool, compare, position, decoys) and "evidence phase proofs: …" for the proofs (read table, points, ms2 spectra, row facts, identities, tp view, graph, write); no clock in the `.wasm`.
