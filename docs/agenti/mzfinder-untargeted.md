# mzFinder: untargeted tables (HR)
The rest of mzFinder: `mzfinder.md`. Rust readers of the tables: section "Readers for other programs' tables" below.
- **Untargeted tables** (`js/25_untarget.js` = `window.UNT`, no DOM: it calls the Rust readers, section below; tests `tests/test_untarget.py` with the hand-written files of `tests/data/untargeted/`): a single feature model `{key "POS:id", id, pol, mz, rt, areas{sample}, detected, ms2{mz,it}, ann[], group, iin, component, nScans}` per table `{program, file{name, sha256}, pol, samples, features, edges, stats, warnings}`;
  external annotations are an open structure `{source, type, score, shared, ppm, name, cleanName, ik, smiles, inchi, formula, adduct, analog, propagated, notes}` (open to other sources, such as SIRIUS). `UNT.detect` recognises the file from its columns; `UNT.build(files)` merges main table + MGF + annotations + GNPS2 + network.
  Readers: mzMine (full table with `spectral_db_matches:*` and `datafile:<F>:area`; `*_annotations.csv` completes InChIKey/`entry_id` only on the same feature and the same name or InChI, `matchedlipid` rows are dropped;
  the library structure holds only if the formula explains the precursor within 20 ppm with the declared adduct or a common one, otherwise `structure: "unreliable"` and the structure is removed; without a formula `unverified`), FBMN (`*_quant.csv`, MGF with only `MSLEVEL=2` and the block with the most peaks per `FEATURE_ID`, IIN edges),
  MS-DIAL (alignment `.txt`, metadata rows at the top, `MS/MS spectrum` = `mz:int`), GNPS2 (`#Scan#` = id, `|MassDiff|/SpecMZ` > 15 ppm = analog, propagated names dropped, `InChIKey-Planar` preferred, `component` −1 = none), mzFinder HR (`fromMzfinder`). Sample names without `.mzML`.
  `UNT.assessAllExternal(table, "attributio")` reads the external sources with the "attributio" profile of `levels/1` (2a, name conflict, isomers not discriminated, none; parity with the synthetic campaign of the data repository only with `MZLAB_DATI`).
- **Untargeted match** (`js/26_untarget_match.js` = `window.UNTM`, `js/27_untarget_ui.js` = `window.UNTUI`; tests `tests/test_untarget_match.py` with a fake engine, `e2e_untarget`): the "Feature tables" tab → "Match a feature table..." opens the `#unt` window (HR only, never in LR).
  The files of a table are loaded (recognised from their columns); the polarity comes from the menu, from the file names or from the `IONMODE` of the MGF; the SHA-256 fingerprint goes in `table.file.sha256`.
  `UNTM.run` sends every feature with MS2 to `LIB.call("searchAll")` in blocks of 1000 (precursor tolerance in ppm, field `#unt-tol`) and scores the row with `LIVELLI.assess` ("mzlab" profile: `nScans` = fragmentation scans of the table or `MERGED_ACROSS_N_SAMPLES` of the MGF, 1 if unknown, so without a count 2a stops at 3);
  without MS2 or without a candidate the level is 5, and 4 only if ONE formula from an external source explains the m/z within 5 ppm.
  External annotations (mzMine, GNPS2, MS-DIAL) are evidence only, with source and score in the "External evidence" column, never a level.
  2b is not assigned by the program: `UNTM.decide` ("Level decided by the chemist" menu) accepts it from 2a, 3a, 3b or 4 and rejects it on 5 and 0.
  The table (`#unt-t`) is a `TPTAB` (`docs/agenti/mzfinder-table.md`): frozen level and m/z columns, sorting from the headers, "Columns", chips (L2/L3/L4 "or better", L5, MS2, decided) in AND, search, "Export view";
  a click on a row opens it below itself (only one open) with the Overview tab (chromatogram and mirror with `LIB.mirror` on the first candidate of `LIB.call("search")`),
  Samples (if there is more than one sample, `TPRIGA.fill`) and Identity (evidence, external annotations, the decided-level menu and "What is it?" with `LIB.whatIs(UNTM.panelOf(f, table))`, a fake panel shaped like those of the Data tab).
- **Untargeted export** (`js/28_untarget_export.js` = `window.UNTX`; tests `tests/test_untarget_export.py`, `e2e_untarget`): the buttons "Excel (.xlsx)" (`xlsx.js`: sheets Features, Evidence, Library records, Parameters),
  "CSV (;)" (UTF-8 with BOM, decimal point, fields containing `;` or quotes are quoted) and "MGF" (only features with MS2, `LEVEL=`, `NAME=`, `LIBRARY_RECORD=`, `LIBRARY_LICENSE=`, `#` header lines with the table fingerprint and the licences of the cited records)
  export all features or only those of the active table view ("only the filtered features"; for identities, their members).
  "Export view" of `TPTAB` instead downloads the view as it is (`untargeted_view.csv`, with the filters at the top).
  Fixed columns (`UNTX.HEAD`): `key` (`POS:12` = polarity + id), `polarity`, `feature_id`, `mz`, `rt_min`, `level` (the decided one if present), `level_proposed`, `level_decided`, candidate, library, formula, InChIKey, SMILES, entropy, cosine, shared peaks, Δppm, MS2 peaks and scans, record,
  record authors and licence (text as in the record, "not stated" if missing), evidence, external evidence, file and `table_sha256` of the source table; then one area per sample.
  The `(polarity, id)` key plus the SHA-256 fingerprint lets SIRIUS and the chemist's review attach rows without ambiguity. The Parameters sheet reports tolerance, profile and level thresholds. The level words (evidence) follow the page language, as in "What is it?".
  **Open data** (`js/30_untarget_fair.js` = `window.UNTF`; tests `tests/test_fair.py`, `e2e_untarget`): next to the buttons, "GNPS2 (FBMN)" downloads a `.zip` with `quant.csv` (mzMine format: `row ID`, `row m/z`, `row retention time`, IIN columns, `<sample>.mzML Peak area`),
  `ms2.mgf` (one block per `FEATURE_ID`, MS2 only, without names or levels) and `iin_edges.csv` (only the IIN edges between the exported features, not the cosine ones),
  and "SIRIUS (.ms)" a `.ms` with the features that have MS2 (`FAIR.siriusMs`, without formula, name `feature_<key>`, MS1 only if the feature carries it). Files only, nothing is sent; the files read back by `UNT.build` give the same features, areas, MS2 and edges.
- **Feature identity** (`finder_base/identity.rs`; entries `identity_graph` and `polarity_pairs`, stateless: the table arrives in the payload; test `crates/mzlab-feat/tests/legacy_parity.rs`): `build` makes a graph between the features of a table (positive or negative) with an edge only if ALL three conditions hold:
  co-elution (|ΔRT| within `apex_scans` × `cycle_s`, 2 scans of 1 s by default; the table has no per-scan apexes, so it is the ΔRT), correlation of the areas over the common samples (Pearson r ≥ 0.85, at least 3 common samples, otherwise no edge)
  and a mass relation explained within 5 ppm / 2 mDa (`iimn.relations`: isotope, adduct, in-source loss; plus the differences between two adducts that are not [M+H]+ and the dimer).
  The connected components are the identities: the main hypothesis is the neutral mass that explains the most members (ties: a base ion among the members, smaller error, area), the alternatives stay in `alternatives` (max 4); each member has its role with Δm/z and ppm.
  Each edge carries its evidence: relation label (with all possible readings, e.g. NH4/NH3), Δm/z and ppm, r, common samples, ΔRT in s and in scans, `source`.
  If the mzMine table already has the IIN (`ion_identities:iin_id`, `annotation network number` and `best ion` of FBMN, `EdgeType` ≠ Cosine edges) those links enter as an "mzMine IIN" edge (`source` "mzMine table" or "mzMine edges") and the steps between members of the same group are not recomputed.
  `polarity_pairs`: POS and NEG features with the same neutral mass within 5 ppm under the pairs [M+H]+/[M+Na]+/[M+NH4]+ ↔ [M-H]-/[M+FA-H]-/[M+Cl]- and RT within 0.15 min (evidence, not a verdict). Constants and rules rewritten from Attributio (`THIRD-PARTY-LICENSES.md`).
  **Evidence of each edge** (`finder_base/edge.rs`, used by `build` for all edges, including those of the mzMine IIN; test `legacy_parity.rs`): `edges[].evidence = {kind, label, text, relations, evidence[], summary}`, where `kind` is `adduct`, `isf`, `undetermined` or `other` (isotope or unexplained step: no label).
  Windows: co-elution 0.05 min, tolerance max(0.002 Da, 5 ppm); the MS2 arrive in the payload (`features[].ms2`, the 40 strongest peaks).
  **Adduct**: the Δm is in the table (`iimn.relations` and `STEPS`, the Attributio steps) and, if there are MS2, the skeleton is shared (≥ 50 % of the fragments of the lighter one also in the heavier one, at the same m/z or shifted by the Δm) or the typical loss appears (−17.027 from [M+NH4]+);
  [M+Na]+/[M+K]+ that do not fragment = hint only (`strength: hint`).
  **In-source fragment?**: the step is a neutral loss, the m/z of the lighter one is among the MS2 fragments of the co-eluting heavier one AND the heavy/light area ratio is stable across samples (CV ≤ 30 %, at least 3 common samples; CV from `ionfamily.ratio_constancy`, in the ratio from `isf.features`).
  **Not distinguishable**: both readings hold (e.g. 17.0265 = NH4 or −NH3; 46.0055 = formate or −HCOOH) or neither. Each piece of evidence has `strength` `evidence`, `against`, `hint` or `info`.
  The view (`UNTID.edgeText`) writes "adduct (evidence: …)" / "in-source fragment? (evidence: …)" / "not distinguishable" in front of the edge data.
  The report "Where does this ion come from?" (`origine.js`, `api/origin`) adds, only for HR files and when mzFinder is loaded (`window.TPCALL`), the section "Proofs (mzFinder)" with the same evidence as a list (`origin_evidence` in `api.py`, `edge_evidence.report_evidence`; `app.py` adds `hr`, `pol`, `ms2_peaks` to the report), without a label.
- **Identity view** (`js/29_untarget_identity.js` = `window.UNTID`, pure; `js/27_untarget_ui.js`; test `e2e_identita`): `window.TPCALL` is the `call` of the mzFinder Web Worker.
  `UNTID.payload` sends the engine only the features with at least 3 samples or with the mzMine IIN (the others are single-feature identities, read as [M+H]+ / [M-H]-), `compute` adds the singletons and numbers `ID1…` by RT,
  `annotate` gives each identity level, candidate, structure key (first 14 characters of the InChIKey, `structConflict` if the members' candidates differ) and external sources from the BEST of the members (2b only if decided by the chemist).
  In the tables window, after the match, "group by identity" (with "Cycle time", s, for the "2 scans") replaces the table with a second `TPTAB` (`#unt-g`) with ONE row per identity (level, ID and member count, neutral mass, RT, maximum area, best candidate);
  the expanded row has the Identity tab (`UNTID.identityHtml`) and the Features tab (`UNTID.membersHtml`: role, e.g. "[M+Na]+ (0.3 ppm)", level and candidate of each member, with a button that opens the feature in the feature table).
  The Identity tab shows neutral mass and alternative readings, the evidence of each edge (`UNTID.edgeText`: relation, Δm/z and ppm, r over the common samples, ΔRT in s and in scans, or "mzMine IIN") and the small network (`networkSvg`: nodes in a circle with the m/z, labelled edges,
  solid = adduct, dashed = isotope, dotted = in-source loss, thick = mzMine IIN, Okabe-Ito colours from `--idn-*` variables); filters (level, text, MS2) apply per identity; the export stays per feature.
  Wording: "hypothesis", "evidence", never verdicts. `UNTID.pairPolarity` sends the two tables (POS and NEG) to `polarity_pairs` (no button calls it: the window loads one table at a time).

## Readers for other programs' tables (Rust)

- **Module** `crates/mzlab-feat/src/import/` (no dependency besides `mzlab-core`; no regex: the expressions of `25_untarget.js` are written by hand): `delim.rs` (`each_row`: streaming delimited text with quotes, BOM and line breaks inside quotes; `num`, `Cols::pick` by column NAME),
  `model.rs` (`Table`, `Feature`, `Rec` = open annotation with the keys in writing order; `table_json`), `chem.rs` (`formula_mass`, `norm_adduct`, `check_structure` at 20 ppm, `clean_name` with the "attributio" profile of `levels/1`, `is_propagated`).
  Then: `mzmine.rs` (full table, annotations, FBMN quant, IIN edges), `mgf.rs`, `msdial.rs`, `gnps.rs` (library and network), `join.rs` (`detect` by columns, `build`).
- **Same output as the reference JS readers**: `tests/data/untargeted/golden/golden.json` (written by the JS readers, frozen) on the fixtures of `tests/data/untargeted/`; `crates/mzlab-feat/tests/import_parity.rs` compares whole tables, numbers, adducts, names, formulas, spectra, file recognition and quoted text (CRLF included).
  The masses come from `mzlab-core` (plus B and Fe): the ppm of `check_structure` may differ from the JS beyond the ninth digit, the decisions do not. The BOM does not hide the columns from `detect`.
- **Order of the GNPS2 annotations**: the JS comparison is not a total order (different sources are "equal"), so `gnps::engine_sort` reproduces the binary-insertion sort of the browser engine.
- **Binding** `crates/mzlab-feat-import-wasm` (separate `.wasm`, `wasm-feat/import/`, `import` entry of `manifest.json`, cap 512 000 B in `build_feat_wasm.sh`): `add(name, sha256, text)` queues the files (one copy each), `build(pol, max)` gives the table as JSON and empties the queue, `clear`, `detect`, `check_structure`, `norm_adduct`, `clean_name`, `formula_mass`, `is_propagated`, `num`.
  Errors `{error_key, params{message}}` with `columns`, `empty`, `noTable`.
- **Page**: `TP_Mine/js/25_untarget.js` (`window.UNT`) does not read files: `UNT.ready()` downloads the `import` `.wasm` (manifest, SHA-256 checked; the untargeted window and `UNTM.run` call it before reading or scoring), `UNT.use(module)` injects it
  (the node tests get it from the `MZLAB_IMPORT_PKG` variable, set by `tests/conftest.py`, which builds the package with `wasm-bindgen --target nodejs`; without cargo, `wasm-bindgen` or node those tests are skipped).
  `build`, `detect`, `checkStructure`, `normAdduct`, `cleanName`, `formulaMass`, `isPropagated`, `num` pass the arguments through and return the JSON, without computing numbers.
- **Stays in JS**: `fromMzfinder`/`fromRows` (package rows already computed), `sha256Hex`, `assessExternal`/`assessAllExternal`/`markIsomers` (glue over `LIVELLI.assess`, which has user-editable thresholds and i18n texts).
- **In the desktop app** the readers are the same but are called from the native route `feat/import` (`docs/agenti/rust-desktop.md`): no `wasm-feat/import/`; `Check::json` (`import/chem.rs`) writes the `check_structure` response for the `.wasm` and for the app.
