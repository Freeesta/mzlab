# Acquisition method (`method/1`)

The method of ONE sample (instrument, source, experiments, LC, detectors, log) as a single JSON, whatever the starting file. Schema: `mzlab/web/schemi/method-1.json`. Code: `crates/mzlab-core/src/method.rs` (tree, `.dam` adapter, SHA-1, `userParam`), `method_wiff.rs` (`.wiff` adapter) and `method_raw.rs` (+ `method_raw/script.rs`, `fields.rs`: Thermo `.raw` adapter). The "no answers" principle applies: the document reports what the file says, with no verdicts.

## Document rules
- An unknown value is ABSENT (never `null`, never 0); empty sections are omitted; units are in the field name (`flow_mL_min`, `ce_eV`, `injection_uL`).
- Sections: `schema` (= `method/1`), `origin` (format, files with name/SHA-1/bytes, sample number, `file_created` = local time of the instrument PC, no time zone; `reader`), `sample`, `instrument`, `operator`, `ms` (`source`, `periods[].experiments[]` with `parameters` and `transitions`), `lc` (`gradient`, `flow_mL_min`, `oven_C`, `pressure_max`), `autosampler`, `detectors`, `log`.
- `fields` (every field of the file that the sections do not carry: `origin`, `key`, `value`, `unit?`, `mapped?`, `identity?`; sorted by origin and key), `raw` (Log or method text ≤ 256 KB; ≤ 512 KB in the `.raw`, short texts first), `warnings` (i18n key + `place`: `meta.nonDecodificato`, `meta.mancante`, `meta.troncato`; for the `.raw` also `meta.ioneScartata` and `meta.daTabella` with the scan counts, and `meta.nonDecodificato` for an undecoded MS order, an event found by number in a cut table and a profile with unknown calibration, rejected).
- Size: every reader of the document reads `DOC_MAX` (1 MB) after `<run>` (site, wizard, reopened mzML); the mzML writer cuts it at that point with `method_fit::fit` (first the last entries of `fields`, then the last texts of `raw`, each with `meta.troncato`), never losing everything. A document that fits stays identical byte for byte.
- Visible warnings: every key of `warnings` has IT/EN text in `lang/*/errori.js` with `{dove}`; the Method window lists them at the top of the file section (`metodo-doc.js`, `NOTE_KEYS`, `data-mnotes`), `mzlab-cli file convert` prints them as `note:` lines and writes them in `warnings` of the `--report` (`tests/test_avvisi_metodo.py`).
- The `ms` parameters are sorted by id (the order in the file is an accident of the writer): the same method read from `.dam` and from `.wiff` gives the same `ms`. `type` of an experiment is "MRM" only if there are transitions; the file name is not proof.

## Adapters
- `.dam`: `from_dam` (experiment method; LC and detectors from the XML of the LC method).
- `.wiff`: `from_wiff(&Ole, sample, &Source)`. From `SampleSubtree/SampleN/{Log, SampleDABE/DATA, SampleDABE/CFR_INFO}` and from `SummaryInformation` (property 12 = creation, FILETIME).
  The source type (`ms.source.type`, e.g. "Turbo Spray") is the "Source Type" of the `.wiff` Log; a `.dam` alone does not say it, so it is missing. Instrument manufacturer and model are read from the Log ("Config Table", keys in any case: Analyst writes `Component ID:`, SCIEX OS `Component Id:`), never from a value written in the code: if the file does not give them, the field is absent.
  The software is "SCIEX OS" if a Log line names it, otherwise "Analyst". The method experiments are all those the file contains (even more than sixteen), as in the reader list.
  Measured on the 3200 files: model and serial ("Config Table" record of the Log), user and computer (`driver:User=` record), pumps and sampler (driver entries), run start/end.
  `sample.name` (first string of `DATA`) and the Analyst version (string of `CFR_INFO`) are CONFIRMED: the name is that of the msconvert mzML file (`<wiff>-<name>.mzML`), the version is in the `GLPTables`. TO BE CONFIRMED (position in the stream, no label): `sample.vial`. The DAD is decoded but not validated (no `meta.nonDecodificato` warning for the DAD): `wiff-variants.md`, DAD section.
  With the `estesi` feature (`sciex` module) the document also has `fields` (`DabsInfo`, `SampleTable`, `GLPTables`, DAD header) and the sMRM experiments carry `programmato` and `finestra_s`: `wiff-variants.md`.
- `.raw` (Thermo): `method_raw::from_raw(&RawFileReader, source, &Source, notes)`, `raw::method_sha1(raw, source, name, sha1, notes)`.
  From the `sample` sequence row (vial, injected volume, id, comment, dilution, weight, volume, ISTD, method file name); from the InstID block `instrument` (model, `series` = third string, Xcalibur version = fourth, `hardware` = fifth: positions measured on v66, same as the msconvert mzML, TO BE CONFIRMED on other instruments); from the audit tags `operator.user` (`tag2` of AuditStart) and `origin.file_created` (FILETIME without time zone); from the computer name `operator.computer`.
- Embedded method (`method_raw/ole_raw.rs`): the `.raw` carries the method as an OLE2 document (streams `LCQ Header`, `AuditData` and, per device, `Text`, `Data`, `Header`, `Comments`) that starts within the first 64 KB, found by signature `D0 CF 11 E0 A1 B1 1A E1`; `ole.rs` reads it (the `.wiff` one, unchanged) and every `Text`/`Data`/`Comments` stream (UTF-16 or UTF-8) is a text block with its path.
  - The UTF-16 heuristic of `opentfraw` (`instrument_method_blocks`) adds only the texts the container does not have; a file without a container uses only that and `warnings` has `meta.nonDecodificato` with `place` "Method: OLE container not found (texts found by scanning)".
  - From these blocks (LC script, Orbitrap text, XML): `lc` (gradient from `chromeleon::parse`, flow, oven, `pressure_max`, `solvents` = channel and name from the `PumpModule.Pump.%A1_Equate` lines), `autosampler.parameters` (`SamplerModule.*` numbers), `ms.source.type` from the filter of the first scan (ESI, NSI…), `ms.periods[0].experiments[]` from the `ScanEvent` of the XML (`index`, `mz`, numeric `parameters` with the unit of the XML); the three whole texts in `raw`.
- Orbitrap text settings (`method_raw/settings.rs`): the `Label: value [unit]` lines for chromatographic peak width, apex trigger, loop count (Top-N), intensity threshold, minimum AGC, dynamic exclusion, isotope exclusion, charges, isolation window and (N)CE are `ms.settings[]` (`id`, `label` as written, `values` if it is a list of numbers or `value` if it is text, `unit`).
  - They complete the experiments of the XML: an `NCE` equal to the mean of the steps in the text (`20, 35, 60`) becomes `nce` = the list; `Isolation_high` (a width in m/z) becomes `isolation_mz` and `Isolation_low`/`Isolation_high` leave `parameters` (they stay in `fields`). The known labels are in the `KNOWN` table: a different label does not enter.
- Inclusion list (`method_raw/inclusion.rs`): the table after the `INCLUSION LIST` line of the Exactive text (columns found by name: mass, formula, species, charge, polarity, start and end, (N)CE, name; cells separated by `|` or tabs) is `inclusion[]` of the last experiment (or of an experiment of its own): `mz`, `formula?`, `species?`, `charge?`, `polarity?`, `t_start_min?`, `t_end_min?`, `nce[]?`, `name?`.
  - Only a description of what the instrument was meant to fragment: never turned into "expected TPs", never passed to Tabui. The format is tested on rewritten texts; the test on the real text of a file with the list (`tests_e2e/e2e_metodo.py`, `MZLAB_DATI`) is skipped without the private repository.
- TSQ (`method_raw/tsq.rs`): the table `Compound Name | Start Time | End Time | Polarity | Precursor | Product | Collision Energy | RF Lens (or Tube Lens) | Dwell` of the method text (columns are found by name, missing ones are absent) goes into an experiment of `ms.periods[0]` with `type` (`Experiment Type`), `parameters` (the `Label (unit): number` lines before the table) and `transitions` (`q1`, `q3`, `ce_eV`, `rf_lens_V`, `dwell_ms`, `polarity`, `t_start_min`, `t_end_min`, `name`).
  The file may keep only the first bytes of the method summary: if the table ends inside a row, `warnings` has `meta.nonDecodificato` with `place` "Method MS: transitions cut by the file"; if the text announces transitions but no table can be read, `place` is "Method MS: transitions". Older TSQs (Vantage/Quantum) may not open in `opentfraw`.
- Lock mass (`method_raw/lock.rs`): `ms.calibration.lock_mass` = `mode` (`Use lock masses`: best/off), `lists` (`polarity`, `name`, `masses_mz` of the `Lock Masses:` block), `number_in_trailer` and `correction_ppm` ([min, max] over the scans; equal if constant). Description only: no data is corrected.
- Detectors (`method_raw/detectors.rs`): `detectors[]` from the `UV_VIS_n.Wavelength/Bandwidth/RefWavelength/RefBandwidth`, `3DFIELD.Min/MaxWavelength/BunchWidth` and `Data_Collection_Rate` lines of the Chromeleon script (the first line of each key counts); the lamp is not in the file. If the 3D field is there, `warnings` has "UV 3D field (PDA spectra)".
- `fields` of the `.raw`: header, sequence row, InstID, RunHeader, the 62 trailer fields (value if equal in all scans, otherwise range), every script line, the `ScanEvent` elements of the XML (`agilent::meta::collect`; the rest of the XML, about 17,000 entries in an Orbitrap, is whole in `raw`) and the analog channels (`Controller<N>`: name, unit, samples, driver, model, serial). The status log (`thermo-raw:StatusLog`: every channel with unit, value or range) is in `fields`; `meta.nonDecodificato` only if its schema is not found. 
- `.raw` log: `log` = error log (`t_min` in minutes, `text`, `level` if it starts with Info/Warning/Error; `method_raw/registry.rs`).
- `log_series` = list of the status log and trailer series that change (`method_raw/series.rs`; points on request with `/api/registro`, never in the open).
- The `raw → mzML` conversion writes the document in the `<run>` (`rawfilter::with_run_extra`): `mzml_metodo` rereads it (`Mzml::run_head`, up to 1 MB after `<run `).
- mzML: `userParam name="mzLab method/1"` in the `<run>` with the document (XML escape); `from_userparam` rereads it.
- mzML written by others (`method_mzml.rs`, `Mzml::metodo`, op `mzml_head_metodo`, last fallback of `lr_metodo` after `.wiff` and `.dam`): `from_mzml_head` reads the header up to `<spectrumList` and at most the first 64 scans (never the whole file, cap 8 MB).
  - Fields: `origin` (mzML, source file with SHA-1, `run@startTimeStamp` = `file_created`), `sample.name` (`sampleList`), `instrument` (model, serial, software), `ms.periods[0].experiments[]` (one per MS level) with the scan parameters equal in all the scans read (injection time, resolution, CE, isolation, window), and in `fields` (`mzml:<element>`: `scanSettings`, `sample`, `dataProcessing`, `target`, `run`) the rest of the header plus, as a `min..max` range, the scan parameters that change (`mzml:spectrum`).
  - A document already written by mzLab wins. Test: `tests/method_mzml.rs` (mzML built in the test). Not verified on real msconvert mzML (no real file).
- `.D` (Agilent MassHunter GC/MS): `AgilentD::metodo(&Source)` (`crates/mzlab-core/src/agilent/doc.rs`). `sample` from `sequence.xml` (name, vial, injected volume, method file, dilution); `instrument` from `Devices.xml` (model, serial, firmware) and `Contents.xml` (acquisition program and version); `operator` from `SequenceOperator` (otherwise `OperatorName` of `sample_info.xml`) and from the computer of the audit log;
- `ms` of the `.D`: `source` EI with the numeric tune values of `acqmeth.txt`; `periods[0].experiments[]`: one with the mass range for a scan run, one per group for SIM (start, resolution, every ion with its dwell in `parameters`).
- `fields` of the `.D`: every name/value of `AgilentD::metadata` (none excluded) with `mapped` if a section carries it; the whole text of `acqmeth.txt`, `runstart.txt` and `IndexedDataConverter.log` is in `raw`. The undecoded parts (header of `MSScan.bin`, tail of `MSTree2.bin`) are in `warnings` (`meta.nonDecodificato`) and, with bytes and SHA-1, in `fields`. GC (oven, injector, column) has no section: it stays in `fields` and in the method text. There is no `lc` or `detectors` for GC/MS.
- `.D` LC/MS (`agilent` module, `crates/mzlab-core/src/agilent_ext/lcdoc.rs`): in addition to the above, `lc` (gradient, oven), `autosampler`, `detectors`, `instrument.moduli` (every module of `Devices.xml`), `ms.periods[].experiments[]` with the `transitions` (Q1, Q3, CE, fragmentor, dwell, dMRM windows) or the reference and precursor lists of the Q-TOF; format and keys in `agilent-lcms.md`.
- The `.D → mzML` conversion writes the document as `userParam name="mzLab method/1"` in the `<run>`, with the SHA-1 of all the files read (also `MSPeak.bin`), as for the `.raw`.
- The `.wiff → mzML` conversion (`WiffReader::mzml_header`, native and `sciex` module) writes the `from_wiff` document in the same way (LC with the gradient of `VendorAppMethod`): the Method window of a `.wiff` passed through the module rereads it from the mzML. The scan table (`testata_tabella`) stays without it.
- A `.wiff` without `.wiff.scan` does not open as data but gives its method.
- Method folder `.m` (Agilent MassHunter, only `DaMethod/Quant/quantitative.xml`): `agilent::quant::metodo_m` (op `lr_metodo_m`, `metodoM` in `rust-convert.js`, UI `metodo-m.js`) gives a `method/1` with the `quantification` section (compounds, RT, ions, levels as written in the file: processing settings, not results). No automatic matching with the `.D` run (the names differ). Tests: `crates/mzlab-core/tests/agilent_method_m.rs`, `tests_e2e/e2e_metodo_m.py`.

- Shimadzu (`.qgd`, `.lcd`: `crates/mzlab-lettori/src/shimadzu/meta.rs`, `documento`): `instrument` from the name in the file, `sample` from `File Property`/properties XML, `ms` from the events seen (SIM/scan with m/z range) and from the MRM transitions; operator, user and paths are `identity`: they stay in the reader document and not in the `userParam` of the mzML. The rest, undecoded, is in `warnings` (`meta.nonDecodificato`); details in `docs/agenti/shimadzu.md`.

## Matching `.wiff` and mzML
The ProteoWizard mzML have in `<sourceFile>` a SHA-1 cvParam (MS:1000569) equal to that of the `.wiff` (the name in the mzML may differ from the real file); the sample comes from the `nativeID` `sample=N`. `mzml_sources` reads the first MB of the mzML; `sha1_file` computes the fingerprint of the `.wiff`. A `.wiff` loaded alone with mzML already open with the same SHA-1 gives each its own document (note `load.note.wiffMethod`); without a match the error `err.file.wiffNoScan` remains.

## Route and engine
- Page: the Method window (`showMethod`, `eventi.js`) ends with the section "Method recorded in the file" of `metodo-doc.js` (`METODO_DOC.html(f)`, from `/api/metodo?k=`): file (format, bytes, SHA-1, date), sample, instrument, operator, MS experiments; LC (with gradient), detectors, all the fields and the log are in `<details>`
- Log with times in the Method window (`metodo-registro.js`, `METODO_REGISTRO`) has one button per time that moves the cursor of the first chromatogram to that RT. Only what the file says, every value goes through `EH()`, no warning; texts in `method.doc.*`. Test: `tests_e2e/e2e_metodo.py`.
- GET `/api/metodo?name=<file>` → `{"source":"mzml|wiff|dam|none","metodo":{…}}` (op `lr_metodo` of `rust-metodo.js`, called from `rust-worker-lab.js`).
- GET `/api/registro?k=<file>&id=<series>` → the analog chromatogram of the series (`time`, `intensity`, `unit`), computed on request by the `thermo` module in a session kept for 30 s (op `natregistro` of `rust-worker.js`, `registroDi` in `rust-nativo.js`; in the app the same op of `rpc_nat.rs`, reader opened at every request, same bytes: `crates/mzlab-desktop/tests/natregistry.rs`; `rawreader.rs::registro_di`); an id that is not in the list gives an error; the series travels in the `series` field of the message (`id` is the request counter).
- Engine (`crates/mzlab-wasm/src/method.rs`): `sha1_file`, `mzml_sources`, `mzml_metodo`, `wiff_metodo` (reads the whole `.wiff`, refuses above 192 MB with `memory_budget`), `lab_metodo`.
- Tests: `crates/mzlab-core/tests/method_raw_parity.rs` (every `.raw` with its mzML: serial and version equal to msconvert, gradient points equal to those of the script, document inside the mzML of the conversion) and `crates/mzlab-core/tests/method_parity.rs` (real data, `MZLAB_DATI`): `ms` of the `.wiff` equal to the named `.dam`, SHA-1 equal to that of the reference mzML; `tests_e2e/e2e_metodo.py` (route and flow of the lone `.wiff`).
- "Acquisition method" window (`showMethod` in `eventi.js`, `gradiente.js`): data only, no explanatory text; without a method there is only the button "Load the method (.dam)" next to the file row; the Gradient section is read-only; a section without data does not appear.
