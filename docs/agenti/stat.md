# Statistics as steps (`table.stats`, `table.pca`, `table.kmd`)
Rust engine `crates/mzlab-feat/src/stat/` (modules `compare.rs`, `kmd.rs`, `special.rs`, `json.rs`); `step/1` descriptors in `steps/stats.rs`, native only (`wasm: None`: the `table` `.wasm` does not carry them). Tests: `cargo test -p mzlab-feat --test stat` (parity, null simulation, refusal, forbidden word, descriptor defaults); references: `tests/golden/statistica_pca.json` (PCA, `mzlab/statistica.py`) and `tests/golden/kmd.json` (KMD, `tools/kmd_reference.py`, `--check` in `tests/test_kmd.py`).
- **Decision G1**: p-values and q-values live only in the `stat/1` output (admin/HR); no view shows them and no text says a result is "significant" (the guard is in `tests/stat.rs`).
- **`table.stats`** (`stat::compare`, `stat::stats_json`): for each comparison of the design (`b` against `a`) the Welch t on log2(area + pseudocount) (missing area = 0), plus a one-way ANOVA over all the conditions with files; Benjamini-Hochberg correction within each family of tests (a p that cannot be computed does not count among the tests); log2FC = log2((mean b + p) / (mean a + p)) on the raw areas. Pseudocount given, otherwise 3 × the median of the positive areas of the blanks, otherwise of the reference, otherwise `FLOOR` (1000), never below `FLOOR`.
- **Refusal**: with fewer than `MIN_REPLICHE` (3) files in a condition the comparison (or the ANOVA, if any condition is short) answers `refused: "fewReplicates"` with empty rows and a warning `{code, group, n}`: no number. If the variance is zero in both groups and the means differ, t and p are absent.
- **Output for the charts**: the comparison rows (`log2fc`, `p`, `q`) feed the volcano; `heat` has `groups`, `z` (per-feature z-score of the mean of log2(area + p) in the conditions with at least 3 files) and the sorted indices `rowOrder`/`colOrder` from deterministic UPGMA hierarchical clustering with branch orientation at the edges (`[]` if `heat` is empty, projection on a contrast axis and `sortc` beyond 256 elements).
- **Input**: `Layout` (condition of each file, blanks, reference) from `layout_from_design(&[Sample], &Disegno)` and `comparisons_from_design`; `stats_json` reads `{matrix, groups (name or null per file), blank, reference, comparisons, pseudo}`.
- **`table.pca`** (`stat::pca_json`): it is `mzlab_core::pca::pca_analysis`, the same as the `api/stat/pca` API (filters, declared imputation, log2 and scaling, SVD, leave-one-out stability, 95 % ellipses); the PCA view is described in `alta-risoluzione-statistica.md`.
- **`table.kmd`** (`stat::analyse`, `kmd_json`): port of `kmd-calc.js` (units CF2, CF2O, C2F4, CH2; KMD windows; steps, Spearman ρ); JavaScript `Math.round` is `floor(x + 0.5)`. The series are candidates, never identifications. Execution in the plan: `flow_kmd.rs` (m/z and RT of the `.mzfeat` rows, output `report`).
- **Execution**: `table.stats` runs in `mzflow` plans (`mzlab-cli/src/flow_stats.rs`, see `cli.md`); `table.pca` too (`flow_pca.rs`: roles and replicate groups of the files as `pca.js`); `table.kmd` too (`flow_kmd.rs`). The text is `mzlab_feat::flow_stat` (`stats_text`, `pca_text`, `kmd_text`), the same in the CLI and in the browser.
- **In the browser**: `flow/lazy/flow-web-stat.js` (`F.webStat`, executors of `F.liveJobs`) calls `flow_stats`, `flow_pca`, `flow_kmd` of the `flowstat` `.wasm` (`run_stat.rs`, `runs_in.wasm = flowstat`) on the alignment (or gapfill) table of the plan in OPFS, or of a `table.filter` view of it (`F.liveJobs.tableOf`); `samples` and `design` are plan files (`S.samplesJson`); without one of them it `block`s with `platform.computer`. Module downloaded only if one of the three steps runs; no view shows the p-values. Test: `tests_e2e/e2e_flow_web_stat.py` (bytes equal to `flow run`, also on a view).
