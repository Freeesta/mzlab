# mzfeat: feature table, ids and samples

- **Order and ids** (`aligned_ops.rs::sort_rows`, called at the end of `series::finish`, so also by the slab path).
  - The rows of the `.mzfeat` come out in increasing m/z order, then RT, then previous order (stable).
  - `Aligned::id(row)` = 1-based position, `row_of_id` the inverse, `is_id_ordered` the check.
  - The id holds for one recipe and one set of inputs (same bytes of the `.mzfeat`), not across different recipes.
- **Counts per row**: `Aligned::state_counts(row)` = (detected, targeted, filled); presence is read from `state`, never from `area > 0`.
- **Samples** (`samples.rs`, the `samples/1` of `docs/schemi/samples-1.json`): the reduced view of the metadata of each file that the table reads (type, time, replicate, group, concentration); the only format on disk is `samples/1`.
  - `propose(&[(name, sha256)])` proposes type (`sample`, `blank`, `dark`, `t0`, `qc`, `std`, `calibration`), time, replicate, group, concentration and injection order from the names: it is a wrapper of `mzlab_core::samples::propose` (`samples/1`, `docs/agenti/samples.md`) that gives an infusion the type and time its name would give (`table_kind_of_name`: the table has no infusion role) and gives the QC the time of the name.
  - The replicate is numbered per type, time and concentration; `istd` starts false.
  - `to_json` writes the canonical `samples/1` (the group is derived from the type when read back) and `digest` is its SHA-256, the one recorded by the `samples` operation of the `.mzflow`.
  - `from_json` reads a `samples/1` (an infusion takes its name's type, the group is the type but for sample, std and calibration) and rejects another schema, a type outside the table's and bad numbers (`error.badSamples`); `to_tsv` writes the metadata table in the mzmine format.
  - Changing a metadatum does not change the detection.
- **Row summaries** (`aligned_meta.rs`, `rowmeta.rs`; `Aligned::meta`): for each row, from the files that detected it.
  - Median peak edges (`rt_lo`, `rt_hi`), charge, shape, median S/N and FWHM with the OR of the `qreason` bits.
  - Observed M+1/M (`iso_m1`, only in a family) and MS2 of highest purity (`ms2_file`, `ms2_purity`; `NO_FILE` = none).
  - `rowmeta::compute` computes them at the end of `align_and_fill` (in memory and in slabs, same bytes), reading the files in blocks of rows by m/z interval.
  - The rows added afterwards (targeted) have `RowQ::NONE`; the empty vector means not computed.
- **Row identity** (`rowident.rs`, `Aligned::ident`): `neutral` (f64), `ion` (u8) and `src` (u8) per row, computed in `evidence_to` after the last `sort_rows` (so they do not travel with the rows).
  - With a hypothesis found by `evid::match_hypotheses(hyps, table)`: neutral mass and adduct of the hypothesis, `src` = `sources << 1 | SRC_DETECTED`; without: reference protonated (or deprotonated) ion, `src` = only the detected bit (at least one file with the cell detected).
  - `ion` = 1 + position in `adduct_names()` (0 = none); the names are in the meta `adducts`.
- **Per-file data** (`facts.rs`): `file_facts(&Index)` reads from the `.mzidx` polarity (MS1 scans), mean resolution, acquisition (`ms1`, `dda`, `dia` if most MS2 isolate a window beyond 5 m/z, `mrm`) and analyzer; they go into the meta `columns` (one object per file, in the order of `inputs`) and the SHA-256 of the `samples/1` in `samples` (`Origin::facts`, `Origin::samples`; `origin_from_meta` reads them back and `evidence_to` keeps them).
- **Views** (they do not touch the `.mzfeat`; the parameters are those of the `normalize` and `filter` operations of the `.mzflow`, schema in `docs/schemi/feature_pipeline-3.json` `$defs`).
  - `norm.rs`: one factor per file (`factors`) with `Method` none, sum, median or internal standard (`Reference::Id` in `u32`, otherwise `error.badView`, or `Nearest`: among the rows within `ppm` and `rt_tol` the nearest by combined deviation of m/z and RT, each in its own tolerance; on a tie the first; it also holds for `qc::standard_cv`); the normalized area is `area * factor` (`normalised`; `None` without a peak). A cell not `ABSENT` with finite area > 0 counts; blanks and `dark` are scaled, they do not decide the target.
    A standard that does not exist is `error.normNoStandard`; a file without a peak of the standard has factor NaN.
  - `filters.rs`: ordered rules (`min_detected`, `min_area`, `min_height`, `blank`, `mz`, `rt`, `ms2`, `qc_cv_max`, `duplicates`); `apply` returns per row 0 (kept) or the rule (1-based) that rejected it first. `blank` without blanks is `error.filterNoBlank`, `ms2` without summaries `error.filterNoSummaries`: never a silent pass.
  - `filters_blank.rs`: options of `blank` (`Rule::BlankWith`, JSON `quantity`, `statistic`, `scope`, `subtract`; fold ≥ 1, comparison ≥).
  - `scope` `max` judges the row from the best sample, `each` keeps it if every sample with a peak reaches the threshold; `subtract` makes the view show `max(0, value − fold·blank)` (`View::sub`) of the chosen quantity: area or norm_area change the areas, `height` changes only the heights (`View::height_at`, CSV `height`, `view_table`); each sample is cut by the blanks of its own batch or matrix with `matching` (`blank_groups`), and a dark file by all blanks.
  - `counts.blank` (any blank rule, the plain `blank_ratio` too: ratio as given, default options): `{quantity, fold, groups, dropped:[[id, value, level, fold]...], dropped_total, truncated, fallback_all, ungrouped_all}`; `dropped` = the first 200 rows that rule dropped by row order (`fold` = deciding value / blank level of its group; `null` and level 0 without a blank level).
    - `dropped_total` counts all of them, `truncated` says the list is cut; `fallback_all` `{total, files}` names the samples with no blank of their batch or matrix that used all blanks (files capped at 200), `ungrouped_all` (with `subtract`) the dark files cut by all blanks.
  - `qc_cv_percent`: sample CV of the QCs with the non-detected at 0, `None` with fewer than 2 QCs; rule `Rule::QcCvZero` (JSON `qc_zero`). All off = the usual `Rule::Blank`/`Rule::QcCv`, same table and same digest.
  - `duplicates` (`Rule::Duplicates(tol, rt_min)`, negative tol = Da like `axis::da`; step `dup_ppm` on a high-resolution table or `dup_da` on a unit-resolution table, the other is `err.flow.param.axis` in `view_json`, + `dup_rt` default 0.1 min): among the rows within the m/z and RT window the one with the maximum area stays (tie: the first row); it is judged from the strongest and compared with the rows already kept, so a chain of close rows does not lose its ends. Proofs: `tests/dup_rule.rs`.
  - `qc_cv_max` (`Rule::QcCv(cv %, qc_min_files)`, default 3): CV (sample standard deviation / mean, in %) of the measured areas (`norm::measured`) in the files of type `qc`; the row needs a peak in at least `qc_min_files` QCs, otherwise it is rejected; with fewer `qc` files than `max(qc_min_files, 2)` the error is `error.qc.tooFew` (parameter `have`), never a number. Proofs: `tests/qc_rule.rs` (0, 2 and 6 QCs).
  - `drift.rs` (`deriva/1`): drift correction, one factor per cell (`factor`, corrected area = area × factor, `Drift::area`; it never overwrites the measured areas). Per batch of `design/1` (`batches_of`) it interpolates the QC areas against `Sample::order` with a line (≥ 3 QC peaks in the batch) or a local tricubic line (`Method::Loess(span)`, ≥ 5 peaks); reference level = median of the QC areas of the row; `curve` = value of the curve at each injection, `cv_before`/`cv_after` = CV % of the QCs.
    - It is refused with `error.drift.tooFewQc` (fewer than 5 QCs in a batch) or `error.drift.qcNotAtEnds` (the first or last injected file of the batch, blanks and dark excluded, is not a QC); a row with too few QC peaks in a batch has NaN there.
    - `summary_json` and `curve_json` for the chart. Step `table.drift`. Reference `tools/drift_reference.py` → `tests/golden/feat/deriva.json`; proofs `tests/drift.rs` (parity 1e-9, refusals, CV after ≤ before, same bytes).
  - `view.rs`: `build`/`from_spec` (kept rows, factors, reasons), `digest` (parameters + ids of the kept rows), `counts_json`.
  - `qc.rs` (`qc/2`): per file cells per state and total area; per condition (type, group, time, concentration) with ≥ 2 replicates the median CV of the rows with a peak in all; CV of the standard. Numbers only, no threshold.
  - `report.rs` (`report/2`): rows, files, cells per state, view and `qc/2`; `header_lines` are the `#` lines at the head of the exports.
  - `tabcheck.rs` with `tabcheck/{basic,cells,env,num,pairs,series}.rs` (`tabcheck/1`, schema `docs/schemi/tabcheck-1.json`): 15 deterministic checks of the table (`size`, `blank`, `contaminants`, `qc_cv`, `qc_intensity`, `rt_drift`, `duplicates`, `adducts`, `isotopes`, `insource`, `long_traces`, `homologous`, `missing`, `structure`, `polarity_units`), each with `value`, `threshold`, `flag` (`ok|note|warn`), `rows` (≤ 20 ids, in a pair the heavier row first), `files` and `proof` (the numbers used). Numbers only: a flagged row is a candidate, never an identification.
    - Input: table, `Sample` (roles blank, qc, sample), optional view and `Options {polarity, expected_polarity, mz_tol_da}`; 0.005 Da in HR, from 0.1 Da up it is unit resolution (isotopes at 1 Da, no homologous series). The areas are the measured ones, the RT window of two coeluting rows is the median FWHM (0.59 × the cell width).
    - A check that lacks a role (blank, QC), the files or the accurate mass gives `note` with null `value` and `proof.missing`, never a number. The constants (ESI+ adducts Na 21.98194, NH4 17.02655, K 37.95588 and ESI− Cl 35.97668, HCOO 46.00548; isotope 1.00336 Da; thresholds) are at the head of the modules with their comment.
    - `structure` is `mzlab_core::pca` on the 2 000 most intense rows (like `table.pca`), `homologous` is `stat::analyse` (KMD) with ≥ 5 members at consecutive steps and RT in order (|ρ| ≥ 0.8).
    - Cap of 6 000 estimated tokens (`ceil(bytes / 3)`, like `context/1`): beyond it, examples and pairs are halved (`truncated` true), the 15 checks stay. Same bytes for the same input.
    - Routes: site `table_check(read, size, campioni_json, spec, polarity, options_json)` of the `table` `.wasm`; desktop `feat/table` with `kind:"check"`; both call `core::tabcheck_json`, and the native example `table` writes `check.json`. Proofs: `cargo test -p mzlab-feat --test tabcheck` (tables made like the files of `tools/dati_sintetici.py`: contaminant in every file, sodium adduct, isotopes, three in-source fragments, QCs that lose a quarter of the signal, RT drift) and the parity in `tests/test_feat_table_wasm.py`.
  - `plausible.rs` (`plausible/1`, `docs/schemi/plausible-1.json`): seven checks on the shown values, read against `Limits` (defaults in parentheses): `non_finite`, `mz_range` (20–5000), `rt_range` (0–600 min), `negative`, `peak_shape` (width in (0, 30] min and apex), `empty_rows`, `ppm_error` (beyond 50 ppm from neutral mass + adduct).
    - `flag` `ok|warn` (`note` for `empty_rows`, `na` with `missing` `accurate_mass` at unit resolution or `identity` without identity columns), `count`, ≤ 20 ids. The resolution is decided by `mz_tol_da` if the page passes it (≥ 0.1 Da = unit), otherwise by the recipe saved in the table (`recipe::is_unit_text`): LR and HR are not written in the engine; the box is a coherence check, it gives no answers.
    - Routes: site `table_plausible(read, size, options_json)`, desktop `feat/table` with `kind:"plausible"` and `options`; `options_json` = `{"mz_tol_da","mz_min","mz_max","rt_max","width_max","ppm_max"}` (empty = defaults; the page takes them from `a.mzTolDa` and `a.plausibleLimits`); Flow step `table.plausible` (same parameters, `--set INSTANCE.NAME=VALUE`); proofs `cargo test -p mzlab-feat --test plausible` and parity of `plausible.json` in `tests/test_feat_table_wasm.py`.
- **Exports** (`export.rs`, `export_ms.rs`, `ms2spec.rs`; `Ctx` = table, samples, view, SHA-256, polarity): the rows are those of the view (all without one) and the areas the normalized ones when there is a view; same bytes in the site and the desktop.
  - `csv_full`: `id, mz, rt, rt_range:min, rt_range:max, charge` and for each file `datafile:<F>:area|height|feature_state`; the states are `DETECTED`, `FILLED`, `TARGETED`, `UNKNOWN` (cell without peak, without area or height); with `mzmine_states` filled and targeted become `ESTIMATED`. Areas to 8 significant digits.
  - `quant`: the FBMN table (`row ID`, `row m/z`, `row retention time`, `correlation group ID`, `annotation network number` at -1, `best ion` and `neutral M mass` only for the rows with a hypothesis, then `<sample>.mzML Peak area`).
  - `mgf` (FBMN, `FEATURE_ID` = row id) and `sirius` (`.ms`, `feature_<id>`, without formula): one entry per row with spectrum, `#` lines at the head from the report. The row spectrum is a single one in the program (`ms2spec::spectra_with`, also used by the `evidence_sources_to` proofs): in the `.mzidx` of the file `ms2_file`, among the MS2 with a window that contains the m/z and time inside the peak edges, the one with the highest TIC (`MERGED_ACROSS_N_SAMPLES=1`); a single pass on the MS2 peaks of each file.
  - Row spectrum options, off by default (`Recipe.ms2`, outside `file_text`: the fingerprint of the `.mzfeatf` does not change; keys read by `run.rs::apply_params`, in `export_ms2` from the view spec): `ms2_spectrum` (`best` | `consensus`: all the suitable scans of the row, then the files where it has a peak, `msntree_build::consenso` at 8 ppm, 40 %, 0.5 %, intensity 100 = strongest peak).
  - `ms2_background`: removes the peaks that recur in the blanks (10 % of the MS2 with base peak ≥5000 of each blank, 80 % of the blanks, at most 25; 0.01 Da, 0.5 Da in `unit`), never the precursor ±1. Without blanks no subtraction and `SpecInfo.bg = "no_blank"`; the file carries `# MS2 background: <state>, <n> peaks removed`.
- **`.mzfeat` format version 2** (`store_base.rs::TABLE_FORMAT`, also `store::TABLE_FORMAT`).
  - It contains `id` and the summaries as arrays, and in the meta `summaries` (0/1); the identity columns are optional, with `identity` (0/1) in the meta.
  - A version 1 file is read with empty summaries; a truncated file is rejected even if the missing arrays are ones the reader does not ask for.
  - `sort_rows` also runs in `evidence_to` after the targeted rows are added, so the ids written are the final ones.
- **Row for the page** (`row.rs`): `row` gives `row/2` (m/z, RT, edges, charge, `quality` with words `shape`/`snr`/`points`, `iso_m1`, `ms2`, `ident` with adduct and sources, one cell per file with type, time, area, height, apex, width and state in words; summary not computed = `null`, unknown id = `error.rowNotFound`); `traces` gives `row_traces/2` from the `.mzidx` of the series: one XIC per file (edges ± 3 widths, at most 400 points that keep the maximum of each group), the MS1 at the apex of the file with the highest area (−1…+4 Da) and the MS2 chosen as for the MGF export.
  - Proofs: `tests/row.rs`.
  - `row/2` also has `family`: size and ions with m/z, RT and role (the reference first), `null` in the per-ion table (`Aligned::family_size`); the proofs of the edges are in `famiglia/1` (`famrecord.rs`, `mzfeat-tests.md`).
- **Proofs**: `tests/samples.rs` (names → types, round trip, refusals, TSV), `tests/store.rs` (ids, counts, sorting that keeps rows whole), `tests/export.rs` (writers, MS2 choice on a synthetic index), `tests/view.rs` (factors, rules, spec, qc, report), `tests/rowident.rs` (identity, per-file data, table without identity), `tests/rowmeta.rs` (medians, MS2, M+1/M, files in memory and in slabs).
- **Inclusion list from the expected products** (`export_inclusion.rs::inclusion_expected`, step `export.inclusion` of `steps/table.rs`, executor `mzlab-cli/src/flow_inclusion.rs`): each expected product (neutral formula, RT, priority) × the chosen adducts, RT window ± `rt_window` (start never below 0), same columns as the mzFinder list (`legacy::out::inclusion_row`, which `inclusion_csv` also uses), rows ordered by RT, m/z, formula. It assigns no levels or verdicts. Proof: tests of the module (timolol).
- **mzTab-M** (`export_mztab.rs::mztab`, step `export.mztab` of `steps/table.rs`, `kind` `mztab` of `export_table` in the `table` `.wasm`): MTD (one run and one assay per file, one study variable per group), SML and SMF for each row of the view (areas per file, mean and variation per group, `NaN` where the file has no peak, RT in seconds). It does not write the SME section: it requires the reference to the source spectrum, which the table does not keep.
  - The file opens with a `COM` line in English: it carries only the quantification, the identification columns have no score.
  - Every row has reliability 4 (default scheme 1-4, "unknown compound"): the export adds no identity and raises no level (a row with a hypothesis carries only the adduct). Written from the public specification; proof: `tests/export_mztab.rs` (reader in the test). The check with the official validator is done by hand.
