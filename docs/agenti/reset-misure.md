# Reset del browser: misure
Misure del reset sul sito costruito, per i tre percorsi: «Reset completo» (`QQRESET.run("all")`), «Solo file e sessione» (`QQRESET.run("files")`) e il reset dell'avviso d'errore (`window.qqHardReset()`). Il funzionamento sta in `dati-3200.md` («Reset vero»); qui ci sono solo i numeri e ciò che resta.

## Come si misura
- `python3 tools/prepara_sito.py`, poi `python3 tests_e2e/misura_reset.py [--rep 3] [--only all_a_50,files_b_50] [--out FILE] [-v]`; poi cancellare `site/`. Stampa una riga JSON per giro e una tabella (mediana/massimo); non asserisce nulla. `verifica.py` legge solo `e2e*.py`, quindi la CI non lo lancia.
- Sonda `tests_e2e/lib_reset.py`: `seed(pg, n)` crea `n` file finti in `mzlab/files` e `mzlab/idx`, una cartella e un database inventati, `librerie`, `mzlab-libs`/`mzlab-libdir`, una lista, una molecola, tre cache e tre preferenze; `probe(ctx)` avvolge, solo per il tempo, `removeEntry`, `deleteDatabase`, `caches.delete`, `unregister`, `qqEngineStop`, `QQRESET.run`/`last`, i `setItem` durante `QQ_RESETTING`, `lr_clear` e `qqReady`; `state(pg)` elenca OPFS, database e righe per store, cache, localStorage, service worker e `storage.estimate()`.
- Le chiamate al binding durante lo scaricamento della pagina si perdono: la sonda tiene il registro anche in sessionStorage (`__rs.prev`) e la pagina dopo lo rimanda.
- Varianti (50 file): a = motore fermo, solo file finti; a2 = due file d'esempio aperti; b = la stessa scheda indicizza un mzML sintetico grande (~33 MB, `tests_e2e/mzml_grande.py`); c = seconda scheda aperta e ferma; d = seconda scheda che indicizza; e = liste utente lette una volta (`LISTE.ready()`: la connessione di `liste.js` resta aperta).
- «Totale» = dal clic al `qqReady` della pagina nuova. Dopo «tutto» e `qqHardReset` la pagina nuova ricarica una volta per l'isolamento (`isolateOnce`, due richieste di documento): il totale lo comprende (~0,5-1 s). «files» ricarica una volta sola.
- WebKit e Firefox: non disponibili nel container (solo Chromium).

## Cosa resta
- **tutto**: OPFS solo `mzlab/` con `conv/ feat/ files/ idx/ tiles/ warm/` vuote (le ricrea la pagina nuova); `mzlab_lab` ricreato vuoto; cache solo `mzlab-app-<versione>` (a volte `mzlab-big-*` del prefetch a riposo); localStorage solo chiavi scritte dalla pagina nuova (`mzlab.avvii`, `mzlab.migrato`, `mzlab.barra.*`, `mzlab.memBudget.log`) più `mzlab.sessione` quando c'erano file aperti.
- **files**: restano `librerie`, `mzlab-libs`, `mzlab-libdir`, le preferenze, le cache che non iniziano con `mzlab-big-` (anche `mzlab-app-*` e cache estranee); spariscono cartella e database inventati; `mzlab_lab` ricreato con `kv:1`; `liste_utente` e `molecole` si perdono (il modo cancella tutto `mzlab_lab`).
- **qqHardReset**: restano cartelle, database e cache che non conosce per nome (`synt-invented`, `synt-invented-db`, `synt-other-cache`), oltre a `librerie`, `mzlab-libs`, `mzlab-libdir`.
