# Tests in the cloud environment (session container)
The command is in CLAUDE.md
- **Chromium**: Playwright 1.63 looks for `/opt/pw-browsers/chromium-1243`; the link `/opt/pw-browsers/chromium` may point to an older version. If it is missing, `verifica.py` does NOT go red: it prints `SKIP e2e: Playwright/Chromium not available: python3 tools/verifica.py --setup`. Prepare it with `python3 tools/verifica.py --setup` (installs Chromium if needed and then runs the whole verification, ~10 min). To check only the browser: `python3 -c "from playwright.sync_api import sync_playwright as s; p=s().start(); p.chromium.launch().close()"`.
- **One round at a time**: launched in the background, `verifica.py` prints only at the end; the limit for background commands is 30 minutes (explicit `timeout` for long tests). An `e2e*.py` process left alive is stopped by PID (never `pkill -f` with words that appear in the command).
- **Tests that build the site** (`e2e13`, `e2e_mzidx`, `e2e_avvio`, `e2e_identita`, `e2e_libreria_*`, `e2e_rust`, `e2e_untarget`): they are skipped until `site/` exists. First `python3 tools/build_site.py` (no download, writes `site/`), then `verifica.py --solo e2e13,...`; afterwards `site/` is deleted. `e2e_rust` also needs the WASM (absent in the cloud), and so does `tools/bench.py`.
- **Data**: without `mzlab-dati` the files are synthetic (`tools/dati_sintetici.py`): no `.dam` → `e2e9`, `e2e_dam_incoerente` skipped. A `SKIP` step does not turn the test red.
- **Known reds**: the list is `tools/noti_rossi.txt` (unstable under load, non-blocking); a red not listed must be compared with `origin/main` as below.
- **Unstable under load**: `e2e_tour`, `e2e_tocco`, `e2e_hr_scanbin`. With several parallel rounds or less CPU they can give false reds: rerun them with `--solo`.
- **Is a red yours?** Rerun the same `--solo` on a worktree of `origin/main` (`git worktree add --detach <folder> origin/main`): red there too = not yours; green there and red on yours = yours. A red that passes on a second try alone is load, not code; if a test cites texts, ids or buttons changed by a PR, the test must be updated in the same PR that changes them.
