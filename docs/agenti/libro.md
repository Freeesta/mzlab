# Libro (convertitore Markdown → HTML)

- `tools/libro/` (Python puro, MIT, deterministico) converte una sezione `.md` del Libro in una pagina HTML in stile Teoria; legge e scrive solo le cartelle date (`cli.py --src --out [--pubblico]`). Dialetto e costrutti ammessi: `tools/libro/LEGGIMI.md`; ciò che non conosce si ferma con `file:riga` (`LibroError`).
- `pagina.py` assembla la pagina, `blocchi.py` i blocchi, `inline.py` il testo corrente; l'HTML grezzo nel Markdown viene escapato, salvo il blocco recintato ```` ```html ```` (solo per i capitoli elencati in `tools/libro/importati.txt`, `grezzo.py`, senza script né `on*=`). `cli.py --teoria` scrive capitoli pubblicati; i sorgenti dei capitoli stanno in `mzlab/web/teoria/src/` (un file `NN-slug.md` per capitolo) e `tests/test_libro_generato.py` ne controlla l'HTML accanto.
- `importa.py` porta in Markdown un capitolo HTML una volta sola (blocco per blocco, o blocco grezzo se il DOM canonico di `dom.py` cambierebbe) (l'import è finito: i capitoli si modificano dal sorgente `.md` o dall'editor della Teoria e `tests/test_libro_generato.py` tiene la pagina uguale al sorgente).
- `--pubblico` toglie i blocchi `<!-- privato -->` e rifiuta i `[I]` rimasti. I file `*.appunti.md` e `*.qa.md` non si convertono.
- Prova: `tests/test_libro.py` sulla fixture sintetica CC0 `tests/data/libro/` (HTML d'oro `S1_prova.html`: si rigenera chiamando `converti()` sul `.md`). Il testo vero del Libro sta solo nel repository privato `mzlab-dati`, mai in questo.
- `crates/mzlab-libro` (rlib senza dipendenze): il convertitore in Rust, `convert(testo, nome, &Options{pubblico, teoria, raw_ok})`, stesso dialetto e stessi errori `LibroError{file, line, msg}` di `tools/libro` (`inline.rs`, `blocks.rs`, `page.rs`; gli snippet `inline:` e il tema sono incorporati dai file di `tools/libro/`). Prova di parità `cargo test -p mzlab-libro`: ogni `mzlab/web/teoria/src/*.md` deve dare byte per byte l'HTML committato accanto. `slug()` conosce solo le lettere latine accentate comuni (nei capitoli Teoria gli id dei titoli sono espliciti).
- `crates/mzlab-libro-wasm`: il ponte `mzlab-libro/3` (`version()`, `headings_retitled`, `reindex_chapter`, `convert_chapter(testo, nome, raw_ok)` = pagina Teoria, errore `file:riga: messaggio`; `preview_chapter` = la stessa pagina con `data-src` sui blocchi modificabili; `edit_preview_block(testo, nome, raw_ok, src, html)` = il sorgente con quel blocco riscritto);
- `.wasm` a parte `wasm-feat/libro/` (voce `libro` del manifest, tetto `limit_libro` in `tools/build_feat_wasm.sh`, 152 008 B misurati), per l'editor della Teoria in modalità amministratore. Prova: `tests/test_libro_wasm.py` (stessi byte dell'HTML committato, attraverso Node).

## Editor del Libro (pagina admin)
- `mzlab/web/libro/editor.html` (+ `editor.js`, `gh.js`, `vault.js`, `norm.js`, `editor.css`): editor visuale (Milkdown/Crepe + KaTeX, bundle in `mzlab/web/vendor/libro/`, costruito da `tools/libro/editor/build.mjs`) che legge e scrive le sezioni nel repository PRIVATO `Freeesta/mzlab-dati` (`libro/testo/`) con l'API GitHub. Il codice è pubblico, il testo del Libro non entra mai nel sito: sta solo in memoria. Interfaccia in inglese (esclusa da `controlla_i18n`), non nel menu, `noindex`.
- Token: fine-grained, solo `mzlab-dati`, solo «Contents: Read and write», scadenza 90 giorni; sigillato con passphrase (AES-GCM + PBKDF2, `localStorage`) o solo per la scheda (`sessionStorage`); mai in URL né in log. CSP propria: `script-src 'self'`, `connect-src https://api.github.com`.
- Salvataggio: un commit diretto su `main` del repository privato per file (PUT con lo sha letto): se qualcuno ha cambiato il file risponde 409, l'editor non sovrascrive e mostra il testo dell'utente. «History» = `GET /commits?path=`; caricare una versione vecchia non salva finché non si preme Save.
- Tre file per sezione: `X.md`, `X.appunti.md` («My notes»), `X.qa.md` («Questions & answers»); gli ultimi due non si convertono. `norm.js` toglie `\[`, `\~`, i punti elenco `*` e le righe vuote in eccesso scritti dall'editor. Equazioni: blocco `$$…$$` con `{#eq:id}` sulla riga dopo.
- Prove: `tests_e2e/e2e_libro_editor.py` (GitHub simulato), `tests/test_libro_editor.py` (CSP, normalizzazione, nessuna riga del Libro privato nel repository pubblico).

## Editor della Teoria (pagina admin)
- `mzlab/web/libro/teoria.html` (+ `teoria-editor.js`, `pr.js`, `wasm.js`, `teoria-editor.css`; `vault.js` con un proprio slot): modifica il sorgente Markdown di un capitolo (`teoria/src/NN-*.md`) in una textarea, lo converte con il `.wasm` `libro` (manifest di `wasm-feat/`, SHA-256 controllato prima di eseguirlo), mostra l'anteprima (iframe `sandbox="allow-same-origin"`, senza script) e invia la modifica come UNA pull request sul repository pubblico. Interfaccia in inglese, non nel menu, `noindex`; CSP `script-src 'self' 'wasm-unsafe-eval'`, `connect-src 'self' https://api.github.com`.
- Caricando un capitolo l'editor controlla che il convertitore riproduca la pagina di `main` dal sorgente di `main`; altrimenti non lo apre. Il capitolo ammette blocchi ```` ```html ```` solo se è in `tools/libro/importati.txt` (letto da `main`).
- «Send change»: se una PR dell'editor (ramo `libro/teoria-…`) è aperta non scrive niente; se `main` ha cambiato sorgente o pagina dopo il caricamento risponde conflitto senza scrivere; altrimenti crea il ramo `libro/teoria-NN-<capitolo>-<aaaammggoomm>` da `main`, committa il `.md` e la pagina `.html` generata, apre la PR e attiva l'auto-merge (GraphQL, squash); se l'auto-merge è rifiutato lo dice. Mai scritture dirette su `main`, mai push forzati.
- Titoli: si cambia solo il TESTO dei titoli h2/h3 (dall'anteprima, `data-src` `h<riga>`, o dal riquadro sorgente); ogni sezione mantiene la sua àncora: la riga ha `{#id}` e, se non lo aveva, l'editor scrive quello che la sezione ha ora (`teoria.js` lo ricava dal testo), perché i collegamenti non si rompano.
- Restano rifiutati, con un messaggio (`titles.rs`, `headings_retitled`): titoli aggiunti, tolti o spostati, il cambio di livello, il titolo del capitolo (h1) e il glossario (`21-`).
- Se un titolo cambia, l'editor invia come terzo file `indice-ricerca.js` con le righe di quel capitolo rifatte (`index.rs`, `reindex_chapter`: porta in Rust la parte per capitolo di `tools/genera_indice_teoria.py`); `crates/mzlab-libro/tests/index.rs` prova che dà indietro l'indice committato, byte per byte, per ogni pagina; se `main` ha cambiato l'indice dopo il caricamento non scrive niente.
- Token: fine-grained, solo `mzlab`, «Contents: Read and write» e «Pull requests: Read and write», scadenza 90 giorni; stessa custodia dell'editor del Libro (passphrase o scheda).
- Prove: `tests/test_teoria_editor.py` (CSP e flusso di `pr.js` su un GitHub finto in Node), `tests_e2e/e2e_teoria_editor.py` (pagina vera, `.wasm` vero, GitHub simulato).
- Modifica dall'anteprima: un clic su un paragrafo semplice, una voce di elenco di una riga o una cella di tabella (`data-src` = righe `a-b`, riga `n`, riga e colonna `n:c`) lo rende scrivibile; Invio o un clic altrove lo conferma, Esc lo annulla.
- Il blocco modificato torna al convertitore (`crates/mzlab-libro/src/edit.rs`, `frag.rs`): HTML in linea → Markdown (`**`, `*`, `_`, `~`, `^`, `` ` ``, `$`, `[@k]`, `[I]`, `@eq:`, `[testo](indirizzo)`; ogni altro elemento è rifiutato), righe sostituite, poi la pagina rifatta deve dare lo stesso HTML del blocco (`canon`): se no «edit it in the source box».
- Titoli, equazioni, riquadri, figure, blocchi ```` ```html ````, elementi annidati e blocchi il cui HTML non si rilegge (tag incrociati nel sorgente) non hanno `data-src`: un clic dà l'avviso. `cargo test -p mzlab-libro --test parity` prova che ogni blocco modificabile dei 23 capitoli, restituito invariato, lascia il sorgente identico.
- Annulla/ripeti e bozza (`storia.js`): ogni capitolo ha una cronologia in memoria (`makeHistory`, 200 stati; un passo dopo un annulla scarta i «ripeti»); i passi sono le modifiche dall'anteprima e la scrittura nel riquadro (raggruppata a 600 ms). Pulsanti Undo/Redo e Ctrl+Z / Ctrl+Maiusc+Z / Ctrl+Y nel riquadro.
- La bozza non inviata (testo, riga di sommario, sha di partenza; MAI il token) sta in `localStorage` (`mzlab.libro.teoria.draft.<capitolo>`). Riaprendo il capitolo: se parte dallo stesso sha di `main` si offre «Restore the draft»; se il capitolo è cambiato si offre solo «Copy the draft» (non si rimette per non sovrascrivere; l'invio confronta comunque gli sha). «Discard the draft» e l'invio la tolgono; con lo storage bloccato l'editor funziona senza bozza.
- Prove: `tests/storia_node.mjs` con `tests/test_teoria_editor.py` (cronologia, bozza, token assente, storage bloccato) e i passi `history_and_draft` di `tests_e2e/e2e_teoria_editor.py`.
- Anche didascalie e domande: `data-src` `t<riga>` (riga `Tabella: …`, elemento `<caption>`), `f<riga>` (testo tra virgolette di una figura `![…](… "…")`, in uno `<span>` solo nell'anteprima; senza `"` nel testo), `qs<riga>` (domanda `??? …`, `<summary>`), `qa<a>-<b>` (righe della risposta, che diventano una riga). Nell'anteprima le domande sono aperte e lo spazio in un `<summary>` si scrive invece di piegarlo.
