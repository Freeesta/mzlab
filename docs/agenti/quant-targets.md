# Target list over many files (`quant.targets@1`, `mzlab-cli quant targets`, `quant union`)
Files: `crates/mzlab-feat/src/quant_targets/` (`targets.rs` table, `params.rs`, `run.rs` engine, `text.rs` table/log/plan/JSON), `crates/mzlab-cli/src/quant_targets_cmd.rs` (CLI), `flow_quant_targets.rs` (descriptor + executor), `crates/mzlab-feat-wasm/src/run_quant.rs` + `flow/lazy/flow-web-quanttargets.js` (browser).
Tests: `crates/mzlab-feat/tests/quant_targets.rs`, `crates/mzlab-cli/tests/quant_targets_cli.rs`, `src/flow_quant_targets_tests.rs`, `tests/test_quant_targets_wasm.py` (wasm = CLI = flow run, byte for byte), `tests_e2e/e2e_flow_quant_targets.py`; synthetic mzML in `crates/mzlab-feat/tests/common_quant/`.

## What it does
- One pass per file: the targets are grouped by polarity and each group is one `Routes::sweep_matrix` over the index (every XIC at once, cut in chunks of half `budget::TARGET_BYTES` divided by the files read at once, one chunk held at a time; a chunk changes no column).
- The trace is rounded like `trace xic` (rt 4, y 1 decimals), then `peakq_lrauto::lr_auto_integrate` (the engine of `peak auto-lr`) between `rt_min` and `rt_max` with S/N 0 and 2 points (every peak is kept and `min_sn`, `min_points`, `min_shape` judge it afterwards; `peak auto-lr` itself defaults to S/N 5 and 5 points), the tallest peak of the window, and `peakq::quality` for the shape.
- It replaces one `trace xic | peak auto-lr --set lr_sn=0 --set lr_min_pts=2` process per target and file; the areas are the same numbers (CLI test `areas_are_those_of_the_trace_xic_and_peak_auto_lr_commands` runs both commands).
- The tallest peak whose apex is inside the window is the row; `peaks_in_window` says how many there were. Area counts x s (engine counts x min x 60), height counts, rt min.
- Speed: the `.mzidx` is sorted by m/z, so a sweep reads only the peaks inside the target windows (never every scan). `prepare` checks the run, `Job::file` is the pass over one file (its index, then every target) and `Job::finish` joins the passes in file order: the CLI runs files on `--workers` threads (default one per core, 1 to 8 `MAX_WORKERS`, more refused; `par::par_map_with`), the Flow executor on one per core up to 8 (`par::par_map_with`), and the bytes are the same for any count (test `the_bytes_are_the_same_whatever_the_workers`).
- Benchmark: `tools/bench_quant_targets.py` (245 synthetic files x 250 targets on 4 vCPU: 9.4 s from mzML, 4.1 s from `--cache`; `measurements-speed.md`).
- No new cache: the CLI builds each index once per run in a temporary folder (or takes it from `--cache DIR` through `idx_cache`); `.mzidx` inputs are opened as they are. Same inputs give the same bytes.

## Inputs
- Targets: CSV (`,`, `;` or tab) or JSON (`[{...}]` or `{"targets":[...]}`): `id`, `mz`, `rt_min`, `rt_max`, optional `polarity` (`+`/`-`, empty = every scan) and `role` (`target`, `standard`/`parent` = reference). Duplicate ids, `rt_min >= rt_max`, an id with a control character, bad numbers: `err.quant.targets.table` (row = the CSV file line, header = 1, or the 1-based JSON item; detail); no row: `err.quant.targets.empty`.
- Files: mzML, maker's files and folders the readers take, folders holding them (name order, a set folder is one file, subfolders read), `.mzidx`; a `.mzidx` beside its source input is skipped (a note), two inputs of one file name are refused (`err.cli.input.twice`, the name is the row key). None: `err.quant.targets.noFiles`.

## Parameters (CLI flag = step parameter)
- `da` 0.5 (XIC half window, Da, 0.001 to 5), `min_sn` 3, `min_points` 5, `min_shape` 0.5 (Gaussian correlation), `offset` `0`, `blank_pattern` empty, `ms_level` 1, `smooth_half` 0 (= automatic per trace, column `smooth_half`), `valley` 10 %. A value out of range is `err.quant.targets.param` (exit 2), never clamped.
- `rt_ref` `off` (default), `auto` (first standard/parent row, any polarity) or a target id, each with `@RT` where it is expected (else the centre of its window); `rt_span` 0.6 min (0.05 to 5): the reference apex (tallest peak of its m/z, after its polarity's offset) is looked for in its window widened by `rt_span`, the shift = apex - expected is added to the window of EVERY target of that file (rows keep the measured `rt`; the column `rt_shift_min` is the shift).
  A peak under `min_sn`/`min_points`/`min_shape`, or none: shift 0, status `weak`/`not_found`, `warn.quant.targets.rtRefNotFound`; apex on the search border: applied, `warn.quant.targets.rtRefEdge`; `auto` with no reference row: `warn.quant.targets.noRtReference`, nothing moved. Off writes no new column or key (every old byte is kept).
- `offset`: a number of Da (|D| <= 0.6), `auto:MZ[@RT]` (the `mzcal` spec of `trace xic --mz-offset`), or `auto`: measured per file and polarity on the first reference row of that polarity (else of none), at the centre of its window. No reference: 0, `warn.quant.targets.noReference` and a choice in the log. The evidence of every measure (`mzcal::Offset::evidence_json`) is in the log; a failed measure keeps 0 with its mzcal warning.

## Output
- CSV header `file,id,area,height,sn,rt,flag,state,points,shape,start_rt,end_rt,peaks_in_window,smooth_half,mz_offset_da`, one row per file and target in input order, never hidden. `--json`: `quant-targets/1` (`rows` as objects with the same keys, numbers or `null`, and `log`). `--dry-run`: `quant-targets-plan/1` (parameters, files with their blank flag, targets, rows), no data read.
- Flags (`;`-joined, `ok` when none): `no_scans` (no scan of that level and polarity: `warn.quant.targets.noScans`), `no_peak`, `below_threshold` (S/N < `min_sn`, numbers kept), `bad_shape` (points or shape under the minimum), `edge` (apex on the first or last scan inside the window), `in_blank` (a file matching `blank_pattern` has the target detected; set on the other files' rows with a peak; a pattern matching no file: `warn.quant.targets.noBlank`). Detected = a peak without `no_scans`, `no_peak`, `below_threshold`, `bad_shape`.
- State (one per row, the words of `mzlab_feat::EVIDENCE` of the Dig): `detected`; `forced` (a peak under `min_sn` or the shape minimum, its numbers kept and flagged, never hidden); `absent` (no peak in the window or no scan, numbers empty). No value is gap-filled, so there is no `filled` state.
- Sparse data: unit-resolution files of whole ion counts where most scans hold no peak at the target are read as they are (an empty scan is a 0 in the trace); a weak peak gets its own S/N (test `sparse_ion_counts_give_a_peak_with_its_s_n_and_stray_counts_none`).
- Log `quant-targets-log/1`: `params`, `files` (`file`, `blank`, `offsets` per polarity with `mz_offset_da`, `reference`, `evidence`, `detected`; with `rt_ref` also `rt_ref` {`reference`, `expected_rt`, `apex_rt`, `sn`, `search`, `shift_min`, `status` ok|edge|weak|not_found}), `choices` (`offset_reference.+|-|any`, `rt_reference`, `rt_expected`, `smooth_half`), `warnings`. With `rt_ref` on the CSV and rows gain a last column `rt_shift_min` and the params `rt_ref`, `rt_span`.
- Hints (stderr of the CLI only, never in the table or log; `Outcome::hints`, keys `note.quant.targets.*`): the first reference row missed (not detected) in a non-blank file at offset 0 names `--offset auto`; its apex moving 0.1 min or more between files with `rt_ref` off names `--rt-ref auto`. Task words are in `catalog/related.rs` (`commands --find`: «mass offset per polarity», «rt drift internal standard», «delay of the uv detector» finds `quant targets` / `dad delay`).
  The `.wasm` leaves the hints out (`cfg(target_arch = "wasm32")` in `rtref.rs`/`run.rs`: the site has no stderr; it saves 2.4 KB of the 5 % rule); showing them in the page is a follow-up.
- Offset per polarity, today: `quant targets --offset auto` measures it per file AND polarity on the first reference row of each polarity; `trace xic`/`features --mz-offset auto:MZ` measure one offset on the `--polarity` in use (`mzfeat-lr.md`). Follow-ups: the same per-polarity spec for `trace xic`/`features`; the PDA/UV delay applied at conversion (`dad delay` only estimates, `dad.md`).

## Coverage and limits
- SIM: SIM spectra are MS1 scans and are swept like any scan. SIM/SRM files stored only as chromatograms have no scans in the index: every row is `no_scans` (follow-up: read chromatograms, as `chrom.transitions` does).
- Browser: the `.wasm` `quanttargets` of its own (`mzlab-feat-wasm` feature `quant_targets`, `run_quant.rs`: `flow_quant_targets` over the `.mzidx` of OPFS, the same `quant_targets::run`), 210,630 B optimised, cap 221,184 (`tools/moduli/quanttargets.toml`); no existing module grows (inside flowtab +19.3 %, finder-lr +7.6 %, untargeted +18.8 %, interp +14.7 %). `flow/lazy/flow-web-quanttargets.js` fetches it only when the step runs (worker op `flow_quant_targets`), keeps `<id>.csv` and `<id>.log.json`; files one after the other.

## One list for many series (`mzlab-cli quant union`, AU-4 slice 1)
- What: the feature tables of several series (conditions, replicates; the CSV of `mzlab-cli features`, one per series) become ONE target list (`id,mz,rt_min,rt_max,polarity,role`), the table `quant targets --targets` reads, so a whole campaign is measured once and every cell is integrated or an explicit `absent` row. One list per polarity: run it per polarity (`--polarity` gives the rows that have none the polarity written in the list).
- Code: `crates/mzlab-core/src/series_union/` (`read.rs` the tables, `warp.rs` the RT map, `merge.rs` the matching, `report.rs` the document, `params.rs`), CLI `crates/mzlab-cli/src/quant_union_cmd.rs`, app op `lr_union` (`rpc_lr.rs`), site `union_tables` of the `rotte` `.wasm` (`rust-worker.js` op `lr_union`); schema `union/1` (`docs/schemi/union-1.json`).
- Tests: `series_union/tests.rs`, `crates/mzlab-cli/tests/quant_union_cli.rs` (CLI = engine bytes, exit codes, union then `quant targets` = the pass of each series alone), `crates/mzlab-desktop/tests/parity_union.rs` (app = core = wasm bytes, in `tests/test_parita_rotte_app.py`).
- Rule: rows of different series are one target when m/z agree within `da` (0.5) and RT within `rt_tol` (0.1 min), after the optional map; rows of one series are never merged. Series are matched in the order given against the first row of each target, nearest RT first (then m/z), one row per series per target; the first table fixes the RT frame. Output m/z and RT are the means of the rows; the window covers the window of every row in its own series (no window: RT +- `rt_tol`), plus `pad`, start at least 0. Ids `U0001...` follow polarity (none, -, +), m/z, RT.
- `rt_warp` `off` (default) or `piecewise`: anchors are the rows both a series and the first one hold (nearest in RT within `da` and `rt_gap`, mutual); their shifts are cut in up to 8 blocks along RT, each gives a median point and the map is the line through them (flat outside); fewer than 3 anchors: no map, `rt_warp_skipped` in the choices. This is a map of its own on the tables, not `rtmap.rs`, which needs one aligned table.
- Nothing is hidden: two targets that stay within both tolerances (rows of one series) are `conflicts` and both stay; `min_series` N lists the targets seen in fewer series under `dropped` instead of writing them (default 1 keeps all); every automatic choice is in `choices` (`rt_warp`, `rt_warp_skipped`, `window_from_rt_tol`, `polarity_from_param`, `rt_min_clamped`) and one line each on stderr. Every target lists its rows (series, id, line, m/z, RT, mapped RT, deltas) in `union/1`.
- Exit codes: 0, 2 usage or a parameter out of range (`err.union.param`), 3 a table that cannot be used (`err.union.table`: table, line, field), 4 a file missing, 6 `--out` cannot be written. No `--dry-run`: it reads only the CSVs and writes only `--out`.

## The Flow step (`features.union@1`, AU-4 slice 2)
- What: `table` (many: one alignment per series, the first fixes the RT frame) gives `targets` (the CSV `quant.targets` reads, wire it to its `targets` port) and `union` (`union/1`). The parameters are the flags of `quant union` (`da`, `rt_tol`, `rt_warp`, `rt_gap`, `min_series`, `pad`, `polarity`; `any` = every scan; a table holds no polarity, so run one list per polarity). `flow defaults features.union` lists them.
- Code: `crates/mzlab-feat/src/union.rs` (`union_text`: each `.mzfeat` becomes the `features` CSV with the decimals of `export::csv_full`, ids = row ids, window = the median RT range of the row, then `series_union::run`), descriptor `steps/union.rs`, native `flow_union.rs`, site `flow_series_csv` of the `flowtab` `.wasm` (`run_tab.rs`, one CSV per table) + `union_tables` of the `rotte` `.wasm` (worker op `lr_union`), driven by `flow/lazy/flow-web-union.js` (`tableOf` takes the n-th table of a many port); flowtab does not link the join (it grew it +12.8 %).
- Tests: `crates/mzlab-feat/tests/union_step.rs` (golden `tests/data/union/`, `MZLAB_UPDATE_UNION=1`), `flow_union_tests.rs` (plan = engine = `series_union::route` on the same CSVs, `--set`, range refusal), `tests/test_flowtab_union_wasm.py` (flowtab + rotte = `flow run` bytes).
- Not yet (follow-ups): reading aligned tables that carry `datafile:` states (which states count as a row of a series is a choice to log), a page node with a polarity split.
