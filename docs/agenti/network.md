# rete: the network of products (`rete/1`)

- **What it is** (`crates/mzlab-feat/src/network/`, schema `docs/schemi/rete-1.json`): the parent and the accepted products of `tp/1` (`ST_TP` with formula) as nodes in columns per step, and an arc for every rule whose ion formula change leads from one node to another. It is not an identification: it neither creates nor raises any level. Texts in English only (Tabui). The mzFinder HR view (`21_tpmine_hr.js`) is unchanged.
- **Arcs** (`rete/arcs.rs`, shared with `legacy::network`): `best_pairs` gives for every pair of ions the best arc over all rules (first the kinetics `consistent`/`n/a`/`against` with margin `STEP` 5 min, then from the parent); `counts`, `same_change`, `neutral_mass`. `legacy::network::mass_network` calls them and its output does not change (test: `legacy::network::golden`).
- **Construction** (`rete::build(tp, parent, rows, rules, params) -> Rete`): `NetworkRow` = table row with neutral and ion formula from the best hypothesis, `tmax`, MS2 fragments equal and shifted with respect to the parent. With `--features interp`, `rows_from_interp(table, tp, parent, interp, tmax)` derives them from `RowInterp` (`change[0]`, `vs_parent`). Rows are sorted by m/z, RT, id before anything else: same bytes for every permutation.
- **Thresholds** (`NetworkParams`, written in the output): `ppm` 10 (error of the observed m/z difference against the mass of the change, in ppm of the product); `min_fragments` 0 (an arc from the parent with a compared MS2 keeps at least that many fragments in common, equal or shifted).
- **Layout** (`rete/layout.rs`): step = distance in arcs from the parent (arcs read in both directions); a group the parent does not reach starts at step 1 from its node with the lowest `tmax`. Within a step, order by m/z, RT, id (`pos`). Nodes are the parent and the products touched by an arc.
- **Arc** (`Arc`, `rete/1`): `from`/`to` = row ids, `rule`, `scope` (`literature`/`class`/`generic` from the level), `delta` (change of the ion formula, gains first, true minus U+2212), `dm`, `ppm`, `delta_rt`, `kinetic`, `ms2` (`equal`/`shifted`, only if the source is the parent and an MS2 was compared) and `reason` in words ("shares 5 fragments, 2 shifted by +15.995; the source peaks first").
- **From the `.mzfeat`** (`rete::network_text`, feature `interp`, `rete/run.rs`): reads the table with the `tp/1` block (the areas give the time of the maximum of each row among the treated, from the roles of `samples/1`; without roles `kinetic` is `n/a`) and the `interp/1` rows from the `interp` file (the same file if it carries both); rules `TP_Mine/data/regole_tp_2.json`. Errors: `error.tpNoBlock`, `error.rete.noInterp`.
- **Step `tp.network`** (`steps/tabui_link.rs`, in the Tabui registry after `tp.position`; `docs/schemi/steps-tabui-1.json`): inputs `tp` and `table`, optional `samples`; output `network` (type `transform`: no dedicated type in `DataType`). In the native `mzlab-cli` runner (`flow_network.rs`, `network_job` in `flow.rs`; the crate enables `mzlab-feat/interp`); in the `table` `.wasm` the route `rete_build(table_read, size, interp_read, interp_size, campioni_json, rules, ppm, min_fragments)`.
- **`.wasm` weight** (wasm-bindgen 0.2.129 + wasm-opt 1.4.0 `-Oz`, as `tools/wasm_opt.sh`): `table` 316,447 → 393,828 B (+77,381, cap 512,000 B). In the `interp` `.wasm` the same route would give 507,112 → 570,862 B (+63,750), above the cap: that is why it sits in `table`.
- Tests: `tests/network_run.rs` (file written by the real store: arcs, times from the roles, two files or one, errors), `mzlab-cli` `flow_network_tests` (the plan with the step), `steps_tabui_parity` (thresholds), `tests/network_golden.rs (`mass_network` on a hand-made Dig against `tests/data/mass_network_timolol.json`, saved before the extraction; `MZLAB_UPDATE_GOLDEN=1` rewrites it), `tests/network_interp.rs` (`rows_from_interp`), `tests/network.rs` (synthetic timolol: arcs and directions, columns, isolated group, filters, reason, 720 permutations, schema keys, parent alone).
