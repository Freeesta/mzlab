# Drawing: right-click menu
The core is in CLAUDE.md; the rest of the Drawing area is in `drawing.md`.

- **Right-click menu** (`#ctx`, rows of `disegno-menu.js`: `role=menuitem`, arrows/Enter/Space/Esc): opens with a right click, the Menu key or Shift+F10 and closes with a click or Esc, also inside the Ketcher iframe. `TPDraw.undo` ignores an empty stack (an extra Ctrl+Z shows no error). Clipboard copies (`copyText` in `disegno-menu.js`) say "Copied" only if the browser accepted, otherwise "Copy failed: select the text"; no rejected promise is left unhandled.
- **Menu row registry** (`menuAdd`/`menuFill` in `disegno-menu.js`, also `TPDraw.menu.add`/`.ids()`): no header row: the menu `aria-label` says "Selection (n atoms)" or "Whole drawing". An entry is `{id, when: 'selection'|'whole'|'any', order, label (key or function), title?, show?, run}` or `{id, when, order, rows: async ctx => [{text, title?, id?, run?, sub?}]}`; a row with `sub` (rows of the same kind) opens a submenu (`ctxSub`: `div.ctx-sub[role=menu]`, row `aria-haspopup`/`aria-expanded`;
  it opens on hover, click or tap, with Enter/Space/Right arrow, and closes with Left arrow/Esc, which returns to the row; to the right of the row, or to the left if there is no room; rows at least 24 px tall); same `id` = replaced; every row has `data-row` = its `id` or that of the entry.
  `ctx` = `{K, ev, sel, atoms, bonds, whole, smiles, x, y, kbd}`. Base rows (`draw.js`): `copy-smiles` 10, `info` 15, `links` 17, `center` 20, `partials` 50, `fragments` 60 (the two sides of the bond under the pointer, each capped with H, with `title`). A row that fails stays out, the others do not. Test `e2e_menu_selezione`.
- **Touch copy, cut, paste** (`disegno-appunti.js`, ES module, `initAppunti(d, K, fr)` from `hideMacro`, `window.__tpAppunti` in the iframe; page only, no CLI route or Rust; test `e2e_disegno_appunti_tocco`).
  Registry rows: `select-molecule` (1; only if the selection does not cover the molecule under the finger: `moleculeAt` = `editor.findItem` + `fragment` of the atoms), `copy` 2, `cut` 3, `paste` 4 (`blank: true`: on an empty canvas it is the only row; "Paste here" if `whole`), `delete` 5.
  Long press with the finger: `touch.js` sets `__tpLong` in the iframe (no vibration), `pressRing` of `disegno-tablet.js` draws the `.tp-ring` ring; on an unselected molecule it selects it whole, then opens `#ctx` (rows 44 px tall on touch).
  Copy/Cut press Ketcher's `copy-button`/`cut-button`: `initAppunti` wraps the iframe's `clipboard.write/writeText` and keeps KET (`web chemical/x-indigo-ket`) and molfile in an internal clipboard before the browser can refuse; if nothing arrives it falls back to the molfile of the selection (`pieceMolfile`).
  **Trap**: Ketcher's paste ALWAYS reads `navigator.clipboard.read()` (a synthetic `paste` with `clipboardData` is not enough; its Paste button refuses). During our paste the iframe's `read/readText` return the internal clipboard (`feeding`), then a `ClipboardEvent("paste")` is fired on the `.cliparea`.
  Ketcher's paste tool shows the structure on the cursor (not translucent); releasing places it with its centre on the point; one undo step.
  On touch, Copy/Cut "arm" the paste (`#tp-paste-chip`, "Cancel", Esc): the next touch (`pointerdown` in capture, never seen by the `touch.js` engine) pastes there, a drag moves the preview before release, the browser `click` after release is stopped.
  "Paste here" (empty canvas or no selection) places at once at the pressed point; with the mouse "Paste" attaches the copy to the cursor and a click places it.
  Delete: `tool("eraser")` removes the selection, then the selection tool returns (a synthetic `keydown` Del is ignored by Ketcher).
- **Information...** (row `info`, `disegno-selezione.js`, ES module loaded on first click): `#bigdlg` with formula, masses (m/z if there is a charge, average weight), charge, heavy atoms, rings (aromatic), unpaired electrons and pieces from `selection/1` (`chem::sel` of `mzlab-feat`: `.wasm` `grafo` `sel()`, app `feat/grafo` `kind: "sel"`, CLI `mol sel`, same bytes), from the V2000 molfile of `pieceMolfile` (selection or whole drawing; for a selection a note says that open valences are completed with H).
  InChI and InChIKey from Indigo; a "Copy" button per row (`aria-label` "Copy: name"). Test `e2e_menu_info`.
- **Outside searches** (entry `links`, order 17, `disegno-link.js`, ES module loaded on the first menu opening): two submenus: "PubChem" (`link-pubchem`: "This structure (exact)", "Similar structures", "Substructure") and "Other sites" (`link-other`: "ChEBI: this structure (InChI)", only if Indigo gives the InChI, and "BioTransformer: predict metabolites"); `data-row` = `link-<id>`.
  Order, URL and text to copy come from `link/1` (`chem::link` of `mzlab-feat`: `.wasm` `grafo` `link()`, app `feat/grafo` `kind: "link"`, CLI `mol link`, same bytes as `tools/link_reference.py` in `tests/dati/link_golden.json`).
  The exact search is always the first of the PubChem submenu; the others follow the order of `link/1` (one piece: substructure, then similar). URLs are RFC 3986 percent-encoded (every byte outside `A-Z a-z 0-9 - . _ ~`). The page makes no requests: on click it copies the SMILES (if `copy` is present) and then opens the URL with `window.open(url, "_blank", "noopener,noreferrer")`; the toast (`#toast-container`, `role=status`) says where to paste it. Test `e2e_menu_link`.
- **URLs used**: PubChem `https://pubchem.ncbi.nlm.nih.gov/#query=<SMILES>` plus `&tab=similarity` or `&tab=substructure` (fragment form not verifiable from the container: the rows also copy the SMILES, so if PubChem does not fill it in, just paste it; `search.cgi` is retired); ChEBI `https://www.ebi.ac.uk/chebi/search?query=<InChI>` (form of the ChEBI page); BioTransformer `https://biotransformer.ca/new` (SMILES box, no parameter in the documented URL).

## What is not copied from ChemDraw
- No resource (icons, cursors, templates, style sheets, example documents) and no text (help, tooltips, menus, notices): the words are ours, in `lang/`. No trademark as a feature name ("ChemDraw-style", "ChemDraw-compatible"). No proprietary algorithm rebuilt from the documentation (NMR rules, ClogP, commercial pKa): estimates come from published methods (Crippen) and say "estimate"; journal formats are described with their numbers.
- **ChemDraw-format files** (`.cdxml` text, binary `.cdx`) open in the Drawing tab through Ketcher's own reader (Indigo), by three routes, all wired by `mountImport` of `disegno-file.js`:
  - Ketcher's Open dialog (its file chooser has no `accept` filter): a `.cdxml` that needs a change below is swapped for the changed copy before Ketcher reads the input.
  - A drop on the canvas: `readStructure` reads the file; one starting with `VjCD` goes in as base64, as the Open dialog does.
  - Pasted text: only CDXML with an empty attribute is added by `mountImport`; any other paste is Ketcher's own, and the paste guard of the search box lets a single line through as CDXML only when it opens with the XML declaration, a DOCTYPE or `<CDXML`.
  - No format is parsed in JS. Two changes to the text come first and each is named in the notice `draw.import.changed` under the SMILES field, never silently: empty attributes dropped from every CDXML start tag, quoted values, comments and CDATA untouched (RDKit writes `BondLength=""` and Indigo then draws nothing, without an error), and UTF-16 and 8-bit text decoded as the byte-order mark or the XML declaration says (a UTF-16 declaration is rewritten as UTF-8). Binary CDX changes nothing: it goes in as base64.
  - A file Indigo cannot read (truncated or non-CDXML XML, plain text, an empty file) leaves the canvas as it was and shows `draw.import.unreadable` with the file name; a file the browser cannot read shows `draw.import.failed`.
  - Page only (the editor is Ketcher in an iframe): no Rust or CLI route.
- **What was tried and read** (`e2e_disegno_cdxml_rdkit`, files of `tests/dati/cdxml/` written by `tools/cdxml_fixtures.py` with RDKit's `MolToCDXMLBlock`; `expected.json` holds RDKit's own reading of each file, `MolsFromCDXMLFile`): for every file and every route Ketcher gives the same atom, bond, fragment, charge, isotope and radical counts and the same InChI as RDKit.
  - Read: aromatic and fused rings, wedge and hash stereo, E and Z double bonds, charges, isotopes (`[2H]` is drawn as the label D), radicals (RDKit writes one unpaired electron as `Radical="Singlet"`, and Ketcher and RDKit both read it as a singlet), spiro, bridged and large rings, several fragments on a page, hydrogens drawn as atoms, two pages, a 70 kB file.
  - Composed in the generator, not written by RDKit (it has no text or reaction writer), so checked against the CDXML element names and RDKit's reader only: a reaction scheme (two reactants, an arrow with a text, one product: Ketcher gives the arrow and the two sides), the labels OH, NH, NH2, and Ph and OMe as expanded nodes that hold their own fragment.
  - A label-only node (`NodeType="Unspecified"`, such as Boc) stays a pseudo atom named Boc in Ketcher; RDKit reads the same node as a carbon.
  - Not covered: files from Open Babel, Marvin, ChemDraw and ChemDoodle, binary `.cdx` from any writer but Ketcher itself, text styles, colours, graphics and everything else that is not a structure.
  - Two pages with the same ids are not read by Indigo (blank canvas); a very large file loads slowly (400 copies of a two-molecule drawing, 6,400 atoms, took minutes).
- CDX and CDXML come from Indigo inside Ketcher: never claim fidelity or compatibility with ChemDraw files and no `.cdx` rebuilt in Rust. mzLab writes and documents only open formats: molfile V2000/V3000, SDF, SMILES, InChI, `mol/1`.
