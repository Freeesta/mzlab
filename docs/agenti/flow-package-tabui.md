One PR per step, in the order below.

## DEV prompt (copy it into a new chat)
You are the DEV "Flow Tabui". Zone: `crates/mzlab-cli` and the engines already in `crates/mzlab-feat`. Read `docs/agenti/cli.md`, `rust-flow.md`, `flow-coverage-tabui.md`. For each step: (1) register the descriptor in the CLI registry (`flow::steps()`; the Tabui descriptors are in `crates/mzlab-feat/src/steps/tabui*.rs`, exported in `docs/schemi/steps-tabui-1.json`), (2) an executor that reads the inputs as files and produces a file of the output port's type, (3) test: same result as Tabui on the same synthetic data (never lab data), (4) one line in the area file. Do not touch `.github/workflows`, do not raise the `.wasm` ceilings.

2. **`tp.generate`** (DONE, `flow_generate.rs`) (inputs `parent`, `features`; output `hypotheses`): `crates/mzlab-feat/src/hypo.rs` (`generate(rules, inp, p)`, `HypoParams::default()`, `Registry::to_json`) and the rules in `hypo/rules.rs`, `hypo/sources.rs`; `parent` input as name/neutral formula/SMILES fields (text input or small file), parameters from `HypoParams`.
3. **`tp.link`** (DONE as `tp.link@2`, `flow_link.rs`: descriptor changed, inputs `table samples parent index hypotheses`, the construction of `tp/1` is inside the step) (inputs `table`, `spectra`, `hypotheses`; output `tp`): hypothesis ↔ feature matching in `crates/mzlab-feat/src/steps/tabui_link.rs` (descriptor) and in the code that builds `tp/1` (`interp/`, `evid.rs`); the `tp/1` output is the input already accepted by `tp.network` (`flow_network.rs`).
4. **`tp.filter`** (DONE as `tp.filter@2`, `flow_refilter.rs`: inputs `tp` and `hypotheses`, output `filtri/1`; on top of the output of `tp.link`) (input `table`; output `table`): the product filters of `crates/mzlab-feat/src/interp/filters.rs` (`filtri/1`), same shape as `table.filter` but on the `tp/1` rows.
5. **`tp.position`** (DONE, `flow_position.rs`: `SiteParams`; gap: MSn tree votes) (inputs `tp`, `parent`; output `sites`): `posiz/1`, see `docs/agenti/posizioni.md` (`chem/positions.rs`); proof: classes compatible with the MS2 identical to those of the page.
6. **`features.ms2_link`** (NOT DONE by choice: included in `features.detect`, not separable without changing the bytes; it stays in `BUCHI` with the reason) (inputs `index`, `peaks`; output `peaks`): `crates/mzlab-feat/src/ms2.rs` (`link`) and, for low resolution, `crates/mzlab-feat/src/legacy/lr/ms2link.rs`; parity with `tests/lr_ms2link.rs`.
