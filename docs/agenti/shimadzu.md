# Shimadzu `.qgd` and `.lcd` (module `shimadzu`)

Code: `crates/mzlab-lettori/src/shimadzu/` (feature `shimadzu`, cap 327 680 B), OLE2 container read with `mzlab-core/src/ole.rs`. Written from the real files (7 `.qgd`/`.lcd` and others from the private data repository); the `openszraw` 0.3.0 crate (Apache-2.0) was read only to learn where the streams are, it is not the truth and is not copied. Never in tests or documents: paths, names of people or methods from the real files.

## What it reads
- `.qgd` (GC/MS, GCMSsolution): EI and SIM scans; MRM records (GC-TQ) as SRM chromatograms. `.lcd` of a single quadrupole (LCMS-2020/2050, storage `Mass Raw Data`): scans and SIM per event. `.lcd` of a triple quadrupole (8030/8040/8050/8060, storage `TLM Raw Data`): MRM as SRM chromatograms, no spectra.
- `.lcd` Q-TOF / IT-TOF / 9030 (`QTFL RawData`): recognised and refused with `err.file.shimadzu` (`detail`): without an msconvert mzML it cannot be proved that the m/z are within 5 ppm. An `.lcd` with only `LSS Raw Data` (PDA) is `Fiducia::Forse` and is refused as "no spectrometer data".
- A `.qgd`/`.lcd` that starts as OLE2 but has other storages (`Ignoto`: the `detail` lists up to 8) or the directory beyond the end (`Broken`) is `Forse` and `err.file.shimadzu`, never "type not accepted"; a `Broken` whose header points beyond the end (`Ole::header_cut`: copy cut before the directory) is `err.file.cutShort`. `.lcdx` is not read (not verified to be the same format) and stays in `formati-noti.js` (unsupported).
- A `.qgd`/`.lcd` with sectors used by the FAT beyond the end (`Ole::cut_short`: copy interrupted after the directory) is `err.file.cutShort` (bytes of the file and bytes required) like the one cut before, never an opening with fewer scans or none; test `crates/mzlab-lettori/tests/cuts_warned.rs` (every cut: an error with a key, or whole scans and the lost ones counted by `missing`).
- `riconosci` looks at the names of the OLE directory (`dir.rs` reads few sectors: header, DIFAT, FAT, up to 256 directory sectors; never the whole file) and looks for `GCMS Raw Data`, `TLM Raw Data`, `Mass Raw Data` or `QTFL RawData` with the OLE signature: never the extension alone. `scegli` takes the first storage whose `MS Raw Data` has bytes (the others exist empty in every `.lcd`).

## Streams (same names in all three data storages)
`<storage>/MS Raw Data` (the records), `Spectrum Index`, `Retention Time` (u32 milliseconds per record), `TIC Data` (u64 per record). The number of records is `Retention Time / 4`.
- **`.qgd`, `Spectrum Index`**: `4n` bytes of u32, or `8n+2` bytes (2 bytes and `n` u64) in recent files; `rec::offset`. Record i goes from `off[i]` to `off[i+1]` (the last to the end of the stream).
- **`.qgd`, record**: 32-byte header; `kind` (u16) and `npk` (u16) are at 20 and 22 in files with a 32-bit index, at 24 and 26 in the others (chosen by looking at the first 16 records, `carica::scansioni`). Point = u16 m/z×20 and an intensity of `w` little-endian bytes, with `w = kind`; `kind ≥ 100` is MRM: `w = kind-100` and the point is (u16 Q1×20, u16 Q3×20, intensity). A record is valid only if its length is `32 + npk × (2 or 4 + w)`; the others are counted in `illeggibili` and reported with a warning.
- **`.lcd` `Mass Raw Data`**: u32 index; 64-byte header with the event (u16 at 8), `w` (u16 at 52), `npk` (u16 at 54); point = u16 m/z×20 and `w` bytes. The event is the method segment; the polarity is not decoded (0).
- **`.lcd` `TLM Raw Data`**: `Spectrum Index` of 24 bytes per record (length, number, offset at 8, ...). Record = 12 bytes (marker, uncompressed size, compressed size) and a zlib stream (`mrm.rs::record`, cap 16 MB uncompressed; index entries whose record shares bytes with that of another entry are unreadable, `mrm.rs::shared`: a record is inflated only once); inside, a 44-byte header (u32 count at 40; byte 33 with bits 6-7 = polarity: both 1 negative, both 0 positive) and `npk` points of 12 bytes (u32 Q1×100, u32 Q3×100, u32 counts).
- The TIC of the stream is the sum of the decoded intensities: exact on all the `.qgd` and `.lcd` 2020 tried (`tests/shimadzu_data.rs`); it is the only internal proof, because the data repository has neither an msconvert mzML nor a `.cdf` of these files.

## From the index to the spectra
- Id `scan=<record number>`; filter `EI scan` / `EI SIM` for `.qgd`, `Q1 event N scan` / `Q1 event N SIM` for `.lcd`. A scan with at most 64 m/z whose list (FNV fingerprint) repeats in at least 3 records is SIM (`carica::mark_sim`); it is a heuristic not confirmed by a reference. m/z = u16/20; `Spectrum.wide` only if an intensity exceeds 2^24.
- MRM: one `ChromKind::Srm` chromatogram per (Q1, Q3, polarity) with id `SRM SIC Q1=<q1> Q3=<q3> sample=1 period=1 experiment=1 transition=<j>` (as `wiff/run.rs`) and, if negative, ` polarity=negative`. `CE` and dwell time are not decoded: two transitions with the same Q1/Q3 and different CE would merge. The reader already has SRM chromatograms, so `SrmFromScans` adds none.
- Times in minutes (`ms/60 000`). TIC `Chromatogram` with the `TIC Data` stream.

## Method and header
- `method/1` (`meta.rs`): `strumento` (model from `GCMS Configuration/System` or from the system streams, e.g. "GCMS-QP2010": it is what the file declares, even for the QP2020NX), `software` (version from `File Property`), `campione` (name, id, vial, injected volume), `ms` (EI source for GC, periods/experiments from the events seen with m/z range and, for MRM, the transitions), `campi` (every field read from the `File Property` or from the XML of the `.lcd` properties).
- **Identity**: operator, "generatedBy", "modifiedBy", paths and names of data/method/tune/batch files are `Campo::id()`: they stay in the reader document and do **not** pass into the mzML (`Header::run_params` carries the document without identity). Dates: FILETIMEs reported as the file states them (`YYYY-MM-DDThh:mm:ss`, unknown time zone).
- The `File Property` of a `.qgd` has fixed offsets (`prop.rs::qgd`): version at 4, generatedBy at 20, date at 52, modifiedBy at 60, date at 92, software version at 148, sample name at 204, id at 236, operator at 300, acquisition date at 508, data file at 580, method file at 836, tune file at 1092, batch file at 1604. In the `.lcd` the properties are XML (`@StoX@`/`@FtoX@` for encoded values).

## Not decoded (entries of `avvisi`, `meta.nonDecodificato`)
`GC-2010/GC17A Instrument Parameters` (oven and injector program), `GCMS Configuration`, `LSS Raw Data` and `PDA 3D Raw Data` (UV), `GUMM_Information`, `<storage>/Status`, `MS Status Data`, `Mass Parameters`, `Status Curve`, the embedded `.qgm` method, the records of type 0x0e of a FIA `.lcd` (95 in one file) and 2 records of `kind` 101 of a `.qgd` that do not respect the length formula. Non-ASCII text (CP932) becomes `?`.

## Tests
`cargo test -p mzlab-lettori --features shimadzu`: module unit tests; `tests/shimadzu_synthetic.rs` (containers built in `tests/common/ole.rs` and `common/shimadzu.rs`, invented numbers); `tests/robustness_shimadzu.rs` (truncations, bytes and words at 0xFFFFFFFF, `Limiti` caps); `tests/shimadzu_data.rs` (real files, skipped without `MZLAB_DATI`). Page: `tests_e2e/e2e_shimadzu.py` with `tools/shimadzu_sintetico.py`.
**Not verified (no real file with a reference)**: parity of m/z and intensities with msconvert or `.cdf`; polarity of the `Mass Raw Data` events; the SIM heuristic; the 9030 (refused).
