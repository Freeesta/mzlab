# Fast CI: what is conditional

- **Concurrency**: `test`, `rust`, `sito-rust`, `desktop` cancel the running run on PRs (`desktop` also on pushes to `main`: it does not feed the `pages` gate; a cancelled run is not a failure in `metrics_ci.py`); a push to `main` of `test`, `rust`, `sito-rust` has its own `run_id` group (each commit has its own result, awaited by the `pages` gate).
- **Pages** (`pages.yml`): `wasm-core` (engine, libraries, readers), `wasm-feat-a`/`wasm-feat-b` (the halves of `build_feat_wasm.sh`) and `packages` (libraries, suspects) run in parallel (`pages-*` artifacts of `site/static`); `assemble` runs `build_site.py`, copies the parts, writes the manifest and `build.json`; `deploy` only on `main` and after `gate`. Cargo cache `pages-core-|feat-a-|feat-b-` with `ci_cargo_mtime.py`. `concurrency` `pages-build` without cancellation: a running build finishes, of the waiting ones the latest stays. Site diff: `tools/compare_trees.py A B`.
- **Deploy gate** (job `gate` of `pages.yml`, `tools/ci_cancello.py`): on every push to main that rebuilds the site `deploy` starts only if the summary jobs required of PRs are green on the commit: `test.yml` (`pytest (ubuntu-latest, 3.11|3.14)`, `browser (ubuntu-latest, chromium)`, `javascript`, `tipi (tsc)`), `rust.yml` (`changes`, `rust-ok`), `sito-rust.yml` (`sito-changes`, `sito`); list in `REQUIRED`.
  It queries the API (the commit's `push` runs, last attempt of the jobs) every 60 s during the build. It closes at the first red, cancelled or skipped job, if a workflow does not start within 10 min or after 150 min, and the previous site stays. After the re-run of the red check: re-run of the failed `pages` jobs. It makes "Require branches to be up to date" unnecessary; the lab copy (`qqq-pages.yml`) has no `gate`.
- **Paths of `pages.yml`** on push to main: a push that changes only `docs/` (except `docs/schemi/`), `tests/` (except `tests/golden/`), `tests_e2e/`, `CLAUDE.md`, `.claude/` or other workflows does not republish the site. `rust-misc-a` runs only if its crates or their dependents change (`tools/ci_crates_toccati.py`).
- **`rust`**: `changes` + `rust-ok` (the only gate: it depends on all the jobs) always present; in parallel, only if `crates/`, `Cargo.*`, `rust-toolchain.toml`, `deny.toml` or the scripts of the Rust check change: `rust` (tests of `mzlab-feat`), `rust-core` (core, readers, lib, mol, target), `rust-misc-a` (Attributio, chem, llm), `rust-misc-b` (the other crates: a new one lands here), `rust-wasm` (build, graph), `rust-wasm-guardie` (guards), `rust-det` (determinism), `rust-lint`, `deny`; caches `rust-<os>-lint|wasm|wasmguard|det|testfeat|testcore|testmisca|testmiscb-…`.
- **`deny`** (licences and sources): besides the `rust` filter, it runs only if a `Cargo.toml`/`Cargo.lock`, `deny.toml`, `vendor/` or `rust.yml` changes (`deny` output of `changes`); otherwise it is skipped and `rust-ok` accepts it.
- **`sito-rust`** (`sito-wasm-core|feat-a|feat-b` build the `.wasm` files in parallel and pass them as artifacts to `sito-e2e`, which writes the manifest with `build_feat_wasm.sh site/static manifest`; `sito` summarises): runs on every PR; `sito-changes` (paths: `crates/`, `Cargo.*`, `mzlab/`, `tests_e2e/`, `tests/golden/`, the site tools, the workflow; list in the job) decides whether to build, otherwise the jobs are "skipped" and `sito` is green; on main it runs on every push (gate) and at night, saving cargo caches only at night (`pages.yml` saves the same builds on every push).
  `sito-wasm-*` restore the cache `pages-<part>-` (saved on every push to main; the nightly one is evicted within an hour), with the build identity of `pages.yml` and `MZLAB_CACHE_JOB=wasm-<part>`, shared `ci_cargo_mtime.py` registry; `sito-e2e` restores `pages-e2e-`, saved by the `native-e2e` job of `pages.yml` (only its two native release builds), with `MZLAB_CACHE_JOB=native-e2e`.
- **`desktop`** (job `shim` + 3 OSes): only if `crates/mzlab-desktop/**` changes (includes `tauri.conf.json` and `prepare.py`), the workflow, at night (catches changes of `Cargo.lock` alone), or by hand; on PRs it runs `shim` + Linux build (macOS universal and Windows only on main, at night and in releases); the page in the installer is verified before every release.
- **`release.yml`, job `sito`**: builds the same site as `pages.yml` (same caches, same key `librerie-` with `tools/librerie_catalogo.json`, packages of the normative and in-silico lists), so a release zip contains what would be published; `tools/compare_trees.py` compares the two trees.
- **`notte`, Rust cache**: `browser` and `completa` use the cache `sito-e2e-<OS>-<hash Cargo.lock>-<hash crates>`; `ci_cargo_mtime.py restore` gives unchanged files their old mtime and `record` writes the registry before saving (on a miss only), so the next night only the changed crates recompile. The `test.yml` browser shards build the site in their own step (`tools/prepara_sito.py`) and save the cache right after it, before the tests: a shard cut at its time limit is cancelled, and when the save came after the tests that left main with no cache, so every run built cold (~500 s).
- **`test`** (`pytest (ubuntu-latest, 3.11|3.14)`, `browser`, `javascript`, `tipi`): always run (required checks of the protected `main`). The two names `pytest (ubuntu-latest, 3.11)` and `pytest (ubuntu-latest, 3.14)` are check NAMES produced by the `pytest` job (a gate that depends on the 3.11 shards): Python 3.14 really runs only in `notte.yml`. `tipi` has a 10-minute timeout.
- **`e2e changed files (chromium)`** (job `e2e-cambiati` of `test.yml`, PRs only, NOT required): the e2e tests of the changed files (`tools/ci_e2e_cambiati.py` on the `# covers:` lines of the tests, read by `verifica.py`) without the smoke round of `browser` and without the tests that need `sito`, `wasm` (the .wasm files CI builds in its jobs), `dam` or `veri`.
  A core file would select them all (the full round belongs to `notte.yml`): the job runs a fixed set instead, one cheap test for every `# covers:` prefix among only the green ones of the night's full round (`tools/ci_e2e_verdi.json`, to be rewritten with `ci_e2e_cambiati.py --verdi`; greedy coverage per second, cap 30 s per test and 600 s in total, 150 s timeout per test so that a hanging test becomes a red with its name instead of using up the 30 minutes: the whole job stays under 22 minutes), and writes the names and the reason to the log. Caches read-only, 30-minute timeout.
- Cache: cargo (`registry`, `git`, `target`), `wasm-bindgen`, Playwright browser (saved only on main) and pip, keyed on `Cargo.lock` + `rust-toolchain.toml` (Playwright: `pyproject.toml`) and `restore-keys` on the prefix: a new `Cargo.lock` does not start from zero.
  `build_site.py` downloads nothing (`--pyodide-dir`, `--no-pyodide`: accepted with no effect).
  The MassBank spectral libraries and the mzFinder suspect index (`genera_sospetti.py`) are cached in `site/static/librerie` and `site/static/mzfinder/sospetti`.
- **e2e in parallel**: `verifica.py` launches the e2e tests in the same group (`--paralleli`, default CPUs - 1, at most 6); those with `sito` in `NEEDS` run only with `--solo` (in the `sito-e2e` round), not in the night's `completa`; each test takes a free port (`free_port()`) and, if it uses `Run`, its own working folder; the files that several tests copy into `site/static` go through `copia()`/`scrivi()` of `tests_e2e/lib.py` (they write only if changed, with atomic rename).
  The slowest tests (`SLOW` in `verifica.py`) start first. A new test uses no fixed ports and does not write into `site/` without `copy_file()`.
  `sito-e2e` starts together with the `sito-wasm-*`: it installs, builds the site and the native `--release` builds of the two slow e2e tests, then waits for them (`tools/ci_attendi_job.py`) and downloads the artifacts.
- **mzFinder .wasm in tests**: `lib.build_feat` copies `wasm-feat` and `wasm-lettori` from `site/static` if already built there (CI and local runs), otherwise it launches `tools/build_feat_wasm.sh` one at a time (file lock, they share cargo's `target/`).
- **`.wasm` builds** (`tools/build_feat_wasm.sh`, `tools/build_lettori_wasm.sh`, `tools/wasm_opt.sh`, `tools/wasm_paralleli.sh`): one cargo invocation per module; `build_feat_wasm.sh <site/static> [all|a|b|manifest]` builds everything (pages, release) or one half (CI) and writes the manifest only with `all` or `manifest`; a single `cargo build -p a -p b` would unify the features of `mzlab-core` and bytes and sizes would change (engine +14 %).
  `wasm-bindgen` and `wasm-opt` of each module run in the background while cargo compiles the next one (`wasm_pack`; `wasm_wait` prints the logs in order and fails if a job fails); `wasm-opt` is binaryen version_133 (official GitHub tarball, SHA-256 pinned in the script; if it does not match the script fails) and is installed once per `$RUNNER_TEMP` (`flock`).
  The 48 files of `site/static/wasm*` have the same SHA-256 as the serial build; the caps do not change. Measurement (4 CPUs, warm dependencies, workspace crates from scratch, engine + libraries + 13 mzFinder modules + 8 readers): 643 s serial, 350 s with background jobs.
  `rust-core` compiles once (`cargo test --no-run`) and launches the test binaries four at a time with `tools/ci_binari_test.py -j 4 -- <cargo test arguments>` (working directory = package root, `CARGO_MANIFEST_DIR` set, one log group per binary, then the doctests with `cargo test --doc`; same set of tests as the serial `cargo test`: 684 passed, 0 failed, 1 ignored; a red binary makes the step red); execution 223 s → 134 s locally (4 CPUs).
  `rust-misc-a` and `rust-misc-b` use the same tool (one call per `cargo test` command; same set of tests: 125 + 6 + 3 and 391 passed, 1 and 4 ignored, 39 and 52 "test result" lines as in serial); execution 26 s → 11 s and 64 s → 36 s locally (4 CPUs): the rest of the jobs is compilation.
  `rust-wasm` (build, graph) and `rust-wasm-guardie` (pytest of the guards, which build their own `.wasm` and `nativo`) run in parallel: locally 208 s + 214 s serial, 223 s for the guards alone (no sharing of artifacts).
  `rust-core` runs only if the `core` output of `changes` is true (those crates, `Cargo.*`, `rust-toolchain.toml`, `vendor/`, `.cargo/`, `tests/golden/` or `rust.yml` change); otherwise skipped and `rust-ok` accepts it.
- **Rust tests and guards** (jobs `rust`, `rust-core`, `rust-misc-a`, `rust-misc-b`; guards in `rust-wasm-guardie`, determinism in `rust-det`): `cargo test` runs the binaries one after another (compilation 230 s + execution 192 s over 205 binaries); the other binaries last ≤ 11 s, so no `cargo-nextest`.
  `rois_parity` (30 s): `tools/roi_reference.py` processes the files in parallel, one process per CPU. `samples::number_replicates` counts with a `HashMap` keyed by `NumberKey` (34 000 names, 1.5 s; a NaN falls back to the pairwise comparison).
  The memory guards (`tests/test_guardie_memoria.py`, `tests/test_feat_wasm.py`) build, generate the series and measure in parallel, each measurement in its own folder: 112 s → 57 s with the builds cached.

- **`e2e_flow_msn`**: the `mzlab-cli msn graph` reference (211 s cold) goes to the background at the start and the `graph` step collects its output.
- **Measurements of the Rust jobs and discarded cuts** (rust-det, opt-level, single upstream build, crate fan-out): `docs/agenti/optimizations-tried.md` ("CI: misure dei job Rust e tagli scartati").

## Ten practical rules before opening a PR
Before opening the PR: `python3 tools/pre_pr.py --veloce` (about 30 s: only the cheap checks, plus CSP hash and the list of the e2e tests that `--cambiati` would run; never clippy nor e2e; every step prints "[i/N] name" before starting) or `python3 tools/pre_pr.py` (1-2 minutes: map, thresholds, i18n, JS syntax if you touched `mzlab/web/`, globals, tsc, e2e imports, fmt, clippy and `cargo machete` if the Rust paths of `rust.yml` change, then `verifica.py --cambiati`; `--senza-e2e` skips the last step).
  If the e2e tests do not start (browser missing) the summary says "E2E SKIPPED: Chromium not found, the CI will run them" and the exit is 2, not "All green". In the cloud `tools/chromium_cloud.py` (used by `tests_e2e/lib.py` and `verifica.py`) falls back to `/opt/pw-browsers/chromium` if the Chromium Playwright looks for is missing; never `playwright install`.
  The golden data `tests/golden/e2e/*.json.gz` contain the product version (`"version"`): a version change touches them and they must be regenerated with `MZLAB_UPDATE_GOLDEN=1 python3 tools/verifica.py --solo <test>` (`tests_e2e/golden_ref.py`), not with `--setup`.
1. **New file = indexed at once**: `python3 tools/indice.py` and the file is in a group (CI checks it with `--controlla`).
2. **Limits**: function ≤ 80 lines, file ≤ 500 lines, document ≤ 25 KB, document line ≤ 600 characters; `controlla.py` warns (WARN) from 475 lines and from 23.5 KB: split before overflowing, because two parallel PRs on the same file overflow together.
3. **HTML from code** always with the `h` template tag (`h\`...\``), which escapes; never concatenate file texts into HTML.
4. **Texts** as keys of `lang/it.js` and `lang/en.js`; Tabui (mzFinder) in English only and without `lang/` keys (`controlla_i18n.py`).
5. **Types**: `// @ts-check` in new files, the file is in a project of `tools/tipi/` (global types regenerate themselves at every check, they are not committed).
6. **Rust**: `cargo fmt --all` and `python3 tools/controlla_rust.py` (fmt and clippy against the base) before the push. The pre-push hook (`pre_pr.py --veloce`) runs only the fmt half, `controlla_rust.py --solo-fmt`, against the same base: it blocks only new unformatted files.
7. **Memory in the `.wasm`**: no exported function returns a whole `Vec<u8>` (use a `WriteAt`; `tools/api_byte_ammesse.txt` allows only what exists) and to sort use the `mzlab_core::sortc` module (`sortc::by`, `by_key`, `ord`, …) instead of the standard library `sort*`, which weighs on the `.wasm`.
8. **e2e**: wait for the STATE, not the clock: `ready(pg)`, `wait_for_js(pg, expr)`, `saved(pg)` before every `reload()` that must resume the session; never new `wait_for_timeout` (`tools/attese_base.json` only goes down).
9. **Deleting or renaming a file**: look for callers also in `crates/*/tests`, `tests_e2e`, `tools` and `.github/workflows` (`grep -rn name`); `tools/check_import.py` catches vanished Python imports.
10. **Before closing**: `git merge origin/main` (never rebase), resolve keeping everyone's work, rerun `pre_pr.py` and a single push.

## Tests that launch node or read the platform
- A pytest test that passes a path to `node -e` writes it with `.as_posix()` (Windows backslashes would end up in the JS string) and every node `subprocess.run` has `text=True, encoding="utf-8"` (on Windows the default decoding is cp1252).
- The "wasm-bindgen CLI" step of `rust.yml` (job `rust-wasm`) comes before the cache save: the binary in `~/.cargo/bin` enters the cache and the guards do not recompile it.
- The theme snippet at the top of `index.html` (`tools/tema_testa.py`) reads the `mzlab.*` keys first and then the `qqq.*` fallback ones for `prefs`.

- Job `pytest-shard` of `test.yml` (three shards in parallel, all 3.11: `rest-a` and `rest-b` (the two halves of `rest`) and `solo311`; Python 3.14 on Linux runs only in `notte.yml`; starts after the `prebuilt` jobs (`needs: prebuilt` with `!cancelled()`: no runner sits idle polling; if a `prebuilt` fails the shard builds on its own), test step 30 min, job 60 min; the `pytest` job is the gate with the required check names (3.11 and 3.14), green if all the shards are). The test step prints `--durations=50`.
- `rust.yml`: every job with a cargo cache runs `tools/ci_cargo_mtime.py restore` right after the restore and `record` before the save (main saves when the Rust sources change and its cache of the same prefix is ≥ 6 h old, `ci_cache_fresca.py`, also in the pytest shards and in `browser` of `test.yml` (cache `sito-e2e-`, saved only by main); a PR saves only while the most recent cache has no registry), so unchanged crates are not recompiled.
- Cargo recompiles a crate whose sources are newer than the output, and the checkout gives every file the checkout time. `tools/ci_cargo_mtime.py restore` puts an old date back on the tracked files identical to those recorded in `target/.mzlab-tree2` (written by `record` before the cache save); changed files recompile. Without a registry `restore` does nothing.
  `record` writes only the files already guaranteed by the previous registry and those of the crates cargo really compiled in that run (a `.fingerprint` newer than `target/.mzlab-stamp`, left by `restore`): a run that is red before compiling, or started from an older cache, does not guarantee sources its `target` never saw; the registry carries the job name (`target/.mzlab-job`) and `restore` ignores that of another job (a cache taken as a fallback from `restore-keys` has only the build variants of that job) (test: `tests/test_ci_cargo_mtime.py`).
  `record` deletes the `.fingerprint` of the variants not recompiled (native, wasm32, `target/fam/`) of a crate just guaranteed.
  The cargo cache keys carry the prefix `v2` (`rust-v3-`, `pytest-wasm-v3-`, `sito-v2-`): raising it makes the old caches unreachable.
  `cargo run` holds the lock of the build folder until the program ends, and the tests launch `msn graph` for 60-110 s at a time: the other workers that call cargo wait (same `test_valida_lr`: 10 s locally, 670 s in CI). In the pytest jobs `tools/ci_cargo/cargo` is first in the `PATH`: `cargo run` becomes `cargo build` plus the execution of the built binary, every other command and every target not found go to the real cargo.
  The shim `tools/ci_cargo/cargo` gives every feature family a folder `target/fam/<name>` (`cli`, `feat`, `feat-<feature>`, `wasm`; the rest stays in `target/`): `mzlab-feat-wasm` compiled with different features in the same folder recompiled at every alternation (68 s each time) and the builds queued on the lock. After a successful build the binaries, examples and `.wasm` files are hard-linked at the same paths under `target/`, so the paths written in the tests still hold. `tests/test_ci_cargo_famiglie.py` tests the family choice.
  `concurrency` of `test.yml`: PRs share the group per branch (cancel-in-progress), a push to `main` has the group of its own `run_id`: in a shared group a waiting run is replaced by the next one even without cancel-in-progress, and that run's cache is never saved.
  The pytest shards (`target` cache, `doppi` and `aree` exclusions, `prebuilt` builds, order and halves): `ci-selection.md`.
  The `rest` shard skips with `--deselect` the entries of `tools/pytest_solo_311.txt`: tests where Python only drives the Rust binaries and the `.wasm` files (same output on every Python); the 3.11 shard `solo311` runs only those entries, `rest` runs the rest: together the shards cover the suite exactly once, with no lost or doubled tests (`tests/test_pytest_shards.py` compares the whole collection with the two shards and rejects entries without a test).
- **Docs only**: `tools/ci_solo_doc.py <base sha>` (in the same `solo` step) adds `solo=true` and `kind=doc` only if EVERY changed file is a root `*.md`, `docs/**/*.md` or under `.claude/`; a `.md` elsewhere (fixture, crate README), a `.json` of `docs/schemi/`, no files or no base give everything. With `kind=doc` `pytest` runs only the `PYTEST` list of the script (forbidden names, version/CHANGELOG, gate, i18n, guards, selection) and `browser` skips install and e2e; the jobs stay green for the ruleset. Test: `tests/test_ci_solo_doc.py`.

State of open PRs (read-only, no token, standard library): `python3 tools/state_pr.py [--stato stato.json]` prints one line per PR (head SHA, required branch-protection checks N/M, `mergeable_state`, auto-merge, minutes since the last event, chat if it is in `stato.json` of the private repository) and the result of the last "test" run on `main`.
- Rules to reduce conflicts between PRs: one PR at a time per area if they touch the same files; after the last merge of `main` and before pushing, the full `python3 tools/pre_pr.py`; generated files are regenerated with the tool only at the end of the merge, never by hand; the Coordinator squash-merges when CI is green.

PR events are not read from a `pull_request_target` event: `registra-pr-recenti` reads the last 24 hours of PRs and `test` runs from the API on every poll (opened, one `push` per head sha, merged/closed; deduplicated; `reopened` is no longer recorded).
CI statistics: `stat-ci.yml` (cron every 10 minutes, which GitHub however launches only a few times a day, with a `cursore.json` cursor that never goes back; every `push` to main also reads the recent runs; no `pull_request_target`: GitHub blocks it by default in public repositories from 2 December 2026; no secrets, checkout of main only) launches `tools/ci_metrics.py registra-recenti|registra-pr-recenti|registra-conflitti` and appends JSONL rows with a `v` field to `eventi-AAAA-MM[-N].jsonl` of the orphan branch `stat-ci`: runs,
jobs with every step, caches, times per test file (`junit-*`), cancellations, PR and push shape, real conflicts (`git merge-tree`), runner load; never log texts.
After 14 days `compatta` removes the heavy fields. `riempi-verde` (at every poll and push, 30 rows at a time, a single attempt per row) fills `verde_a_unione_s` of the merged PRs that lack it.
A file of 50 MB or more is frozen (never rewritten, only read; `eventi.jsonl` is the old single file); the reading tools (`tools/ci_metrics_file.py`) merge them all; publishing to `stat-ci` never makes a PR fail.
Test phases (setup/call/teardown, xdist worker: plugin `tools/ci_pytest_tempi.py`, `tempi-test.json` in the artifact `junit-<python>-<shard>`) and .wasm sizes against the caps (`tools/ci_wasm_dimensioni.py`, artifact `wasm-dimensioni`) are `test_durate` and `wasm` rows.
Summary: `python3 tools/ci_metrics.py riepilogo [--da AAAA-MM-GG]` (after `git fetch origin stat-ci`) prints tables of PRs, jobs, caches, slow files, test phases, .wasm, conflicts, cancellations, load and queue; reds are only real ones (without `annullato` and `aggregato`), with the share of PRs with a real red.
Measured workflows: `WORKFLOW_MISURATI` in `ci_metrics_data.py` (`test`, `rust`, `sito-rust`, `desktop`, `pages`); of the critical path: `WORKFLOW_CRITICI` (without `pages`). `registra-coda` writes a `coda` row (open non-draft PRs, behind, in conflict, green waiting, age of the oldest open and green).
`esporta [--out DIR]` writes one CSV per type, `giornaliero.csv` (UTC day: runs, reruns, PRs open during the day and at day end, merged, open→merge and green→merge as mean/median/maximum, real reds and by cause, other) and `giornaliero-coo.csv` with the columns of `misure/giornaliero.csv` (chats_running and notes kept by the COO).
Critical path: `python3 tools/ci_metrics.py percorso [--da AAAA-MM-GGTHH:MM]` prints, per type of merged PR (docs only, Rust, site/other), the median and maximum in minutes from the push to the last required check (the longest among the runs of `WORKFLOW_CRITICI`, first attempt, green) and the slowest jobs.
The cause of a red job is `aggregato` (`rust-ok`, red only because another job is), `lint`, `test`, `soglia`, `timeout` (cancelled after ≥240 s inside a non-cancelled run, e.g. npx stuck), `annullato` (replaced by a push) or `altro`; the merged `pr` row has `commit_n`. Test: `tests/test_ci_metrics.py`. Modules: `tools/ci_metrics.py`, `tools/ci_metrics_data.py`.
Merging a PR (read-only, for the Coordinator): `python3 tools/coo_merge.py PR SHA` verifies that the head is SHA, that `test` and `rust` are green in the `stat-ci` events (rust absent = skipped), merges onto `origin/main` in a temporary worktree with `controlla.py` and `indice.py --controlla`, flags the risky paths (`Cargo.*`, workflows, `*.wasm`, CSP, desktop) and prints `{pr, sha, verde, combine, rischi, unire}`. Test: `tests/test_coo_unisci.py`.

## Acceleration proposals still open
- Changed files of a PR: `tools/ci_base.py <base>` gives the first parent of the merge with the current `main`, not the event's `base.sha` (which, when `main` has moved on, counts other people's files); `push` and `merge_group` use the usual base. `changes` and `sito-changes` + rebalancing of `rust-misc-a/b` (−20 s). Left out: the single upstream build and the split of `rust-core`.
