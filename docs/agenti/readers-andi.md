# "andi" module: netCDF/AIA files exported by the vendors (`.cdf`)

Family `andi` (`crates/mzlab-lettori/src/andi/`, feature `andi`, cap 262 144 B, `.wasm` in `wasm-lettori/andi/`), separate from `aperti` because `aperti` is at its cap. Reader contract and on-demand loading: `readers-module.md`, `extending.md`.

- `netcdf.rs`: read-only netCDF-3 reader, classic (`CDF\x01`) and 64-bit offset (`CDF\x02`): `numrecs` (also "streaming"), dimensions, global attributes, variables (type byte/char/short/int/float/double, `vsize`, `begin`), big-endian, record variables with `recsize` (a single record variable has no padding). The header is read with a 64 KB window; every count, name length, `begin` and data range goes through `Limiti` and the file size before allocating; the rest is `err.dam.unreadable` with the reason.
- netCDF-4/HDF5 (`\x89HDF`) is `err.file.netcdf4` ("export to netCDF-3/AIA"); `CDF\x05` does not open. A header describing more data than the file contains (a list with more entries than the bytes left, a variable with more values than the file's bytes, a `begin` past the end, an unknown tag) is `err.file.cdfDamaged` ("damaged or truncated, copy or export again"), with `detail` in English only in the CLI; never `error.memoryBudget` for a file of a few KB.
- `ms.rs`, `ENTRY` `id "andi-ms"`, extensions `.cdf` and `.nc`: `riconosci` looks for `mass_values` in the first 256 KB after the magic (`Si`), `ordinate_values` (`Forse`), HDF5 (`Forse`, to give the right key). A scan = `scan_index` + `point_count` over the points of `mass_values`/`intensity_values` (each variable read applies `scale_factor`/`add_offset` if it has them; sorted by m/z if they are not); RT = `scan_acquisition_time` / 60, or `time_values` of the first point; TIC = `total_intensity` (otherwise summed from the points); window = `mass_range_min/max`. Level 1 always.
- Polarity from `test_ionization_polarity`; SIM from `test_scan_function` ("Selected Ion Detection") with filter "SIM"; profile if `experiment_type` says "Continuum", centroids otherwise. `cromatogrammi` = `TIC` and `BPC` (computed from the points). `intestazione(k)` = each per-scan variable (times, ranges, counts, mass ranges) with its unit.
- Counts with a second source (`netcdf/counts.rs`, `ms/counts.rs`): `vsize` of each variable against its dimensions, the variables' data never overlapping each other or the header (header, fixed variables, then the records), `numrecs` never below the records the bytes contain; `scan_index`/`point_count` integers, never negative or fill values, scans with points never overlapping and, if `numrecs` is written, inside `mass_values` (gaps between scans are allowed). Every disagreement is `err.file.cdfDamaged`, never a file read with other scans.
- Fill values (`_FillValue`, the netCDF default fill of the type, the -9999 of the AIA models) = no value: a missing TIC is summed from the points, a missing time comes from `time_values` or is `err.file.cdfDamaged`, a point with fill m/z or intensity is dropped. On decoding: m/z outside 0..10^6 (also NaN) or points whose sum is over 1000 times away from `total_intensity` are `err.file.cdfDamaged` (type or offset misread); a scan without a time is `err.file.cdfDamaged`.
- Interrupted copy: the index stops before the first scan whose `mass_values` or `intensity_values` do not lie entirely in the file (`Cdf::intera`) and `missing` counts the others, never an error scan by scan; the ANDI-Chromatography branch stays for files without listed scans. Test: `crates/mzlab-lettori/tests/cuts_counted.rs` (every cut).
- BPC without a second decoding: each decoding of a scan (`spettro`, `completa`) annotates its base peak (`ms/bpc.rs`, `bpc_note`: maximum from 0 of what `intensity_f64` gives, like the decoded BPC); when every scan is annotated `traccia("BPC")` gives those values (`bpc_points`), otherwise it decodes the scans. The `.mzidx` and the BPC asked for afterwards decode each scan once (twice without `total_intensity`); `crates/mzlab-lettori/tests/andi_bpc.rs` counts the bytes read and compares the bits of BPC and TIC with a cold reader (even, zeros, empty, negative, NaN).
- ANDI-Chromatography (`chromato.rs`, ASTM E1947): a `.cdf` with `ordinate_values` and without `mass_values` is a sample without scans and with a single `ChromKind::Analog` chromatogram (id = `detector_name`, unit of `ordinate_values`); the times are `raw_data_retention` (with `scale_factor`/`add_offset`) or `actual_delay_time + i * actual_sampling_interval` (s → min).
- `header.rs`: `metodo(c)` has the `origin` (format `andi-ms`, `file_created` = `experiment_date_time_stamp` as written), `sample.nome` (`experiment_title`), `instrument` (`instrument_mfr`, `_model`, `_serial_no`, `_fw_version`, `_sw_version`), `operator.utente` (`operator_name`), `ms.source.tipo` (`test_ionization_mode`); `fields` = every global attribute (`andi:global`) and every `instrument_*` (`andi:instrument`), sorted, with `identity` for operator, serial and paths.
- `testata_mzml`: model, serial, date, components, this file as source with SHA-1 and the `method/1` document in the `<run>`.
- Page: `LETTORI_FAM.andi` (`lettori-famiglie.js`: `.cdf` and `.nc` in `soloModulo`, so the module takes every file with those extensions and the engine does not reject them); `#pick` and the loaded folder (`cartella-carica.js`) accept them.
- Tests: `crates/mzlab-lettori/tests/andi_ms.rs` (files written by a netCDF encoder in `tests/common/andi.rs`: CDF1 and CDF2, short/int/float/double, `scale_factor`/`add_offset` on times and retention, SIM, profile, polarity, TIC/BPC, method, written mzML, chromatography), `andi_hostile.rs` (HDF5, truncations, huge counts and dimensions, long name, `begin` outside the file, negative `point_count`;
- the three real `.cdf` of `dati/formati/aperti/netcdf_cdf/` with `MZLAB_DATI`), `andi_parity_agilent.rs` (with `--features tutte`: the `.cdf` exported from a 5977 run against its `.D` folder read by `agilent-d`: same scans, RT within 1e-3 min, TIC within 1e-3, m/z within 0.01), `tests_e2e/e2e_lettori_modulo.py` (a synthetic `.cdf` opens in the Data view).
- `andi_counts.rs`: false counts, fill values, and every byte of the CDF1 and CDF2 header changed in three ways: the file gives the same scans, counts the lost ones or is an error, never a different result without a warning.
- Not verified: Shimadzu GCMSsolution or LECO files (none in the data); ANDI-Chromatography on a real file (synthetic only); `CDF\x05` (64-bit data).
