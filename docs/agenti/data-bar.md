# Data view: side bar and tools
Part of the Data view (`docs/agenti/data.md`).

## Side bar and tools
- **Tool bar** (`#stbar` in the header, `role="toolbar"`, `barra.js`/`BARRA`): a single place per tool, the same in LR and HR. The single list `CMD` (`id`, `dom` = button id, `ic`, `panel`, `items` for menus, `run`, `visible`, `bar: false` for commands that live elsewhere in the page and are found only with the palette, `group`; texts `cmd.<id>.lab|name|tip|kw` in `lang/`, `kw` = keywords in Italian and English) generates bar, menus,
  "More" and palette (`search: true` = advanced or rare command, search only; "More" keeps only the external links PubChem and BioTransformer): a new button or command is added only there (and its `cmd.<id>.*` keys). Order: File · Calculator · Losses · Lists · Table; in HR, after a separator, Scan ▾ · Formulas ▾ · Libraries; at the end "More ⋯" (PubChem and BioTransformer, which open in another tab, and the groups that do not fit).
  Priority: `fit()` shows the labels in words only from 1440 px (below, icon with `aria-label` and tooltip), then moves into "More" from the right Table, Lists, Losses and the HR groups, never wrapping; File and Calculator always stay out. Keyboard: arrows, Home and End with roving tabindex, ↓ opens the menus, F6 or Alt+0 bring the focus to the bar, Esc gives it back (← → of the chromatograms stay with the charts).
  Outside the Data view (Draw) the same buttons open windows (`#refdlg`, `#calcdlg` as a dropdown, `LISTE.open`) and File and the HR group do not appear. Calculator: "Search in Δm" opens Neutral losses (`tables.js`, tab `ls`) with |Δm|. Polarity chips: `ESI+` blue, `ESI−` red, `ESI+/-` purple.
- **Search (palette)** (`paletta.js`, `PALETTE`; results in `ricerca.js`, `RICERCA`): Ctrl+K (⌘K on Mac) or the 🔍 button open `#paletta` (`role="dialog"`, `combobox` field, `listbox` list). Empty field: the last 5 commands used (`mzlab.pal.recent`) and the row "Try: 18, C6H12O6+Na, smoothing" (without data, when `smooth` is absent: "…, calculator", `pal.try.nodata`), never the whole list; with an empty field the `aria-live` region stays silent (no "No results").
  A NUMBER is typed: group "Compatible with" (neutral loss, adduct, contaminant; Rust search `api/ricerca`, tables taken from the page: `LOSSES`, `QADD` (adduct composition), `api/contaminants`; LR "within ±0.5 Da" without decimals, HR Δ in Da and ppm; the world is that of the calculator (`CALCQUI.isHr`): the open files, without files the written digits (18 = LR, 18.011 = HR); never a verdict).
  A FORMULA (also with adduct, `C6H12O6+Na`): mass and common ions via `api/formula`. A WORD: commands of `BARRA.commands` (name, label, keywords it/en, without accents, partial; max 12). Groups have titles; ↑ ↓ scroll, Enter opens the right panel, Esc closes and gives the focus back; results are announced (`aria-live`). Test: `e2e_ricerca`.
- **Side panel** (`#dfiles`, `barra.js`): only two states, hidden or docked at full height (below the header) to the left or right edge; never overlaid: the work area (`#v-workspace`) takes the remaining space (grid of `#v-data`, classes `sb-open`, `sb-right`) and a `ResizeObserver` on `#dpanels` does ONE redraw per frame (`refit`: `fitWidth()` + `redrawAll()`; zoom, selection and cursor stay).
- **File on the empty landing** (`barra.js`, `run` of the `file` command): without files, File behaves like the other tools: with another tool open it SELECTS it (never just shows/hides), a second click hides it, the buttons appear pressed (`aria-pressed`) there too, and Ctrl/⌘+B acts like `#sb-toggle`. Test `e2e_pannello_vuoto`.
- **Vertical spacing of the work area**: tokens in `:root` of `index.html` (`--sp-1..4`, `--pnl-pad-y/x`, `--pnl-gap` read by `pnlGap()` in `pannelli.js`, `--pnl-hd-gap`, `--ctl-py`, `--row-py`, `--tab-py`); a new vertical padding or margin uses the tokens, never a scattered value.
  Touch (`pointer:coarse`): the Files tab, its toolbar and the card headers are 44x44 px targets (block "Touch (coarse pointer)" in `app.css`).
  File rows are 44 px (pitch 45, was 63); the tick box is a 44 px input drawing a 14 px box; the × fills the row height; the 1/2 link chip keeps its pill with a `::after` hit area.
  `--pnl-hd-gap` is 7 px so the chromatogram cursor handle never covers the header buttons; the list keeps 14 px clear of the resize handle. Test `e2e_lista_tocco` (corners with `elementFromPoint`, no overlaps, pitch, desktop unchanged).
  Always-present button `#sb-toggle` in the header (between the Data/Draw tabs and the bar; `aria-pressed`, word "Panel" from 1500 px; visible only in the Data view): shows/hides the last tool used (first start: File); same action with Ctrl/⌘+B and with the `panel` command of the palette. The tool buttons in the bar open the panel on that tool and a second click on the same one goes back to the previous tool (File → Calculator → Calculator gives File back) and hides it only if there is none (`_prev` in `barra.js`); Esc and clicks on the charts do NOT close it (there is `×`).
  One panel at a time (`sb-panel-*`: file, calc, addloss, lists, qaqc, stat; `#hrinfo` for the HR tools: `hdr`, `lst`, `fil`, `cmp`, `iso`, `idn`, `disp`, `BODY` bodies in `banco.js`). Focus: on opening into the panel (only if the focus has not moved before), on closing onto the button that opened it. Width 280–560 px (never beyond half the window), default 300 LR / 340 HR, adjustable with the splitter `#sidebar-resize-handle` (`role=separator`, arrows ±16 px, Shift ±48, Home/End = minimum/maximum, Enter and double click = default).
  `BANCO.fileView(host, k, tab)` (`banco.js`) draws `fil`, `lst` or `alb` of file `k` in someone else's container, on a fake cell (`stand`) that moves no panels: used by Flow (Raw files → Explore).
  Below 900 px (portrait iPad) the panel is a full-width sheet that REPLACES the work area (`sb-sheet`; `×` and Esc give it back); `BARRA.sheet`, `BARRA.dockedWidth` (used by `hostWidth()`). Side: drag the header (`#sb-header`) into the other half of the window (drop zones and preview; with touch, long press) or Alt+Shift+←/→, or the `sideL`/`sideR` commands of the palette; shared key `mzlab.bar.side`.
  Below 900 px, on the landing and with the sample table in view, the panel starts closed and `#sb-toggle` says "File (N)" (`SHEETLBL` in `area-lavoro.js`, N = table rows, key `cmd.panel.files`): the table is the file list (the name opens the file, it scrolls inside its box, the page never sideways; `e2e_landing_stretto`) and "Sample table" closes the sheet.
  Width: until no file has been shown (landing, load table) it stays the default (or the one chosen by hand) and the panel is open from the first draw above 900 px, closed below (`landing`, `byNames` in `barra.js`; `primo()` arranges it before the engine, `sb-first` in `app.css` before `barra.js`; the saved open/closed state does not change).
  Then, until it is dragged (or `setWidth`), it follows the longest file name (`namesWidth` in `lista-file.js`, never below the default (280 px, the minimum, for low resolution; 340 px for high) and never beyond the point where `#tools` keeps every element at its width, i.e. its free space `.sp` stays open (`applyWidth` in `barra.js`), `BARRA.fitNames()` from `renderFileList`; double click or Enter on the handle = automatic again); a DDA file has a single row without the suffix "· Full Scan".
  State for LR and HR in `mzlab.bar.lr` / `mzlab.bar.hr` (`tab`, `open`, `w`, `u` = width chosen by hand, `last` = last item of the HR menus); at startup `init()` rewrites it keeping only valid fields (`pinned`, invalid side, width 0 or out of range go back to defaults); first start: hidden. File switching stays with `#fsel` ◀ ▶ in `#tools`; the file list opens from "File". `BARRA.syncMode()` (called by `BANCO.infoBar`) switches from LR to HR and back. Tests `e2e_pannello`, `e2e_cassetto`, `e2e_strumenti`.
- **View change**: when leaving Data (Draw) `tpview` in `barra.js` remembers in `_away` whether the side panel was open and the scroll of `#sb-panels`; on return to Data it restores them (width and tool stay in `_w`/`_tab`). Test `e2e_pannello_vista`.
- **File list rows** (`bindFileRows` in `explore.js`): click on the row = active file (if hidden it shows it; without shown files, `soloFile`); Ctrl/Cmd+click = adds or removes from the visible ones (`setVisOf`); Shift+click on a box = range (`boxRange`); double click on the name = only this file (`soloFile`, in HR it stays "rename"); renaming is in the right click (`renameFile`); double click on the color square = opens the browser's color picker immediately (`pickFileColor`); right click = menu (rename, color with palette, restore, remove). Test: `e2e_lista_colore`.
- **Double click on a hidden file** (`lista-file.js`, `bindListaFile`): the first click shows the file and rebuilds the rows, so the browser does not send `dblclick`; the second click on the same name within 400 ms does it (also from touch) and a native `dblclick` that follows is ignored.
- **Adding and removing files**: "+" (`#addf`) reopens the single landing (state `add`, `#backwork` "Back to work!" and Esc go back to work); files dropped on the side panel or on the landing go through `upload()`. `fileRemoval` (`lista-file.js`): `take` closes the panels left without files in the tab (`cleanupOrphanPanels`) and `back` reopens them (`reopenPanel`); the last file removed restores the landing and disables the bar; Ctrl+Z within 6 s brings back files and panels.
- **Freeing a removed file**: the load table row follows (tick removed and put back). After 6 s `free` frees the copy (`api/remove`, which reopens the engine's indexes for the remaining files) and `reindexAfterFree` gives the open files their new indexes (same objects, the panels follow the name), so another pending removal stays undoable (`e2e_matrice_bug`).
- **Removing from the list**: every row has a × (`.fl-x`, `aria-label` "Remove NAME", visible on hover and focus, always on touch) that calls `removeFile`; the row menu offers "Remove the N shown files" and "Remove all files" (`removeAllFiles`, a single undo entry). With open files a drop anywhere on `#v-workspace` (states `panels` and `table`) shows `ws-drop` and goes through `upload()` (`area-lavoro.js`). Test: `e2e_aggiungi_togli`.
  "Remove all files" without a list also takes the rows that were read but not opened (`unopenedRows`, `rowRemoval` in `lista-file.js`: in the `OPENNOW` queue, set aside, of the other world): `OPENNOW.hold` takes them out of the queue, the file being opened at that moment enters the removal when it arrives, with the window closed `api/remove` frees copy, index and row after `OPENNOW.idle()`; "Undo" puts them back in the queue only once (`OPENNOW.release`). Test: `e2e_togli_tutti_coda`.
  At the end of the list, the progress rows `.fl.pend.up` of the files being read (`UPROWS`, `data-loading.md`).
- **Removed in another tab**: tabs are not kept in step (no live synchronization). If the copy and index of a file are no longer in the site folder, `lrOpen` of `rust-worker.js` answers `err.file.removedElsewhere` with the name (`err.engine.index`, also with the name, stays for the missing index with the copy present) and the row stays unticked; e2e `e2e_tolto_altra_scheda`.
- **Shown files and active file**: the list is the ONLY control of what is seen (no mode button): the box = drawn file. `E.browse` is derived (`syncBrowse`, `lista-file.js`): true with ONE file ticked in the type; `E.cur` is always one of the ticked ones. ◀ ▶ and `#fsel` make a file active (`goFile`/`activeFile`: with a single file they replace it, with several they move among the ticked ones).
- **Traces and sessions**: a click on a trace of the overlaid TICs makes that file active (`pickTrace`) and the chromatogram header says "scan of <file>" (`paintScanOf`); sessions saved with `browse` are migrated with `migrateBrowse`. Tests `e2e_file_selezione`, `e2e_modo`, `e2e_unfile`.
- **Bar labels** (`fit`/`schedFit` in `barra.js`, `#stbar`): the words next to the icons (keys `cmd.<id>.lab`) are chosen by MEASURING the real space (no pixel threshold): `ResizeObserver` on `#stbar` + `requestAnimationFrame` = one measure per frame (`BARRA.fitStats`).
  Levels, richest first: `lab-all` (words on all, "pill" buttons), `lab-main` (words only on the main tools: `MAIN` = File, Calculator, Losses, Lists and, in HR, Scan, Formulas, Libraries), `none` (icons only); if even so it does not fit, the least used groups (`DROP_ORDER`) go into "More".
  Below 600 px (phone) only File, "More" and Search remain, and Search goes into "More" only if it does not fit (touch bar at 40 px). 8 px hysteresis to return to a richer level; the measure also counts the separators' margins. Never wrapping, never cut. The accessible name (`aria-label`) is always the full name.
  The `#sb-toggle` button shows the word only at `lab-all`. Labels are always automatic (no preference; a stored `mzlab.bar.labels` is ignored). Test `e2e_strumenti`.
- **Close "X"**: a single component, `button.x` in `app.css` (panels, windows, popups, hint): the × character is hidden (`font-size:0`) and an SVG mask X (`--x-mask`) sits at the center of the box, never below 24×24 px (`#bigx`, `#lib-x`, `#refx` of the windows); `#np-closeall` uses the same centering. Test: `e2e_x_centrata` (glyph centroid = center ±0.6 px).
- **Late commands**: `barra.js` loads in the first paint, before `mappa.js` and `arrange.js`; these call `BARRA.late()` at the end of loading and the 2D map commands and `disp.*` enter `BARRA.commands` only once.
- **Bar hint** (`hintShow`/`hintClose` in `barra.js`, `#bar-hint`): a note below the bar ("The tools are here…", `role=status` `aria-live=polite`) appears only the FIRST time the user hides the tools (`close(true)`), then never again (`mzlab.bar.hint`, marked when it appears); it closes itself after 10 s, with × or Esc, or at the first tool opened. Tests disable it by default with the key; test `e2e_barra_hint`. The tip points to the center of `#sb-toggle` (variable `--ha`, recomputed on resize, `fullscreenchange` and ResizeObserver).
- The hints of the bar, of the side-by-side layout and the tour go through a single queue (`suggerimenti.js`): never two bubbles together.
- **Gear** (`settings.js`, `uipOpen`; side panel `#uipset` with the components in `impostazioni-comp.js`, `window.IMPCOMP`): at the top the Language row (bilingual label `#uip-lang-l` + compact switch `.seglang` with the `uip-lang` radios IT|EN, accessible name "Italiano"/"English", no icon).
  Rule: no dropdown around a few controls, and no category titles for common controls.
  A single flat list `#uip-list` (no "Accessibility"/"Appearance" titles), in order of use: Theme `uip-th` and Font `uip-font` (tiles as before, each `role=radiogroup` with `aria-labelledby` on its legend),
  then the rows (label on the left, control on the right, rule above): Chart colors `uip-pal`, High contrast `uip-hc`, Reduce animations `uip-motion`, XIC lens `uip-xiclens`.
  Then the flat groups `C.flat` Data and calculation `uip-g-data` (centroid merging, HR libraries/ppm/decimals, centroids) and Application `uip-g-app` (updates and external files, desktop only); a group with a single control has no title.
  Ids and saved keys (`mzlab.a11y`, prefs) unchanged.
  Then the tour button `#uip-tour`, the "Report a bug" button `#uip-bugbtn` (opens `#uip-bug`, the form is downloaded at first click), and only with administrator mode the dropdown groups `details.imp-g` (state in `mzlab.set.<id>`) Assistant `uip-g-llm` and Diagnostics `uip-g-diag`.
  The theme change (`TEMASOFT.run` in `tema-morbido.js`, used by the `uip-th` radio and by `uipSetTheme`) lasts about 700 ms (variable `--tema-durata` in `transizioni.css`, ease-in-out): view transition (canvases too) or, without the API, class `html.tema-tr` with color transition (`transizioni.css`); with reduced motion it is immediate. Test: `e2e_tema_morbido`.
  At the bottom "Restore defaults" (`uipRestore`: does not touch files or sessions). No preview, no archive section.
- **Guided tour** (`tour.js`, `TOUR`): two-chapter tour (Your data, Tools and movements) with spotlight and accessible label; LR world only, invitation at the bottom, as wide as the side panel with equal margins (`TOURDOPO.centra`, non-modal dialog).
  "Not now" or Esc make a bubble appear under the gear (`TOURDOPO.mostra`, `#tour-later`, `aria-live` polite) saying where to redo the tour: it disappears by itself after 10 s, on click or with Esc at the first load and ONCE only per browser (`mzlab.tour.lr`, in memory if localStorage is missing; cleared by "New session"), repeatable from the gear (from Draw the button starts the Draw tour instead, see `drawing.md`).
  The invitation closes by itself after 30 s (`INVITO_MS` in `tour-dopo.js`) like "Not now", bubble included but without moving the focus; the count stops with the pointer over it or with the focus moved inside and resumes from where it was on exit; it resets if the tour starts or the invitation closes (`TOUR.chiudiInvito`); no duration in the text.
  **End of the tour with the example file** (`TOURSCELTA` in `tour-dopo.js`, `TOUR.chiudiEScegli`/`togliEsempio`
  in `tour.js`, `e2e_tour_scelta`): only if the tour itself loaded the example (`caricaEsempio`, which remembers the
  saved NAME in `exampleName`, not the objects: a new load rebuilds `E.files`), "Finish",
  "Skip the tour" and Esc open a modal dialog (`role=dialog`, `aria-modal`, focus on "Keep exploring with
  this file", Tab stays between the two buttons, Esc = keep). "Remove it and start fresh" removes only that file with
  `fileRemoval` (take + free + `reindexAfterFree`, immediately and without Undo): panels, rows, engine session
  and `mzlab.nbpending` no longer name it, the view goes back to `landing`; saved settings do not change. With
  own files already loaded the tour has loaded nothing: no question, no file touched. A reload
  mid-tour leaves the example as a normal file and no overlay (the tour state is only in
  memory). `TOUR.chiudi` also removes `#tour-live`. Page only: no CLI command.
  The "file" step opens the File side panel and closes it again at the end of the step (`prep` returns the function that undoes it); the "bar" step points to `#stbar`; `e2e_tour` checks that every step finds its visible target.
  The bubble tip (`--ta`) is computed in `updatePosition` from the target's rectangle; geometric test: `e2e_tour_ancoraggio` (1280, 1440, 1024).
- **Do not exist (do not reintroduce)**: Attributions and Suggestions tabs, calibration line, simulated spectrum and silhouette, automatic captions, Isotopes tab, "?" in the chart panels (the general guide stays), "Where does it come from?" in the menus, "Meanwhile read the Theory" during loading.
- **Adducts and losses**: a single button `data-cmd=addloss`, two tabs `#al-t-adducts` / `#al-t-losses` (bodies `#sb-panel-adducts` / `#sb-panel-losses`); the last used is in `mzlab.bar.lr` as `sub`; `BARRA.setTab('adducts'|'losses')` opens the tab. Test `e2e_addperd`.
- Panel header, correction and reference, reference lists, workflow, QA/QC, Statistics, Profile over time, Study report: `docs/agenti/data-tools.md`. Facts about the 3200 data, addresses, stacked chromatograms, analog traces, gradient, adducts, periodic table, data tables, reset, theme, transitions: `docs/agenti/data-3200.md`.
- **MS2 entries of the list** (`ms2Toggle`, `ms2Spectrum`, `ms2Show` in `tabs.js`; `e2e_ms2_voce`): ticking a precursor makes visible the MS2 files that have it and opens ONLY its chromatogram; the product ion spectrum opens with a double click on the name (or on the chromatogram), linked to the chromatogram.
- **MS2 rows per file**: every "m/z" row is a (file, precursor) pair (`data-pk`, `ms2RowOn`; `e2e_ms2_riga_file`), ticked only if the chromatogram really draws that file (`shownFor`); ticking the row of a file that is not drawn makes it the active file and the only one ticked of its type (`fileViewDo`, `unico` rule); the tick adds or removes only that file to the precursor's chromatogram (`ks` of the panel, respected by `shownFor`, saved with the file names), never the rows of the same m/z under other files; without drawn files the chromatogram closes.
- **No empty MS2 pair** (`cleanupOrphanPanels`, also called by `fileViewDo`; `ms2Rehome`, `ms2Show` in `tabs.js`; `STATO.verifica`; `e2e_ms2_invariante`, random sequences with a seed): a pair whose precursor is in no drawn file (ticked, one per `unico` type, held by the rows) does not stay empty: the top one moves to the first precursor of the drawn file that no other pair shows, the others close; `shown()` does not draw an active file removed from the ticks. A linked spectrum whose file disappears moves to a file of ITS tab that has the precursor.
- **MRM / SIM without the chosen channels** (`mrmSel` in `grafici.js`, used by `canali.js` and `sim-ui.js`; `e2e_ms2_invariante`): if none of the chosen channels (`p.tr`, for example quantifier and qualifier of the method) is in the shown files (a SIM file after the MRM file), the panel draws all channels of the shown files; the choice stays for when those files return.
- **The MS2 pair follows the chosen file** (`ms2Follow` in `tabs.js`, called by the click on a row and by `soloFile`; `e2e_ms2_precursori`): if no MS2 pair draws a precursor of the chosen file, the top pair (chromatogram and linked spectrum) moves to its first precursor without making other files visible (`ms2Switch(prec, false)`); the starting pair (`defaultLayoutTab`) takes the first precursor of the active file, not the lowest of all MS2 files.
- **MS2 spectrum without its precursor** (`drawSpec` in `picchi.js`; `e2e_ms2_spettro_file`): if the spectrum's file does not have the chosen precursor, the spectrum falls back to the first loaded file whose precursors contain it; a file without a precursor list (a Full Scan sample) is never the fallback, because it has no MS2 scans to give.
- **Product ion spectrum** (MS2 tab, `ctl` in `pannelli.js`, `ms2Scans`; `e2e_ms2_product`): the file menu offers only files with scans of the chosen precursor, the precursor list is that of the active file, numbers only ("229.1"); MS2 panels are titled "MS² 229.1" (title never truncated: `.hd .ttl` has `min-width:11ch`), the row below the spectrum says only scan and CE; no "Follows" nor "overlay the files"; the `← N` badge (`.ppair`) sits on one row.
- **MS2 never overlaid** (`ESP.unico/soloUno/unici` in `esperimenti.js`; `e2e_ms2_titoli`): `fileViewDo` leaves only one MS2 file ticked (the last), `shown`/`shownFor` draw only one, the "overlay" command is off at MS2 level; Full Scan and MS2 stay in different tabs and panels.

- **File list boxes** (`app.css`, block "tick boxes of the side list"; `e2e_lista_casella`): file (`[data-k]`), precursor row (`[data-pr]`) and group header (`.gall`) are a single control: 24 px target that draws a 14 px square, colors only from CSS variables, ticked, indeterminate, hover and focus states equal in both themes.
