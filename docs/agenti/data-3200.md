# Data view: 3200 data facts and other entries
Part of the Data view (`docs/agenti/data.md`).

## Facts about the 3200 QTRAP data
- Analyst 1.6.3; 3200 data are brought in as mzML (ProteoWizard MSConvert on Windows, instructions on the load screen; profile mode recommended).
- In the mzML files the DAD is only the total chromatogram (TWC): no UV spectra.
- m/z axis offset: +0.14…+0.38 (median +0.24) above the calculated value.
- MRM files: chromatograms only. MS2 files: many empty scans (handled). Q1 versus EMS is not in the mzML: the student chooses.
- The QTRAP fragments a lot in the source: many ions that look like TPs are fragments of the precursor.
- **Addresses** (`index.html`): `#/data` and `#/draw` open the right view immediately (`hashView`, `VIEW_HASH`); a click on a tab does `pushState`, Back/Forward follow `popstate`; `applyView` updates the tab title per view. `#/theory[/x]` and `#/practice` (script in `sito.js`) go back to the main page before the shell reads the address. The engine starts anyway for `#/draw` too (`init()` starts it for the session).
- **Stacked chromatograms of a view** (TIC, BPC, XIC, MRM, DAD…; `syncView`/`unionTime` in `grafici.js`, `cursorLine` in `scroll.js`; test `e2e_asse_x`): they are linked by default (`p.tl`, "link" button of the panel, can be unlinked for one): same time range (by default the union of the panels' times, `p._own` → `p._u`), same zoom and scroll (`syncT`), same cursor and dot.
  The plot margins are shared: `setup()` (in `shell.js`) uses `window.MARG_L`/`MARG_R`, the maximum over the line panels of the whole page, of every tab (`syncView`: tabs shown together with their own margins would reset each other at every draw, endlessly), that ask for the y-axis numbers (`canvas._needL`, measured in `frame()`) and for an optional right axis (`canvas._needR`); at every change the other panels are redrawn, so the left and right edges of the area coincide (± 1 px) for panels of equal width. Only the y axes stay independent.
- **Analog traces and gradient** (`mzlab/analog.py`, `Item.analog_list`/`analog`, `/api/analog?k=&i=&n=`, `/api/gradient?k=` GET and POST, `/api/gradient_parse`; `gradiente.js`, `GRADIENTE`; tests `tests/test_analog.py`, `e2e_gradiente`, `crates/mzlab-core/tests/chrom_kinds.rs`): `Run.chromatograms()` (and `ChromKind` in Rust) distinguishes `pressure` (MS:1003019 or id "Pump Pressure…"), `pda` (TWC, MS:1000812/813) and `analog` (every other trace without MS terms); the file's `info()` exposes `analog: [{i, kind, id, unit, t0, t1, n}]`.
  Unit of a trace (`chromatogram_unit`, Rust `trace_unit.rs` and Python): that of the array or, if it is the generic "number of detector counts" that our mzML writer puts on every trace except the TIC, that of the trace's `userParam` "unità".
  `/api/analog` gives time in minutes and values reduced to min/max per interval; pressure goes in bar only if the file declares a pressure unit with an exact name (pascal/Pa, kPa, MPa, mbar, bar, psi); with another unit or none the values stay as they are, with the file's unit on the right axis, without corrections or warnings (the true scale must be checked on the instrument display).
  The gradient has a single model `{source: dam|raw|file, points: [{t, b, flow?, curve?}], run_time?, solvents?}`: `/api/gradient` gives it from the `.dam` chosen for the file (`lab_pick`), otherwise from the one the engine's POST route received (`App.set_gradient`; the interface does not use it), otherwise `null`; pure parsers in `analog.py` (Chromeleon script `parse_chromeleon`, CSV `parse_gradient_csv`, errors as `gradient.err.*` keys); curves other than 5 are kept and drawn linear with a note.
  The gradient of a file comes from `/api/gradient` (`.dam`), otherwise from the file's `metodo/1` document (`lc.gradiente`: `.raw`, `.wiff`, `.D`, Waters; `fromMethod` in `gradiente.js`, source `file`): only the file's metadata, no manual entry; an mzML has none. Test `e2e_gradiente_metodo`.
  Method window: the "Gradient" section is read-only (chart and table of `lcHtml`, source from the `.dam` or the file's method) and appears only if the file has a gradient; no button to insert, edit, import or remove, no gradient in `NB.gradienti` nor in the `.mzflow`.
  **Trap**: mzML files do NOT contain the gradient; `.dam` files do (`methodinfo._lc`), Thermo `.raw` files as UTF-16 text of the Chromeleon script in the first ~430 KB (`raw::instrument_method_text` in Rust); OpenTFRaw 2.0.0 does not read the data of analog controllers.
- **"Adducts and losses" page** (`#sb-panel-addloss`, tool `addloss`): at the top the docked calculator (`#al-calc`: toggle `#al-calc-tg` with `aria-expanded`, choice in `NOMI.KEY("addloss.calc")`; `#calcdlg` inside `#al-calc-body`), then ONE field (`#calcin`), a row of choices `#al-ctl` (tolerance, unit and polarity on one row) and two tabs `#al-tabs` (Adducts `#sb-panel-adducts`, Neutral losses `#sb-panel-losses`); a saved `sub` that is neither goes back to Adducts. Tests `e2e_addotti_default`, `e2e_strumenti`.
  The `#al-tabs` tabs wrap (text and then row, `flex-wrap`) instead of overflowing the strip: with `pointer:coarse` (40 px buttons) in the narrow panel they are never cut off (`e2e_safari_ipad`, 1024×768).
- **Adducts and losses, rules**: the lists live only in the side panel of the Data view, never in a pop-up window: every entry point (`RIC_GO.*`, `tables.js`) leads there. Polarity `CALCQUI.st.pol` 1, −1 or 0 (both), not chosen = that of the files; one button always stays on. The chip says LR (one decimal, no error on losses) or HR (four decimals, ppm for adducts, mDa for losses).
- **Single field of the page** (`#calcin`): `dockCalc` (`barra.js`) moves it to `#al-find` between toggle and body, so it stays visible even with the keyboard closed; a number, difference or formula drives the three tabs (`CALCQUI.refreshPage`, called by `calcRun` at every change). Outside Data it goes back into the calculator window.
- **Adducts and "what can it be" groups (untitled)** (same logic and same components in four places: area below the mobile calculator `#calcout` (Draw), Adducts tab and combinations of the Losses `#nl-res`; outside Data the `#refdlg` window): `calc-qui.js` `CALCQUI` (choices: tolerance in ppm or Da and polarity in `NOMI.KEY("calcqui")`; `arg`, `gruppi` = lists, losses, adducts, differences, the closest first; tested in node by `tests/test_calc_qui.py`).
  Polarity `st.pol` = 1, −1 or 0 (both): ESI+ and ESI− are independent toggles (`polToggle`, switching off the last one switches the other on), `polOk` filters adducts and losses; without a choice it follows the files (only negative = ESI−, both = both).
- **Adducts tab, default table** (`calc-qui*.js`, `catalogue` option of the view): with an empty field it shows the standard adduct table for the polarity in use (name and mass shift, plus the catalogue of differences); a number or a formula computes it. No informative row above the field. Test `e2e_addotti_default`.
- **Reference lists, polymer series** (`liste.js` `buildIndex`): a series entry (PEG, etc.) is named by the repeating units ("PEG (polyethylene glycol), 3 repeat units", keys `lst.unitName.*`), never by "n=3"; `baseName` keeps the name without the number.
  The resolution is NOT chosen: `mode(arg)` derives it from the open files (`follow`: profile `HR.isHr`, name = instrument or analyzer) and, without files, from what is written (formula or number with ≥3 decimals = high, otherwise low), and exposes it as attributes `data-mode` (hr|lr), `data-src` and `data-name` of `.cq-ctl` (no visible label).
  Other files: `calc-qui-html.js` (`CALCQUIHTML.ctrlHtml`/`groupsHtml`), `calc-qui-ui.js` (`mount`, one view per place, `ctl: null` = follows the page's row of choices; **`CALCQUI.apri(numero, {gruppo})`** puts the number in the `#calcin` field and picks the tab, used by the spectrum ruler), `calc-qui-pannello.js` (the page: `ensureAdducts`, `showSub`, **`CALCQUI.cerca(v|null, scheda)`**, `setCalc`/`calcOpen`, `apriAddotti`, `apriPerdite`).
  The lists (`LISTE.ready()`, the 447 KB contaminant catalogue) are requested only when the field holds an m/z (`deps(true)` in `calc-qui-ui.js`, the only case in which `CALCQUI.liste` reads them): the empty panel at startup does not download them (`e2e_calc_qui`).
  `calc-addotti.js` `CALCADD` is only the data layer (`table`, `catalog`, `shiftText`); the `.cadt` table (`calc-addotti-html.js`) has adduct | Δ mass | exact `m/z` | at unit | error (ppm in high, Da in low) | XIC (`aria-label` "XIC of [M+H]+ 239.2230" in high resolution, "… 239.2" in low). In Low resolution 1 decimal and no ppm. Tests `e2e_calc_qui` (without data) and `e2e_calc`.
  ESI+/ESI− toggles (`#alpol` in the page, `#calcpol` in the mobile calculator), common adducts first and a single "Other" (`.cadd-more`). Values come from `api/adduct_table` (Rust, `mzlab-core::adduct_table`; `adducts()` of `elements.rs` stays the one for parity with Python).
  The unit-resolution isotope pattern of the formula chosen in the spectrum (`picchi.js`, `spettro.js`) comes from `api/ion_pattern` (Rust, `mzlab-core::ionpattern`, isotopes in `isotab.rs`; CLI `mzlab-cli ion-pattern`): `tables.js` requests it and caches it (`QQQRef.unitIon`).
  The written number is the searched `m/z` (no "observed" field): with a number the column "M if this adduct" (empty where the mass would be ≤ 0, `adduct_table.rs`: also m/z ≤ 0 of a tiny formula, without XIC button), with a formula the table of its adducts; tolerance `#altol` (mobile calculator `#calctol`; 5 ppm in high, 0.5 Da in low), the word "Tolerance" to the right of the field. `#calcres-wrap` is a row: "Search" (`#calc-nl`) on the left, result right-aligned; fixed height, so typing a number moves nothing.
  Docked calculator (`#calcdlg.sb-docked`): no groups below (`#calcqui` hidden, only the "interpreted as" row remains), "Search" only picks the tab, the field stays as it is (`calcSearch` in `eventi.js`): a difference (binary minus, also after "=" from the ribbon) picks Neutral losses, a formula Adducts. In Data and on the start page the `#np-calc2` button is not in the bar (`onBar` of the `calc` command; the palette finds it and opens the page with the calculator open); in Draw it is the dropdown as before.
  At the bottom a closed `details#cadd-diffs` (Δ, name, polarity) with the field `#cadd-delta` (Δ between two peaks, same tolerance, pairs of the same sign); the spectrum ruler opens it with `CALCADD.showDelta`. `BARRA.setTab('adducts'|'losses'|'calc')`, `QQQRef.open('ad'|'ls')`, `RIC_GO.*`, `dmOpen` open the page's tab (outside Data they switch to Data), never a window; `RIC_GO.cont` and "Is it a known contaminant?" (`spec.cont`) instead open the Lists panel with the m/z. Tests in `e2e_calc`, `e2e28` and `crates/mzlab-core/tests/adduct_table.rs`.
- **Neutral losses** (`tables.js` `lossRow`, data `perdite.js`, `#sb-panel-losses`; test `e2e_perdite`): one row per loss, `button.nlrow` (Δm | formula | label `loss.<f>.short`, `aria-expanded`) that opens `.nldet` (name, description, exact mass, mechanism, sources). - **Gradient on the chromatograms** (`gradiente.js`: `ensure`/`have`/`curve`/`draw`/`hover`/`reading`; `drawLines` in `grafici.js`; tests `e2e_gradiente`): the right click of ONLY the chromatograms (TIC, BPC, XIC, MRM, DAD) has the checkable item "Show the gradient (%B)" only if at least one file of the panel has a gradient (same `gradient` command in the palette); state `p.overlay = "grad"|null` and `p.gdelay` (min) in the session.
  Drawing: right y axis 0-100 "%B" (ticks 0/25/50/75/100), dashed linear ramps with area at 10 %, color = `--grad` or the first Okabe-Ito not used by the shown files (fallback `--muted`); the right margin (`canvas._needR`) enters the shared margins, so the areas stay aligned even with the axis on in only one panel; one curve if the gradients of the shown files are equal, otherwise that of the current file with a note.
  Reading: within 8 px of the curve "t · %B · flow" in the mouse box; the %B at the cursor time enters the dot's text (`aria-valuetext`). **Gradient delay** (0-10 min, set by the student: "Display options" in HR, "Parameters" popover in LR): thin programmed curve and solid curve at the column shifted, reading with both values.
  **DAD → mass delay** (`analog.detector_delay`, `/api/delay?k=`, cross-correlation of DAD and TIC after removing the baseline, refined with a parabola): the value and the quality (paired peaks, correlation) are in the DAD panel options, manually correctable; "Align DAD and mass" (`p.pdaAlign`, `p.pdaDelay`) shifts only on screen the time axis of the DAD trace. - **Data tables and chart descriptions** (`tdati.js` = single component `TDATI`, `tdati-pannelli.js` = panel adapter `TDATI_P`; tests `e2e_tabelle_dati`): no panel (chromatogram, XIC, MRM, pressure, spectrum, map) has a "Data" button in the header (the table and the description stay reachable with T and D on the focused chart, and from the Download menu with Excel and CSV): T opens a `<dialog>` with a real `<table>` (`caption`, `th scope=col`, first column `th scope=row`), copyable as tab-separated text;
  chromatograms = drawn points (at most 300 per trace) plus the apexes of the integrated peaks, spectrum = peaks above the label threshold (at most 300), map = the 100 most intense cells of the visible region.
  Cap: a table holds at most 200 000 rows (`ROWS_MAX`; `TDATI.maxRows` lowers it in tests), shown and copied; beyond that, `tdati.capped` points to the view export or the desktop app.
  A new chart registers its data with `TDATI.attach(elemento, () => ({ title, head, rows, note }))` and its description with `TDATI.describe(elemento, testo)`: the element gets `role=img`, `aria-label`, `tabindex=0` and `aria-describedby` (chart type, axes with units, visible range, number of peaks); `aria-live="polite"` only on request: the D key on the chart re-reads the description in the `#tdati-live` region.
  A table of more than 200 rows opens with 200 (paginating 1000 cost ~180 ms at 4x CPU), then 1000 at a time when scrolling near the end (`tr.td-more`, `IntersectionObserver`); the count and Copy always cover all rows. `TDATI.watch` finds the chart even when it is itself the node added to the page (test `e2e_kmd_denso`).

- **True reset** (`reset.js`, `QQRESET`, loaded BEFORE the engine; test `e2e_reset`): a reload, even Cmd/Ctrl+Shift+R (skips only the HTTP cache), brings the files back because files and indexes live in OPFS, session and notebook in IndexedDB, offline copies in Cache API/service worker, preferences in localStorage. "Start from scratch" (`wipe("all")`) removes everything in parallel (OPFS, IndexedDB, caches, workers; the OPFS folders with a single 10 s deadline: the one not removed is in `QQRESET.last.errors`) and reloads with `?riparti=1&ripn=<nonce>`. One wipe per entry.
  `QQRESET.wipe(modo)` deletes BY NAME what the browser lists (`root.entries()` of OPFS, `indexedDB.databases()`, `caches.keys()`: no fixed list, folders and databases added elsewhere also count, e.g. the `?lr=1` flow), after stopping the engine (`window.qqEngineStop`: it holds synchronous handles on the files); a database blocked by another connection stays queued and closes at reload (the new engine finishes it: `?riparti`, `startup.md`).
  No idle connection to `mzlab_lab` (`liste.js` closes its own at every operation): the reset of one's own tab is never blocked; test `e2e_reset`.
  Two modes: **all** (OPFS, every database, every cache, service worker, `qqq*`/`mzlab*` of localStorage, sessionStorage) and **files** (files, indexes, list of open files and roles; `clearFilesKeepWork` of `qqq-db.js` does not delete `mzlab_lab`: drawing, lists and molecules stay; preferences, language, theme and libraries also stay: OPFS folder `librerie`, databases `mzlab-libs`/`mzlab-libdir`).
  Single entry: the header's "New session" button (`#newrun`) and the notice "Files stay in the browser" open `QQRESET.ask` (`#resetdlg`: blue "Files" button = files mode, red "Full reset" button = all mode, "Cancel"/Esc with the focus); neither the gear nor the palette has reset commands; "Files" (`QQRESET.run("files")`) removes the files only from mzLab and also reloads with a `#` in the address;
  `?reset=1|all|files` at startup (acts immediately, without starting the engine, then removes the parameter and reloads); the first time after a reload that the files are still there, a discreet notice appears (`#resetnote`, `qqq.reset.note`).
  Measurements: `reset-misure.md`.
