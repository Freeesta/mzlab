# CLI steps: one line per native step
List of the steps run by `FileRunner`, with file, inputs, output and test; rules, registries and gaps are in `cli.md` ("Coverage").

- `spectra.centroid`: profile mzML → centroids (`--set INSTANCE.fwhm=|threshold=`); see `rust-flow.md`. An omitted `fwhm` is measured on isolated peaks (continuous data searched again at 8, 24 and 64 grid points) and is an estimate in `estimates`, with the number of peaks, only if measured; below 8 peaks the fallback width 0.7 Da is used, never called estimated, with `warn.centroid.widthFallback` and `fwhm_basis` = `fallback` in the file record. `threshold` has the default value 3 sigma.
  The file record also has `merged` and `saturated` (centroids with those flags, counted the same way) and `fwhm_model` (`{a, b}` or `single`); `merged` > 0 gives the warning `warn.centroid.merged`, a warning and not an answer; the mzML does not change. `convert --peaks mzlab` (native only, like the choice itself) puts the same counts in `centroidi` `{merged, saturated}` of the `--report`, from the file note in the record (the same for a file taken from the cache), and with `merged` > 0 a line `warning: ... (warn.centroid.merged)` on stderr that does not change the output.
  Grid and saturation (`centroids/grid.rs`, `emit.rs`; test `tests_grid_sat.rs`): a jump beyond 1.5 median steps is compared with the local step (minimum of the 6 neighbouring intervals), so on Orbitrap/TOF grids that widen with m/z no zeros enter inside peaks; a flat apex (≥ 3 points at ≥ 0.99 of the file maximum over ≥ 0.15 FWHM) is a single SATURATED centroid at the centre of the flat part, which in HR keeps the height (lower bound) like the other peaks of the spectrum.
  Doublets (`emit.rs`, `params.rs`; tests `tests_merged.rs`, `centroids_parity.rs`): in HR the estimate fits FWHM = a·m^b on isolated peaks (least squares on the logarithms; it needs ≥ 8 peaks over ≥ 1.3× in m/z and 0 ≤ b ≤ 2, otherwise a single width, `fwhm_model` = `single`; in low resolution and with `fwhm` given always a single one).
  A centroid whose full width at half height (smoothed signal minus background) exceeds 1.12 times that of the file at its m/z has the MERGED flag (16); a saturated peak does not, and with the model neither does a peak with fewer than 5 points per FWHM. On synthetic Orbitrap data at SNR 50 and 1000: 0 out of 411 single peaks, 40 out of 40 1:1 doublets at 0.5 and 0.75 FWHM.
  Model windows (`Params::wb_at`, `w_at`; tests `tests_model.rs`, `tests_pin.rs`): with the model the windows in points (region, merge distance, valley test, shoulder search) are the FWHM at the peak's m/z over the spacing of the 2 points per side, those in m/z (centroid window, ASYMMETRIC, flat apex, shoulder gaussian) the FWHM at its m/z; background, noise and Savitzky-Golay stay the file's. Without the model the centroids are the same bits (hash fixed in `tests_pin.rs`).
  Shoulders with the model (`detect::merged`): a candidate merged only because its valley is not significant is noise and does not count among the members, so the shoulder test (groups of one member) also runs on continuous data. Synthetic Orbitrap, TOF and steep-sampling data, SNR 1000 and 50: 1:0.3 shoulders at 1 FWHM found 188-400 out of 400 (0 out of 400 without the model), 0 out of 800 singles flagged.
- BASE: the recipe is that of the Pipeline panel with no settings (`run::recipe_for` on the first file of the series) with on top the values the plan writes (preset and parameters, `mzlab_feat::steps::recipe_map`, the only descriptor → `Recipe` mapping).
  `features.detect`, `tp.dig_lr` and the Da: details in `rust-flow.md`.
- `structure.render` (`flow_render.rs`): `drawings/1` from the `sites/1` of `tp.position` and from the parent (`interp::redraw::render_text`, also in the `interp` `.wasm`): same bytes as the `drawing` of the `interp` block.
- `structure.reactivity` (`flow_reactivity.rs`): `reatt/1` of the parent from `mzlab_chem::flow::reactivity_text` (also in the `chem` `.wasm`); `solvent`, `conformers`, `protomer`, `seed` are its options.
- `structure.moiety` (`flow_moiety.rs`): the rows of a candidate table (CSV with the SMILES column `column`) that contain the substructure `query` (with `keep` = `lacking` those that do not), with `moiety_matches` as the last column; optional `stereo`; rows without a readable structure excluded. `chem::moiety::moiety_text`, also in the `molkit` `.wasm` (`flow_moiety`); output `<instance>.csv`. Tests `flow_moiety_tests.rs`, `test_molkit_wasm.py` (fixture `tests/dati/moiety.json`).
- `export.table_csv`, `export.mztab` (`flow_export.rs`): `table_file` on a `.mzfeat` and a samples file (`samples/1`), `kind` = `full`, `full_mzmine`, `quant`, `csv_semicolon` (`<instance>.csv`) or mzTab-M (`<instance>.mzTab`); polarity from the recipe; test `flow_export_tests.rs`.
  - Export of a view: `table` = `.mzfeat` of `features.align`/`features.gapfill` (whole table) or the view of `table.filter` (only the kept rows, with its rules and the normalisation: the view carries `origine` = SHA-256 of the table and rules text, `core::view_json_origin`/`view_table::view_origin`, plus `campioni` (the samples table, for the blank); the table is found again in the run with `table_by_sha` (`flow_export.rs`); a view without `origine` or with the table missing gives `err.flow.export.view`; the site passes the view to `export_table_auto`).
  - View in every other step that reads a table (`flow_view::resolve`, from `flow::dispatch` before the executor): an input of type `table` that is a view becomes the table it represents, `mzlab_feat::view_table::table_of_view` (the same function as `flow_table_of_view` of the `table` `.wasm`): kept rows with the view's areas (normalised, blank subtracted), recipe and file of the table; ids renumbered 1..n, no `tp/1` block and no evidence. Written once per view (`view-<sha16>.mzfeat` in the working folder) with the table's provenance. Test `flow_view_tests.rs`.
- `features.estimate` (`flow_estimate.rs` → `mzlab_ops::run::feat::run_estimate::estimate_of`, the same function as `flow_estimate` of the `hr` `.wasm` in the browser): for each index `estimates/1` (type `qc`, one file `<instance>-<root>.json`): the `run::preview` measurements on the file itself, file recipe (see below): `noise`, `min_height`, `ppm`, `fwhm`, `rt_tol`, `dead`, `da`, `defect`, each with the numbers it comes from; no histograms or example traces. It proposes, does not decide: `features.detect` does not read it. Test `flow_estimate_tests.rs`.
- `features.estimate`, the recipe: polarity of the file's MS1 scans and its profile (Da and LR heights at unit resolution: `Recipe::for_index_estimated_in`, rule of `mzlab_feat::nature`), then only the parameters written in the plan (a descriptor default is not a choice); the `polarity` and `axis` used are in the file and, if decided by the file, among the prov estimates.
- `formula.ms1` (`flow_formula.rs`, `mzlab_feat::flow_formula_ms1`): an `ion` not written in the plan is `[M-H]-` or `[M+H]+` according to the polarity of the MS1 scans of each file, estimate in prov; a written `ion` of opposite polarity wins, with `warn.flow.formula.ion` in the rows and in prov. Each row states its `ion`.
- `table.stats` (`flow_stats.rs`): `stat/1` of `stat::compare` on the areas of the `.mzfeat`. Inputs `table`, `samples` (a `samples/1` document; role `sample` = `serie`, `blank` = blank; files are matched to columns by name, then by SHA-256, an unknown one is neither condition nor blank) and `design` (`design/1`: conditions, reference, comparisons). Parameters `pseudocount`, `floor`. Output `report`. Test `flow_stats_tests.rs`: bytes equal to the engine called by hand and to `stats_json`.
- `table.plausible` (`flow_plausible.rs`): from `.mzfeat` the `plausible/1` (`<instance>.json`); thresholds `mz_min`, `mz_max`, `rt_max`, `width_max`, `ppm_max` and tolerance `mz_tol_da` (≥ 0.1 = unit, empty = table recipe) with `--set INSTANCE.NAME=VALUE`. Test `flow_plausible_tests.rs`.
- `table.kmd` (`flow_kmd.rs`): from `.mzfeat` the m/z and RT of each row to `stat::kmd_json` (the engine of `kmd-calc.js`); output `report` `<instance>.json` with rows (KM, KMD, series) and candidate series; `unit`, `tol_mda` and `min_members` go to the engine. The series are candidates, not identifications. Test `flow_kmd_tests.rs`.
- `table.pca` (`flow_pca.rs`): the answer of `pca_json` (route `api/stat/pca`) on the areas of the `.mzfeat`, requested as the page does (`pca.js`): matrix with 0 for absent cells, role of each file from the samples (`std`/`calibration` = `standard`, `t0`/`infusion` = `sample`; unknown file = `sample`) and replicate group (role, time, concentration; without time or concentration the file is alone). Each descriptor parameter has its `--set`. Test `flow_pca_tests.rs`.
- `export.inclusion` (`flow_inclusion.rs`, `mzlab_feat::export_inclusion_tp::inclusion_csv_of`): the `tp` port reads a JSON `[{formula, rt}]` or the `.mzfeat` of `tp.link` (accepted product rows: neutral formula and RT; without a formula, at the observed m/z); an unwritten `adducts` is `[M-H]-` if the file's recipe is negative, `[M+H]+` otherwise. In the browser: `F.webInclusion` (`flow-web-inclusion.js`, `interp` `.wasm`, `flow_inclusion`), same bytes. Tests: `flow_inclusion_tests.rs`, `e2e_flow_neg_lr.py`.
- `table.drift` (`flow_drift.rs`): `drift::correct` on the QC files of each batch (`samples` + batches of the `design`, matched to columns by name or SHA-256); output `table` `<instance>.json` = `deriva/1` (method, batches, median CV before/after) plus `factor`, one factor per cell; the `.mzfeat` does not change. `method` and `span` go to the engine; without enough QCs or at the batch ends the step is refused (`error.drift.tooFewQc`, `error.drift.qcNotAtEnds`). Test `flow_drift_tests.rs` (factors of the reference `deriva.json`).
- `features.align`, `features.gapfill` (`flow_base::align_job`, `flow_indexes.rs`): each index of the series is opened once per step (`Indexes::open`); type check (`one_kind_of`), recipe, file facts and filling read copies of its tables on a new handle (`Index::over`, empty caches: what `open` would give), and a file with changed size or modification date is reopened entirely. With the tables in cache `align_mem` opens only the first index, for the recipe. Same bytes; test `flow_indexes_tests.rs`.
  - Cap: after the type check only the first indexes whose tables fit in `KEEP_BYTES` (256 MB) stay in memory; the others are reopened entirely at each use.
- `features.group` (`flow_group.rs`): `ionnet::group_text` on a per-ion table (`table`); output `groups` `<instance>.json` = `ionnet/1` (group, species, neutral mass per row and edges for GNPS), the same text as the `flowtab` `.wasm`; `ion-groups.md`.
- `chrom.transitions` (`flow_transitions.rs`, `mzlab_feat::transitions::transitions_text`): the transitions table (parameter `transitions`, CSV) integrated in every mzML of `source`; output `peaks` `<instance>.csv` according to `output` (`peaks`, `table`, `candidates`), each parameter with its `--set`, preset `example_1`. A `.wiff` goes first through `convert.mzml`. Details `transitions.md`; test `flow_transitions_tests.rs`.
- `table.filter@2` (`flow_table.rs`): the `view_json_origin` view of the table (the page's `view_json` plus `origine`), rules in descriptor order, `samples` as a `samples/1` document; test `flow_table_tests.rs`.
  - NTS rules, all off by default (`filters.rs`, `filters_blank.rs`, `filterspec.rs`): `blank_match` (`batch`|`matrix`: each sample against the blanks of its batch or matrix, otherwise all blanks, listed per file in `conteggi.bianco_ripiego`), `min_replicate_fraction` (replicate group = series, role, time, concentration, or the group of `samples/1`; fraction rounded to the file, at least one), `normalize=istd` with `istd_id` or `istd_mz`+`istd_rt`, `blank_keep_istd` (the standard's row skips the blank rule, needs `normalize=istd`).
  - `blank_cells` (`detected` default|`all`): with `detected` only the blank cells found by detection (state `detected`/`targeted`) make the blank level, a cell filled by gap-filling counts 0 (as in mzmine); `all` also counts the filled ones (`BlankOpts.detected_only`, field `celle_bianco` of the rule). A plan saved with `table.filter@1` is migrated to `@2` with `blank_cells=all` (`migrate.rs`, `from_only`), so it does not change.
  - Batch, matrix, series and group of `samples/1` travel in the view as `etichette` (`filterspec::spec_with_samples`).
- `tp.generate` (`flow_generate.rs`): `ipotesi/1` of `hypo::generate` on the rules `regole_tp_2.json`, like `run_hypotheses` of the page (no suspects index, families or imported list; the `features` port is not read). `parent` is a formula (written as `elements::fmt`), a SMILES (groups and breaks choose the rules) or a JSON `{name,formula,smiles}`; test `flow_generate_tests.rs`.
- `tp.link@2` (`flow_link.rs`): the page's chain for a parent: hypotheses searched in the series (`run::hypotheses_stored`), evidence and view of the `tp/1` products (`run::evidence_sources_to`), interpretation of each row `interp/1` (`interp::run::run_to_with`, thresholds `LinkParams`). Test `flow_link_tests.rs` (series `feat_synthetic.py`).
  Inputs: `table` (made by this plan: the `Lineage` gives the `.mzfeatf` and the recipe), `samples` (`samples/1`), `parent` (formula, SMILES or JSON with `rt`; without `rt` the strongest row within 5 ppm is used), `index` (one per file, in table order), `hypotheses` (the `ipotesi/1` of `tp.generate` with the default parameters for that parent, otherwise `err.flow.link.hypotheses`). Output: the `.mzfeat` with `tp/1` and `interp/1` that `tp.network` reads.
- `tp.filter@2` (`flow_refilter.rs`): the `filtri/1` registry of the table that `tp.link` interpreted, re-read with the step's thresholds (`interp::refilter`): F1-F4 from the table (`filtri::row_facts`), F5 from the rows of the `interp` block and from the calibration in the meta, decoys from the hypotheses (`hypotheses` = `ipotesi/1` of `tp.generate`).
  With the default thresholds it is the registry the interpretation saved; with different `tol_min`/`tol_max` F5 uses the calibration rounded to 2 decimals of the meta.
  Inputs `tp`, `hypotheses`; output `filtri/1` (type `table`). Test `flow_refilter_tests.rs` and `interp_synthetic.rs`.
- `tp.position` (`flow_position.rs`): the position of the modification of each row interpreted by `tp.link` (the `site` key of `interp/1`), re-read with the step's thresholds (`interp::reposition`, `SiteParams`: the defaults are the constants of `site.rs`). Inputs `tp` and `parent` (SMILES or JSON with `smiles`; without a structure `err.flow.position.smiles`); output `sites/1` (`{id, recomputed, site}` per row, type `transform`).
  With the default thresholds `site` is the one saved in the block, byte for byte; with others it is redone from the row's MS2 consensus (rounded as in the block). **Gap**: the votes of the MSn tree are not in the file, so a row whose `site` comes from the tree (`source: tree`) keeps it as is, whatever the threshold. Test `flow_position_tests.rs`, `interp_reposition.rs`.
- `tp.dig_lr` (`flow_digl.rs`): the Tabui LR Dig (`lr::dig`) on full scan, output `dig`; each setting of `plan::Settings` has its `--set`; see `rust-flow.md`.
- In the registry but without a native executor: `features.ms2_link` (included in `features.detect`: no executor of its own, see the comment in `BUCHI`), `annot.hazard`, `structure.draw` (page only: `native: false`). The list is `BUCHI` in `flow_rule_tests.rs`: it only gets shorter.
- `spectra.chimeric` (`flow_chimeric.rs`): for each MS2 of an MGF the precursor purity in the surrounding MS1s (`fill_purity`) and, with the table, the co-isolated features (`ms2_engine::chimeric::intruders`); inputs `spectra`, `index`, `features`, `library` (the last two optional), output `spectra` with the rows `PURITY`, `PURITY_BAND`, `CHIMERIC`, `INTRUDERS`; nothing is removed from the spectrum. Test `flow_chimeric_tests.rs`.
- `spectra.insilico` (`flow_insilico.rs`): each MS2 against the candidate structures of a local list (`suspects`: CSV, `screen/1` or catalogue of the package `insilico/1`, `docs/agenti/insilico.md`), ranked by the peaks that the bond fragments explain (`ms2_engine::insilico`); output `candidates/1` with hypotheses `source: insilico`, never an identity; `--set INSTANCE.db_ppm=|frag_ppm=|max_bonds=|top=|score_terms=`. Test `flow_insilico_tests.rs`.
- `rt.predict` (`flow_rtpredict.rs`): the candidates (`candidates/1`) compared with the RTs of the campaign standards (`standards`, optional `queries`) with the window `logp_window` (Crippen) or the forest `forest`; writes for each hypothesis predicted RT, residual and `rt_ok`, with `parent` the direction of the RT change; evidence only, it adds no hypotheses and fixes no levels. Test `flow_rtpredict_tests.rs`.
- `msn.library_export`, `msn.table_export` (`flow_msnlib.rs`): from the `msn-graph/1` graph of `spectra.msn_graph` (input `graph`) the MSP or MassBank library (`format`, `levels`, `clean`, `annotate`, `id`) or the CSV table (`view` = `modifications`, `nodes`, `peaks`; `clean`); same bytes as `mzlab-cli msn-lib export`. Test `flow_msnlib_tests.rs`.
- `msn.figure` (`flow_msnfigure.rs`): from the `msn-graph/1` graph the figure `svg`, `html` or `png` (`format`, `view` = `tree`, `radial`), same bytes as `mzlab-cli msn-graph figure`; one format per run; the PNG only with the cargo feature `png`. Test `msn_figure_tests.rs`.
- `table.match` (`flow_tablematch.rs`): the MS2 of each row of the aligned table (`table`, `samples`, `index`) against a library (`library`) with the engine of `spectra.match`; output `candidates/1` with `query` = row id; tolerances and filters as `spectra.match` (`tol_da`, `tol_ppm`, `precursor_ppm`, `top_n`, `decoys`, `score_terms`). Test `flow_tablematch_tests.rs`.
- m/z tolerances: on the unit-resolution axis (LR files) `features.align`, `features.gapfill`, `features.ms2_link` and `table.filter` are written in Da (`tol_da`, `dup_da`); `ppm`, `max_ppm_span`, `tol_ppm`, `dup_ppm` on that axis, and `tol_da`/`dup_da` on the ppm axis, are `err.flow.param.axis` (never a silent conversion); map in `steps/recipe_map.rs`, test `flow_lr_tol_tests.rs` (under `flow_lr_tests.rs`).
- `convert.mzml` on a partly read sample (truncated, damaged block, rejected events; `readers::Losses`): the cause key goes among the `warnings` and `{declared, read, cause}` in the file note (`files`) of `prov.json`, `report.json` and `flowrun/1`, also from the cache, with the same counts as `conversion/1`. Test `flow_partial_tests.rs`.
- `index.mzidx` on a vendor file read in part: the index writes `source.lost` (`upload::index_reader_with`, site, app and CLI) and the run records it as `convert.mzml`; in the browser `flow_idx_source` gives the index's `source`, `flow-web-prov.js` passes its `lost` to `record_prov`, which reads it as the cause among the `warnings` and file note (`run_web.rs`). Tests `flow_partial_idx_tests.rs`, `run_web_tests.rs`, `e2e_flow_web_prov.py`.
- `meta.compare@1` (`flow_compare.rs`, `flow_compare_feats.rs`): `comparison/1` on `candidates`, `annot`, `peaks` (`.mzfeatf`, `type: "peaks"`, `by: "file"` with `per_file`) and `table` (`.mzfeat`, `type: "table"`, `by: "feature"`); for features it pairs `(m/z, rt)` with `pairing::abbina` (`mz_tolerance_ppm` 5, `rt_tolerance_min` 0.2) or `mz_tolerance_da` (0.3) on the unit axis and computes `mean_overlap`, `mean_rank_corr` on the areas and median deviations. Tests `flow_compare_tests.rs`, `flow_compare_table_tests.rs`.
- `examples/flow.rs` (not a command): thin caller of `mzlab_cli::flow::run_plan`: reads an `mzflow/2` file, checks it, runs it with N threads and writes `prov.json` (SHA-256, ms, heap peak per instance); it also compiles for `wasm32-wasip1` (`tools/wasi_run.mjs`). The same `run_plan` is the `flow/run` route of the desktop app (`crates/mzlab-desktop/src/flow_run.rs`).
