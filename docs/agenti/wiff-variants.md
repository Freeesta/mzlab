# `.wiff` of other SCIEX instruments (`sciex` module, `estesi` feature)

The site engine reads only the 3200 QTRAP (`wiff.md`). The variants live in the same reader (`crates/mzlab-core/src/wiff/`) under the Cargo feature `estesi` of `mzlab-core`, turned on by `mzlab-lettori` (module `sciex`) and off in `mzlab-wasm`: the engine `.wasm` is the same with or without this work (same SHA-256).
The `variante` method of the `Lettore` trait and the `cv:` parameters of `mzmlwrite.rs` sit behind `feature = "sciex"` of `mzlab-core` (which includes `estesi`, turned on by `sciex` of `mzlab-lettori`): the other modules, under their ceiling, do not carry them; the `wiff_variants*.rs` tests want `--features sciex`. The lines shared with the engine carry their `#[cfg(...)]` on the same line; the new code lives in `*_estesi.rs` / `extended.rs` files.

## What is a "variant" and what is rejected
- `Wiff::variante()` (`extended.rs`): Log model different from "3200 QTRAP", an experiment code outside {15 full scan, 11 product, 4 MRM}, or a scheduled MRM experiment (stream `sMRM`, `window_s`; also valid without a Log). `Lettore::variant(c)` exposes it; `mzlab_lettori::motivi(l, c)` adds `"variante"` if sample `c` or another sample of the pair is one (the page gives the whole pair to a single reader); the module's `probe` (`mzlab-lettori-wasm`) answers `{"formato":"sciex-wiff","campioni":[],"motivi":["variante"]}` even when the open fails with `err.file.wiff`.
- Sparse blocks without an `sMRM` stream (files with or without a Log): `reader.rs::build` (feature `sciex`) reads the first MRM block of each experiment; if it starts with `-(N + 0.01)` (`scan::sparse_head`) the sample is a variant (`other_version`), so the probe gives it to the module instead of the engine, which would reject the block (`sparse MRM block`). Tests: `tools/wiff_mrm_sparse.py` (136 transitions with staggered windows, no Log), `sciex_probe.rs`, `test_wiff_programmati_sito.py` ("variant" probe, module mzML = CLI, engine that rejects).
- Page rule: the `sciex` row of `lettori-famiglie.js` has `sonda: true`; `shell.js::wiffToMzml` calls `LETTORI_MOD.probe("sciex", mem)` for every pair and, if the reasons contain "variante", creates one file per sample with `LETTORI_MOD.stand` (the engine does not see the pair). If the probe fails, the pair goes to the engine as before. Cost: every `.wiff` pair downloads and starts the `sciex` module (≈420 KB); `probe` (`open_probe`) builds the index of sample 0 only and judges the others from the method (`variant_of`), it does not read their blocks (`tests/test_wiff_sonda_leggera.py`).
- Never a full scan for an unknown code: in the module and in the CLI `err.file.wiffScanType` (`code`, `experiment`) and `err.file.wiffPeriods` (`periods`; several periods: no real file, cycle layout not verified); in the engine `Wiff::readable` rejects only the sample with a code outside `modi::nativo` with `err.file.wiff`, `detail` = `scan type code C (experiment E)`, and the module probe takes both keys as a variant; several periods are `err.file.wiffPeriods` also in the engine (next line).
- A sample that the reader rejects (unknown code, several periods, `.wiff2`) stays in the list with 0 scans and gives its error when its data are requested (`Wiff::refused`); the pair is rejected whole only if no sample opens. Test: `wiff_variants.rs` (`ms3_file` of `tools/wiff_riferimento.py`).
- The other rejections are `err.file.wiff` with `detail`: `no scan type code (experiment E)`, `TOF block` (block starting with `ffffffff`), `scan block version V` (V outside 1..3), `sparse MRM block` (also in the engine: `run.rs::dense_mrm` rejects a block that starts with `-(N + 0.01)` instead of reading its markers as intensities; a negative first cps of another shape, `scan::sparse_head` at ±0.004, is noise of a dense block), `MRM block`.
- TOF (TripleTOF, ZenoTOF, X500): code 8 (TOF MS) or 9; the `.wiff.scan` block codec is another one and there is no reference mzML for any TOF: always rejected. The SCIEX OS `.wiff2` is recognized by `Wiff2SampleInfo` (`WiffNSampleInfo`) next to an unconfirmed code and rejected with `err.file.wiffNeeds2`; code 0 is Q1 MS full scan (level 1, profile, like EMS; meaning deduced from the method name, the spectra and the Analyst ScanType table).
  In the CLI an X500 or QSTAR `.wiff` with the spectra in the `.wiff2` gives `err.file.wiffNoScan` (asks for a `.wiff.scan` that does not exist) and a `.wiff2` alone `err.file.notAccepted`, not `err.file.wiffNeeds2` [eseguito, WF-08].
- Modes table (`wiff/modes.rs`, `MODI`, index = code 0..16): Analyst abbreviation (Q1, Q1MI, Q3, Q3MI, MRM, Prec, PI, NL, EPI, ER, MS3, TDF, EMS, EMC; 8 and 9 "TOF MS", "TOF MS/MS", 10 "?"), level, CV, output and `confermato`. Confirmed (seen in real files): 0, 4, 5, 6, 7, 11, 13, 15; the others follow Analyst's `ScanType` enum. `modi::nativo` = {0, 1, 3, 4, 11, 15} (the engine), the `sciex` module accepts the `confermato` ones and the two SIMs; `modi::sigla(code)` gives the page the exact experiment type.

## Measured format (QTRAP 4500/5500/6500/6500+)
- Codes in `ExperimentHeader` +122: 4 MRM, 5 precursor ion (PIS), 7 neutral loss (NL), 8 TOF MS, 9 TOF MS/MS, 11 product ion/EPI, 15 survey/full scan. Polarity: u32 at +86 (0 positive, 1 negative; measured on 40 files; the IS sign does not give it). Fixed mass/precursor: f64 at +42 (`Experiment.precursor` of product ion 6; for EPI the method's one remains, not verified). PIS and NL are level 2; the header mass is the precursor of both, for the NL it is the loss (also in `Experiment.fixed`; `extended::refine`).
- Scan block: after `fe ff ff ff` a u32 version V ∈ {1,2,3}, then V ranges `[start, end, step, scale]` (f64), then u32 N and the nibble stream. m/z = start1 + bin·step1; intensity = count × scale of the last range k ≥ 1 with m/z > start_k, otherwise of range 0. The 3200 writes V = 2. Σ(count·scale) = index TIC on all real files (0 differences over 59 883 scans).
- MRM blocks: dense (one f32 cps per transition) or sparse (sMRM): the first f32 is `-(N+0.01)` with N = transitions of the experiment, then positive values (cps of consecutive transitions) and tokens `-(k+0.01)` = k consecutive transitions that measured zero (points at 0, not absent: every transition has a point in every cycle, like the vendor library); the sum must be N. Dense and sparse experiments alternate per row. Test: `crates/mzlab-lettori/tests/sciex_probe.rs` (`mrmrado.json` of `tools/wiff_mrm_sparse.py`).
- Scheduled (sMRM): msconvert keeps every transition in its window (target RT ± window/2) and fills with zeros inside the window; we write one point per cycle, zeros included (also outside that window, e.g. an isolated value equal to the row TIC); that the vendor cuts at the window is not proven. On the non-zero points of the mzML they all coincide (15 891 out of 15 891 in the test file); the test comparison for scheduled MRMs is "every non-zero point of the mzML is ours, with the same value".
- `Wiff.trim_scheduled` (off by default) cuts every scheduled transition to target RT ± window/2, like msconvert; test: `tests/wiff_scheduled.rs` (`programmati` of `tools/wiff_riferimento.py`).
- Scan TIC (`Wiff::has_tic`, like ProteoWizard): every full scan experiment (15, Q1), PIS, NL and MS3 gives a `TIC` chromatogram (id with `sample= period= experiment=` if the experiments with TIC are more than one) with the index TIC of every non-empty block, like the MRMs; product-ion (6, EPI), SIM and samples without a method have none. Tests: `wiff_modes.rs` (`tracce`, `bpc` of `tools/wiff_modes.py`), `wiff_variants.rs`, `tests/test_wiff_cromatogrammi.py` (module = CLI).
- BPC (`BPC`, same times and ids as the TIC; `Wiff::has_bpc`): full scan, PIS and NL (not MS3), the maximum of every scan; MRM (not SIM), the highest transition of every cycle, right after its TIC. `Wiff::visit` gives it with the spectra; `WiffReader` (`wiff/bpc.rs`) lists it only after the mzML writer has read all the scans (`extra_scansione` → `watch`: no second pass, `cromatogrammi` and `guscio` decode nothing), so it holds for the written spectra (centroids if `--peaks` asks for them).
- TIC of every spectrum in the mzML and in the `tic` section of the `.mzidx`: the one from the block index (`SpectrumExtra::tic`, `lettore::header_tic`, in every build, engine without `estesi` included; `scantable/inert.rs` does not treat a spectrum with a vendor TIC as inert) when it is finite and > 0, otherwise the profile sum. Site/app parity test: `tests/test_wiff_tic_parita.py` (engine in Node, `tests/mzidx_nativo_node.js`, against `mzlab-cli flow run`); the saved chromatograms stay different: the full scan TIC chromatogram exists only with `estesi`.
- Shared methods: a batch has one `MethodN` per distinct method, fewer than the samples. `wiff::method_no` chooses it from the `.dam` name in `SampleDABE/DATA` and in `AcqMethodFileInfoStm` (`method_name.rs`; the sample's own `MethodN` first if it matches). Otherwise the nearest `MethodN` below the sample, only if it acquires what its blocks have (`borrow_agrees`: `Idx` rows with points > 0 = scans; an MRM does not take a scan method nor the reverse), otherwise none. Tests: `wiff_mrm.rs` (pairs `transizioni_lotto` and `transizioni_misto`), `wiff_prestito.rs` (`wiff_mixed.py`).
- The nearest `MethodN` is found in a single pass over the container paths, never with a search for every number below the sample: 1 000 samples open in under a second (`mzlab-lettori/tests/robustness_wiff_samples.rs`).
- Spectrum types in the mzML (`Lettore::extra_mzml`, `cv:<accession>` parameters of `mzmlwrite.rs`): `MS:1000341` precursor ion spectrum, `MS:1000326` constant neutral loss spectrum (in the `fileContent` and in every spectrum).
- PIS: the fixed Q3 m/z is the spectrum precursor (`Experiment.precursor`, `extended::refine`), as in the ProteoWizard mzMLs: `<precursorList>` with window ± `iso_half`, selected ion, CID activation and CE if the method has one; no `<productList>`. NL: like ProteoWizard, the header mass (the loss) is the selected ion of the `<precursor>`, without `<isolationWindow>` (`SpectrumExtra::no_window`), with CID activation and CE like the PIS; the loss (Da) is also the userParam `constant neutral loss (Da)` (`modes::LOSS_PARAM`).
- MS3 (code 13, 3200 QTRAP): level 3, `precursor` = second isolated mass (`ExperimentHeaderQTrapEX` +64, f64), the first (`ExperimentHeader` +42) in the userParam `ms3 first precursor m/z`, abbreviation `MS3` in `KINDS`; V3 blocks; with a single mass in the header it is read as MS2.
- Not seen in any file: `MS:1000789` enhanced multiply charged, `MS:1000791` enhanced resolution, Q1/Q3 scans: no code produces them yet.
- Instrument: `Header` with the CV term of the model (`estesi::instrument_cv`: 4000 QTRAP, API 4000, 3200, QTRAP 4500/5500/6500/6500+, Triple Quad 4500, TripleTOF 5600/6600, QSTAR); a model without a term is `MS:1000031` + userParam `instrument model`.

## `method/1` (estesi: `method_wiff/extended.rs`)
- Fallback method (above) for samples without a `MethodN`.
- Scheduled experiment: in the stream `Experiment<i>/sMRM` (52 bytes) u32 at +36 = 1 and u32 at +40 = window in seconds (360 in the "6minWindow" file, 120 in the one whose mzML keeps 120 s around the target). The experiment carries `programmato: true` and `finestra_s`; in its transitions the number that the method keeps in the dwell time field is the target time in minutes and the field is called `rt_min` (not `dwell_ms`).
- `campi`: strings of `SampleSubtree/DabsInfo` and `SampleTable` (`s1`, `s2`, …: sample name, plate type, position), tables of `MethodN/GLPTables` (UTF-16 text: Q1/Q3 calibrations and resolution, detector; one entry per table, titled by the first row) with the Analyst version ("File was created with the software version", `mappato: strumento.software`), DAD header (see below).
- `campione.nome` CONFIRMED: first string of `SampleSubtree/SampleN/SampleDABE/DATA`, now used for `Campione.nome` in `wiff/reader.rs` and in `wiffName` (`conversione.js`). The Analyst version CONFIRMED from the GLPTables (1.6.3 and 1.6.2). `campione.vial` (last string of `DATA`, numeric, 0 without a plate) is still TO BE CONFIRMED.

## What is NOT read
- Several periods (`Period1…`), for every scan type: `err.file.wiffPeriods` (`periods`) in the module (`extended::refine`) and in the engine (`one_period`), never folded onto Period0; no real file has them, the cycle layout is not verified. Test: `wiff_mrm_edges.rs` (`mrmperiods`, `fullperiods` of `tools/wiff_mrm_edges.py`).
- The true precursor of a dependent EPI: the mass at +42 is the one saved with the method, not the one chosen by the IDA at every cycle, and `DDERealTimeData` is not read; for this reason a sample that has the `DDERealTimeData` stream writes its experiments 11 WITHOUT precursor (level 2, channel `dd:2:EPI`), in engine, reader and mzML (`wiff/mod.rs::dependent_scans`; test `crates/mzlab-core/tests/wiff_ida.rs`, file `ida` of `tools/wiff_riferimento.py`: one IDA sample and one fixed-mass sample). Without that stream the EPI keeps the header mass.
  Today a public IDA sample with `DDERealTimeData` gives "partial read, 0 of 1170 scans" (`warn.wiff.damaged`): every scan block is counted as damaged by the block check [eseguito, WF-14b, open; before the check the 1170 spectra were written].
- `.wiff2` (SCIEX OS) and TOF (codes 8, 9): rejected, another codec and no reference mzML.

## DAD
- 3200 UV/Vis detector (DAD): reading, map, UV spectrum, TWC/XWC, integration and MRM panel in `dad.md`.
- `Devices/Device_N/{Channel, DevRealTimeHeader, DevData}` (column pressure, flow, temperature) are chromatograms after the TIC (`wiff/devices.rs`): a pressure (name with "pressure" or unit psi, bar, mbar, Pa, kPa, MPa) in pascal as `pressure array` (MS:1000821, `pressure_unit.rs`, like Thermo), the others with the file's unit; a channel without points is missing, a repeated name takes ` #N` (the device). Assumption: point k is at k × the channel step from the start (the stream has no times); `scale_min/max` are not used.
- `DDERealTimeData` (IDA) is not read: `raw-not-extracted.md`.

## Tests
- `tools/wiff_riferimento.py`: `variants(out)` writes `variante.wiff` (QTRAP 5500, V1 and V3 blocks, EPI, PIS, NL, an empty block) and the files to reject (`periodi`, `tof`, `codice`, `bloccotof`, `versione4`), with the expected values in `riferimento.json`.
- `tests/wiff_variants.rs` (feature `estesi`): synthetic, rejections, damage (every byte overwritten: no panic); `tests/wiff_variants_real.rs`: with `MZLAB_DATI` the real files (`dati/formati/sciex/wiff`, `scansioni_speciali`): 32 files, 388 samples read, 6 rejected (TOF and `.wiff2`), index TIC always equal; comparison with the ProteoWizard mzMLs of PIS/NL (3594 spectra) and MRM (108 chromatograms, 94 scheduled); `method/1` (name, window, `rt_min`, version, DAD).
- `tests/wiff_scheduled.rs` (`programmati`: two MRM experiments, one sMRM with a 60 s window): one TIC per experiment, `rt=`/`window=` in the ids, optional cut; `tests/wiff_mrm.rs` (`transizioni`): CE, dwell and name up to the mzML.
- `tests_e2e/e2e_wiff.py`: the synthetic "variant" pair goes through the `sciex` module.
- Real files are missing for: multiple periods, EMC/ER, Q1/Q3 scans, EPI with precursor (the mass at +42 is the method's), TripleTOF/ZenoTOF (TOF block codec).
- `tools/wiff_modes.py` + `tests/wiff_modes.rs` (feature `sciex`): matrix of the 14 modes in `modi/<SIGLA>.wiff` and `modi.json` (code, confirmed, today's expectation: read with level/precursor/CV type or rejected with `scan type code C (experiment 1)`, future expectation); Q1 has 3 samples with only Method1 (samples 2 and 3 take it from `method_no`), read as EMS; codes 1-3, 12-14, 16 are assumptions from Analyst's ScanType enum, the Q1MI/Q3MI blocks (one f32 per ion) too; Q1MI/Q3MI read as SIM. Whoever adds a mode changes `modi.json`.
- SIM (Q1MI 1, Q3MI 3; no real file, `tools/wiff_sim.py`, `tests/wiff_sim.rs`, `e2e_wiff_sim.py`): blocks read as a dense MRM (one f32 per ion and cycle), every ion is a `ChromKind::Sic` chromatogram with id `SIM SIC Q1=<m/z> sample period experiment transition dwell polarity=positive|negative name` (`Wiff::trace_of`, engine and `sciex`), never SRM; in the mzML the ion is the target of `<precursor>` (without activation), plus `MS_dwell_time` (s); masses from the counted `MassRangeEx` (rows `Q1, Q1, 0, dwell`, empty name; `wiff_massrange.rs`, pair `sim`); without a table: `SIM #<transition>`.
- SIM on the page: the `SIM SIC Q1=…` header is a transition without Q3 (`mzmlhead::chrom_of`: `kind "srm"`, empty `q3`; in the `source.rs` list it is `ChromKind::Sic` as in the reader), so the SIM-only file is of type "mrm", `/api/mrm` lists the ions with `q3: null` and the page key is Q1 alone (`trKey` in `grafici.js`); in the Data panel it is the `sim:` channel with label `SIM <m/z> (+|−) <dwell> ms "name"` (`channels.rs::sim_label`).
- Test classes (`[eseguito]`, `[letto]`, `[non provato]`) and readers-review codes: as in `waters.md`.
