# Browser capabilities and the common notice

- `capacita.js` (ES module, first in the list of `carica.js`; `window.CAPACITA` for classic scripts): feature detection, never the user agent; page probes once per load (≈0.1 ms), nothing saved, the function comes back by itself when the browser supports it.
- Names: `simd128`, `opfs`, `opfsSync`, `cartellaLocale`, `webgl2`, `isolamento`. `opfsSync` lives only in workers: the engine worker reports it in `ready.cap` (`rust-bridge.js` → `nota()`); until the capability arrives it is "being checked" and the function stays on.
- `REQUISITI`: function → capability (`motore`: simd128+opfs+opfsSync; `cartella`: cartellaLocale; `mappa3d`: webgl2; `indiceParallelo`: isolamento). `indiceParallelo` without isolation: the constructor decodes on its own (same bytes) and `rust-worker.js`, for an mzML of at least 32 MB (`BIG_IDX`), sends `{op:"cap-off"}` and `rust-bridge.js` calls `serve`: the common notice once per session. A function turns off only if one of ITS capabilities is missing. `serve(function, command)` → true, or false with the notice.
- `avviso-capacita.js`: `aria-disabled` on the command, a `cap.missing` note with the link to the app next to it, a summary line in `#cap-live` (`aria-live=polite`); colors from CSS variables. In the desktop app everything is "yes" (native engine).
- Testing: `?cap-off=name1,name2` or `MZLAB_CAP_OFF`. Test: `e2e_capacita`.
- Same switch style in the address, but remembered by the service worker: `?nav=cache` / `?nav=network` (pages from the cache or from the network, `service-worker.md`).
- Linked points: engine (`rust-bridge.js` `start`), pointed folder (`cartella-puntata.js` `supported`), library folder (`libreria-corpo.js` `folderOk`), 3D map (`mappa.js` `open3d`). Fallbacks decided by Federico remain (OPFS instead of the folder, `FileReaderSync`, `nowebgl2` of a context that is then not created).
- Isolation (`SharedArrayBuffer`): `sw.js` adds COOP/COEP/CORP to every same-origin response (also from cache); `isolateOnce` in `browser.js` reloads ONCE on the first visit with no open files (guard `sessionStorage` `mzlab.coiReload`; `?cap-off=isolamento` does not reload; after a reset only the guard equal to the `?ripn=<nonce>` of the address counts, so the reset ends up isolated by itself). A cross-origin resource must have CORS/CORP. Test `e2e_isolamento`; `Run.page` sets the guard (the nonce, if the address has it).
- Fallbacks for missing APIs (not turned-off functions): `compat.js`, first import of `capacita.js`; table for Safari and iPadOS in `compat-safari.md`.

- **Rule**: the site uses the best of recent browsers (up-to-date Chrome/Edge, Firefox, Safari) and checks function by function with feature detection in a single place (`capacita.js`), never the user agent; a missing function turns itself off with the common notice and the link to the app, and comes back by itself when the browser supports it; the rest of the site always works. No fallback engine in the site: the fallback is the app, with the same bytes.
- **OPFS read block** (`BLOCK` of `crates/mzlab-wasm/src/blocks.rs`): 4 MiB, because in Chromium every `SyncAccessHandle.read` goes through the browser process: at 4 MiB reading is ~2.5× faster than at 1 MiB (about 1200 versus 490 MB/s); Firefox and WebKit do not change. Firefox and WebKit give a single handle per file: a parallel reader uses ONE per file.
