# Bruker timsTOF reader (`.d` with `analysis.tdf` or `analysis.tsf`)

`crates/mzlab-lettori/src/bruker/` (feature `bruker`, `.wasm` module `bruker`, ceiling 524 288 B; measured after `wasm_opt -Oz`: 416 514 B with `ruzstd`). Registry entries: `bruker-tdf` (members `x.d/analysis.tdf` + `analysis.tdf_bin`) and `bruker-tsf` (`analysis.tsf` + `analysis.tsf_bin`); a `-wal` next to the database, if present, is read (the last confirmed frame wins).
- Bruker folders without `analysis.tdf`/`.tsf` that the module does not read are recognized (`Forse`, `legacy_key` in `tdf_helpers.rs`) to say what they are: only `analysis.baf` → `err.file.brukerBaf`, `analysis.yep` (ion traps) → `err.file.brukerYep`, `ser` or `fid` directly in the `.d` folder (FT-ICR) → `err.file.brukerFtms`, a `fid` next to `acqu`/`acqus` outside a `.d` (MALDI FLEX) → `err.file.brukerFlex`; all tell the user to export to mzML.
- The page gives the same keys (`BrukerD.legacyKey` in `agilent-d.js`; FLEX among the ignored files, `CartCarica.flexMaldi`). BAF, YEP, FT-ICR and FLEX stay unreadable without the SDK.
- A database without its `_bin`, a `_bin` without its database or a database that is not SQLite (empty or cut copy) are `Forse`: `apri` gives `err.file.brukerNoBin` (`name` = folder, `file` = the missing file) or the SQLite error with key; the page does the same count (`BrukerD.missing` in `agilent-d.js`).
- A frame of the index that names an absent or unusable row of `MzCalibration` (`MzCal::validate`): its m/z cannot be computed, so its spectrum leaves the index on opening and is counted (`Lettore::missing`, cause `warn.bruker.noCalibration`, `BrukerReader::uncalibrated`), the rest is read; only a run in which no frame is left is `err.file.brukerCalibration` (`frame` = `Frames.Id`).
- A damaged or cut `.tdf`/`.tsf` or `_bin`, or one with an unread layout (SQLite page, zstd block), is `err.file.brukerDamaged` when it stops the run: the warning text does not show the reader's detail (`detail`, written by the CLI after the key). A damaged auxiliary table (`GlobalMetadata`, `TimsCalibration`, `PropertyDefinitions`, `GroupProperties`) keeps the rows read before the damage and is flagged in `Data::damaged` and in `method/1.warnings` as `meta.danneggiato`; the run is read.
- A frame whose block does not decode (zstd, sizes) leaves the spectrum without points and counted, and is worth 0 in the BPC (`traces.rs`), never the whole run. The count comes from reading the spectra (`readers::Skips`): a BPC requested alone does not count it.
- Damaged pages or records of the database (`sqlite_min/walk.rs`, `tolerant` mode that `apri` turns on): a page that cannot be read or does not add up (type, count, cycle) is left out with what depends on it, a record that does not decode is left out alone; they are counted per table (`Sqlite::left_out`) and go into `method/1.warnings` («table T, P damaged pages and R damaged records left out»). The frames of a lost page are not in the index: their number is not in the file, it is not estimated. Strict mode stays the default of `Sqlite`.
- Cut `*_bin` and frames without calibration together: `losses` keeps the cause `warn.file.brukerCutBin` and counts both; the spectra without calibration are also counted in `method/1.warnings` (`meta.danneggiato`, `BrukerHeader::uncalibrated`), so both causes are stated.

## Module files
- `sqlite_min.rs`, `sqlite_schema.rs`, `sqlite_wal.rs`: read-only SQLite 3 reader without an SQL engine (no `rusqlite`). Table b-tree pages (5, 13) and index pages (2, 10, for `WITHOUT ROWID` tables, with reordered columns: primary key first), overflow, WAL log. Iterative walk with every pointer, length, depth and page count passed through `Limiti`; a page already seen or a cycle is an error, not an infinite loop.
- SQLite overflow: a chain that returns to a page, or a cell that declares more bytes than the file's pages hold, is `err.file.brukerDamaged` (`tests/robustness_sqlite_overflow.rs`), never the same value copied over again.
- `block.rs`: `tdf_bin` blocks. `zstd()` uses `ruzstd` only after reading the window and size announced by the zstd frame header (the ceiling is `Limiti.byte`) and requires the exact expected size. A block starts with `u32` length, `u32` number of scans (`ns`), then the data.
- `calib.rs`: m/z calibration. `tables.rs`: database tables. `spectra.rs`: spectrum slicing (`stretches`: the scan ranges merged and passed to the per-scan offsets `Picchi::inizio`; `summed`: merge by TOF index, 11-bit radix of 1024 points). Bench: `examples/bruker_bench.rs` (`measurements-formats.md`). `tsf.rs`: TSF blocks. `header.rs`: `method/1` and mzML header. `tdf.rs`: `ENTRY`, `BrukerReader`.

## Tables read
`Frames`, `Precursors`, `PasefFrameMsMsInfo`, `DiaFrameMsMsWindows`, `DiaFrameMsMsInfo`, `PrmFrameMsMsInfo`, `PrmTargets`, `FrameMsMsInfo`, `MzCalibration`, `TimsCalibration`, `GlobalMetadata`, `Properties`, `PropertyDefinitions`, `GroupProperties`. A missing table has no rows (not an error). Every key of `GlobalMetadata` ends up in `fields` (origin `bruker:global`); operator, serials, paths, folders, computer and user are marked `identity`.

## Blocks (`Frames.TimsId` = offset in `tdf_bin`)
- Compression 2 (`TimsCompressionType`, zstd): inside the zstd, `ns + 2·np` `u32` words written in 4 byte planes (all the 0 bytes, then the 1 bytes, ...). The first `ns` are the header (scan `s` has `word[s+1]/2` peaks, the last one the rest of `NumPeaks`); then pairs (TOF index delta, intensity). The accumulator starts at `u32::MAX`: the first TOF index of a scan is delta−1.
- Compression 1: `ns+1` `u32` offsets, then for each scan an LZF stream of `i32` words: a negative word skips |v| TOF indices, a non-negative one is an intensity at the current index, which then advances by 1. The number of scans is the one written in the block (the whole ramp, e.g. 985), not the one in the `Frames` table.
- Cut `*_bin` (interrupted copy): on opening `tagliati` (`tdf_helpers.rs`) flags the frames whose block does not end inside the file (a block ends where the next begins; only the header of the last one that starts in the file is read); their spectra leave the index, `Lettore::missing` counts them and the rest is read (TIC, BPC, mzML, `.mzidx`). `Reader::losses` gives declared, read and the cause `warn.file.brukerCutBin` (`tdf::CUT_BIN`), written in `conversion/1` of the mzML by the module and by the CLI (which exits with 3).
- TSF: `u32` size of the zstd profile, `u32` size of the zstd lines; the lines are `NumPeaks` TOF positions `f64` then `NumPeaks` intensities `f32`; the profile (if there are no lines) has `DigitizerNumSamples` `u32` samples, kept only if nonzero.

## m/z (`MzCalibration`, `ModelType` 1)
`t = DigitizerDelay + DigitizerTimebase·tof`. With `k = 1e6/√C1`, `u = t − C0 + C2·C4`, `s = 2u / (k + √(k² + 4·C2·u))`, `m/z = s² − C4`. No centering shift. Per-frame temperature correction: `m/z · (1 − 1e-6·(dC1·(T1frame − T1cal) + dC2·(T2frame − T2cal)))`. Non-finite constants or `C1 ≤ 0` give an error with a key, not numbers.

## Intensity
They are raw counts (those of the block). `SummedIntensities` and `MaxIntensity` of the `Frames` table are normalized to 100 ms: the TIC of the index is `SummedIntensities·AccumulationTime/100`. Equal TOF indices in the same spectrum are summed (msconvert leaves them as separate points: same sums).
- Chromatograms: TIC (MS1 from `Frames`, MS2 summed from the points at the first call of `indice`; probe, mzML, `conversion/1` and the SRM test ask for `index_without_tic`, without decoding frames: `crates/mzlab-lettori/tests/bruker_without_tic.rs`) and BPC, the maximum of the 32-bit intensities of every survey spectrum; the reader keeps the maximum of every spectrum already decoded (`maxima`, `traces.rs`), so the BPC after a full round (`.mzidx` index, mzML) decodes no frame again. Test: `bpc_equal_before_and_after_the_round_trip` (`tests/robustness_bruker.rs`).

## Spectra
- `MsMsType` 0 (MS1): one frame is one spectrum, mobility summed.
- 8 (DDA-PASEF): one spectrum per (frame, precursor), rows of the same pair merged, scans summed, with isolation (`IsolationMz`, `IsolationWidth`) and CE; order: first scan of the window (like msconvert). In the `<precursor>` of the mzML the selected ion is `MonoisotopicMz` (or `LargestPeakMz`), the window center `IsolationMz` and the charge `Charge` of `Precursors` (a charge of 0 or empty is not written); test `tests/bruker_precursor.rs`.
- 9 (diaPASEF): one spectrum per window of the group (`DiaFrameMsMsInfo` → `DiaFrameMsMsWindows`) and per cycle.
- 10 (PRM-PASEF): one spectrum per row of `PrmFrameMsMsInfo`.
- Other types: one spectrum per frame, level 2 if `FrameMsMsInfo` exists.
- Scan ranges are half-open [start, end), from 0. The filter strings contain neither «SRM», «MRM» nor «CRM» (so they are not mistaken for triple-quadrupole traces).
- Per-point mobility does not enter the engine. In `fields` of every spectrum are the TIMS scan range and, for TDF, the warning `meta.nonDecodificato` (see below).

## Method and header
`method/1` from `GlobalMetadata`, `Properties` and the calibrations (`MzCalibration`, `TimsCalibration`); `mzml_header` with `Header::run_params` = `("mzLab method/1", document)`, instrument, serial, software, `startTimeStamp` and SHA-1 of `analysis.tdf` (TDF only); components quadrupole + time-of-flight + microchannel-plate detector (the file does not name them), from which the scan table reads high resolution (`hr1`, test `a_timstof_is_high_resolution`).

## Tests
- `cargo test -p mzlab-lettori --features bruker`: unit tests (varint, columns, calibration, TSF) and `tests/robustness_bruker.rs` (SQLite and `tdf_bin` built in the test: confirmed WAL, unconfirmed and with wrong checksum, `WITHOUT ROWID`, page cycle, long varints, fake zstd and with a huge window, lying peak counts, truncations at every step, `tdf_bin` cut inside a frame, BAF, Agilent folder); `tests/test_lettori_parita.py` (`test_bruker_with_truncated_tdf_bin_equals_cli`): same mzML from the module and from the CLI for a cut folder.
- `tests/bruker_data.rs` (real data with `MZLAB_DATI`, skipped without it): comparison with the msconvert mzML (`combineIonMobilitySpectra`) on a DDA-PASEF run and an MRM one with compression 1: maximum difference 0.07 ppm on m/z, same intensity sums; a clean diaPASEF folder; the synthetic folders of timsrust.
- Page: `tests/test_bruker_d.py` (node): a `.d` folder with `analysis.tdf` goes to the `bruker` family, a `.D` with `AcqData` to `agilent`; in `lettori-famiglie.js` the `bruker` row comes before `agilent` and decides from the members (`analysis.tdf`, `analysis.tsf`, `analysis.baf`), never from the extension. `agilent-d.js` (`BrukerD`) sends the folder to the module with `LETTORI_MOD.stand`.

## Not verified
- Compression 2 has no reference mzML: it is checked only against `Precursors.LargestPeakMz` (a few ppm) and by reading real folders (DDA, MRM, diaPASEF with WAL).
- TSF: m/z equal to that of Bruker's `.mgf` on one sample; mobility not verified.
- Inverse mobility 1/K0 (`TimsCalibration`, `ModelType` 2): the formula is not known nor derivable from the files, so it is not computed; the scan ranges are written (DEV-10 will use the points with mobility).
- BAF is not read (it needs the Bruker SDK).
- TIC of the index: the factor `AccumulationTime/100` assumes `SummedIntensities` is normalized to 100 ms in every schema version; it is not verified on all versions (no synthetic file or document decides it), so the rule stays this one.
