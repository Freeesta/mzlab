# Single loading bar (`mzlab/web/progresso.js`)

- **One model** for every load (`.mzML`, `.raw`, `.wiff`, `.D`/Waters folders, ready-made `.mzidx`): `PROGRESSO` (classic script, before `conversione.js`; row in `carica.js` and in `tools/tipi/pagina.json`/`stretto.json`). The page bars show what the model says: the rows of the files being loaded (`CONVROWS`, below), the "Load data" veil (`waitStato` in `shell.js`: phase, "n of N", elapsed time every second, "Preparing the files" while no file is in the batch, "Cancel" in `#ldact`) and Tabui (`loadMaker` in `20_tpmine.js`).
- **Loading rows**: `upload0` adds a `CONVROWS` row IMMEDIATELY for each file of the batch (and `upload(..., demo)` for the examples, `fetchDemo`: the download is the first 40% of the row, `CONVROWS.base`), in order of arrival; the rows live only in the side list (`upload-rows.js`), never in the work area, and each goes away when its file is open. `#up` has no bar or card.
- **Layout still during the batch** (`e2e_carico_stabile`): while files are being read the work area stays the entry page (`workState`), with the drop zone still; the load table (`CONVROWS.table/tools`, `.ldtab`, `table-layout:fixed` with `colgroup`) holds only the files read. One count and one clock for the whole job (`CONVROWS.ready`), at the top of the side rows.
- **In-place updates**: the "Download/Save" buttons live in `.cvtool`, always present (`data-off` + `inert` = invisible, same space); a new percentage changes only its side row (`UPROWS.fill`, wraps `CONVROWS.fill`), `renderFiles` is only for adding or removing rows (`paint` merges the requests). `UPROWS.paint` rewrites `#fl-up` only when its shape changes (count row, rows in order, which are in error: `box._k`), otherwise it updates text, `title`, bar and count in place, never rereading the `innerHTML` (`tests/test_righe_carico.py`).
- **End of batch**: no reordering (rows stay in order of arrival, `CONVROWS.rank`, until the student edits a value: `thaw`); no card, ring or closing text is left; if no file is shown the first one is opened (`OPENNOW.first`).
- **Bar of a row**: `rowPc(native, frac)` (`progresso.js`, tested by `tests/test_progresso.py`). Builder files: load 0-40%, read 40-85%, index 85-100% (0.3 and 0.75 of the model). mzML: the model fraction as it is (`mzmlFrac`); never backwards (`CONVROWS.base` + `set`).
- **Phases of an mzML**: `mzmlFrac(byte, phase, local)`, phases `MZML_STAGES`: load (copy into OPFS), start (pool worker), scan (scan table), read (the builder reads the file), index (the passes from scratch, only above `MZML_SPILL_MB`), list (index opening and file entry; not `open`, which closes the provisional TIC). Each phase weighs its measured cost `MZML_COST` (ms = fixed + per MB).
- **Row text and summary**: on the right "Downloading/Loading 12/28 MB" (bytes), "Reading 3 200 / 5 500 scans" (from the engine; for an mzML the share of the file read by the builder over the scans of its table), "Indexing". "Queued" with no percentage while no builder is free (`pc` null; the bar keeps `bar`, the last). At the top "3 of 5 ready · 0:12" (`CONVROWS.ready`), read by `#cvlive` (`role=status`, only when the count changes); the rows have no `aria-live`. Bars updated at most every 100 ms (`queue`).
- **Waiting for the engine**: a file dropped before `AVVIO` is ready already has its row (state `engine`, `conv.st.engine`/`conv.row.engine`, no percentage, bar at 0); when the engine is ready the row moves to "Queued" and then to the normal phases, on the same element (`startup.md`).
- **Queued before the copy**: in a batch the copy of a file waits for a slot (two copies at a time) (`createCopyGate` in `rust-carica.js`, the copy's `wait`): the row says "Queued", with no percentage, until its copy starts.
- **Input**: the event `mzlab-index {name, frac, phase}` (`frac` = 0..1 of the whole file; phases `read`, `open`, `scans`, `chrom` of `nativo-fasi.js`, `W`, plus `done`/`total` scans and `wait` in queue for the `CONVROWS` rows). `upload0` in `shell.js` calls `PROGRESSO.begin(name, size)` for all the files of the load before reading any, `set` on every event, `end` at the end (also on error).
- **Input of an mzML**: `lr.js` composes `mzmlFrac` from the phase and its fraction: the copy (`lr_put`, and its end), the pool (`stages`: worker created 0, `.wasm` delivered 0.5, ready 1), `idx-worker.js` (scan and read from the position read, index = bytes reread / written to scratch; at most every 100 ms, `tick`). The desktop app sends no progress during `lr_index` (single reply): the row goes from start to end.
- **Measured costs** (headless Chromium, 4 cores, synthetic mzML; `MZML_COST`): 0.16 MB: copy ~30 ms, worker start 40-270 ms (270 with the `.wasm` still compiling), table ~20 ms, builder ~100 ms, opening ~30-45 ms; 76 MB: copy ~0.8 s, table ~0.2 s, read ~1.5 s, passes ~1.4 s (they reread ~99% of the bytes written to scratch), opening ~30 ms. Five 0.16 MB files: two wait ~0.3-0.45 s for a free builder ("Queued").
- **Rules** (tested by `tests/test_progresso.py`, for every reader, with sequences that go back and repeat, plus a fuzz): a file never goes back; the total never goes back (a file added midway widens the denominator, the shown value stays); no 100% before `end()` of the last file (at most 99); weight of a file = size; when the batch is done, the next `begin` restarts from 0. The phase shown is that of the slowest file, with "n of N" when there is more than one file.
- **Conversions** (`ConvUI` in `conversione.js`): in loading (`moduloToMzml`, `box` null) nothing is drawn: progress is the side row; each file has its own `AbortController` (`ConvUI.stop`, the row's x). "Download .mzML" of a sample (`CONV.make`) shows the card in `#up` with its bar (same rules: `maxPc`, at most 99 until `end()`, which removes it); convert/index weights in `PROG_W.conversione` (0.75/0.25, like `CONV_W`; `progCompose`).
- **Browser test**: `tests_e2e/e2e_progresso.py` (mzML series + `.wiff` pair, records `aria-valuenow` of the side rows: forward only, 100 only at the end, no bar in `#up`; five mzML: no row stuck at the same percentage beyond 400 ms unless "Queued", which shows no percentage).
- **Common panel for the other heavy operations** (`mzlab/web/avanzamento.js`, ES module imported on first use): `avanza(box, {title, n, cancel, signal, t, eta})` gives `item(k, name)` ("k of n: name"), `set(frac|null, text)` (bar forward, `aria-valuenow` only if the percentage is known, never 100 before the end), `ok`/`fail(name, msg, diag)`/`stop`, `end({head})`. Used by the library packs (`libreria.js`, `cancel: false`: "Cancel" stays the window's); Tabui's Dig (`t` = English texts); tests `e2e_esempi.py`.
- `silent: true`: a clean outcome leaves no summary, the panel fades in 0.5 s (immediately with reduced motion); errors and cancellations stay.
- **Common panel rules**: clock every second, "Still working..." after 2 s without news, advice after 30 s, remaining time only beyond 5% (or `eta`) and 3 s; at the end the summary "k of n completed, n failed, n cancelled · m:ss" with the errors and "Details"/"Copy diagnosis" (or only "Copy diagnosis" if the diagnosis is a text), which disappears by itself after 8 s only if nothing failed.
