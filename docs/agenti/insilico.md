# In-silico candidate package (`spectra.insilico`)

- **What it is**: the structures of PubChemLite for Exposomics (CC-BY-4.0, DOI 10.5281/zenodo.22953038, version and SHA-256 fixed in `tools/genera_sospetti.py`) in pieces by mass interval, which `spectra.insilico@1` ranks. Data, never code in a `.wasm`; never in the repository.
- **Format** (`insilico/1`, schema `docs/schemi/insilico-1.json`): `catalogo.json` + `NNN.bin` (zlib of a CSV with the columns `Identifier,CompoundName,SMILES,MolecularFormula,MonoisotopicMass`, sorted by mass and id, about 12 MiB raw per piece). Per piece: mass interval, rows, compressed and raw size and SHA-256.
- **Packer**: `mzlab-cli db insilico pack PUBCHEMLITE_CSV OUT [--version T] [--doi T] [--json]` (`crates/mzlab-cli/src/insilico_pack.rs`); no network, no clock, same input same bytes. The one-line summary goes to stderr; stdout is empty, or with `--json` the `insilico/1` catalogue just written (a saved format: its first key is `format`, not `schema`). `read_piece` reads and checks one piece of a folder.
- **Site**: `pages.yml`, job `packages`, downloads the CSV (`tools/pubchemlite_pacchetto.py`, SHA-256 checked), packs it into `site/static/insilico/`; cache on the key of the sources + packer sources + `Cargo.lock`; a network error only warns.
- **Download in the browser** (`mzlab/web/insilico-scarica.js`, uses the helpers of `normative-scarica.js`): two clicks. The first asks only for the catalogue and shows "N MB"; the second downloads the pieces into Cache Storage `mzlab-libs` (each one checked, catalogue written last, Cancel). Before the click no request starts. After that everything is offline.
- **Windowed reading**: `mzlab-feat/src/flow_insilico.rs` (the only implementation, site and app). The window of a precursor is the neutral mass ± `db_ppm`; only the pieces that intersect it are read, one at a time. In the browser `flow_insilico_pieces` names the pieces, the page decompresses and checks them (`reader`), `flow_insilico` ranks. Same `candidates/1` as the whole CSV file.
- **`suspects` input**: recognised from the bytes: CSV, `screen/1` (structures of its outcomes) or `insilico/1` catalogue. The catalogue of the plan must match the installed one, otherwise the step is blocked (`input.insilico`: download the package or choose a list).
- **Site executor**: `flow/lazy/flow-web-insilico.js` (one entry in `F.liveJobs`); the "In-silico candidates…" button is in the node results. Texts in English in the Flow (`flow-ui.js`).
- **App**: `crates/mzlab-desktop/src/insilico.rs` puts the same pieces in `<libraries folder>/insilico/` (routes `insilico/status|install|check|cancel`); `flow run` takes `insilico/catalogo.json` as `suspects` and reads the pieces next to it. Tests: `insilico_pack_tests.rs`, `flow_insilico_tests.rs`, `insilico_tests.rs`, `tests_e2e/e2e_flow_insilico.py`.
