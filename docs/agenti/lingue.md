# Interface text (English only)
The core is in CLAUDE.md. mzLab (site, desktop app, CLI) and the qqq teaching site are English only; the Italian dictionaries, the language selector and `?lang=` were removed. The catalog keeps the key structure of a multi-language catalog (`lang/<lang>/<area>.js`, keys, `I18N.t`) so that a translation could come back later: keys stay, strings are never inlined in the code.

- All new text is written in English in `mzlab/web/lang/en/<area>.js`. The program always starts in English; a language stored by an older version (`mzlab.lang`, `qqq.lang`) is ignored silently, no migration.
- `i18n.js` (loaded first) + `lang/en.js`: in the source a loader that writes the area files `lang/en/<area>.js` (see below).
  In the built site the catalog is two files (`bundle_lang` of `tools/build_site.py`, test `tests/test_bundle_lang.py`): `lang/en.js`, blocking before the first paint, has only the keys written in `index.html` and in the scripts loaded before `carica.js` (plus the prefixes they build, e.g. `cmd.`); `lang/en-resto.js` has the rest and `carica.js` puts it first in the queue, before any other script.
  Until the rest has arrived (`I18N.awaitRest`/`I18N.done`) a missing key gives "" (never the bare key), goes into `I18N.late` with a `console.error`, and the static HTML keeps its text until `done()`; `tests_e2e/e2e_lingua_parti.py` and `e2e_tour` want `late` empty.
  Keys are `area.component.item`. `I18N.t(key, params)` with reduced ICU ({name}, plural); `data-i18n`, `data-i18n-html`, `data-i18n-title`… for the static HTML (the HTML holds the English text); `I18N.num/fix/err` for numbers and errors.
- **Area files**: one key per line in `lang/en/<area>.js`, a key in one file only, ≤500 lines; a new key goes in the file of its prefix (or in `altre-*` if the prefix is small); a new file goes in the loader list. From Python: `tools/lang_catalog.py`; guard: `tests/test_lang_parti.py`.
- `<html lang>` and the title are set by a tiny inline script at the top of the head of `index.html` (its hash is in the CSP: `python3 tools/csp_hash.py`). Codes are stored, never translated texts (panel titles `@chrom`…, types `blank`/`sample`); text written by the user is never translated.
- A technical term of spectrometry goes in `lang/glossario.json` with its source (`en` forms to use, `evita_en` forms to avoid, `chiavi_ok` keys where an avoided form is legitimate); a message with parameters has its description in `lang/contesto/<area>.json` (same name as the area file, only that area's keys; the description of a key no catalog has stays in `contesto/orfane.json`; `controlla_i18n.py` checks the right file). Python returns keys and parameters (`UserError`, `message()`), not sentences; the server answers `{error, error_key, params}`.
- **Engine errors**: every `err.*`/`error.*`/`warn.*` key written as a literal in `crates/` (except `mzlab-cli`, `mzlab-desktop`, `mzlab-llm`, tests and examples) has its text in `lang/en/errori-*.js` (by family, the 2nd segment of the key: `-flow`, `-file`, `-llm`, `-a-m`, `-n-w`; ≤250 lines); `controlla_i18n.py` looks for it (list `CRATES_WITHOUT_TEXT` for keys no student sees, one reason per entry) and `I18N.err` shows `error.generic` with the detail when a key has no text, never the key.
- **Errors in the terminal**: `mzlab-cli` prints an engine error with the text of `lang/en/errori-*.js` (included in the binary with `concat!(include_str!(..))`, `{name}` parameters filled) and the key in brackets, `error: <text> (err.x, other=parameters)`, then `(mzlab-cli COMMAND --help)` of the command run (`crates/mzlab-cli/src/error_text.rs`; the `--report` of `convert` keeps the raw key). The catalog stays one line `"key": "text",` per entry, without escapes: the test `every_key_of_the_catalogue_is_found` checks it.
- `python3 tools/controlla_i18n.py` rejects keys used but missing or orphan, bad ICU braces, a static-HTML text that differs from the catalog, Italian left outside the catalog (and inside it), glossary forms to avoid, missing context descriptions and vendor/tool names.
- Names and classes of contaminants are English: `chem/contaminants_en.json` (a test requires the entry for every id). The recognition of the names of the user's files stays Italian-aware (`project.py`): file names are data.
- Tests: the e2e tests read the English texts of the catalog; `e2e_avvio_lingua`/`e2e_lingua` check that a stored language is ignored and the page starts in English.
- **Traps**: a literal key in `t("…")` or `data-i18n` must exist in the catalog (the check does not see keys built from pieces: use `t(`prefix.${x}`)`); `t()` never builds a sentence from pieces; an HTML attribute (`title`) cannot contain `"` or entities (`&Delta;` is written `Δ`).

- **Numbers**: everywhere the decimal is the point and there is no thousands separator: the only formatter is `NF` in `i18n.js` (`I18N.fix`, `I18N.num`, `{x, number}`, `#` of the plural; one `Intl.NumberFormat` per number of decimals, built once: `tests/test_i18n.py`); never `toLocaleString`, `Intl.NumberFormat` or `.replace(".", ",")` in the code. Input with a comma is normalized with `.replace(",", ".")` where it is read. CSV exports use "," and ".".
- **Saved memory**: a `localStorage` value read as an object goes through `lsObj(key)` (`i18n.js`: a plain object or `{}`, never an error). The notebook (`NB`, `explore.js`) is cleaned by `nbClean`, saved with `nbMerge` (only the fields changed by THIS tab win, other tabs are not undone), refreshed at `visibilitychange` (`nbSync`) and not saved before it has been read; one save at a time (`nbQueue`), the one superseded by a newer one is dropped (`nbGen`); tests `e2e_memoria`, `e2e_shim`.
