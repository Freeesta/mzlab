# `family_record`: la famiglia di un file a richiesta
- **Cosa fa**: `family_record(read, size, name, recipe)` (crate `mzlab-feat-wasm`, modulo `family.rs`, feature `detect`, quindi nel `.wasm` HR; passo Rust `family::record`) rifà L1-L3 di UN file `.mzidx` con gli stessi passi di `analyse_file` e restituisce il record `famiglia/1` (`mzlab_feat::famrecord::record`): le prove degli archi, che né `.mzfeatf` né `.mzfeat` salvano, nascono qui e non restano.
- **Argomenti**: `read(k, offset, length) -> Uint8Array` e `size` come `detect_file` (file 0 soltanto); `name` finisce nel campo `file` del record; `recipe` è il JSON di `detect_file` (`{"polarity": 1|-1|null, "mode": ...}`, più `floor`, `min_height`, ...) e vale lo stesso `recipe_for`: stessa ricetta della pagina = stesse famiglie della tabella.
- **Uscita**: una stringa JSON `{schema:"famiglia/1", file, families:[{family, size, members:[{row, mz, rt, role, parent...}], arcs:[{lo, up, delta_mz, delta_rt, r, kind, admitted_by, readings:[{kind, name, step, ppm}], proofs:[{kind, value, threshold, points, sign}]}]}]}`. Solo numeri e parole, nessun verdetto; `row` è la riga del `.mzfeatf` dello stesso file.
- **Errori**: stringa JSON `{error_key, params}` come gli altri export: `error.badRecipe` (ricetta non valida), `error.badIndex`/`error.io` (lettura), `error.memoryBudget` con `{fase:"family_record", stima_mb, budget_mb}` se il testo stimato (600 B per riga + 900 B per arco) non sta nel budget del `.wasm` (192 MB, nessun parametro).
- **Determinismo e prova**: stessi byte con gli stessi ingressi; `crates/mzlab-feat-wasm/tests/family_record.rs` (serie sintetica `degdma`, salta senza python3/numpy) confronta il record con quello dell'esempio nativo `famiglie.rs`, la seconda esecuzione e il rifiuto a budget zero.
- **Peso**: il `.wasm` HR dopo `wasm-opt -Oz` passa da 1 131 442 a 1 136 182 B (+4 740) sotto il tetto `limit_hr` 1 212 416.
