# The compact `commands --json` listing: what is left out and how to put it back

Moved from `cli-agenti.md`. The whole listing (no PATH) stays under the 33,000-byte cap of `the_whole_listing_is_compact_and_the_path_listing_is_full` by saying once what is shared and leaving out what the usage line or a rule already gives; `commands --json PATH...` gives each command in full. The schema is `docs/schemi/commands-1.json`, the code `crates/mzlab-cli/src/catalog/doc.rs`. Every rule below has a test that puts the data back and compares it with the full listing.

## Rules
- The whole listing (no PATH) is compact, under the 33,000-byte cap: a flag used by two or more commands has its `help` once in the top-level `flag_help`; `exit_codes` is left out when derived from the usage line (`derived_exits` in `catalog/doc.rs`), `examples` when it is only the usage line without its `[optional]` parts, `stdout.format` when `json` (`stdout_note`), `stdin` when an argument is `NAME|-`; `--json` and an optional `--out` are only in the synopsis (`implied`).
- Read from the synopsis (`catalog_restore_tests.rs` puts each back and compares with `commands --json PATH...`):
  - a flag has no `required` when the usage line writes it outside `[ ]` and `( )`, no `repeat` when its value ends `...`, no `enum` when its type is `enum` (the values are the `a|b|c` of its value);
  - a command has no `args` when every argument is a path (or `...`): they are the words of the usage line that are not a flag, a flag's value or `|`, in order, `optional` inside brackets, `repeat` when ending `...`. A command with a non-path argument keeps `args`.
  - It was 28.6 KB of the 33,000-byte cap when these rules were added (32.6 KB before).
- Types: a flag carried by two or more commands that all give it one type other than `string` has that `type` once in the top-level `flag_type`; no flag `type`: its `flag_type`, else `string`; an arg with no `kind` is a `path` (`rest` for `...`), one with no `optional` is required.
- The derived exit codes: 0, 1, 2 always; +3 when the path starts with `flow ` or is a verdict command (`VERDICT` in `crates/mzlab-cli/src/contract.rs`); +4 when it has a path or rest argument or a path flag other than `--out`; +5 when it has `--sample` or `--id` or its path starts with `sample `, `dad ` or `msn graph`; +6 when it has `--out`. The derived example is `mzlab-cli ` + the synopsis without its `[optional]` groups (a word with a bracket inside stays) and without `...` tokens. Both rules are also in the `exit_codes_note` / `examples_note` of the listing.
- `commands --json PATH...` gives each command in full, always with `type`, `kind` and `stdout.format`. To add a command: write its row and `FLAG_HELP` text as before; do not add members to the compact listing without moving something out (`the_whole_listing_is_compact_and_the_path_listing_is_full`).
