# The page dialog «Choose samples» (PR 4 of the wiff chooser plan)

Plan: `wiff-sample-choice.md`; CLI side: `sample-flag.md`.

- `mzlab/web/wiff-choose.js` (lazy, `carica`), called by `wiffToMzml` (`shell.js`) once per loading, BEFORE any sample is read: the pairs of the loading are listed with `native_samples(.., listing = true)` (`samples_list/1`: container and index, the `.wiff.scan` is not read), ONE modal `<dialog>` lists them, one table per file (tick, name, number, type, scans, size), then only the ticked samples become files of the list. The skipped samples are never indexed; with a subset chosen only the byte ranges of those samples are copied to OPFS (PR 5, `wiff-range-copy.md`).
- No sample logic in JS: the list and sizes come from the engine, the first ticks from the engine's `sample_default` (wasm) = `mzlab-cli sample select FILE --default [--budget-mb N]` (`readers::selection::suggest`; byte parity test `tests/test_sample_selection_parita.py`), the «numbers» field (`1,3,5`, `2-4`) from `sample_selection`. Worker ops `natdefault`, `natselect` (read-free), page method `nativeAsk`.
- Q1 (done): the dialog shows only when some file has several samples; Settings > Data > «Choose samples of a file»: «When a file has several» (default), «Always ask» (also a one-sample file), «Never, open all» (today's behaviour). Key `mzlab.pick` in localStorage (absent = default). Q2 (done): all ticked when the sections add up to at most a quarter of the engine's memory budget (`SMALL_SHARE`), none ticked otherwise; Open stays disabled until something is ticked, nothing is blocked. Q3: wiff-first, the dialog takes any `samples_list/1` with several samples.
- Open questions decided simply (the owner decides afterwards): one dialog for all pairs of a loading; Cancel opens nothing from the loading and says so in a note; the choice is NOT remembered per file yet; no name filter, no per-file select buttons (global «Select all», «Select none», numbers field); a reopened file with a subset chosen skips the OPFS cache check (it would answer with every sample); a pair the readers module takes (`variante`) is filtered by the ids of its probe.
- Not here: date/vial columns (X1), the owner's Analyst 1.6.3 screenshot (the layout is one table per file in `wiff-choose.js` and `.wiffchoose` in `app.css`, easy to change).
