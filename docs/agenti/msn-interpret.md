# Interpretation of MSn fragments (`interpretation` of `msn-graph/1`)
Optional key of the graph (schema `docs/schemi/msn-graph-1.json`); graph contract in `msn-graph.md`. They are evidence with a reason and a confidence, never verdicts: the user can always change them. Computed in Rust only.
- **Where**: `crates/mzlab-core/src/msngraph/interpret.rs` (table `known_losses()`, `interpret`, `interpretation_json`, `with_interpretation`); tests in `tests_interpret.rs`. Same inputs = same bytes; without the key the graph does not change.
- **Losses (phase 1)**: the table has the common neutral losses (Hill formula, English name, exact mass from the formula). For each edge: with the formulas of the two nodes the loss is looked up by formula (`source: "formula"`, `confidence: "high"` if it is in the table and within the window, otherwise `low` with `name: null`); without formulas it is looked up by mass within `max(ppm × precursor m/z, 2 mDa)` (`source: "mass"`, `medium` if only one, `low` if more than one, the others in `alternative`). `activations` = the distinct activations that saw the edge.
- **Command and page**: `mzlab-cli msn-graph FILE --interpret [--loss-ppm 10]`; the route `api/msn_grafo?interpret=1[&loss_ppm=10]` (`crates/mzlab-msngrafo-wasm`) gives the same bytes. The "Fragmentation graph" tab always asks for `interpret=1` for the drawing (not for exports and library) and shows in the node panel "Neutral loss to this ion" (`lossLine` in `infusione-grafo-nodo.js`): name, formula, mass, error, confidence, activations, alternatives; evidence, not a verdict. The step `spectra.msn_graph@1` has the parameters `interpret` and `loss_ppm` (same bytes).
- **Rules (`rules` of `msn-graph/1`)**: table `crates/mzlab-core/data/fragrules-1.json` (schema `docs/schemi/fragrules-1.json`), strict reader in `msngraph/rules.rs` (a key outside the schema is `err.fragrules.badKey`; masses are recomputed from the formulas), evaluation in `rules_evaluate.rs` (tests in `tests_rules.rs`). Without SMILES the rules that do not ask for structure apply (`Regola::structure_law` false); those that ask for it wait for the products expected from the structure (below).
- **Rules, adduct**: the adduct is that of the typed formula (`+H`/`-H` if it is just the ion; `[M]+` = none) and a rule with `ions` holds only on the root precursor.
- **Rules per edge**: the rules whose formula (or mass within `loss_tolerance_mda`, 3 mDa) is the loss, with error, priority and source keys; `composite` = pairs of rules whose sum is the loss (only if the edge has a beam measurement: everything that is not CID); `stepped` = a measurement at summed energies; warning `warn.msngrafo.radicalLoss` (a loss with an odd number of electrons from an even-electron ion without a `radical` rule).
- **Rules, cut-off and counts**: trap cut-off (`CID` measurements only): `q/0.908 × precursor m/z`, `q` = `cutoff_q` (0.25); `unobservable` lists the rules whose product falls below it, and an edge to a node below the threshold carries `warn.msngrafo.belowCutoff`.
- **Rules, counts and evidence**: `counts` = `{explained_edges, edges_without_rule, explained_intensity}` (share of the maximum intensity of the edges). The `ion` rules (e.g. Na+) mark the nodes with that m/z. Formula candidates gain the `rule` evidence when the loss from the precursor's candidate is that of a rule.
- **Rules, output for the page**: each applied rule carries `why` (reason for the downgrade, from the engine) and `refs`; `rules.fonti` = `[{key, doi, pmid}]` of the cited sources and `rules.soglie` = `[{id, value, why, origin, to_calibrate, refs}]` (`trap_cutoff`, `loss_tolerance_mda`: in `fragrules-1.json` they have `origin` and `to_calibrate: true`); the page has no copies of the table.
- **Rules: command and page**: `--rules [--cutoff-q 0.25] [--loss-tol-mda 3]`; query `rules=1&cutoff_q=&loss_tolerance_mda=` (the key is added in `graph_json`, so `.wasm` and command give the same bytes); step `spectra.msn_graph@1`: `rules`, `cutoff_q`, `loss_tolerance_mda`. Without `rules` the bytes do not change.
- **Structure rules**: with `rules` and a SMILES, `mzlab_feat::chem::rules::with_expected` (command in `msn_graph::graph`; on the page the `.wasm` `msnregole` computes them and `rust-msngrafo.js` passes them in the key `expected`, `wasm-caps.md`) fills `Opzioni.attese` (`Attesa{rule, formula, ion}`): for each rule whose required groups (`all_groups`/`any_groups`), excluded groups (`excludes`) and `site` are satisfied by the structure, the product it gives (the table's formula, or the one computed from the site).
- **Rules, comparison with the graph**: the core (`rules_evaluate.rs`) compares them with edges and nodes like the formula-only rules; a `cleavage` rule without a site (`remote_fixed_charge`) produces nothing. A SMILES that cannot be read leaves only the formula rules.
- **Rules, groups and sites**: `Mol::groups_ext()` (`chem/rules_site.rs`) = `groups()` plus `phosphate`, `sulfate`, `o_glycoside` (5/6-membered ring with one O, at least 3 C with an exocyclic O, O-glycosidic bond at the anomeric carbon) and `glucuronide`; `groups()` and `regole_tp/2` do not change.
- **Rules, the sites**: the 17 `site` values are named functions on `Mol::site` without SMARTS; those with a product compute it: `gamma_h_carbonyl` (alkene of the ester = alkyl minus one H), `cyclohexene_ring` (the two pieces of the retro-Diels-Alder, only if the molecule splits), `benzyl` (C7H7 if the piece with the ring is not substituted), `alpha_c_n` (N side of each acyclic Cα-Cβ bond), `acyl` (carbonyl side of each acyclic single bond of the carbonyl). A group or site name in the table that the code does not know makes `chem_rules.rs` fail.
- **`after` rules**: a rule with `after` holds on an edge only if an edge entering its precursor is explained by a rule of `after` (second pass of `evaluate_with`); without a previous edge it does not apply, and does not enter `composite` or `unobservable`.
- **Bond breaks (`breaks`)**: `crates/mzlab-feat/src/chem/breaks.rs` (computation) and `mzlab-core/src/msngraph/breaks.rs` (types, JSON; schema in `msn-graph-1.json`). With the SMILES, for each node the pieces of the structure with 1 or 2 single bonds cut (each cut gives an H to the piece) and up to `h_max` H moved (−2..2, 0 = simple cut) whose m/z falls within `struct_ppm` of the node's: `hypotheses {bonds, piece, formula, h, theoretical_mz, ppm}` (≤20 per node, `n` counts all).
- **Breaks, edge and coverage**: an edge is `explained` if a hypothesis of the child lies inside one of the parent; `counts.intensita_spiegata` = share of the spectra's intensity on explained edges.
- **Breaks, limits**: a salt is not cut (`structMixture`); beyond 120 bonds the pairs use the first 120 (`rottureCapped`); hypotheses, never assignments.
- **Breaks: command and page**: `--breaks [--h-max 2] [--max-bonds 2] [--struct-ppm 10]`; query `breaks=1&h_max=&max_bonds=&struct_ppm=` of the `.wasm` `msngrafo`; step `spectra.msn_graph@2`: `breaks`, `h_max`, `max_bonds`. Without `breaks` the bytes do not change. Tests: `crates/mzlab-feat/tests/chem_breaks.rs`, `crates/mzlab-cli/src/msn_graph_breaks_tests.rs`.
- **Exports**: the tables `nodes` and `modifications` (`tables.rs`) add columns (`bond_break_*`, `loss_name`, `loss_confidence`, `bond_break_explained`) only if the graph has the keys `interpretation`/`breaks`; the export routes of the `.wasm` accept `interpret=1` and `breaks=1` like the graph route (`with_keys`).
- **Page**: with a SMILES and an ion, `viewUrl` also asks for `breaks=1`; the node panel shows the hypotheses (`infusione-grafo-rotture.js`: formula, m/z, ppm, bonds, H) and whether the loss from the precursor is explained, as evidence.
- **Library**: `msn-lib add` accepts `--interpret` and `--breaks` (with `--smiles`) like `msn-graph` (`msn_graph::with_keys`): the `msn-lib/1` entry embeds the whole graph with the keys `interpretation` and `breaks`, and `table_text` on the entry's graph (and of the step `msn.table_export`) shows the conditional columns. Test: `msn_lib_tests.rs`.
- **Validation** (`mzlab-cli msn-rules RECORD... --rules --decoy SEME` prints one line of numbers per record, `msn-rules sum` aggregates them by layer and polarity; orchestration in `tools/validate_rules.py`, engine in `crates/mzlab-cli/src/msn_rules/`): coverage (a)/(b)/(c) against three deterministic decoys (shuffled structure `Mol::rimescola`, spectrum of another record, shifted losses); numbers, thresholds and downgraded rules in `msn-manual.md` §7.

## Substructure checks (`site`)
- No SMARTS in the engine (the table's `smarts` is documentation only): each `site` is a named function on `Mol` (atoms, bonds, written aromaticity, implicit H) in `crates/mzlab-feat/src/chem/rules_site.rs`, with a test on a generic molecule. The 17 names: `amide_nh2`, `n_dimethyl`, `n_ethyl`, `gamma_h_carbonyl`, `methyl_ester`, `methoxy_near_charge`, `acetate`, `acetyl_on_heteroatom`, `chromone`, `cyclohexene_ring`, `so3h`, `methoxy_aryl`, `ureido_nh2`, `n_methylcarbamate`, `benzyl`, `alpha_c_n`, `acyl`. A rule is evidence with its source, never a formula choice.

## Fragment formulas (`msngraph/formulas.rs`, `candidates.rs`, `annotate.rs`)

Code: `msngraph/formulas.rs` (ion), `candidates.rs` (sub-formulas, DBE, electrons, M+1), `annotate.rs` (windows, evidence); tests: `tests_formulas.rs`, `tests_selection.rs`, `tests_decoys.rs`.
- **Input** (`options.formula`): the ION (`C8H11N4O2+`, `C8H11N4O2-`, `C8H11N4O2 [M]+`) or neutral + adduct: positive `[M+H]+`, `[M+Na]+`, `[M+NH4]+`, `[M+K]+`; negative `[M-H]-`, `[M+Cl]-`, `[M+HCOO]-`, `[M+CH3COO]-` (also `+H`, `-H`, `+CH3COO`); charge 1, electron mass subtracted (positive) or added (negative).
- **Polarity**: that of the file (most of the scans); windows, sub-formulas and losses are the same in the two polarities. Unreadable formula: `warn.msngrafo.badFormula`; sign or adduct of the other polarity: `warn.msngrafo.polarity`; in both cases the graph stays mass-only.
- **Root**: the level-1 node closest to the theoretical m/z within 0.5 Da (the isolation window); beyond `ppm_formula` (MS1 missing, nominal precursor of the method) the formula still holds with `warn.msngrafo.rootMissing` on the node; no node within 0.5 Da: `rootMissing` without a node, no formulas and no nodes removed. Only the nodes reached from the root along the edges are annotated, isotopes excluded.
- **Windows**: candidates = sub-formulas of the root (DBE ≥ −0.5, ≤4096 per node) with m/z within `ppm_formula` (10) of the node's m/z.
- **Wide window**: below `low_mz` (150: there the Orbitrap is off by 1-2 mDa absolute, i.e. 10-20 ppm) a candidate up to `low_ppm` (20) also holds with at least `min_evidence` (1) evidence items: `loss` (from a candidate q of a precursor, q − c is a known loss of `LOSSES`, by counts), `isotopes` (`m1` observed within ±30 % or ±2 percentage points of the expected M+1 of the formula; it does not hold, for or against, when `isolation.stretto`, see "Isolation window"), `msn` (the node is isolated and one of its fragments has a candidate in the narrow window under c).
- **Hierarchical constraint (DAG)**, at a fixed point: a candidate of a fragment lies under a candidate of each precursor that has one (if none satisfies them all, one is enough: a co-isolate stays) and at least one precursor has one (one without does not); a candidate of an isolated precursor contains a candidate of each fragment that has one, provided one remains. Recalibration (`ricalibra`, ≥5): after removing the median ppm, beyond max(2; 4.8 half-widths of the densest 40 %) it drops out. Even electrons: with a narrow even one, radicals without evidence drop out (`prefer_even`).
- **User choices** (`choices`): each goes on the node closest to its m/z within the window (`warn.msngrafo.fixedNotFound` if there is none) and becomes its only candidate; the children are constrained to it. Elements outside the root: ignored; outside the window or not under a precursor: it stays, with `warn.msngrafo.userConflict` on the node (one per node).
- **Output**: `candidates` by |ppm| then Hill, with DBE, electron parity (Σ atomic number − charge), window and evidence; `choice` and `source` only with one candidate (`single`), for the root (`root`) or from the user (`user`). Nodes without candidates leave the graph (with their isotopes) and are counted in `discarded_formula`; an isolated precursor removed leaves `warn.msngrafo.isolatedUnexplained` with the id of its tree node.
- **Warning on the graph** (`annotate::muchi_non_spiegati`): with ≥ 50 % of the fragment peaks' intensity without a node, `warn.msngrafo.mostUnexplained` (wrong formula or adduct?).
- **Unexplained**: the peaks of a spectrum whose node leaves the graph stay in `spectra[].picchi` with `node` null and are counted on the precursor node (`unexplained`: how many fragments, the 3 most intense), so the user sees what was not annotated.
- **Isolation window**: width from the file (`iso` of the scans; the widest among the scans of a tree node).
- **Effect on intensities**: with a narrow window only the precursor's monoisotopic passes, so no fragment has the M+1 (`isolation.stretto` below 2 × 1.00336 Da: the page does not present the absence of the M+1 as a defect) and the relative intensities of the monoisotopic fragments stay those of the monoisotopic alone.
- **With a wide window** the precursor's M+1 (≈ 1.1 % per C) also enters: its fragments that keep the 13C go to the fragment's M+1, those that lose it with the neutral loss add to the monoisotopic, which gains about 1.1 % × (C of the loss) of its value: a few %, less than the uncertainty between scans. The narrow window instead changes the absolute intensity (fewer ions), and at deep levels leaves fewer peaks above `min_rel`.
- **Losses**: for each edge between two nodes with a choice and the fragment under the precursor, `loss.formula` (the usual name of the known loss, `NH3` and not `H3N`, otherwise Hill) and `loss.ppm` (deviation of the loss in ppm of the precursor's m/z).
- **Without a formula**: no assignment; the losses are Δ m/z with the list of known losses compatible within the tolerance (written "compatible with H2O", never "H2O").

## Structure cuts for a node (`structures`)

Optional key of `msn-graph/1`; interface in `infusion-graph.md`. They are candidates with evidence, never identifications: the broken bond stays a hypothesis.
- **Where**: types, input from the graph (`Grafo::structures_input`: m/z, polarity, peaks of the spectra of which the node is the precursor, candidate formulas) and JSON (`structures_json`, `with_structures`) in `crates/mzlab-core/src/msngraph/structures.rs`; computation in `mzlab_feat::chem::structures::structures` on the fragmenter `chem/fragmenter.rs` (the same as Attributio, `attributio-revisione.md`). `mzlab-core` does not depend on `mzlab-feat`: whoever answers (`mzlab-cli` and the `.wasm` `msngrafo`, same bytes) calls `mzlab_feat::chem::structures::strutture_testo`.
- **Computation**: the acyclic single bonds of the molecule (the user's SMILES; at most 400; a salt or a mixture is not cut and gives `warn.msngrafo.structMixture`) are cut one by one, each side takes an H; the forms of each side are ion, radical, −H2O, −2H2O, −CO, −CO2, −NH3 (graph polarity). A cut is a candidate if a form of one side falls within `struct_ppm` (10) of the node's m/z; the other peaks of the node's spectrum that the same side explains are the cut's `peaks`.
- **Output** (`structures`): `{node, smiles, mz, ppm_tol, atoms, bonds, warnings, candidates: [{formula | null, theoretical_mz, ppm, cuts: [...]}]}`. Cuts with the same theoretical m/z (within 0.2 mDa) go in one candidate; `formula` is the node's candidate formula with that m/z (null without a formula or without a match). A root node or one without a compatible cut has an empty `candidates`. Same inputs = same bytes.
- **A cut**: `bond {idx, atoms [a, b], label}`, `side` 1|2 (carries the charge), `piece` and `rest` (0-based atom indices as in the SMILES), `formula` (neutral, with the cut's H), `variant`, `loss`, `theoretical_mz`, `ppm`, `peaks [{mz, rel, ppm, formula, loss}]`. Order: candidates by |ppm| and m/z; cuts by bond, side, variant.
- **Command and step**: `mzlab-cli msn-graph FILE --smiles S --structures nK [--struct-ppm 10]`; step `spectra.msn_graph@2` with the parameters `structures` (`nK`, `all` or `tutti`) and `struct_ppm` (same bytes). Errors with a key: `err.msngrafo.noSmiles`, `badNode`, `badSmiles`. Tests: `crates/mzlab-feat/tests/chem_structures.rs`, `crates/mzlab-cli/src/msn_graph_structures_tests.rs`, `flow_msngraph_tests.rs`.
- **Interface**: the fragment box of a node (level ≥2, with SMILES) asks for `structures=<id>` and shows the cuts; the site's engine (`.wasm` `msngrafo`, query `structures=<id>` and `struct_ppm`, errors with a key like the CLI) answers with the key; the e2e tests also use the simulated response `tests_e2e/fixtures/msngrafo_strutture.json`. Parity tests: `tests/test_msngrafo_wasm.py`, `e2e_msngrafo`, `e2e_infusione_grafo` (real engine). Details in `infusion-graph.md`.

## The `view` key (`msn-graph/1`)

Code: `crates/mzlab-core/src/msngraph/view.rs`, `layout.rs`, `layout_radial.rs`. Schema: `docs/schemi/msn-graph-1.json` (optional `view`, version 1). The format stays `msn-graph/1`: `view` is a trailing key that old readers ignore.

- **What it is**: what whoever draws the graph needs and the graph does not state openly, computed ONLY from the fields already present (`nodes`, `edges`, `measurements`), so `completa(json)` adds to an old graph the same bytes as a graph built today (test: built = completed). Abstract coordinates (columns, rows, rings, degrees): pixels and styles belong to the drawing. A rule proposal written in the JSON (`rule`), never a mechanism.
- **Position**: always last; `structures`, `structures_all`, `rules`, `interpretation` and `breaks` are inserted before it (`view::with_key`).
- **Head**: `{version: 1, algorithm: "best-path/1", rule (in words), order (id per column and row of the tree), nodes, edges}`.
- **`nodes[]`** (same order as the graph): `id`; `levels` (MS of the measurements in which the fragment is really present, `rel` > 0; the root [1]); `rel` (intensity in the parent's spectrum on the best path, % of the base peak; root: `rel_max`) | null; `rel_max`; `best {da (id) | null, steps, cost [steps, minimum rel along the path | null, isolated edges]}`; `incoming` (distinct precursors); `common` (entranti ≥ 2); `tree {col, row}`; `radial {ring, angle}`.
- **`edges[]`**: `{da, a, best}`; `best` is true if it is the incoming edge chosen for `a`.
- **Best path** (`best-path/1`, `view::percorsi`): dynamic programming on the DAG in topological order (the smallest index among the ready ones). Among the incoming edges the winner is: fewer steps from the root; then the highest minimum rel along the path (for each edge the most intense measurement counts); then more isolated edges; then the smallest precursor id. Test: the number of nodes where the path differs from a minimum-cost spanning tree (degenerate Chu-Liu/Edmonds, in the tests only) is the one expected on the synthetic graph.
- **Tree** (`posa::tree`): up to 8 barycenter rounds (the one with fewer crossings is kept), then swaps of adjacent rows while they remove more crossings than they make (only the edge pairs of the two nodes count); the node's `pos` stays the simple barycenter.
- **Radial** (`layout_radial.rs`): ring = steps of the best path; angle proportional to the leaves of the subtree of `best.da`, in degrees at 2 decimals, without trigonometry.
- **`completa`**: `mzlab-cli msn-graph complete IN.json [--out F]`, function `complete` of the msngrafo `.wasm`, `msnCompleta` in `rust-msngrafo.js`; error with key `err.msngrafo.badGraph` if the text is not an `msn-graph/1`; a graph with `view` comes back as it is.
- **Related options**: `molfile` (like `smiles`, `--molfile FILE`, step parameter with `--set`) and `structures=tutti` (the key `structures_all`: one `structures` value for each node of level ≥ 2 with candidates).
- **Loss**: `loss.formula` uses the usual names (H2O, NH3, HNCO, HF, HCl, H3PO4, HPO3; the rest in Hill order, e.g. C4H8).
- **Where it runs**: in the builder (`json` adds `view` at the end, so CLI, Flow and page write the same bytes) and in the msngrafo `.wasm` (`completa`); its weight and cap are in `wasm-caps.md`.
- **Test on 80 ions**: `tools/generate_msngraph_80.py` writes `tests_e2e/fixtures/msngrafo_80.json` (1 root, 9 levels, masses only; `view` added by `msn-graph complete`); `tests/msn_layout_80.js` (in `test_flow_grafico.py`) asks `layout` of `msngrafo-vista.js` for one box per ion and 0 overlaps in tree and radial; the tree's crossings against the barycenter (≤ half) are tested by `tests_view.rs`.
