# `.wiff` + `.wiff.scan` reader (SCIEX 3200 QTRAP)

`crates/mzlab-core/src/wiff/`: pure Rust, no new crate, no Python or Pyodide. The container is an OLE2 file read with `ole.rs`; the `.wiff` gives index and method, the `.wiff.scan` the points. The block format is NOT the one of OpenSXRaw (Sigilweaver, Apache-2.0: its QTRAP support does not work on 3200 files); it was derived from real files compared with the ProteoWizard mzMLs of the same files. Code written from scratch.

## Files
- `mod.rs`: `container(bytes, name)` (error `err.file.notWiff`), `samples(&Ole)` (sample numbers of the `SampleIdxTable`; an injection without an `Idx` stream, which acquired nothing, stays a sample with 0 scans: "empty" on the site with its number, an empty mzML on the CLI stated in the progress output; synthetic `gaps`), `Wiff::open(&Ole, name, scan_len, sample)` (`scan_len = None` → `err.file.wiffNoScan`; other failures `err.file.wiff` with `detail`), `Wiff { sample, records, experiments, polarity, method }`. One sample = one injection = one item on the site.
- `container.rs`: the container is read by sector (`Ole::open_at`, `open_member`): only FAT, directory and mini stream are held, so a `.wiff` above `WIFF_MAX` opens; `Wiff::load_dad` reads the DAD stream when asked for. Test: `wiff_by_sector.rs`.
- `run.rs`: `Wiff::run(&mut ReadAt) -> mzml::Run`: spectra (`Spectrum`, profile) and chromatograms of `chromatograms.rs`, equal in the engine and in `estesi` (one `TIC` per full-scan or MRM experiment with data (just `TIC` if there is one, otherwise `TIC sample= period=1 experiment=`), after an MRM TIC its `BPC` (highest transition of the cycle) and its SRMs, at the end the `BPC` of every full scan if the scans were decoded; PIS, NL and MS3 in the module: `wiff-variants.md`).
- SRM of `run.rs`: one `SRM SIC Q1= Q3= sample= period=1 experiment= transition= ce= dwell= polarity= name=` per transition (CE, dwell in ms and name from the method; in a scheduled experiment `rt=` (min) and `window=` (s) in place of `dwell=`; `polarity=positive|negative` of the experiment, absent if unknown; the mzML derives from it a CID `<activation>` with the CE, the userParam `MS_dwell_time` and the term `positive scan`/`negative scan`; test `crates/mzlab-core/tests/wiff_polarity.rs`), `unit` as in the mzMLs. The `Run`s are the ones the rest of the program reads.
- SRM/SIM units (oracle: `ChromatogramList_Sciex` of ProteoWizard): `ce=` of the id is the magnitude of the energy (a negative-mode method stores it with its sign; absent if 0) and `methodcheck` compares magnitudes; `dwell=` of the id is in ms, the userParam `MS_dwell_time` in seconds like msconvert (`mzmlsrm::dwell_param`), and `mzmlhead` gives it in seconds also for a SIM that has only `dwell=` (divided by 1000); test `tests/wiff_mrm.rs`.
- `names.rs`: `display_names(file, [(number, DATA name)])`, the single rule for sample names: the name written in the file stays; a sample without a name in a file with several samples is `<stem>_s<N>` (N = 1-based position, `_2`, `_3`... only if the name is already in use); a file with a single sample stays `<file> #<number>`. List, mzML and labels read `Campione.nome`.
- `unindexed.rs`: the `.scan` sections that the `.wiff` index does not list (below, "On the site").
- `idx.rs`: `SampleIdxTable` and `SampleN/Idx`. `scan.rs`: blocks (versions 1-3 of the scan block, the 3200 writes 2; a TOF block or one of another version is `err.file.wiff` with `detail`, never an empty scan) and codec. Polarity: one rule for engine and module, the one of the experiment header (offset 86: 0 positive, 1 negative), otherwise the sign of IS (`Wiff::polarity_of`).
- `methodinfo.rs::method_of_sample`: the method of the sample (optional: the samples of a batch can outnumber the methods, and some samples have no method).
- `tools/wiff_dump.py FILE.wiff [--all] [--log]` (standard Python only, `mzlab/reader/ole.py`): short text to find where a lab file keeps what the reader does not show yet (sample names, dates, vials): streams grouped by sample and method with their sizes, for each sample scans (rows of `Idx`), experiment types and readable strings of the small streams; `Log` (may hold the operator's name) only with `--log`. The output stays out of the repository. Test: `tests/test_wiff_dump.py`.

## Format (3200 QTRAP)
- `SampleSubtree/SampleIdxTable`: 32-byte header, 16-byte rows (u32 sample number, u32 position B). The sample's section in the `.scan` starts at B - 20; a row with B < 20 (an injection that acquired nothing writes 0) stays a sample without blocks (`idx::sections` gives `None`; synthetic `vuoto0`), never removed from the list.
- `SampleN/Idx`: 32-byte header, 54-byte rows: u32 offset (from section start), u32 size (= block length), f64 time in MILLISECONDS (+8), u8 (+16), f64 TIC in cps (+18, equal to the TIC of the mzML), f64 (+26, number of points, 0 = empty scan; not in an IDA sample, see below). Block k starts at section + offset + 44 and ends where the next starts (the last: end of file).
- An `Idx` row of all zeros (offset, size, time, TIC, +26) places no block (`idx::place`): it stays out, never a scan at rt 0 read to the end of the file, and it is counted in `losses` (`Wiff::unplaced`, `warn.wiff.damaged`; not the first empty row followed by real rows); synthetic `zeri`.
- One cycle = one row per experiment, in order: row k → cycle k / E, experiment k % E, with E = number of experiments of `Period0` of the method (1 if missing). The mzMLs omit empty scans (here too).
- Scan block: marker `fe ff ff ff 02 00 00 00`, 8 f64 `[start1, end1, step, scale1, start2, end2, step2, scale2]`, u32 N at +72, data at +76. m/z = start1 + bin × step; intensity = count × (scale2 if m/z > start2, strict comparison, otherwise scale1). There are two ranges because the detector has two scales. `step2` is not used (equal to `step` in all files seen).
- Nibble stream (high first) for N points, position `pos` in bins from 0: 1..7 = one point with that count (pos += 1); 0 = one point with a long count; 8 = long jump; 9..15 = jump of nibble - 8. "Long" = skip the rest of the byte if in the middle of one, then a byte v; if v = 0 four u32 LE bytes follow.
- MRM block (no marker): one f32 (cps) per transition, `size / 4` transitions.
- `MassRangeEx` with counted grammar (`methodinfo/mass_range.rs`, `wiff-full-spec.md` §2.2): if `ExperimentHeader` +176 announces N > 0 entries, the table is read as a 40-byte head + exactly N entries (counted UTF-16 name, even empty or non-ASCII; counted parameters) and nothing else; a stream with more or fewer bytes is `err.file.wiffMassRange` (`experiment`, `expected`, `detail`; `wiff/mass_check.rs`): sample refused in engine, reader and CLI. With N = 0 the marker search stays. Test `crates/mzlab-core/tests/wiff_massrange.rs`, fixtures `tools/wiff_massrange.py`.
- Transition masses: Q1 and Q3 at the precision of the file's f32 (the shortest decimal that rereads the same f32: 412.125 stays 412.125), with the counted grammar and with the marker search; CE, DP, EP, CEP, CXP at 2 decimals, dwell at 1.
- Method `MethodSubtree/MethodN/DeviceMethod0/Period0/ExperimentI/ExperimentHeader` (180 bytes): f64 at +42 = precursor mass (valid with code 11), u32 at +122 = scan type (15 = full scan, 11 = product of an ion; MRM has 0x0004FFFF). Level 2 and precursor only with code 11; any other code is read as a full scan (level 1). Polarity = sign of the `IS` parameter (ionspray voltage) of `Experiment0`; 0 if missing.


## Reader rules (isolated defects)
- R1 Isolate, never refuse: a damaged or odd unit (block, scan, spectrum, channel, sample, file section) stays out, counted and reported (`warn.<format>.damaged` with the number); everything else loads.
- R2 Smallest unit: the scan is dropped, not its sample; a sample is refused only if it has no usable scan, a file only if it has no usable sample; `err.file.*` only when nothing can be read.
- R3 Never silently: the read summary says how many units stayed out and where (partial read), equal on site, app and CLI.
- R4 Every reader has a synthetic fixture with one broken or odd unit among valid ones that loads everything else (byte parity site/app/CLI) and a test that no single-unit defect becomes a refusal of the file.
- R5 Every new check is non-fatal and is tried on the private real data before the merge.
- Metadata-only probe: `tools/wiff_probe.py FILE.wiff [--sample N]` (standard Python, own decoder): block versions, stream tokens, counts per class, bytes after the points and, per scan, sum of decoded intensities / TIC of the row (+18) in quantiles; no m/z or intensity printed.

## Profile/centroid policy
We keep what the file contains, with no implicit peak picking: the 3200 `.wiff` contains PROFILE data (bins of 0.06 with counts, zero bins are not stored: the ProteoWizard mzMLs fill them with zeros, here there are none), hence `Spectrum::profile = true`; the rest of the program treats profile files as always (peaks are found by `profile_peaks`). `raw.rs` also follows the rule: `profile` comes from `scan_mode` of OpenTFRaw (centroid list of the file; profile only if the scan has nothing else). Centroiding is a user option, not implemented in the reader.

## Parity (`tests/wiff_parity.rs`, `tools/wiff_riferimento.py`)
- Synthetic pairs written by `tools/wiff_riferimento.py` with an independent encoder (no lab data): m/z, intensities <= 1e-9, times and counts equal, level, precursor, polarity, MRM chromatograms, errors. Skips without `python3` (`MZLAB_GOLDEN_STRICT=1` makes it fail).
- Real files against the ProteoWizard mzMLs (private data repository, folder `dati/3200 qtrap/wiff/` with `mzML/` and `mzML_profilo/` beside it; `MZLAB_DATI`): 23 mzMLs (FullMass, MS2, MRM), points above zero, m/z <= 1e-9, intensities <= 1e-9 (1e-6 where the mzML has 32 bits), RT, level, precursor, polarity, chromatograms. Skips without data. The last scan of each mzML is excluded: ProteoWizard reads it wrongly (the TIC of the index confirms our value).

## On the site (conversion to mzML)
- `core/src/mzmlwrite.rs`: streaming mzML writer (`MzmlWriter`, `Header`; reuses the zlib state and buffers from one array to the next): nativeID as msconvert writes it, spectra with zlib (default level: the mzML bytes do not change), TIC/SRM chromatograms; reread by `mzml::read` gives the same data (test in `mzmlwrite/tests.rs`). `Wiff::to_mzml(&mut ReadAt, W, name)` (and `to_mzml_progress`, which reports every 32 spectra how many it wrote) writes a sample one spectrum at a time (`visit`, `spectrum_count`).
  - The `.wiff.scan` goes through `window.rs` (1 MB window: one JS read per ~1 MB instead of three per scan).
  - mzML header: the model of the `Component ID` of the Log (the Log writes "3200 Q TRAP": with spaces removed it is `MS:1000651`; another model is `MS:1000031` with the name in a userParam of the `<run>`; without Log, `MS:1000031` alone: another QTRAP written by SCIEX OS may also lack the Log), `startTimeStamp` from the file creation date (`SummaryInformation`, local time of the instrument PC, no time zone) and the SHA-1 of `.wiff` (`Wiff::wiff_sha1`, set by whoever has the bytes: `Ole::sha1_hex`) and `.wiff.scan` (`Membro::sha1` of the fingerprints if present, otherwise read once).
- `core/src/wiff/reader.rs`: the pair as a `Lettore` (`sciex-wiff` in `LETTORI`): the `.wiff` is read whole at opening (within `Limiti::byte`), the `.wiff.scan` by position (1 MB window that stops where the last block of the sample ends according to its `size`, `Record::data_end`; no block is read beyond its `size`).
  - The SHA-1 fingerprint of the `.wiff` is computed once per opening, not per sample. `apri_solo(fs, limiti, Some(c))` reads the block heads of sample `c` only (the others: 0 scans in `campioni()`, index built on first use): used by `build_mzidx_native` (`contato::apri`, `crates/mzlab-wasm/src/counted.rs`), because every sample has its own worker and a container with dozens of samples would reread the whole `.wiff.scan` for each.
  - Truncated `.wiff.scan` (interrupted copy): a block that does not fit whole in the file (`Record::cut`: start, end or `size` of the index row beyond the end) enters neither the index nor the MRM chromatograms, never read halfway; the sample loads with the whole scans and `Lettore::missing(c)` counts the cut blocks, `build_mzidx_native` returns it as `missing` and the sample row says so (`native-reading.md`, Summary).
  - Damaged `.wiff.scan`: a block that the index row says is full (+26 > 0, `Record::points`) but without a scan head (`Record::damaged`) stays out of index and engine and is counted in `losses(c)` with the cause `warn.wiff.damaged` (`TRUNCATED` if there are also cut blocks). +26 is not the number of points in every file (sparse 3200 product-ion scans: 1 where the head has 2 to 5 points; IDA sample: `points` NaN), so it is not compared with the head;
  - The block is judged on its bytes (`scan::read_block`, read whole when the index is built): the head's points occupy the row's `size`, with at most 4 bytes of padding (the 3200 carries a stream of `u` bytes to `u + 4 - u % 4`), even an empty head. `Block::Damaged` is a block its bytes contradict (padding beyond 4 bytes, head longer than the block, points beyond the stream), a TOF block (`ffffffff`) and a head with a version outside 1..3: it stays out and is counted in `losses` (`warn.wiff.damaged`), never read as a scan or MRM;
  - `scan::Tally`: a sample is refused (`err.file.wiff` with the cause of the first damaged block) only if all its blocks are damaged, with no scans or MRM blocks (`wiff_blocks_v13.rs`: `version4`, `tofblock`); equal in `visit` and `build`. Values changed at equal point count are not seen (no checksum). Tests `wiff_sparse_product.rs` (`tools/wiff_prodotto_rado.py`, `--odd`: padding, extra points, a TOF and a version 4 among valid blocks), `test_lettori_parita.py`, `wiff_damaged.rs`, CLI `convert_partial_tests.rs` (exit 3).
  - The refusal belongs to the single sample (`losses::isolate`: the `err.file.wiff*` error of `build` becomes its `failure`, at opening and in `ready`); the other samples of the pair open and convert byte for byte equal to the healthy pair (`wiff_isolation.rs`, `sciex_isolation.rs`, CLI `convert_isolation_tests.rs`; `tools/wiff_isolation.py`: `sano`, `guasto`).
  - MRM block with a NaN or infinite cps (or, in the module, a sparse block that does not add up): that cycle stays out and is counted (`chromatograms::Mrm::Damaged`, `Cycles`), the other cycles are read, never a NaN in the traces (engine `dense_mrm`, module `scan::mrm_cols`). An MRM sample that loses cycles counts them as cycles (`Losses::in_cycles`: "9 of 10 MRM cycles", `conversion/1.unita` = `cicli`); a whole one stays `complete(0)`. Synthetics `mrm_nan`, `mrm_taglio`.
  - `Idx` row of size 0 (a cycle that acquired nothing) of any experiment: stays out without being counted, so the TIC and every transition or SIM ion of a dense experiment have the same times (engine `run.rs`, module `run_extended.rs`). Test `tests/wiff_mrm_edges.rs` (`tools/wiff_mrm_edges.py`: empty row and first negative cps of a dense block).
  - Truncated `.wiff`: sectors marked as used by the FAT beyond the end (`Ole::cut_short`), or directory, mini FAT, DIFAT or first FAT sectors of the header beyond the end (`Ole::header_cut`, the copy cut before `Ole::open` finds the directory) → `err.file.wiffTruncated` in `wiff::container` (file bytes and bytes required), never `err.file.notWiff` nor an opening with 0 samples; test `crates/mzlab-core/tests/wiff_truncated.rs` (every length of the `.wiff.scan`, engine and reader equal).
  - `.wiff.scan` newer than the `.wiff` (copy made during acquisition): `unindexed.rs` looks, where the index data end, for the section marker (`11 11 11 11 82 05 00 00` + u32 number; the first block is 24 bytes later) and rebuilds each section as a sample after the indexed ones, MRM only: fixed-size blocks (multiple of 4) of the nearest indexed sample with that layout, which also gives method and times.
  - Rebuilt section: name `<file>_s<N>`, `mzlab:wiff-unindexed` in the mzML header; without a donor or with non-finite counts (NaN/inf; negatives are valid noise) it is excluded and counted. `Reader::unindexed()` = (recovered, excluded) → ONE note `warn.wiff.unindexed` (site, `convert`). Test: `crates/mzlab-core/tests/wiff_unindexed.rs`.
  - Tail: `last_id` counts only the table rows with a section; a trailing row with the same number is replaced by the recovered section (unique ids). The last block cut at the end of the file is a loss of the sample (`unplaced`, `warn.wiff.damaged`).
  - Reason per sample, never just "no data": index with a sample without scans or chromatograms = `warn.wiff.emptySample` (CLI: progress line; site: `"why":"empty"` of `native_samples`, tooltip and type-cell row); rebuilt section = `warn.wiff.inferredSample` (`"why":"inferred"`); unread scan type = `err.file.wiffScanType` with `type` (label of `modi`, e.g. MS3), `code`, `experiment`.
  - One `Campione` per injection: the index lists the non-empty scans (MRM blocks are chromatograms, read once by `Wiff::chromatograms` with the points counted at opening, `Parte::counts`), `scansione` = `Wiff::spectrum_of` as `visit`, `intestazione` gives sample, cycle, experiment, `metodo` = `from_wiff` (the SHA-1 of the `.scan` is not computed). Test: `tests/wiff_reader.rs`.
- `mzlab-wasm/src/natives.rs`: the two files are read by offset from Blob, the `.wiff.scan` never whole in memory (`native-reading.md`).
- Page: `shell.js::wiffToMzml` (before `rawToMzml` in `upload()`) pairs `.wiff` and `.wiff.scan` by name, lists the samples with `rb.nativeSamples` and makes one `x.mzML` file per injection (`NATIVO.sample`); they are read as they are (`native-reading.md`).
  - The sample indexes are built in parallel in the pool of `idxpool.js` (cores - 1, at most 4, 2 on phone/iPad); the copy of the two files into OPFS is a single one, the samples share it.
  - "Download .mzML" of a sample (`CONV.make`) writes its mzML on request; "Cancel" stops the writing.
- List: every pair enters the file list ("Converting", `CONVROWS` in `conversione.js`) as soon as its two files are together (row of the `.wiff`, "Reading the file"), then one row per sample with the index phase (reading, scan index, chromatograms) and the percentage; the row gives way to the real file when the index is there.
- Pairing: the two files of a pair are matched by name (case-insensitive), even if they arrive in different uploads (`WIFF_WAIT`); a file without a partner gives a warning (`err.file.wiffNoScan`, `load.wiffWait`) and stays waiting, also a TOF `.wiff` whose partner is a `.wiff2` [read, WF-08: `wiff-variants.md`].
- One mzML per sample: the DATA name of the sample (`name.mzML`; without a name `name_s<N>.mzML` if the `.wiff` has several); a name already taken goes through the `.raw` counter (`name.wiff.mzML`, `name_2.wiff.mzML`), never `_s<N>` (`conversione.js::wiffName`); they enter as normal files (OPFS, `.mzidx`), with the "Download mzML" button of the `.raw` files (`CONV`).
  - The list recognises the type (Full Scan, MS2, MRM) from the content; mzFinder LR reads the same files of the Data tab. Without the Rust engine `.wiff` stays an unopenable format (conversion guide). The desktop app does not convert `.wiff` files.
- Single sample without DATA name: the reader calls it `<file> #<number>` (extension as the file writes it, `.WIFF` included, number of the container); `wiffName` and `manual_table_cmd.rs::wiff_name` recognise it in any letter case and make `name.mzML` of it.
- Test: `tests_e2e/e2e_wiff.py` (synthetic pairs of `tools/wiff_riferimento.py`, no lab data, no request to Pyodide up to the TIC trace; the MRM `two_s2` and the files with fewer than 21 points per scan go through Python); `wiff_parity.rs` rereads every written mzML.

- Collision energy and isolation (`Experiment.ce`/`iso_half`, `activation` of `wiff/mod.rs`; `extra_of` in `wiff/reader.rs` → `SpectrumExtra.ce`/`iso_half`): every level-2 experiment takes the CE from the method (`Kind::Scan.ce`) if it has ONE value only (several values: no CE); the window is ±0.35 m/z (0.7 FWHM: unit resolution assumed, the Q1 one is not read); `mzmlwrite/head.rs::plain_precursor_into` writes them in every build, also in the engine without `sciex` or `precursori` (`tests/test_wiff_energia_parita.py`).
  PIS and NL have them like a product ion; NL without `<isolationWindow>` (`wiff-variants.md`).
- The MS2 spectrum always writes `<activation>` (CID `MS:1000133`, CE `MS:1000045` in eV) with window offset; the CE also enters the `collision_energy` column of the `.mzidx`. CE and offset are written only with the `sciex` or `precursori` features. Test: `tests/wiff_energy.rs` (`energia` of `tools/wiff_riferimento.py`), schema in `mzmlwrite/tests_xsd.rs`.
- Product spectrum: if the file shown by the MS2 panel does not have the panel's precursor (`p.prec`, tolerance 0.6), `drawSpec` (`picchi.js`) uses the first loaded file that has it; if none has it, the message `spec.noPrec`. The test uses `prodotto.wiff` of `tools/wiff_riferimento.py` (one sample with the precursor 305.0 only; one with 229.1 at every cycle and 305.0 once in four, dense scans, irregular times) and also checks an RT window that contains only scans of the other precursor.

## Known limits
- The engine verifies only full scan, product of an ion (MS2) and MRM in one period of the 3200: an unknown experiment code or a block of another codec is `err.file.wiff` (with `detail`), more periods `err.file.wiffPeriods`, never a full scan. The variants (other QTRAPs, PIS, neutral loss, sMRM, EPI) are in the `sciex` module: `wiff-variants.md`.
- The DAD and the device traces (pressure, flow, temperature: `an:` channels after the TIC, synthetic pair `dispositivi` of `tools/wiff_dispositivi.py`, tests `crates/mzlab-lettori/tests/sciex_devices.rs` and `tests/test_lettori_parita.py`) are described in `dad.md` (DAD) and `wiff-variants.md` (devices); the sample names are in `method/1` (`sample.nome`).
- The TIC is the one of the index (like the mzML), not the sum of the points. i18n keys: `err.file.notWiff`, `err.file.wiffNoScan`, `err.file.wiff`, `err.file.wiffPeriods`, in the module and the CLI also `err.file.wiffScanType`, `err.file.wiffNeeds2`, `err.file.wiffMassRange` (texts with the limit and MSConvert as the next step; in the catalogs when the page uses them).
- Centroids: `readers_centroids::centroidato(reader)` with `Conversione` writes one point per peak with `centroidi` (parameters from <=64 scans; measured width, or fallback 0.7 if the isolated peaks are fewer than 8, and the `w_basis` of the userParam says so); the mzML declares `MS:1000035` and the software "mzLab centroidi". MRMs do not change. The page does not offer the choice.
- Channels (`channels/wiff.rs`): a scan with nativeID `sample= … experiment=` and without a filter takes its abbreviation from `Scan::scan_type` (EPI, PI, EMS, Q1: userParam `modi::SCAN_TYPE_PARAM` of every spectrum), otherwise by level (1 → EMS, 2 → EPI: msconvert does not say it); the page shows "EPI" and "Product" (explained in the title); an EPI without a precursor (IDA, `wiff-variants.md`) goes in the channel `dd:2:EPI`, one with a fixed precursor stays `ms:`.
  - Prec and NL have the abbreviation of their CV term; ER and the periods are not named; MS3: abbreviation `MS3`, channel `MS³` (`exp` proposal in `mzidx.md`).
- MRM channels: label with the method name if there is one, otherwise Q1→Q3.
- Periods > 0: no lab sample has them, the reader refuses with `err.file.wiffPeriods` (test `wiff_variants.rs`, file `periods`) and the channels have a single period.
- SIM in Data: the `SIM SIC Q1=` channels of all open samples are SIM ions of the transition panels; the windows integrated by hand go in the "Manual integrations" card (`transitions.md`); `mzlab-cli file channels` lists them as `api/canali`. A SIM id without `Q1=` enters as "ion N" (`transitions.md`). A `.log`/`.wiff.log` dragged along is skipped with a note. Fixture `sim3` of `tools/wiff_sim.py` (7 ions, 0.8 s cycle, blank + 3 samples, isomer pair at 25 s) and `sim3_cut.wiff` (`.wiff.scan` cut at 60 %).
- `mzlab-cli file channels` of a `.wiff`: one sample at a time, like site and app (`--sample ID`, otherwise the first and the others named on stderr; a list `1,3,5` or `2-4` gives one `channels/1` line per sample; an id the file does not have = `err.sample.unknown`, exit 5), with the same bytes as the mzML of that sample written by `convert` (`channels_tests.rs`).
- Not read (details in `wiff-variants.md`): more periods, the true precursor of an EPI, `.wiff2` and TOF.
- Test classes (`[executed]`, `[read]`, `[untested]`): as in `waters.md`.
