# Molecules database (`molecules/1`, `crates/mzlab-core/src/molecules/`)
Related areas: `samples.md` (the structure model), `lists.md` (CSV and canonical JSON), `rust-routes.md` (the routes), `mzfinder.md` (Tabui's "Name" field). Schema `docs/schemi/molecules-1.json`.

- **What it is**: one record = one molecule (`id`, `name`, `synonyms`, `formula`, `charge`, `mass`, `smiles`, `inchikey`, `adducts`, `collections`, `classes`, `external` (`cas`, `pubchem_cid`), `properties`, `notes`, `origin`). Keys and values in English. The engine gives no verdicts: it holds and searches data.
- **`id`**: `ik:<full InChIKey>` if there is an InChIKey, otherwise `u:<12 hex of the SHA-256 of the record's canonical JSON at birth>`; assigned by `finalizza` when empty and never changed again (renaming a molecule does not change the `id`).
- **Mass**: COMPUTED from `formula` (Hill order, `elements::fmt`) and `charge` (`pysum` of the masses minus `charge` electrons), to 6 decimals; in files it is a check column: if it differs by more than 0.0005 Da the row has `error.molecules.massMismatch`. A `mass` in the JSON is ignored when there is a `formula`.
  - **Mass-only entry**: without `formula` and with a positive mass (column or JSON key `mass`) the entry stays with an empty `formula` and that mass, as is to 6 decimals (`charge` ignored); without a mass it is `badFormula`. It is found by name and by mass and enters the HRMS lists; it has no formula to write in the ion field.
- **CSV** (`csv.rs`): separator `;` (or tab or comma if the header has no `;`), empty lines and `#` skipped, double quotes also across lines, BOM removed. Canonical columns in the order of `COLUMNS`: `id;name;synonyms;molecular_formula;charge;monoisotopic_mass;smiles;inchikey;adducts;collections;classes;cas;pubchem_cid;notes;origin;catalog`, then for each property `prop:<key>[<unit>]` + `prop:<key>:source` (mandatory) + `prop:<key>:conditions` (only if someone uses it; with two units for the same key the source is `prop:<key>[<unit>]:source`).
- **Cells and columns**: lists in a cell are separated by `|` (an element containing `|` is `error.molecules.badList`). On reading, the header gives the columns in any order; `name` and `molecular_formula` are mandatory.
- **Errors**: every wrong row gives a `RowError` (row, key, text) and the file is rejected if there is one: `noName`, `badFormula`, `massMismatch`, `badMass`, `badInchikey`, `badCharge` (not an integer), `badProperty` (without unit or source, or a non-numeric value), `dupProperty` (two values for the same key), `badList`, `badOrigin`, `badId`, `dupId` (at the second row with the same `id`), `badColumn`, `noColumn`.
- **Row in the JSON**: the "row" of an error is the position of the record (from 1).
- **Canonical JSON** (`json.rs`): `{"schema":"molecules/1","molecules":[...]}` (`schema` first, the other keys in alphabetical order), records sorted by `id`, `synonyms`/`collections`/`classes` sorted without duplicates (case ignored; synonyms without the `name`), `adducts` in the given order, `properties` by key.
- **Record keys**: `adducts, charge, classes, collections, external{cas,pubchem_cid}, formula, id, inchikey, mass, name, notes, origin{catalog,created,file,modified,type}, properties[{conditions,key,source,unit,value}], smiles, synonyms`; origin types `catalog`, `imported`, `user`.
- **Digest**: `digest()` is the SHA-256 of the canonical bytes (it enters `prov/1` when a step uses the molecules). CSV → JSON → CSV gives the same bytes if the CSV is canonical and sorted by `id`.
- **Order**: the CSV keeps the row order (the catalogue is in its own order); the JSON is always sorted by `id`.
- **Levels** (`levels.rs`): catalogue < imported < user. `merge(catalog, others)`: the same `id` higher up replaces the whole record, in place of the first; new ones follow. "Edit" of a catalogue molecule = the user's copy with the same `id`; removing it brings the catalogue one back.
- **Search** (`search.rs`, a single one): `search(ms, q, limit, ppm)`. A number is a mass (`|q − mass| ≤ mass·ppm·1e-6`, ordered by deviation, the `score` is the deviation in ppm); a valid formula (one C or at least two elements) is the same Hill formula (`score` 0) and then also text; text (≥ 2 characters, lowercase) on `name` and `synonyms` gives 0 equal, 1 starts with, 2 word start (after space, `-`, `(`, `,`), 3 contains, looking only at the first occurrence like Tabui's old field; at equal score the shorter `name` wins, then the order.
- **Numbers**: a number is NEVER searched as text (a whole CAS with hyphens is).
- **Routes** (`routes.rs`, `route(op, input)`, JSON in and out): `load` (`{"catalog": CSV text, "user": document}`, each optional: what is missing stays; keeps the catalogue and the user's molecules in the engine, in a `static Mutex`),
  `search` (`{"q","limit"=8,"ppm"=10}` → `[{id,name,formula,charge,mass,smiles,adducts,score}]`), `get` (`{"id"}` → record or `null`),
  `list` (`{"catalog"|"collection"|"molecules": document, "adducts":[..]}` → `[{id,name,synonyms,formula,mass,mz:[one per adduct, null if unknown]}]`: the molecules of a catalogue or a collection, or of a document not in storage, with the m/z computed by the engine).
  `search` with `"wide":true` (`search_wide`: the same answers, then the molecules of a full InChIKey or of the first block of 14 characters, and only if there is nothing the names one letter away, score 4 whole name and 5 start of name, from 4 characters),
  `adducts` (the names of the `elements::adducts()` table), `ion` (`{"q","adduct"}` with `adduct` = `neutral` or an adduct: a formula is the ion and the adduct's atoms are removed (`composition::adduct_atoms`), an m/z loses the table's offset → `{kind, adduct, formula, mass, mz}`; adduct absent from the formula = `err.ion.notHeld`),
  `from_csv` (`{"csv","file","level"=imported,"collection"}`: with `collection` every record enters that collection; the header also accepts `formula`, `mass`, `comment` for `molecular_formula`, `monoisotopic_mass`, `notes`; the page passes the file name without extension → document, or `{"errors":[{key,line,text}]}`),
  `validate` (`{"csv"}` → `{"errors","n"}`), and on a document `to_csv` (CSV text), `to_json` (canonical, `id` assigned), `digest`.
- **Where they arrive**: page `api/molecules/<op>` (`lr-map.js` → `lr_molecules` in `rust-worker.js` → `molecules` of `crates/mzlab-rotte-wasm/src/lib.rs`, module `rotte` loaded at the first request); the desktop app answers the same ones (`rpc_lr.rs`).
- **Catalogue**: `mzlab/web/molecole/catalogo.csv` (1228 records, canonical form), a static file that the page passes to `load` once; it is NOT in the `.wasm`. Rows in the order of `composti.csv` (`catalog = tabui`), then only the `hrms` ones; the 43 common ones (same full InChIKey) are one `tabui|hrms` record with the name from `composti.csv` and the other names as synonyms. The adducts' m/z are not copied: the `hrms` rows have `adducts = [M+H]+|[M+Na]+|[M+NH4]+`.
  `tools/generate_molecules.py` wrote it from the two earlier CSVs plus the `ADDED` list (records added later, at the end: timolol, `tabui|hrms`).
- **`structure:` classes**: read from the SMILES with fixed rules (`tools/classes_structure.py`, called by `generate_molecules.py`): `carboxylic_acid`, `ester`, `sulfonamide` (only C-SO2-N), `nitro` (on C or N, not nitrates), `quaternary_ammonium`, `fluorinated`/`chlorinated`/`brominated`/`iodinated`; no use or effect inferred. Closed vocabulary of types: `chemical`, `effect`, `psychoactive`, `role`, `structure` (`tests/test_classi_struttura.py`).
- **Tests**: `crates/mzlab-core/tests/molecules.rs` (CSV/JSON round trips, one error per row, search, levels, catalogue rewritten to the same bytes, parity with Tabui's "Name" field with `tests/data/molecole_tabui_oro.json` made by `tools/molecole_oro_tabui.mjs`: the order of the Tabui-only molecules is identical and none of the 43 common ones is lost, but these may also appear under the `hrms` names),
  `hrms_list_keeps_the_mz_of_the_old_csv` (the m/z of `list` on the `hrms` catalogue equal within 1e-5 to `tests/dati/molecole_hrms_oro.json`), `tests/test_molecules_migration.py` (no loss with respect to the two earlier CSVs), `tests_e2e/e2e_molecules.py` (the routes in the page, `MZLAB_LR_MISS` empty).
- **User storage** (routes `api/molecules/archive/read` and `archive/write`, op `lr_molecules_archive`): browser = IndexedDB `mzlab_lab`, store `molecole` (the store name is an identifier, kept; keyPath `id`, one `molecules/1` record per row, `DB_VER` 4 in `qqq-db.js` and `nomi.js`; `upgrade()` only adds the store, the other four stay), read and written by `rust-worker.js`; desktop app = `molecules.json` in the data folder (`store.rs`, `Store::molecules`: canonical JSON of the same `to_json`, written halfway and renamed; an invalid document is rejected and the file does not change).
  Neither "New session" nor `lr_clear` touches it; `write` replaces all records with those of the document.
- **Page** (`molecules-archive.js`): `ready()` loads `static/molecole/catalogo.csv` and the storage once with `load`; `search`, `getMolecule` (`get`), `save` (validates with `to_json`, the engine gives the `id`; a new molecule with an `id` already present is `exists`), `remove`, `exportAs`.
  `importFile` (CSV with `from_csv`, JSON with `to_json`, level `imported`; a molecule with the same `id` as one of the user's (level `user`) stays as it is and is counted in `kept`); `exportAs` gives CSV (`to_csv`) or canonical JSON of the whole storage. No computation in JS: Hill formula, mass, `id`, per-row errors and CSV/JSON belong to the engine.
- **"Molecules" window** (`molecules-ui.js` + `molecules-module.js`, ES module `@ts-check` loaded at the first click on the "Manage" link of the molecule field; `window.MOLDB.open()`): without a search it lists the user's molecules, with at least 2 characters the results of `search` (50); columns name, molecular formula, mass, origin (Catalogue, Imported, Yours); "Edit" opens the form (a catalogue molecule is saved as a `user` copy with the same `id`), "Delete" (only `user` and `imported`, with a question; focus goes to "Cancel") brings back the catalogue one if there was one.
  Import: `.csv`/`.json` file, a file with wrong rows imports nothing and shows one line per error (`error.molecules.*` translated, `{row}`); Export CSV and JSON downloads `mzlab-molecules.csv`/`.json`.
  Tab stays inside, Esc goes back from the form or closes, focus returns to the button.
- **Search field** (`molecules-field.js`, `MOLDB.field(host, {texts, onPick, limit, ppm, manage, value})`): ARIA combobox (`role=combobox`, `aria-expanded`, `aria-controls`, `aria-activedescendant`, listbox with `role=option`, announcement of the number of results in a `status` region), arrows, Enter, Esc, 120 ms wait, at least 2 characters. All texts are passed by the caller (`testi.label/placeholder/none/count/manage`: Tabui passes English); with `testi.manage` there is the "Manage" link that opens the window (or `gestisci()`).
- **Tests**: `tests_e2e/e2e_molecules_ui.py` (only invented molecules "Esempina", "Provolone B": keyboard, add/edit/delete, catalogue copy, import with errors, export and reimport, reload, migration 3→4 with rows in files/kv/liste_utente/manifest, combobox, axe light and dark), `tests/test_molecules_db5.py`, `store::tests` and `tests/rpc.rs` of the desktop.

- **Old archives**: records stored before the keys were English (`nome`, `massa`, `origine`, ...) are not migrated or converted: the engine refuses a record with `nome` and no `name` (`error.molecules.oldFormat`, one per record, shown as "Row N: ..."), and a document with `molecole` and no `molecules` (same key, line 0). The window shows them (`A.errors()`, the catalogue still works) and the next save rewrites the whole archive without them (browser: the store is cleared and written again, so `DB_VER` stays 4).
  - **Desktop**: `molecules.json` is read, else the old `molecole.json` (so the engine refuses it with the same message); a save writes `molecules.json` and removes the old file.
  - **Tests**: `molecules.rs` (`an_old_format_archive_is_refused_with_its_own_message`), `rpc.rs` (`an_old_molecule_file_...`), `e2e_molecules_ui.py` (step with an old IndexedDB row).
