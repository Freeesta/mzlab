# Attributio in Rust (level cascade, Bench 2b) and the MZ track

Attributio lives inside Flow (`flow/`), which registers in `QTOOLS` unconditionally (mechanism in `docs/agenti/mzfinder.md`); the internal research panels stay behind `uipAdminOn()` (`mzlab/web/settings.js`).

## AT track: Attributio port
- **Goal**: port Attributio 1.12.0 (private repository `Freeesta/attributio`) to Rust with parity on the synthetic campaign. Level 2b is a chemist's decision: the program proposes and shows the evidence; only with `[levels] auto_2b = true` (off by default) does the program write 2b by itself for `2b-strong` proposals, always marked «auto-2b».
- **Rule for ported modules**: every ported Rust file opens with `// Ported from Attributio <.py path>.` and nothing else; no person's name; the `LICENSE` and the Attributio `.py` files are not copied. List of ported modules in `LICENZE-TERZI.md` (Attributio row).
- **Reading modules** (`crates/mzlab-feat/src/attributio/`, feature `attributio` with no new dependencies; every read goes through `Io::new(&read,&list)` closures or `MemFiles`, no direct disk access): `campaign.rs` (types and accessors) + `campaign_read.rs` (`Campaign::from_toml(text, file_name, folder, Env)`, subset of TOML from `toml.rs` that errors with the line number on the rest, historical names accepted, same messages as `CampaignError`).
- **Tables and detection**: `frame.rs` (text tables with the pandas «missing» words), `detection.rs` (DETECTED rule per site and sorbent, `blank_fold`, `detection_table`, `feature_state`, neutral mass).
- **Sorbents and sources**: `sorbents.rs` (`blank_abundance`, per-sorbent lists, `collapse_twins` twins, `remap_ids`), `sources.rs` (`load_sources` / `load_sources_mem`: `Sources` with tables per polarity, SIRIUS, standards, decisions, warnings and row counts per source).
- **Readers** (`readers/`): `mzmine.rs`, `gnps.rs` (cleaned library names, network), `sirius.rs` (canopus, structures, spectral matches), `ms2.rs` (feature MGF, JSON-lines library), `standards.rs` + `standards_cfg.rs` (settings, library and Level 1 decisions; candidates by mass and RT, MS/MS state scale; the spectral comparison comes from the caller as a `Comparer`: the similarity belongs to AT-05).
- **Origin and log**: every `Feature` has `origin()` (`auto` / `user`) and `audit` (`AuditEntry {field, auto, chosen, reason}`, written by `annotate/decide.rs` when a decision changes level, name or group relative to the program's choice, with the automatic value of the first change and the reason of the last); the `origin` column of the table and the `level_origin` field of `annot` expose it.
- **Automatic 2b** (`review/auto2b.rs`, `[levels] auto_2b`, false by default, part of the fingerprint): `auto_rows` writes a row `level = 2b`, `decided_by = auto` for every level 3 feature (not 3b) whose review proposal is `2b-strong`; `with_auto(user, auto)` puts the `auto` rows BEFORE the chemist's, which override them (removing them restores the program's level); `auto_2b_table(io, root)` computes them from the campaign (empty when off).
- **Automatic 2b, marking**: `annotate/decide.rs` marks the feature `Decision.auto_2b` (`origin()` `auto-2b`, log `by = auto`); the counts tally it separately (`2b-auto`); the RT rule cancels it like any 2b. Never in low resolution (Attributio uses HR spectra). False-positive test: `tests/attributio_auto2b.rs` (20 000 decoys, 0 promoted).
- **Levels in the decisions**: the `level` column allows `2`, `2b`, `3a`, `3b`, `3` (no sublevel) or empty; `evidence_type` allows `library`, `analog`, `fragments`, `in_silico`, `context`. The chemist writes 2b (with `justification`) or, with `[levels] auto_2b = true`, the program does (row `decided_by = auto`, see «Automatic 2b»). The bases of the `attributio` profile of `livelli-1.js` give 3a (name conflict, indistinct isomers, RT isomer, expert review, CSI:FingerID).
- **Decision columns**: `level`, `name`, `identity`, `justification`; files with the old Italian names (`livello`, `nome`, `identita`, `motivazione`) are read (`LEGACY_COLUMNS` in `readers/feature_decisions.rs`) and rewritten with the English ones.
- **Sublevel 3 in Rust** (`annotate/decide.rs`): level 3 has `level_sub` «a», or «b» if the chemist writes `3b`; `livelli_attesi.csv` and the `livelli`/`proposte` golden data carry the sublevel (edited by hand, no longer identical to the Python reference for level 3).
- **Decisions**: `feature_decisions.rs` (`evidence_checklist` column read if present and always written last; history is append-only: `merge_decisions` replaces only the row with the same `decided_on` and `decided_by`; accept → reject → accept on different days leaves 3 rows and the last one wins).
- **Decision run**: `plan_sha256` and `engine_version` (`PROVENANCE_COLUMNS`, from the run's `prov/1`: `plan_sha256` and `agent.version`) are the last two columns, read if present and written only once a row has a value: a file without them is read and rewritten identically; `decision_text` takes them from the decision's fields of the same name.
- **In CI**: the `rust` job of `rust.yml` runs with `--features attributio,untargeted,record` the 24 `mzlab-feat` test files that compile only with the `attributio` feature (`attributio_*`, `normative_official`, `score_terms_insilico`, `score_terms_rt`, `untargeted_to_attributio`, `steps_attributio_parity`, `rt_descriptors`); a new such file must be added to that line.
- **Reading tests**: `cargo test --release -p mzlab-feat --features attributio --test attributio_letture --test attributio_standard` (16 tests, helpers in `tests/attributio_common/`: parity with `sintetica/{campagna,letture,rilevazione,sirius,standard,decisioni}.json` and `sorbenti/sorbenti.json`, hand-made cases for TOML, decision merging and error messages; with `MZLAB_DATI` it reads the real campaigns and prints the rows per source, without it it skips).
- **Panel and `.wasm`**: level table, crate `mzlab-attributio-wasm`, desktop route and page in `docs/agenti/attributio-pannello.md`; Bench 2b (review, checklist, alternatives, decisions) is in `docs/agenti/attributio-banco.md`.
- **Synthetic campaign**: `tests/data/attributio/campagna_sintetica/` (invented, 148 KB, 15 features: POS 1-6 and 8-14, NEG 1-2; `livelli_attesi.csv` with columns `_pol;_id;mz;rt;level;level_sub;level_basis;name;level_decisive`); provenance and sha256 in `tests/data/attributio/LEGGIMI.md`.
- **Review (AT-05)**: spectral matching, library index, sources and settings in `crates/mzlab-feat/src/attributio/review/`; modules, intended differences and tests in `docs/agenti/attributio-revisione.md`.
- **Registry data, lists and hazard**: `crates/mzlab-feat/src/attributio/tox/`, text snapshots, no network:
  - `vocab.rs`: English words, Italian aliases read-only.
  - `ghs.rs`: acute and chronic CLP/GHS categories (`classify`, `from_h_codes`).
  - `registry.rs`: pure registry rules (representative CID, CAS/DTXSID from synonyms, aquatic H codes, PubChemLite categories, SusDat predicted toxicity, counts).
  - `hazard.rs`: acute and chronic T1-T5 hazard record (`resolve_blocks`, `record`, `coverage`); ECOSAR with usage rules and «no effect at saturation».
  - `candidates.rs` and `ecosar.rs`: candidates per level (curated, measured, notified, predicted) and choice of the best; ECOSAR per-taxon values with the usage rules.
  - `amenability.rs`: generic LC-ESI rules of the lists (`lc_esi_amenable`); RDKit's `detection_form` and `structure_from_smiles` are not ported (they need InChIKey).
  - `snapshot.rs`: typed readers of `compound_registry.csv`, `reglist_membership.csv`, `ecotox_values.csv`, `ecosar_endpoints.csv`.
  - `reglists/` (regulatory lists): `catalog.rs` (list of lists and their order, generated), `b1.rs` (`match_campaign`: B1 by full InChIKey, first flagged block; tables `ident`, `long`, `summary`, `coverage`), `p3.rs` (`cross_table`: comparison between campaigns).
  - `reglists/` (continued): `schema.rs` (20-column A1 schema: `read_list`/`write_list`, `collapse_by_skeleton`, long and wide membership tables).
  - `reglists/` (continued): `screen.rs` and `screen_types.rs` (B2: `screen_campaign` on plain rows of suspects, features and evidence; 5 adducts, 5 ppm, classes A-D and X, robust RT~logP line; logP is XLogP3 and, for a suspect with SMILES but no XLogP, our own Crippen (`fill_logp`, source «Crippen (own)», with the `record` or `crippen` features); without logP the RT is «n.a.»).
  - `reglists/` (continued): `confirm.rs` (B3: `evaluate` with the level 3 / 2a rules on SIRIUS tables, MetFrag summary and chemist's decisions; `prepare`, which writes the files for SIRIUS and MetFrag, belongs to the native builders).
  - `reglists/` (continued): the lists are built with `mzlab-cli normative build` (`crates/mzlab-cli/src/normative/`, native only; sources with SHA-256 pins in `normative/sources.json`; A1 CSV plus `entry_ref;ec;dtxsid;form;status`, `provenance.json`, `unresolved.tsv`): `docs/agenti/normative.md`.
  - Tests: `cargo test --release -p mzlab-feat --features attributio --test attributio_tox --test attributio_reglists --test attributio_screen --test attributio_confirm`, parity with `tests/golden/attributio/tox/{ghs,istantanee,registro,pericolo,amenabilita,b1,schema,b2,b3}.json` (invented snapshots in `tests/data/attributio/istantanee_sintetiche/`); golden data: `tools/attributio_tox_reference.py` via `tools/attributio_reference.py --solo tox-ghs tox-istantanee tox-registro tox-schema tox-b2 tox-b3` with Python 3.12 (needs pandas).
- **Exports (AT-08)**: evidence, Schymanski folder, publication table, quantification and gradient in `crates/mzlab-feat/src/attributio/export/` and `review/evidence.rs`; `.wasm` `attributio-export` (in the site merged with the other three Attributio modules: `docs/agenti/wasm-caps.md`); modules and tests in `docs/agenti/attributio-export.md`.
- **Golden data**: `tests/golden/attributio/sintetica/{campagna,letture,rilevazione,livelli,identita,proposte,decisioni,sirius,standard,abbinamenti}.json` and `tests/golden/attributio/sorbenti/sorbenti.json` (campaign `tests/data/attributio/campagna_sorbenti/`: per-sorbent lists, twins, blank abundance); sorted keys, ~40 KB in all; written by `tools/attributio_reference.py`, command and sha256 in `tests/golden/attributio/LEGGIMI.md`. A case that does not match is not fixed by changing the golden data.
- **Reference**: `ATTRIBUTIO_SRC=<attributio/src> python3 tools/attributio_reference.py [--campagna D] [--uscita D] [--controlla]` (sets `UNTARGET_OFFLINE=1`; requires pandas, numpy and matplotlib; without `ATTRIBUTIO_SRC` it exits with 2). `--controlla` compares `livelli.json` with `livelli_attesi.csv` and exits 1 if a row differs. A new stage = one `stadio_*` function and one JSON.
- **Test without the source**: `tests/test_attributio_oro.py` (does not import Attributio): the JSONs exist, are under 100 KB each and 300 KB in all, and `livelli.json` matches `livelli_attesi.csv`.
- **Parity thresholds**: equality for levels, sublevels, bases, names, identities, counts and proposal classes; numbers 1e-9 relative; fragments assigned with the same formula and ppm within 0.005; fragmenter without RDKit ≥ 0.90 of equal explained fragments. The real campaigns are compared by the local agent on the Mac (`MZLAB_DATI`); here only aggregate numbers.

## Decisions in force
- **Choices**: Attributio is ported to Rust (no Pyodide); mzLab writes `evidence_checklist` and Attributio ignores it; the curation CSVs are read from the campaign folder; `.siriusdb` only in the desktop app (in the site MGF, MSP, JSON, MassBank); the real campaigns are compared only on the Mac with `MZLAB_DATI`; POS and NEG are compared separately, as in Attributio.
- **Local-minimum resolver** (MZ track, `crates/mzlab-feat/src/untargeted/resolve.rs`, after mzmine 3.9.0): input is the chromatogram over all MS1 scans with zeros where missing; threshold = `chromThreshold` quantile (0.85) with the zeros, below it becomes 0; regions between zeros. A point is a local minimum if no point within ± `searchRange` (0.1 min) is lower and the maximum up to there is ≥ `minRatio` (1.7) times the minimum.
- **Resolver peak**: a region is a peak with ≥ `minDataPoints` points, maximum ≥ max(absolute height, relative × maximum) and ≥ `minRatio` × both edges, duration within `peakDuration`. Where this line is wider than the mzmine source, the source wins.
- **Agreement with mzmine** (`tools/bench/motivi_mzmine.py`): the difference comes from the definition of the row and from the protocol, not from the parameters: rows per family versus rows per ion, population without a common height floor (areas in different units), background (we discard persistent traces, mzmine keeps what stands out of them), gaps and cuts (mzmine closes at one missing scan and discards peaks longer than 1 min), one-to-one alignment per file against the largest feature of the group, areas.
- **Agreement protocol**: compare per ion, above a common height floor, per file before alignment, with the reason for every unmatched row.
