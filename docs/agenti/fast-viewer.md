# Fast viewer: the spectrum XIC button

- **Module**: `mzlab/web/xic-spettro.js` (ES module, `window.XICBTN`: `wire`, `click`, `mark`, `sync`, `chosen`, `pending`). Hooks in `pannelli.js` (bar HTML, `xicTraceFor`, `xicDirect(mz, after, panel, over)`), `spettro.js` (`specClick` yields to `XICBTN.click`), `picchi.js` (`mark`, `sync` in `drawSpec`), `grafici.js` (band `p.band`), `azioni.js` (`contestoGrafico`: the chosen peak wins over the highest), `eventi.js` (`pendKey`). Test: `tests_e2e/e2e_xic_spettro.py`.
- **Keys**: "XIC" button = "pick a peak" mode (Esc exits, chain `xic-scelta`); `,` and `.` previous/next peak; Enter extracts; Shift+Enter or Shift+click adds a trace; Space on the button does not scroll the scans.
- **Window**: LR = nominal window of `xicTraceFor` ([n−0.2; n+0.8]); HR = ppm of the file's profile (`HR.ionTrace`). A typed tolerance replaces the default one and appears in the label; never invented.
- **Scan line**: `xp.cur` (band if the spectrum is an average of several scans); apex and area in `.xb-info`; area at once in HR, in LR only after the student's integration.
- **Spectrum types covered**: LR full scan and HR MS1 (`e2e_xic_spettro`), HR and LR MS2 (no button nor peak pick: a click extracts nothing), spectrum of the second file as a click on the map opens it, and overlaid files (`e2e_xic_spettro_tipi`). A click during the fade of `#loading` (0.4 s) falls on the start screen and does not reach the canvas: the tests wait until the canvas is under the pointer. Infusion MSn and Tabui stay out.

## Measurement bench
- **Command**: `python3 tools/bench_viewer.py lr,hrc,hrc_big,lr20,hrp,hr15 --wd DIR --native --json > run.json` (site built in `DIR/site`, headless Chromium, Rust/WASM engine; `--md run.json` reprints the table). Native: `cargo run --release -p mzlab-core --example viewer_times -- FILE.mzidx [N] [--json]`; `genera DIR` and `indicizza FILE.mzML OUT.mzidx` create and index a synthetic file. G7: `--g7 DIR` (native) and `--g7-site FILE` (site) on a large mzML. `--only-g2` and `--only-g5` limit the run.
- **Trace and bench site**: `--trace` adds the phases of the open (engine operations with times, empty answers, errors, `MZLAB_LR_MISS`, memory), also for a case that does not open. The site built by the bench lacks the modules of `build_feat_wasm.sh`: without `rotte` the first `lr_samples` kills the worker (which restarts); for faithful numbers build the site as `pages.yml` and pass it with `--site`.
- **Cases** (synthetic, never lab data): `lr` 1500 scans x 500 peaks; `hrc` 3000 x 3000; `hrc_big` 6000 x 5000; `hrp` 400 x 50000 in profile; `lr20` = 20 `lr` files; `hr15` = 15 `hrc` files. Every case opens the files with the profile on disk, `--enable-precise-memory-info` and `gc` exposed.
- **What is measured**: the clock starts at the event (click, key, wheel) and stops at the last panel `draw()`; the phases are request (`fetch`), engine (`X-Py-Ms`), JSON (`Response.json`) and rest (draw).
- Gestures: G1 click on the TIC and linked spectrum; G2 XIC from the spectrum panel (ions not in cache); G3 XIC on all files of the tab; G4 pointer sweep over the spectrum (frames and long tasks); G5 zoom (Ctrl+wheel) and pan (Shift+drag) of TIC, spectrum and XIC with 3k, 50k and 1M points; G6 right arrow = next scan; G7 XIC on an index of billions of peaks; M memory after 1000 XIC. Only rounds on the same machine are compared.

## HR profile spectrum
- The MS1 section of an HR file is single precision, so the step of the profile points is read from the mzML (`prime_steps`); `route` answers empty and `specexact` (`Engine.spectrum_exact`, op `specexact` of `rpc.rs`) goes through `Routes::mzml_route("/api/spectrum")`: step from the mzML, then the index route. The step stays with the index open: later windows are served by `route`. Test: `profile_hr_spectrum.rs`.
- The HR spectrum of a scan is decided from the table and the per-scan arrays, without walking the peaks (`Routes::select_scans`); test `spectrum_single_scan.rs`.
- **Open gap**: `api/scanbin` of profile scans has no Rust route (it ends in `MZLAB_LR_MISS`); `scroll.js` falls back to the window request, so the next-scan key is slower on profile files.
- **G7 on the site**: a multi-GB mzML may not enter the file list in reasonable time; a case that does not open is a gap of the viewer.

## Binary XIC
- **Route**: `api/xicbin` (format in `rust-routes.md`) in place of the JSON for `getXic` and the XIC panel without `ref=`; `Routes::xic_into` writes `[rt(n), y(n)]` as `json::round` (RT 4 decimals, y 1), which avoids the text except for fractions very close to 1/2. Tests: `xicbin_parity.rs` (bit for bit with `JSON.parse(xic)`), `jsonround::tests::fast_rounding_is_the_text_rounding` (`MZLAB_ROUND_N`), a step in `e2e_hr_xic` and `e2e_xic_spettro` (`Object.is` between `api/xic` and `api/xicbin`). The bench serves its synthetic G5 traces also for `api/xicbin`.

## XIC panel draw and request path
- `XICBTN.prefetch(tr)` (`xic-spettro.js`, called by `xicDirect` before `addPanel`) starts the `api/xicbin` requests of the new panel (memoized by `getXic`) while `addPanel` builds the DOM; `draw()` finds the traces ready or on the way.
- `archivio.js` keeps in the lease the file's `FileSystemFileHandle` and the folder's (`fh`, `dh`) between two opens; `wake()` reopens only the SyncAccessHandle. An error on the reopen (file replaced, folder removed) looks for the file again from scratch; `NoModificationAllowedError` (writer of another tab) stays the error and the read falls to the Blob.
- Handles stay closed while the worker is idle (`parkAll`): an open handle makes the index write from another tab fail (`createWritable` -> `NoModificationAllowedError`, `e2e_formato_nuovo`, `e2e_mzidx`, `e2e_lettura_sync`).
- `transizioni.js` reads the tokens `--t-med` and `--ease-out` once (again if `data-a11y-reduce` or `prefers-reduced-motion` change, or if the value was still empty); `DDA.sync` asks `hostWidth()` only when a hooked trio exists.
- A new XIC panel is drawn once: its first draw (`!p._a`) waits up to 12 ms for the peak labels (`ETPK.ready`, called in `drawLines` before `setup`, so the canvas does not empty while waiting); a slower engine does not block the draw, the labels arrive later with `drawSoon`. Later redraws (zoom, pan) do not wait.

## XIC lens on hovering a peak
- **Module**: `mzlab/web/xic-lente.js` (`window.XICLENS`: `move`, `leave`, `show`, `sync`, `close`, `closeAll`, `trace`, `shown`); hooks in `eventi.js` (`cv.onmousemove`, `cv.onmouseleave` of the `spec` chart), `xic-spettro.js` (`target`, `lensArgs`, `commit` exposed in `XICBTN`; `choose` shows the lens, `extract` closes it, `sync` closes it if scan or zoom change). Preference `UIP.xicLens` (on; Settings "Appearance" and button `data-a="xicp"` of the bar, `XICBTN.setLens`; off on infusions). Test: `tests_e2e/e2e_xic_lente.py`.
- **What it does**: on the peak snapped as the click does (label within 34 px, then `p._a.snap`) a 176 × 96 px box appears with the XIC of that ion for the spectrum's file, window and tolerance of the click (`XICBTN.lensArgs`), the current scan line.
- **Drawing**: the time axis is in the canvas (`XICDRAW`, `xic-lente-disegno.js`): equidistant integer ticks (step 1/2/5/10…, at least 4; with a short duration one decimal equal on all), without "min"; the trace has a fill under the curve, a 1.5 px line and keeps the minimum and maximum of every pixel column (a narrow peak stays tall).
- **Apex time**: only the number ("14.2", `title` "Retention time"), near the top and never beyond the edge; it appears only if the apex is ≥ 3× the median and wider than one point (`XICLENS.clearPeak`); no dot. It changes only when the snapped peak changes.
- **Fixed place**: the box sits in the top right corner of the chart (on the left if the pointer, an apex or a trace point within 12 px is there), without a title row ("m/z a–b · file name" is the box `title`, the `aria-label` and the `T` table); if the chart is too narrow for two boxes (less than about 400 px) it sits at full width under the top edge.
- **Never above**: pointer, peak or right-click menu (right click closes the lens). The path to the lens may cross other peaks: the click opens the one the lens shows. Test: `fixed_place`, `right_click` in `e2e_xic_lente.py`.
- **Closing**: leaving the peak, Esc (entry `xic-lente`, prio 28; the same peak does not reopen it until the pointer changes peak), wheel, change of scan or spectrum zoom. A peak chosen with the keys `,` `.` or with a click keeps it open ("sticky" state) until Esc, another peak or a view change.
- **Commitment**: click on the lens, Enter or Space when it has focus (Tab from the spectrum canvas), or the XIC button: `XICBTN.commit` = pick the peak + `extract`, the same path as the click with the button pending. On touch there is no hover: a tap on the peak opens the lens (compatible mouse events) and a second tap on the lens commits it.
- **Requests**: `xicBin('api/xicbin?…')` for one file, a single one in flight; if the peak changes while waiting, the last wins (sequence number); LRU cache of 64 traces per (file, level, m/z, tolerance). The drawing is in `requestAnimationFrame`; for every pixel column it keeps first, minimum, maximum and last point (no apex lost). No `px` in `api/xicbin`: not measured as necessary.
- **Accessibility**: the lens is a `role="button"` with `aria-label` (ion, apex, keys), `TDATI.attach` (key `T` = table with RT and intensity of all points, without decimation), polite `aria-live` entry only for peaks chosen with keys or click (never on hover), no transition, colors from CSS variables, target ≥ 40 px.

- **Lens drawing**: a new answer is drawn at once in its own task (not in the pointer handler); a cached trace waits for the frame.
- **Memory**: the 64-trace cache cycles; `python3 tools/bench_viewer.py lr,hrc --only-m` checks page heap and engine memory after 1000 previews of different ions.

## Wheel zoom
- **One draw per step**: each wheel step makes one `draw()` (`tests_e2e/e2e_zoom_un_disegno.py` checks it on TIC and spectrum, with the same image as a fresh draw). The bench clock starts at the first `wheel` event, not at the Ctrl press; `--only-g5` skips G1-G4, G6 and M. When the width of the y labels changes, `syncView` redraws.
- **Spectrum bar** (`barra-spettro.js`, `SPECBAR`; `e2e_barra_spettro`): title "MS" + level in superscript (`aria-label` "MS level n", copied text "MS1") and time without "RT" (tooltip "Retention time"); "Overlay files" is an icon toggle (`SPECBAR.overlay`, disabled with a single file); "Follows" is the bare symbol `←n` / `⊘` (aria-label and menu unchanged); with several overlaid files the XIC button says "XIC of N files" and the legend of the single XIC panel bolds the active file (`.tg.act`).
