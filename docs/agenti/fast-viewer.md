# Fast viewer: the spectrum XIC button

- **Module**: `mzlab/web/xic-spettro.js` (ES module, `window.XICBTN`: `wire`, `click`, `mark`, `sync`, `chosen`, `pending`). Hooks in `pannelli.js` (bar HTML, `xicTraceFor`, `xicDirect(mz, after, panel, over)`), `spettro.js` (`specClick` yields to `XICBTN.click`), `picchi.js` (`mark`, `sync` in `drawSpec`), `grafici.js` (band `p.band`), `azioni.js` (`contestoGrafico`: the chosen peak wins over the highest), `eventi.js` (`pendKey`). Test: `tests_e2e/e2e_xic_spettro.py`.
- **Keys**: "XIC" button = "pick a peak" mode (Esc exits, chain `xic-scelta`); `,` and `.` previous/next peak; Enter extracts; Shift+Enter or Shift+click adds a trace; Space on the button does not scroll the scans.
- **Window**: LR = nominal window of `xicTraceFor` ([n−0.2; n+0.8]); HR = ppm of the file's profile (`HR.ionTrace`). A typed tolerance replaces the default one and appears in the label; never invented.
- **Scan line**: `xp.cur` (band if the spectrum is an average of several scans); apex and area in `.xb-info`; area at once in HR, in LR only after the student's integration.
- **Spectrum types covered**: LR full scan and HR MS1 (`e2e_xic_spettro`), HR and LR MS2 (no button nor peak pick: a click extracts nothing), spectrum of the second file as a click on the map opens it, and overlaid files (`e2e_xic_spettro_tipi`). A click during the fade of `#loading` (0.4 s) falls on the start screen and does not reach the canvas: the tests wait until the canvas is under the pointer. Infusion MSn and Tabui stay out.

## Binary XIC (V-2)
- **Route**: `api/xicbin` (format in `rust-rotte.md`) in place of the JSON for `getXic` and the XIC panel without `ref=`; `Routes::xic_into` writes `[rt(n), y(n)]` as `json::round` (RT 4 decimals, y 1), `json::round` avoids the text except for fractions very close to 1/2. Tests: `xicbin_parity.rs` (bit for bit with `JSON.parse(xic)`), `jsonround::tests::fast_rounding_is_the_text_rounding` (2·10⁷ values, halves and neighbors, `MZLAB_ROUND_N`), a step in `e2e_hr_xic` and `e2e_xic_spettro` (`Object.is` between `api/xic` and `api/xicbin`).
- **.wasm engine** (after `wasm-opt -Oz`): 1 681 799 -> 1 683 584 B (+1 785), cap 1 703 936.
- **Measurements** (same machine and round, branch site against `origin/main`, p50 / p95 ms, n = 30): G2 `lr` 30.8 / 42.4 -> 30.5 / 48.2; G2 `hrc_big` 38.8 / 55.4 -> 38.2 / 47.7; G3 `lr20` 369.6 / 503.1 -> 347.4 / 402.1 (JSON 15.2 -> 9.0 ms, request 99.0 -> 79.6, summed engine 1204 -> 975 ms). M unchanged (JS heap and engine). Not passing: G2 p50 <= 16 (30), G3 LR p50 <= 30 (347); HR G3 (`hr15`) not measurable here.
- **Where the time goes (G2 `lr`, p50 ~25 ms)**: request ~12 ms + XIC panel draw ~13 ms. In the worker `idxxicbin` costs 0.7 ms (wasm; 8 file reads in OPFS = 0.2 ms); the rest of the round is outside the computation: `ARCH.wake()` reopens the SyncAccessHandle on every request (4.1 ms p50, max 10.8) and the answer waits ~3.7 ms for the main thread, busy creating the panel (overlaps with the draw).
- **Keeping handles open: not possible**: `parkAll` closes the handles as soon as the worker is idle because another tab must be able to write or remove the index. Keeping them 1 s after the last request gives G1 -3/-4 ms but G2 within the noise (22-29 ms before, 23-26 after) and breaks `e2e_formato_nuovo` and `e2e_mzidx` (`NoModificationAllowedError` on writing/removing the index). G2 p50 <= 16 ms requires shortening the XIC panel draw or changing the index access between tabs.
- **Bench**: the synthetic G5 traces are served also for `api/xicbin`.

## XIC panel draw (V-3)
- **What**: `XICBTN.prefetch(tr)` (`xic-spettro.js`, called by `xicDirect` before `addPanel`) starts the `api/xicbin` requests of the new panel (memoized by `getXic`) while `addPanel` builds the DOM (~6 ms on the main thread); `draw()` finds the traces ready or on the way. The visible result does not change: same requests, same window.
- **Where the ~18 ms of G2 `lr` went** (instrumenting the global functions): `addPanel` 6.2 ms p50, then `seriesOf` (request) ~9 ms, then `drawLines` beyond the wait ~3 ms, `afterDraw` 0.7; `setup` 1.0, `axes` 0.5, `legend` 0.1, `smooth` 0.1: the real draw is below 5 ms, the rest was serial waiting.
- **Measurements** (same machine, site built before/after, G2 `lr`, p50 / p95 ms, n = 30): before 18.5 / 32.5; after 15.2 / 22.9 and, in the round with the final version, 17.2 / 25.6 (request 8.5 -> 11.4-12.9 because it now includes the panel construction; rest 9.0 -> 3.8-4.0). The gain is 1-3 ms of p50 and 7-10 ms of p95; G2 p50 <= 16 passes in one round out of two: the noise between rounds is of the same order.

## XIC request: reopening the index (V-5)
- **What**: `archivio.js` keeps in the lease the file's `FileSystemFileHandle` and the folder's (`fh`, `dh`) between two opens; `wake()` reopens only the SyncAccessHandle, without redoing the descent from the root. An error on the reopen (file replaced, folder removed) looks for the file again from scratch; `NoModificationAllowedError` (writer of another tab) stays the error it was and the read falls to the Blob. Handles stay closed while the worker is idle: no change in the rule between tabs (`e2e_formato_nuovo`, `e2e_lettura_sync` green).
- **Phases of the `idxxicbin` request** (G2 `lr`, p50 ms, 27 requests per round, timers in the worker and in the page's Worker, outside the repository): message to the worker 0.1-0.3; `wake()` 3.6-4.3 -> 1.6-1.8 (p95 6.9-9.2 -> 2.4-5.5); wasm 0.5-0.6; return message 0.4-0.9 -> 1.6-2.0 (the answer now waits for the main thread, busy with `addPanel`).
- **Measurements** (same machine, site before/after alternating, G2 `lr`, p50 / p95 ms, n = 30, three rounds): before 19.3 / 26.0, 18.2 / 30.8, 17.4 / 24.2; after 16.6 / 26.2, 17.1 / 25.2, 15.6 / 21.6. Gain of p50 ~2 ms; p50 <= 16 passes in two rounds out of three. The rest of the request (req 12.4-13.1) is the main thread: the answer arrives before `addPanel` finishes, so further worker-side cuts (index in memory, handles always open) no longer lower G2.
- **Why handles are not kept open**: an open handle makes the index write from another tab fail (`createWritable` -> `NoModificationAllowedError`, tested with `e2e_formato_nuovo`): a release protocol between tabs is needed, not covered here.

## Main thread of the click on a peak (V-6)
- **Where the ms go** (G2 `lr`, CPU profile of the main thread, ms per repetition, functions that pay a forced layout or style): `draw` (`p.cv.clientWidth`, first layout of the just-created panel) 3.4; `hostWidth` called by `DDA.sync` inside `fitHost` 1.9; `getPropertyValue` of `transizioni.js` (`ms()` inside the panel observer, style recomputation at every move) 1.5; `legPlace` 1.0; `setTransform` (canvas size) 0.7. - **Measurements** (site before/after alternating, G2 `lr`, p50 ms, n = 30, three rounds): before 21.4, 23.9, 23.1; after 20.6, 19.9, 19.9.

## Second draw of the XIC panel (V-7)
- **What**: a new XIC panel was drawn twice: the second time, about 25 ms after the first, for the peak labels (`etichette-picchi.js`: the engine computes them after the first draw, then `drawSoon` waits for a frame). G2 measures up to the last `draw()`, so the p50 included the second pass.
- **How**: the first draw of a panel (`!p._a`) waits up to 12 ms for the labels (`ETPK.ready`, called in `drawLines` before `setup`, so the canvas does not empty while waiting); the panel is drawn once with the labels. An engine slower than 12 ms does not block the draw: the labels arrive later, with `drawSoon`, as before. Later redraws (zoom, pan) do not wait.
- **Look and data**: identical (same labels, same margins, same header, same legend); only the labels now appear with the first draw instead of an instant later. No control removed or moved.
- **Measurements** (same machine, 4-CPU cloud container slower than that of V-6, site before/after alternating, `python3 tools/bench_viewer.py lr --only-g2`, G2 `lr`, p50 ms, n = 30, three rounds): before 38.4, 37.6, 39.2; after 23.1, 21.5, 23.7 (p95 46-58 -> 29-52). HR (`hrc`, one round): 38.3 -> 26.0. The remaining time is the request (~12 ms, engine ~5.5) plus the draw (~10 ms): the forced layout of `draw` (`clientWidth`) weighs ~2.8 ms and `legPlace` ~0.9.
- **Tried and discarded**: `contain: layout style` on `.pnl` does not change G2; widening the left margin before the draw (`axes`) removes no draw: the second was that of the labels.
- **Diagnosis** (`--only-g2` limits the bench to G1 and G2): order and duration of every `draw()` per repetition, who calls `drawSoon`, style and layout time per phase of the Chromium trace.

## XIC lens on hovering a peak (V-5 lens)
- **Module**: `mzlab/web/xic-lente.js` (`window.XICLENS`: `move`, `leave`, `show`, `sync`, `close`, `closeAll`, `trace`, `shown`); hooks in `eventi.js` (`cv.onmousemove`, `cv.onmouseleave` of the `spec` chart), `xic-spettro.js` (`target`, `lensArgs`, `commit` exposed in `XICBTN`; `choose` shows the lens, `extract` closes it, `sync` closes it if scan or zoom change). Preference `UIP.xicLens` (on; Settings "Appearance" and button `data-a="xicp"` of the bar, `XICBTN.setLens`; off on infusions). Test: `tests_e2e/e2e_xic_lente.py`.
- **What it does**: on the peak snapped as the V-1 click does (label within 34 px, then `p._a.snap`) a 176 × 96 px box appears with the XIC of that ion for the spectrum's file, window and tolerance of V-1 (`XICBTN.lensArgs`), the current scan line.
- **Drawing**: the time axis is in the canvas (`XICDRAW`, `xic-lente-disegno.js`): equidistant integer ticks (step 1/2/5/10…, at least 4; with a short duration one decimal equal on all), without "min"; the trace has a fill under the curve, a 1.5 px line and keeps the minimum and maximum of every pixel column (a narrow peak stays tall).
- **Apex time**: only the number ("14.2", `title` "Retention time"), near the top and never beyond the edge; it appears only if the apex is ≥ 3× the median and wider than one point (`XICLENS.clearPeak`); no dot. It changes only when the snapped peak changes.
- **Fixed place**: the box sits in the top right corner of the chart (on the left if the pointer, an apex or a trace point within 12 px is there), without a title row ("m/z a–b · file name" is the box `title`, the `aria-label` and the `T` table); if the chart is too narrow for two boxes (less than about 400 px) it sits at full width under the top edge.
- **Never above**: pointer, peak or right-click menu (right click closes the lens). The path to the lens may cross other peaks: the click opens the one the lens shows. Test: `fixed_place`, `right_click` in `e2e_xic_lente.py`.
- **Closing**: leaving the peak, Esc (entry `xic-lente`, prio 28; the same peak does not reopen it until the pointer changes peak), wheel, change of scan or spectrum zoom. A peak chosen with the keys `,` `.` or with a click keeps it open ("sticky" state) until Esc, another peak or a view change.
- **Commitment**: click on the lens, Enter or Space when it has focus (Tab from the spectrum canvas), or the XIC button: `XICBTN.commit` = pick the peak + `extract`, the same path as the click with the button pending. On touch there is no hover: a tap on the peak opens the lens (compatible mouse events) and a second tap on the lens commits it.
- **Requests**: `xicBin('api/xicbin?…')` for one file, a single one in flight; if the peak changes while waiting, the last wins (sequence number); LRU cache of 64 traces per (file, level, m/z, tolerance). The drawing is in `requestAnimationFrame`; for every pixel column it keeps first, minimum, maximum and last point (no apex lost). No `px` in `api/xicbin`: not measured as necessary.
- **Accessibility**: the lens is a `role="button"` with `aria-label` (ion, apex, keys), `TDATI.attach` (key `T` = table with RT and intensity of all points, without decimation), polite `aria-live` entry only for peaks chosen with keys or click (never on hover), no transition, colors from CSS variables, target ≥ 40 px.

- **G4 measurements** (4-CPU cloud container, headless Chromium at 60 Hz, built site, synthetic data `B_FullMass` LR and `HR_DDA-Exploris-t30` HR; from the `mousemove` event to the moment the lens changes the `aria-label` after the draw, n = 30 per round, 3 rounds alternating LR/HR, p50 / p95 ms): LR cold (no trace in cache) p50 14.3-15.0, p95 18.6-22.8 (median of rounds 21.4); HR cold p50 6.7-8.8, p95 12.8-17.1 (median 16.7); cached (draw in the next frame) p50 17.5-17.8, p95 18.3-22.4.
- **Lens drawing**: a new answer is drawn at once in its own task (not in the pointer handler); a cached trace waits for the frame. Waiting for a frame also after the answer cost 33-35 ms at p95 cold (two frames).
- **G4 sweep**: continuous 3 s, one move per frame, 3 rounds: 59.9-60.2 FPS median, frame p95 17.0-18.4 ms, 0 long tasks (a single 54 ms long task in one HR round, not repeated). No `px=N` of `api/xicbin`: not needed.
- **M of the lens** (`python3 tools/bench_viewer.py lr,hrc --only-m`, 1000 previews of different ions at 1 Da, the 64-trace cache cycles): page heap after repeated GC LR 8.3 → 11.8 → 12.1 MB and HR 9.7 → 13.6 → 13.8 MB (+3.8 and +4.1 MB, almost all in the first 250, then +0.3), engine memory 32 → 32 MB (0), browser RSS 1.25 GB.

## Wheel zoom (G5)
- **The fixed cost of ~30 ms belonged to the bench**: the clock started at the first event, and in zoom the first event was the Ctrl press (`keyboard.down`) that the bench does before the wheel (the wheel starts ~27 ms later, Playwright round trip). `analyse` now starts from the first `wheel` event if there is one. The product does not change: one `draw()` per wheel step (`draws_p50` = 1, `tests_e2e/e2e_zoom_un_disegno.py` checks it on TIC and spectrum, with the same image as a fresh draw).
- **Second draw**: does not exist (margins hypothesis): the width of the y labels does not change between one zoom and the next in the measured cases, and when it changes `syncView` redraws as before.
- **Bench**: `--only-g5` skips G1-G4, G6 and M; `chromium_path` also finds `chrome-linux64/`.
- **`lr` measurements** (4-CPU cloud container Xeon 2.3 GHz, commit a8158d7, built site, n = 30, 3 rounds, clock from the wheel, p50 / p95 ms): zoom TIC 4.0-4.3 / 4.3-6.1, spectrum 3.6-3.8 / 5.1-5.8, XIC 3k 2.2-2.3 / 3.1-3.2, XIC 50k 4.7-4.8 / 5.9-8.0; pan TIC 2.8-3.0 / 3.1-5.0, spectrum 4.6 / 6.1-6.8, 3k 3.3-3.4 / 3.7-4.7, 50k 5.4-5.9 / 6.5-9.3. With the old clock every `lr` zoom gave 30-34 ms.
