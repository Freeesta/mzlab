# qc.mass_accuracy@1: mass accuracy and table correction

- **What it does**: for each file it measures the mass error (ppm) on ions that must be present (the lab background list `mzlab/web/contaminanti.json`, without the lists with `"background": false` such as pesticides, internal standards, ions from the user's CSV) and, with `model` != `none` and a linked table, rewrites the `mz` (and `member_mz`) column of the `.mzfeat` with what was measured. Numbers only, no verdict. Raw data and indexes are only read.
- **Code**: `crates/mzlab-feat/src/massacc/` (one module per method: `ols`, `huber`, `ransac` and `offset`, `linear_mz`, `linear_mz_rt`, chosen with enums in `fit.rs`; `measure.rs` looks for the ions in the indexes, `analyse.rs` fits, `istd.rs` area and RT of the standards, `refs.rs` reads list and CSV, `correct.rs` rewrites the table in place, `report.rs` writes `massacc/1`). Single entry point `massacc::check`: used by `mzlab-cli` (`flow_massacc.rs`) and by the `table` `.wasm` (`mass_accuracy` in `mzlab-feat-table-wasm/src/massacc.rs`).
- **Ports**: `raw` (mzidx, many), `table` (optional), `samples` (optional: files with `istd` are checked for the standards), `references` (optional CSV `name, ion, rt, rt_min, rt_max, role`; `ion` is a formula with charge or adduct, or an m/z; `role` = reference, istd, standard). Outputs: `massacc` (`docs/schemi/massacc-1.json`) and `table` (only with a model: `written_if("table", model != none)`, the check rejects a wire from `table` without a `table` input or with `model=none`, `err.flow.port.unwritten`).
- **Parameters** (all with `--set INSTANCE.NAME=VALUE`): `search_ppm`, `min_intensity`, `min_refs`, `robust` (huber, ransac, plain), `model` (none, offset, linear_mz, linear_mz_rt), `warn_offset_ppm`, `warn_spread_ppm`, `warn_is_rt_min`, `warn_is_area_rsd`. Warnings: `warn.qc.mass.offset|spread|is_rt|is_area|few_refs`. A unit-resolution file is rejected by the plan check with `err.flow.facet` (the `raw` port takes only `hr`: the error in ppm makes no sense on a 0.1 Da axis), same on the site and in `flow run`.
- **Lock mass**: read only if the index carries it; otherwise `lock_mass` is `null`.
- **Native cache**: the two outputs (report and table) live in the same entry (`Made.extra`, `Entry.extra` in `flow_cache.rs`).
- **Browser** (`flow/lazy/flow-web-qc.js`, `F.webQc`): one call to the pool (`ident("proofs", "mass_accuracy", ...)`, operation `mass_accuracy` of `TP_Mine/files/feat-worker.js`) that reads the `.mzidx` files from OPFS; `raw` must come from `index.mzidx`, `table` from `features.align`/`features.gapfill`; the corrected table is in OPFS next to it, named with the SHA-256 of the report. `samples` and `references` are plan files (text in `S.samplesJson`). View: `flow/lazy/flow-views-qc.js` (table per file, error against RT and against m/z with data table, standards, save the corrected table).
- **Tests**: `crates/mzlab-feat/tests/massacc.rs`, `flow_massacc_tests.rs`, `tests_e2e/e2e_flow_qc_mass.py` (same SHA-256 as `flow run`, second pass from the cache, `MZLAB_LR_MISS` empty, axe).
- **`.wasm` weight**: the code lives in `hr` (feature `flow_ms2` of `mzlab-feat-wasm`, `run_massacc.rs`), not in `table` which has no headroom; sorting with `mzlab_core::sortc`, not `sort_by`.
- **Check from the TIC right-click** (HR file with MS1, entry `chrom.masscal` in `composizione.js`): `masscal.js` (lazy module) asks `api/masscal?k&min_intensity` and shows a summary row ("N contaminant ions found; offset ... ppm; spread ... ppm"), a table (ion, theoretical and observed m/z, error, scans, intensity, RT), two charts (error against m/z and against RT, with data table), a ppm threshold that colours only the numbers and a CSV download.
- **Check, engine and test**: in the browser op `masscal` of the worker (`rust-masscal.js`, `mass_accuracy` of the `proofs` `.wasm`, `model=linear_mz_rt`, no table); in the app op `masscal` (`rpc_masscal.rs`); same `massacc::check`. Test `e2e_masscal.py` (synthetic file from `tools/dati_sintetici_massa.py`). App parity: `crates/mzlab-desktop/tests/parity_masscal.rs` (op `masscal` = `massacc::check` on a separately built index).
