# Extending mzLab: the vendor file readers

Code: `crates/mzlab-core/src/readers.rs` (contract `CONTRATTO = 1`). Readers: `raw.rs`, `wiff/`, `agilent/`, `mzml.rs`; the `LETTORI` registry lists those that implement the trait (`agilent`, `wiff`, `raw`).

## The contract
- `Lettore`: `format`, `samples` (at least one; a `.wiff` has several), `index(c)` (one `ScanEntry` per scan: id, RT in minutes, level, polarity, TIC, base peak, filter, precursor, `Posizione` in the raw file), `scan(c, k)` (reads only the bytes of `k`), `scan_header(c, k)` (`Campo`: name, value, unit, CV: collision energy, isolation, trailer), `chromatograms(c)` / `chromatogram(c, id)`, `method(c)` (`method/1` document).
- `losses(c)` (`Losses`: declared scans, read scans, cause key; default: index rows plus `missing`) is the only point to override for a reader that loses scans; `index_outcome`, `scan_outcome`, `chromatograms_outcome` give `ReadOutcome { data, losses }`. Every wrapper (`Finished`, `SrmFromScans`, `Centroidato`, `Counting`, `Scans`) forwards `losses`; `conversion/1`, the CLI (exit 3) and the page (`conv.row.missing`: read of declared; with the cause `warn.raw.eventsRefused` `conv.row.noEvent`: scans without an event) read it.
- The cause reaches the load row as `cause` next to `missing` (`build_mzidx_native`, `lr_index` of the desktop; from the readers module `cause(h, c)` and `ExternalReader::losses`).
- Page: `rust-nativo.js` (engine worker) and `native-reading.md`: the page reads a vendor's files with `rb.nativeSamples(members)` and indexes them from the readers (`native_attach`, `build_mzidx_native`); the mzML is written only on request (`native_to_mzml`). Test: `tests_e2e/e2e_lettori.py`.
- `Membro::sha1` (optional): SHA-1 of the whole member already computed by whoever copied the file (`upload::impronte`, `Passata`); `RawReader` uses it in `mzml_header` instead of reading the file. A reader that writes the SHA-1 in the header can do the same.
- The mzML writer: `mzml_header(c)` (header of the mzML file: instrument, sources, SHA-1; `None` = plain header) and `extra_mzml(spectrum)` (`SpectrumExtra`: SIM, window, userParam). `readers_mzml::Conversione { peaks, opz, steps }` is the only mzML writer on top of `Lettore` (`write*` are its short forms) for every format, `.raw` included.
- `Picchi::Profilo` asks for `Lettore::scan_profile` (only `.raw` has it, otherwise `err.conv.noProfile`). Every reader trace becomes a chromatogram (pressure `MS:1003019`, the others `MS:1000626` with `userParam` `unità`). `Lettore::not_carried` declares field and reason of what the format has and mzML does not (reasons in `conv.rs`): it ends up in `conversion/1` in the `<run>`. The declared CV is 4.2.6 in every form.
- Precursors and vendor fields (feature `precursori` of `mzlab-core`, turned on by `thermo`, `aperti`, `bruker` and the default; off in the engine and in the other modules, under cap): `SpectrumExtra::precursors` (list of `Precursore`: selected m/z, charge, intensity, isolation window target/offset, activation, energy, parent `spectrumRef`), vendor `tic`/`base_peak`, `scan_params` under `<scan>`, `cv_params` under `<spectrum>`; without the feature the writer ignores them.
- `extra_scansione(c, k, spectrum)` (default = `extra_mzml`) is what the writer asks of a reader that must reread the file (Thermo: trailer); the index rows built by the reader (`mzidx_reader::row`) and `source::scan_text` ask for it too, so the index from the reader and the index from the mzML have the same totals (vendor TIC) and precursors (test `extras_only_in_the_trailer`, `mzidx_rows_direct.rs`). With fields of the feature the rows are read from the written text (`scantable/inert.rs`, `extra_inerte`).
- Thermo `.raw` (`rawreader.rs`): the `intestazione` of an FT scan also carries `thermo:noise_function` (the nodes `m/z,noise,baseline` separated by `;`, the noise and baseline of a peak are the interpolation), `thermo:noise` and `thermo:baseline` (median of the nodes); without nodes (ion trap, SRM) nothing. The peaks do not change. `mzml_header` gives instrument (`opentfraw::mzml::run_terms`), analysers, `opentfraw.*` of the run, startTimeStamp, SHA-1 of the file (read at the first request of the header) and `method/1`.
- Random access: streaming is `scansione(c, 0..n)`. An error is an `err.file.*` key, never a panic; what the file does not have is absent from the answer.
- No reader: `open_bare` gives `err.file.empty` (`name`) for a 0-byte member with a registry extension, `err.file.notThisFormat` (`name`, `ext`, `size`: truncated or damaged copy) for one with an `ONLY_HERE` extension (`.mzxml`, `.mzxml.gz`, `.cdf`, `.nc`, `.qgd`, `.lcd`, `.raw`, `.wiff.scan`; a `.wiff.scan` has no signature, so the error names the `.wiff` next to it, `ext` `.wiff`), otherwise `err.file.notAccepted`. The core's `readers::open` stays `notAccepted`: the site engine uses it to hand the file to the module.
- Non-finite numbers: `mzlab_core::readers_finite::Finished` (in `mzlab_lettori` as `finite`) wraps every reader opened by `readers::open` (site engine, CLI), by `mzlab_lettori::open_bare` (and so `open`: app, modules) and by `readers_finite::wiff_sample` (a single `.wiff` sample, site index and modules): an index RT or TIC, an m/z, an intensity or a chromatogram point that is NaN or infinite is `err.file.nonFinite` (`scan`, `what`, `value`) or `err.file.nonFiniteTrace` (`trace`), never a value; a negative or out-of-order RT belongs to the file and passes.
- Damaged scan (rules R1-R5): a unit that does not decode (scan, spectrum, block, channel) is left out, counted and reported; the rest loads. The scan is discarded, never the sample: `err.file.*` only if nothing can be read. A new check does not stop reading, has a synthetic fixture with a broken unit among good ones (site, app and CLI identical byte for byte) and runs on the private data (`MZLAB_DATI`) before the merge.
- `readers::Skips` (`readers/skips.rs`) in the common loops (`readers_mzml::spettri`, `mzidx_reader::table`/`spettro`/`rows_before_double`): a scan with an `err.file.*` error (`damages_one`) is written without points from its index row; if none can be read the first error comes back. `Finished` marks the broken scans and `losses` removes them from `read` with cause `warn.file.damaged` (if there is no other loss already); the header `conversion/1`, written earlier, does not count them: the CLI (stderr, exit 3, run note) and the site load report (`conv.row.damaged`) do.
- `SrmFromScans` and `Finished` also forward `scansione_profilo` and `testata_tabella`; site and app give the same key for the same `.wiff` pair (`mzlab-lettori/tests/engine_finite_parity.rs`).
- Non-finite numbers in the site's flat mzML: `scantable::read_in` (RT, TIC), `mzml::picchi::assemble` (RT, peaks, mobility: parser and helpers), `mzml::finish_chromatogram` and `Mzml::chromatogram` (points) give the same keys as the readers.
- `FileSet`: the files of a set (`X.wiff` + `X.wiff.scan`, the members of a `.raw`/`.D` folder, a single file) with logical name and `ReadAt`; `testa(i, n)` gives the first bytes.
- On the site: `crates/mzlab-wasm/src/natives.rs` opens a set of files from the registry (`Members`: names, sizes, `read(i, offset, length)`) with `native_samples`, `native_attach` (reading for the routes) and `build_mzidx_native` (index v2).
- `native_to_mzml(names, sizes, read, c, centroid, numpress, sink, progress)` writes the sample as mzML in chunks of about 64 KB (zlib-rs level 2; `numpress` true = MS-Numpress, lossy, off by default). A `.wiff` sample is instead downloaded from the `sciex` module (`to_mzml_with`, `readers-module.md`).
- `Limiti { profondita, voci, byte }` (`Limiti::sito()`, `Limiti::desktop()`) passed to every `open`: a reader compares with `ok_entries` and `profondita_ok` the numbers read from the file before allocating or recursing.

## Adding a format
A format the engine does not carry is born in `crates/mzlab-lettori/src/` behind the feature of its family and its row goes in `lettori-famiglie.js` (`docs/agenti/readers-module.md`); a format that lives in the engine follows the steps below in `mzlab-core`.
1. A module that implements `Lettore` on top of `ReadAt` (never `read_to_end` beyond 8 MB), and a `VOCE: VoceLettore { id, contratto, estensioni, riconosci, open }`. `riconosci` looks at the initial bytes and the member names, the extension alone is not enough (`Fiducia::Si` only with clues in the bytes).
2. A row in `LETTORI`. Recognition (`readers::riconosci`, `readers::open`) and the extensions of the file pickers (`readers::estensioni`) come from the registry.
3. Tests: a file built in the test, the comparison with msconvert's mzML of the same file (private data, skipped without `MZLAB_DATI`) and, for every number read from the file, the hostile case (loop, depth, huge count).
4. `err.file.*` text keys in `lang/en.js` and `lang/en/`.

## Parser defects fixed by construction
`ole.rs` (`Ole::open(data, name, &Limits)`) accepts sectors of 512 or 4096 bytes and mini-sectors of 64, visits each DIFAT sector only once, walks the directory without recursion, each entry once, rejects storages nested beyond `Limits::profondita` (`err.dam.unreadable`) and directories beyond `Limits::entries` (`error.memoryBudget`), and stops every chain (the mini FAT one too) at the stream size; whoever already has the bytes in memory passes `Limits::held()`. `xmltree.rs` rejects more than 256 nesting levels (the method reads as "absent").
