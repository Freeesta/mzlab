# MSn fragmentation graph (`msn-graph/1`) and standards tree library (`msn-lib/1`)
Contract of the graph and its library (components in §9). Related area: MSn infusion in `high-resolution.md`, routes `msn_tree`/`msntree` in `rust-routes.md`, builder `msntree_build.rs` in `rust.md`. Synthetic examples only (`TP_Mine/tests/msn_synth.py`, `tests/golden/ref/msntree_rotta/`): the real files and their names stay in mzlab-dati. CID/HCD fragmentation rules from the literature (PMID/DOI per rule): `crates/mzlab-core/data/fragrules-1.json`.

## 0. Summary of the choices
1. **What it is**: from the nodes of the precursor tree (`msntree_build::tree`, one node per path and energy) an ion GRAPH is built: a node = one fragment ion seen in one or more spectra, at any level and energy; an edge = precursor → fragment observed in the MSn spectrum of that precursor, with the neutral loss. It is a DAG, not a tree: the same ion can come from several precursors.
2. **With the molecule's formula, given by the USER** (typed, or taken from Tabui's molecule list with SMILES and adduct): each fragment receives the subformulas of the root within ±10 ppm (up to 20 ppm below m/z 150 with an extra evidence), constrained on the DAG, each with its ppm error; no automatic proposal or score, a choice only if there is one candidate or if the user makes it. Fragments without a subformula leave the graph. Without a formula: a graph by masses (Δ in Da, losses compatible with a known list, never assigned).
3. **Where it runs**: module `crates/mzlab-core/src/msngraph/` (pure Rust, no extra dependency); on the site a separate `.wasm` `msngrafo` (cap 790 528 B, measured 713 373 B: `tools/moduli/msngrafo.toml`) loaded by the engine worker at the first request, like the `thermo` module (`carica-modulo.js`). The engine's `.wasm` does not carry it (`tools/moduli/motore.toml`: cap 2 300 000 B, measured 2 276 717 B). Native: `mzlab-cli msn graph`, step `spectra.msn_graph@2`.
4. **Interface** ("MSn infusion" tool): it appears in the workspace only when ONE file is loaded and loading recognises it as an HRMS MSn infusion. Formula or name field (autofilled from Tabui's list: formula, mass, SMILES, adduct), below it the graph of all the file's levels, for each fragment the candidates with ppm and a box to draw or assess its structure with the drawing already in the app (§5).
5. **Standards library** (`msn-lib/1`, `docs/agenti/msnlib.md`): one entry per standard and condition (ion, polarity, instrument, activation and energies) with the `msn-graph/1` graph, the nodes' consensus spectra and provenance (SHA-256 of the raw files, engine); MS2 nodes are also exported as spectral library records (`.mzlib` already searches them); tree search (`msnlib.md` §2). Data and library stay in mzlab-dati.

## 2. Data model `msn-graph/1`
Schema `docs/schemi/msn-graph-1.json`; every reader (`msngraph::version`, the page, the app) reads `/1` only, with no converter for earlier files; a `/2` or later is `error.newerFormat` (`new-format.md`). JSON written with `json::Out`, keys in fixed order, numbers rounded (m/z 5 decimals, ppm and Da of the losses 5/2 decimals, relative intensities 1 decimal), no `HashMap` in the output order, sorting with `crate::sortc`: same inputs = same bytes (test: two runs and permuted inputs give the same SHA-256).
- **Head**: `schema: "msn-graph/1"`, `engine` (crate version), `source {name, sha256_idx}` (the SHA-256 of the `.mzidx`, not of the path), `options` (below), `polarity` (1/−1), `roots` (ids of the level-1 nodes), `ion {formula, theoretical_mz, observed_mz, ppm} | null`, `counts {nodes, edges, discarded_heavy, discarded_isotopes, discarded_weak, discarded_formula}`, `warnings[] {key (warn.msngrafo.*), tree (id of the tree node, empty if the warning is on the graph), node (id) | null}`.
- **`options`** (all in the JSON, so the graph can be rebuilt): merge `ppm` 5, `da_min` 0.002, `min_rel` 2 (% of the base peak), `max_peaks` 120, `activation` `null|cid|hcd|…`, `isotopes` false; formulas `formula` (the ion as given) | null, `smiles` and `molfile` (only repeated, for the drawing) | null, `ppm_formula` 10, `low_mz` 150, `wide_ppm` 20, `min_evidence` 1, `pick` `[{mz, formula}]` (user choices).
- **`nodes[]`** (order: level of the first observation, then ascending m/z): `id` (`"n" + index` in that order), `mz` (intensity-weighted mean of the observations, 5 decimals), `dev_ppm` (maximum deviation of the observations from the mean), `level` (MS level of the spectrum where it first appears; 1 = root), `isolated` and `tree: [...]` (the `msn_tree` nodes of which it is the precursor), `observations` (number of spectra), `rel_max`, `isotope_of` (id) | null, `m1` (M+1 of the most intense observation, % of it) | null, `pos {col, row}`, `formula` | null.
- **`nodes[]`, windows and unexplained**: `isolation {width_da (its window, Da), upstream_da (the narrowest on the path of the spectrum of the most intense observation), narrow}`, `unexplained {n, peaks: [{mz, rel}] (the 3 most intense)} | null` (§3).
- **`formula` of a node**: `{candidates: [{formula, theoretical_mz, ppm, dbe, electrons: "pari"|"dispari", window (10 or 20), proofs: ["loss"|"isotopes"|"msn"]}] (by |ppm|, then Hill), choice: formula | null, source: "root"|"single"|"user"|null}`. Candidates, never identifications.
- **`edges[]`** (order: `da`, then `a`): `da`, `a` (ids), `loss {da_mass, formula | null, ppm | null, compatible: [names from the known list] }`, `measurements[]` = one per spectrum in which the fragment appears, sorted by level, activation, energy: `{tree (id of the msn_tree node, i.e. the spectrum), level (MS of the spectrum), att, ce, n_scans, rel}`. `isolation` true when the edge is part of an actually isolated path (the fragment is also the precursor of a child node of that spectrum).
- **`spectra[]`** (one per tree node with a spectrum): `{tree, level, att, ce, precursor (id), width_da, peaks: [{mz (in that spectrum), rel, node (id) | null}]}`, the peaks after `min_rel`, `max_peaks`, heavy ones and isotopes. `node` null = fragment that left the graph (unexplained): the spectrum CLEANED of background is the peaks with a node; it is the data of the page's CSV, MGF, MSP and `msn-lib/1` exports (§5).
- **`structures`** and **`structures_all`** (optional keys, only if requested, before `view`; without them the bytes do not change): the structure cuts (`options.smiles`/`molfile`) whose piece gives the m/z of ONE node (`--structures NODE`) or of every node of level ≥ 2 with candidates (`all`, one `structures` value each); form and rules in `msn-interpret.md`.
- **`view`** (ALWAYS, last key; computed only from the fields already in the graph; `completa(json)` adds it to an old graph with the same bytes): model, best path, layouts and `completa` in `msn-interpret.md`.
- **Without a formula** everything stays the same except `ion`, `formula` and `loss.formula` null and `discarded_formula` 0; the list `root_candidates` (`msngraph/root.rs`: ≤ 8 formulas from `compose` for the m/z of the first root, `{formula, theoretical_mz, ppm}`) helps fill the field; it is `[]` when the formula is present.

## 4. Merging fragments across levels, energies and paths
- **Observations**: the peaks of the consensus of the `msn_tree` nodes (with the `Raggruppa` options), at most 120 per spectrum, above `min_rel`. Discarded and counted: peaks beyond the precursor's m/z plus the tolerance (`discarded_heavy`); the precursor's residue in its own spectrum is skipped (it is not an edge). An isolated precursor that is missing from the parent's spectrum still has its isolation edge, with one measure at `rel` 0 and the warning `warn.msngrafo.precNotFound`.
- **Merge**: peaks sorted by m/z, a new group when the gap from the previous exceeds `max(ppm·m/z, da_min)`; a group wider than 2 times the tolerance is split at the largest jump (no chains). The isolated precursor of a node (nominal in the filter) is tied to the peak of the parent's consensus as `msntree.rs` does (the most intense within ±0.5 Da); if a second peak within ±0.5 Da exceeds 30 % of the first, `warn.msngrafo.isolation` on the node (the isolation window takes two).
- **When NOT to merge**: different polarities (two graphs, one per polarity: the page chooses); different charges; peaks within tolerance but with disjoint candidate sets when the formula is present (two isobaric ions: kept separate with `warn.msngrafo.isobaric`); isotopes (M+1 at +1.00336 Da with relative intensity ≤ 0.011·C_max + 0.1 of the monoisotopic one in the same spectrum): by default removed and counted in `discarded_isotopes`; with `isotopes` true they stay as nodes with `isotope_of` and their edges.
- **Energies and activations**: the same edge observed at different CE or activations stays ONE edge with several `measurements` (intensity per energy is the breakdown curve); the option `activation` keeps only the spectra of that activation: measures, edges and nodes seen only with the others disappear. It depends on the per-scan CID/HCD label; the tests use synthetic files with both activations.
- **Several paths (DAG)**: a node reached from several precursors has several incoming edges (e.g. a fragment seen in the root's MS2 and in the MS3 of an intermediate fragment). If the same ion is ISOLATED by two different paths, the two spectra stay distinct (`tree` lists both); if their cosine (`finder_base::ms2`-like, on the consensus) is < 0.7, `warn.msngrafo.isomers`: same mass, perhaps different structures.
- **Layout** (`pos`, `layout.rs`): column = `level`; rows ordered by barycentre (two passes, left-right and back) from the order of decreasing m/z; deterministic. The tree and radial layouts and the best path are in `view` (`msn-interpret.md`).

## 5. Interface: "MSn infusion" tool
- **When it appears**: in the workspace, only if ONE file is loaded and loading recognises it as an HRMS MSn infusion (`kind: "infusion"`, several MSn levels); not with other files. ES modules `infusione-grafo*.js` (`// @ts-check`, project in `tools/tipi/`), texts in `mzlab/web/lang/en/` (`grafo-msn.js`, keys `msngrafo.*`; "Ion formula", never "formula" alone).
- **Field**: ion formula or name of a molecule from Tabui's list (same mechanism as its tool: autofills formula, mass, SMILES, adduct); errors with a key under the field. Below the field the graph is built at once from the file already loaded, with all levels; settings: `ppm_formula`, `low_mz`, `low_ppm`, `min_evidence`, "Activation", "Isotopes".
- **Graph**: SVG with the Rust coordinates, columns per level; node = m/z, candidates with ppm (the error always visible), evidence of the wide-window candidates; solid border = isolated; several candidates: list and one-click choice (request with `choices`); edge label = loss. Colours from CSS variables (Okabe-Ito), targets ≥ 24×24 px, zoom and pan with buttons and keyboard; `TDATI` table and "Copy data".
- **Drawing**: next to each fragment a box to draw or assess its structure with the drawing already in the app (Ketcher, `drawing.md`), starting from the molecule's SMILES; the broken atom or bond is a user hypothesis, never a fact.
- **Click on a node**: the path from the root lights up; the active cell shows the node's spectrum if it is isolated (filter `msn:<id>`), otherwise the parent's spectrum with the peak highlighted. Keyboard: ←→ columns, ↑↓ nodes, Enter = click, Esc = off.

## 6. Flow, command line, Attributio
- **Figure and HTML**: `msn-graph/1` is output as SVG, standalone HTML and PNG from the command line (with `--out` and `--figure`, stdout is `msn-figures/1`) and the step `msn.figure@1`; layout of `view` (G2), text rule of `msngrafo-vista.js`; details in `msn-manual.md`.
- **Step** `spectra.msn_graph@2` (`package: core`, `flow_msngraph.rs`, `steps-cli-1.json`): input `source` (mzML of an infusion), output `graph` (`msn-graph/1`, type `report`, the same bytes as `mzlab-cli msn graph`); parameters = the command's options with the names of its flags and the defaults of `Opzioni::default()` (`pick` = `MZ=ION,...`), plus `structures` and `struct_ppm` (`msn-interpret.md`); a plan `@1` is migrated (`rust-flow.md`, `flow::migrate`); native executor in `FileRunner`; in the `.wasm` `msngrafo` the step does not run.
- **CLI**: `mzlab-cli msn graph FILE.mzML [--formula ION] [--smiles S] [--ppm-formula 10] [--low-mz 150] [--wide-ppm 20] [--min-evidence 1] [--activation A] [--isotopes] [--pick MZ=ION]... [--structures NODE [--struct-ppm 10]] [--out PATH]` (`crates/mzlab-cli/src/msn_graph.rs`): index like the app, `msngraph::read` (tree and consensus) and `costruisci`, JSON `msn-graph/1`.
- **CLI, test on private data**: `--summary` (`msn-summary/1`, a few hundred bytes instead of the whole graph, numbers only) and with `--truth FILE` the counts against a file `{nodes: [{path, formula}]}` (paths found, right formula among the candidates, unique and right, maximum ppm, fragments annotated, discarded, nodes and peaks kept/discarded per level), for tests on private data. `msn compare A.json B.json` validates a tree measured twice (`msnlib.md` §4).
- **Attributio** (proposal only): for a feature with an MS2 and a candidate formula, the fragments of an infusion graph of a standard (or of an `msn-lib/1` entry) explained as subformulas give an `evid/1` evidence "MSn tree of a reference" with the score of `msnlib.md` §2; the evidence (`msnlib.md` §2, `msn_tree_hits`) shifts the order of the candidates, it does not assign the level (level 2a only as a proposal in `levels.md`; level 1 requires the standard's RT on the same LC method, which an infusion lacks).
- **mzFinder**: `finder_base::msn` is separate (parity with its reference) and builds its own tree; it does not read `msn-graph/1`.

## 7. Risks, sizes, real data
- **Thermo reader**: a real 8-level infusion (scan event with 3+ reactions) needs the per-scan CID/HCD label and is checked only on real files held in mzlab-dati; everything else is tested on synthetic data.
- **`.wasm`**: module `msngrafo` (crate `mzlab-msngrafo-wasm`, `wasm-feat/msngrafo/`, manifest entry `msngrafo` with SHA-256, cap and measured size in `tools/moduli/msngrafo.toml` (790 528 / 713 373 B after `wasm-opt`), with only the `chem` features of `mzlab-feat` for `structures=<id>`); the page applies only the formula rules (`msn-interpret.md`). The engine worker loads it (`rust-msngrafo.js`, op `msngrafo` of `rust-worker.js`) at the first request of `api/msn_grafo`; the main engine and the other modules do not change (no new route in the main `.wasm`).
- **Chemistry**: isobars within 5 ppm (rare below m/z 300 with CHNOS), radicals, rearrangements (an "odd" loss stays a proposal with a penalty, not an error), wide isolation windows that catch the isotope (isolated M+1: node with a warning), few scans at deep levels (the 50 % consensus loses weak peaks: read `n_scans` in the measure).
- **Performance**: no time is measured. Memory: a consensus holds all its spectra together (40 B per point, `msngraph::read::POINT_BYTES`); the estimate, extrapolated after 8 spectra, above `Options::budget` gives the calm refusal `error.memoryBudget` (phase `msnGraph`, own IT+EN texts and `.native`), never a trap.
- **Consensus budget**: `budget_mb` of the request (the page passes the engine's; without it, 192 MB), in the app the machine's memory, in the CLI `--budget-mb N` (by default the machine's). The index is hashed in 1 MiB blocks (`sha256_hex_at`), without copying it. Test: `tests/test_msngrafo_wasm.py` (same refusal from `.wasm` and CLI), tests of `read.rs`.
- **Real data** (local only, `MZLAB_DATI`): the 8-level infusion and the 4 FIA of the other series in `dati/HRMS/` of mzlab-dati; the truth file `verita_msngrafo.json` (expected nodes, edges, proposed formulas expected from the standards' known formulas); tests that require them with `NEEDS` (skipped in CI). In the public repo no compound name, m/z or spectrum of those files.
