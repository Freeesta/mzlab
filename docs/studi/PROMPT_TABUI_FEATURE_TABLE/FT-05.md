## Obiettivo
La griglia di `div` della Feature table (`TP_Mine/js/37_feature_table.js`, `PIPET`) diventa un `TPTAB` virtualizzato: colonne di riga ferme, stato delle celle con i simboli, ordinamento, filtri della vista come gettoni più «More filters», dettaglio sotto la riga con il file scelto nella riga stessa. I numeri restano quelli del `.wasm` della tabella (`session.view`, `session.rows`, `session.qc`): il JS non calcola.

## Da fare
1. **Tabella** (`37_feature_table.js`): `TPTAB.mount` con `virtual: 300`, id `ft-t`; colonne `id` (sticky), `mz` (4 decimali, sticky), `rt` (2 decimali), `detected` («rilevata in N di M file», dal conteggio degli stati della riga), `max` (area massima), poi l'insieme `samples` = una colonna per file con area breve e simbolo `TPTAB.state` (DETECTED → detected, FILLED → filled, TARGETED → targeted, UNKNOWN o vuoto → absent). Il titolo di ogni colonna-file è il nome breve con il tipo e il tempo da `campioni/2` se ci sono («t0», «30 min», «blank»), nome intero nell'aiuto. Insiemi: `essential` = id, mz, rt, detected, max; `samples`; `all`. Ordinamento sul modello (le righe arrivano da `session.rows(spec)`).
2. **Filtri**: la vista resta quella dei parametri `normalizza`/`filtra` (`specOf`), ma la barra di 8 campi diventa: gettoni «Not in blank» (regola `bianco` con il valore di default della ricetta), «Detected in ≥ 2 files» e un pulsante «More filters» che apre in linea (non una finestra) i campi numerici di oggi; «N of M rows» e «Rejected by each filter» restano (`#ft-n`, `#ft-why`). Normalizzazione: una tendina nella stessa riga.
3. **Riga che si apre**: schede `xic`, `spectra`, `samples`, `evidence`; in testa al pannello una tendina «File» con i file della serie (default: il file con l'area più alta della riga); XIC e MS2 si chiedono per QUEL file (`PIPER.detail` riceve il file: aggancio di una riga in `34_pipeline_run.js`); se il file non è aperto nella scheda Dati, una frase lo dice e un pulsante «Open in Data» lo apre (cerca come la pagina apre un file di OPFS: `grep -n "openFromOpfs\|opfsOpen\|mzlab/files" mzlab/web/*.js | head`). Nessun dettaglio vuoto senza motivo (P12).
4. **Export view** del componente accanto ai sette pulsanti di `38_feature_export.js` (che restano: sono i formati per altri programmi).
5. Lista delle identità (`33_pipeline_view.js`) NON in questo pacchetto (resta com'è).
