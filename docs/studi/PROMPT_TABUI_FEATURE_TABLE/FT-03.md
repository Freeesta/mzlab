## Obiettivo
La riga espansa della Feature table della Pipeline (FT-05) deve mostrare tutto ciò che il `.mzfeat` sa di una riga senza calcolare nulla nel JS e senza dipendere dal file aperto in Data. Oggi il `.wasm` della tabella (`crates/mzlab-feat-table-wasm`) dà solo il foglio delle righe (`export.rs:94`: id, m/z, RT, bordi, carica, area e stato per file); i riassunti di riga (`rt_lo`, `rt_hi`, `q_shape`, `q_snr`, `q_fwhm`, `qreason`, `iso_m1`, `ms2_file`, `ms2_purity`), l'identità (`neutral`, `ion`, `src`) e le celle per file (`area`, `height`, `apex_rt`, `width`, `state`) stanno nel `.mzfeat` (`store.rs`, `store_read.rs`) ma non escono.

## Da fare
1. **`crates/mzlab-feat/src/riga.rs`** (nuovo, una riga `pub mod riga;` in `lib.rs`): `pub fn row(table, samples, id) -> Result<String>` → JSON `riga/1` canonico: `{schema:"riga/1", id, mz, rt, rt_lo, rt_hi, charge, quality:{shape, snr, fwhm, flags:["shape"|"snr"|"points"]}, iso_m1, ms2:{file, purity}|null, ident:{neutral, adduct, sources:["detected","hypothesis",…]}|null, cells:[{file, type, time, area, height, apex_rt, width, state:"detected"|"filled"|"targeted"|"absent"}]}`. I bit `qreason` diventano parole con le costanti di `quality.rs` (`Q_SHAPE`, `Q_SNR`, `Q_POINTS`); l'addotto è il nome di `adduct_names()` (meta `adducts`); tipo e tempo dei campioni dal `campioni/1` dato (`samples.rs`). Riassunti non calcolati (vettore vuoto) → campi `null`, mai numeri inventati. Id che non esiste → errore con codice `rowNotFound` (messaggio in inglese, come gli altri di Tabui).
2. **`pub fn traces(table, samples, id, open_index, ppm) -> Result<String>`** → `riga_tracce/1`: per ogni file l'XIC alla m/z della riga (±ppm, finestra RT = bordi ± 3 larghezze), al più 400 punti per file (decimazione che tiene il massimo di ogni gruppo); lo spettro MS1 all'apice del file con l'area più alta (m/z della riga −1…+4); la MS2 di `ms2_file` scelta come fa `ms2spec::spectra` (stessa regola dell'export MGF). Legge i `.mzidx` con lo stesso `Index::open` di `export_ms2`.
3. **`crates/mzlab-feat-table-wasm/src/lib.rs`**: `table_row(table_read, size, samples_json, id)` e `table_row_traces(table_read, size, samples_json, id, index_read, index_sizes, ppm)` con la stessa forma di `export_ms2` (riga 101); contratto di memoria di `docs/agenti/memoria.md`.
4. **`TP_Mine/js/36_feature_qc.js`**: nella sessione di `PIPEQC.open` due metodi `row(id)` e `traces(id, ppm)` (stessa via di `view`/`rows`, anche nel worker), e le loro chiavi in `CONTRACT` (riga 11). Nient'altro nel JS.
5. Ricostruisci il `.wasm` con `tools/build_site.py` (aggiorna lo SHA-256 del manifest come fa lo script); tetti di dimensione cambiati solo se la misura lo chiede, con la misura nella PR.

## Prove
- `cargo test -p mzlab-feat riga` (nuovo, su una serie sintetica di `tools/feat_mirato.py` o sui dati di prova già usati da `export.rs`): per 5 righe i valori di `row` coincidono con il foglio `xlsx_rows` (m/z, RT, bordi, carica, aree e stati per file) e con i campi del `.mzfeat` letti da `store_read`; una riga mirata ha `quality` `null`; `traces` dà un XIC per file con il massimo dentro i bordi della riga; id inesistente → errore. JSON canonico (stessi byte a ogni giro).
- `cargo test -p mzlab-feat-table-wasm`, `cargo clippy` come in CI, `python3 tools/build_site.py`, `tests/test_pipeline_contract.py` verde con le chiavi nuove, `python3 tools/verifica.py --cambiati`, poi cancella `site/`.
