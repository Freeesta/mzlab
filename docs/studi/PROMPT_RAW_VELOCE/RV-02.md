# RV-02 — Centroidi del file segnati come profilo

Pacchetto RV-02 dello studio `docs/studi/RAW_VELOCE.md` (§2.4). File d'area da leggere: `docs/agenti/lettori-modulo.md`, `docs/agenti/mzfinder-ingresso.md` (indice `.cen.mzidx`).

## Obiettivo
`LettoreRaw::scansione` (`crates/mzlab-core/src/rawlettore.rs:290-296`) chiama `extract_spectrum(..., false)`, che per una scansione con lista di centroidi legge solo quella (`read_peaks_only`, `vendor/opentfraw/src/scan_data.rs:120`). Ma `raw::spectrum` (`crates/mzlab-core/src/raw.rs:18-33`) segna `profile = (scan_mode == Profile)`: un'acquisizione Orbitrap a profilo («FTMS + p») esce con i centroidi del file marcati come profilo, `lettori_centroidi::centroidato` li ricentroida e butta ~82 % dei picchi (su un file del laboratorio 1 051 091 → 186 194;
scansione 0 da 492 a 66). Sbagliati anche lo spettro mostrato, il `.cen.mzidx` di mzFinder e l'mzML scaricato.

## Da fare
1. In opentfraw (o in `raw::spectrum`, scegli il punto più piccolo): `SpectrumRecord` dice che cosa contengono davvero i picchi (lista di centroidi del file, profilo, o profilo senza lista). `Spectrum.profile` = vero solo quando i punti sono un profilo. Regola come msconvert (impostazione predefinita): la lista dei centroidi se c'è, altrimenti il profilo.
2. Controlla tutti i chiamanti di `extract_spectrum` con `include_profile = true` (`raw.rs:147-173`, `vendor/opentfraw/src/mzml.rs`): lì il profilo è chiesto ed è vero.
3. Parità con msconvert: per LAB-B (Orbitrap a profilo, nel repository privato) e PXD077492 (SIM «FTMS + p»), l'mzML di msconvert senza filtri: stesso numero di punti per scansione, m/z ≤ 1e-6 relativo, `centroid spectrum` dichiarato. Test in `crates/mzlab-core/tests/` (salta senza `MZLAB_DATI`).
4. `lettori_centroidi::centroidato` non tocca più una scansione che il lettore dà come centroidi: test con un lettore finto che dà centroidi e profilo alternati.
5. Indici già nel browser degli utenti: un `.mzidx`/`.cen.mzidx` costruito prima ha picchi sbagliati. Aggiungi un numero di versione del lettore nel `source` dell'indice (o nella `probe`) così l'indice vecchio non vale più e si ricostruisce; scrivi la regola in `docs/agenti/mzidx.md`.
6. Golden: se `tools/golden.py` ha dati d'oro di un `.raw` a profilo, rigenerali e spiega in PR quale numero cambia e perché.
