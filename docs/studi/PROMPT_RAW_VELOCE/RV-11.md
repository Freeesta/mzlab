# RV-11 — Tabui: `.raw` scelti direttamente, indice durante il caricamento, riuso da Dati

Pacchetto RV-11 dello studio `docs/studi/RAW_VELOCE.md` (§2.9). File d'area da leggere: `docs/agenti/mzfinder-ingresso.md`, `docs/agenti/mzfinder.md` (righe 1-20), `docs/agenti/lettura-nativa.md`, `docs/agenti/dati-carico.md`.

## Obiettivo
Richiesta di Federico: i file caricati in Dati (anche `.raw`) passano a Tabui senza conversione manuale; un `.raw` scelto direttamente in Tabui si prepara durante il caricamento, con barra di avanzamento e senza attese morte. Oggi:
- Dati → Tabui («Reload from Data», `TP_Mine/js/20_tpmine.js:125,265`) riusa il `.mzidx` v2 della scheda Dati (`stubIndexed`, `TP_Mine/files/finder-idx.js`); un campione la cui prima MS1 è segnata profilo fa costruire `<nome>.cen.mzidx` rileggendo il `.raw` da zero (`ask("cenidx")` → `rb.nativeCentroidIndex` → `lr_index_cen`): ~4,8 s nativi su LAB-B, e sbagliato finché RV-02 non è unito;
- `#tp-in` accetta solo `.mzML` (`TP_Mine/js/20_tpmine.js:196`).
Obiettivo: (a) Dati → Tabui con costo 0 per ogni campione a centroidi; (b) un `.raw`/`.wiff`(+`.wiff.scan`) scelto in Tabui è pronto nel tempo dell'indice di Dati (stesse fasi, stessa barra); (c) un profilo vero costruisce l'indice a centroidi nella stessa decodifica, non dopo.

## Da fare
1. Misura prima (con RV-02 unito): per LAB-A, LAB-B e il BAF, il tempo da «Reload from Data» a Tabui pronto e il tempo dalla scelta di un `.raw` in Dati alla mappa (strumento: un e2e con `performance.now()` nella pagina, ripetuto 3 volte, mediana). Tabella in PR.
2. **Caricamento diretto**: `#tp-in` accetta `.raw`, `.wiff`, `.wiff.scan` (le cartelle `.D` con lo stesso selettore di cartella di Dati, `cartella-carica.js`). Il file entra nello stesso archivio della scheda Dati (`NATIVO.sample` → `upload()` → `lr.js`: copia in OPFS, segnaposto, indice v2) e compare anche nell'elenco di Dati: un solo archivio, nessuna copia doppia. Tabui riceve il segnaposto (`put` con `nat:true`) appena l'indice è pronto.
3. **Barra**: nella riga del file in Tabui, le fasi di `nativo-fasi.js` (lettura, scansioni, cromatogrammi) dal messaggio `mzlab-index {name, frac, phase}`; Tabui resta usabile mentre gli altri file si preparano (nessun blocco della pagina). Testi solo in inglese, senza chiavi `lang/` (regola di mzFinder, `docs/agenti/mzfinder.md`).
4. **Profilo vero**: quando il campione entra da Tabui e il lettore dice che le MS1 sono profilo (dopo RV-02: solo file senza lista di centroidi), `build_mzidx_native` costruisce nella stessa decodifica anche `<nome>.cen.mzidx` (due costruttori alimentati da una sola lettura; dopo RV-04 la decodifica è già unica). `lr_index_cen` resta per i campioni già in Dati.
5. **Riuso**: «Reload from Data» non rilegge mai un `.raw` il cui indice (o `.cen`) ha la dimensione registrata giusta; prova con il contatore delle letture del membro (`reader` di `rust-nativo.js`, `seen`) che resta a 0.
6. Equivalenza: il `.mzidx` costruito da Tabui è identico byte per byte a quello costruito da Dati; i risultati di Tabui su LAB-A sono gli stessi passando da Dati o dal caricamento diretto (`tests_e2e/e2e_tpmine_nativo.py`, `e2e_tpmine_ingresso.py`, più un e2e nuovo per il caricamento diretto con barra; salta senza file veri).
