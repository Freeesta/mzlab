File d'area da leggere oltre a quelli comuni: docs/agenti/lettori-modulo.md, docs/agenti/dati-cartella.md.

## Obiettivo
Leggere le cartelle `X.raw/` di MassLynx (Xevo TQ in MRM/SIR, Xevo G2-XS/Synapt/Vion QTof in MS, MSe, DDA) con il modulo `waters` (feature `waters` di `crates/mzlab-lettori`, tetto 327 680 B; aggiungi `waters` alla tabella di `tools/build_lettori_wasm.sh`, che fino ad allora la salta).

## Da fare
1. Pagina: una cartella `.raw` (directory) oggi non è raggruppata; in `mzlab/web/cartella-carica.js` e `agilent-d.js` (`AgilentD.locate/group`) aggiungi il raggruppamento delle cartelle con `_FUNC001.DAT` come insieme di membri `x.raw/_FUNC001.DAT`… (il Thermo `.raw` è un FILE e `rawlettore.rs::riconosci` vuole il suo magic: nessun conflitto). Prova in node come `tests/test_agilent_d.py`.
2. `crates/mzlab-lettori/src/waters/` + `VOCE` (riga `waters` di `lettori-famiglie.js`: membro `_FUNC001.DAT`) (`id: "waters-raw"`): `_FUNCTNS.INF` (funzioni: tipo, intervallo, polarità), `_FUNCnnn.IDX` (indice delle scansioni: offset, punti, RT, TIC) e `_FUNCnnn.DAT` (coppie codificate: ricava le codifiche dai file e dalla specifica di `openwraw`, Apache-2.0, che dichiara m/z non corretti per lock mass, 30-100 ppm), `_HEADER.TXT`, `_extern.inf` (testo del metodo), `_INLET.INF` (LC), `_CHROMS.INF` + `_CHROnnn.DAT` (tracce analogiche: pressione, UV a una lunghezza d'onda → `ChromKind::Analog`/`Pda`). Il formato decodificato va scritto in un file d'area nuovo `docs/agenti/waters.md` (con la riga in AGENTS.md §5).
3. Funzioni: MS (livello 1), MSe (funzione a bassa e alta energia: livello 1 e 2 come msconvert, precursore assente), DDA (MS2 con precursore), MRM/SIR (cromatogrammi SRM/SIC per canale, id come `wiff/run.rs`, Q1/Q3/CE da `_extern.inf`), funzione lock mass (riferimento): esclusa dagli spettri, data come cromatogramma e nei `campi`; correzione lock mass NON applicata (dichiarata in `metodo/1`).
4. `metodo/1`: `_HEADER.TXT` (`$$ Acquired Name/Date/Time`, `Instrument`, `Sample Description`, `Job Code`, `User Name` → `identita`, `Bottle Number` → vial, `Inlet Method`, `MS Method`), `_extern.inf` (sorgente, capillare, cono, temperature, gas, CE per funzione, intervalli), `_INLET.INF` (gradiente, flusso, colonna, forno).
5. Test: una cartella costruita nel test (2 funzioni, codifica più semplice), casi ostili su `IDX`/`DAT`/`INF`; parità con l'mzML di msconvert per ogni file vero (`MZLAB_DATI`); e2e con la cartella sintetica (`tools/waters_sintetico.py`, generatore di file come `agilent_sintetico.py`).
