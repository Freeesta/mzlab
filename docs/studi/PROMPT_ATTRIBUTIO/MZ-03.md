## Obiettivo
Riscrivere da zero il join aligner e il peak finder (riempimento) di mzmine 3.9.0. Sorgenti: `align_join/JoinAlignerTask.java` e `JoinRowAlignScorer.java` alla v3.9.0 (su master il codice sta in `align_common/BaseFeatureListAligner.java`: segui 3.9.0), `RowVsRowScore`, `FeatureListUtils.getAlignmentScore`, `gapfill_peakfinder/multithreaded/`. L'uscita deve essere la tabella `Aligned` di mzLab, così tabella, esportazioni e statistica esistenti la leggono senza cambiare.

## Da fare
1. `crates/mzlab-feat/src/untargeted/join.rs`:
   - Parametri: `JoinParams { tol_da: 0.0015, tol_ppm: 5.0, w_mz: 3.0, w_rt: 1.0, rt_tol: 0.2 }`.
   - Funzione: `align(lists: &[Vec<Feature>], p: &JoinParams) -> Rows`.
   - Algoritmo di §5.3:
     1. Le liste si ordinano per numero di righe decrescente; la più grande fa da base.
     2. Per ogni lista successiva si calcola il punteggio di ogni coppia (riga, feature) dentro le tolleranze: `Σ w·(1 − |Δ|/semiampiezza)/Σw`.
     3. I punteggi si ordinano in modo globale e decrescente, con spareggio stabile e documentato.
     4. Una feature per file per riga; le feature senza riga diventano righe nuove.
     5. m/z e RT della riga = media dopo ogni lista, come mzmine.
2. `crates/mzlab-feat/src/untargeted/gapfill.rs`. Parametri: `GapParams { intensity_tol: 0.2, tol_da, tol_ppm, rt_tol }`. Per ogni cella vuota cerca nel file il segnale dentro m/z ± tolleranza e RT ± `rt_tol`. Il picco viene costruito come fa il peak finder 3.9.0 (cerca la classe del gap e scrivi nel commento come accetta il picco); area nella stessa unità di MZ-02. L'ingresso dei punti è il `.mzidx` del file (`mzlab_core::idxread`) e la lettura avviene per finestra, mai il file intero in memoria. Il riempimento di oggi (`crates/mzlab-feat/src/gapfill.rs`) non si tocca.
3. `crates/mzlab-feat/src/untargeted/table.rs`: `to_aligned(rows, files) -> Aligned`. Una riga per ione, cioè `Mode::Ion` o l'equivalente in `recipe.rs` (cerca come la tabella distingue righe e famiglie). Area in conteggi·s, celle riempite segnate come riempite (stesso campo della pipeline di oggi). Se `Aligned` chiede campi che il join non produce, mettili vuoti e scrivi quali nel commento; non cambiare la forma di `Aligned`.

## Prove
- `crates/mzlab-feat/tests/untargeted_join.rs`: da `resolved.csv` (ingresso) a `aligned.csv` di `tests/data/untargeted/mzmine39/`. Parità: stesse righe (stesso insieme di feature per riga) ≥ 0,99, m/z e RT della riga entro 1e-6. Casi a mano:
  - due feature di pari punteggio (spareggio);
  - feature fuori tolleranza che crea una riga nuova;
  - lista base scelta per numero di righe;
  - due feature dello stesso file vicine (una sola entra).
- `untargeted_gapfill.rs`: da `aligned.csv` a `gapfilled.csv`; aree delle celle riempite entro 1e-6 relativo per ≥ 0,99 delle celle.
