# PERF-01: the spectrum of one HR scan without the full-section pass

You are a chat of mzLab (repository Freeesta/mzlab). Read AGENTS.md, `docs/studi/OTTIMIZZAZIONE_PRESTAZIONI.md` §1-2, `docs/agenti/visore-veloce.md` (G1, G6), `docs/agenti/rust-rotte.md` (row `spectrum` centroid HR). Branch `claude/perf-spettro-hr` from `origin/main`. English for code, commits and PR.

**Problem (measured).** A click on the TIC of an HR centroid file asks `api/spectrum` for a window that holds ONE scan. `rust-bridge.js:147` first sends the `route` op. `Routes::spectrum` → `hr_spectrum` (`hrroutes.rs:14`) → `hr_window` → `binned_cells` (`spectrum.rs:91`) walks EVERY peak of the MS1 section (`each_peak(si, 0, total, …)`), sees `n == 1` and returns `None`. Then the bridge sends `specexact`: `spectrum_exact` (`hrroutes.rs:24`) calls `hr_window` again (a second full pass) and finally replaces the peaks with `mzml.spettro(sc)`. Native cost of ONE pass: 48.5 ms with 9 M peaks (3 000 × 3 000), 190 ms with 30 M peaks (6 000 × 5 000). In the site, G1 costs 804 / 2 427 ms (engine 574 / 1 775 ms) and G6 (ArrowRight) costs 104 / 287 ms.

**Do.**
1. Split the selection out of `binned_cells`: one function gives `n`, `sel`, `in_win` (and `scan_ids`) from the scan table and the section arrays only. These are the `ok`/`sel`/`in_win` it computes today, with the same filter (`Filtro::passa`), precursor tolerance and window bounds. `binned_cells` uses it, so nothing is duplicated.
2. `hr_spectrum`: compute the selection first. With `n == 1`, return `None` without touching the peaks. Otherwise keep today's behaviour.
3. `spectrum_exact`: same selection. With `n == 1 && in_win.len() == 1`, build the `Binned` without the pass and fill `mz`/`y` from `mzml.spettro(sc)`. Today the scan is read only when the index pass found at least one peak (`if !m.mz.is_empty()`). Keep that answer exactly. Use a per-scan peak count if the index stores one (look in `idxread`: section arrays and `Scan`). If it does not, prove from `mzidx.rs` which peaks the builder drops (zero intensity? out of range?) and apply the same rule to what `spettro` returns, so that "index has no peak for this scan" ⇔ "empty `mz`". If you cannot prove the equivalence, keep the old pass ONLY for that undecidable case, and write down why.
4. Do not touch `rust-bridge.js`: with 2-3 the first call costs microseconds. Do not change the JSON, the rounding (`binned_json`) or the `None` / empty contracts.
5. `examples/visore_tempi.rs`: the spectrum row today reports "answered None" on HR files. Make it time the real one-scan HR path: route + `spectrum_exact` on the mzML, as the worker does. Report p50/p95 before and after on `bench_mappa.write_file` `hrc` 3000×3000 and `hrc` 6000×5000.
