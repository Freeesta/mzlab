# Verification of Gemini's loading-path reviews (lots 1-2 of 6)

Phase 1: read-only. Every claim was checked against the code on `origin/main` (the lines Gemini cites are often off; the lines below are the real ones). Nothing was measured: speed verdicts reason from the code and from the measurements already in `docs/agenti/` (`misure-rust.md:12`, `mappa-fluida.md:48,86`, `caricamento-mappa.md:14`). Where a number would decide, the row says what to measure and where (native example, or browser e2e in CI only). None of the speed proposals appears in `docs/agenti/ottimizzazioni-tentate.md` (grepped: Windowed, lease, parkAll, SharedArray, corriere, spill, BufReader, transfer, mobility: no hit), so no dead end is repeated. Legend: **T** true, **F** false, **P** partial. Groups for phase 2: **a** safe, output identical; **b** real bug, output changes (listed); **c** do not do.

## In brief

- Lot 1 (13 items): 2 T, 7 P, 4 F. Lot 2 (21 items): 7 T, 11 P, 3 F. Total 34: 9 T, 18 P, 7 F.
- Real bugs, ranked: **D1** (a stale `open()` after a worker death/recycle sets `s.bad` and opens a big mzML in memory although the index exists); **C2** (CLI `prepare_late` accepts non-mzML as an empty index while the site refuses: a parity bug); **D4** (`held` reservation leaks, copy not cancellable); **D3** (false `error.quota` for the 2nd..Nth sample of a `.wiff`); **D2** (stale native stub when a plain mzML reuses a name).
- Real speed wins, ranked: **C3-2** (`testo_scansione` reads the whole `<spectrum>` incl. arrays; Metodo of an HR mzML does ~900 such reads; header-only is output-identical), **S3-2** (`DeclaredWindow::note` does 2 `format!` + 2 scans of the header for every scan, then discards), **V10** (prefetch the next block in the OPFS copy), **S6** (the spectrum route decodes the same bytes twice: `spettro` then `mobilita`), **V3c** (the same `.mzidx` is parsed 3 times in a row), **V3a / V1** (sync handle instead of `FileReaderSync`; needs a browser measurement).
- Gemini's headline claim **S1 is false and its fix would be a large regression** on the site (see S1). **V11, D7, D10, S7** are false or unreachable.
- Needs Federico: nothing in lots 1-2 touches dependencies, CSP, defaults, `.mzlib` or new storage. V5 (keep pool workers alive) changes the memory policy of the index builder: his call if ever pursued.
- Several Gemini fixes are wrong as written: D1 (`slots[k] !== s` is never true), S6 (accession list omits three of twelve), V3b (transfer detaches buffers that the retry paths re-post), S1 (small window), D7/V11 (premise false). They are marked **fix OK? no**.
