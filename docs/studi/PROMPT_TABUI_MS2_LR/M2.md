## Obiettivo
`crates/mzlab-feat/src/legacy/lr/ms2.rs::pool` sceglie le scansioni MS2 di una riga in modo implicito (precursore entro `tol_da`, tempo dentro `window(e)` attorno a `ref_rt` e traccia con segnale, come lo lascia M0) e solo quando si apre il dettaglio. Va sostituito da un abbinamento esplicito, calcolato una volta dopo il Dig, con le regole 1-11 dello studio (§4), riportato nel riassunto come `ms2_links/1` (§5) e correggibile con `relink`. Nessuna interfaccia in questo pacchetto (è M4): solo motore, `.wasm` e worker.

## Da fare
1. Nuovo modulo `crates/mzlab-feat/src/legacy/lr/ms2link.rs` (dividilo se supera ~300 righe: `ms2link/exp.rs` esperimenti e tracce, `ms2link/rules.rs` regole, `ms2link/json.rs` uscita):
   - `experiments(d: &LrDig, open) -> Vec<Exp>`: per ogni file `ms2` e per ogni file delle colonne (`d.lc`) le righe dell'indice con `level == 2`, raggruppate per (polarità, precursore arrotondato a 0,1, CE arrotondata a 0,1 o `None`); per ognuna `scans: Vec<usize>`, traccia `(rt, tic)` dalle righe dell'indice (nessun picco letto), `time` del file (`FileLr.time`), intervallo di tempo. Indici dei file nell'ordine di `open` di oggi: colonne poi file `ms2` (vedi `skip = d.lc.len()` a ms2.rs:101).
   - Picchi della traccia: `mzlab_core::peaks::detect_peaks` (S/N ≥ 5, dopo `settings.rt_min`) per l'elenco; per la regola 4 `lr::peak1d::find_peak(rt, tic, Some(atteso), rt_tol_min, 3, 3)` (S/N ≥ 3). Acquisizione a finestra (meno di 10 scansioni fuori da ±`rt_tol_min`): il picco sono le scansioni dentro la finestra (regola 4, secondo capoverso). Costanti con nome in testa al modulo: `PREC_TOL = 0.5`, `SN_LINK = 3.0`, `SN_PEAK = 5.0`, `SN_DRIFT = 10.0`, `FEW_OUTSIDE = 10`, `ISO = [1.00335, 2.0067]`.
   - `link(d, exps, overrides) -> Links`: regole 1-11 nell'ordine dello studio. Tempo atteso = apice della cella della riga nel file full con lo stesso `time` del file MS2 (se `apex_rt` c'è), altrimenti `e.ref_rt`; deriva del file come regola 5 (due passate). Le righe candidate sono `d.entries` (genitore id 0, candidati, inattesi). Polarità della serie = quella delle scansioni di livello 1 dei file full (maggioranza). Frammento in sorgente: stessa soglia di `insource` (0,5·`rt_tol_min`, `lr/rows.rs` e `mzfinder-lr.md`).
   - `Links { exps, links, unmatched, parent_has_ms2 }` e `json(o)` = `ms2_links/1` esattamente come §5 dello studio; `why` in inglese, breve, con i numeri (p. es. «precursor 0.12 Da from the calculated m/z; MS2 peak 0.03 min after the full-scan apex»).
2. `LrDig` (`lr/mod.rs`) tiene `links: Option<Links>`. `ms2::pool` (ms2.rs:91) usa gli abbinamenti della riga (stati `auto`, `ambiguous` per la riga scelta, `isf`, `user`) e, per ogni abbinamento, le scansioni dentro `[lo, hi]` del picco della traccia; `window` sparisce. Senza `links` (nessun file MS2 né scansione di livello 2) il pool è vuoto come oggi senza file `ms2`. Con più CE: `detail.ms2` = la CE con più scansioni (forma invariata), `detail.ms2_links` = un oggetto per abbinamento `{file, precursor, ce, apex, lo, hi, state, why, scans, fragments}` (frammenti come `ms2_json`). `rows[].ms2` del riassunto (`lr/summary.rs`) = numero di abbinamenti nel pool. `transitions_json` usa la CE dell'abbinamento scelto.
3. Il genitore: `lr/tree.rs` prende la sua MS2 dal pool del genitore (che passa dagli abbinamenti); se `parent_has_ms2` è falso la nota dell'albero non cambia.
4. `crates/mzlab-finder-lr-wasm/src/lib.rs` (`FinderLrDig`, riga 102): `ms2_link(read, sizes, overrides_json) -> Result<String>` (calcola, tiene e restituisce `ms2_links/1`) e `relink(read, sizes, overrides_json) -> Result<String>` (stessa cosa con nuove correzioni, senza rifare il Dig; poi `summary` riflette i conteggi nuovi). `summary` include `ms2_links` quando c'è.
5. `TP_Mine/files/finder-lr.js`: in `run` (fase «ms2», riga ~100) apri `cols` con `c.openIdx(cols)` e chiama `dig.ms2_link(...)` con `JSON.parse(a[2]).ms2_overrides || []`; `ofDig` accetta `ms2_relink` (args: overrides JSON) e restituisce il nuovo `ms2_links/1`. `TP_Mine/files/tpmine-worker.js:32`: aggiungi `ms2_relink` a `OF_DIG` (con `last === "pyodide"` risponde un errore in inglese «MS2 matches need the Rust engine»). `lr/plan.rs::settings` (riga 152) ignora `ms2_overrides` senza errore.
6. `crates/mzlab-finder-lr-wasm/examples/finder_lr.rs`: un argomento facoltativo `--ms2 N` = gli ultimi N mzML sono file MS2 (non entrano nel rilevamento né nell'allineamento, come nel browser) e scrive `ms2_links.json`. Ti serve per la prova sui dati veri.
7. `TP_Mine/tests/lr_synth.py`: `write_ms2(folder, experiments, times)` scrive un mzML MS2 (precursore, CE, picchi gaussiani della traccia a tempi dati, rumore costante altrove, scansioni ogni 0,02 min su tutta la corsa) per l'e2e di M4; nessuna logica di prodotto.
