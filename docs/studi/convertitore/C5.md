PR 1 · «mzlab-cli convert»:
1. `mzlab-cli convert INGRESSO... --out CARTELLA [--zlib N] [--numpress] [--peaks file|profile|mzlab] [--workers N] [--report FILE.json]`: INGRESSO è un file, una cartella dei produttori o una cartella da scorrere; gli insiemi si riconoscono come nella pagina (`.wiff` con il suo `.wiff.scan`; un `.wiff` con più campioni dà un mzML per campione, `<nome>-<campione>.mzML`).
2. Un file già convertito con gli stessi SHA-256 di ingresso, versione dello scrittore e parametri si salta (cache come `flow_cache.rs`); `--fresh` lo rifà.
3. `--report`: per file `{ingresso, uscita, sha256, spettri, secondi, conv/1}` o `{errore, causa}`.
Accettazione: `cargo test -p mzlab-cli convert` (in `convert_tests.rs`): cartella sintetica con un mzXML, un `.cdf`, una coppia `.wiff` sintetica (`tools/wiff_grande.py`) e un file rotto → tre mzML validi per `xmllint` (se presente), codice 1, riga d'errore con causa per il file rotto, byte uguali all'uscita di `mzlab-cli flow run` con un piano `convert.mzml` sugli stessi file e uguali con `--workers 1` e `--workers 3`; seconda corsa: tutti saltati; `cargo test -p mzlab-cli flow_rule_tests` verde; `--help` elenca ogni opzione.
