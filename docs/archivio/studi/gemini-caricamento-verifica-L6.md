## Answers to the COO's three questions
- **P1.** Gemini is right on the numbers: the idle-callback timeout is 1000 ms and `whenProbed` gives up at 800 ms (`rust-budget.js:37-49`). `ordered` waits `Promise.all([compile(), ready()])` before it posts the module (`rust-supervisor.js:22-30`), and the worker starts instantiating when `module` arrives (`rust-worker.js:401`), so the wasm instantiation waits for the probe (its running time when the page is idle, up to 800 ms when the main thread is busy; zero when the result is cached in sessionStorage, i.e. only the first open of a tab). The probe only feeds `probe_mb` of `budget_choice` (`rust-worker.js:388`); with 0 the policy still works (that is what happens after the 800 ms timeout today), so skipping its result is safe. Posting `module` right after `compile()` keeps the order module → policy → budget → down → commands because the policy still waits for `ready`. Risk: low. Two cautions: (a) when the timeout wins, the probe still runs at ≥1000 ms and allocates while the worker opens files (sets `PROBE` for the next session only); running it with `setTimeout(run, 0)` when `whenProbed` asks, or a rIC timeout below 800, is sensible; (b) a test must pin the message order.
- **C-A / C-B vs the loading-UI chat.** C-A (`explore.js` `remap`, `PEND`) and C-B (`mzlab-index` listener, `getChrom`) are in the Explore state code, not in `avanzamento.js`, `progresso.js`, `conversione.js` or `shell.js`; they do not overlap with the progress clarity work unless that chat edits `explore.js` near these lines. C-B reads the same `mzlab-index` event that the loading panel uses but only consumes `early_tic`. **C-C overlaps** (`avanzamento.js`).
- **P8.** The worker is single threaded and answers in order, so parallel requests do not run faster; the gain is the gap between a reply and the next post, about one message per file (sub-ms). Buffers: each answer carries its own transferable `buf`; with N outstanding answers the pool cannot reuse one, so N buffers are allocated, which the old loop also did (`list` keeps all of them until `packXic`). `Promise.all(ks.map(...))` keeps the order of `list`. If one answer fails, the other buffers must still go back (`recycle`), which is C-F's `finally`. Do both together or neither.
