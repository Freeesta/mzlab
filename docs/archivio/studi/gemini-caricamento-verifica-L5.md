# Lot 5 verification (Gemini, `crates/mzlab-desktop`): phase 1, no code changed

Method as in `gemini-caricamento-verifica.md`. Verdicts: T = true, P = partial, F = false. Scope: `src/*.rs` + `shim/*.js`. `mapped.rs` holds the only `unsafe` of the crate (memmap2, header says so; the repo has no automatic guard on it): not touched.
"Linux test?" says whether the logic can be reproduced by a unit test in the cloud (no browser, no Windows).

## In brief
- 16 items: **T 5** (J1, J3, J6, J8, K7), **P 10** (J2, J4, J5, J7, K1, K2, K3, K4, K5, K6), **F 1** (J9).
- **Rank first: J3 then J1.**
  - **J3** loses data: removing one sample of a multi-sample native file deletes the files its siblings still use.
  - **J1** can panic the conversion worker (index shifted under a released lock) and leaves its thread counted forever, so the background queue can stall.
- **K1 is not safe as written** (hard_link): the temp mzML names are reused after a page reload and rewritten in place (details below). It needs a precondition.
- J5 is the same family as lot 2 D7 and must be decided together with it. J8 is a UX decision for Federico.

## Speed (K)

| id | claim | verdict | evidence | fix OK? | output changes? | Linux test? | risk | zone |

| K1 | `hard_link` instead of `copy` in `lr_put` | **P**, **unsafe as written** | `rpc_lr.rs:70-75` copies a temp mzML (`is_temp`) into `own_dir` under the engine lock. Real cost for GB files. Danger: the temp names are `mzlab-<process>-n<msgid>.mzML` and `…-c<msgid>` (`rpc_nat.rs:50`, `rpc_msn.rs:~157`), created with `File::create` (truncate in place). Message ids restart when the webview reloads while the process lives, so a later conversion truncates the **same inode** that the hard link made the stored file: the registered mzML is silently corrupted. Also `temp_dir()` is often another filesystem on Linux, so it falls back to `copy` there. `cleanup()` deleting the temp name is harmless; the in-place rewrite is not | only after the temp files are written as a unique name (or `.part` + rename). A `rename` of the temp onto `dest` is an alternative but breaks the `Picked` entry that still points at the temp | bytes equal | **yes** (rewrite after link and check) | medium | Z-4 |
| K2 | cap the background conversion at 2 threads and wait 50 ms | **P** | `conv_coda.rs:73-81` uses cores-1; `work` waits while `INDEXING > 0` only before starting each job; a running conversion is not paused (design, `conv_coda_tests.rs:78`). The 50 ms re-check closes the window where `conv_add` precedes `Indexing::new()`. The numbers (500-4000 ms) cannot be measured here. The thread count is a default | the re-check is cheap; the count is a default → Federico, with a measurement on a laptop | no | yes (gate) | low | Federico + Z-2 |
| K3 | `Arc<Run>` so the global lock is not held during TIC/XIC | **P** | `engine.rs:248-254` holds `inner` during `f`, and `inner` also guards `picked`, `progress`, `temps`. The change is mechanical (`runs` type, `open`, `close`, `reset`) | OK, small | no | n/a | low | Z-5 |
