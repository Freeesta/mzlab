# Gold data of mzmine 4.10.90 per stage (synthetic files)

Output of mzmine 4.10.90 on the four synthetic mzML files of the 3.9.0 set (`tests/data/untargeted/mzmine39/`, same numbers and same hashes), one CSV per stage, same formats. Reference of the parity tests `crates/mzlab-feat/tests/untargeted_*_410.rs`.
The mzML files are not in the repository: `tools/bench/oro_mzmine.py --genera DIR` writes them again, byte for byte.

- **Written on**: 2026-10-19 by `python3 tools/bench/oro_mzmine410.py --oro` (it checks first that every parameter name of the batch exists in the parameter classes of `mzmine-community-4.10.90.jar`: mzmine ignores the others without a word).
- **mzmine**: 4.10.90, `https://github.com/mzmine/mzmine/releases/download/v4.10.90/mzmine_Linux_portable-4.10.90.zip`, sha256 `15b616c9ce60edaa8c7b8ae8be10c44d49a784542efe68838bfab721b6e8c7ca`; license MIT, (c) 2004-2022 The mzmine Development Team (`https://github.com/mzmine/mzmine/blob/master/LICENSE.txt`, branch master checked).
- **JDK**: the one inside the package (`lib/runtime`): openjdk version "26.0.1" 2026-04-21 / OpenJDK Runtime Environment Temurin-26.0.1+8 (build 26.0.1+8).
- **Platform**: generated on macOS arm64 with mzmine.app 4.10.90 and the Temurin JDK of the app
- **Charge in `isotopes.csv`**: the 4.10 export of the grouper has no charge column, so `role`, `charge` and `principal` are derived (`_fase_isotopi`): a removed row is an isotopologue of the kept row within 0.1 min whose m/z is lower by 1 to 4 times 1.003355/z (z in 1..3, tolerance 0.01), the charge of a kept row is round(1.003355 / spacing of its nearest removed row) and every other removed row is a whole multiple of 1.003355/z; kept rows with removed rows are principal (charge z), the others alone (charge 0). `isotopes_finder.csv` is written as exported: `pattern_peaks` is the column `isotopes` of the finder export (number of peaks of the pattern, empty when no pattern was found), `pattern_mz` is empty because 4.10.90 does not export the m/z of the peaks, and an empty `charge` means that the finder found no charge.
- **Command**: `bin/mzmine -b fasi.xml -t TMP`, `bin/mzmine -b isotopi.xml -t TMP`, `bin/mzmine -b finder.xml -t TMP` (no interface), parameters of `tools/bench/parametri/mzmine/predefinita.json`.
- **Input files** (sha256 of the mzML written by `oro_mzmine.py`, equal to the ones of the 3.9.0 set, with every array decoded and rounded to 6 significant digits; mzmine 4.10.90 reads them after `senza_cromatogrammi`, which drops the TIC chromatogram: its parser fails on it, no stage uses it:

- `oro_1.mzML`: `948314014e6ad2e3bf8d2f522cd18214aee2a5122b3a54ed8dec544aa037c73a` (as read by mzmine: `ab5ac30aca3ddb7466fa5525d8c4d7916f29899ce165df9d9350364b35bb9b5e`)
- `oro_2.mzML`: `d0184e55228e681cf3b1cda0e45c0e3287fa8268c14922330c384db7a928adf8` (as read by mzmine: `3978802b51111f7d4dff3674846f03df45cadf8fe38c6257e02fa558077e2168`)
- `oro_3.mzML`: `809850330d577ff5d24aaaeb86bedaca196e61747c8a14141d3879603476cb18` (as read by mzmine: `a6c183cb0f9cbcea25e4dd6229775ce05848f834f6deadba7e419a69412abed4`)
- `oro_4.mzML`: `c15f09494dd6c07e079d0f7252759cc428e33434a68ad2459060483875f14e11` (as read by mzmine: `a13fbc977835ac797b9361cc97bc2061189bb2656cc351dc381f30127b6724a9`)

## Files
`adap.csv`, `resolved.csv`, `aligned.csv`, `gapfilled.csv`, `isotopes.csv` have the columns of the 3.9.0 set (see its LEGGIMI); `isotopes.csv` is the output of the isotope grouper («13C isotope filter»).
